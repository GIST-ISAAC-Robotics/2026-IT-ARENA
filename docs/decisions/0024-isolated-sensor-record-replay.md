# ADR 0024: 원시 센서 기록과 구동부 없는 격리 재생

- 날짜: 2026-09-24
- 상태: 채택, PC 검증 결과는 별도 보고서에서 관리
- 선행: [전체 계획 A2](../reports/DEVELOPMENT_PLAN_2026_09_22.md), [구동 계약](0023-mcu-actuation-contract-reference.md)

## 목적

실제 센서가 없어도 같은 입력을 반복 사용해 제어기 변경을 비교하고 Jetson 처리량을 시험할 수 있게 한다. 시뮬레이터의 느린 실행 시간과 제어기의 처리 시간을 구분한다. 이번에는 센서 필터·경로/속도 정책·차량/트랙을 바꾸지 않는다.

## 결정

1. 명시적인 `--record-inputs`에서만 원시 RGB·CameraInfo·순차 LiDAR·IMU·후륜 엔코더, 비교용 명령·상태·콜백 계측을 기록한다. 기본 실행과 legacy 구동은 유지한다.
2. ROS 메시지의 원래 직렬화 바이트(CDR)와 `header.stamp`를 보존한다. MCAP의 시각은 기록기 ROS 수신 시각이고, 별도 JSONL에는 원래 헤더 시각·기록기 단조 수신/쓰기 시각·제공되는 DDS 순번을 남긴다. 헤더를 수신 시각으로 덮어써 지연을 없애지 않는다.
3. MCAP 청크의 무손실 Zstd 압축을 사용한다. 원시 RGB를 JPEG/영상으로 바꾸지 않는다. 파일 SHA-256과 토픽별 `수신시각+길이+CDR` 누적 해시·개수를 검증하고, 기록 큐 유실/시계 역전/파일 누락/기록 실패 자료는 정상 재생 대상으로 받지 않는다.
4. 실제 실행한 두 제어기의 매개변수도 보존한다. 재생은 새 ROS 도메인·localhost·`/replay` 경로에서 **지역 Pure Pursuit와 독립 LiDAR 보호층만** 실행한다. 센서 허용 목록 외 자료는 발행하지 않는다. 당시 `/drive`, `/drive/safe`, MCU 상태는 비교 자료이지 재생 명령이 아니다. MCU/모터/시뮬레이터는 실행하지 않는다.
5. 기본 비활성인 `timing_probe`로 센서 콜백·운동 입력·제어 콜백의 단조 벽시계 소요시간, 콜백 진입 시 센서 나이를 구분한다. ROS 역직렬화 이전 대기나 전체 센서→모터 지연, GPU 시간·CPU 점유율 측정으로 확대하지 않는다.
6. 재생 시각은 기록 당시의 ROS 수신 시각을 따르며 원래 헤더는 유지한다. 재생 종료 뒤 센서 공급만 끊고 시계는 진행해 보호층의 0명령을 확인한다. 출력은 모형을 움직이지 않으므로 이 결과를 제동거리나 새 폐루프 완주로 해석하지 않는다.
7. 재생 CDR는 원시 직렬화 발행 경로로 전달한다. 재생기 발행 지연과 제어기 콜백 처리 부하를 분리하며, 선택형 `~/timing_snapshot`으로 진단 로그 수신 수와 실제 콜백 완료 수를 대조한다. 0.5배속 기능/스케줄 통과와 1배속 기능 실패를 함께 보존하며 실패를 통과로 만들기 위한 제어/보호 수치 변경은 하지 않는다.

## 한계와 후속

- 저장 큐의 무손실과 센서 발생부터의 완전 무손실은 다르다. BEST_EFFORT 수신 이전의 DDS 누락은 별도이며 가능한 순번 관측과 실제 콜백 수를 보고한다. `complete=true`는 기록기 내부 완료 조건이다.
- 재생 스케줄·DDS·콜백 실행 순서는 매번 조금 달라질 수 있다. 원시 데이터 무결성과 최종 조향 명령의 비트 단위 동일성을 혼동하지 않는다.
- 파일 검증·선택형 계측·압축/역직렬화에도 비용이 든다. PC의 1배속 성공이나 실패를 Jetson 성능으로 단정하지 않는다. Jetson에서는 실제 전력 모드·클록·발열과 함께 별도 측정한다.
- 실물 C1 점별 시각/배열 순서, IMU/MCU 시간 변환, 실제 센서 드라이버 QoS·누락·지연은 부품 도착 후 확인해야 한다.
- RGB 원시 파일과 상세 수신 로그는 로컬에 보존하고 Git 기본 추적에서 제외한다. 매개변수·해시·검증 요약·실패 기록은 남긴다. 외부 게시나 대용량 업로드 승인은 포함하지 않는다.

## 선택 근거

설치된 Jazzy의 `rosbag2_py` MCAP 쓰기/읽기·`zstd_fast` 지원을 직접 확인했다. MCAP 청크 압축은 파일을 다시 탐색하며 읽기 위한 구조를 유지한다. [rosbag2 MCAP 공식 설명](https://github.com/ros2/rosbag2/blob/rolling/rosbag2_storage_mcap/README.md)을 참고하되, 다른 버전의 예제를 그대로 지원한다고 가정하지 않는다.
