# ADR 0025: 영상 인식과 고빈도 제어 실행의 분리

- 날짜: 2026-09-29
- 상태: 지역 Pure Pursuit에 채택. 검증 범위와 잔여 문제는 [A3 결과](../simulation/JETSON_REPLAY_2026_09_28.md)에서 관리한다.
- 선행: [지역 제어기](0022-b0183-c1-local-pursuit-prototype.md), [격리 재생](0024-isolated-sensor-record-replay.md)

## 이유

Jetson 기준 시험에서 RGB 신호/마커 인식과 IMU 수신·조향 타이머가 한 실행 흐름을 공유했다. 영상 판정을 바꾸지 않는 연산 최적화 후에도 IMU 누락과 제어 시작 간격 변동이 남았다. 영상 콜백이 실행되는 시간과 누락의 상관관계가 있어, 센서율이나 보호 한도를 완화하지 않고 실행 경계를 분리한다.

## 결정

1. `local_pursuit`의 `vision_execution=process`를 기본으로 한다. `inline`은 기존 동기 경로의 비교용이다. 기존 `lidar`/`stereo` 모드의 인식 경로는 바꾸지 않는다.
2. ROS/DDS 상태를 `fork`하지 않고 `spawn`한 자식 프로세스에서 같은 `StartSignal`과 ArUco 검출을 수행한다. 자식에는 ROS 노드·주행 발행 권한이 없으며 결과 후보만 반환한다. 출발 확정과 벽 추종 방향은 부모 제어기만 반영한다.
3. 한 요청만 처리하고 대기 영상은 최신 한 장으로 교체한다. RGB 본문은 최대 1920×1080×3바이트 공유 버퍼에 복사하며 파이프에는 작은 메타데이터/결과만 보낸다. 진행 중인 버퍼를 덮어쓰지 않는다. 현재 `rgb8`/`bgr8`와 행 패딩을 검사하며 잘못된 크기·용량 초과는 고장으로 처리한다.
4. 기존 0.095초 인식 간격 제한을 유지하지만, 실제 처리 영상의 선택·결과 반영 시점은 달라질 수 있다. 60 fps 수준의 RGB 수신과 약 10 Hz의 신호/마커 인식을 구분한다. 조향 경로는 계속 순차 LiDAR와 엔코더/IMU 보정으로 계산한다.
5. 결과의 요청 번호·reset 세대·원래 촬영 시각·단조 수신 시각을 확인한다. 촬영 후 유효 시간과 수신 후 벽시계 제한을 유지하고, 처리 요청의 1초 watchdog을 추가한다. 결과 수신 시각으로 촬영 시각을 덮어쓰지 않는다.
6. 오래되거나 미래 시각인 결과, reset 이전 결과는 출발 연속 판정에 누적하지 않는다. 요청에는 **부모가 마지막으로 채택한 상태**를 복사해서 보내며, 자식의 미채택 상태를 다음 요청에 몰래 이어 쓰지 않는다. 시계 되감김에서도 세대를 바꾼 뒤 결과를 읽는다.
7. 작업 프로세스 사망·처리 watchdog·결과 식별 불일치·입력 형식 오류는 고장으로 고정한다. 제어기는 기존 `SENSOR_STOP` 경계로 0명령을 내보내며 단순 reset만으로 재출발하지 않는다. 노드를 정상 재시작하고 다시 출발 조건을 충족해야 한다. `/drive` → 독립 보호층 → `/drive/safe`는 그대로다.
8. 종료 시 부모가 먼저 0명령을 발행하고 작업 프로세스의 정상 종료를 기다린다. 제한 시간 내 종료하지 않으면 자식만 종료하고 이를 경고로 남긴다. 결과 수집기는 작업 프로세스 잔존까지 확인한다.

## 대안과 한계

- 같은 프로세스의 스레드는 Python 실행 간섭과 공유 상태 동기화가 남는다. 별도 ROS 영상 노드는 향후 확장에 유리하지만 현재는 추가 토픽·직렬화·상태 동기화 계약을 피하고 작은 내부 경계로 분리한다.
- 수신 콜백이 짧아졌다고 인식 계산 자체가 같은 비율로 빨라진 것은 아니다. 영상 작업 시간과 제어 콜백 시간은 따로 보고한다. CPU·메모리와 결과 반영 지연도 추가된다.
- 한 번에 한 장/최신 대기 한 장 정책은 모든 영상의 인식을 보장하지 않는다. 동일 영상·동일 순서의 판정 일치와 실제 재생의 프레임 선택·시간 차이를 구분한다.
- 고장 시 0명령 발행은 실제 모터 제동거리·MCU 고장 대응·실차 안전 인증이 아니다. 카메라/IMU 드라이버, 긴 입력·열 포화·물리 센서 시간 계약은 별도 검증한다.
