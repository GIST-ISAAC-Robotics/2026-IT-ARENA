# 결정 기록 0004: D435i 명목 사양과 고속 스트림 분리

- 날짜: 2026-08-31
- 상태: 사용자 승인에 따른 로컬 구현

## 배경

초기 기초 모델은 RGB와 같은 좁은 시야각을 공유하는 통합 RGB-D 카메라와 임시 거리·주기를 사용했습니다. 사용자가 고속 주행을 위한 RGB 60 FPS·깊이 90 FPS와 공식 사양 대조를 요청했습니다. 제공된 지도에는 약 10.3 m의 거의 직선인 구간이 있어 RGB 렌더링 거리와 깊이 유효 거리를 구분해야 합니다.

## 결정

1. RGB·깊이를 별도 Gazebo 센서로 분리하고, 기본값을 각각 848×480의 60/90 FPS로 설정합니다. 같은 주기의 결합 실험용 60/60과 저부하 30/30도 선택 가능하게 합니다. 실제 하드웨어 동기화가 활성화된 상태로 기록하지 않습니다.
2. 명목 RGB 69.4°×42.5°, 깊이 87°×58°로 각각 내부 파라미터를 계산합니다. 실제 보유 장치의 보정값이 들어오기 전까지 명목 근사임을 명시합니다.
3. 848×480의 깊이 최소 거리는 0.195 m, 시뮬레이션 최대 절단 거리는 3 m로 둡니다. 4 m는 명시적으로 바꾸는 확장 실험값이며, 사양상 정확도가 보장되는 절대 상한으로 취급하지 않습니다. RGB 렌더링 경계는 별도로 20 m입니다.
4. 기존 ROS 토픽을 유지하고 깊이 전용 `CameraInfo`를 연결합니다. `32FC1` 깊이, RGB·깊이의 미정렬 상태, 점군의 합성 회색조 `rgb` 필드 등 실물과 다른 부분을 문서화합니다.
5. 점군은 별도 지연 구독 브리지로 분리합니다. 대용량 영상의 송수신은 프로젝트 실행 범위에서 조정하고 시스템 전체 네트워크 설정은 변경하지 않습니다.
6. 공식 설정값 검증, 실제 수신 프레임률, 실제 시간 대비 시뮬레이션 진행 속도를 별도로 기록합니다. 시뮬레이터의 시간 해상도·처리 부하를 실물 센서 사양으로 혼동하지 않습니다.

## 결과와 한계

- 트랙 원본·실험 지도 형상과 차량 외형·주행 치수는 변경하지 않습니다.
- 해상도별 사양과 수평·수직 시야각을 다루지만, 실물의 렌즈 보정·스테레오 오차·노출·롤링 셔터·시간 지연은 아직 재현하지 않습니다.
- 시뮬레이션에서 정답 위치·이상적 IMU 자세를 얻을 수 있다는 사실은 대회용 자율주행 입력으로 사용해도 된다는 뜻이 아닙니다.
- 고속 기본값은 현재 PC의 실시간 60/90 FPS 처리를 보장하지 않습니다. 정밀한 시간 동기화·지속 점군 처리량과 Jetson의 실제 성능은 별도 검증 항목입니다.

출처, 실행 선택, 거리 해석과 검증 절차는 [D435i 사양과 시뮬레이션 설정](../sensors/D435I_SIMULATION.md)에 있습니다.
