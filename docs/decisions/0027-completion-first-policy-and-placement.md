# ADR 0027: 첫 완주 우선 정책과 센서 배치 재검토

- 날짜: 2026-10-27 (KST)
- 상태: 아래 사용자 결정은 현재 개발 기준이다. 구체적인 제어 임계값·최종 장착 치수·실행 프로필은 구현·검증 전이다.
- 출처: 10/27 저장소 재검토 대화의 사용자 후속 지시. 공식 규정은 별도 원문으로 구분한다.
- 관계: [ADR 0020](0020-b0183-c1-procurement-baseline.md)·[0021](0021-local-path-pure-pursuit.md)·[0022](0022-b0183-c1-local-pursuit-prototype.md)·[0026](0026-motor-shaft-encoder-baseline.md)의 당시 선택·실험은 보존하며 아래 범위만 갱신한다.

## 1. 사용자와 팀이 결정한 것

| 항목 | 현재 결정 | 이 결정의 범위 |
|---|---|---|
| 구매 부품·구동 방식 | 이미 구매한 센서와 구동 방식을 유지한다. B0183·C1·LSM6DSOX, 브러시 DC 모터·MD20A, 단일 모터축 엔코더 등 구매 구성은 재선정 대상이 아니다 | 품목별 수령·조립·실물 성능은 확인 전 |
| 센서 배치 | 높이·전후 위치·피치·지지 구조는 설계 과정에서 변경할 수 있다. 기구 설계는 아직 본격적으로 확정되지 않았다 | C1 높이 95 mm·전방 60 mm·후방 60° 가림이나 수평 카메라는 실물 고정 요구가 아님 |
| 제어기 | 지역 경로 + Pure Pursuit는 현재 개발 수단이며 필요에 따라 바꿀 수 있다 | PP를 영구 제약으로 두지 않음. 전면 교체 결정은 아님 |
| 우선 목표 | 첫 완주를 우선한다. 경미한 접촉 가능성까지 없애려다 진행을 못 하는 정책은 재검토한다 | 의도적인 접촉을 주행 수단으로 삼지 않으며 접촉 결과는 따로 기록 |
| 잔디 | 두 바퀴까지 활용한다. 충돌이 임박한 경우에는 세 바퀴 이상 잔디 진입의 페널티를 감수하는 쪽을 충돌보다 선호한다 | 상시 세 바퀴 이상 주행, 벽 충돌·전복 위험, 복귀 불가능한 회피를 포괄 승인한 것은 아님 |
| 측방 간격 | 종전의 일률적인 큰 간격을 고정 요구로 삼지 않는다. 지나치게 엄격한 조건을 완화하는 방향을 유지한다 | 새 고정 최소 간격 수치는 미정 |
| 무반환 | ±100° 안의 유효 반환이 하나라도 빠지면 멈추는 일률적 정책은 재검토한다. 소수 결측과 큰 관측 공백을 구분한다 | 무반환을 무조건 빈 공간으로 바꾸거나 임의의 N개까지 안전하다고 확정하지 않음 |
| 노면 평가 | 차체 전체가 항상 도로 안에 있어야 한다는 개발·평가 조건은 경기 정책에서 수정한다 | 차체 외형과 회전 시 차체가 지나가는 공간의 충돌 검사는 유지 |
| 속도 | 약 15 km/h를 목표 상한으로 검토한다. 보통 주행이 9 km/h인 것은 허용하며 센서·처리·차량 성능이 부족하면 낮춘다 | 즉시 모든 경로에 4.167 m/s를 명령하거나 실차 도달 성능을 보장한 것은 아님 |
| 기보유품 | 주요 부품을 예산에 포함하는 현재 팀 방침에 따라 기보유품을 사용하지 않는다 | 오래된 공개 댓글을 근거로 기보유 센서를 새 대안에 다시 넣지 않음 |
| 카메라 기구 | 높이·피치 가변 기구를 필수 요구로 두지 않고, 시뮬레이션에서 배치를 비교해 고정 마운트를 정하는 방향을 우선한다 | 최종 높이·피치는 미정 |
| 문서 | 누적된 현재 상태·과거 결과·임시 제약을 정리한다 | 과거 실패·원시 근거·당시 조건을 새 정책의 성공으로 바꾸지 않음 |

후방 마커를 위로 옮겨 C1 측정 높이를 비우는 것은 사용자 제안이며 배치 변경 범위 안이다. 정확한 높이·지지대·카메라 간섭은 기구 도면에서 결정한다. 후방 전체를 보지 않는 복귀 정책의 구체적인 수용 조건은 이번 대화로 자동 확정하지 않는다.

## 2. 공식 규정과 개발 가정의 구분

- **공식:** 두 바퀴까지 잔디 무벌점, 세 바퀴 이상 진입 시 페널티와 장시간 주행의 심판 재량. 차량 외형 20×15×40 cm 이내, 후방 5×5 cm 마커, 온보드 연산·시각 출발 신호·HW/SW 정지 요구. [공식 MANUAL 고정본](https://github.com/MOSW626/istech-it-arena/blob/d8107de6ccff14ae17db7fb08732b55fed82b5b4/MANUAL.md), [규정 확인 목록](../HARDWARE_AND_RULE_QUESTIONS.md).
- **사용자/팀:** 위 표의 구매 고정·배치 자유·기보유품 미사용·잔디와 충돌의 우선순위·15 km/h 목표. 공개 문서와 별도로 전달된 결정도 출처를 사용자 확인으로 기록한다.
- **개발 가정:** ±100°의 모든 반환 유효 요구, 모든 방향 15 cm, 차체 전체 도로 안, 97/115 mm 합산 예산, 9 km/h 상한, 후방 60° 마스크, 출발 전 빨강 네 열 관측 조건 등. 코드·시제품·시험마다 적용 범위가 다르며 공식 요구로 취급하지 않는다.
- **실측:** 시뮬레이션·핀홀 기하·판매 사양·선형 모터 계산은 실차 실측과 구분한다. 실제 센서 시각·제동·그립·장착은 확인 전이다.

공개 규정에서 일반 접촉과 공격의 세부 구별, 복귀 차량과 후방 차량의 책임을 확정하지 못했다. 충돌보다 잔디를 선호하는 팀 정책을 뒤차 양보에 관한 공식 판정으로 확대하지 않는다.

## 3. 개발 권고와 아직 결정하지 않은 상세

### 관측과 진행성

결측 개수만 세지 않고 연속 각도 폭, 주행·제동 경로와의 겹침, 가까운 기존 장애물, 최근 유효 관측과 경과 시간을 함께 쓰는 방향을 권고한다. 작은 결측 때문에 항상 정지하지 않는 운영 정책을 설계하되 추정·미관측·관측을 구별한다. 관측이 불완전한 상태에서 진행을 허용하는 것은 잔여 위험을 수용하는 정책 변경이며 데이터 이름만 바꾸어 해결됐다고 하지 않는다.

기존 필요한 이동 외곽 검사와 최근 광선 보완도 43 m 지점에서 실패했다. 검사 범위를 줄인다는 말만으로 새 해결책을 주장하지 않는다. 실패와 반례는 [10/24 결정 자료](../autonomy/OBSERVATION_DECISION_BRIEF_2026_10_24.md), [10/21 관측 계약](../autonomy/G1_OBSERVATION_CONTRACT_2026_10_21.md)에 남긴다. 정확한 결측 허용 폭·시간·속도와 알려진 위협 처리 방식은 후속 구현에서 명시한다.

### 노면·측방·복귀

차체–장애물 충돌 검사와 바퀴–노면 페널티 평가를 나눈다. 기본 보호층 전체가 도로 경계를 강제하는 구조는 아니며, 기존 평가기·`road_only` 경로 후보와 `two_wheel_grass` 측방 시제품이 공존한다. 세 바퀴 이상 긴급 회피는 아직 없다. 경로 후보·선택·평가기까지 새 정책에 맞춰야 한다.

불필요한 중앙 복귀를 줄이고 관측한 옆차·최근 위협·뒤 모서리 이동 영역을 고려하는 방향을 권고한다. 후방 미관측 전체가 비어 있음을 매번 증명하도록 할지, 어느 움직임에서 어떤 잔여 위험을 수용할지는 상세 정책 검토가 남는다. 좁게 서 있는 그리드의 출발과 주행 중 새로 간격을 좁히는 행동도 구분한다.

### 속도와 방지턱

현재 코드의 `local_fast` 상한은 2.5 m/s(9 km/h)다. 15 km/h는 4.167 m/s 목표이며, [15:1·65 mm 구동 계산](../hardware/DRIVETRAIN_GEARING_2026_10_02.md)에서도 공칭 전압·무부하 약 13.6 km/h로 계산되어 구동 여유를 따로 확인해야 한다. 감속비 변경은 이번에 결정하지 않았다.

방지턱은 검출기부터 새로 만들기보다 기구 통과·관측 변화·저속 통과 범위를 먼저 확인하는 방안을 권고한다. 카메라 검출 채택 여부는 미정이다. 기본 실행은 방지턱 비활성이며 공개 450×50×10 mm 형상의 정적 기하 결과를 동적 통과 성공으로 쓰지 않는다.

### 카메라와 가림

고정 마운트 후보는 높이·전후 위치·피치·영상 ROI를 함께 비교한다. 공식 6그리드와 마커 접근에 자차·앞차 가림, 차체 기울기를 포함한다. 상대차 자료가 없으면 시험용 높이·형상을 가정으로 표시한다.

코스 마커가 가려져도 바로 정지하거나 잘못된 벽으로 바꾸지 않도록 경로 선택을 검토한다. 현재 코드는 ID 30에서 오른쪽 벽, ID 0/20/45에서 왼쪽 벽을 선택하므로 카메라를 신호등 전용으로 쓰려면 이 역할을 대체해야 한다.

출발 후보의 빨강 네 열 사전 확인은 공식 규정 자체가 아니라 검출 정책이다. **빨강이 앞차에 가림 → 앞차 이동 → 초록만 노출** 상황을 추가 검토한다. 앞차의 움직임만을 자기 차량의 출발 신호로 삼지 않으며 초록만 새로 보았을 때 필요한 영상 근거는 후속 설계 대상이다.

## 4. 반영 상태

이번 변경은 현재 기준·계획·문서 안내의 정리다. 실행 코드·센서 좌표·9 km/h 설정·안전 임계값·노면 판정기를 바꾸거나 새 주행을 실행한 결과가 아니다. 구현 순서는 [현행 개발 계획](../DEVELOPMENT_PLAN.md), 하드웨어 전달 항목은 [확인 목록](../HARDWARE_AND_RULE_QUESTIONS.md), 실제 완료 범위는 [현재 현황](../PROJECT_CONTEXT.md)을 따른다.
