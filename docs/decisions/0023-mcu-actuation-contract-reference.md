# ADR 0023: MCU 속도 제어·정지 계약의 PC 참조 구현

- 날짜: 2026-09-22
- 상태: 사용자 역할 분담을 반영한 **PC 참조 구현·시험 완료**. 실물 보드/ESC·최종 전송 형식·펌웨어는 미확정이다.
- 선행: [ADR 0002](0002-jetson-esp32-actuation-boundary.md), [ADR 0008](0008-single-motor-mechanical-differential.md), [전체 계획 A1](../reports/DEVELOPMENT_PLAN_2026_09_22.md).

후속: 선택형 [A1-2 ROS/가상 MCU 연결](../hardware/ACTUATION_ROS_2026_09_22.md)의 ROS 14조건·Gazebo 부분 주행/정지 두 경우·전체 회귀 365개를 통과했다. 아래 A1-1 당시의 비연결 결정/근거는 보존한다. 기본 legacy, 기존 모터 PI/물성/제어기 및 공식 원본은 유지한다.

## 결정

1. 사용자 설명에 따라 MCU는 **ESP32-S3 우선 후보**, 적어도 Arduino/ESP32 계열 보드를 검토한다. Jetson은 목표 속도/조향각을 만들고, MCU가 엔코더 피드백으로 단일 모터 속도를 제어하는 분담을 기준으로 한다. BLDC 정류는 호환 ESC에 맡기며 MCU 직접 FOC는 범위 밖이다.
2. 부품이 없는 첫 작업은 A1 전체를 한 번에 완료했다고 하지 않고 **A1-1: 명령·피드백·정지 상태 계약과 보드 없는 실행 검증**으로 한정한다. GPIO/ESC 드라이버·무선 STOP·ROS 구동 경로 삽입은 별도 단계다.
3. 보드에 종속되지 않는 Python 참조 수신기와 호스트 생산기, 길이/CRC32 프레이밍, 단일 모터 PI 예제를 제공한다. 이후 C++ 펌웨어 포팅 때 같은 실패 시나리오/참조 결과를 대조한다. Python 코드를 그대로 ESP32에 올린다는 뜻이 아니다.
4. MCU 부팅 기본값은 구동 금지다. `ARM`은 신호등 출발이 아니라 출력 허가이며, 실제 출발 신호 판단은 Jetson에 남긴다. STOP·명령 만료·엔코더/제어 주기 고장은 정지 상태를 고정한다. 정지 해제 `CLEAR`와 구동 허가 `ARM`은 별도이며 둘 다 신선한 엔코더 저속 지속 관측을 요구한다.
5. MCU 부팅 ID·상태 세대·호스트 ID·증가 순번으로 과거 명령/재부팅을 구분한다. MCU가 발행한 짧은 유효기간 토큰과 호스트 원래 명령 나이로 만료를 제한한다. 통신 수신이나 상태 조회만으로 모터 제어 주기 감시를 갱신하지 않는다.
6. 초기 USB 유선 연결을 우선 제안하지만 통신 하드웨어/핀/baud는 확정하지 않는다. CRC/토큰은 암호학적 인증이 아니다. 무선 정지 링크와 실제 전기적 구동 차단은 별도 안전 경로다.
7. 기존 지역 Pure Pursuit·LiDAR 보호층·코스 실행 경로·물성·속도는 변경하지 않는다. 다음 A1-2에서 `/drive/safe` 뒤에 어댑터를 연결하고 명령/노드 재시작·시뮬/실시간 시계 경계를 검증해야 한다. MCU 내부 엔코더 오차의 실차 영향도 아직 검증하지 않았다.

## 근거와 한계

[구동 계약·검증 보고서](../hardware/ACTUATION_CONTRACT_2026_09_22.md)에 필드·상태·유효기간, 시나리오 11개/단위 38개/전체 회귀 340개와 남은 작업을 정리했다. 단순 종방향 가상 모터의 정지 결과를 Gazebo/실차 제동거리나 ESP32 실행 성능으로 승격하지 않는다. 실제 부품이 정해지면 임시 제어 주기·엔코더 분해능·게인·만료 한도를 실측으로 교체한다.
