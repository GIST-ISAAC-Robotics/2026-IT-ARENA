## 조건

## 현재 상태 · 다음 단계

사용자가 CH1 재연결·무명령 정지를 확인한 뒤 같은 USB 세션에서 `powered_5pct_250ms_1` 요청을 한 번 발행했다. duty 50‰(실제51/1024), 지속250 ms다. MCU 기록의 시작235,024,655 µs, 마감235,274,655 µs, 종료235,274,746 µs로 **마감+91 µs에 PWM0**이며 종료 readback PWM/DIR0·active/armed=false다. PCNT/software count·A/B 상승/하강·ISR edge 변화는 모두0, invalid/ring drop 증가0이다. 사용자가 첫 짧은 시험은 보지 못했다고 답했으므로 이 첫 회차의 육안 회전/정지는 미확인으로 보존한다.

사용자가 더 오래 관찰하기를 요청해 동일 출력으로500 ms 구동·약3.5초 PWM0 간격을5회 반복했다. 사용자 응답은 **“매번 돌아가고 멈추는 것을 봄”**이다. 반복별 MCU 마감 초과는43/30/30/30/30 µs, 매회 종료 PWM0·허가 해제, 엔코더 PCNT/software/ISR·A/B 상승/하강 변화0이었다. 총 실전원 명령6회 중 육안 확인은 후반5회이며 펌웨어 사전 검사2회는 전원 분리 시험으로 구분한다.

이 결과는 고정한 단독 모터의 제한 출력 회전과 PWM0 구간 정지를 관찰한 것이다. MD20A 진리표상 PWM0은 단락 제동이지만 관찰만으로 coast 대비 감속 향상이나 제동 토크·정지 시간/거리·정지 축 유지 토크를 검증하지 않는다. 엔코더가 실제 회전 때도0이므로 저속 손 회전만의 문제로 보지 않고 엔코더 전원 전달/접촉/CF/실제 GPIO 경로를 이어서 확인해야 한다.


사용자가 각 PWM0 구간의 정지와 **CH1 분리 완료**를 확인했다. 그 뒤 `STOP` 파일→`X` 응답으로 active/armed=false·PWM0·포트 close를 확인하고, 장치 소유자0과 기존 root:dialout 0660 유지까지 확인했다. 이 최초 시험 종료 당시에는 **motor_probe_v1 대기 상태**를 남겼고 이전 IMU 앱은 복구하지 않았다. 최신 상태는 아래 재시험 종료 기록을 따른다. 추가 시험 전 현재 앱 종류와 모터 전원을 다시 확인한다.

독립 감사는 raw UART와 JSONL **48,816프레임 전체 일치**, 상태24,377개·motor24,403개·CRC 오류0·sequence 공백0·boot1·invalid/ring drop/송신 오류0을 확인했다. 전체 edge frame은2개다. 이 두 에지는 **첫 실제 구동 전 대기 중 A의 상승/하강 한 쌍**, ISR 기록 간격7 µs·순계수0이며 원인은 미확인이다. 호스트 phase 이름은 물리 전원 상태 센서가 아니므로 당시 CH1 연결 여부를 자동 판정하지 않는다. 실제 구동6회 구간의 edge/count 변화0과 구분하며 이 한 쌍을 정상 회전 신호로 채택하지 않는다.

### 구동 이후 배선 해체 구간의 별도 이상

전체 UART55,197프레임은 JSONL과 일치하며 CRC/sequence 공백0·boot1·송신 오류0이다. 그러나 **마지막 PWM 종료281.538255초 뒤**, MCU431.164953~474.672361초의 대기 중 추가1854에지가 계수됐다. 저장 edge frame1584개·ring drop270개·invalid3회·순계수+3이며 이 구간 motor 기록은 모두 inactive/PWM0이다. 따라서 구동4회 구간의 정상과 전체 세션의 무잡음을 혼동하지 않는다.

최초 전구간 에지 연속성 감사는 실제 누락 때문에 실패했다. 실패와 원문을 보존한 뒤 구동 구간과 후반 구간을 따로 감사했으며 전체 실패를 삭제하거나 판정선을 통과로 바꾸지 않았다. **사용자 후속 설명: 엔코더·모터 쪽 연결은 모두 제거했고 ESP32 쪽은 유지했다.** 개별 선과 분리 시각을 기록하지 않았으므로 추가 신호를 정상 배선 상태의 모터 EMI나 특정 부품 고장으로 확정하지 않는다. 전원/신호 해체 중 입력 부유에 의한 가능성이 있으며 실제 회전/속도로 해석하지 않는다.

### 종료와 접지 배선 판단

사용자가 처음에는 CH1 연결을 유지하겠다고 하여 포트를 유지했다. 이후 종료 지시와 CH1 분리 완료 응답을 받고 `STOP`→`X`로 PWM0·허가 해제·포트 close를 확인했다. 원래 IMU app1 MiB를 복구하고 readback SHA `eaf5c5493a2f8b4b1ec69b9eb1e867fd57d172662e72f6861a56bdc15d0df6ae` 일치, IMU 프로토콜18프레임·inactive 상태3개·포트 소유자0을 확인했다. 사용자가 종료를 요청한 뒤 추가 구동이나 GND 제거 비교는 하지 않았다.

사용자의 GND 핀 부족 질문에는 엔코더 CH4−/GND와 ESP32/CF의 공통 기준 연결을 유지하도록 권고했다. 별도 ESP32 GND 핀을 하나 더 소비할 필요 없이 신호 GND 분배점을 사용할 수 있다. MD20A·전원 보드를 경유한 간접 공통 경로의 실제 도통은 미확인이고, 해당 경로에 의존하면 CH1 등 커넥터 분리 시 기준이 끊길 가능성이 있으므로 분기 제거를 확정하지 않았다. 모터 전력 귀환은 기존 CH1−→MD20A VB−의 전력 배선을 유지하고 센서 점퍼/MCU 헤더를 통과시키지 않는다.
