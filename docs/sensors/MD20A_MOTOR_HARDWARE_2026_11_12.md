# MD20A · MB4266 최초 단발 모터 시험

2026-11-12, GPT가 워커 없이 수행한다. **현재: 약5%·500 ms를 5회 반복했고 사용자가 매번 회전/정지를 육안 확인했다. MCU는 각 PWM0 종료를 확인했으나 엔코더는 전 구간0이다. 모터 단독 구동/정지 관찰과 엔코더 입력 실패를 구분한다. CH1 분리·통신 종료·원문 독립 감사를 마쳤고 전압은 사용자 요청으로 미측정이다.**

## 조건

- [엔코더 손 회전](PGE213_ENCODER_HARDWARE_2026_11_12.md)에서 입력 에지0과 CF B1/B2 LOW를 관측한 뒤 사용자가 실제 모터 회전 시험을 요청했다. 엔코더 미검출 실패를 정상으로 바꾸지 않는다.
- 사용자가 기존 CH01 배터리 전원에 연결했다고 보고했다. 현행 [배선](../hardware/ESP32_GPIO_WIRING_2026_11_11.md)의 M01 CH1→MD20A로 이해한다. 이후 요청에 따라 CH1을 분리했고, 축에 연결된 부품이 없음·본체 고정·축 주변 비움·HA/HB→CF B1/B2 재연결을 확인했다.
- 첫 실제 구동은 사용자가 요청한 낮은 출력과 PWM0 제동 확인에 맞춰 **약4.9805%(51/1024), 250 ms, DIR LOW** 한 번으로 준비했다. 전류·회전 속도 제한을 뜻하지 않는다. 제어 프로그램은 무회전을 이유로 자동 증가시키지 않는다.
- PWM15/DIR6, 엔코더4/5, UART0 921600 8N1. IMU는 기존 사용자 확인상 분리, 서보에는 명령을 보내지 않는다. 운영 속도 제어/ROS 경로는 변경하지 않는다.

## MCU 사전 검사 · 모터 전원 없음

별도 [`firmware_motor_probe`](../../src/arena_vehicle_interface/firmware_motor_probe/README.md)를 기존 ESP-IDF v6.1에서 빌드하고 app 주소 `0x10000`만 업로드했다. app SHA-256은 `6b2d0117e52824cc2b9462d2fe845393c873219486712463482460b8d7d2bd73`다. 직전 엔코더 앱 partition 1 MB를 백업했으며 SHA-256은 `a5d2b19cba9bf306106a63f2248147c8a2e03e9c56c21740ed11c76f1c436f79`다. bootloader/partition/NVS를 변경하지 않았다.

첫 호스트 v1/`session_v1`은 ROM 부팅 바이트와 첫 info 프레임이 같은 줄에 있어 identity 조회 timeout으로 실패했다. 구동 명령0, 종료 때 active/armed=false·PWM readback0·포트 close를 확인했다. raw/소스/실패는 보존했다. 호스트 v2는 부팅 시에만 CRC 유효 프레임 앞의 접두부를 분리하도록 수정했고 관련 파서3검사를 통과했다. MCU 앱은 변경하지 않았다.

`session_v2`에서 부팅 접두부684바이트를 기록했고, 다음 사전 검사를 통과했다.

| 항목 | 결과 |

| ARM 없는 PULSE·다른 boot | 거절·PWM0 |
| 100‰ 초과 duty·500 ms 초과 지속시간 | 거절·PWM0 |
| 2초 ARM 만료·잘못된 CRC·미완성 줄 timeout | 거절·허가 해제·PWM0 |
| 50‰·250 ms 단발, 후속 정지 명령 없이 대기 | MCU 타이머가 마감+30 µs에 출력 종료 |

두 PWM 시험은 모터 전원 없는 논리 출력 시험이다. 물리 PWM 파형·드라이버 출력·회전/제동 성능을 측정했다는 뜻은 아니다. UART 처리와 분리한 `esp_timer`의 이번 종료 지연은 모든 조건의 최악 지연 보증이 아니다.

## 현재 상태 · 다음 단계

사용자가 CH1 재연결·무명령 정지를 확인한 뒤 같은 USB 세션에서 `powered_5pct_250ms_1` 요청을 한 번 발행했다. duty 50‰(실제51/1024), 지속250 ms다. MCU 기록의 시작235,024,655 µs, 마감235,274,655 µs, 종료235,274,746 µs로 **마감+91 µs에 PWM0**이며 종료 readback PWM/DIR0·active/armed=false다. PCNT/software count·A/B 상승/하강·ISR edge 변화는 모두0, invalid/ring drop 증가0이다. 사용자가 첫 짧은 시험은 보지 못했다고 답했으므로 이 첫 회차의 육안 회전/정지는 미확인으로 보존한다.

사용자가 더 오래 관찰하기를 요청해 동일 출력으로500 ms 구동·약3.5초 PWM0 간격을5회 반복했다. 사용자 응답은 **“매번 돌아가고 멈추는 것을 봄”**이다. 반복별 MCU 마감 초과는43/30/30/30/30 µs, 매회 종료 PWM0·허가 해제, 엔코더 PCNT/software/ISR·A/B 상승/하강 변화0이었다. 총 실전원 명령6회 중 육안 확인은 후반5회이며 펌웨어 사전 검사2회는 전원 분리 시험으로 구분한다.

이 결과는 고정한 단독 모터의 제한 출력 회전과 PWM0 구간 정지를 관찰한 것이다. MD20A 진리표상 PWM0은 단락 제동이지만 관찰만으로 coast 대비 감속 향상이나 제동 토크·정지 시간/거리·정지 축 유지 토크를 검증하지 않는다. 엔코더가 실제 회전 때도0이므로 저속 손 회전만의 문제로 보지 않고 엔코더 전원 전달/접촉/CF/실제 GPIO 경로를 이어서 확인해야 한다.


사용자가 각 PWM0 구간의 정지와 **CH1 분리 완료**를 확인했다. 그 뒤 `STOP` 파일→`X` 응답으로 active/armed=false·PWM0·포트 close를 확인하고, 장치 소유자0과 기존 root:dialout 0660 유지까지 확인했다. 보드에는 **motor_probe_v1 대기 상태**가 남으며 이전 IMU 앱은 복구하지 않았다. 추가 시험 전 현재 앱 종류와 모터 전원을 다시 확인한다.

독립 감사는 raw UART와 JSONL **48,816프레임 전체 일치**, 상태24,377개·motor24,403개·CRC 오류0·sequence 공백0·boot1·invalid/ring drop/송신 오류0을 확인했다. 전체 edge frame은2개다. 이 두 에지는 **첫 실제 구동 전 대기 중 A의 상승/하강 한 쌍**, ISR 기록 간격7 µs·순계수0이며 원인은 미확인이다. 호스트 phase 이름은 물리 전원 상태 센서가 아니므로 당시 CH1 연결 여부를 자동 판정하지 않는다. 실제 구동6회 구간의 edge/count 변화0과 구분하며 이 한 쌍을 정상 회전 신호로 채택하지 않는다.

[공개 집계·독립 감사](../../artifacts/validation/2026-11-12/md20a_motor_bench_v1/README.md)에 범위와 결과를 모았다. 원시 묶음 SHA-256은 `0363a50ff11c5a4d08726f95682a10fae7e5ecbd6a54d7dda129551f2b8a8a70`이며 원격/로컬 일치를 확인했다.
