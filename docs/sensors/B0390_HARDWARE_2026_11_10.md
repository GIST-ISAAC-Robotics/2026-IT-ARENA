# B0390 실물 카메라 입력 검증 — 2026-11-10

## 범위와 연결

사용자 요청으로 실물 이관을 시작했다. 납품된 B0390의 카메라 자체 CSI는 **22핀**, 연결 케이블은 **22↔22 FPC**라고 사용자가 확인했다. 기존 15↔22 현재 연결 표기를 정정했다. 초기 위임은 사용자 지시로 중단했으며, 이후 GPT가 직접 접속·설정·취득·검토했다. 모터·서보·주행 명령은 실행하지 않았다.

저장된 DPAPI 자격 증명과 기존 SSH 호스트 키를 이용해 접속했다. `.local` 이름이 공인 주소로 해석되어 시간초과가 났으나, 현재 Wi-Fi 이웃 목록에서 찾은 숫자 주소의 키가 저장된 키와 일치함을 확인한 뒤 접속했다. 비밀번호·현재 사설 주소·실내 영상은 이 공개 문서에 저장하지 않는다. 접속법은 [Jetson 접속 문서](../hardware/JETSON_ACCESS.md)를 따른다.

연결 포트를 사전에 확정하지 못해 기본 제공 Dual 구성을 사용했다. 비연결 쪽 `imx219 10-0010`의 부팅 시 I2C probe `-121`은 별도로 기록한다. 이것을 연결된 센서의 연속 수신 오류로 합산하거나 삭제하지 않는다. 보드의 CAM0/CAM1 실크와 Argus 순번의 대응은 현물 대조 전까지 확정하지 않는다.

원본 `/boot/extlinux/extlinux.conf`를 `/boot/extlinux/extlinux.conf.before-b0390-20261110`에 백업하고 양쪽 SHA-256 `6f0058726d34211f177eb09e1883ab68edb244a89831c706d43952c3ddab54b2` 일치를 확인했다. Jetson-IO가 기존 `primary` 부팅 항목을 보존하고 `JetsonIO` 기본 항목에 NVIDIA 제공 `tegra234-p3767-camera-p3768-imx219-dual.dtbo`를 추가했다. 새 extlinux SHA-256은 `03594241d45e8db889295959b9d1316cdce9073efbcdf1cbe66da971d3f57c1b`이다. 커널·JetPack·드라이버 패키지 교체는 하지 않았다.

원상복구가 필요하면 백업 해시와 현재 diff를 확인하고 원래 `primary` 부팅 항목을 선택하거나 extlinux 백업을 복원한 뒤 재부팅한다. 현재 정상 수신이 확인된 구성은 유지한다.

## 센서 모드와 측정 방법

Argus가 노출한 실제 모드는 3280×2464/21, 3280×1848/28, 1920×1080/30, 1640×1232/30, **1280×720/60 fps**다. 이번 선택은 **mode 4의 1280×720/60**, 출력은 NV12(NVMM) → `nvvidconv` BGRx → `videoconvert` BGR → appsink다. 출력 크기와 센서 active 크기가 모두 1280×720이며 `videorate`·프레임 복제·의도적 drop은 없다. 센서 내부 크롭/비닝과 실효 화각은 별도 검증이 필요하다.

[`probe_jetson_camera.py`](../../scripts/probe_jetson_camera.py)는 source pad와 BGR appsink의 PTS/수신 단조 시각을 분리한다. appsink는 `sync=false max-buffers=8 drop=false`다. 워밍업 5초 뒤 최소 300초 동안 모든 BGR 프레임의 CRC32·PTS·간격과 온도를 기록하고 대표 첫/마지막 프레임을 보관한다. PNG 인코딩·저장은 연속 측정 후 수행해 저장 비용을 수신 간격에 넣지 않는다. Jetson 내부 측정으로 SSH 전송 속도를 배제했다.

사전 기본 기준은 평균 59.4 fps 이상, 300초 이상 연속 측정, 수신 timeout/파이프라인 오류/재시작/PTS 역전/동일 CRC32 연속 프레임 없음, source와 sink PTS열 일치, EOS·NULL 정상 종료다. 프레임 간격의 긴 꼬리는 별도로 보고하며 평균 통과가 순간 지연 0을 뜻하지 않는다.

**시각의 한계:** 설치 플러그인은 `do-timestamp=true`이며 여기서 측정한 것은 Gst source PTS다. Argus sensor timestamp/capture ID/노출 시작 시각을 직접 취득한 시험이 아니다. PTS와 원천 순번이 센서 내부 누락을 완전히 증명한다고 주장하지 않는다. source→sink 시간도 노출→인식 전체 지연이 아니다.

## 결과와 한계

**기본 취득 통과:** 워밍업 5초를 제외한 300.014563초에 18,016프레임, Gst PTS 60.047025 fps·BGR 수신 60.047085 fps였다. 오류/경고/재시작/연속 동일 CRC32/PTS 역전은 0, source와 sink PTS열은 전부 일치했고 EOS·NULL 정상 종료했다. 수신 간격 p99 19.475797 ms·최대 26.577298 ms이며 25 ms 초과는 3회, 33.333333 ms 초과는 0회다. 완전히 일정한 간격이나 센서 내부 무손실 판정은 아니다. CPU 최대 49.5°C, 보드 입력 전력 평균 6.629 W였다. 자세한 집계와 실패 보존은 [검증 산출물](../../artifacts/validation/2026-11-10/b0390_hardware_camera_v1/README.md)을 따른다.

최초 120프레임의 기본 Argus 수신은 정상 종료했다. 계측기 v1/v2는 GPU 열 센서 sysfs를 읽는 Python `TypeError`로 각각 측정 1프레임 뒤 중단했다. 카메라 오류가 아닌 계측 오류로 보존하고 온도값 미제공 예외 처리를 보완했다. v3 짧은 5초 측정은 302프레임, source PTS 60.023 fps·호스트 수신 60.017 fps, source/sink PTS 일치·오류 0·정상 종료였다.

사용자는 시험 도중 카메라가 한동안 바닥을 향해 있었고 벽 쪽으로 돌렸다고 알렸다. 초기 어두운 장면과 방향 변경이 포함된 실내 시험이다. 마지막 벽·근접 케이블 영상을 직접 확인했으며 원본 PNG·CSV는 Git 제외 경로에 보관했다. 노출·아날로그 게인 실측값과 색상표·초점·왜곡·화각·움직이는 신호/마커·ROS 촬영 시각·전체 인식 파이프라인은 이번 기본 취득 시험으로 검증하지 않았다. 다른 센서·모터·서보의 실물 이관도 남아 있다.
