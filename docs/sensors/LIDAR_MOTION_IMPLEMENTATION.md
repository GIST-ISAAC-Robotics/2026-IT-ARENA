# 엔코더·자이로 기반 회전식 LiDAR 보정 구현·시험

작성: 2026-09-08. **이번 구현·시험 종료**. 독립 직선 20 km/h 결합 보정은 통과했으나 공식 코스는 최고 12.38 km/h였고 종료 검증은 미통과입니다. 과거 순차 무보정 기준선과 실물 성능을 구분합니다.

## 구현 범위

- 공통 평면 보정 계산: `src/arena_autonomy/arena_autonomy/lidar_motion.py`.
- ROS 입력/진단: `src/arena_autonomy/arena_autonomy/lidar_motion_ros.py`.
- 입력은 취득 시각이 있는 좌우 후륜 엔코더와 IMU 각속도입니다. 정확한 Gazebo 위치·자세,
  이상적인 `/odom`, 지도, 조향 명령을 이동 추정 입력으로 사용하지 않습니다.
- `none / deskew / shift / both` 선택형이며 기존 기본값은 none입니다.
- 출력은 원래 점 인덱스에 대응하는 XY 배열입니다. 원시 `/scan`을 덮어쓰거나
  보정 결과를 균일 각도 `LaserScan`으로 다시 만들지 않습니다.
- 상대차 운동·슬립 추정·절대 자기 위치·방지턱 3차원 보정·실물 자동 교정은 미구현입니다.

구체적 시간·좌표·공백/외삽 계약은 [ADR 0018](../decisions/0018-sensor-based-lidar-motion-compensation.md)에 있습니다.

## 사용 예

```bash
# 일반 본선 데모: 기존 신호/마커·ToF 보호와 저속 정책 유지
ros2 launch arena_bringup demo.launch.py headless:=true lidar_acquisition:=sequential lidar_compensation:=both

# 독립 고정 속도 시험: 일반 데모와 달리 ToF 해제, 빈 시험장
python3 scripts/validate_lidar_control_lab.py --case straight_5kmh --rate 10 \
  --acquisition sequential --compensation both --render-backend software \
  --output artifacts/validation/새로운_보정_시험

# 같은 조건 행렬. snapshot은 snapshot_matched+none이며 나머지는 sequential이다.
python3 scripts/run_motion_comparison.py --output artifacts/validation/새로운_보정_행렬
```

`motion_scan_timing_verified`는 실물에서는 기본 false입니다. 시뮬레이션의 시간 계약
확인을 실물 C1 검증으로 승계하지 않습니다. `motion_gyro_bias_rad_s`, `motion_wheel_scale`,
장착 파라미터와 허용 입력 시간 간격은 측정 후 설정하며, 동작을 보기 좋게 만드는
임의 보정 강도 계수가 아닙니다. 현재 IMU 잡음·온도/진동 모델은 이상화 상태입니다.

초기 이동 추정은 필터 융합이 아니라 구간별 직전값 유지입니다. 엔코더 각속도는
현재 `JointState` 시각까지의 이전 계수 구간 평균이므로 순간 속도와 같지 않습니다.
이를 임의로 미래로 당기거나 정답 속도에 맞춰 배율을 학습하지 않았습니다. 가감속·슬립,
실물 timestamp 지연·자이로 바이어스·평면 가정 위반에서 남는 오차는 후속 측정 대상입니다.

## 실행별 근거

완료한 스모크와 행렬 원문은 `artifacts/validation/2026-09-08/lidar_motion/` 아래 새 폴더에
보존합니다. `report.json`, `commands.jsonl`, `motion_inputs.jsonl`, `scans_raw.jsonl`,
물리 평가 trace, 획득/프로세스 종료 감사와 소스 해시를 분리합니다.

첫 기하·시간/기존 검사 21개, 이후 일반 제어·ROS 경계 198개, 영상 시간/실행 인수와
오프라인 감시 경계까지 추가한 전체 206개를 통과했습니다.
IMU의 측정 없음 표시에서 numpy.bool_가 JSON에 기록되지 않는 오류도 고장 입력 검사로
찾아 Python bool로 변환했습니다. 실패 XML은 보존하고 재통과 XML은 v2,
역방향 각도·빈 점군·이력 회복 등을 추가한 198개 결과는 v3로 구분했습니다.
v4는 tests 폴더만 검사한 196개이고, src 아래 차량 인터페이스 9개와 새 감시 경계
1개를 포함한 전체 206개 결과는 `unit_results_v5.xml`입니다.
최종 전체 검사는 **208개 통과**이며 `unit_results_v6.xml`에 보존했습니다.
실행 23개의 당시 입력 소스 ZIP은 모두 해시가 일치했습니다. 종료는 22개 정상,
아래 공식 촬영 1개 실패입니다. 이를 독립 주행 20회와 혼동하지 않습니다.

### 공식 코스 촬영 요청에 따른 별도 검증

사용자 요청으로 공식 코스 전체 한 바퀴를 3인칭으로 촬영합니다. 20 km/h는
직선 최고속도 목표이고 코너에서는 기존 전방 거리·곡률·횡가속 제한을 적용합니다.
독립 일정 속도 시험과 공식 코스의 가감속 주행은 다른 실험입니다.

- `autonomy_control_rate_hz` 선택 인수를 추가했습니다. 기본 20 Hz는 유지하고
  고속 단독 촬영에서만 100 Hz를 명시합니다. 센서 10 Hz를 100 Hz로 바꾸지 않습니다.
- 단독 고속 촬영에서는 기존 `tof_safety:=false` 시험 옵션을 명시합니다. 현재 ToF의
  낮은 표적 0.5 m 검출 가정은 빈 공간에서도 약 1 m/s로 제한하기 때문입니다.
  일반 기본 보호·ToF 설정 수치·차량 물성·공식 월드는 변경하지 않습니다.
- 영상에는 실측 시뮬레이션 지면 속도·진행 거리·보정 모드·ToF 제한 해제를 표시합니다.
  수신 프레임 시각을 보존하고 별도 1배 시간 영상에서 누락 구간은 직전 프레임을
  유지합니다. 프레임 누락을 재생 가속으로 숨기지 않습니다.

### 공식 코스에서 드러난 오프라인 감시 시간 문제

`demo_short_v1`은 센서 시뮬레이션 시각이 유효한 동안에도 벽시계 3초 미수신 감시로
SENSOR_STOP/TOF_STALE_STOP이 반복되었습니다. 공식 코스·500 Hz 원시 광선의 계산이
느려 주기 사이 실제 시간이 길어진 조건입니다. 첫 실행은 5.3 sim초 부근에 진단 중단했고
정상 종료했으며, 목표 1 m 완료로 처리하지 않았습니다.

`sensor_wall_timeout_s`를 선택형으로 추가해 기본 3초는 유지하고 오프라인 실행만
30초를 명시합니다. 엔코더/자이로·scan·RGB·ToF의 **측정 시각 기준 제한은 그대로**이며
정답값이나 미래 입력을 허용하지 않습니다. 센서 물리 주기·순차 500 Hz·구동/마찰을
완화한 것이 아닙니다. 실물에서 30초 정지 감시를 권장하는 설정도 아닙니다.

공식 코스 `demo_short_v2`는 ToF 보호를 켠 채 1.01989 m 주행·정지·정상 종료를
통과했습니다. 순차 10 Hz, 제어 수신 약 20.11 Hz, 보정 상태 15개 중 거부 0,
조기 출발·벽 겹침 표본 0이었습니다. 목표 지점의 중심선 거리는 약 1.12 cm입니다.
시작 그리드가 중심선에서 약 9 cm 떨어진 조건이며 전 구간 최대 오차와 구분합니다.
이는 짧은 연결 검사이고 본선 한 바퀴·고속 시험은 아닙니다.

### 공식 코스 한 바퀴 촬영 결과와 미통과 항목

`official_video_v1`은 본선 한 바퀴와 약 2 m를 더해 **48.6727 m** 주행했습니다.
실제 최고 종방향 속도는 **12.3775 km/h**, 주행 60.426 sim초의 시간 가중 평균은
2.8190 km/h입니다. 20 km/h는 명령 정책의 상한 목표였으며 **도달하지 못했습니다**.
따라서 이것은 20 km/h 완주 영상이 아닙니다. 속도를 더 올리기 위해 물성이나
제어 제한을 임의로 완화하지 않았습니다.

- 최대 중심선 거리 0.131084 m, 평면 차량 외형의 정적 벽 겹침 표본 0, 조기 출발 없음,
  코스 마커 0/20/30/45와 양쪽 벽 전환을 확인했습니다. 이는 3차원 접촉 전부가 없었다는 뜻이 아닙니다.
- 순차 LiDAR 10 Hz, 수신 `/drive` 약 100.015 Hz, 기록된 보정 상태 294개는 모두 정상입니다.
  단, launch 로그에는 짧은 `WALL_LOST`가 두 번 있습니다. 낮은 빈도로 발행된 상태 표본만으로
  전체 제어 시간의 실패가 0이라고 주장하지 않습니다.
- 초반 방지턱 부근에서 차체가 크게 들렸으며 최대 절대 피치는 **42.67°**, 롤은 10.14°였습니다.
  [해당 영상 프레임](../../artifacts/validation/2026-09-08/lidar_motion/official_video_v1/bump_inspection/frame_00059.jpg)을 남겼습니다.
  평면 이동 보정은 이런 자세 변화를 보정하지 않습니다. 실물 전복 임계값을 뜻하지 않지만,
  방지턱 사전 감속 없이 안전한 고속 주행이 검증됐다고 할 수 없습니다.
- 목표 도달 후 정지 확인이 **실제 시간 60초 제한**을 넘었습니다. DISABLED 명령 이후에도
  시뮬레이션은 약 1.2초만 진행한 기록이 있어 느린 계산 대비 검사 시간 부족이 유력하지만,
  최종 제동 trace를 보존하지 않아 실제 정지 여부나 단일 원인을 확정하지 못합니다.
- 이후 Gazebo GPU 종료가 멈춰 SIGINT/SIGTERM 뒤 SIGKILL(-9)로 끝났습니다.
  부모 launch의 반환 코드 0과 별개로 정상 종료가 아니므로 원문 `passed:false`를 유지합니다.
  독립 시험의 정상 정지·종료를 이 영상 실행의 성공 근거로 대신 쓰지 않습니다.

영상은 960×540·20 fps·1,210프레임·60.5초이며 모두 디코딩했습니다. 취득 시각으로
1배속 사본을 생성했고 누락/유지 프레임은 0입니다. 원본을 보존했으며 마지막 부근에
신호등이 추적 카메라를 잠시 가립니다. 종료 제동 구간은 영상에 포함되지 않습니다.
[영상·그래프·원문 색인](../../artifacts/validation/2026-09-08/lidar_motion/README.md)을 확인합니다.

이번에는 추가 장시간 실행 없이 시험을 마무리했습니다. 다음 우선순위는 방지턱 인식과
사전 감속 검토, 주행·제동 기록을 함께 남기는 시뮬레이션 시간 기준 종료 검사,
실물 C1 시각/엔코더·자이로 교정입니다. GPU 종료 문제는 별도 진단 대상으로 남깁니다.

최적화는 `wsl_nvidia` GPU·D3D12 수명 보조·GUI/깊이 카메라 해제를 사용합니다.
현재 Ogre2 로그에서 D3D12 NVIDIA RTX 5070 Laptop을 확인했습니다. Bullet은 이전
시험에서 물리 궤적도 달라졌으므로 이번 보정 비교에는 적용하지 않았고 기본 충돌
검출기를 유지합니다. 판정용 차량 상태 발행은 켜 두며, 추적 카메라는 녹화에만
추가합니다. 보정 계산 시간 p95 약 0.6~0.7 ms와 전체 시뮬레이션 계산 속도를 구분합니다.
다음 검토 주제는 카메라 기반 방지턱 인식이며 이번 구현에는 포함하지 않습니다.
