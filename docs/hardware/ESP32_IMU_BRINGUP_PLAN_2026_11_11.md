# ESP32·LSM6DSOX 조립과 실물 시험 계획

모터 드라이버·엔코더·조향 서보까지 확장한 [통합 배선도 v1](ESP32_GPIO_WIRING_2026_11_11.md)을 별도로 작성했다. 아래 IMU 7선 배선은 그대로 유지한다. 추가 장치의 설계 결선과 실제 검증 상태는 통합 도면을 따른다.

작성: 2026-11-11. 상태: **사용자가 ESP32–IMU 7선 배선과 Jetson USB-A → ESP32 USB-C 연결을 완료했다고 알렸다. 식별·백업·업로드·원시 수신 시험을 진행했으며 [실측 보고서](../sensors/ESP32_LSM6DSOX_HARDWARE_2026_11_11.md)에 결과를 기록한다. 상세 보정은 미실행이다.** 점퍼선 때문에 IMU가 바닥에서 떠서 안정적으로 놓기 어려우므로 상세 보정은 고정 지지대를 마련한 뒤 수행한다. 현재는 보정 없는 식별·원시 수신 시험을 먼저 진행하는 계획이다. 계획은 GPT-6 Astra 단계에서 작성했으며 사용자는 실제 작업을 현재 GPT-6.1 Sol로 진행하도록 승인했다. 앞선 6.2 표기는 사용자 말실수로 정정했다. 워커는 사용하지 않는다.

## 1. 범위와 연결 위치

현재 우선 범위는 **ESP32 식별/메모리/USB 통신 → IMU 식별/원시 입력 → 주기·단위·대략적인 축 반응 → Jetson 연속 수신과 ROS 형식 대조**다. 상세 보정은 고정 지지대를 마련한 뒤 진행하며 최초 수신 시험의 선행 조건이 아니다. 두 장치는 사용자 설명상 함께 연결되어 있지만 진단은 ESP32부터 순차 수행한다. 최종 연속 시험은 ESP32가 IMU를 읽어 Jetson으로 전달하는 전체 경로를 측정한다. 차량 모터·서보·엔코더는 연결하거나 구동하지 않는다.

권장 연결은 `노트북 —SSH→ Jetson —데이터 USB→ ESP32 —SPI+INT1→ IMU`다. [승인 전장 구성](APPROVED_ELECTRICAL_LAYOUT.md)과 같은 USB 전원·드라이버·포트 재연결 경로를 처음부터 검증할 수 있다. 노트북은 편집·빌드·분석·원격 조작을 맡는다. USB 통신이 정상인 경우 업로드도 Jetson에서 할 수 있으므로 ESP32를 노트북으로 옮길 필요는 없다.

빌드는 저장소의 기존 PC/WSL ESP-IDF 환경을 먼저 확인하고 소스·도구 버전을 고정한다. 동일 바이너리를 Jetson으로 복사해 해시 대조 후 업로드한다. Jetson에 새 전체 툴체인을 설치하는 일은 선행 조건이 아니다. USB 인식·자동 리셋에 문제가 있을 때만 노트북 직접 연결을 대조 시험으로 사용한다. 이 경우 호스트 변경과 펌웨어 변경을 동시에 하지 않는다.

## 2. 부품 확인과 조립

[구매 기준](ESP32_BUDGET_REVIEW_2026_10_02.md)·[11/8 조달 변경](PROCUREMENT_AND_CABLES_2026_11_08.md)에 **11/11 사용자 설명**을 반영한다. 4438은 정품이라고 확인했으며, ESP32는 처음부터 호환 보드로 구매했다. 실제 ESP32 PCB 인쇄가 상품 자료와 조금 달라 제조사/판본은 미확인이다. 판매 페이지의 YD/VCC-GND 표기를 실물 제조사로 확정하지 않는다.

| 부품 | 문서상 예정품 | 실물 확인 방법 |
|---|---|---|
| ESP32 개발보드 | **호환 보드, 실제 제조사/판본 미확인**. 구매 문서의 VND018/YD-ESP32-S3·ESP32-S3-WROOM-1 **N16R8**은 비교 기준 | PCB·모듈 인쇄·USB 브리지/포트·헤더 기능을 실물로 확인, 칩 조회, Flash 16 MB와 PSRAM 8 MB의 독립 확인 |
| IMU | **정품 Adafruit 4438 LSM6DSOX** 6축 보드(사용자 확인) | 핀 배치·납땜 확인, WHO_AM_I 및 설정 레지스터·동작 확인 |

호환 보드인 점 자체를 불량이나 구매 착오로 취급하지 않는다. 원래 YD 보드의 헤더·CH343P·USB 포트 위치·자동 리셋 회로가 같다고 가정하지 않는다. USB VID/PID와 칩 조회로는 개발보드 제조사까지 확정할 수 없으므로 확인 가능한 범위와 미확인을 나눈다. 조립 전 ESP32 앞뒷면·모듈 표기·헤더 숫자·USB 주변 인쇄를 대조하며, 필요하면 사용자 사진으로 물리 위치를 확정한다. IMU는 정품 여부 재조사를 요구하지 않고 입력 동작을 검사한다.

아래는 **ESP32-S3 및 해당 GPIO의 노출/기능 확인을 전제로 한 논리 배선표**다. 호환 보드의 물리 배선 확정도는 아직 아니다. 실물 핀 대조 후 **전원과 USB를 분리한 상태에서** 7가닥을 연결한다. ESP32 숫자는 GPIO 번호이며, 위에서 세는 물리 핀 번호가 아니다. 핀 헤더가 미납땜이면 먼저 납땜하며 구멍에 선을 끼워 접촉만 시킨 상태로 시험하지 않는다. 짧은 점퍼선(우선 약 10–15 cm)을 사용하고 두 보드를 비전도성 단단한 바닥에 고정한다. 이 길이는 시험 배치 제안이지 제조사 최대 허용값이 아니다.

사용하는 7개 연결만 적었다. Adafruit 4438은 **아래쪽 긴 핀 줄의 실물 표기**를 따른다.

| ESP32 | Adafruit 4438 | 역할 |
|---|---|---|
| **3V3** | **VIN** | IMU 전원 |
| GND 또는 G | GND | 공통 접지 |
| GPIO12 | SCL | 통신 클록 |
| GPIO11 | SDA | ESP32 → IMU |
| GPIO13 | DO | IMU → ESP32 |
| GPIO10 | CS | 센서 선택 |
| GPIO9 | **I1** | 데이터 준비 알림 |

- IMU의 **3Vo는 출력**이므로 이번 전원 입력으로 연결하지 않는다. VIN에 ESP32 **5V를 연결하지 않는다**. Adafruit 보드의 논리 입력 레벨 변환은 VIN 기준이다.
- 위쪽 `SCX`, `SDX`, `CS`, `DO`, `GND` 줄은 이번에 연결하지 않는다. 위쪽 CS·DO는 아래쪽 CS·DO와 다른 보조 인터페이스 핀이다. [Adafruit 핀 그림](https://learn.adafruit.com/lsm6dsox-and-ism330dhc-6-dof-imu/pinouts)과 실크를 대조한다.
- **실물 실크는 `INT1`이 아니라 `I1`이다.** `I1`·`I2`의 첫 글자는 대문자 I이며 숫자 11·12나 GPIO11·12가 아니다. 제조사 정면 사진처럼 `LSM6DSOX` 글씨가 바로 보이는 방향에서 I1은 아래쪽 긴 핀 줄의 오른쪽에서 두 번째이며, `CS`와 `I2` 사이에 있다. GPIO9를 `I1`에 연결한다.
- I2(문서상 INT2)·3Vo·보조 센서 핀·STEMMA QT는 이번에 연결하지 않는다. 별도 레벨 변환기나 풀업 저항을 추가하지 않는다.
- 점검 뒤 Jetson USB-A ↔ ESP32의 **실물에서 확인한 USB-to-UART 포트 한 개**를 데이터 케이블로 연결한다. YD 자료는 CH343P 브리지와 S3 직접 USB 두 포트를 설명하지만 보유 호환 보드도 같다는 증거는 없다. 브리지 칩과 포트 수/기능부터 대조하며 왼쪽/오른쪽을 단정하지 않는다. 두 호스트나 별도 전원에 동시에 연결할 필요가 없다.
- 일반 USB 연결을 위해 Jetson 전체를 종료할 필요는 없다. SPI 점퍼선을 수정할 때는 ESP32 USB를 먼저 분리한다. 카메라 CSI 케이블 교체와는 다른 절차다.

GPIO 배정은 기존 핀 예산을 유지한 것이다. [VCC-GND 자료](https://github.com/vcc-gnd/YD-ESP32-S3)는 비교 대상으로만 쓰며, 보유 호환 보드의 회로도나 실물 검증을 대신하지 않는다.

## 3. 실행 순서와 수용 조건

### A. ESP32 식별·기존 상태 보존

1. 기존 C1을 포함한 USB 장치와 새 장치의 VID/PID·serial/물리 경로·드라이버를 대조한다. `/dev/ttyUSB0`나 `/dev/ttyACM0`을 번호만 보고 선택하지 않는다. 한 프로세스가 포트를 소유하게 하고 권한 변경 전 상태를 보존한다.
2. 읽기 조회로 칩 종류/리비전·Flash JEDEC ID/실제 용량·보안 상태를 확인한다. 예상은 ESP32-S3와 16 MB Flash다. 부트로더 조회/포트 개방은 리셋을 일으킬 수 있으므로 정상 부팅 로그와 구별한다.
3. 첫 쓰기 전에 읽을 수 있는 전체 Flash와 설정을 비공개 작업 경로로 백업하고 해시를 보존한다. 예기치 않은 읽기 제한이 있으면 기존 내용을 보존할 방법을 먼저 확인한다. eFuse·보안 설정 변경이나 강제 우회는 이 시험 범위가 아니다.
4. 센서 진단 전용 펌웨어에서 PSRAM 모드/초기화·장착 용량을 확인한다. 기대값은 8 MB이며 할당된 heap/free 값과 물리 용량을 혼동하지 않는다. 할당한 시험 영역만 쓰고 읽어 확인하며 영역/크기를 기록한다. 2 MB Flash·PSRAM 비사용인 과거 빌드 검사는 N16R8 확인 근거가 아니다.
5. 예상과 다르면 실측 모델로 기록하고 설정/판본 문제를 조사한다. COM 포트 인식만으로 ESP32 모델이나 메모리까지 합격 처리하지 않는다.

### B. IMU 식별·설정·기본 동작

1. 별도 ESP-IDF 센서 진단 앱을 사용한다. 기존 `firmware_bench`는 IMU 구현이 없는 구동 계약 검사 앱이므로 그대로 올려 센서 앱으로 간주하지 않는다. ST 레지스터 드라이버를 우선 검토해 정확한 커밋과 라이선스를 보존하고 SPI 오류를 호출자까지 전달한다.
2. SPI는 우선 1 MHz의 진단 설정으로 시작한다. WHO_AM_I `0x0F`의 기대 응답은 `0x6C`다. 읽기 성공·센서 상태·소프트 리셋 후 복구를 확인한다. ID 일치는 데이터와 메모리 검사를 대신하지 않는다.
3. 첫 측정 설정은 **가속도·자이로 각각 208 Hz, 자이로 ±500 °/s, 가속도 ±8g, 고성능 모드**다. [현재 B0390 시뮬 프로파일](../../src/arena_description/config/b0390_c1_jr60p20_sim.yaml)의 출발값이며 최적값으로 확정한 것은 아니다. 과거 감사의 100 Hz 문구를 최신 시뮬 값으로 사용하지 않는다.
4. FS/ODR·필터·BDU·자동 증가·FIFO·INT1 극성/발생원을 설정 뒤 다시 읽는다. 명목 주기는 약 4.808 ms다. 최초 DRDY/레지스터 읽기로 배선을 확인한 뒤 연속 기록에는 원래 FIFO tag/순서/상태/내부 timestamp를 보존하는 수집을 우선한다. accel과 gyro를 무조건 같은 취득 시각으로 묶지 않는다.
5. ST 절차의 자체 시험은 후속으로 남긴다. 이번에는 사용자 지정대로 형식/원시 수신을 우선했다. 자체 시험을 수행할 때는 정해진 시험 설정/축별 응답을 기록하고 영점·정확도 교정과 구분한다. 정상 설정 복원과 readback 후 별도 측정 구간을 시작한다.

### C. 연속 수신과 재연결

1. 설정을 안정시킨 뒤 **보정하지 않은 원시 입력을 5분 연속 기록**한다. 예열·설정 변경·사용자 움직임 구간을 구분한다. 안정된 지지로 §5의 예비 자이로 영점 추정까지 가능한 경우에만 별도 추정 구간 뒤 이 기록을 독립 비교에 함께 사용한다. 영점 추정이 불가능해도 통신/주기 시험은 진행한다. 표본 시각 기준의 실제 ODR와 호스트 수신률을 분리하고 accel/gyro별 개수, 간격 중앙값/p95/p99/최대, sequence 공백·CRC/파싱 오류·FIFO overrun·재부팅·포화·SPI 오류·큐 유실을 집계한다. 흔들리는 설치 상태의 분산을 센서 자체 잡음으로 보고하지 않는다.
2. 기준은 식별/설정 일치, 연속 구간의 재부팅·버스 오류·CRC 오류·보고된 overrun/전송 유실 0, 새 표본/타임라인의 일관성이다. 누락을 검출할 근거가 부족하면 **무손실 미검증**으로 표시한다. 실측 주파수와 분산을 그대로 제시하고 명목 208 Hz에 맞춰 표본을 복제하거나 재표본화하지 않는다. ODR 허용차는 선택한 모드의 제조사 근거를 대조해 적용한다.
3. USB 한 번 분리/재연결, ESP32 한 번 리셋, 수신 프로그램 재시작을 구분해 확인한다. 사용자 조작이 필요한 시점만 안내한다. 이전 boot ID/부분 패킷/과거 표본이 새 세션으로 합쳐지지 않고 다시 수신되는지 확인한다. 송신·수신 카운터를 대조하되 MCU가 못 읽은 센서 표본까지 그것만으로 검증했다고 하지 않는다.
4. 단일 링크 정상 후 ROS 기록을 대조한다. 카메라·C1과의 동시 부하 및 차량 진동 시험은 이 두 장치의 최초 합격 뒤 별도 후속이다.

## 4. 데이터 형식과 시간 계약

센서 자체는 accel/gyro 각 축의 **signed 16-bit 원시 값**, 온도 및 상태를 제공한다. ESP32의 USB 패킷과 ROS 메시지는 별도 어댑터가 만드는 형식이다. 따라서 원본을 보존한 뒤 다음 층을 구분한다.

| 층 | 반드시 보존/확인할 항목 |
|---|---|
| 원시 센서 | 원래 축 순서·정수값·온도 raw·읽기 상태·FIFO tag/원순서·timestamp raw·설정 readback |
| MCU 진단 전송 | 형식 버전·길이·boot ID·전송 sequence·스트림별 식별/카운터·CRC·오류/포화/유실 상태·MCU INT 관측 및 읽기 시작/끝 시각 |
| 호스트 기록 | 원래 수신 바이트·수신 monotonic/벽시계·파싱 결과·변환 계수/설정 ID·펌웨어/드라이버/도구 버전과 해시 |
| ROS 대조 | `sensor_msgs/Imu`, rad/s·m/s², 실측한 축/장착 변환과 frame, stamp의 시계/불확실성, 공분산의 근거 |

센서 좌표의 raw와 차체 좌표로 변환한 값을 구분한다. 차체 기준은 x 전방·y 좌측·z 위, 양의 회전은 오른손 법칙이다. 정지한 센서 z축이 위라면 가속도 z는 약 **+9.81 m/s²**이며 0이 아니다. 중력을 이미 제거한 값과 혼용하지 않는다. [REP-145](https://github.com/ros-infrastructure/rep/blob/master/rep-0145.rst).

±500 °/s에서 raw 1,000은 17.5 °/s ≈ 0.305433 rad/s, ±8g의 감도는 0.244 mg/LSB다. 실제 설정을 읽어 단위를 한 번만 변환한다. Adafruit 라이브러리의 이미 SI로 변환된 출력에 다시 변환 계수를 곱하지 않는다. ST DS12814의 해당 FS 감도와 선택한 소스 구현을 대조한다.

LSM6DSOX에는 자력계가 없고 이 시험에서는 자세 추정기를 추가하지 않는다. quaternion을 실제 자세처럼 제공하지 않고 ROS에서 orientation unavailable을 `orientation_covariance[0] = -1`로 표현한다. gyro/accel 공분산을 알 수 없으면 규약상 unknown으로 표시하며, 추정치를 쓸 때는 측정 조건을 남긴다. 미래 통합 `/imu/data`와 구별되는 진단 토픽(예: `/imu_probe/data_raw`)으로 먼저 확인한다. 검증된 취득 시각이 없으면 수신 시각을 그 사실과 함께 별도로 기록하고, 시각 검증을 요구하는 제어/보정 입력에 연결하지 않는다.

32-bit·25 μs 센서 timestamp, MCU 단조 시계, Jetson 단조/ROS 시계는 서로 다르다. 내부 timestamp와 FIFO 표본 대응, wrap/reset·boot 세대, MCU→Jetson 대응과 불확실성을 검증한다. 드라이버의 읽기 함수 호출 시각이나 USB 도착 시각을 센서 취득 시각으로 단정하지 않는다. 필터 지연도 별도다. 세부 금지/단위 경계는 [기존 실물 입력 감사 §9](HARDWARE_CAPTURE_AUDIT_2026_10_13.md#9-1023--lsm6dsox-입력을-연결하기-전)를 따른다.

진단 링크는 우선 460800 baud를 후보로 하되 실제 패킷 길이·208 Hz 두 스트림·상태 프레임을 합산해 8N1 선로 점유율에 여유를 둔다. 느린 출력 때문에 취득 작업을 막지 않도록 유한 큐와 유실 카운터를 사용한다. UART0의 ROM/부팅 로그와 센서 프레임은 구분하고 시작 동기·CRC로 재동기화한다. 측정 중 로그를 데이터 프레임에 섞지 않는다. 기존 차량 명령 wire protocol은 이 진단 전용 기록으로 변경하지 않는다.

## 5. 보정 순서와 사용자 조작

**11/11 현재 설치 조건:** 점퍼선 때문에 보드가 떠서 평평하게 놓기 어렵다는 사용자 설명에 따라 여섯 방향 보정·정밀 영점/잡음·장착 transform 확정은 뒤로 미룬다. 자이로 영점에 필요한 것은 수평보다 **정지 상태**다. 비전도성 작은 상자나 지지대에 기울어진 채라도 흔들리지 않게 고정할 수 있으면 예비 측정은 가능하다. 안정적으로 지지할 수 없으면 생략하고, 손으로 잡고 있는 구간을 정지 영점 근거로 사용하지 않는다.

기울어진 정지 상태에서는 중력이 여러 가속도 축으로 나뉘므로 z 한 축이 +g가 아니라는 이유로 실패 처리하지 않는다. 세 축 크기가 대략 g인지 확인하는 것은 기본 단위/응답 점검이며 정밀 교정은 아니다. 여섯 방향 보정은 IMU를 작은 판/브래킷에 고정한 뒤 차량 장착 전에도 할 수 있다. 최종 차량 장착 뒤에는 장착 축과 영점을 다시 확인한다.

**이번 측정의 보정 관련 값은 예비 추정치로만 남기며 운영 계수로 확정하지 않는다. 장착 뒤에는 이번 확인 항목도 다시 점검한다.** 정지 여부를 독립 검증하지 않은 평균은 겉보기 영점 후보이며 실제 회전·미세 흔들림이 섞일 수 있다.

**공장 보정이 있어도 조립 뒤의 영점·축·온도 확인은 필요하다.** 첫 연결 확인에는 기존 보정값이 없어도 되며 처음부터 raw를 남긴다. 보정 전 기록을 지우거나 보정된 값만 저장하지 않는다.

1. **자이로 영점:** 단단한 곳에 움직이지 않게 둔 채 초기 약 3분 예열하고 온도/영점 추이를 본다. 3분은 시험 시작 제안이며 열적 안정 보장이 아니다. 안정된 별도 60초 구간에서 세 축 bias와 표준편차를 추정한다. 이어지는 5분 검증 구간에만 그 고정 bias를 적용해 잔류 평균과 적분 drift를 비교한다. 추정에 사용한 구간에서 평균 0을 얻은 것을 독립 검증으로 보고하지 않는다. 움직이는 동안 계속 평균을 빼 실제 회전을 지우지 않는다. [Adafruit 영점 보정 설명](https://learn.adafruit.com/adafruit-sensorlab-gyroscope-calibration).
2. **가속도계 여섯 방향:** 센서의 +X/−X/+Y/−Y/+Z/−Z가 위를 향하도록 각 자세를 20–30초 유지한다. 자세를 바꾸는 구간은 제외하고 여섯 면의 bias/scale 후보와 잔차를 계산한다. 중력까지 빼서 세 축을 모두 0으로 만들지 않는다. 가능한 한 직각을 유지하는 지그/단단한 상자를 사용하며 손으로 대충 놓은 결과는 정밀 교정으로 승인하지 않는다. 별도 반복 자세에서 확인한다.
3. **축과 부호:** 축 화살표를 기록하고 각 축으로 천천히 회전시켜 대응 축·부호를 확인한다. 손으로 약 90°/180° 돌리는 시험은 단위·부호·큰 배율 오류를 찾는 용도다. 정확한 회전 기준 장비 없이 자이로 배율 정확도를 인증하지 않는다.
4. **차량 장착 후:** 최종 장착 transform과 정지 영점을 재확인한다. 진동·온도 영향, 필터 선택과 지연은 실제 장착 상태에서 별도 측정한다. 정밀 gyro scale/비직교성·온도 보정곡선은 이번 초기 시험의 필수 완료 조건으로 추가하지 않는다.

이 센서는 6축이므로 자력계용 8자 돌리기 보정이 기본 절차가 아니다. gyro 영점 보정으로 yaw drift를 줄일 수는 있지만 절대 방위가 생기거나 장기 위치 적분이 정확해지는 것은 아니다. 이번 소비자의 LiDAR 운동 보정은 각속도가 핵심이며, 가속도 정밀 교정을 기다리느라 식별/통신/자이로 확인을 미룰 필요는 없다.

## 6. 산출물과 인계

- 실제 실행 후 이 문서에는 결과 보고서 링크와 완료 범위만 추가한다. 상세 결과는 실행일 기준의 ESP32·IMU 기술 보고서 한 곳에 모은다.
- 비공개 `build/` 아래에 기존 Flash 백업, 장치 고유 ID, 원시 UART/FIFO/시각 로그, 원본 펌웨어/설정/해시를 보존하고 Git 제외를 확인한다. 공개 `artifacts/validation/<실행일>/`에는 비식별 설정·통계·검증 JSON과 재현 절차만 둔다.
- 보정 계수에는 장치 구분·온도 범위·FS/ODR/필터·축·원자료 구간·추정 방법·독립 검증 결과·버전을 묶는다. 운영 기본값이나 센서 내부 offset 레지스터에 즉시 굽지 않고 원시 값과 함께 명시적 시험 옵션으로 적용한다.
- 최신 시뮬의 208 Hz·범위·축/시각·임시 백색잡음을 실측과 비교하고 바꿀 항목을 정리한다. 정지 RMS를 잡음밀도로 오인하지 않으며, 시뮬 수정/주행 검증 완료로 확대하지 않는다.
- 종료 때 포트/프로세스·임시 권한·센서 측정 상태와 남은 펌웨어를 명시한다. 보드를 재부팅해도 진단 앱인 상태임을 기록하며 원래 펌웨어를 복구했다면 해시/부팅을 확인한다.

**GPT-6.1 Sol 재개 지점:** [실측 보고서](../sensors/ESP32_LSM6DSOX_HARDWARE_2026_11_11.md)의 완료 범위와 현재 펌웨어부터 확인한다. 식별·수신기 수정 후5분·리셋/재개방은 완료했으며 첫 수신 실패도 보존했다. 다음은 I1 발생 조건을 갖춘 시험·독립 스트림/취득 시각·ROS 어댑터이며, 안정적으로 고정한 뒤 영점·여섯 방향·장착 축을 재확인한다. 이미 완료한 같은5분 시험은 새 변경이나 문제 없이 반복하지 않는다. 사용자 연결 보고·소프트웨어 확인·전기/장착 검증의 범위를 구분하고 기존 C1/카메라와 무관한 변경을 유지한다.
