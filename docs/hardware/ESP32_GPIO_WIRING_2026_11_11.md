# ESP32 주변 통합 배선 설계 v1

작성: 2026-11-11. **2026-11-13 조립 인계 갱신:** ESP32의 3V3 두 개와 GND 네 개에 맞춰 전원 분기를 지정하고, 두 PDB의 CN/CH 대응과 정격을 제조사 자료로 확인했다. 서보 전원은 기존 CH5/CH6 선택 범위 중 **M01 CH5(CN6)**를 조립 기준으로 지정한다. 어댑터–서보는 **보유한 3선 전용 케이블 1개**를 사용한다.

IMU SPI, 서보 무부하 왕복, 교체 CF를 통한 엔코더 손 회전·약5% 모터 구동 중 계수는 확인했다. [엔코더 시험](../sensors/PGE213_ENCODER_HARDWARE_2026_11_12.md)과 [모터 시험](../sensors/MD20A_MOTOR_HARDWARE_2026_11_12.md)에 초기 실패·성공 구간·해체 구간 추가 신호를 구분해 보존했다. **이번 헤더 재분배는 조립 지시이며 전체 하네스의 실물 검증 완료를 뜻하지 않는다.** 고속 파형·정확한 회전당 계수·장착 교정·운영 제어는 별도다.

- **[전체 배선도 — HTML](schematics/esp32_gpio_wiring_v1.html)**: ESP32·IMU·CF·엔코더·모터·서보·PDB·STOP 스위치를 각각 한 번만 표시하고 신호·전원·분기를 한 장에 연결했다. 전체 보기/원본 크기 버튼으로 확대한다.
- **한 장 원본:** [SVG](schematics/esp32_gpio_all_v1.svg) · [PNG](schematics/esp32_gpio_all_v1.png).
- **[별도 층별 케이블 배치도](schematics/vehicle_wiring_layers_v1.html)**: 임시 STEP의 층을 유지하고 Y 분기를 상부 1단 J01 근처에 두어 LiDAR 광축을 지나는 전원4쌍·USB2개를 표시한다. [층별 배치와 통과량 설명](WIRING_LAYERS_2026_11_13.md).
- **[전체 연결표](schematics/esp32_gpio_pin_table_v1.md)** · [기계 판독 JSON](schematics/esp32_gpio_v1.json).

Jetson 전원은 PDB 쪽 +/− 두 선에서 배럴 케이블 하나로 이어지고, Adapter–서보는 가까운 두 3핀 포트 사이의 전용 케이블 하나로 표시했다. C1은 지급 USB 어댑터를 경유한 USB 케이블 하나, B0390은 22↔22 FPC 하나다. 굵은 선은 다심 케이블 묶음이며 도체를 단락시키는 접속점이 아니다.

도면은 모듈 간 배선도이며 내부 PCB 회로·전선 길이/굵기·독립 STOP 회로를 나타내지 않는다. **3V3①/②, GND①~④는 배선 관리명이며 실물의 위아래·좌우 순번이 아니다.** 해당 실크가 있는 핀을 하나씩 배정하고 하드웨어팀이 라벨을 붙인다. [승인 전장 구성](APPROVED_ELECTRICAL_LAYOUT.md)의 전원 구조와 기존 IMU GPIO 배정을 유지한다.

**2026-11-13 사용자 재확정:** 현재 회로도/배선 구성은 확정 기준이다. 기존 GPIO·전원·분기·STOP 결선을 기준으로 펌웨어를 연결하며, 별도 지시 없이 배선 후보를 재선정하지 않는다. 설계 확정과 실제 조립·동작 검증은 구분한다.

## 1. 기존 IMU 배선을 유지하는 이유

[11/11 실측](../sensors/ESP32_LSM6DSOX_HARDWARE_2026_11_11.md)에서 ESP32-S3·Flash 16 MB/PSRAM 8 MB와 LSM6DSOX SPI 수신을 확인했다. 현재 GPIO9–13은 엔코더4/5, 모터15/6, 서보17/18과 충돌하지 않는다. 따라서 IMU를 옮길 이유가 없다.

ESP32는 처음부터 호환 보드로 구매했으며 제조사/PCB 판본은 미확인이다. YD/VCC-GND 자료의 P1/P2 순번이나 USB 포트 좌우 위치를 이 보드에 적용하지 않는다. 실측 USB 브리지는 WCH VID/PID `1a86:55d3`, UART0 GPIO43/44 경로지만 정확한 브리지 칩 형번은 미확정이다. **보드의 GPIO 실크와 현재 통신된 USB 포트**를 기준으로 연결한다.

외부 장치에 사용하는 GPIO는 STOP 입력을 포함해 총 **12개**다. UART0 GPIO43/44는 보드 내부 USB-UART 전용으로 별도 예약한다. 11/12 이 세션의 시험 종료 시 원 IMU 앱을 복구했다. 이후 펌웨어 상태와 이번 조립 지시를 혼동하지 않는다.

## 2. IMU — 기존 GPIO 배정 유지

| ESP32 | Adafruit 4438 | 역할 |
|---|---|---|
| **3V3①** | **VIN** | IMU 전원 |
| GND① | GND | 공통 접지 |
| GPIO12 | SCL | SPI 클록 |
| GPIO11 | SDA | ESP32 → IMU |
| GPIO13 | 하단 DO | IMU → ESP32 |
| GPIO10 | 하단 CS | 센서 선택, LOW 유효 |
| GPIO9 | I1 | INT1 알림 입력, 동작 검증은 후속 |

핀 이름은 사용자 확인 실크를 따른다. **I1은 대문자 I와 숫자 1**이며 `11`처럼 보일 수 있다. 상단 `SCX / SDX / CS / DO / GND`, 하단 `3Vo / I2`는 이번 결선에서 사용하지 않는다. `3Vo`는 레귤레이터 출력이므로 VIN 대신 전원을 넣지 않는다. SPI는 실측했지만 I1 인터럽트 검증까지 통과한 것은 아니다. [Adafruit 핀 설명](https://learn.adafruit.com/lsm6dsox-and-ism330dhc-6-dof-imu/pinouts).

## 3. 모터 드라이버 — MD20A와 MB4266-24180

| 출발 단자 | 도착 단자 | 역할 |
|---|---|---|
| ESP32 GPIO15 | MD20A PWM | 속도 제어 PWM |
| ESP32 GPIO6 | MD20A DIR | 방향 제어 |
| ESP32 GND③ | MD20A 신호 GND | 신호 기준 |
| M01 **CN2(CH1) +** | MD20A VB+ | 모터 전원 입력 |
| M01 **CN2(CH1) −** | MD20A VB− | 전력 귀환 |
| MD20A MA | 모터 단자 6 (+) | 최초 시험용 모터 극성 |
| MD20A MB | 모터 단자 5 (−) | 최초 시험용 모터 극성 |

MD20A는 3.3 V 입력을 지원하므로 PWM/DIR에 CF-0108을 넣지 않는다. 제한 시험은 **20 kHz·약5%·500 ms**로 진행했으며 PWM0 구간 정지를 관찰했다. 운영값·제동시간·부하 운전까지 확정한 것은 아니다. 일반 RC 서보용 50 Hz 펄스 폭 명령과 구분한다. [Cytron 사양](https://www.cytron.io/p-20amp-6v-30v-dc-motor-driver).

제조사 진리표상 PWM LOW는 두 출력 LOW인 **brake**다. PWM HIGH/DIR LOW일 때 MA HIGH·MB LOW이며 DIR HIGH일 때 반대다. MA/MB는 양방향 H-bridge 출력이라 둘 중 어느 것도 고정 GND가 아니다. 위 모터 단자 5/6은 보존된 제조사 모터/엔코더 자료의 번호이며, 보유 케이블 색이나 단자 방향을 보지 않고 결정하지 않는다. MA→6/MB→5가 차량 전진이라는 뜻도 아니다. 바퀴를 띄운 시험에서 전진 명령과 엔코더 부호를 함께 확정한다. [공식 연결 데이터시트 §4](https://docs.google.com/document/d/1eKpt66z-1qLMJkaXrHU1AfKqSVeIpEnM43vECpkYuWA/edit).

**부팅·리셋 구간 PWM LOW는 아직 실측하지 않았다.** GPIO 초기화에서 LOW를 설정하더라도 그 이전 ROM/리셋 구간을 보장하지 않는다. 현재 진단 펌웨어를 사용한 채 모터 전원을 켜서 정지 동작을 기대하지 않는다. USB 포트 재개방 때 실제 MCU 리셋이 관측됐으므로, 후속 구동 펌웨어는 새 boot·기존 명령 무효·재허가 계약과 실제 PWM 파형을 확인해야 한다. 별도 EN 핀이 없는 MD20A에 GPIO21을 임의 연결하지 않는다.

## 4. 조향 — Bus Servo Adapter (A)와 ST3215-HS 1개

| 출발 단자 | 도착 단자 | 역할 |
|---|---|---|
| ESP32 GPIO17, UART1 TX | Adapter A H2 **TX / TXD** | 명령 송신 |
| ESP32 GPIO18, UART1 RX | Adapter A H2 **RX / RXD** | 응답 수신 |
| ESP32 GND④ | Adapter A H2 GND | 신호 기준 |
| M01 **CN6(CH5) +** | Adapter A 전원 + | 12 V, 이 채널 최대 2 A |
| M01 **CN6(CH5) −** | Adapter A 전원 − | 서보 전력 귀환 |
| Adapter A 서보 포트 D/DATA | ST3215-HS D/DATA | 단선 반이중 데이터 |
| Adapter A 서보 포트 V+ | ST3215-HS V+ | 서보 전원 |
| Adapter A 서보 포트 G/GND | ST3215-HS G/GND | 서보 접지 |

**어댑터의 서보 3핀 포트 하나 ↔ ST3215-HS의 3핀 포트 하나를 보유한 3선 전용 케이블 1개로 연결한다.** 위 표의 D/DATA·V+·G/GND는 그 케이블 내부 세 선의 기능이며, 별도 점퍼선 세 개를 제작하라는 뜻이 아니다. 커넥터 실제 핀 순서도 아니다.

**점퍼 두 개 모두 A 위치**, UART 헤더는 **TX→TX / RX→RX**다. 일반 UART 장치의 교차 연결 습관을 적용하면 이 제품에서는 잘못 연결할 수 있다. 이는 [Waveshare 공식 배선 안내](https://docs.waveshare.com/Bus_Servo_Adapter_A/Product-Wiring-Example)의 명시 사항이다. H2의 실제 핀 순서와 D/V/G 케이블 방향은 보드 실크로 확인하며 좌우 순번이나 선 색은 추측하지 않는다.

[제조사 회로도](https://files.waveshare.com/wiki/Bus_Servo_Adapter_A/Bus_Servo_Adapter_A.pdf)의 UART/버스 변환부는 3.3 V 논리이며 자동 방향 전환을 사용한다. 별도 방향 GPIO16이나 ESP32 3V3/5V 전원선을 어댑터 H2에 연결하지 않는다. GPIO17/18을 서보의 D 한 선에 직접 묶지 않는다.

**11/14 실물 정정:** 사용자는 실제 보유 어댑터에 USB 단자가 없다고 확인했다. 앞선 “어댑터 USB는 비워 둔다”는 제품 동일성 가정을 철회하며 USB 직접 연결을 대안으로 사용하지 않는다. 위 Waveshare 링크의 제품과 보유 보드의 판본·회로 동일성은 재확인이 필요하다. 기존 ESP32 UART를 통한 실제 통신 성공은 보존하되, Jetson에 옮길 때에는 실제 헤더 기능과 반환 신호 전압을 확인한다. [ESP32 없이 제어하는 대안 조사](MOUNTED_DC_TEST_2026_11_14.md#esp32-없이-제어하는-대안-조사).

전원은 DC 5.5×2.1 mm 잭(중앙 +) 또는 해당 전원 단자 중 하나를 사용한다. **M01 CH5(CN6) 12 V/2 A**, 서보 한 개로 조립한다. CH6(CN7)은 예비이며 CH5와 병렬 연결하지 않는다. 이는 이번 조립 채널 선택이며 앞선 벤치 시험의 실제 채널 확인을 소급하지 않는다. [서보 실측](../sensors/ST3215_HS_HARDWARE_2026_11_12.md)에서 ID1/1 Mbps를 확인했으나 실제 조향 전류·전압 강하·링크 중립·끝단은 후속이다. 직렬 서보이므로 ESP32의 PWM 서보 출력 핀을 추가하지 않는다.

## 5. 엔코더 — 정상 교체 CF의 채널 1/2 사용

PGE-213은 NPN 오픈 컬렉터·내부 풀업형이며 모터축의 HA/HB 두 신호를 읽는다. 엔코더 신호는 5 V 측 B1/B2로, ESP32 입력은 3.3 V 측 A1/A2로 연결한다. HA/HB를 ESP32에 직접 연결하지 않는다.

| 출발 단자 | 도착 단자 | 역할 |
|---|---|---|
| J01 **CN5(CH4) +** | **T5V** → 엔코더 pin 1 VCC + CF VB | 5 V 전원 분기 |
| ESP32 **3V3②** | **T3V3** → CF VA + CF OE | 한 3V3 핀에서 두 갈래 |
| ESP32 **GND②** | **TGND** → CF GND + 엔코더 pin 2 GND + J01 CN5− + STOP 선 2 | 다섯 단자의 명시적 공통 접지 |
| PGE-213 pin 3 HA | CF B1 | A상 5 V 측 |
| CF A1 | ESP32 GPIO4 | A상 3.3 V 측 |
| PGE-213 pin 4 HB | CF B2 | B상 5 V 측 |
| CF A2 | ESP32 GPIO5 | B상 3.3 V 측 |

**CF VA=3.3 V, VB=5 V, OE=VA와 같은 3.3 V**다. OE는 VCCA 기준이므로 5 V에 연결하지 않는다. 이 배선은 3.3 V가 살아 있는 동안 enable하며 독립적인 전원 시퀀스/Hi-Z 제어 회로를 제공하지 않는다. [TI 데이터시트](https://www.ti.com/lit/ds/symlink/txs0108e.pdf). 미사용 채널은 미연결로 둔다.

공통 GND를 추가한 뒤에도 기존 보드는 출력이 LOW에 머물렀다. 다른 보드로 교체하자 B측 HIGH 약4.95 V와 네 A/B 상태, 손 회전 양방향 계수, 약5% 모터 구동 중 PCNT/software 일치를 확인했다. 이는 교체 전후 기능 차이이며 불량 소자나 내부 고장 지점까지 특정한 결과는 아니다. 사진의 서로 다른 PCB·B2 실크 문제는 [보드 식별 이력](APPROVED_ELECTRICAL_LAYOUT.md#44-신규-cf-0108과-기존-헤더-보드의-구분)에 보존한다. 기능 확인된 보드의 실제 A1/B1·A2/B2 실크를 사용한다.

고속 상승/하강 파형과 A측 전압 실측은 아직 없다. 제조사 7 PPR·x4의 28 counts/rev는 후보이고, 손으로 돌린 대략 한 바퀴를 정확한 교정값으로 채택하지 않는다. 시험 종료 후 엔코더 쪽 전원·신호를 제거하고 MCU 쪽 선을 남긴 구간의 추가 에지는 정상 회전 데이터로 사용하지 않는다. 상세 판정은 위 시험 보고서를 따른다.

## 6. 전원 헤더 분배와 PDB 단자

### 6.1 ESP32의 3V3 두 개 / GND 네 개

| ESP32 관리명 | 연결 대상 | 역할 |
|---|---|---|
| 3V3① | Adafruit 4438 하단 VIN | IMU 전원 |
| 3V3② | T3V3 분배점 → CF VA + OE | 한 3V3 핀을 두 갈래로 분기 |
| GND① | Adafruit 4438 하단 GND | IMU 접지 |
| GND② | TGND 분배점 → CF GND + 엔코더 pin 2 + J01 CN5(CH4)− + STOP 선 2 | 센서/CF/STOP의 명시적 공통 접지 |
| GND③ | MD20A Signal GND | PWM/DIR 신호 기준 |
| GND④ | Adapter A H2 GND | UART 신호 기준 |

**GND 핀을 추가로 확보할 필요가 없다.** CF·엔코더 전원 GND·STOP 스위치 선 2를 TGND 한 점에 모으고 ESP32 GND② 하나로 연결하면 된다. 기존 공통 GND 분기를 없애는 설계가 아니다. MD20A를 통해 간접적으로 연결될 것이라고 가정하지 않는다.

| 분배점 | 같은 노드로 연결할 단자 |
|---|---|
| T3V3 | ESP32 3V3② ↔ CF VA ↔ CF OE |
| T5V | J01 CN5(CH4)+ ↔ PGE-213 pin 1 VCC ↔ CF VB |
| TGND | ESP32 GND② ↔ J01 CN5(CH4)− ↔ PGE-213 pin 2 GND ↔ CF GND ↔ STOP 스위치 선 2 |

분배점은 절연한 납땜 접속 또는 체결 가능한 공통 단자대로 만든다. T3V3/T5V는 각각 3접점, TGND는 STOP 스위치까지 포함한 5접점이 같은 노드다. 이는 추가 DC-DC나 전원 분배 PCB가 아니라 전선 접속점이다. 별도 분기선 여러 개를 ESP32 핀 여러 개에 각각 꽂을 필요가 없다.

### 6.2 PDB: CN1은 입력, CHn은 CN(n+1)

J01과 M01 모두 **CN1=배터리 입력**이다. **CH1→CN2, CH2→CN3, CH3→CN4, CH4→CN5, CH5→CN6, CH6→CN7**이며 CN1과 CH1은 다른 것이다. 제조사 [J01 Preliminary p.3](https://github.com/MOSW626/istech-it-arena/blob/main/docs/hardware/PM_KAIST-MR-J01_Preliminary.pdf), [M01 Preliminary p.3](https://github.com/MOSW626/istech-it-arena/blob/main/docs/hardware/PM_KAIST-MR-M01_Preliminary.pdf)의 포트 표와 보드 그림을 직접 대조했다.

| 보드 | 채널 | 커넥터 | 전압 | 전류 한도 | 조립 기준 연결 |
|---|---|---|---|---|---|
| J01 | 입력 | CN1 | 21–36 V DC | — | 배터리 + / − |
| J01 | CH1 | CN2 | 19 V | 최대 2.3 A | Jetson DC 입력 |
| J01 | CH2 | CN3 | 5 V | CH2+CH3 합계 최대 1.5 A | 미사용 / 예비 |
| J01 | CH3 | CN4 | 5 V | CH2+CH3 합계 최대 1.5 A | 미사용 / 예비 |
| J01 | CH4 | CN5 | 5 V | 최대 0.5 A | T5V → 엔코더 VCC + CF VB |
| J01 | CH5 | CN6 | 3.3 V | CH5+CH6 합계 최대 0.6 A | 미사용 / 예비 |
| J01 | CH6 | CN7 | 3.3 V | CH5+CH6 합계 최대 0.6 A | 미사용 / 예비 |
| M01 | 입력 | CN1 | 24–36 V DC | — | 배터리 + / − |
| M01 | CH1 | CN2 | 입력 전압 그대로 | 입력 전류 공급 능력에 따름; 고정 A 정격 미제시 | MD20A VB+ / VB− |
| M01 | CH2 | CN3 | 입력 전압 그대로 | 입력 전류 공급 능력에 따름 | 미사용 / 예비 |
| M01 | CH3 | CN4 | 입력 전압 그대로 | 입력 전류 공급 능력에 따름 | 미사용 / 예비 |
| M01 | CH4 | CN5 | 입력 전압 그대로 | 입력 전류 공급 능력에 따름 | 미사용 / 예비 |
| M01 | CH5 | CN6 | 12 V | 이 채널 최대 2.0 A | Adapter A 전원 입력 → 서보 1개 |
| M01 | CH6 | CN7 | 12 V | 이 채널 최대 2.0 A | 예비; CH5와 병렬 금지 |

정격은 공급 한도이지 부하가 항상 소비하는 전류가 아니다. **J01 CH2+3은 합계1.5 A, CH5+6은 합계0.6 A**이고 **M01 CH5/6은 각각2 A**다. M01 CH1~4의 입력 전류 의존 표기는 무제한 전류라는 뜻이 아니며 배터리·배선·커넥터의 한도를 별도로 지킨다.

배터리 보유 케이블 기준: **배터리 XT60 암 → XT60 수/XT30 수 변환선 → XT30 암 1입력/수 2출력 Y선 → J01 CN1·M01 CN1의 XT30 암**. 각 분기는 +와 − 두 선 모두 연결한다. **Y 분기점은 상부 1단 J01 근처**에 두며, 배터리에서 공통 2심을 올린 뒤 두 PDB로 나눈다. 그림에서도 단일 공통 구간과 두 갈래를 명시한다. CN 단자의 실제 +/− 방향은 기판 실크·커넥터 키로 확인하며 그림의 좌우로 추측하지 않는다.

### 6.3 전력 귀환과 신호 GND

- MD20A VB−는 **M01 CN2(CH1)−**, 어댑터 전원 −는 **M01 CN6(CH5)−**로 직접 귀환한다. 모터·서보 전류를 ESP32 헤더 GND나 센서 점퍼선에 맡기지 않는다.
- GND①~④와 TGND는 장치 사이 신호 기준을 연결한다. GND는 이 회로의 DC 공통 기준이며 벽 콘센트의 보호접지 유무와 별개다.
- IMU·CF의 3.3 V는 ESP32에서만 공급한다. **PDB 3.3 V 출력과 ESP32 3V3를 병렬 연결하지 않는다.** T3V3와 T5V도 합치지 않는다. J01 CN5의 5 V는 ESP32 VIN/5V 또는 Jetson J12와 연결하지 않는다.
- 모터·서보 전력선에는 일반 Dupont 점퍼선이나 브레드보드를 사용하지 않는다. 센서용 전원/신호 분기는 체결·절연을 확보한다.
- 6S 팩의 운용 중 전압이 M01 제조사 입력 하한24 V보다 낮아질 수 있다는 기존 제한, Jetson 공급 한도와 서보 부하 전류는 [전장 기준 §7](APPROVED_ELECTRICAL_LAYOUT.md#7-정격상-주의--승인된-배치를-변경하라는-뜻은-아님)을 따른다. 이번 배선 문서 갱신은 이 운전 조건의 시험 통과가 아니다.

## 7. STOP 스위치 결선과 후속 제어 구현

**11/13 사용자 지시로 STOP 결선을 도면에 반영했다.** 보유품은 `I/O` 표시가 있는 2선 유지형 ON/OFF 스위치다. 아래 두 선을 연결하며 모델·DC 정격 표시는 없는 것으로 기록한다.

| 스위치 | 연결 대상 | 역할 |
|---|---|---|
| 선 1 | **ESP32 GPIO8** | 내부 풀업을 활성화한 정지 입력 |
| 선 2 | **TGND 공통 GND 분배점** | 기존 ESP32 GND②·CF·엔코더·J01 CN5− 접지에 한 갈래 추가 |

**별도 3V3선은 연결하지 않는다.** ESP32의 3V3 2개·GND 4개 배정을 그대로 유지하고, TGND만 4접점에서 5접점으로 늘린다. 선 1/2는 관리명이므로 보유한 수동 2선 접점의 두 선을 각각 배정하면 된다. 전원을 분리한 상태에서 `I=도통`, `O=개방`인지 확인해 차량에 `O=STOP` 표시를 붙인다.

펌웨어에 적용할 동작은 `GPIO8 INPUT + 내부 PULLUP`, `O/개방=HIGH → STOP`, `I/도통=LOW → 구동 허가의 필요조건`이다. 스위치선 단선도 풀업이 동작하는 입력에서는 HIGH로 읽힌다. STOP 때 구동 명령을 차단하고 모터 PWM을 0으로 유지한다. I로 돌려도 자동 출발하지 않으며 기존 `CLEAR → DISARMED → ARM` 절차를 따른다. 서보 전원은 유지되며 별도 정지 처리 정책을 구동 계약에 맞춰 구현한다.

이는 **배선 설계 완료**이며 현재 펌웨어 구현·장착·STOP 실물 시험 완료를 뜻하지 않는다. 정지는 MCU 프로그램 실행에 의존하며 스위치에 모터 전류를 흘리지 않는다.

### 7.1 공식 정지 규정 확인 (2026-11-13, 배선 설계와 구분)

- [현재 공식 MANUAL §5](https://github.com/MOSW626/istech-it-arena/blob/2e41f5674a4c8a611bb65e966ea8827d41611017/MANUAL.md#L193-L199)는 하드웨어 스위치·소프트웨어 스위치 각각 최소 1개와 당일 심판 앞 작동 시연을 요구한다. 항목의 이름은 **원격 비상정지**다.
- 해당 조항에는 배터리/모터 전원 직접 차단, MCU/프로그램과 독립된 회로, 릴레이 사용이 필수라고 명시되어 있지 않다. 따라서 전력선 절단을 규정 의무로 단정하지 않는다.
- 반대로 **GPIO 입력을 MCU가 처리하는 물리 스위치를 HW 스위치로 인정한다는 명시도 없다.** 차량 탑재 스위치와 별도 원격 SW 정지의 조합으로 충분한지, HW 경로도 원격이어야 하는지는 미확인이다. 공식 이슈 16건·댓글 67건을 조회했으며 [회의 결과 #6](https://github.com/MOSW626/istech-it-arena/issues/6#issuecomment-5764291947)에도 세부 회로 정의는 없었다.
- 채택한 배선은 GPIO8 물리 입력이며 별도 원격 SW STOP도 준비한다. 접점 개방/단선 시 정지로 읽고, 스위치 복귀만으로 자동 재출발하지 않는 처리는 팀의 구현 방침이며 공식 규정 문구와 구분한다. 현재 입력·출력 구현이나 검차 통과를 뜻하지 않는다.
- 공식 확인이 필요한 문장: “차량의 2선 물리 스위치를 MCU GPIO로 읽어 모터 정지를 처리하고, 별도로 원격 SW STOP을 제공하는 구성이 HW·SW 스위치 요건을 충족합니까? HW 스위치도 원격 작동 또는 MCU와 독립된 차단을 요구합니까?” 외부 문의는 게시하지 않았다.

[조회·판정 기록](../../artifacts/validation/2026-11-13/wiring_stop_rule_review_v1/source_review.json). 단자가 아닌 전력 경로에 정격 미상의 스위치를 직렬 삽입하거나 PWM 출력을 GND에 단락시키는 안은 채택하지 않는다. 한 장 도면에는 GPIO8·TGND 두 연결선을 표시했다. 규정 해석 미확인을 배선 설계 보류로 취급하지 않으며, 기존 명령 계약의 정지 유지·명시적 재시작 원칙을 따른다.

| 구분 | GPIO | 현재 처리 |
|---|---|---|
| USB-UART UART0 | 43 / 44 | 보드 내부 호스트 통신, 외부 배선 금지 |
| 물리 STOP 입력 | 8 | **결선 설계 반영:** 스위치 선 1, 내부 풀업 입력; 선 2는 TGND |
| 구동 허가 요청 / watchdog | 21 / 47 | 상대 회로 미정, 연결하지 않음 |
| 배터리 ADC | 1 | 분압·보호 미정, 배터리 직접 연결 금지 |
| 선택 고장 입력 / CLEAR 입력 | 2 / 14 | 예약만 유지 |
| 여유 후보 | 7 / 16 / 39 / 40 / 41 / 42 | 39–42는 외부 JTAG와 겸용 |

부팅 strap GPIO0/3/45/46, 메모리 GPIO26–37, native USB19/20은 새 장치에 배정하지 않았다. GPIO38/48은 제조사 미확인 보드의 LED 등 연결 가능성을 고려해 기존 예약을 유지한다. 칩 GPIO 제약과 실제 PCB 배선은 별개다. [Espressif GPIO 안내](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/gpio.html).

GPIO STOP 입력은 MCU 실행에 의존하며 독립 전력 차단 기능을 제공하지 않는다. 이는 기능 차이이며 규정이 독립 전력 차단을 명시했다는 뜻이 아니다. 상대 회로가 없는 예약 핀에 임의로 모듈 단자를 연결하지 않는다. 구현 시 [기존 구동 계약](ACTUATION_CONTRACT_2026_09_22.md)과 `/drive`→독립 보호층→`/drive/safe` 경계를 유지하고, UART/SPI/PCNT/PWM 동시 동작 및 리셋/통신 단절을 실물로 확인한다.

## 8. 문서 검증과 조립 시 확인

이번 갱신은 STOP 포함 GPIO 12개 중복/제외/예약 충돌, 전원 헤더 6개 배정, 3개 분배점의 접속 대상, 두 보드의 CN/CH 대응을 정적으로 검사했다. 부품별 한 장 SVG를 PNG로 렌더링해 글자·단자·분기점과 겹침을 확인했다. 문서 링크·JSON·diff를 검토했으며 이번 작업에서 Jetson/ESP32 접속·펌웨어 변경·장치 구동은 하지 않았다.

1. USB와 각 전원을 분리한 상태에서 3V3①/②·GND①~④를 실물 핀에 배정하고 라벨을 붙인다.
2. 통합 도면의 T3V3/T5V/TGND 표시대로 T3V3/T5V/TGND를 만들고, 특히 J01 CN5−와 ESP32 GND②가 TGND에 함께 연결됐는지 확인한다.
3. 기존 GPIO 배정으로 신호선을 연결하고 STOP 선 1은 GPIO8, 선 2는 TGND에 연결한다. 어댑터 점퍼 두 개는 A, 서보는 3선 전용 케이블을 사용한다.
4. PDB 보드명과 CN 번호, 출력 전압, +/− 극성을 대조한다. 핀/선 순서·색은 도면만으로 추정하지 않는다.
5. 최종 장착 뒤 센서 수신·부하 전류·전체 동시 동작·리셋/통신 단절·STOP을 통합 확인한다. 앞선 개별 벤치 시험을 전체 조립 검증으로 대체하지 않는다.

원본 [JSON](schematics/esp32_gpio_v1.json)과 [생성 스크립트](../../scripts/render_esp32_wiring.py)를 수정한 뒤 `python scripts/render_esp32_wiring.py`로 SVG·HTML·연결표를 재생성한다. PNG는 동일 SVG의 브라우저 렌더 사본이며 통합 도면2740×1930이다. 도면과 펌웨어가 자동 연동되는 것은 아니므로 드라이버 적용 시 다시 대조한다.
