# 실물 Bring-up 및 Calibration Runbook

작성: 2026-11-09  
상태: **실물 시험 절차 초안 — 실제 장치 연결·교정·주행 완료를 의미하지 않음**

이 문서는 현재 저장소의 센서 기록 감사, 구동 계약, 구매·배선 대조 문서를 실제 차량 인수·개별 시험·통합 시험 순서로 연결한다. 기존 계약의 한도나 센서 계수를 임의로 바꾸지 않는다. 각 단계는 원본 측정값·장치 식별·설정·판정·미해결 사항을 보존하고, 통과하지 못한 단계의 다음 구동 단계를 진행하지 않는다.

**중요한 계수 주의:** 10월 문서의 15:1·420 count/wheel rev·0.4862 mm/count는 이전 구성의 이력이다. 현재 현황은 공칭 8.9706:1이다. 따라서 과거 420 count/wheel rev 환산을 실물에 그대로 적용하지 않는다. 28 count/motor rev도 납품 엔코더에서 확인할 가정이다. 공칭비만 곱한 이론값은 약 251.18 count/wheel rev이지만, 실제 기어비·엔코더 체배·유효 구름 둘레를 확인하기 전에는 교정 계수로 채택하지 않는다.

CF-0108은 사용자가 신호 변환용으로 선정한 부품이다. 현재 저장소에는 상세 사양·핀 배열·입력 허용전압·출력 구조·주문/수령/실물 적합성이 확인되지 않았다. 아래 절차의 레벨 변환 단계는 **부품 데이터시트와 보드 실크를 확인한 뒤** 진행한다. 부품명만으로 A/B 배선을 확정하지 않는다.

## 1. 시험 운영 원칙 및 공통 기록

### 1.1 단계별 허가

1. **무전원 검사:** 장치 식별, 기구 간섭, 배선 연속성·극성 확인. 배터리와 USB를 모두 분리한다.
2. **전원 단독 검사:** 전류 제한 가능한 벤치 전원으로 한 전원 레일씩 확인한다. 모터·서보 출력선은 분리하거나 기구적으로 안전한 상태로 둔다.
3. **입력 전용 검사:** MCU/Jetson에 센서만 연결하고 구동 출력은 비활성 상태로 유지한다.
4. **액추에이터 개별 검사:** 구동 바퀴를 지면에서 띄우고 저전압·낮은 출력부터 확인한다. 서보는 링크를 분리한 상태에서 중앙/방향/범위를 확인한다.
5. **차체 고정 시험:** 바퀴를 띄운 상태에서 조향 링크를 연결하고 좌우 끝단·간섭·명령/피드백을 검사한다.
6. **저속 지면 시험:** 넓고 비어 있는 평탄 구역에서 별도 안전 담당자와 물리 STOP 접근을 확보한 뒤 수행한다.
7. **통합 주행:** 센서·제어·통신·STOP 사전 조건을 모두 통과한 경우에만 진행한다.

어느 단계에서도 최초 부팅/USB 연결/통신 복구/MCU 재부팅만으로 모터가 움직이면 안 된다. STOP은 일반 DRIVE보다 우선하고, 버튼 해제나 링크 복구만으로 자동 재출발하지 않아야 한다. 실물에서 확인되지 않은 제동 방식을 비상정지로 간주하지 않는다.

### 1.2 모든 세션에 남길 정보

- 날짜/시간(KST), 작업자·안전 담당자, 시험 장소, 단계 ID, 성공/실패/중단.
- 부품 제조사·정확한 모델·PCB revision·시리얼/서보 ID·펌웨어/SDK/드라이버 버전.
- 전원 공급원, 설정 전압, 전류 제한, 시작/최저/최고 전압, 관측 전류·온도.
- 배선 사진(개인정보·주변 환경 제거), 커넥터 핀 배열, 케이블 길이/굵기, 접지점.
- 명령값과 **실제 측정값을 별도 필드로** 기록. 명령을 측정값으로 복사하지 않는다.

### 2.2 배선표 작성

각 연결을 `전원+`, `GND`, `신호/데이터`로 구분하고 양끝 핀 번호를 적는다. 색상만으로 핀 기능을 추정하지 않는다.

특히 다음을 전수 확인한다.

- 배터리 XT60, XT30 변환선/Y선, PDB J01/M01의 실제 수·암, 극성, 허용전류.
- J01→Jetson 전원선, M01→MD20A 전력선, MD20A→모터 2선, 서보 어댑터 전원선.
- VND018 USB-UART(CH343P) 포트와 직접 USB 포트를 구분하고 데이터 지원 케이블인지 확인.
- PGE-213의 전원/GND/A/B 핀을 기판 실크·판매 자료·실측으로 대조.
- CF-0108의 입력측/출력측, 채널 방향, 전원 핀, GND 공통 여부, 입력/출력 논리 수준, pull-up 필요 여부를 데이터시트와 보드로 확인.
- LSM6DSOX의 실제 SPI/I²C 선택과 CS/INT 핀을 확인한다. 현재 GPIO 표는 문서 기반 배치 후보이며 실물 PCB 판본과 연속성 검사가 우선이다.

**통전 금지 조건:** 극성 불명, 단락, 전원 레일 혼선, 커넥터 강제 체결, 노출된 맨선 접촉, 전류 정격 미확인, GND 경로 미확인 중 하나라도 있으면 배터리를 연결하지 않는다.

## 2.3 조향 서보 전원 선행 조건

Bus Servo Adapter (A)는 전압을 낮춰 주는 DC-DC 강압기가 아니다. 제조사 문서상 ST 계열 사용 입력 범위는 9–12.6 V이며, 어댑터 출력은 입력과 같은 전압이다. 어댑터의 허용 전류는 최대 5 A이고, USB-C는 통신용이지 서보 전원 공급용이 아니다. 따라서 **6S 배터리(공칭 22.2 V)를 어댑터에 직접 연결하면 안 된다.** VND018의 5 V도 서보 전원으로 사용하지 않는다.

- 서보 전원은 어댑터 입력 허용 범위와 ST3215-HS의 실제 정격이 겹치는 안정된 별도 레일로 공급한다.
- PDB에 해당 전압 출력이 실제로 있는지 회로/측정으로 확인한다. 없다면 정격·과도응답·발열·전류 여유가 확인된 DC-DC 강압기를 별도로 사용한다. 단순 XT30 변환선은 전압을 낮추지 않는다.
- 전원 레일의 무부하/서보 이동 중 전압, 순간 전류, 커넥터/강압기 온도를 기록한다. 어댑터 5 A 한도를 넘지 않도록 하며, 정격 확인 전 stall 시험은 하지 않는다.
- 어댑터의 전원 입력과 UART/USB 통신 경로를 구분한다. USB 연결만으로 서보가 정상 전원 공급된다고 판단하지 않는다.

제조사 근거: [Bus Servo Adapter (A) 사양](https://docs.waveshare.com/Bus_Servo_Adapter_A), [전원·통신 배선 예시](https://docs.waveshare.com/Bus_Servo_Adapter_A/Product-Wiring-Example), [FAQ — 출력 전압/최대 전류/레귤레이터 없음](https://docs.waveshare.com/Bus_Servo_Adapter_A/FAQ).

### 현재 저장소에 기록된 임시 전원·통신 토폴로지

아래는 [구매·케이블 대조 문서 §3.6](PROCUREMENT_AND_CABLES_2026_11_08.md#36-전원-분기와-stop)와 [ESP32 인터페이스 검토](ESP32_BUDGET_REVIEW_2026_10_02.md)의 연결 관계를 합쳐 표시한 것이다. **서보 전원은 M01 CH5 또는 CH6 단일 12 V 채널을 우선 시험 후보로 두며, 실제 부하 적합성은 미검증**이다.

```text
6S 배터리 21.0~25.2 V
  └─ XT60↔XT30 변환선 + XT30 Y 분기
       ├─ J01 (입력 사양 21~36 V)
       │    ├─ CH1 19 V ───────────────→ Jetson Orin Nano Super
       │    ├─ CH4 5 V, 0.5 A ────────→ 예비 (현재 엔코더 전원에 사용하지 않음)
       │    └─ CH2/CH3 5 V, 합계 1.5 A → 예비 (필요 시)
       │
       └─ M01 (입력 사양 24~36 V; 6S 방전 구간은 사양 밖)
            ├─ CH1~4 배터리 전압 직결 → MD20A → MB4266 모터
            └─ CH5 또는 CH6 12 V, 2 A → 서보 어댑터 DC 입력 (조건부 실측)
                                               └─ ST3215-HS 1개

Jetson USB-A ──데이터+5 V──→ VND018 USB-UART USB-C (ESP32 전원/통신)
VND018 3.3 V ─────────────→ Adafruit 4438 IMU VIN (기존 핀 계획)
Jetson J12 pin 2 또는 4 (5 V) + pin 6 또는 9 (GND) ─→ PGE-213 엔코더 VCC/GND
PGE-213 A/B ──→ CF-0108(사양·핀 배열 확인 후) ──→ VND018 GPIO4/5
VND018 UART TX/RX/GND ────→ Bus Servo Adapter (A) UART
Bus Servo Adapter (A) 서보 포트 ─→ ST3215-HS 1개
```

VND018은 Jetson USB-A→USB-C 데이터 케이블 한 개로 전원과 UART 통신을 함께 공급하는 기존 구성을 우선한다. IMU는 VND018의 3.3 V 핀을 사용한다. VND018의 실제 사진에서는 헤더가 `5Vin`으로 표기되어 있고 `IN-OUT` 점퍼를 확인할 수 없다. USB 전원 상태에서 이를 엔코더용 5 V 출력으로 사용할 수 있다고 가정하거나 점퍼를 납땜하지 않는다. 엔코더 전원은 Jetson Orin Nano Developer Kit의 40핀 확장 헤더 J12를 사용한다. PGE-213은 5 V·14–20 mA이며, NVIDIA가 명시한 J12 5 V 공급 한도 0.5 A 안에 충분히 들어간다. Jetson J12 pin 2 또는 4를 VCC에, pin 6 또는 9를 GND에 연결한다. 공통 GND 및 A/B 레벨 변환이 필요하다.

서보는 우선 M01의 CH5 또는 CH6 중 **한 채널만** 사용해 12 V를 Bus Servo Adapter (A)의 DC 5.5×2.1 입력 또는 2P 나사 단자에 공급하는 것이 현재 부품으로 가능한 현실적인 경로다. XT30 수 피그테일을 DC 5.5×2.1 수 플러그 또는 나사 단자로 연결한다. 단, ST3215-HS의 stall 2.4 A가 채널 정격 2 A보다 높으므로 stall/기계적 끝단 시험은 금지하고, 낮은 토크·자유로운 링크 상태에서 전압 강하와 전류를 측정한다. M01의 6S 저전압 입력은 명시 정격 밖이므로 실제 팩 전압 구간에서 12 V 유지 여부를 관찰한다. **CH5와 CH6을 병렬 연결하지 않는다.** 이 시험에서 전압 강하·리셋·과열·전류 제한이 나타나면 그때 별도 DC-DC를 검토한다.

### 전체 회로 교차검토 — 2026-11-10

**NVIDIA J12 5 V 상한 해석:** Carrier Board Specification Table 3-3에는 J12 pin 2/4에 1 A가 적혀 있으나 Table 5-3의 connector-per-supply 한도는 0.5 A다. 본 설계는 더 낮은 **0.5 A**를 적용한다. 엔코더 14–20 mA는 이 보수적 상한의 4% 이하다. J12의 3.3 V 헤더는 Table 5-3상 0.1 A이므로 IMU 전원을 Jetson 3.3 V 헤더로 옮기지 않는다.

**B0390 전원 주의:** Arducam B0390 공식 판매 사양은 peak current 300 mA, NVIDIA carrier spec은 camera connector VDD_3V3_SYS 260 mA/connector다. 이 값은 측정 조건·실제 납품품에서 다를 수 있으나 문서상 한도를 초과하므로 단순 호환으로 취급하지 않는다. CSI VCC 핀에 별도 3.3 V를 임의 주입하지 않는다. 카메라 실측 또는 제조사 확인 후 필요하면 전원 주입이 안전하게 설계된 CSI 인터페이스를 검토한다.

**Jetson 전원 주의:** J01 CH1 2.3 A는 팀 공식 PDB 문서가 인용한 부팅 3 A보다 작다. NVIDIA carrier board는 DC jack 9–20 V를 허용하고 DCJ_IN 전류 능력을 별도로 명시하지만, 이것이 J01 2.3 A 출력으로 부팅된다는 보증은 아니다. Jetson 단독 부팅, 저전력 모드, 카메라/C1/ESP32 추가 순으로 시험하고 19 V 최저값·입력 전류·부팅 실패·전원 관련 throttling을 기록한다.

**M01 전원 주의:** 공식 PDB 문서는 M01 24–36 V 입력과 6S 21–25.2 V 사이의 차이를 명시한다. CH1~4는 입력 pass-through이므로 낮은 전압도 통과할 것으로 추정하지만, CH5/6 12 V buck이 24 V 미만에서도 규정 출력을 유지하는지는 제조사 확인이 아니다. 주행 팩 전압 구간에서 12 V 출력의 regulation·리셋·온도·전류를 측정해야 한다.

**서보 전원 주의:** M01 12 V/2 A는 단일 ST3215-HS의 2.4 A locked-rotor current보다 낮다. M01 12 V 채널을 사용한 저부하 초기 시험은 가능할 수 있지만, stall/기계적 끝단/고부하 조향 시험을 하지 않는다. 정상 조향에서 전류 피크가 2 A를 넘거나 전압 강하가 생기면 즉시 중단한다. CH5/CH6 병렬 연결 금지. 최종 운용에는 배터리 전압 범위 전체에서 동작하는 별도 12 V DC-DC와 충분한 전류 여유가 필요할 수 있다.

#### C. 독립 하드웨어 STOP — 필수 미완성 회로

공식 대회 MANUAL §5는 하드웨어 스위치와 소프트웨어 스위치를 각각 요구하고 검차 시 시연하도록 한다. 현재 GPIO8은 STOP 상태 입력일 뿐이며, GPIO21 구동 허가와 GPIO47 watchdog은 외부 회로에 연결되지 않았다.

- MCU의 GPIO/펌웨어와 독립적으로 모터 구동을 억제하는 물리 경로가 필요하다.
- MD20A PWM LOW는 제동 동작이므로 MCU PWM 핀을 물리 스위치로 직접 단락하지 않는다. MCU 핀 손상 없이 fail-safe low가 되도록 절연/게이팅 및 pull-down을 설계하고, MD20A의 실제 정지 전류·제동 응답을 검증한다.
- 모터 전원 차단 방식을 택하면 DC 정격과 모터 기동/고장 전류에 맞는 차단 소자·커넥터·배선이 필요하다. 일반 소형 푸시버튼을 모터 전력선에 직접 넣지 않는다.
- USB 분리, Jetson 종료, MCU 재부팅, watchdog 정지, 물리 STOP 각각에서 모터가 재출발하지 않는지 확인한다. CLEAR와 ARM은 분리한다.
- **하드웨어 STOP 회로가 구현·검증되기 전에는 실차 주행 승인 불가.**

### USB로 VND018 전원 공급 및 Jetson 포트 부하

VND018의 CH343P USB-UART 포트에 Jetson USB-A를 연결하면 USB 5 V로 보드 전원을 공급하면서 UART 데이터도 함께 주고받는다. 따라서 J01 CH4 5 V를 VND018 보드 전원으로 별도 연결하지 않는다. **다만 사용자의 실제 보드는 5 V 헤더가 `5Vin`이고 IN-OUT 점퍼는 확인되지 않는다.** V1.4 회로의 점퍼 개조를 실물 확인 없이 적용하지 않는다. 전원 출력 여부를 계측하고 별도 엔코더 공급원과 전원 중복/역급전을 주의한다.

NVIDIA Orin Nano Developer Kit의 USB-A는 4개이며, 위아래로 쌓인 포트 한 쌍의 VBUS 제한은 합계 3 A다(포트 하나당 3 A가 아님). C1과 VND018은 USB 전원을 쓰므로 가능하면 서로 다른 USB 스택에 연결한다. USB 장치와 다른 주변기기를 추가한 뒤 Jetson 부하·USB 재연결·전압 강하를 확인한다. [NVIDIA USB 포트 사양](https://docs.nvidia.com/jetson/orin-nano-devkit/user-guide/latest/hardware_layout.html).

**센서 전원 정리**
- B0390: CSI 커넥터를 통해 Jetson에서 공급.
- RPLIDAR C1: Jetson USB에서 전원과 데이터를 함께 공급.
- LSM6DSOX: VND018 3.3 V 레일 사용(기존 SPI 배선안).
- PGE-213: 5 V, 판매 사양 14–20 mA. Jetson J12 pin 2 또는 4(5 V), pin 6 또는 9(GND)에서 공급한다. 40핀 헤더의 5 V 공급 한도는 총 0.5 A이며 엔코더 부하에 충분하다. VND018의 `5Vin` 헤더/IN-OUT 점퍼는 사용하지 않는다. A/B는 CF-0108 적합성 확인 후 3.3 V로 변환해 ESP32 GPIO4/5에 입력.

### 11/10 실물 사진 확인: VND018 5Vin과 엔코더 전원 경로

**사용자 실물 사진 기준으로 VND018의 5Vin 헤더를 USB 5 V 출력으로 사용하지 않는다.** 앞면 아래 양쪽 헤더는 `5Vin`으로 표기되어 있고, 뒷면에는 `USB-OTG` 2패드가 보이며 `IN-OUT` 표기는 확인되지 않는다. ESP32 모듈의 `ESP32-S3-WROOM-1 V1.3` 표기는 모듈 표기이지 캐리어 PCB 리비전의 증거가 아니다. V1.4 회로의 IN-OUT/D26 점퍼를 실물에 추정 적용하거나 납땜하지 않는다.

**엔코더 5 V 전원은 Jetson 40핀 확장 헤더 J12를 사용한다.** NVIDIA Orin Nano Developer Kit Carrier Board Specification SP-11324-001 v1.2:
- J12 pin 2 및 pin 4: Main 5.0 V supply.
- J12 pin 6 및 pin 9: GND.
- Table 5-3: J12 40-pin header의 VDD_5V_SYS 공급 한도 **0.5 A**.
- PGE-213 판매 사양 소비전류 14–20 mA이므로 이 공급 한도에 충분한 여유가 있다.

연결은 Jetson J12 pin 2 또는 4 → PGE-213 VCC, J12 pin 6 또는 9 → PGE-213 GND로 한다. Jetson은 J01 19 V로 전원을 공급받으므로 J12 5 V는 Jetson 캐리어 보드의 시스템 5 V 레일이다. 40핀 헤더의 GPIO 신호 핀은 3.3 V 논리이며, pin 2/4는 GPIO가 아니라 전원 핀이다.

PGE-213 A/B는 5 V pull-up 신호이므로 ESP32 GPIO4/5에 직접 넣지 않는다. 기존 CF-0108의 실제 입력·출력 정격과 핀 배열을 확인한 뒤 5→3.3 V 레벨 변환을 거친다. Jetson과 VND018은 USB 케이블로 연결되어 있으므로 GND 기준이 공유되지만, 엔코더와 레벨 변환 회로의 GND를 명시적으로 공통 연결한다.

**이 구성에서는 VND018의 5Vin을 엔코더 전원으로 사용하지 않으며, IN-OUT/USB-OTG 패드를 납땜하지 않는다.** J01 CH4 5 V는 엔코더 전원에 사용하지 않고 예비로 남긴다.

NVIDIA 근거: [Jetson Orin Nano Developer Kit Carrier Board Specification — §3.3, Table 3-3, §5, Table 5-3](https://developer.nvidia.com/downloads/assets/embedded/secure/jetson/orin_nano/docs/jetson_orin_nano_devkit_carrier_board_specification_sp.pdf). PGE-213의 소비전류와 A/B 출력은 구매·케이블 대조 문서 및 판매 회로를 기준으로 하며 실제 납품품의 파형은 별도 확인한다.

### 지급 PDB의 서보 전원 한계

[공식 지급 PDB 사양](https://github.com/MOSW626/istech-it-arena/blob/main/docs/hardware/power-modules.md)은 Preliminary 판이며 다음을 명시한다.

- J01: 19 V CH1 최대 2.3 A, 5 V CH2/CH3 합계 1.5 A, 5 V CH4 0.5 A, 3.3 V CH5/CH6 합계 0.6 A.
- M01: 입력 24~36 V, CH1~4는 입력 전압 직결, CH5/CH6은 12 V 각 2.0 A.
- 우리 배터리 6S 22.2 V는 공칭 전압에서 M01 입력 하한 24 V보다 낮다. 만충 25.2 V일 때만 사양 범위에 들어가며, 방전 중 전압이 내려가면 정격 범위를 벗어난다. CH5/CH6이 낮은 입력에서도 12 V를 유지할 수 있다는 추정은 제조사 확인이 아니다.
- 구매·케이블 대조 문서의 단일 ST3215-HS 사양은 **6–12.6 V, 무부하 240 mA, 구속(stall) 2.4 A**다([Waveshare 제품 사양](https://www.waveshare.com/st3215-hs-servo-motor.htm)). 과거 전원 모듈 문서의 2개 서보 합계 4 A는 현재 구성의 단일 서보 정격이 아니므로 적용하지 않는다.
- M01 CH5/CH6은 12 V 각 2.0 A이므로 **단일 서보의 2.4 A 구속 전류보다 낮다.** 구속 시험을 하지 않더라도 기동/급격한 부하에서 여유가 부족할 수 있어 단일 서보 전원으로 적합하다고 승인할 수 없다.
- M01 전체 입력은 24–36 V이고 6S 배터리는 만충 25.2 V, 공칭 22.2 V다. 따라서 배터리 전압이 내려가면 보드의 명시 입력 범위 밖에서 운용된다. 12 V 강압 채널이 입력 하한 미만에서도 정상 regulation을 유지하는지는 공식 문서에서 보증하지 않는다. 단순히 'buck이므로 될 것'이라고 가정하지 않는다.

**현재 실물 시험 권장안:** 추가 구매 없이 M01 CH5 또는 CH6 중 한 채널의 12 V를 먼저 시험한다. 이는 정격 여유가 충분하다고 승인한 것이 아니라, 단일 서보의 실제 조향 부하가 2 A 안에서 동작하는지 제한된 시험으로 확인하는 임시 경로다. 서보를 기계 끝단에 밀어 넣거나 stall시키지 말고, 낮은 토크/속도에서 전압·전류·온도를 기록한다. 2 A 초과·전압 강하·리셋·과열이 관찰되면 즉시 중단하고 별도 6S 입력 대응 DC-DC를 검토한다. M01 입력 24–36 V 정격과 6S 배터리의 방전 전압 불일치는 여전히 미해결 위험이다. **M01 CH5/CH6 병렬 연결 및 6S 배터리의 서보 어댑터 직결은 금지한다.**

## 3. 1단계 — 전원 레일과 독립 STOP 확인

### 3.1 배터리/PDB/전원 분배

1. 배터리를 분리한 상태에서 멀티미터로 배터리·변환선·Y선·PDB 입력/출력의 극성을 각각 확인한다.
2. 배터리 공칭 6S 22.2 V라는 문구만 믿지 말고 실측 전압을 기록한다. 완충 전압과 각 부품 입력 허용 범위도 데이터시트로 대조한다.
3. 처음에는 배터리 대신 전류 제한 벤치 전원을 사용한다. 전압은 각 장치의 명시된 입력 범위에 맞추고, 전류 제한은 해당 장치/시험 단계에 맞춰 보수적으로 설정한다.
4. PDB J01/M01 출력 전압, 무부하 전압, 부하 인가 시 전압 강하·전류·발열을 각각 기록한다.
5. Jetson, MCU, 서보, MD20A 논리/모터 전원은 각각 어떤 레일에서 공급되는지 블록도로 남긴다. 서보의 기동/부하 전류가 MCU/Jetson 전원 레일을 끌어내리지 않는지 확인한다.
6. USB 연결로 인한 역급전 가능성을 확인한다. 외부 전원과 USB 전원을 동시에 연결하기 전에 보드의 전원 경로를 확인한다.

전원 공급 정격, 퓨즈/차단 소자, 전선 굵기, 커넥터 허용전류가 검증되기 전에는 모터 stall·서보 stall 시험을 하지 않는다. Bus Servo Adapter (A)에 6S 배터리를 직접 연결하지 않는다.

### 3.2 물리 STOP / 소프트웨어 STOP

- 물리 버튼의 NO/NC 접점, 눌림/해제 논리, 배선 단선 시 상태를 측정한다.
- 버튼이 ESP32 GPIO에 상태만 전달하는지, 구동 허용/전력 경로를 실제로 차단하는지 회로를 구분해 그린다. GPIO 입력만으로 독립 하드웨어 차단이 완성됐다고 쓰지 않는다.
- 모터 출력이 안전하게 억제되는지 바퀴를 띄운 상태에서 낮은 출력으로 시험한다. STOP을 누르면 명령 수신·일반 제어 주기와 무관하게 정지 경로가 우선되어야 한다.
- Jetson 프로세스 종료, USB 분리, MCU 재부팅, 명령 만료, STOP 버튼 눌림을 각각 따로 시험한다.
- STOP 해제·통신 복구·재부팅 뒤에는 DISARMED/정지 고정 상태를 유지하고, 명시 CLEAR → 별도 ARM 전까지 구동이 없어야 한다.
- 정지 요청 수신, MCU 정지 상태, 모터 출력 억제, 실제 차체 정착은 서로 다른 증거로 기록한다.

실제 차체 정지거리는 외부 영상/거리 측정으로 확인한다. 단일 모터축 엔코더 0 count는 차체 정지 증명이 아니다.

## 4. 2단계 — MCU·통신만 먼저 올리기

### 4.1 VND018 확인

1. PCB 판본, USB 포트 명칭, 칩/메모리, 납땜 헤더를 기록한다.
2. 모터·서보·센서를 분리하고 데이터 USB로 PC/Jetson에 연결한다.
3. 포트 식별, 재연결, 부팅 로그, 펌웨어 업로드/리셋, GPIO high/low, watchdog 동작을 확인한다.
4. 저장소의 핀 배치 후보(GPIO 4/5 엔코더, 15/6 MD20A PWM/DIR, 12/11/13/10 IMU SPI, 9 INT1, 17/18 서보 UART, 8 STOP, 21/47 구동 허가/watchdog, 1 ADC)는 실물 회로도/보드 판본과 대조하기 전까지 확정 핀맵으로 사용하지 않는다.
5. USB-UART와 직접 USB의 전원/데이터 역할, 부트 스트랩 핀, 외부 회로 연결 시 부팅 실패 여부를 기록한다.

### 4.2 Jetson↔MCU 링크

- 우선 유선 USB-UART로 시작한다. 무선 네트워크/노트북 중계는 첫 연결 시험에 넣지 않는다.
- 출력 비활성 상태에서 MCU 상태 조회, host→MCU 명령 프레임, MCU→host 상태 응답을 확인한다.
- 분할 프레임, 연속 프레임, CRC 오류, 잘못된 길이, 중복/역순 seq, 재부팅 boot ID 변경, USB 분리/재연결을 시험한다.
- 실제 명령 전송 시각·원래 목표 생성 시각·MCU 수신 시각·응답 시각을 각각 기록한다. MCU 수신 시각을 센서 취득 시각으로 대신 쓰지 않는다.
- 저장소의 임대/TTL 계약을 포팅한 뒤 명령 만료·STOP 우선·재부팅 후 자동 ARM 금지를 확인한다. 참조 구현의 100 ms/50 ms/500 ms 등은 실물 안전 합격값이 아니며, 측정 없이 완화하지 않는다.
- PC 참조 구현과 MCU 포팅 결과는 동일 입력/기대 출력 벡터로 대조한다.

## 5. 3단계 — 센서별 개별 연결·교정

각 센서는 처음에 **구동 출력 비활성**으로 연결한다. ROS 메시지의 정상 발행과 물리 교정 통과를 별도 판정한다.

### 5.1 모터축 엔코더 PGE-213 + CF-0108

**전기 인터페이스 검사**

1. PGE-213의 전원 전압과 A/B 출력 구조(open-collector/push-pull 등)를 실물 회로/데이터시트로 확인한다.
2. 엔코더 VCC/GND만 연결해 전류와 전압을 확인한다. A/B 신호는 오실로스코프/로직 분석기 또는 고임피던스 측정기로 확인한다.
3. CF-0108 데이터시트·핀 배열을 확인하고, 5 V 전원은 엔코더에 유지하며 A/B 신호만 ESP32 입력 허용 범위로 변환하는 구성이 맞는지 확인한다.
4. CF-0108의 각 채널 방향과 전원 요구가 확인되기 전에는 5 V 신호를 ESP32 GPIO에 직접 연결하지 않는다. 보드가 양방향 자동 감지형인지, 방향 고정형인지, 입력에 pull-up이 필요한지 이름만 보고 추정하지 않는다.
5. 엔코더를 손으로 천천히 회전시켜 A/B 파형, 위상차, 펄스 누락, 카운트 부호를 확인한다. MCU PCNT의 glitch filter는 정상 최소 펄스 폭보다 짧게 설정한다.

**계수·부호 교정**

- 모터축에 기준 표시를 하고 정해진 방향으로 정확히 N회전시켜 누적 카운트 변화량을 기록한다. 양방향으로 반복해 부호와 대칭성을 확인한다.
- 실측 count/motor rev와 데이터시트 28 count/rev 가정을 비교한다. 다르면 실측 원인(7 PPR 정의, 2/4체배, 출력 에지, 누락)을 먼저 찾는다.
- 바퀴를 띄운 상태에서 모터축 회전과 바퀴 회전수를 각각 세어 실제 감속비를 구한다. 8.9706:1은 공칭값으로만 보관한다.
- 바닥에 기준 거리를 표시하고 직진 이동시켜 실제 이동거리/누적 count를 측정한다. 타이어 변형·유효 반경·기어비·슬립이 포함되므로 단순 외경 계산값과 비교한다.
- 전진/후진, 저속/중속에서 반복하고 원시 누적 count·취득 시각·수신 시각·seq·boot를 보존한다.

**환산식**

`counts_per_wheel_rev = counts_per_motor_rev × measured_gear_ratio`

`distance_per_count = measured_effective_wheel_circumference / counts_per_wheel_rev`

`wheel_speed = Δcounts × distance_per_count / Δacquisition_time`

단일 모터축 하나로 좌우 바퀴 개별 속도, 차동기 양쪽 회전, 차체 정지, 바퀴 슬립을 관측할 수 없다. 따라서 해당 신호를 좌우 속도나 차체 속도로 꾸며내지 않는다.

### 5.2 IMU LSM6DSOX

1. 보드 전원·통신 버스·주소/CS·INT1·실제 보드 판본을 확인하고 WHO_AM_I 등 장치 식별 레지스터를 읽는다.
2. ODR, full-scale range, 내부 LPF/FIFO, timestamp/data-ready 설정을 명시하고 원시 register/설정값을 보존한다.
3. 차량을 평평한 기준면에 고정하고 각 축의 +방향을 하나씩 확인한다. x/y/z를 각각 위·아래·좌·우로 돌려 가속도/각속도 부호를 기록한다.
4. 차량 좌표계(base_link)와 센서 좌표계(imu_link)의 회전 관계를 실측 장착 방향으로 정의한다. frame 이름을 맞춘 것만으로 축 교정이 끝난 것은 아니다.
5. 외부에서 움직이지 않도록 고정한 구간을 별도 기록해 gyro bias 후보를 계산한다. 충분한 시간·표본·최대 샘플 간격 조건을 기록하고 온도도 함께 남긴다.
6. 수동으로 알려진 각도만큼 회전시켜 yaw rate의 부호·단위(rad/s 또는 deg/s)와 적분량을 확인한다. 90°/180° 등 기준 회전에서 누적 yaw와 외부 각도계를 비교한다.
7. 정지·진동·모터 전원 ON/OFF·서보 작동 조건에서 잡음과 bias 변화를 따로 기록한다. 모터/전원 노이즈와 실제 회전을 혼동하지 않는다.

초기 교정 후보는 자동 적용하지 않는다. 자이로 bias/축 변환/필터 계수 변경은 원본 데이터와 전후 비교를 보존하고 별도 검토 후 반영한다.

### 5.3 RPLIDAR C1

1. USB 어댑터·케이블·전원 경로와 장치 식별을 확인하고, 모터/서보 출력 비활성 상태에서 드라이버를 올린다.
2. 실제 SDK/드라이버 버전, scan mode, sample rate, 회전 방향, 각도 범위, 거리 단위, 무응답/무반사 표기를 기록한다.
3. 벽의 직선 거리 2~3개를 줄자로 측정해 각도별 거리값과 비교한다. 검은색/반사 표면·근거리·원거리에서 이상값을 분리한다.
4. 센서를 수평으로 고정하고 0° 기준 방향과 회전 방향을 확인한다. 차량의 전방/좌측 좌표계로 변환한 결과를 물리 기준선과 비교한다.
5. C1의 timestamp가 스캔 시작/종료/각 점 중 어디에서 생성되는지, SDK가 점 순서를 정렬/재배열하는지 확인한다. host callback 수신 시각을 점별 취득 시각으로 간주하지 않는다.
6. 센서를 정지한 채 반복 측정한 뒤 손으로 일정 각도 회전시켜 순차 취득 시각·scan skew·IMU/엔코더 보정 방향을 대조한다.

C1은 순차 취득의 시간 오차가 운동 보정에 직접 영향을 준다. 실제 timestamp 위치와 드라이버 계약을 확인하기 전에는 운동 보정 계수나 신선도 한도를 조정하지 않는다.

### 5.4 Arducam B0390 RGB 카메라

1. 전원 OFF 상태에서 CSI 리본 접점 방향과 Jetson 포트를 확인하고, 고정/렌즈 방향·초점·시야각을 기록한다.
2. Jetson에서 실제 인식된 카메라·센서 모드·해상도·FPS·노출·gain·white balance·PTS/sequence를 수집한다. 시뮬의 1280×720·60 Hz는 실물 사양 보증이 아니다.
3. 컬러 차트/빨강·초록 LED·ArUco ID를 고정 거리·조명에서 촬영한다. RGB/BGR 순서, row stride/padding, 영상 회전/반전, 왜곡, 화각을 확인한다.
4. 정지 장면과 차량/마커 이동 장면을 분리해 motion blur·노출 변화·검출 누락·촬영 시각과 수신 시각 차이를 기록한다.
5. 실제 camera timestamp의 clock domain과 PTS 의미를 확인한다. ROS header stamp가 callback 시각으로 대체되지 않는지 확인한다.
6. 기록 영상에서 기존 신호등/ArUco 검출기를 먼저 평가한 뒤, 실시간 노드로 연결한다.

### 5.5 버스 서보 ST3215-HS 1개 및 실제 조향각 교정

**이 차량의 조향 액추에이터는 ST3215-HS 서보 1개다. 이 서보가 실제로 어떤 혼·링크·너클 구조를 구동하는지는 현재 문서만으로 확정할 수 없으므로 CAD와 조립된 실물에서 확인한다. 좌우 바퀴가 어떤 기구로 연동되고 각도가 어떻게 달라지는지도 측정으로 확인한다.** 이 단계가 조향 교정의 핵심이다. 제어기의 `steering_rad`는 차량 모델 기준 목표 조향각이지 서보 명령 위치나 실제 바퀴각이 아니다. 서보 내부 위치 피드백(읽을 수 있는 경우)도 혼/출력축 위치이며, 링크·너클 뒤의 타이어 진행 방향과 동일하다고 가정하지 않는다.

**A. 서보 단독 식별**

1. 단일 서보의 ID, 모델, 펌웨어, 통신속도, 응답 패킷/위치 단위, 전원 범위를 읽어 기록한다.
2. Bus Servo Adapter (A)의 전원 입력·UART TX/RX·자동 방향 전환·서보 전원 경로를 확인한다. ESP32 GPIO 17/18은 현재 배치 후보일 뿐 실물 핀 연속성 확인 후 사용한다.
3. 서보 혼/링크를 분리한 상태에서 현재 위치와 동작 모드를 먼저 읽는다. 임의의 절대 중앙값으로 이동시키지 말고 현재 위치 주변의 작은 상대 이동만 명령한다. 명령 위치, 응답 위치, 전류, 이동시간, 정착시간, 온도를 기록한다.
4. 작은 양·음 방향 명령을 여러 번 반복해 명령-응답 방향, deadband, backlash, 반복 오차, 통신 실패를 확인한다.
5. 기구적 끝단까지 밀어 stall시키지 않는다. 기구 간섭·전류 급증·온도 상승·비정상 소음이 발생하면 즉시 정지한다.

**B. 바퀴 실제 각도 측정**

1. 차체를 수평 기준판에 고정하고 앞바퀴 아래에는 회전판(turn plate) 또는 각도 눈금을 둔다. 차체는 움직이지 않게 하되 조향 링크와 너클은 자유롭게 움직이게 한다.
2. 바닥에 차체 중심선과 각 바퀴의 직진 기준선을 표시한다. 타이어의 한 점만 재지 말고 휠 평면/허브 기준으로 방향을 측정한다.
3. 휠 허브/휠 평면에 각도 기준자를 부착하거나, 위에서 촬영한 휠 중심선과 기준선을 비교해 실제 바퀴 방향을 측정한다. 각도계가 타이어 곡면에 안정적으로 붙지 않으면 타이어 옆면이 아니라 허브/휠 평면을 기준으로 한다. 직진(0°), 작은 좌/우, 중간 좌/우 위치를 기록한다.
4. 단일 서보 명령을 각 위치에서 멈춘 뒤 좌·우 바퀴각을 각각 읽어 기록한다. 한 개의 서보 혼/링크가 실제로 어떤 기구를 움직이는지, 좌우 바퀴가 함께 움직이는지, 방향과 각도 비율이 어떻게 되는지 실물에서 확인한다. 좌우 측정은 같은 명령 위치에서 반복한다.
5. 좌우 끝단은 기구적 간섭이 없는 범위에서만 천천히 접근한다. 타이어/링크/서보 혼/차체 간섭, 과도한 전류, 링크 over-center가 생기기 전에 제한한다.
6. 직진 명령을 반복해 영점 편차와 히스테리시스를 측정한다. 좌회전/우회전 접근 방향별 결과를 따로 기록한다.

**C. 명령-각도 매핑**

- `steering_rad=0`에서 좌우 바퀴가 실제 직진하는 단일 서보 명령 위치를 찾는다.
- `steering_rad` 양수는 차량 좌회전이라는 계약을 유지한다. 양수/음수 입력에서 실제 바퀴가 어느 방향으로 도는지 확인하고 부호가 반대면 **MCU 펌웨어의 조향 명령 변환 계층**에서 명시적으로 부호를 변환한다. Bus Servo Adapter (A)는 UART 통신/전원 인터페이스이며 차량 조향각을 자동 변환하는 장치가 아니다.
- 여러 점의 `(steering_rad, servo_command, left_wheel_angle, right_wheel_angle)` 데이터를 수집한다. 중앙 부근과 좌/우 끝단 사이의 비선형성·유격을 확인하고, 필요하면 구간별 보간표를 사용한다.
- 차량 모델의 단일 조향각과 실제 Ackermann 좌우 바퀴각은 구분한다. 축거·윤거 실측값을 사용해 기하학적으로 기대하는 안쪽/바깥쪽 바퀴각과 실측을 비교한다. 링크가 Ackermann 조건을 만족한다고 가정하지 않는다. 조향 링크 구조가 도면/실물로 확인되기 전에는 좌우 바퀴가 완전한 Ackermann 관계를 갖는다고 전제하지 않는다.
- 좌우 최대 조향각, 좌우 비대칭, servo rate limit, 명령-실제 각도 지연을 측정한다. 최소 회전반경은 정지 상태의 각도만으로 확정하지 말고, 측정한 축거·바퀴각으로 우선 계산한 뒤 저속 원호 주행에서 외부 궤적을 재어 확인한다.
- 저장소의 가상 조향 속도 3 rad/s, 관절 한계 ±0.45 rad 등은 실물 서보 한계가 아니다. 측정 전 실물 파라미터로 복사하지 않는다.

**D. 시간 응답**

1. 작은 각도 step 입력을 주고 명령 송신 시각, 서보 응답 시작, 목표 위치 도달, 실제 타이어각 정착 시각을 별도 기록한다.
2. 좌/우 방향, 작은/큰 step, 무부하/링크 연결 상태에서 반복한다.
3. 상승/하강 지연, 최대 각속도, overshoot, settling time, 반복 편차를 계산한다.
4. 서보 위치 피드백과 실제 타이어각을 동시 측정해 링크 유격/탄성으로 생기는 차이를 확인한다.
5. 실측 결과를 vehicle model 및 steering rate/latency 파라미터 후보로 제안하되, 원본 시뮬 결과를 소급 수정하지 않는다.

ST3215-HS는 360° 위치 제어가 가능한 버스 서보이므로, 조향 링크가 허용하는 기계적 범위보다 큰 명령을 보내면 링크를 파손할 수 있다. MCU의 서보 명령 변환 계층에서 목표 범위를 실제 기구 끝단보다 안쪽으로 제한하고, 전원 재인가/ID 재설정 후에도 현재 위치를 읽기 전 임의의 절대 위치 명령을 보내지 않도록 한다. 서보의 위치 응답이 정상이어도 실제 타이어각이 맞지 않으면 조향 교정 실패다. 서보 피드백이 제공되지 않으면 외부 각도계 측정을 기준으로 하고, 상태 화면에는 실제 각도 대신 명령값만 표시한다.

## 6. 4단계 — 구동 모터·MD20A 단독 시험

1. 모터를 차체에서 들어 올리고 기어/바퀴 회전부에 손·케이블이 닿지 않도록 고정한다.
2. MD20A의 모터 전원 입력과 논리 입력 범위, PWM 주파수/극성, DIR 논리, 전류/열 보호, 회생/제동 동작을 제조사 자료와 실물 판본으로 확인한다.
   - MD20A 데이터시트의 PWM/DIR 진리표에서 PWM LOW는 양쪽 모터 출력이 LOW가 되는 제동 상태로 정의된다. 따라서 PWM=0을 coast(자유 회전)라고 가정하지 않는다. 실제 바퀴를 띄운 저출력 시험에서 PWM=0, DIR 변화, 전원 차단의 동작을 각각 관찰하고, STOP에 사용할 동작을 별도 확인한다.
3. 모터를 MD20A에 연결하기 전 모터 권선 저항/단락 여부와 샤프트 자유 회전을 확인한다.
4. 바퀴를 띄운 상태에서 가장 낮은 유효 PWM부터 짧게 구동한다. 전진/후진 방향, 시작 duty, 정지 명령 시 coast/brake 동작을 기록한다.
5. 배터리/전원 전압, MD20A 입력전류, 모터전류(가능한 경우), 드라이버/모터 온도, PWM duty, 회전 방향을 동시에 기록한다.
6. 짧은 펄스 여러 번으로 기동 지연·정지 지연·반복성을 확인한다. 긴 stall·역방향 급전환·전류 제한 없는 시험은 하지 않는다.
7. 엔코더 카운트와 외부 회전계/영상으로 모터축 방향·회전수·누락을 대조한다.
8. 실물 제동을 확인하기 전에는 STOP 시 실제 정지거리나 제동성능을 주장하지 않는다.

## 7. 5단계 — 센서/구동 통합과 시계 검증

### 7.1 센서 단독 기록

먼저 [SENSOR_PROBE_RUNBOOK](SENSOR_PROBE_RUNBOOK.md)을 사용해 `/scan`, RGB, `/imu/data`, 단일 모터축 encoder 등 실제 발행 토픽을 기록한다. 실제 토픽명/메시지 타입/frame/단위가 확인되기 전에는 예시 토픽명을 복사하지 않는다.

- ROS header stamp, 장치 취득 시각, host monotonic 수신 시각, seq, boot generation을 각각 보존한다.
- 기록 완결성과 센서 교정/제어기 입력 적합성은 분리 판정한다.
- 원시 CDR/바이트와 정규화 감사 파일을 따로 보관한다.
- 센서 기록 중에도 구동 출력은 비활성으로 둔다.

### 7.2 시간 기준 대조

1. MCU의 실제 timestamp를 찍는 코드 위치와 clock source를 확인한다.
2. 센서 취득 시각, MCU 송신/수신, host monotonic, ROS clock을 함께 기록한다.
3. 왕복 시각 원문을 수집하고 저장소의 clock bounds 도구로 offset/skew 가능한 구간을 계산한다. 왕복 지연을 반으로 나눠 편향을 제거했다고 가정하지 않는다.
4. ROS 시각이 system인지 simulated인지 확인하고, 실물 센서 timestamp에 simulated clock을 섞지 않는다.
5. 각 센서 timestamp가 언제 생성되는지(C1 점/scan, camera exposure/PTS, IMU data-ready, encoder edge/sample)를 확인한다.
6. 실제 clock mapping·신선도 한도 변경은 불확실성 구간과 실제 처리 지연을 검토한 뒤 별도 승인한다.

### 7.3 Jetson 연산/열/메모리

- 실제 Jetson에서 카메라·C1·IMU·엔코더 입력과 전체 ROS 노드를 동시에 올린다.
- 센서별 FPS/Hz, callback 간격, end-to-end 지연, drop/queue, CPU/GPU/메모리, 온도·전력 모드를 기록한다.
- 평균뿐 아니라 p50/p95/p99/max와 장시간 추세를 남긴다. PC 측정치를 Jetson 성능으로 환산하지 않는다.
- 실제 제어 주기 deadline miss와 sensor freshness를 별도 집계한다.
- 영상 해상도/주기·LiDAR scan mode를 바꿀 때 인식 성능·timestamp·처리량을 같이 평가한다. 단순히 FPS를 낮춰 성공으로 만들지 않는다.

## 8. 6단계 — 저속 실차 주행 단계

아래는 독립된 게이트다. 각 게이트 실패 시 원인을 기록하고 해당 단계에서 멈춘다.

| 게이트 | 시험 | 통과 근거 |
|---|---|---|
| G0 | 차체 고정, 센서·통신만 | 모든 센서의 유효 데이터·frame·단위·timestamp 출처 확인, 구동 출력 0 |
| G1 | 바퀴 띄운 상태 모터·엔코더 | 방향·카운트·저속 속도 환산·명령 만료·STOP/재부팅 시험 |
| G2 | 바퀴 띄운 상태 조향 | 중앙/좌우 각도표·기구 간섭 없음·좌우 명령/피드백·지연 측정 |
| G3 | 바닥 직선 초저속 | 외부 거리/시간과 엔코더 속도 비교, 직진 편향·정지거리 기록 |
| G4 | 넓은 반경 좌/우 원호 | 실제 회전반경·좌우 비대칭·조향 응답·IMU yaw 적분 비교 |
| G5 | 저속 직각 코너 | 벽/장애물 여유·조향 제한·속도 감속·정지 개입 검증 |
| G6 | 전체 센서/운영 통합 | 신호등·ArUco·C1·RGB·IMU·encoder·STOP·재시작·통신단절 동시 확인 |
| G7 | 경기 속도 단계 상승 | 각 속도 단계마다 반복/온도/전압/제동거리 확인 후 별도 승인 |

최초 지면 시험은 보행 속도 이하의 낮은 목표에서 시작하되, 실제 속도 제한은 실측 제동거리·공간·안전 담당자 판단으로 더 낮출 수 있다. 속도 단계는 한 번에 크게 올리지 않는다. STOP 버튼을 담당자가 즉시 누를 수 없는 환경에서는 주행하지 않는다.

**실차에서 반드시 측정할 결과:** 직진 편향, 최소 좌/우 회전반경, 조향 명령-실제각 오차, 조향 지연/각속도, 가속/감속 응답, STOP 정착 시간·거리, 엔코더 속도 오차, IMU yaw 변화, LiDAR 운동 보정 전후 벽 흔들림, 카메라 인식률·촬영 시각, 통신 지연/끊김, 배터리 전압 강하·발열.

## 9. 중단 기준과 복구

다음 중 하나라도 발생하면 즉시 STOP하고 구동을 해제한다.

- 배선/극성/전원 레일 이상, 예기치 않은 리셋, 연기·냄새·비정상 발열.
- 센서 frame/축/부호/단위가 예상과 다르거나 timestamp 역행·재부팅 세대 혼합.
- 엔코더 카운트 점프·고착·방향 불일치, 서보 실제 각도와 명령 방향 불일치.
- 서보/링크 기구 간섭, 비정상 소음, 과전류, 위치 피드백 불일치.
- 명령 만료·USB 분리·MCU 재부팅·Jetson 프로세스 종료 시 구동이 계속되거나 자동 재출발.
- STOP이 즉시 고정되지 않거나 실제 제동이 예상과 다름.
- LiDAR/카메라/IMU 입력이 stale인데 제어기가 이를 신선한 데이터로 사용하는 경우.

복구는 원인 격리 → 무전원 점검 → 원시 로그 보존 → 수정 → 해당 게이트 재시험 순이다. 한 번의 통과로 이후 단계까지 소급 승인하지 않는다.

## 10. 측정 결과 기록 양식

세션별 `bringup_<date>_<stage>/` 폴더에 다음 파일을 둔다. 원시 대용량 파일은 저장소 밖에 보관한다.

| 파일 | 내용 |
|---|---|
| `session.md` | 장치/작업자/배선/전원/환경/시험 절차/중단·승인 기록 |
| `measurements.csv` | 시간, 명령, 실제 측정값, 전압/전류/온도, 표본 번호 |
| `calibration.yaml` | 승인된 계수만. 후보 계수는 별도 `candidate`로 분리 |
| `audit.json` | 저장소 감사 도구 출력 |
| `manifest.sha256` | 원시/요약 산출물 해시 |
| `summary.md` | 통과/실패/미실시, 근거 링크, 다음 단계 |

### 조향 측정 CSV 예시

```csv
timestamp_s,servo_id,command_position,feedback_position,left_wheel_deg,right_wheel_deg,supply_v,current_a,settling_time_ms,approach_direction,notes
0.000,1,NA,NA,0.0,0.0,NA,NA,NA,center,initial_reference
```

`NA`는 미측정이다. 명령 위치/내부 피드백/실제 바퀴각을 한 열로 합치지 않는다.

## 13. 대회 전 현실적인 최소 검증 범위

이 문서는 전체 특성화 절차를 포함한다. 대회 전에는 아래 우선순위로 수행하며, P0를 통과하지 못한 상태에서 P1/P2를 진행하지 않는다.

| 우선순위 | 반드시 확인할 내용 | 이번 단계에서 생략 가능한 내용 |
|---|---|---|
| **P0 — 전원·구동 안전** | 실제 전원 레일/극성/정격, 서보 전원 경로, 물리·소프트웨어 STOP, MCU 부팅 시 출력 비활성, USB 단절·재부팅 시 자동 구동 금지 | 장시간 열화 시험, 상세 전원 효율 분석 |
| **P1 — 주행에 필요한 최소 교정** | 엔코더 방향·실측 count/rev·거리 환산, IMU 축/부호와 정지 bias, C1 방향/거리·scan 수신, B0390 영상/FPS/신호·마커 검출, 서보 영점·좌우 실제 바퀴각 5~7개 명령점·기구 안전 범위, 모터 저출력 방향/정지 응답 | 전체 360° 서보 맵, 고밀도 보간표, 정밀 열/진동 특성화 |
| **P1 — 저속 실차 게이트** | 직진, 좌·우 넓은 원호, 저속 직각 코너, 외부 측정 정지거리, STOP/통신 단절 확인 | 경기 최고속도 반복, 장시간 endurance |
| **P2 — 여유가 있을 때** | 시계 offset/skew 정밀 구간, p99/max 장시간 처리량, 반복 분산, 온도별 bias, 고속 코너/제동 envelope | 대회 직전 새 제어기/센서 구조 변경 |

**대회 전 최소 조향 표본 권장:** 직진 0점, 좌·우 작은 각도, 좌·우 중간 각도, 안전한 범위의 좌·우 최대 근처를 포함한 5~7점. 각 점은 명령값·서보 피드백·좌/우 바퀴각을 기록하고, 중앙 복귀를 여러 번 반복해 영점 재현성을 확인한다. 기계 끝단을 찾기 위해 서보를 stall시키지 않는다.

**시간 추정(대략):** 배선이 맞고 펌웨어가 이미 준비돼 있다는 조건에서 P0 1~2시간, P1 센서/엔코더/조향 2~4시간, 저속 실차 1~2시간 정도를 잡는 것이 현실적이다. 이는 보장 시간이 아니라 계획용 추정이다. 핀맵 오류, 전원 부품 미확보, 펌웨어 미완성, 드라이버/SDK 설치 문제 중 하나라도 나오면 반나절 이상 추가될 수 있다. 따라서 P2를 대회 전 필수로 잡지 않는다.

실물 시험 당일에는 새 기능 구현과 교정을 동시에 하지 않는다. 측정 → 결과 기록 → 명백한 부호/단위/영점 오류만 수정 → 같은 게이트 재시험 순으로 진행한다. 측정값이 불확실하면 기존 시뮬 파라미터를 임의로 맞추지 말고 해당 속도/기능을 제한한다.

**현재 완료 판정:** 이 문서의 절차 정리만 완료다. 실제 장치 인수, 전원 통전, 펌웨어, 교정, STOP, Jetson 실행, 실차 주행은 모두 별도 실행·증거가 필요하다.
