# ESP32 저가 대체 보드 검토

확인일: 2026-10-02. 상태: **사용자 제공 수정 구매안·예산 구분 반영, 문서 기반 핀/USB 검토**. 주문·구매 완료·펌웨어 실행·실차 검증을 뜻하지 않는다.

## 현재 구매안과 예산 구분

10/2 사용자가 후속 확인한 예산 구분은 **모터·센서 등 주요 부품은 주최 측 지원 30만 원, 기타 제작비는 동아리 자체 예산 약 10만 원**이다. 센서를 자체 예산으로 구매하면 30만 원 집계에서 빠진다는 이전 견적 전제는 적용하지 않는다. 어댑터와 신호 변환 IC는 팀에서 제작비로 처리할 예정이라고 전달했으며 이번 요청은 부품 조사와 문서 반영까지다.

[공식 MANUAL §3](https://github.com/MOSW626/istech-it-arena/blob/main/MANUAL.md#3-지원-물품--예산)도 지원 30만 원, 동일 품목 합산 3만 원 이상 집계, 모터·센서의 금액 무관 포함, 필라멘트·볼트/너트·전선 제외와 제외 항목 자체 부담 10만 원 이내를 명시한다. **공식 일반 규정**과 **어댑터·변환 IC를 제작비로 편성하려는 팀 계획**을 구분한다. 개별 두 부품의 분류에 대한 새 공식 답변을 확보했다고 기록하지 않는다.

사용자 제공 **수정 구매목록 이미지**의 각 1개 가격·옵션·배송비를 전사하고 합계를 계산했다. 이전 Excel을 자동 수정하거나 실제 주문하지 않았다.

## 판단

수정 구매안은 MD20A를 유지하고 기존 43,450원짜리 ESP32-S3 보드를 **Waveshare ESP32-S3-DEV-KIT-N8R8**로 바꾸며 IMU를 포함한다. CPU나 PSRAM을 줄이지 않고 지원 예산 안에 들어온다. 아래 원메이커 N16R8은 비교 이력이며 수정 구매안의 선택 제품이 아니다.

구매 구성은 [10/2 구동 선정](DRIVETRAIN_GEARING_2026_10_02.md)의 모터축 A/B 엔코더 1개, MD20A PWM/DIR, 지급 ST3215-HS 직렬 서보를 전제로 한다. IMU Adafruit LSM6DSOX 4438은 수정 구매안에 포함됐다. 카메라 B0183과 C1 LiDAR는 Jetson에 연결한다. 정지용 추가 ESP32나 휴대 송신기는 구매 범위에 넣지 않는다.

## 현재 구성의 핀 예산

[Waveshare 제조사 회로도](https://files.waveshare.com/wiki/ESP32-S3-DEV-KIT-N8R8/ESP32-S3-DEV-KIT-N8R8-schematic.pdf)를 렌더링하여 모듈·헤더·USB·LED 연결을 확인했다. 22핀 헤더 두 줄, 총 44개 물리 단자에 전원/GND/EN 등이 포함되므로 **44 GPIO가 아니다**. GPIO로 표기된 헤더 위치는 36개이며 이 중 메모리 점유 핀도 제외해야 한다.

제외 대상은 GPIO35–37(Octal PSRAM), 0/3/45/46(부팅 설정), 19/20(칩 USB), 43/44(USB-UART), 38/48(보드 판본 공통 LED 회피)이다. 따라서 보수적으로 **23개**를 배치 후보로 계산한다. Waveshare 회로도의 LED는 GPIO38이므로 해당 회로도와 실물이 일치하면 48을 추가로 돌려받을 수 있지만 기본 여유에는 넣지 않았다. [Espressif GPIO 제약](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/gpio.html)

| 기능 | GPIO 번호 | 개수 |
|---|---|---:|
| 모터축 엔코더 A/B, PCNT | 4, 5 | 2 |
| MD20A PWM / DIR | 15, 6 | 2 |
| IMU SPI SCLK / MOSI / MISO / CS | 12, 11, 13, 10 | 4 |
| IMU 데이터 준비 INT1 | 9 | 1 |
| ST3215 UART TX / RX | 17, 18 | 2 |
| 서보 어댑터 방향 제어, 필요 시 | 16 | 1 |
| 차량 물리 STOP 상태 | 8 | 1 |
| 외부 구동 허가 요청 / watchdog 진행 | 21, 47 | 2 |
| 배터리 ADC | 1 | 1 |
| 선택 외부 고장 / 정지 해제 요청 | 2, 14 | 2 |
| **배치 합계** | | **18** |
| **여유** | **7, 39, 40, 41, 42** | **5** |

핀 집합 계산으로 중복·제외 핀과의 충돌이 없음을 확인했다. 여유 중 39–42는 외부 JTAG와 겸용이며 외부 JTAG 프로브를 연결하면 일반 확장 핀으로 동시에 쓰지 않는다. 자동 방향 전환 서보 어댑터가 확정되면 16도 반환하여 17개 사용/6개 여유가 된다. Jetson 통신용 43/44는 위에서 별도로 예약했으므로 18개에 중복 산입하지 않았다. 이 배치는 배선 확정안이 아니다.

Waveshare는 USB-C 한 개에 CH334F 허브를 연결하고 칩 USB와 CH343P USB-UART를 함께 제공하는 구조다. 제조사/Linux 드라이버 조사와 남은 실물 조건은 아래 [USB 연결 검토](#usb-연결-검토--102-후속)에 정리했다.

STOP GPIO는 접점/정지 상태를 읽는 신호이며, 버튼을 GPIO에만 연결한 것으로 독립 정지 회로가 완성되지 않는다. 기존의 서보 반이중 TTL 인터페이스와 엔코더 5 V → 3.3 V 수신 회로도 계속 필요하다. 전기적 조건은 [기존 핀 검토](ESP32_S3_PIN_REVIEW_2026_09_30.md#실제-연결-전-남은-조건)를 함께 따른다.

## CPU·메모리·주변장치 판단

[Espressif S3 데이터시트](https://www.espressif.com/sites/default/files/documentation/esp32-s3_datasheet_en.pdf) 기준 듀얼코어 LX7 최대 240 MHz, 내부 SRAM 512 KB, UART 3개, 일반 SPI 2개, PCNT 4유닛, 하드웨어 PWM이 있다. 현재 연결은 PCNT 1유닛, IMU용 SPI 1개, 호스트·서보용 UART 2개, MD20A PWM 1채널을 사용한다. 이번 대체 후보는 같은 칩이므로 이 자원을 줄이지 않는다.

MCU가 맡는 것은 엔코더 계수·IMU 취득·속도 제어·서보 통신·정지/통신 만료 관리다. 영상과 LiDAR 처리는 Jetson이 맡는다. [현재 구동 계약](ACTUATION_CONTRACT_2026_09_22.md)의 참조 시험은 제어 200 Hz, 엔코더 피드백 100 Hz, 호스트 명령 50 Hz, 프레임 payload 상한 1536바이트와 유한 큐를 사용한다. 이 정도 역할에 **S3의 하드웨어 사양을 낮출 이유는 없으며, 동일 사양 저가 보드로 충분히 검토를 진행할 수 있다**. 실제 펌웨어 메모리 사용량이나 CPU 점유율은 아직 측정하지 않았으므로 수치 여유나 마감 준수를 보장하지 않는다.

- Flash는 프로그램·설정 저장 공간이다. N16R8의 16 MB가 N8R8의 8 MB보다 커도 CPU가 빨라지는 것은 아니다.
- 내부 SRAM은 빠른 작업 메모리다. 제어 상태·중요 큐·인터럽트 관련 데이터를 우선 배치한다. 512 KB 전부가 애플리케이션의 빈 heap인 것은 아니다.
- PSRAM 8 MB는 별도 보조 작업 메모리이며 내부 SRAM과 접근 조건이 다르다. 핵심 정지/제어 경로가 PSRAM에 의존하지 않게 설계한다. Flash 접근으로 캐시가 비활성화되면 외부 RAM 접근도 제약될 수 있다. [공식 외부 RAM 문서](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/external-ram.html)
- 실제 펌웨어에서는 메모리 인식, heap/stack 여유, PCNT 계수 손실, PWM·센서·UART 동시 실행 지연과 통신 단절/리셋 시 출력을 확인한다. 이번 확인은 문서와 핀·가격 계산까지다.

## USB 연결 검토 - 10/2 후속

**Jetson USB 호스트에 연결하는 현재 용도에서 구조적인 비호환은 찾지 못했다.** 실제 보드는 아직 없고 Jetson 원격 조회도 시간 초과했으므로, 해당 Jetson의 드라이버 설정·실제 장치 열거·통신 지연을 확인한 결과는 아니다. 원격 드라이버 설치나 설정 변경은 하지 않았다.

```text
Jetson USB 호스트 포트
  └─ 데이터 통신용 USB 케이블 → Waveshare USB-C → CH334F USB 허브
      ├─ CH343P USB-UART → ESP32 UART0 (GPIO43/44): 주행 명령·피드백 후보
      └─ ESP32-S3 직접 USB (GPIO19/20): 업로드·디버깅 후보
```

- [Waveshare 설명](https://docs.waveshare.com/ESP32-S3-DEV-KIT-N8R8)은 단일 USB-C로 두 독립 직렬 포트를 제공한다고 명시한다. 허브를 별도 구매할 필요는 없다. 직접 USB 포트의 실제 노출은 펌웨어의 USB 설정과 절전 상태에도 영향을 받는다. 두 경로가 같은 데이터의 복사본인 것은 아니며 펌웨어에서 역할을 나눠야 한다.
- [CH343 제조사 WCH의 Linux 문서](https://github.com/WCHSoftGroup/ch343ser_linux)는 기본 `cdc_acm` 드라이버로 일반 직렬 통신이 가능하다고 명시한다. 일반 UART 통신 때문에 처음부터 외부 커널 모듈을 설치할 이유는 없다. 제조사 전용 드라이버의 흐름 제어/GPIO 같은 확장 기능과 구분한다. CH343과 [S3 직접 USB](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/usb-serial-jtag-console.html) 모두 Linux에서 `ttyACM*`로 보일 수 있으므로 번호만으로 구별하지 않는다.
- 기존 구동 계획대로 **CH343 → UART0를 주행 통신 우선안**, S3 직접 USB를 개발용으로 두는 구성이 가능하다. 실물에서 `lsusb -t`, `udevadm info`, `/dev/serial/by-id/` 또는 USB 경로로 식별하고 장치별 별칭을 부여한다. 보드에 고유 serial이 없는 경우 by-id만 믿지 않고 물리 경로를 함께 사용한다.
- CH343의 DTR/RTS는 회로도를 보면 부팅/리셋 회로와 연결된다. 포트 열기·닫기와 업로드가 MCU를 리셋할 수 있으므로 실행 중 자동 리셋을 피하도록 호스트 설정을 검토하고, 리셋되더라도 출력 OFF·이전 명령 무효·새 ARM 필요라는 계약을 유지한다. [Espressif 자동 리셋 설명](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/advanced-topics/boot-mode-selection.html)
- 직렬 속도를 예제 기본값 115200 bps로 고정하지 않는다. 코드의 최대 payload 1536바이트와 헤더/CRC 8바이트를 매번 50 Hz로 보내는 가정은 한 방향에만 `1544 × 50 × 10 = 772,000 bit/s`가 필요하다(8N1). 이는 실제 프레임 크기를 측정한 부하가 아니라 상한 예시다. 실제 명령·센서·상태 프레임의 크기/빈도로 UART 속도와 여유를 정하고, 유한 큐와 지연을 실측한다. 보드 가격이 높은 기존 USB-UART 경로에서도 동일하게 필요한 검토다.
- 카메라·LiDAR는 이 보드의 내부 허브 뒤에 연결하지 않는다. USB-C가 외부로 한 개이므로 USB 호스트 기능을 이용해 주변 USB 기기를 꽂는 보드로 해석하지 않는다. 현재는 Jetson이 호스트이므로 이 제약은 요구와 충돌하지 않는다.
- [Waveshare FAQ](https://docs.waveshare.com/ESP32-S3-DEV-KIT-N8R8/FAQ)는 부족한 USB 전압으로 반복 재접속할 수 있다고 안내한다. 데이터 케이블·안정된 5 V·USB/외부 전원 역급전 조건을 확인하고 모터/서보 전력은 별도로 공급한다. 한 케이블/허브가 끊기면 두 경로 모두 잃으므로 통신 단절 정지 시험이 필요하다.

입고 후 확인 대상은 USB 장치 구분 → 메모리 인식/업로드 → 명령·IMU·엔코더 동시 통신 → 포트 재개방/케이블 단절/보드 리셋 → 이전 명령 거부와 정지 유지다. 이번 조사는 이 실물 시험을 대신하지 않는다.

### 서보 어댑터

`ESP32 UART → Bus Servo Adapter (A) → ST3215-HS` 경로다. MD20A는 주행 DC 모터용이므로 이 기능을 대신하지 않는다. [제조사 결선 안내](https://docs.waveshare.com/Bus_Servo_Adapter_A/Product-Wiring-Example)는 ESP32 UART 연결을 지원하며 **점퍼 A 위치, 컨트롤러 TX → 어댑터 TX, RX → RX**로 명시한다. 이 제품 단자의 표기 기준을 따라야 하며 일반 UART 관행으로 무조건 교차 배선하지 않는다. GND도 공통으로 연결한다.

[어댑터 회로도](https://files.waveshare.com/wiki/Bus_Servo_Adapter_A/Bus_Servo_Adapter_A.pdf)를 렌더링해 3.3 V 버퍼와 TX 신호에서 생성하는 내부 TXEN을 확인했다. 따라서 이 어댑터를 선택하면 MCU의 별도 방향 GPIO16은 사용하지 않아 17개 배치/6개 여유로 계산할 수 있다. 단선 버스의 응답 대기·송수신 순서는 소프트웨어에서 관리한다.

서보 전원은 통신과 별도다. [ST3215-HS의 6~12.6 V 범위](https://www.waveshare.com/product/modules/motors-servos/st3215-hs-servo-motor.htm)에 맞는 전원(예: 적정 용량의 12 V)을 어댑터 전원 단자에 공급한다. 어댑터가 6S 배터리 전압을 서보 전압으로 내려주는 제품은 아니며, 회로도상 서보 전원은 DC 입력에서 전달된다. ESP32 USB 전원으로 서보를 구동하지 않는다.

### 엔코더 수신 회로

`PGE-213 A/B → SN74LVC2G17 두 입력 → 3.3 V A/B → ESP32 PCNT` 경로다. [PGE-213 판매 회로](https://www.motorbank.kr/goods/goods_view.php?goodsNo=1000009561)는 A/B를 Vcc로 당기는 4.7 kΩ 저항과 5 V 예시를 제시한다. 엔코더를 5 V로 공급하는 현재 검토 조건에서 ESP32에 직접 넣지 않는다. 3.3 V로 낮추는 것은 엔코더의 전원 전체가 아니라 출력 A/B 신호다.

[TI 데이터시트](https://www.ti.com/lit/ds/symlink/sn74lvc2g17.pdf)는 입력 5.5 V 허용, 5 V → 3.3 V 하향 변환, 2채널 비반전 Schmitt 입력을 명시한다. IC 전원은 3.3 V로 공급하고 공통 GND를 사용한다. A/B 위상 관계를 유지하는 두 비반전 채널로 사용할 수 있다. **엔코더를 12/24 V로 공급해 해당 전압까지 올라가는 신호를 이 IC에 바로 넣는 구성은 해당하지 않는다.** 실제 납품 출력·회로·최대 회전수의 파형과 계수 손실은 별도로 확인한다. SOT-23-6 변환 기판을 사용할 수 있으며 패키지별 핀 번호를 확인한 뒤 조립한다.

### 예산 영향과 팀 확인용 문장

사용자 후속 설명에 따라 **두 인터페이스는 제작비 약 10만 원 쪽으로 편성할 예정**이다. 찾은 후보의 소계는 서보 어댑터 10,032원 + IC 최소 주문 5개 2,420원 = **12,452원**이며, 엔코더 변환 기판·커패시터와 별도 주문 시 배송비는 추가다. 전체 제작비에는 다른 기구/배선 비용도 들어가므로 이 소계만으로 10만 원 내 완결을 판정하지 않는다. 지원 구매안 **296,137원**과 구분해 기록하며, 이번에는 부품 조사만 수행했다.

> ST3215-HS는 일반 PWM 서보가 아니라 단선 TTL 통신 서보라서, ESP32 TX/RX와 연결하는 반이중 통신 회로가 필요하다고 합니다. Waveshare Bus Servo Adapter (A)가 약 1만 원인데, 이 기능을 하는 어댑터나 자체 회로도 준비하고 있나요? 그리고 PGE-213을 5 V로 쓰면 A/B 출력도 5 V 쪽으로 올라가는 회로라, ESP32용 3.3 V 변환이 필요하다고 합니다. 2채널 SN74LVC2G17 같은 부품으로 만드는 수신 회로까지 고려한 건지 확인 부탁드립니다. 이미 같은 기능을 준비했다면 중복 구매할 필요는 없습니다.

## ESP32 이름과 가격 차이를 읽는 방법

`ESP32-S3-WROOM-1-N8R8`과 `DevKitC`는 서로 다른 층위를 가리킨다.

1. **ESP32-S3: 칩 계열.** ESP32, S2, S3, C3, C6 등은 CPU·무선·USB·주변장치가 다른 제품군이다. 번호가 커질수록 모든 기능이 상위가 되는 순위표가 아니다. 예를 들어 C3는 단일코어 RISC-V 최대 160 MHz, S3는 듀얼코어 LX7 최대 240 MHz다. [Espressif 제품 비교](https://www.espressif.com/en/products/socs/esp32c3/overview)
2. **WROOM-1: 칩을 얹은 모듈.** 칩과 메모리·안테나 등을 작은 금속 실드 모듈로 묶은 제품이다. 이 모듈만 파는 저렴한 상품은 USB와 핀 헤더가 달린 완성 개발보드와 다르다.
3. **N8R8 / N16R8: 해당 모듈의 메모리 옵션.** 여기서 N8R8은 Flash 8 MB + PSRAM 8 MB, N16R8은 Flash 16 MB + PSRAM 8 MB다. R8을 생략한 N8과 동일시하지 않는다. [WROOM-1 데이터시트](https://www.espressif.com/sites/default/files/documentation/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf)
4. **DevKitC / DEV-KIT / 호환 보드: 모듈 주변의 기판.** USB 회로, 전원 레귤레이터, 리셋 회로, 외부로 꺼낸 GPIO, 핀 납땜 여부, 회로도 제공이 달라진다. 같은 S3 모듈을 써도 작은 보드에서 필요한 핀을 모두 꺼내 놓았다는 보장은 없다.
5. **판매처·유통 조건: 최종 가격.** 동일 사양이어도 제조사, 수입 경로, 유통 마진, VAT 표시, 배송비, 납기에 따라 결제액이 달라진다. 이번 43,450원과 22,990원 제품은 핵심 CPU·메모리가 같으므로 가격 비율을 성능 비율로 해석하면 안 된다. 개별 가격 차이의 정확한 원가 구성은 공개 자료로 확인하지 않았다.

현재 차량에는 **S3 + 필요한 GPIO 노출 + USB 연결 + 확인 가능한 회로도**가 구매 판단의 중심이다. Flash를 더 늘리는 것보다 현재 배치를 그대로 사용할 수 있는 보드를 고르는 편이 유용하다.
