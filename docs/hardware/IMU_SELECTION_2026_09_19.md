# B0183·C1 구성의 IMU 역할, 요구 사양과 국내 구매 후보

작성·가격 확인: 2026-09-19. 제조사 자료, 현재 프로젝트 소스와 국내 판매 화면을 대조한 설계 검토다. 실물 구동 시험은 하지 않았다.

## 추천

**Adafruit LSM6DSOX 모듈 4438을 우선 추천한다. 단독 기본 배송 포함 24,249원이며 IMU 예산은 약 2.5만 원이면 된다.** 6축 원시 가속도·각속도, SPI/I²C, 데이터 준비 인터럽트, FIFO·센서 타임스탬프와 공개 라이브러리가 있어 현재 목적에 맞는다. 이 기능들이 기본 예제에서 자동으로 모두 활성화되는 것은 아니다.

사용자는 B0183·C1을 선택했고 B0410 ToF 카메라는 기록만 남기도록 했다. [ADR 0020](../decisions/0020-b0183-c1-procurement-baseline.md)에 반영했다. IMU는 아직 추천 단계다.

## 현재 IMU가 실제로 하는 일

[ADR 0018](../decisions/0018-sensor-based-lidar-motion-compensation.md), [구현 기록](../sensors/LIDAR_MOTION_IMPLEMENTATION.md), `src/arena_autonomy/arena_autonomy/lidar_motion_ros.py`와 `lidar_motion.py`를 확인했다.

| 역할 | 현재 상태와 의미 |
|---|---|
| C1 한 스캔 내부의 차량 회전 보정 | 구현된 선택형 기능. IMU 각속도를 고정 장착 회전으로 차체 z축에 투영하고 시간 적분한다. 서로 다른 시각의 광선을 같은 차량 좌표계로 옮기는 데 사용한다. |
| 스캔 취득 후 현재까지의 이동 보정 | 같은 IMU·엔코더 이력으로 구현된 선택형 기능. 취득한 벽의 좌표를 현재 차체 기준으로 옮긴다. 관측 자체를 새것으로 만드는 기능은 아니다. |
| 전진 이동량 | 좌우 뒷바퀴 엔코더 각속도 평균을 사용한다. 가속도 이중 적분으로 속도·위치를 구하지 않는다. |
| 방지턱의 pitch/roll, 진동·충격 진단 | IMU 추가 활용 후보. 현재 평면 보정은 자세 quaternion과 가속도를 사용하지 않으며 동적 3차원 기울기 보정을 구현한 상태가 아니다. |
| 절대 방위·장시간 자기 위치 추정 | 현재 IMU 보정의 역할이 아니다. 자이로만 계속 적분하면 오차가 쌓이며, 별도 영상/LiDAR 관측 등으로 보정할 문제다. |

C1을 대표 10Hz로 쓰면 한 바퀴에 약 0.1초가 걸린다. 예를 들어 차량이 200°/s로 회전하는 순간에는 한 바퀴 동안 20°가 변한다. 이 가상 예시는 회전 보정 필요성을 설명하며 우리 차의 실측 회전율은 아니다.

**6축이면 충분한 이유:** 현재 직접 필요한 것은 자이로의 각속도이며, 일반적인 6축 모듈에 함께 있는 가속도계는 추후 자세·충격 진단에 활용할 수 있다. 지자기 3축을 더한 9축이나 자세 계산기가 현재 보정의 필수 조건은 아니다. 모터·자성체·전류 배선이 있는 차체에서 지자기 출력을 신뢰할 수 있는지는 별도 문제다. 이는 시스템 설계 판단이며 모든 9축 제품이 나쁘다는 뜻은 아니다.

현재 시뮬레이션의 IMU는 200Hz이고 `/camera/imu`라는 토픽을 사용한다. 새 실차에서 B0183이 그 IMU를 제공하는 것으로 가정하지 않는다. 별도 IMU 어댑터와 토픽 재매핑을 마련해야 하며 이번 조사에서는 실행 코드를 바꾸지 않았다.

## 필요한 수준

아래 숫자는 **구매와 후속 시험을 위한 설계 제안**이다. 대회 규정, 제조사의 주행 보장값 또는 이미 검증된 실차 한계가 아니다.

| 항목 | 제안 | 이유 |
|---|---|---|
| 센서 구성 | 3축 자이로+3축 가속도계, 6축 | 자이로로 회전을 측정하고 가속도계는 후속 자세/진동 진단에 사용 |
| 실제 새 표본 출력 | 최소 100Hz급, 우선 **200/208Hz** | 10Hz 스캔 동안 약 20개 회전 표본. 기존 200Hz 시뮬레이션과 가까운 시작점 |
| 여유 출력 | 400/416Hz 선택 가능하면 좋음 | 더 빠른 움직임·필터 지연 비교 여지. 높은 숫자 자체가 정확도는 아님 |
| 자이로 범위 | ±500°/s부터 검토, 필요하면 ±1000°/s; ±2000°/s 지원 제품 | 포화되면 잘못된 회전량을 적분하므로 실제 급커브·충격 기록에 맞춰 결정 |
| 가속도 범위 | ±8g 시작, ±16g 선택 가능 | 방지턱·진동에서 포화 여부 확인. 최대 충격 가속도는 아직 모름 |
| 자이로 잡음 밀도 | 고성능 모드에서 0.01°/s/√Hz 이하를 우선 비교 | 구매 후보를 좁히는 참고 지표. 실제 자세 오차·드리프트 보장값과 다름 |
| 영점 오차 | 예열·정지 교정 후 잔여 평균 0.2–0.5°/s 이하를 초기 시험 목표로 검토 | 단기간 회전 적분의 일정한 오차를 제한. 공장 출하 스펙으로 요구하는 값은 아님 |
| 시간 관리 | 데이터 준비 인터럽트 또는 FIFO의 표본 시각 복원; 센서·엔코더·LiDAR의 공통 시간 영역 | PC에서 메시지를 받은 시각을 실제 측정 시각으로 쓰지 않음 |
| 시각 정렬 | 초기 목표 약 1–2ms, 실제 전체 지연·필터 지연까지 측정 | 시험 목표이지 모든 구간에서 이 값만 만족하면 안전하다는 조건은 아님 |
| 연결 | ESP32-S3의 3.3V 논리, SPI 우선; 짧고 부하가 관리되는 I²C도 가능 | 일정한 취득 시각과 배선 신뢰성이 중요. 200Hz 때문에 I²C가 원천적으로 불가능한 것은 아님 |
| 문서·보드 | 회로도·라이브러리·실제 노출된 INT 핀·원시 자이로 접근 | 센서 칩의 기능과 판매 모듈에서 쓸 수 있는 기능을 구분 |

주기를 200Hz로 설정하는 것과 서로 다른 새 표본 200개를 정확한 시각으로 받는 것은 다르다. 같은 표본의 반복 발행, 수십 ms FIFO 묶음 대기, 과한 저역통과 필터 지연은 높은 명목 Hz로 해결되지 않는다. 현재 코드의 50ms 입력 공백·30ms 외삽 한도는 오류 거부 설정이며 목표 지연이나 허용 안전 지연으로 사용하지 않는다.

오차 규모의 예를 들면, 일정한 잔여 자이로 바이어스 0.5°/s가 0.1초 쌓이면 회전 오차는 0.05°다. 2m 거리 점의 회전 오차만 환산하면 약 1.75mm다. 이것은 센서 잡음·배율·시간·진동·장착·엔코더 오차를 제외한 계산으로, 우리 보정의 실제 오차 예측값은 아니다. 비싼 장시간 절대 방위 성능보다 짧은 구간의 자이로 교정과 시각 관리가 먼저라는 판단 근거다.

서로 다른 제조사/모드/시험 조건의 대표값이므로 이 열만으로 완성 모듈의 정확도 순위를 확정하지 않는다. ISM330DHCX는 비싸지만 이 잡음 수치만 보면 LSM6DSOX보다 낮지 않다. 산업용이라는 이름이 모든 오차에서 자동 우위를 뜻하지 않는다. ST 문서의 대표값은 보장값이 아니며, ISM330DHCX의 최소/최대 칸도 특성 평가에 기반한 제한이 명시돼 있다.

LSM6DSOX와 ISM330DHCX의 Adafruit 보드는 동일 계열 라이브러리와 공개 핀 설명이 있다. ICM Click은 통신 방식 선택 점퍼 설정과 MCU 드라이버 통합을 추가로 확인해야 한다. 전용 Click 호스트 보드 구매를 필수로 산정하지 않았으며 공개 핀으로 S3 연결을 설계하는 전제다.

BNO085의 장점은 회전 quaternion 등 융합 출력의 편의성이다. 하지만 Adafruit는 ESP32·ESP32-S3에서 BNO08x의 I²C 구현이 잘 동작하지 않는다고 명시한다. 모든 연결이 불가능하다는 뜻은 아니며 SPI 대안을 검토할 수 있다. 각 출력 보고서의 주기·시각·교정 동작을 별도로 확인해야 하고, 높은 융합 출력 Hz를 원시 자이로의 실제 주기로 그대로 옮기지 않는다.

## ESP32-S3와 Jetson 연결 제안

`IMU ─ SPI + 데이터 준비 신호 → ESP32-S3 ← 좌우 엔코더`

`ESP32-S3 ─ 취득 시각·표본 순번을 포함한 USB 직렬 데이터 → Jetson Orin Nano / ROS 2`

- S3가 IMU 취득 시각과 엔코더 구간을 같은 시계로 기록하고, Jetson이 사용할 시간 영역과의 오프셋·드리프트를 관리한다. S3를 쓴다는 것만으로 USB C1의 시간까지 자동 동기화되지는 않는다.
- 시작 예시는 LSM6DSOX 고성능 모드·208Hz·자이로 ±500°/s·가속도 ±8g다. 실제 포화와 진동을 보고 변경한다. 저역통과 필터는 잡음뿐 아니라 지연도 확인해 고른다.
- 센서 영점은 예열 후 정지 상태에서 추정한다. 주행 중 계속 평균을 빼면 실제 커브 회전까지 지울 수 있으므로 초기 설계에 넣지 않는다. 배율·축 정렬과 장착 강성도 확인한다.
- 이 경로라면 JetPack 6.2용 IMU 전용 커널 드라이버를 찾는 문제가 줄어든다. S3 라이브러리 적용과 USB 수신·ROS 어댑터 구현은 여전히 필요하며, 이번 조사로 실물 호환성을 검증한 것은 아니다.
- ROS 출력은 실제 표본 시각, 올바른 IMU frame, 각속도 rad/s·가속도 m/s²를 사용한다. 자세를 추정하지 않는다면 자세 데이터가 없는 메시지로 명시한다. 현재 코드의 `/camera/imu` 계약에는 재매핑 등으로 연결한다.
- 예를 들어 32바이트 표본을 208Hz로 전송하면 약 6.7kB/s다. 패킷 여유를 포함해도 영상 처리와 비교하면 작은 데이터량이지만, 직렬 속도·ROS 처리 지연은 따로 측정해야 한다. 단순 바이너리 전달과 6축 처리 때문에 Orin Nano의 주행 연산이 크게 소모될 것으로 보지는 않는다. 이는 부하 실측값이 아닌 구조상 판단이다.

## 전체 예산에 반영

9/19 같은 디바이스마트 실제 화면에서 B0183은 VAT 포함 55,000원, C1은 99,000원이다.

| 구성 | 일반 합배송 적용 합계 | 총 40만 원에서 남는 금액 |
|---|---:|---:|
| B0183 + C1 + 추천 LSM6DSOX | **175,549원** | **224,451원** |
| B0183 + C1 + ISM330DHCX | **193,820원** | **206,180원** |

세 품목 모두 같은 판매처의 기본 무료배송 조건을 적용한 계산이다. 서로 따로 주문하면 첫 안은 57,700+99,000+24,249 = **180,949원**이다. 따라서 현재 협의에는 카메라·라이다·IMU **약 18만 원**을 제시할 수 있다. 남은 금액은 모터·구동계·서보·MCU·엔코더·전원 등 다른 품목에 배분할 몫이며 차량 전체 견적을 완성했다는 뜻은 아니다. ToF 추가 여부, 추가 연결 케이블의 실제 필요 여부는 별도이며 임의 금액을 넣지 않았다.
