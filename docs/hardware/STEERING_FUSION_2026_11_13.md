## 측정 정의

- 차량 앞바퀴가 직진하는 기준 자세에서 서보 입력을 0°로 둔다. Fusion 서보 조인트의 **증분 각도**이며 서보의 절대 count·장착 후 중립은 아니다.
- 바퀴 조향각은 차량 앞 방향 기준, **차량 좌회전이 양수**인 바퀴의 수평 방향이다. 좌우 바퀴가 따로 기록된다. CSV의 서보 부호는 Fusion 조인트의 부호이며 **양수 입력이 우회전**이다.
- Fusion CAD 좌표에서 +Y는 위, −Z는 앞, −X는 차량 좌측이다. 각 바퀴 occurrence의 변환 행렬로 중립 시 CAD +X 방향인 바퀴 회전축을 추적하고, 수평축 성분에서 진행 방향을 계산했다. 킹핀은 조향 너클이 차체에 대해 회전하는 축이다. 이번 모델에서 바퀴 조향 조인트는 킹핀 회전이고 바퀴의 구름 회전은 별도 조인트다. 표본 전부에서 바퀴축 변환으로 얻은 방향은 킹핀 표시값의 부호 반대와 수치상 일치했다. 따라서 앞선 수동 관찰은 바퀴 조향을 본 것이 맞지만, 그 조인트의 부호는 차량 좌회전 양수와 반대다.
- Fusion의 구동 명령과 같은 API `RevoluteJointMotion.rotationValue`를 사용해 중립에서 각 방향으로 0.5°씩 이동하고 양 끝 설정값을 추가했다. Autodesk는 이 속성의 단위를 라디안, 설정 동작을 Drive Joints 명령에 대응한다고 설명한다. [Autodesk API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_RevoluteJointMotion_rotationValue.htm). 원 데이터에는 바퀴 변환 행렬과 원 조인트 각도도 남겼다.

## 기구와 시뮬레이터 대응

모델에는 서보 혼→드래그링크→타이로드→좌우 너클이 있으며 각 너클을 킹핀이 지지한다. 내륜이 외륜보다 더 회전한다. 수치상 CAD 조인트 킹핀 축 간 거리는 약 **98.311 mm**, 앞뒤 축거는 기존 STEP 검토 기준 **128 mm**, 바퀴 중심 윤거는 직진 기준 약 **123.9 mm**다. 킹핀 간격과 윤거는 서로 다른 치수다. 실제 사용 치수·CAD 판본 대응은 조립 후 재확인한다.

중립 자세에서 좌우 킹핀은 차체 중심에서 ±49.1556 mm, 좌우 타이로드 접점은 ±45.3513 mm이며 앞뒤 좌표도 같다. **좌우 너클 쪽 배치는 대칭**이다. 반면 서보축은 중심에서 왼쪽17.000 mm, 드래그링크의 타이로드 접점은 중심에서 왼쪽4.181 mm에 있어 구동 링크 전체는 좌우 거울 대칭이 아니다. 서보축→혼 접점의 수평 성분은 오른쪽0.07377 mm·뒤쪽9.35522 mm이고, 혼은 차량 전후 방향에서 약0.4518° 기울어져 있다.

관측된 같은 크기 입력의 좌우 방향 차이가 이 형상에서 생길 수 있는지 별도 평면 링크 방정식으로 확인했다. 회전축 중심과 연결점만 사용해 연속 분기를 푼 결과 95개 입력에서 Fusion의 킹핀 결과와 최대 약1.1×10⁻⁹° 차이였다. 이 계산에서 서보 ±10°의 내륜 차이는 약0.0270°다. **가상 실험으로 혼 접점의 좌우 오프셋0.07377 mm만 0으로 바꾸고 새 드래그링크 길이를 사용**하면 내륜 차이는 약0.0110°로 줄었다. 이는 혼 중립 각도가 미세한 비대칭에 기여한다는 근거이며, 나머지 차이를 하나의 원인으로 특정하거나 설계 오류·실물 오차로 단정하지 않는다. 한쪽에 배치된 서보 자체가 반드시 결함이라는 뜻도 아니다. 형상 변경은 계산에서만 수행했고 Fusion 설계는 편집하지 않았다. [계산·가상 실험](../../artifacts/validation/2026-11-13/steering_cad_fusion_v1/planar_check.py).

CAD 분석 당시 `single_motor` 시뮬레이터의 `SteeringAngles`는 중앙 등가 조향각을 입력받아 **이상적인 애커만 관계**로 좌우 목표를 계산하고, `wheelLimit`은 내륜 상한이다. `vehicle.yaml`의 0.45 rad은 약25.78°인 기존 임시 내륜 상한이며 서보 축 한계가 아니다. 현재 시뮬 축거/윤거와 이번 CAD 값도 다르다. 따라서 CAD 입력 ±23°를 그대로 `max_steering_angle_rad`에 넣거나 내륜30°만 바꿔 좌우 링크 운동이 재현됐다고 판정하면 안 된다.

간단한 차이를 보이기 위해 킹핀 간격98.311 mm와 축거128 mm를 쓰고 킹핀을 바퀴 중심으로 보는 이상화 계산을 하면 내륜30°에 외륜 약21.8°다. CAD의 약23.3°와 다르다. 바퀴 중심과 킹핀의 오프셋과 조향 시 중심 이동을 생략한 비교이므로 차이를 곧바로 실차 타이어 미끄럼이나 설계 결함으로 판정하지 않는다. 실제 바퀴 중심·접지와 동역학을 포함한 모델 비교가 필요하다.

인계 방안: 별도 선택형 프로필에서 위 표를 서보 상대각→좌우 바퀴 목표로 보간하고, 동일 입력에 대한 기존 이상 애커만 결과와 조향각·차량 곡률·코스 통과를 비교한다. 현재 입력 인터페이스의 `steering_rad`는 차량 중앙 등가각이고 표 입력은 서보 조인트 각도이므로 두 변수를 혼동하지 않도록 변환 관계를 명시한다. 중앙 등가각 하나로 일반적으로 좌우 두 값을 정확히 동시에 재현할 수 없다. 기존 제어·보호 경계와 운영 기본 설정은 이번에 변경하지 않았다.

## 무결성·실패·후속

- 중립에서 −10°를 한 번에 입력했을 때 좌/우 킹핀 표시 +0.6°/+121.3°의 비정상 자세가 나타났다. 0→−1→−5→−10°로 움직이면 바퀴 방향 +11.48°/+10.46°가 됐다. Fusion의 다른 해로 튀었을 가능성이 있으나 원인 조인트는 미확정이다. 비정상값은 표에 넣지 않았다.
- 첫 자동 측정은 +끝점까지 움직인 후 0° 복귀를 검사할 때 Fusion이 킹핀 각을 **360°**로 보고하여 단순 숫자 비교가 실패했다. 이 시도는 [원문](../../artifacts/validation/2026-11-13/steering_cad_fusion_v1/fusion_sweep_first_attempt.json)에 보존했다. 두 번째는 360°와 0°를 회전상 동등하게 처리했고, 실제 중립 바퀴 변환 행렬과 두 분기 96행의 단조성·서보 목표 일치·축/킹핀 각도 대응을 검사했다. 중립 복귀는 서보0°·양 킹핀360°(각도상0°)로 확인했다.
- 직접적인 CAD 간섭 검사·기계적 스톱 검사는 수행하지 않았다. 조인트 제한은 모델 설정이며 가능한 최대 조향각 또는 실제 허용각을 증명하지 않는다. 표의 물리 좌우 부호, 서보 count 중립·방향, 실제 좌우각·하중 및 전류는 실물 조립 후 확인한다.
- Fusion의 설계를 저장하지 않았다. 구동 API 호출 후 조향 자세는 중립으로 되돌렸으나 **열린 문서에 저장되지 않은 변경 표시가 남았다.** 다른 사용자의 원래 미저장 작업을 보존하기 위해 문서를 닫거나 저장하지 않았다. CAD 원본 파일과 시뮬 코드·설정은 수정하지 않았다.

원 자료·감사 스크립트: [측정 산출물](../../artifacts/validation/2026-11-13/steering_cad_fusion_v1/README.md). 실장 후 사용 가능한 기존 보간 준비물은 [r319](../../artifacts/validation/2026-11-13/steering_mapping_r319_v1/README.md)이며 실제 실측표는 아직 없다.

## 11/13 후속 구현

사용자 요청으로 설계 최대각과96행을 Python/C++·Gazebo에 반영했다. 선택형 `vehicle.final_cad_2026_11_13.yaml`에서 내륜 약30°·외륜 약23.3°를 사용하며 원0.45rad 임시 내륜 상한을 CAD 한계로 유지하지 않는다. `/drive`의 중앙 등가각은 이 두 각도를 하나로 표현한 값이고 양방향 공통 상한은 약26.2325°다. 서보 축 각도와 구분한다. 제어기/독립 보호/시뮬 MCU가 같은 중앙각 한계를 사용한다.

고정 차체의 Gazebo 부품 검사에서 중립·좌우 중간각·좌우 최대각·중립 복귀7단계가 통과했다. 조립 후 영점 count를 별도 프로필에 기록하고 CAD 상대각에 offset을 더하는 도구도 준비했다. 실물 출력 연결·장착 간섭/유격/부하 확인은 아직 남는다. [구현·명령·검증 범위](../../artifacts/validation/2026-11-13/steering_cad_integration_r368_v1/README.md).

후속 [`export-cpp`](../../artifacts/validation/2026-11-13/steering_export_r376_v1/README.md)는 확인된 장착 프로필을 같은 C++ 영점 구성으로 전달한다. 합성 두 방향402목표에서 Python/C++ count와 각도 대응을 확인했다. 자동 실장 교정이나 출력 활성화는 아니며 실제 프로필과 운영 HAL 연결은 여전히 후속이다.

[r416 운영 빌드 연결](../../artifacts/validation/2026-11-13/runtime_installed_profile_r416_v1/RESULT.md)은 장착 JSON과 명시 board 설정을 선택형 firmware 빌드로 전달한다. 관련18검사·합성 프로필 IDF1회와 실제 compile 선택을 확인했고 기본 미교정 구성은 비활성이다. 앞 문단의 HAL 프로필 연결 공백을 보완했으며 실제 장착 영점/방향·출력값 확인과 업로드·물리 구동은 여전히 남는다.
