# 조립 직후 사각 벽 공간 확인·보정 실행 순서

**11/14 최신 소스 이관:** [r491 최종 소스 묶음](../../artifacts/validation/2026-11-14/runtime_handover_r491_v1/README.md)에 현재 공통721파일과 manifest를 보존했다. r489 독립 보호 정리, r494 현재 점유 기반 추월 복귀, r491 `.1m/s` float32 상한 초과 방지, r495 기존 엔코더 경계의 선택형 설치 전달이 포함된다. ZIP 생성은 설치/실기 확인이 아니며 실제 영점·방향·PI·상한은 채워 넣지 않았다. r495의 소프트웨어 검출 경계도 물리 과도 속도13km/h 절대 보증이 아니므로 아래 낮은 단계와 실측 확인을 유지한다.

2026-11-14 사용자 요청으로 기존 실물 이관 절차를 실행 순서로 구체화했다. **문서/소스 대조만 완료했으며 실제 차량 측정·보정값 채택·출력 시험은 아직 하지 않았다.** 본 문서 준비 중 본 작업의 시뮬레이션·Jetson·공통 제어 코드는 변경하지 않았다.

## 1. 현장 조건과 역할

- 사용자 준비: 약60cm 한 변의 네 벽, 높이30cm 이상, 벽마다 다른 팀 마커 하나씩, 마커 중심 높이 약20cm, 흰 여백 포함 출력물 약5cm. 벽의 직각도·평행도·정확한 치수는 미확인이다.
- 이 공간은 장착 확인·근사 보정·짧은 이동용이다. 자유 자율주행·연속 회전·최고속도·추월 시험장은 아니다. 삐뚤어진 벽을 센서 오차로 간주하여 정사각형으로 보정하지 않는다.
- 사용자: 차를 받침대/바닥에 놓기, 벽/마커를 향해 놓기, 바퀴 직진 여부·물리 STOP 조작 확인, 필요한 거리/검은 코드 치수 알려주기. 외부 사람이 필요한 이 동작은 자동화했다고 표시하지 않는다.
- GPT 실행 담당: 당시 Jetson/ESP32 자원 소유권 확인 → 설치 상태/기존 실행 설정 확인 → 해당 단계만 실행 → 원자료 회수/집계 → 보정 후보 산출 → 같은 설정에 반영 → 짧은 재확인 → 결과·미완료 항목 기록. 매 명령마다 승인을 다시 묻지 않으며, 구동 단계 전 받침/주변 상태는 한 번 확인한다.
- 센서 포트는 기존 runtime host 한 개가 소유한다. IMU 점검을 위해 별도 UART bridge나 다른 펌웨어를 동시에 실행하지 않는다. 차량 도착 후 실제 설치 펌웨어/포트에 맞추며 개발용 probe를 임의 flash하지 않는다.
- 왼쪽/오른쪽 베어링 부족은 사용자 전달 사항이다. 어떤 지지 구조로 조립됐는지 기록하며, 가변 유격을 소프트웨어 영점으로 숨기지 않는다.

## 2. 시간 우선순위와 진행표

시간은 계획상 대략치이며 자동 종료/재시도 예산이 아니다. 이상이 없으면 다음 항목으로 이동한다.

| 순서 | 환경·사람 동작 | GPT 실행·기록 | 다음 단계 판단 |
|---|---|---|---|
| A | 바퀴 모두 뜨고 차체가 안정적으로 고정됨 확인 | 실제 설치 설정/포트/입력 프레임 기록, 낮은 출력의 짧은 구동, 엔코더 부호·피드백, 물리/패널 STOP 각각 확인 | 전진 부호와 출력 차단이 맞음. 공중 관성회전과 PWM 지속을 구별 |
| B | 바퀴 직진 상태 확인, 작은 좌우 조향을 육안 확인 | 중립 count·CAD와 count의 방향 관계·간섭 없는 장착 범위 기록 및 기존 영점 도구에 반영 | 반대 방향/끝단 간섭 없음. 하중 없는 확인이라는 한계 유지 |
| B2 | 전선 최종 고정. 사각 벽 안에서 실제 높이로 놓음. 모호한 구간이 있으면 안에서 몇 cm 재배치 | 기둥 위치·전선 포함 외곽·라이다 위치 대조, 미마스크 스캔으로 실제 자기 반환 측정, 움직임 여유를 더한 거리 한정 마스크 후보/적용/재확인 | 외부 벽을 마스크에 넣지 않음. 자기 반환은 분리하고 같은 방향의 더 먼 벽은 유지 |
| C | 바닥 실제 주행 높이, 모터 정지, 약20초 손대지 않음 | IMU 원시값/프레임/시각과 정지 구간 기록, 차체 yaw축 편향·산포·앞뒤 구간 변화 계산 | 움직임 섞인 구간을 편향으로 채택하지 않음. 필요할 때만 한 번 더 정지 표본 |
| D | 네 방향으로 차체를 정지 배치 | C1 벽 방향/거리·자기 반환 확인. 정밀 손 회전은 요구하지 않음 | 실물 배치와 일치. 벽 사이 각도를 정확히90도로 가정하지 않음 |
| E | 한 마커 정면, 실제 렌즈→마커 평면 거리1~2곳과 검은 외곽 크기 제공 | RGB/ID/픽셀 크기 기록, 카메라 근사 배율 보정 및 새 거리/다른 ID로 짧게 대조 | 검출/크기 선택 오류 없이 거리 크기가 개선됨. 안 맞으면 자동으로 채택하지 않고 원인 분리 |
| F | 바닥에서 짧게 조향 주행할 여유, 필요 시 차를 다시 놓음 | 낮은 속도 단발·좌우 조향·정지/재출발, 고정 마커/같은 벽의 정지 전후 방향과 IMU 적분 회전량 대조, 엔코더 이동 대조 | 지속 방향 오류/가변 유격/큰 환산 오류 없음. 정밀 손 회전·90도 기준을 요구하지 않음 |

최소 필수는 A/B/B2/D/F다. IMU 정지 기록 C는 다른 준비 중 병행할 수 있다. 카메라 거리 보조 E는 실패해도 기본 라이다 주행 준비를 무한정 늦추지 않는다. 첫 단발 예시는0.05m/s·0.5초이며 v×t=2.5cm는 예상값일 뿐 실제 이동 보증이 아니다. 패널·host·MCU의 기존 상한과 독립 보호층을 유지한다. 공간이 좁아 보호층이 차단하면 이유를 확인하고, 억지로 우회해 구동하지 않는다.

### 지상 초저속과 바퀴 공중 속도 시험 — 사용자 상한

- **지상:** 약60cm 사각 벽 안에서는 아주 천천히, 짧은 단발로만 움직인다. 초기 목표0.05m/s, 이 공간의 계획상 상한0.1m/s(0.36km/h), 한 번에0.2~0.5초를 기준으로 실제 벽 여유에 맞춰 더 줄인다. 이 수치는 실행 준비값이며 실제 저속 유지 성능을 보장하지 않는다. 기동이 안 된다고 출력을 크게 올리지 말고 바퀴를 띄운 상태에서 원인을 확인한다.
- **바퀴 공중:** 낮은 목표부터 단계적으로 올려 엔코더 피드백 기반 모터 속도 추종을 확인한다. 예시 단계는 환산 속도0.5→1→2→4→6→8→10km/h이며, 각 단계의 정상 추종·진동·고정을 확인한 경우에만 다음으로 간다. 최대 단계까지 반드시 올리는 시험은 아니다. 실제 무부하 응답과 출력 한계에 맞춰 단계/가속을 더 낮춘다.
- **절대 상한:** 사용자 지시로 이 실물 시험은 어떤 경우에도 환산 속도13km/h(약3.611m/s)를 넘기지 않는다. 명령값뿐 아니라 엔코더 측정 속도의 과도 상승도 포함한다. 13km/h 자체를 목표로 주어 overshoot 여유를 없애지 않는다. 우선 목표10km/h 이하로 시험하며, 상위 시험이 필요해도 실제 응답에 맞춘 여유와 사전 차단을 먼저 검증한다.
- **실행 전 조건:** 실제 최종 감속비·바퀴 지름·엔코더 카운트 정의로 환산을 확인한다. 저속에서 속도 상한·과속 시 출력 차단·피드백 누락 시 차단·물리/패널 STOP의 동작을 확인한 뒤 단계 상승한다. 이 문서의 숫자는 현재 MCU/패널에 상한을 구현·적용했다는 증거가 아니다. 실행 담당이 적용 경로와 실제 읽은 값을 확인하지 못하면 고속 단계는 진행하지 않는다. 소프트웨어만으로 물리적 초과가 절대 없다고 보증하지 않는다.
- **기록:** 목표/측정 속도, 원시 엔코더 count와 시간, 출력, 가속 과도·최대 속도·정상상태 오차·진동/이상 유무를 남긴다. 공중 환산 속도는 실차 이동 속도가 아니며, 좌우 바퀴가 다르게 도는 디퍼렌셜에서는 단일 모터축 피드백만으로 각 바퀴 최고 회전수를 알 수 없다. 한쪽 바퀴를 붙잡거나 막은 채 고속 시험하지 않는다. 공중 결과를 접지 하중에서의 속도 추종 증명으로 확대하지 않는다.

## 3. 측정값을 어디에 적용하는가

### 기둥·전선·센서 장착: 기존 여유＋실측 외곽＋추가 움직임 여유

이 단계는 과거 요청의 필수 항목이며 단순한 라이다 화면 점검과 구분한다. 사용자는 뒤쪽 기둥에 전선을 감아 실제 두께가 CAD와 달라지고, 완전히 단단히 고정되지 않을 수 있다고 설명했다. [확정 패키징의 배선·고정 여유](PACKAGING_FINAL_2026_11_13.md#배선과-고정-여유--사용자-후속-지시)와 기존 도구를 따른다.

1. **실제 위치 확인:** 최종 전선 묶음과 고정 상태의 사진/근접 스캔으로 앞뒤 지주, 전선 포함 외곽, 센서와의 상대 위치를 대조한다. 설계의 앞면6mm 배선 예약은 실측값이 아니며 뒤 기둥에 감은 전선 두께로 대체하지 않는다. 마커 판·지지대·커넥터도 실제 C1 측정면에 걸리는지 확인한다. 센서 위치 자체가 달라졌다면 운동 보정의 `motion_lidar_x_m/y_m/yaw_rad` 등과 기하 설정도 함께 정합시킨다. 마스크만 넓혀 좌표 오류를 숨기지 않는다.
2. **사각 벽 안에서 배경과 분리:** 사용자는 열린 공간을 추가로 확보할 수 없다. **벽을 치우거나 밖으로 옮기는 것을 요구하지 않는다.** 기존 주변0.5m 무장애물 조건은 이전 간단 수집 방법의 전제이며, 보정의 필수 물리 조건이 아니다. 먼저 실제 스캔에서 네 벽의 긴 표면과 CAD/사진상 가까운 자기 구조의 각도·거리대를 대조한다. 센서가 차체 중앙보다 앞에 있으므로 ‘벽까지30cm’로 일괄 가정하지 않는다. 각 구조 방향에서 실제 벽과 후보 거리대가 분리되는지 확인한다.
3. **기준 기록과 필요한 재배치:** 최종 고정·실제 높이·모터 정지에서 최소10초/100스캔을 기록한다. 벽과 분리되는 근접 자기 반환은 이 기록으로 후보를 만든다. 겹치거나 모호한 구간에 한해서 사각형 안에서 차량을 몇 cm 옮기거나 방향을 조금 바꾸고 두 번째 정지 기록을 받는다. 차체에 고정된 지주/전선은 센서 기준에 대체로 남고 외부 벽은 위치가 달라진다는 차이를 이용한다. 센서 잡음·전선 흔들림 때문에 단순히 ‘값이 비슷하다’는 이유만으로 자기 물체로 확정하지 않으며, 실제 이동 전후 벽 표면의 변화와 부품 위치도 함께 대조한다. 몇 cm 이동만으로 분리가 안 되면 다른 방향의 여유를 활용하고, 그 부분만 기존 nominal 유지/미확인으로 남긴다. 다른 보정까지 중단하지 않는다.
4. **예상과 실제가 어긋난 경우:** 도구 검색은 nominal 각도 범위 밖±3도·거리 밖±20mm로 한정돼 있다. 실측 기둥 위치/배선이 이를 벗어나면 먼저 실제 위치로 nominal을 갱신한다. 이 검색 한계를 통과시키려고 주변의 모든 반환을 자기 물체로 학습하지 않는다. 현재 도구는 sector 중심을 자동 재추정하지 않으므로 위치가 바뀐 기둥은 실행 담당이 nominal의 중심/거리대를 명시적으로 수정한다.
5. **여유 적용:** 기본 추가 움직임 여유3mm, 거리 여유2mm, 각도 여유0.5°를 관측 외곽에 더한다. 이는 기존 임시 준비값이며 C1의 전체 거리 정확도나 진동 상한 보증이 아니다. 도구는 각도에서 `0.5° + asin(3mm / 최근접거리)`, 거리에서 관측 최소/최대±(3+2)mm를 사용하고 **기존 nominal과 합쳐 범위를 줄이지 않는다.** 실제 묶음이 더 흔들리는 근거가 있으면 그 움직임에 맞춰 여유를 늘리고 수치·근거를 기록한다. 필요시 사람이 가능한 범위에서 가볍게 배선/차체를 움직인 짧은 추가 기록을 받되 정지 기준 기록과 구분한다. 관측된 가장자리까지만 딱 맞춰 자르지 않는다.
6. **같이 적용:** 검토한 후보의 `mask`만 새 설치 실행 YAML의 planner·guard 양쪽 `lidar_blind_sectors_json`에 같은 값으로 적용한다. `known_structure_policy`와 실제 기하/원시 scan frame의 정합성을 함께 확인한다. 동일 각도라도 해당 가까운 거리 밖의 벽/차량 반환은 유지하고, 미반환을 자유 공간으로 만들지 않는다. 실제 원자료는 삭제하지 않는다.
7. **재확인:** 같은 사각 공간에서 네 방향으로 놓아 자기 반환 때문에 생기는 가짜 장애물이 줄었는지, 같은 방향의 외부 벽은 남는지 비교한다. 짧은 저속 이동 후 배선이 위치를 바꾸면 그 부분만 다시 측정한다. 마스크 확장으로 늘어난 실제 사각은 기록하고 전 방향이 보인다고 설명하지 않는다.

**실행 도구 구분:** 현재 `review_c1_self_returns.py`에는 사각 벽 배경 분리 기능이 없고 `nearby_clear` 확인을 요구한다. 따라서 아래 기존 명령을 이번 벽 안의 원자료에 그대로 실행하면서 `--nearby-clear-confirmed`를 주지 않는다. 벽 안 절차에서는 실행 담당이 저장 원자료의 구조별 후보와 벽을 분리하고, 위5항의 동일 여유 계산/기존 nominal 합집합 규칙으로 후보 JSON을 생성·대조한다. 이 작업은 파일 기반 분석이며 새 주행 제어기나 마스크 자동 학습을 추가하는 것이 아니다. 전체 원시 스캔과 제외한 벽 반환 근거를 함께 보존한다. 기존 CLI 자체에 벽 안 모드가 구현되었다고 표시하지 않는다.

다음은 **주변 무장애물 조건을 실제로 만족하는 경우에만** 사용할 수 있는 기존 명령 참고이며, 이번 사각 공간의 필수 명령이 아니다.

```bash
PYTHONPATH="$PWD/src/arena_autonomy${PYTHONPATH:+:$PYTHONPATH}" python3 scripts/review_c1_self_returns.py \
  --input "$UNMASKED_C1_JSONL" --nominal-mask "$INSTALLED_NOMINAL_MASK" --frame-id "$ACTUAL_C1_FRAME" \
  --stationary-confirmed --nearby-clear-confirmed \
  --residual-motion-mm 3 --range-noise-mm 2 --angular-noise-deg 0.5 --output "$NEW_SELF_MASK_CANDIDATE"
```

세 여유값은 위 기존 초기값이다. 근거가 있으면 실제 설치 후보에서 수정하며 원 nominal/수정 사유를 보존한다. 도구 출력은 `applied=false`이므로 파일 생성만으로 설치 적용 완료라고 하지 않는다. 원자료·nominal·후보·최종 YAML·양쪽 실제 읽은 parameter·적용 후 비교 그림을 같은 회차에 묶는다.

### IMU: 정지 편향을 실제 운동 보정 입력에 반영

이미 구현된 경로는 `MotionInput`의 장착 축 투영 → `MotionHistory.add_gyro`의 `yaw_rate - gyro_bias_rad_s`다. ROS 설정명은 **`motion_gyro_bias_rad_s`**, 단위는rad/s다. `motion_imu_roll_rad`·`motion_imu_pitch_rad`로 계산하는 차체 yaw축은 다음과 같다.

`axis = (-sin(pitch), cos(pitch)*sin(roll), cos(pitch)*cos(roll))`

1. 실제 장착 방향을 확인한 뒤, 같은 ROS 원시 각속도에 위 축을 투영한다. 임의로 sensor.z만 사용하지 않는다.
2. 사람이 정지 상태를 확인한 구간에서 `b = mean(axis·gyro)`를 구한다. 표본 수·원시/투영 평균·표준편차·전반/후반 평균·누락·frame/boot를 같이 남긴다. 정지 모터축은 차체 정지의 단독 증거가 아니다.
3. 실행 담당이 원자료와 배치를 대조한 뒤, 동일 설치 실행 YAML의 **`local_pursuit`와 `lidar_safety` 양쪽에 같은 `motion_gyro_bias_rad_s=b`**를 넣는다. IMU bridge/MCU에서 이미 같은 편향을 뺐는지 확인하여 두 번 빼지 않는다. 무효/누락 입력을0으로 채우지 않는다.
4. 기존 설치 선택 생성 경로로 새 실행 폴더를 만든다. 해시 검증되는 기존 생성 YAML/manifest를 직접 고치지 않는다. 두 노드를 정지 후 새 파일로 시작하고 실제 읽은 parameter와 원시 증거를 확인한다.
5. 새 정지 구간에서 보정 후 평균이0에 가까워지는지 확인한다. 이후 F의 실제 바닥 조향 주행에서 아래 고정 마커/벽 기준 회전량과 비교해 부호·대략적인 크기를 확인한다. 손으로 정확히 한 축만 돌리는 동작은 필수가 아니다. 축 반전은 편향으로 고칠 수 없다.

전체 가속도계/온도/자이로 scale 교정, 절대 방위 보정은 이번 범위가 아니다. 정지 가속도에서 중력을 통째로 빼지 않는다. 기존 `audit_hardware_capture.py`는 편향 후보 통계를 만들지만 자동 채택 도구가 아니며, 현재 기록 형식과 맞지 않으면 그 형식의 parser를 사용한다. 기존 runtime/ROS 기록을 보존하고 단위·축 변환을 명시해 집계한다.

### 실제 조향 주행으로 회전량 대조 — 손 회전 대신

사용자 제안대로 바퀴를 바닥에 놓고 조향하여 짧게 움직이는 것을 기본으로 한다. 사각 벽·마커는 고정하고, 이동 전후에 잠시 정지한 관측을 사용한다. 카메라 근사 배율 E가 끝나면 F에서 수행한다.

1. 같은 벽/마커가 보이는 시작 자세에서 짧은 정지 영상·라이다·IMU를 기록한다. 작은 조향과 낮은 속도로 짧게 이동하고 다시 정지해 끝 자세를 기록한다. 이 두 정지 구간 사이의 실제 IMU 시각으로 편향 보정 각속도를 적분한다. 도착 정지 관측을 여러 프레임 합쳐 영상 지연·순간적인 흔들림의 영향을 줄인다.
2. **라이다 기준:** 같은 물리 벽의 직선 방향이 센서 좌표계에서 얼마나 바뀌었는지 본다. 순수 평행 이동은 벽까지 거리만 바꾸고 직선 방향은 바꾸지 않으므로 회전과 이동을 구분하기 좋다. 직선 방향의180도 모호성을 가까운 연속 자세로 풀고, 다른 벽/차체 반환을 같은 벽으로 연결하지 않는다. 벽 네 면이 직각일 필요는 없고 같은 벽이 충분히 보이면 된다.
3. **카메라 기준:** 같은 고정 마커의 모서리로 구한3차원 회전 자세의 전후 차이를 실제 카메라→차체 장착 자세에 맞춰 변환한다. 단순 화면 중심 이동량은 병진과 회전이 섞이므로 회전각으로 사용하지 않는다. roll/pitch까지 달라졌다면 전체 회전 관계로 비교하고 이미지의 수평 기울기만 yaw로 읽지 않는다.
4. 마커는 작은 정면 정사각형이고 intrinsic도 근사이므로 자세 모호성/잡음이 생길 수 있다. 카메라만을 정확한 기준각으로 취급하지 않는다. 같은 벽의 방향과 마커 자세가 모순되거나 각 변화가 잡음 수준이면 그 구간은 scale 보정 근거로 채택하지 않고 부호/대략 반응 확인까지만 남긴다.
5. 전진 좌회전·전진 우회전 대표를 우선한다. 후진은 실제 모터/기존 수동 명령의 지원·부호를 확인한 경우에만 별도 짧은 구간으로 사용한다. 후진이 준비되지 않았으면 전진 뒤 사람이 다시 배치하며, 이 시험 때문에 자동 후진 기능을 새로 만드는 것을 선행 조건으로 삼지 않는다. 왕복 합계가 거의0이면 오차가 서로 지워질 수 있으므로 각 구간을 따로 비교한다.
6. `IMU 적분 yaw`, `같은 벽 상대 yaw`, `마커 상대 yaw`, 실제 조향/이동 명령과 시간·최종 정지 관측의 산포를 남긴다. CAD 조향각으로 예측한 회전량은 기구/미끄럼 오차가 있으므로 참값으로 쓰지 않는다. 먼저 부호·장착 축·정지 편향을 고치고, 반복적으로 일치하는 근거가 있을 때만 추가 scale 보정의 필요성을 판단한다. 현행 코드에 검증된 scale 적용 경로가 없으면 있다고 가정하지 않는다.

이 대조 방법을 현장 절차로 채택했으며, 현재 별도3센서 자동 회전 교정 프로그램을 실행하거나 구현 완료했다고 주장하지 않는다. 기존 원자료를 실행 담당이 파일 기반으로 비교한다. 차량 조향/실제 접지 확인을 겸하여 별도 정밀 손 회전 실험을 늘리지 않는다.

### 카메라: 실제 인쇄 크기로 근사 거리 배율 보정

기존 [프로필](../../config/perception/vehicle_marker_approx_b0390.json), [영상 검사](../../scripts/inspect_vehicle_marker_image.py), [간이 보정](../../scripts/adjust_vehicle_marker_profile.py)을 재사용한다. 새 파일을 생성하며 원 프로필은 보존한다.

1. 실제 출력물의 **검은 코드 외곽** 한 변을 잰다. 전체 흰 여백 포함5cm를 코드5cm로 넣지 않는다. 팀별 비율이 다르므로 하나의 측정값을 모든 ID에 복사하지 않는다. dictionary/ID도 영상으로 대조한다.
2. 실제 사용 해상도/크롭/회전으로 정면 사진을 저장한다. 높이가 약20cm라고 해서 광축과 자동 정렬됐다고 가정하지 않는다. 마커가 중앙 근처에 오고 평면이 광축에 가능한 수직이 되게 놓는다.
3. 렌즈에서 마커 평면까지의 광축 방향 거리와 코드 픽셀 폭을 이용한다. `fx_px = pixel_width × optical_depth_m / black_code_size_m`. 한두 거리의 [표본 형식](../../config/perception/vehicle_marker_samples_template.json)을 채운다. 범퍼 거리/비스듬한 유클리드 거리를 그대로 넣지 않는다.
4. 기본은 `focal_pixels`를 한 번 적용한다. 기존 도구는 정사각 픽셀 근사로fx/fy를 함께 설정하므로 전체 intrinsic 교정으로 부르지 않는다. `range_scale`은 기존 초점거리를 유지할 때 선택하는 대안이며 같은 오차를 두 방식으로 중복 보정하지 않는다.
5. 보정에 쓰지 않은 다른 위치 또는 다른 마커 사진으로 거리 오차를 비교한다. 두 거리의 배율이 크게 다르면 잘못된 테두리·기울기·크기·해상도를 먼저 확인한다. 흰 판/검은 코드의 중복 후보를 임의로 골라 평균내지 않는다.
6. 주행 보조를 채택할 때만 두 노드에 같은 **`vehicle_marker_profile_path`**를 명시한다. 빈 경로는기존OFF다. 카메라 위치/자세는 실제 장착값을 별도로 반영하며 거리 배율 보정으로 맞았다고 취급하지 않는다.

기존 환경에서 실행할 파일 기반 명령(장치 구동 없음):

```bash
PYTHONPATH="$PWD/src/arena_autonomy${PYTHONPATH:+:$PYTHONPATH}" python3 scripts/inspect_vehicle_marker_image.py --profile "$MARKER_PROFILE" --image "$FRONT_IMAGE" --output "$NEW_INSPECTION"
PYTHONPATH="$PWD/src/arena_autonomy${PYTHONPATH:+:$PYTHONPATH}" python3 scripts/adjust_vehicle_marker_profile.py --profile "$MEASURED_SIZE_PROFILE" --samples "$FRONTAL_SAMPLES" --method focal_pixels --output "$NEW_MARKER_PROFILE"
```

변수는 그날 생성한 실제 파일로만 채운다. 검사 도구의 `black_code_pixels` 목록은현재4×4 전용이므로7×7 ID91을 이 목록에 없다는 이유로 미검출 처리하지 않는다. 전체 `regions`/`rejected`와7×7 검출 결과를 따로 확인하고, 근사 배율용 첫 표본은 지원되는4×4 마커를 사용하는 것이 간단하다.

**벽에 붙인 다른 팀 마커는 점유 보조에서 가상 차량을 만든다.** 광학 시험은 비구동/저장영상으로 진행하고, 일반 벽·짧은 이동 시험에서는 마커 점유 옵션OFF를 유지한다. 마커 보조ON 확인은 별도 단계로 구분한다. 벽 앞 가상 차량 때문에 멈춘 것을 조향 실패로 오인하지 않는다. 이 작은 공간의 가까운 사진만으로 먼 거리 정확도/신호등 인식을 검증했다고 하지 않는다.

- 엔코더: 단일 모터축28카운트·11.911764706:1·65mm 기준을 유지하고 부호와 대략적인 실이동 환산을 먼저 본다. 짧은5cm 이동의 한 번 오차만으로 기어비/반경을 바꾸지 않는다. 들린 차동기 양쪽 바퀴의 개별 속도는 차체 속도 검증이 아니다.

## 4. 자동 기록·반영·재개 규칙

실행 담당은 `artifacts/validation/<날짜>/assembled_car_box_<시각>/`에 같은 회차를 모은다. 원시 bag/상세 수신은 기존 Git 제외 정책으로 보관하고, 공개 보고서에 비밀번호·원격 credential을 넣지 않는다.

- `setup.json`: 조립 식별, 실제 소스/설정 SHA, firmware/포트/frame, 센서 장착, 벽/마커 치수·ID, 확인자 전달, 미측정값은null.
- 단계별 원자료: 정지IMU, 미마스크C1, 원 RGB, host/MCU 사건과 단발 명령·피드백, 사람의 실제 움직임/STOP 관찰.
- `calibration_before/`, `calibration_candidate/`, `calibration_selected/`: 원본/후보/채택을 구분. 측정값·단위·계산법·적용 양쪽 노드·파일 SHA·실제 재시작/읽기 확인을 남긴다. 후보만 만든 경우 selected를 만들지 않는다.
- `RESULT.md`: 각 단계 완료/실패/미실시, 보정 전후 수치, 남은 실물 의존 사항, 다음 명령을 짧게 적는다. 다음 세션은 이 결과와 실제 활성 프로필을 확인하고 완료한 시험은 되풀이하지 않는다.

자동 측정/집계·파일 생성은 GPT가 기존 도구를 조합하여 수행한다. **현재 완성된 단일 원클릭 교정 앱은 없다.** 사람이 필요한 배치/치수/직진·물리 STOP 확인과 그에 따른 짧은 실행으로 구성하며, 임의 자세를 자동 추정해 모든 계수를 한꺼번에 채택하지 않는다. 실제 시험 때는 이 절차를 먼저 읽고 준비된 경로를 사용한다. 명시적 재연결/환경 준비 확인 전 장치를 조작하지 않는다.
