# 2026-09-08 실행 속도 병목 분리

## 센서·ROS 없이 확인한 비용

공식 운영 월드의 진단 사본을 Gazebo C++ 서버로 직접 실행했습니다.
차량은 없으며 GUI·ROS·카메라 없이 100회 준비 갱신 후 1,000회(1 ms 간격)를 계측했습니다.
벽시계 대기 제한만 해제하고 실제 물리 시간 간격은 유지했습니다. 준비/로드/종료 시간은 제외합니다.
엔티티 존재와 누적 1,100회 갱신을 확인합니다.

| 조건 | 1 sim초 계산의 실제 시간 | RTF |
|---|---:|---:|
| 전체 정적 코스·기본 플러그인 | 6.5996초 | 0.1515 |
| 같은 코스·물리 플러그인만 | 5.4697초 | 0.1828 |
| 같은 코스·물리 플러그인 제외 | 1.2250초 | 0.8164 |
| 빈 월드·물리 플러그인만 | 0.00454초 | 220.4 |

시작 시각이나 GPU 사용률로 원인을 추정한 것이 아니라, 코스의 물리 계산만으로도 큰 비용이 발생함을 분리했습니다.
코스 충돌 형상은 3,740개이며 서로 다른 조건의 시간을 완전히 독립적인 합으로 해석하지 않습니다.
빈 월드의 속도를 차량·센서가 있는 실행의 목표 속도로 사용하지 않습니다.

## 충돌 검출 방식 비교

DART 물리 엔진·솔버·시간 간격·코스 형상·표면 물성은 유지하고 `physics/dart/collision_detector`만 비교했습니다.

| 검출 방식 | 물리 1 sim초 계산 시간 | RTF |
|---|---:|---:|
| ODE 명시 | 5.1619초 | 0.1937 |
| Bullet | 2.3412초 | 0.4271 |
| FCL | 5.0984초 | 0.1961 |
| DART | 90초 제한 안에 완료하지 못함 | 미산출 |

이것은 물리 엔진 전체를 Bullet로 교체한 시험이 아닙니다. 같은 형상이라도 검출기마다
접촉점·접촉 법선·바퀴 접촉 판정에 차이가 있을 수 있으므로 기존 주행 통과를 승계하지 않습니다.
설치된 버전이 지원하는 설정은 [Gazebo 8 공식 문서](https://gazebosim.org/api/sim/8/physics.html)를 확인했습니다.

## 선택형 구현

`simulation.launch.py`와 `demo.launch.py`에 다음 인수를 추가했습니다.

- `collision_detector:=configured|ode|bullet|fcl`: 기본은 configured이며 기존 설정 유지.
- `scene_broadcaster:=true|false`: 기본 true. false는 headless에서만 허용하며 GUI·정답 pose 스트림을 발행하지 않음.

원본·공식 운영 SDF를 수정하지 않고 실행 전 임시 사본을 만들며, 상대 리소스 경로를 원본 기준 절대 경로로 풉니다.
종료 시 임시 사본을 정리합니다. 차량·코스 크기·센서 사양·마찰·질량·물리 시간 간격은 바꾸지 않습니다.
SceneBroadcaster의 `/world/it_arena_track/dynamic_pose/info`는 기존 자율주행/시설/ToF 검증기가 사용하므로
이들 검사에서는 false를 사용하지 않습니다. 실제 차량 제어에 정답값을 추가한 것은 아닙니다.

전체 실행 결과와 실패 원문은 [산출물](../../artifacts/validation/2026-09-08/performance/)에 보존합니다.

## 실제 센서·주행 비교

RGB/깊이 848×480·30 Hz, ToF6 8×8·15 Hz, 순간 LiDAR, 공식 코스에서
영상 90개(2.938 sim초) 계측 후 직진·조향·명령 중단 정지를 수행했습니다.

| 조건 | 영상 계측 RTF | 실제 시간당 RGB 수신 | 판정 |
|---|---:|---:|---|
| 기존 CPU·기본 충돌 검출 | 0.10953 | 3.318 Hz | 전체 통과 |
| CPU·Bullet 충돌 검출 | 0.14302 | 4.332 Hz | 전체 통과 |
| CPU·Bullet·SceneBroadcaster 제외 | 0.13937 | 4.222 Hz | 전체 통과 |
| GPU·Bullet·SceneBroadcaster 제외 | 0.14222 | 4.308 Hz | 주행/정지는 통과, 종료 실패 |

네 조건 모두 시뮬레이션 시간당 RGB/깊이 수신은 약 30.293 Hz였습니다.
Bullet 비교는 약 31% 진행 속도 개선이며 같은 sim시간을 계산하는 벽시계 시간은 약 23% 감소합니다.
단일 짧은 비교로 평균 개선율을 보장하지 않습니다. 상태 발행 제거와 GPU 추가의 이득은 확인하지 못했습니다.
충돌 검출 변경은 접촉 계산에 영향을 줄 수 있어 [ADR 0017](../decisions/0017-optional-collision-detector-performance.md)에 따라 기본값 변경을 보류했습니다.

## GPU 종료 진단

GPU 실패 실행은 종료 요청 2초 후 GDB로 스택을 읽었습니다. 렌더 스레드는
`Ogre::SceneManager::destroySceneNode`→`free` 경로에 있었고, D3D12 core는 여전히 로드되어 있었습니다.
이는 단일 시각의 스택으로, 영구 교착이나 core 라이브러리 해제 실패를 확정하는 자료는 아닙니다.
GDB는 종료 단계만 일시 정지했으며 영상 계측에는 개입하지 않았습니다. 종료 시간 자체는 교란될 수 있습니다.

별도 진단은 smoke의 `--shutdown-grace 70`으로 SIGINT 유예를 60초로 늘렸습니다.
첫 실행은 약 2.02초 만에 정상 종료했으므로 늘린 한도가 해결책이라는 증거가 아닙니다.
같은 조건 반복에서는 SIGINT 유예 60초에도 끝나지 않아 약 65.28초 후 강제 종료됐습니다.
두 유예 진단은 디버거를 사용하지 않았습니다. 따라서 단순한 짧은 제한시간 문제로 보지 않습니다.
`gazebo_sigterm_timeout` 기본은 기존 5초, smoke 전체 기본 유예는 15초로 유지합니다.
GPU는 계속 선택형이며 기본 경로를 바꾸지 않습니다.

## 검사

후속 사용자 요청으로 [센서 단독·500 Hz 순차 LiDAR GPU 비교](GPU_FINAL_DIAGNOSTIC_2026_09_08.md)를 추가했습니다. 실제 순차 시험 전체 시간은 약 33% 감소했고 양쪽 정상 종료를 통과했습니다. 위 공식 코스 순간 스캔의 'GPU 추가 이득 없음'과 부하 조건이 다릅니다.

Python 58개와 변경 형식 검사를 통과했습니다. 새 검사는 운영 원본 바이트와 3,740개 충돌 형상·물성의 보존을 확인합니다.
실행별 모든 자식 종료는 `summary.json`에 재감사했습니다. 원문 실패는 그대로 유지합니다.

초기 `.log`는 명령 전달 중 변수명이 사라져 빈 월드를 측정한 실패 기록이며 어떠한 성능 수치에도 사용하지 않습니다.
후속 계측기는 엔티티와 실제 갱신 횟수를 확인합니다.
