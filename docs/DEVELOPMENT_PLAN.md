# 현행 개발 계획: 빠른 완주와 주행 지속성

갱신: **2026-11-02**. [11/1 중간 점검](reports/MIDPROJECT_REVIEW_2026_11_01.md)과 [최종 회의·공식 배포 검토](reports/OFFICIAL_UPDATE_2026_11_02.md)를 함께 반영한다. **직접적인 충돌 위험이 없으면 급정거나 큰 폭의 감속을 줄이고 속도를 꾸준히 유지한다.** 단독 속도와 다중 차량 대응은 계속 핵심이며 새 운영 화면 때문에 뒤로 밀지 않는다. 사용자 결정은 [ADR 0028](decisions/0028-speed-continuity-and-final-gearing.md), 적용 상태는 [현재 현황](PROJECT_CONTEXT.md), 정리 전 계획은 [보관본](archive/2026-11-02-plan/DEVELOPMENT_PLAN.before.md)에 있다.

**직선 차체 최고속도 2 m/s급은 제한 시뮬에서 확인했고 다음 목표는 10 km/h(2.78 m/s)다.** 모든 코너의 목표속도가 아니다. 단발 최고속도보다 랩 시간·불필요 정지·앞차가 움직일 때의 진행을 함께 본다. 드문 오류 조합 전수 검증이나 보호 조건의 누적을 완주의 선행 조건으로 만들지 않는다. 실제 앞길 점유·명시 STOP·지속 입력 고장은 지키되, 개별 감속/정지 조건은 경기 손실과 관측 근거에 따라 단순화·개선한다.

## 작업 순환과 중단 기준

**한 축을 완벽하게 끝낼 때까지 머무르지 않는다.** 다음은 작업 운영 기본값이며, 완주를 막는 새 고장이나 사용자 지시에 따라 바꿀 수 있다.

- 한 묶음은 **문제 하나 → 근거 비교 → 필요한 수정 → 영향 범위 검증/대표 실행 → 결론·재개 조건**이다.
- 시작 후 **약 60–90분**에 결과·남은 범위를 점검한다. 약 2시간이 지나도 원인이 안 좁혀지면 새 장시간 시험을 추가하지 않고 현재 실행을 적절히 마쳐 다음 축으로 옮긴다. 진행 중 시험을 시계에 맞춰 강제 종료하라는 뜻은 아니다.
- **A 단독 속도 → B 다중 차량 → C 운영 또는 D 장비·성능 → A**를 기본 순환으로 한다. 운영 최소 기능이 없는 동안에는 C를 먼저 배정한다. D는 가용 장비·최신 후보·지연 근거가 있을 때 수행하며 의미 없는 미세 최적화로 채우지 않는다.
- 같은 축에서 두 묶음을 연속하려면 **다른 축도 막는 공통 결함**, 곧 끝나는 필수 검증, 실제 충돌/구동 오류 중 이유를 기록한다. '아직 실패가 남음'만으로 연속 작업하지 않는다.
- 성공 후에도 새 무작위 사례를 계속 붙이지 않는다. 실패 후에도 **가설·입력·코드 변화가 없으면 재실행하지 않는다.** 미성립 장면은 미검증으로 남긴다.
- 다음 순환의 재개 항목은 **실패 장면·현재 가설·필요한 자료/변경·경기 영향**을 남긴다. 이것은 매번 사용자 승인을 요청하는 절차가 아니라 자동 진행의 기준이다.

순환 기준은 시간 배분이다. 통과만을 위해 보호 조건·물성·판정선을 낮추라는 뜻이 아니다. 반대로 과거 실험 수치를 영구 금지선으로 고집하지도 않는다.

### 직접 시험할 최소 장면

- **단독:** 긴 직선 가속→급커브→마커 기준 벽 전환을 포함한 한 랩. 최고·1초 평균 최고·유지 시간/거리와 랩 시간을 따로 기록한다.
- **전방:** 느린 차 추종→급정지→재출발, 다른 차 끼어들기. 별도로 우회 중 상대 재출발 후 뒤 합류. 상대 위치 정답은 제어 입력으로 쓰지 않는다.
- **측방·가림:** 좁은 코너 피추월/복귀, 오른쪽 재접근 또는 갈림길 ID30+벽 가림 중 하나. 두 바퀴 잔디를 활용한다. 고정 150/97 mm 비교선을 실물 최소 간격으로 강제하지 않는다.
- **운영:** 최초 시각 출발, 높은 앞차가 가린 신호, STOP→재배치→복구 RESET→같은 경기 START. 신호 없이 앞차만 움직인 경우와 실제 초록이 나중에 보인 경우를 구분한다.
- **표적:** 박스 외형만으로 완료하지 않는다. 비스듬한 차·개방형 또는 돌출 윤곽의 대표 하나를 교통 묶음에 포함하되 모든 차체를 전수 탐색하지 않는다.

### 속도·보호·연산을 판단하는 기준

- 계획 명령→독립 보호 출력→MCU 목표→모터축→차체 중 처음 속도가 막히는 곳부터 본다. 차체 정답 속도/자세는 **평가 전용**이다.
- C1 10 Hz 한 회전 동안 2 m/s에서 20 cm, 10 km/h에서 약 28 cm 움직인다. 관측 거리·스캔 보정·선행 감속·처리 지연을 함께 본다. 제동/마찰을 임의 변경해 최고속도 숫자만 맞추지 않는다.
- 단일 튐·짧은 RGB 공백·음수 축 속도 한 표본과 실제 앞길 점유를 구분한다. 관측이 뒷받침하는 경로는 감속해 이어가되 미관측을 자유 공간으로 채우지 않는다. /drive → 독립 보호층 → /drive/safe·명시 STOP을 유지하며 과한 일시정지 분기는 근거에 따라 줄인다.
- CPU 비용 개선은 실제 입력 적체·제어 마감 초과나 주행 손실을 줄일 때 우선한다. PC 재생과 Jetson 전체 부하, 시뮬 시간과 실제 시간을 구분한다. 전체 회귀의 오래된 전제/소스 계약 실패는 구성 선정 때 정리하되 실제 새 회귀를 숨기지 않는다.
- 종료 직전 요약 0.417초 누락은 다음 평가 정비에 함께 처리하며, 기록만 채우려고 코스를 다시 돌지 않는다.

**턱 인식·턱 전용 감속·정밀 현가는 필수 목록에서 뺀다.** [과거 방지턱 실패](../artifacts/validation/2026-10-31/g1_continuous_prefix_course_v1/run1_bump_analysis.json)는 보존한다. 음수 모터축에서 전진 복구, 도로/잔디 단차의 편측 접지, 차동기 헛돎과 차체 이동의 차이, 피치/롤 센서 변화는 일반 주행 문제이므로 남긴다. 실물에서 증상이 확인되면 모델을 보강한다.

[구매표](<../assets/hardware/procurement/2026-11-01/RC카 제작물품구매 견적_ISAAC.xlsx>)의 59 mm는 댐퍼 길이이지 스트로크·강성·감쇠가 아니다. 공칭 8.9706:1·65 mm·28카운트도 조립 뒤 확인한다. 센서/BOM을 다시 고르지 않고 [제작 전달 목록](HARDWARE_AND_RULE_QUESTIONS.md)의 실제 치수·가림·전원·STOP·응답을 받는다.

## 남은 일정과 통합 마감

**사용자 예상:** 부품까지 약 1주일, 실제 주행 시험은 마지막 약 1주일. 확정 납기가 아니므로 늦어지면 기능 범위를 조정하고 현가 정밀화·새 센서 구매로 시간을 쓰지 않는다.
