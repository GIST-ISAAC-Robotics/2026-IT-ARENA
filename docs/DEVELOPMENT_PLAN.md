# 현행 개발 계획: 빠른 완주와 실제 실행 연결

갱신: **2026-11-13 시간표 없는 상시 작업 큐·조립 후 최소 시험 방침 반영**. [전체 재점검](reports/READINESS_REVIEW_2026_11_12.md)의 근거와 우선순위를 적용한다. 과거 시점별 계획과 ‘다음 작업’은 [바이트 보관본](archive/2026-11-12-midproject/DEVELOPMENT_PLAN.before.md)에 보존했다. 실제 결과는 [현재 현황](PROJECT_CONTEXT.md), 상세 실패와 변경은 [실행 보고서](reports/DECISION_EXECUTION_2026_11_11.md)가 기준이다.

목표는 **직접 충돌 위험이 없고 진행 경로가 보이면 급정거·큰 감속을 줄이며 빠르게 완주하는 것**이다. 단독 최고속도 약10 km/h의 제한 대표는 이미 확보했다. 현재 우선은 조립 전에 **구동 없이 사용 가능한 센서·MCU 상태의 공통 실행을 연결하고 Jetson 지연을 줄이는 것**이다. 실제 모터·서보·엔코더의 최종 구동 보정은 차체 완성 후에 한다. r230의 한 랩 초과 뒤 남은 저속 구간만 계속 보강하며 실물 통합을 금요일 밤으로 미루지 않는다. 이 목표를 안전 조건의 무조건 누적이나 불확실성의 무조건 무시로 바꾸지 않는다. [ADR 0028](decisions/0028-speed-continuity-and-final-gearing.md)을 따른다.

**최신 사용자 전달:** 설계는11/12 저녁~11/13 새벽, 차량 조립은11/13 금요일 저녁 예상이다(확정 납기 아님). Jetson에 ESP32·C1·카메라·IMU가 연결된 것으로 사용자가 추정했으며, 실제 연결·현재 MCU 앱·정상 수신은 다음 시험 전에 확인한다. 이전 모터 시험 당시 IMU 분리 기록을 현재 상태로 고정하지 않는다. 컴퓨터를24시간 켜 두고 시뮬/Jetson 시험을 이어갈 예정이라는 가용시간을 계획에 반영한다. Jetson 성능/Hz와 랩타임·추월 작업 범위를 논의한 뒤, **사용자가 이 계획의 main 반영을 승인했다.** 센서/제어 주기·전력 설정을 변경하거나 새 상시 시험을 시작한 결과가 아니다.

**11/13 장비 가용성:** 사용자가 Jetson·ESP32·IMU 재사용을 허용했다. 수동 확인에서 원 IMU 앱/inactive·WHO_AM_I와 포트 반환을 확인했다. 현재 배선을 재확인하며 실물 입력/판단 비용 시험을 재개하고, 기존 원시 실패와 비구동 원칙을 유지한다.

**11/12 설계·시설 후속 지시:** 별도 설계 검토에서 전달한 차량 지주 단면/배선 전방·안쪽 부착과 C1 상대 위치, 카메라 높이를 CAD 추정 프로필로 반영한다. 상부 전체·질량·구동계 확정으로 확대하지 않는다. 현재 작성 중인 MCU peripheral 결합은 비구동 빌드 준비로 보존하고 이 형상 반영을 먼저 진행한다. 이후 공식 저장소의 **새 신호등 STL**을 확인하며, 트랙 아루코 마커 지주도 신호등과 같은 배치/형상이라는 **사용자 시험 가정**으로 비교한다. [r290](../artifacts/validation/2026-11-12/cad_mount_r290_v1/README.md)에서 차량 지주/센서 선택형 연결과 정지 수신까지 확인했다. [r291](../artifacts/validation/2026-11-12/signal_post_revision_r291_v1/README.md)에서11/12 제작측 첨부 STL을 확보했으며 앞뒤 대각 버팀대가 추가된 것을 확인했다. 선택형 시설 이관 뒤 r292첫12m는 통과했지만 r294한 랩은19.87m 경계 미확정으로 실패했다. 저장 입력에서 원인을 분리하며 마커 지주의 동일 사양까지 공식 확정된 것으로 쓰지 않는다. 차량 자체 기둥과 트랙 시설 지주를 구분한다.

### 랩타임·추월 성능 작업의 범위

**11/13 영상 후속 조건:** 실제 신호등 촬영/HSV 맞춤은 사용자 일정·재료상 어렵고 intrinsic 보정은 추후 담당자에게 맡긴다. r339 저장 변형에서 밝기0.60배 미검출·밝은 소등 초록의 늦은 출발 오검출을 확인했으므로 단순 색 임계값 완화 대신 점등 전/전이 근거를 검토한다. 사용자 승인으로 낮은 상대용 마커 보조를 기본OFF 옵션으로 준비하며 r340은 관측/기록까지만 연결했다. 감속 연결 전에 직선 앞차·옆차·커브·중복 크기·소실의 제한 반례를 확인한다. r341의4mm 판/8mm 분리 지주처럼 희소 상부는 기존 오목형과 구별해 대표 교통 시험에 넣되, 없는 반환을 자유 공간으로 채우거나 실제 차체 외곽을 줄이지 않는다. 정밀 거리/추종과 전수 형상 검증으로 확대하지 않는다. [조건·구현 구분](sensors/B0390_SIM_2026_11_07.md#1113-실물-신호-시험-불가와-차량-마커-보조-검토).

목표인 빠른 완주와 기존 추월 과제는 유지한다. 추가 랩타임/고속 추월의 P2 분류는 이번 일정 수정 전에도 있었으며, 이번 변경으로 성능 개발을 종료한 것은 아니다.

- **현재 주행 손실은 계속 줄인다.** 계산 지연·명령 만료 때문에 생기는 정지/저속, 불필요한 추종 감속, 기존 속도·우회·추월의 퇴행은 원인에 따라 P0 실행 지연 또는 P1 주행 과제로 처리한다. 최고속도만 보지 않고 긴 저속·속도 유지·랩 시간을 함께 평가한다.
- **기본 교통 동작을 완성한다.** 앞차 추종, 정지차 우회/복귀, 피추월·코너 측방 대응과 기존 직선 추월의 연결을 유지한다. 저속 직선 대표의 성공으로 중속/변속·빠른 상대 추월까지 완료 처리하지 않으며, 미완료 범위는 아래 기존 과제 목록을 따른다.
- **추가 성능 개선으로 돌아가는 조건을 둔다.** 선택한 실행 구성으로 입력→판단→보호→MCU 명령 경로와 단독/대표 교통 주행이 성립하면, 남은 모든 예외가 없어질 때까지 기다리지 않고 랩타임·고속 유지·직선 추월의 시간 이득을 비교한다. 실물 통합 일정을 침범하지 않는 독립 시뮬 묶음은 앞서 진행할 수 있다. 채택은 실제 계산 지연과 갱신된 형상을 반영한 결과로 판단한다.
- **최종 설계와 결합된 튜닝은 설계 반영 뒤에 집중한다.** 축거·조향·센서 가림 변화의 영향을 받는 코너 속도/궤적과 추월 간격은 새 모델에서 확인한다. 설계가 없어도 고칠 수 있는 실행 병목·확인된 주행 오류는 먼저 처리한다.
- **경기 이득으로 작업을 고른다.** 추가 최고속도, 코너 감속/재가속, 빠른 상대 직선 추월, P21 중 실제로 시간을 줄이는 항목을 우선한다. 공격적인 코너 추월·세 대 동시 추월은 기존대로 확대하지 않는다. 관제 화면 미관과 드문 형상의 전수 검사는 성능 개선보다 뒤다.

### 24시간 가동 작업의 운용 방식

- **시각별 작업표 없음.** 사람의 수면·휴식에 맞춰 중단하지 않는 작업 큐로 구성한다. 단, 문서를 수정했다는 사실이 실제 PC/Jetson 백그라운드 작업이 시작됐음을 뜻하지는 않는다. 실제 실행은 프로세스/로그로 확인해야 한다.
- 매 순환은 **고정한 입력·소스 → 한 병목/대표 실패 → 필요한 수정 → 관련 회귀/대표 실행 → 결과·다음 재개점** 순으로 마친다. 우연히 통과한 1회 실행을 전체 성능 완료로 부풀리지 않는다.
- 노트북은 독립 시뮬·실패 기록 분석, Jetson은 저장 입력 비용과 비구동 실제 센서 통합을 맡긴다. Jetson 성능 기준 측정에는 무관한 CPU 부하를 겹치지 않고, 실제 통합 부하는 카메라/C1/IMU/ROS를 의도적으로 같이 넣는다.
- 포트 소유/배선/현재 펌웨어가 불분명하면 강제 종료·장치 리셋·재플래시하지 않는다. **무인 허용 범위는 저장 입력·시뮬·빌드·ROS shadow·안전한 센서 읽기**다. 모터/서보/PDB/배터리를 필요로 하는 단계는 외부 의존으로 넘기고 다른 작업을 진행한다.
- 핵심 기능의 대표 최소 기준을 만족한 뒤 성능을 더 개선할 여지가 있어도 다른 미완료 필수 기능으로 이동하고, 주행 손실이 큰 분야에 다시 돌아온다. 전수 희귀 형상·관제 미관·불필요한 재검사보다 실제 지연·긴 저속·제어 연결·추월 성능을 우선한다.

<a id="작업-순환과-중단-기준"></a>

## 작업을 이어가거나 넘어가는 기준

- 실제 경기의 완주를 막는 대표 실패면 필요한 수정을 계속한다. 정해진 시간이나 실험 횟수만으로 미완성을 완료 처리하지 않는다.
- 해당 기능이 대표 조건에서 성립했고 남은 문제가 미세 성능·드문 예외·확장 기능이면 다른 미완성 필수 기능을 우선한다. 전 분야가 그 수준에 도달하면 경기 손실이 큰 곳으로 돌아온다.
- 새 검사는 줄일 접촉·개입·주행 손실이 분명할 때 추가한다. 작은 분기 단위 통과만으로 전체 정체가 개선됐다고 보지 않는다. 변경 근거 없이 같은 실패를 반복하지 않는다.
- 실제 부품/장착이 없어 확인할 수 없는 항목은 외부 의존으로 남기고 독립적으로 가능한 입력/운영 연결을 진행한다. 질문과 필요한 동작은 [제작 전달 목록](HARDWARE_AND_RULE_QUESTIONS.md)에 모은다.
- GPT가 가능한 설계·구현·분석을 직접 수행하고 별도 구현/실행 워커는 사용하지 않는다. 어려운 문제에는 Fable 5.2/high 자문을 선택적으로 사용한다. 실제 PC/Jetson의 상시 실행 상태는 별도 프로세스/로그로 확인하며 문서상 작업 큐만으로 무인 실행을 주장하지 않는다.

<a id="통합-후-권장-속도-시험"></a>

## 주행·속도·연산 평가

계획 명령→독립 보호 출력→MCU 목표→모터축→차체 중 먼저 속도가 막힌 위치를 구분한다. 지도·차체/상대 정답은 평가 전용이며 `/drive → 독립 보호층 → /drive/safe`를 유지한다. 명시 STOP와 실제 앞길 점유·지속 입력 고장을 구별해 처리한다.

C1 10 Hz에서2 m/s는 한 회전20 cm,10 km/h는약28 cm를 이동한다. 점별 보정·관측 거리·계산 지연·제동을 함께 평가한다. 12 Hz만 올려 이를 해결했다고 하지 않는다. 계산비는 빠른 거절과 실제 진행 판단을 나누며 입력 수신·저장 CPU·전체 ROS·실차 결과를 구분한다. 오래된 소스 해시 검사를 통과시키려고 과거 파일을 덮어쓰지 않는다.

직접 필요한 장면은 단독 한 랩, 앞차 추종/급정지/재출발, 끼어들기, 정지차 우회/복귀, 좁은 코너 측방 지속, 최초 시각 출발/가림 해제, 같은 경기 STOP/START다. 기존 대표는 조건이 같으면 재사용한다. 단독 최고속도와1초 평균/유지 시간, 랩 시간, 긴 저속, 명령 급감속, 접촉, 노면, STOP/정상 종료를 따로 보고한다.

<a id="방지턱하드웨어"></a>

## 실물 의존·운영 범위

방지턱 인식/전용 감속/정밀 현가는 필수 목록에서 뺀다. 음수 모터축에서 전진 복구, 도로/잔디 접지·차동기 헛돎, 피치/롤 변화는 일반 주행 항목으로 남기되 실제 근거 없이 세부 모델을 확대하지 않는다.

[승인 전장](hardware/APPROVED_ELECTRICAL_LAYOUT.md)과 [실물 이관](hardware/PHYSICAL_HANDOVER_APPROVED_LAYOUT.md)을 따른다. 카메라 최종 높이·신호 세부 시야·센서 축/영점·실제 측정면 가림·구동 응답은 장착 후 확인한다. 지금 가능한 정지 실센서 연결/기록 검사는 기다리지 않는다.

[운영 요구](autonomy/RACE_MONITOR_AND_RECOVERY_PLAN_2026_11_02.md#1111-추가-요구-시험-속도-상한과-간단한-수동-조작)의 속도 상한과 개발용WASD 또는 짧은 전진/좌·우 버튼을 구현한다. **자율주행 모드에서는 수동 입력 비활성**, 경기 원격 조작은 STOP/START/RESET 범위다. RESET 없는 같은 경기 재개와 최초 신호 대기를 혼동하지 않는다. 일반 시험에 브라우저를 항상 띄울 필요는 없다.

<a id="일정과-종료-조건"></a>

## 남은 단계 — 시각별 계획 없이

**실물은 금요일 저녁 예상, 대회장 출발은 토요일 새벽 5시.** 자체 시험 트랙을 만들 수 없으므로 조립 후 전구간 주행·상대 추월·실제 신호등 시험을 계획하지 않는다. 그 항목은 공식 현장 연습·프리랩에서 처리한다. 공식 일정은 11/14 연습 11–12시, 프리랩 12:30–13시, 본선 13:30–14시이며 팀 단독 사용 시간을 보장하지 않는다.

| 단계 | 필수로 할 최소 행동 | 보류/제외 |
|---|---|---|
| **차량 나오기 전** | P0 큐: Jetson 실제 처리/명령 만료 개선, C1+IMU+B0390+ESP32 무구동 공통 실행, 운용 펌웨어 빌드, 최종 형상 단독/대표 교통 시뮬 | 엔코더를 위해 PDB/배터리 꺼내기, 이미 한 손 회전·개별 수신 재시험, 시각별 일정 |
| **조립 직후** | 배선 담당의 기존 도면 결선 완료 후 **STOP/명령 응답**, 서보 중립과 실제 바퀴 방향, IMU 정지 영점·축, C1 장착 자기 가림, 필요할 때 엔코더 실구동 방향/계수 확인 | 전기 연결 설명 재작성·기존 센서 단독 검증 전체 반복 |
| **작은 4방향 벽 공간** | 낮은 속도로 앞/뒤·좌/우 짧게 움직여 벽 위치/C1, yaw 부호/IMU, 전진 거리/엔코더, 좌우 서보 조향 부호가 상식적으로 일치하는지 보고 눈에 띄는 오차만 조정 | 트랙 모사·코너 고속·공식 랩 검증 |
| **바퀴를 띄운 상태** | 모터 구동 출력/속도 여유, 엔코더 변화, PWM0 정지, 조향 기계 간섭을 필요한 만큼 확인 | 사람이 없는 자동 모터/서보 구동, 지상 고속 시험 |
| **대회장 현장** | 실제 신호·출발, 코너/진입, 제한 교통, STOP/재개를 공식 코스에서 확인하고 안정적인 설정으로 동결 | 현장 시간을 장시간 개발/새 기능 제작 기회로 전제 |

조립 후 **4방향 벽의 짧은 실제 움직임**은 방향/축/기본 보정을 위한 것이지, 전체 코스나 추월의 성공 증명이 아니다. 확정 배선도와 기술 매뉴얼은 배선 담당·문제 발생 시 참고한다. 세부 검사표는 이미 성공한 진단을 다시 수행하라는 필수 작업표가 아니다. 수동 확인 없이 구동을 자동으로 시작하지 않는다.

종료 시에는 **하나의 주행 launch/설정·소스 해시·로그/백업·STOP/START/RESET**을 묶는다. 실물 확인 사실과 미검증 시뮬 기능을 명확히 구분하고, 시간표를 맞추기 위한 추가 검증보다 첫 실제 운용 가능성과 빠른 완주를 우선한다.
