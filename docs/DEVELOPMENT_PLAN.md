# 현행 개발 계획: 첫 완주와 실물 통합

갱신: **2026-10-27 (KST), 통합 재점검·속도 시험 후속 지시 반영**. 구현 근거는 `26ea47bfbf376490fd193fa56eb2a7fa6ae0c98e`, 사용자 결정은 [ADR 0027](decisions/0027-completion-first-policy-and-placement.md), 실제 완료 범위는 [현재 현황](PROJECT_CONTEXT.md)을 따른다. 아래 구현 순서·판정 설계는 개발 계획이지 이미 통과한 시험 결과가 아니다.

[10/23 계획](reports/DEVELOPMENT_PLAN_2026_10_23.md)과 [이번 정리 직전 계획](https://github.com/GIST-ISAAC-Robotics/2026-IT-ARENA/blob/26ea47bfbf376490fd193fa56eb2a7fa6ae0c98e/docs/DEVELOPMENT_PLAN.md)은 당시 이력으로 보존한다. 앞으로의 순서는 이 문서에서 교체하며 실행별 연혁을 다시 누적하지 않는다.

## 목표와 고정 범위

**확보한 저속 단독 1랩을 같은 실행 구성의 교통·공식 출발·방지턱·다랩·실물 운용으로 연결한다.** 조각 시험이나 회귀 개수를 경기 완주로 대신하지 않는다.

- 구매 센서·구동 방식과 기보유품 미사용 방침은 고정, 장착 위치·높이·방향은 변경 가능하다. Pure Pursuit는 현재 수단이며 관측·행동 결합 문제부터 해결한다.
- 두 바퀴 잔디를 활용하며 충돌 임박 시 세 바퀴 이상 이탈 페널티를 감수하는 방향이다. 무벌점 진행이 우선이고 벽·전복·복귀 불가 위험을 함께 본다. 긴급 회피의 구현·검증은 아직 남아 있다.
- **사용자 후속 목표:** 통합이 어느 정도 된 뒤 가능한 구간에서 실제 최고속도 **2 m/s 이상(7.2 km/h)**의 시험을 시도한다. 필수 최소속도·평균속도·전 구간 속도가 아니며, 어렵거나 완주/일정에 부담이 크면 낮은 속도를 채택하고 이 목표는 포기할 수 있다. 기존 약 15 km/h 목표를 2 m/s로 대체하거나 즉시 상한을 바꾼 결정은 아니다.
- 현재 `local_fast` 상한 2.5 m/s, G1 운영 상한 1 m/s, 측방/GUARD 후보 0.35 m/s 및 부분 관측의 더 낮은 상한은 **현재 구현값**이다. 새 속도 목표의 달성 근거로 쓰지 않는다.
- `/drive` → 독립 보호층 → `/drive/safe`, 명시 STOP·입력 만료 처리를 유지한다. 부분 관측으로 진행할 때의 잔여 위험을 기록하며 `unknown`을 측정된 자유 공간으로 바꾸지 않는다. 센서 기반 제어와 평가용 지도·정답·actor 상태는 분리한다.

## 현재 재개점 — 무반환 작업을 덮어쓰지 않는다

마지막 게시된 작업은 [GUARD 곡선/후반부 결측 run2](../artifacts/validation/2026-10-27/g1_guard_curve_v1/README.md)다. 13.018 m·앞차 정지/재개·첫 U자 코너·해당 40초 14관문을 통과했고 STOP·정상 종료·2,047판단 동일 재생을 확인했다. **기본 strict·후보 OFF, 방지턱 OFF·임시 3등·등록 저속 각본 1회**다. 최신 후보의 전체 교통 랩이나 실물 완료가 아니다.

### 통합 후보의 기준

출발점은 [run2 실행 구성](../artifacts/validation/2026-10-27/g1_guard_curve_v1/run2_trial.sh)의 **G1 + `bounded_local_v4` + `corner_distance_candidate` + `per_ray_candidate` + `corridor_fallback` + 평행/통과 선택기 + GUARD 곡선 후보**다. 이는 통합 비교의 출발점이지 경기 기본값 채택이 아니다. 변경 시 소스와 옵션을 함께 남긴다.

구형 M3 실행 후보·최근 관측 옵션과 새 G1 선택기를 이름만 보고 동시에 켜지 않는다. CLI/launch의 실제 허용 조합을 확인한다. 출발 B3·공식 4등·M5·방지턱은 각각 연결 상태를 표시하고, 단독 성공 설정과 교통 성공 설정을 섞어 한 구성의 완주라고 쓰지 않는다. 최소 한 번은 최신 후보를 켠 동일 구성으로 교통을 포함한 전체 1랩과 STOP을 확인한다.

새 센서·전면 제어 스택 교체·범용 도구 확장은 우선순위를 낮춘다. 적극 이동 추월(G3)은 첫 완주·추종·피추월 대응 이후이며 영구 금지는 아니다. G2/긴급 잔디 회피는 실제 우회·복귀가 성립하는 범위를 분리하고, 아직 구현되지 않은 기능을 완료 목록으로 옮기지 않는다.

## 2. 시험 순서와 판정

1. **기존 입력으로 결합 분기를 좁힌다.** 43 m 결측·앞차 정지/재개·측방 가림·M5 입력을 재사용한다. 같은 엄격 조건을 이름만 바꾸어 반복하지 않는다.
2. **변경 원인에 맞는 대표 폐루프를 수행한다.** 아래 장면은 시험 목록이지 모든 조합을 먼저 끝내야 통합 랩에 갈 수 있는 관문이 아니다. 원인/조건 변화 없는 실패 반복과 반례 없는 숫자 조정을 피한다.
3. **같은 후보의 교통 1랩으로 연결한다.** 추종·측방 전이·복귀 후 기본 출력·STOP·정상 종료를 이어서 본다. 공식 출발/M5 연결은 병행하며 임시 신호를 쓴 랩은 그 범위만 인정한다.
4. **방지턱·5랩·실물과 처리 시간을 확장한다.** 공개 50 mm 진행 길이·10 mm 높이 턱의 기구 간섭, 저속 동적 통과, 센서/경로 복구를 확인한다. 실물 벤치는 앞 단계 완료를 기다리지 않는다.
5. **통합 뒤 속도를 단계적으로 시험한다.** 아래 권장 목표를 적용하되 전체 미완료 항목을 끝내야 속도 시험을 시작할 수 있는 새 조건으로 만들지 않는다. 시험하는 구간/기능의 관측·제동·처리 조건을 먼저 확인한다.

### 평가와 증거 범위

- **주 판정:** 완주/진행 시간, 접촉 횟수·상대·결과, 정체와 개입, 바퀴별 노면/세 바퀴 이상 이탈, 복귀, 실제 STOP·정상 종료. 접촉이 있어도 완주 성과는 기록하되 무접촉 통과로 쓰지 않는다.
- **진단/과거 비교:** 기존 차체 도로 이탈 면적·150/97 mm·최초 앞차 1.2 m 실패는 그대로 보존한다. 새 운용 기준은 실행 전에 이유와 함께 정하며, 과거 실패선을 사후 변경하지 않는다. 차체–장애물 충돌과 바퀴–노면 비용은 분리한다. 바퀴 중심 감사만으로 타이어 접지/공식 벌점을 확정하지 않는다.
- **앞차 변경:** 추월 차량이 자차 경로 앞을 막으면 가까운 방해 차량에 대한 추종과 전역 진행을 별도 평가한다. actor 정답 분류는 평가기에만 사용한다. [기존 실패의 원인 분리](../artifacts/validation/2026-10-27/g1_pass_release_operation_v1/README.md).
- **증거 수준:** 단위/광선 합성·저장 입력은 판단 차이, 센서 기반 폐루프는 실제 해당 구성의 주행, 실물은 장착·시간·구동의 확인이다. 각본 actor를 독립 자율 차량으로, 저장 입력 재계산을 새 주행으로 쓰지 않는다.
- **재현성/회귀:** 입력·소스·설정·미실행 분기와 실패를 보존한다. 최신 후보 전체 회귀 보충과 skip 사유 확인을 통합 검증에 묶고 변경 없는 전체 검사를 매 단계 반복하지 않는다. 처리 시간은 전체 파이프라인·입출력 나이·주기 누락을 기록하며 함수 한 개의 비용을 Jetson 실시간 검증으로 쓰지 않는다.

### 통합 후 권장 속도 시험

사용자 목표는 **가능하면 실제 최고속도 2 m/s 이상을 확인**하는 것이며 달성 강제 조건은 아니다. 저속 통합 후보를 비교 기준으로 보존한 뒤 시야와 제동 공간이 있는 직선부터 단계적으로 올린다. 단계 예시 1.0→1.5→2.0 m/s는 개발 제안이며 고정된 사용자 수치 목록이 아니다. 코너·가림·밀집 주행·방지턱은 상황별로 감속한다.

상한/명령만 2 m/s로 바꾸거나 순간 센서 이상값을 성과로 세지 않는다. 실제 도달 속도·유지 시간/거리·평균 속도·랩 시간, 접촉/추종/조향, 제동거리·STOP, 입력 나이·전체 처리 지연을 함께 기록한다. 시뮬레이션 차체 속도 정답은 평가 전용이며, 실물 모터축 속도와 슬립이 있는 차체 이동은 구분한다.

현재 부분 관측+G1은 1 m/s 이하를 요구하고 평행/GUARD 후보는 0.35 m/s 시험 조건을 쓴다. `max_speed` 하나만 올리거나 검사를 삭제하지 말고 관측 범위·점유 시차·제동·조향·재개 조건을 실제 사용하는 속도별로 재검토한다. 낮은 관측 신뢰도에서의 제한 속도까지 2 m/s로 일괄 상향하지 않는다.

불안정·접촉 증가·처리 지연·제동 부족 또는 일정 부담이 크면 원인을 기록하고 마지막으로 확인한 낮은 속도로 돌아간다. 2 m/s나 기존 15 km/h에 맞추려고 새 하드웨어/구동 방식 변경, STOP 약화, 끝없는 재시험을 하지 않는다. 미달을 전체 완주 준비 실패로 취급하지 않는다.

## 3. 하드웨어 설계와 병행할 일

[하드웨어 전달 목록](HARDWARE_AND_RULE_QUESTIONS.md)은 유지한다. 상대팀 전 차량 도면이나 완전 360° 증명을 선행 요구로 추가하지 않는다.

- C1 높이에 걸리는 기판·배터리·기둥·케이블, 전방·측방·뒤 양 모서리 시선을 확인한다. 후방 마커 상향을 포함해 배치 변경 뒤 센서 좌표/축·운동 보정 위치·모델/가림 마스크를 함께 갱신한다.
- 고정 카메라는 [뒤쪽 높이 .20/.30 m 비교](../artifacts/validation/2026-10-27/camera_mount_preparation_v1/README.md)를 설계 입력으로 쓴다. 공식 빨강이 세로 연결 성분으로 보이는 검출 실패와, 순차 증가 시제품이 초록 단독/누락을 거절하는 한계를 분리한다. .30 m나 특정 피치를 확정하지 않는다. 실제 CSI 화각/크롭·시설 사진·자차 가림·기울기를 확인한다.
- C1 원시 시각/누락, B0183 RGB/PTS, IMU 축/단위/시계, 모터축 카운트·MCU UART 콘솔·실제 출력·전기 STOP을 장비 연결 즉시 벤치에서 확인한다. 시뮬레이션/차체 완성을 기다리지 않는다.
- 제작팀과 **담당자·부품 수령 상태·첫 센서/MCU 연결일·차체 조립 예상일·STOP 시연일**을 확인해 전달 목록에 실제 값으로 기록한다. 아직 확인되지 않은 날짜나 전달 완료를 만들어 쓰지 않는다.
- 현재 선택 코드의 Jetson 전체 처리 지연과 입력 나이를 측정한다. 과거 M3 비용을 새 선택기 성능으로 재사용하지 않는다. 지상고·서보 전원·모터/기어 호환·조향·제동·방지턱 확인을 누락시키지 않는다.

실물은 정지/배선 → 기구·센서·시간 → 저속 단독 → 추종/가림 → 출발/재개/방지턱/다랩 순으로 확인한다. 실제 연결 전 구동 출력 비활성 벤치와 정지 경로를 확인하고, 모터축 0을 차체 정지의 증명으로 쓰지 않는다.
