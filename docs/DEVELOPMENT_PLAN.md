**실물과 PC의 병행 조건:** PC는 별도 시뮬 사본에서 한 실행과 결과 분석을 이어갈 수 있다. Jetson에는 실센서·제어·기록의 의도한 통합 부하만 두고 저장 입력 benchmark/빌드/profiler를 겹치지 않는다. 실물의 소스·설정·generated YAML과 바이너리는 실행 동안 고정하고, PC 수정은 자동 동기화하지 않으며 정지·회수 뒤 필요한 변경만 검토해 적용한다. 별도 domain이 CPU/GPU/포트 격리까지 제공하는 것은 아니다.

## 지금의 우선순위와 순환 방식

**11/14 실행 순서:** r475 기본 단독·r492 출발 변형·r496 앞차 대표 이후 PC의 다음은 준비된 r499 옆차 통과/복귀1회다. 조립 전 Jetson 후속은 보존 r498 후보 확인과 필요한 ARM 비교이며 실제 설치 준비를 먼저 마친다. 조립 완료 후 주 담당과 Jetson은 실물 확인으로 전환하고 PC 시뮬은 비간섭 범위에서 이어간다. r466 마커 v2와 r470 native는 공통 통합됐으므로 다시 구현하지 않는다. 약60~61cm 사각 벽과 고정 마커는 장착·근사 보정용이며 자동 코스 주행 검증을 대신하지 않는다.

**최신 차량의 완주와 정지 최소화 원칙:** 주변 차량이 없는 코스에서 멈추는 문제를 우선 해소해 r475/r492 대표를 확보했다. 새 회귀가 드러나면 원인에 맞춰 다시 확인하며, 미세 최적화·희귀 예외를 주 작업으로 확대하지 않는다. 아래 P0 번호는 기존 항목 식별자이며 실행 순위가 아니다. 현재 순서는 상단 전환 계획을 따른다. 교통 actor가 포함된 대표의 실패를 단독 실패라고 부르거나 이전 차량의 완주를 최신 차량에 소급하지 않는다.

현재 정체는 실제 입력으로 원인을 확정해 수정하고 대표 주행으로 확인한다. 같은 정체가 이어지면 속도만 더 낮춘 예외를 누적하지 않고, 중복 보호·과거 측방 상태·불확실성 때문에 현재의 관측된 경로까지 막는 조건을 단순화하거나 재설계한다. 사용자는 접촉 위험을 완전히 없애기 위한 장기 정지보다 완주를 우선한다고 재확인했다. 기존 수치와 보호 조건은 재검토 가능한 설계값이며 영구 금지선이 아니다. 다만 명확한 전방 충돌·관측된 점유·운영 STOP과 명령 전달 경계는 유지하고, 미관측을 자유 공간이나 차량 부재로 바꾸어 결과를 통과시키지 않는다. 변경의 위험과 남은 한계를 기록한다.

검증은 완전 단독 전체 랩과 출발 변형, 앞차 대표의 확보 범위를 구분해 다음 옆차 대표로 이어간다. 벽 형상 변화는 미실행 범위로 남기며 현장 필수 이관을 미루는 선행 조건으로 추가하지 않는다. 완료 기준은 진행거리만이 아니라 전체 코스 통과, 긴 정체/급감속, 접촉, 경로 회복을 함께 본다. 같은 위치를 성공할 때까지 재실행하지 않으며 한 조건의 통과를 모든 실차 조건의 보장으로 확대하지 않는다. 실제 형상 변화는 시뮬 환경에만 적용하고 제어기에 지도나 정답 위치를 넣지 않는다.

**11/13 병렬 역할 원칙(당시 재개 지시):** 실제 작업 순서와 조립 완료 후 전환은 상단11시 이후 계획을 따른다. 독립적인 패널/운영 도구·저장 영상/로그 분석 등은 Astra xhigh에게 병렬 배정할 수 있다. ### 가벼운 접촉 이후 복구 — 11/13 후속 요구, 낮은 우선순위

최소 주행 기능을 확보한 뒤 작은 측방 밀림·순간적인 차체 방향 변화·짧은 IMU 이상값을 대표 2~3장면으로 확인한다. 관측된 진행 경로가 남아 있으면 새 센서 입력으로 경로를 다시 잡고 주행을 이어가는지, 충격 이후 오래 정지하거나 방향을 잃는지를 기존 명령/센서/사건 로그로 평가한다. 이는 제한된 외란 시험이며 실제 충돌 강도·차체 내구성의 재현이나 모든 접촉 후 복구 보장은 아니다.

**새 충돌 추정기와 충돌 추정만으로 작동하는 자동 STOP은 현재 추가하지 않는다.** 사용자는 오검출에 따른 정지와 연산 부담을 우려했으며 낮은 우선순위를 지정했다. 실제 전방 장애물·진로 폐쇄에 대한 기존 감속/정지는 유지하고, 충격 신호 하나만으로 영구 정지 상태를 만들지 않는다. 이 시험 때문에 최소 완주·실장 조향 연결·Jetson 실행 문제를 미루지 않는다.

11/13 공식 원문 재확인에서는 **원격 비상정지 의무·검차 시연**, **10초 이상 정지 후 사람 개입**, **원격은 시스템 리셋(정지·시작)까지**가 각각 명시되어 있다. 사용자가 언급한 조건을 ‘10초 전에는 비상 STOP 명령도 금지’라는 구현 조건으로 옮기지 않으며 기존 STOP/START/RESET을 유지한다. 이 확인은 해당 조항 대조이고 심판의 모든 현장 판정을 예측한 것은 아니다. ### 11/13 재개 후 기본 패널 요구

속도 상한은 별도 개발 모드를 켜지 않아도 기본 운영 패널에서 조정하며 m/s·km/h 입력을 서로 변환해 표시한다. 서버 적용값과 편집 중 값을 구분하고 차량/운영 최대를 넘기지 않는다. 수동 모드는 WASD 대신 목표 속도·실행 시간·단순 예상 이동거리(v×t)·중앙 등가 바퀴 조향각을 조정하는 제한 실행으로 연결한다. 자율 발행과 수동 발행을 동시에 허용하지 않고 기존 독립 보호·STOP·종료 경로를 유지한다. 실제 펄스 시작/준비는 명시 조작이며 패널 기동만으로 ARM/출력하지 않는다. 브라우저/수동 입력 처리가 자율주행의 필수 의존이 되지 않게 한다. r429에서 공통 연결과 실제 HTTP→ROS→독립 guard→가짜 MCU 단발/STOP 대표를 마쳤다. 실물 각도·속도·정지는 별도다. 추가 요청인 라이다/카메라 보기(r434)는 기본 OFF·보기 중에만 ROS 구독·최신1개만 보존·낮은 전송률로 구현한다. 라이다 점 표시는 물체 분류와 구별하고, 카메라는 기존 ROS 영상의 축소 JPEG를 사용해 장치를 다시 열지 않는다. 이 보조 기능 때문에 주행 실행의 지연을 늘리지 않는다.

### 검증을 남길 기준 — 11/13 실행 세션 재검토

사용자는 중복 검증을 줄이는 과정에서 필요한 검증까지 빠질 우려를 다시 전달했다. **시험 수를 최소화하는 것이 아니라 실제 변경과 실패 가능성에 맞춰 검증 범위를 정한다.** 사람의 조작이 필요한 실장/배터리/차량 이동 작업은 뒤로 두며, 다음은 무인으로 수행한다.

- **계산 구현 변경:** 영향받는 함수의 경계·오류 입력 회귀와 저장된 정상/실패 입력의 전후 판단을 대조한다. 속도만 빨라지고 출력이 달라지면 최적화 성공으로 처리하지 않는다.
- **주행 판단 변경:** 해당 원 실패 입력과 대표 반례를 확인하고, 실제 연결된 후보가 적용되는 제한 시뮬 주행을 수행한다. 저장 재생 개선이나 적용0회 주행만으로 기능 완료를 선언하지 않는다. 원 실패는 보존한다.
- **센서/ROS/MCU 통합 변경:** 현재 구성의 수신 수·시각/명령 나이·상태 전이·STOP·정상 종료를 함께 확인한다. 기존 센서별 장시간 기초 검사를 되풀이하지 않으며, 새 연결 때문에 생긴 누락/적체는 확인한다.
- **실물 관측 경계:** 현재 엔코더 입력이 없거나 취득시각이 미검증이면 그 상태를 그대로 기록한다. 가짜0속도나 정답 자세로 전체 실물 경로 판단을 통과시키지 않는다. 필요하면 실센서 관측 노드와 저장 입력 계산 부하를 별도 채널로 결합해 수신 간섭을 시험하고 두 입력을 구분한다.
- **넘어가는 판단:** 대표 기능이 성립하거나 다음 실패 원인이 다른 계층/실물 의존으로 분리되면 다른 미완성 필수 항목으로 이동한다. 실패를 지우거나 검증 자체를 생략하기 위한 순환은 하지 않는다. 검증된 사실이 바뀌지 않는데 같은 시험을 재실행하는 것도 피한다.

현재 상태 메모: r441/r452/r457과 뒤이은 r477/r485/r490 실패는 당시 소스·원 결과로 보존한다. 현재 단독 대표는 r475/r492, 앞차 대표는 r496이며 다음 시뮬은 준비된 r499다. 실물 영점·설치·출력과 최신 전체 ROS 처리율은 여전히 미확인이다. [현재 현황](PROJECT_CONTEXT.md)과 [상세 통합](reports/RUNTIME_SENSOR_INTEGRATION_2026_11_12.md#11-13-panel-steering-integration)을 참고하고 과거 진행 중 메모를 현재 실행 상태로 사용하지 않는다.

### 중단 중 누락 대조와 재개 후 반영

[요구사항 대조 결과](reports/RUNTIME_SENSOR_INTEGRATION_2026_11_12.md#11-13-paused-gap-audit)는 Astra xhigh 두 담당과 주 에이전트의 당시 읽기 전용 검토다. 아래는 그때 발견한 문제와 후속 반영 범위이며 새 실행 순서는 상단11시 이후 계획을 따른다.

- **조립 전 병렬 P0:** 장착 조향 한계를 CAD 전체보다 줄일 때 Python 영점 export가 전체 CAD 범위를 요구하지만 MCU는 선택 `command_limit`만 검사하는 불일치를 수정한다. r430에서 같은 선택 범위·기하를 export/MCU에 전달했고 축소 한계 검사·양방향14표본의 Python/C++ 결과를 확인했다. 공통 반영 완료이며 실제 실장값은 조립 뒤 채택한다. CAD 표·영점 도구 자체는 이미 구현됐으며 재작성하지 않는다.
- **주행 P0 유지:** r428은 중단 전 후보2회와 부모 발행2회를 확인했지만 코너 통과는 미확인이다. 후속 r431은9.81m에서 출력 측 각도 불일치로 명령 갱신이 끊겼다. r437에서 명령 만료는 해결됐지만 코너 정체가 남아, r438에서 현재 이동 영역과 자체 가림을 저속 목표별로 비교한다. 이전 current 후보 개선을 성공으로 합산하지 않는다. r426의 음수 측정속도1건은 기존 양수를 새로0으로 만든 회귀는 아니지만 원0에서 회복하지 못했다. 음수 표본의 실제 주행 영향과 기하를 확인하며 부호를0으로 바꾸지 않는다.
- **실물 실행 선택 명시:** r426은 `simulation_acquisition`/검증 시각 전용이고 실제 입력은 `host_estimated_v1`이다. 시뮬 개선을 실물에 적용 완료로 합산하지 않는다. 최종 실행 묶음에서 실물에 채택할 정책과 미채택 후보를 명시하고, 시간 검증 표식을 가짜로 바꿔 연결하지 않는다.
- **운영 보조 병렬:** 기존 패널·속도상한·짧은 jog·사고 로그를 재개발하지 않는다. 최종 설정/소스 식별·기존 사건 CSV/HTML 내보내기 경로를 실제 선택 실행 묶음과 연결한다. MCU 루프 자체 정지의 watchdog 범위는 명령 만료와 구분해 설치 빌드 설정/감시 대상부터 읽고, 실제 출력 확인은 조립 뒤 최소 STOP 확인에 남긴다. 새 회로나 희귀 고장 시험을 늘리는 항목이 아니다.

### 차량 도착 후 최소 실물 확인

[사각 벽 공간 확인·보정 순서](hardware/ASSEMBLED_CAR_BOX_CHECK_2026_11_14.md)를 사용한다. 약60~61cm 네 벽·높이30cm 이상·벽마다 다른 팀 마커(중심 약20cm, 흰 여백 포함5cm)이며 직각도는 미확인이다. 조립 완료 뒤 Jetson은 실물에 전담하고 PC는 별도 사본의 비간섭 시뮬을 유지한다. **실장 설정·펌웨어→바퀴 공중 낮은 출력/부호/물리·패널 STOP→서보 중립/간섭→실제 높이 C1·IMU→지상0.05m/s·0.2~0.5초 단발(상한0.1m/s)**을 우선한다. IMU 정지 기록은 다른 준비와 병행하고 마커 근사 배율은 저속 이동의 선행 조건으로 두지 않는다.

자기 가림은 상자 안 원자료에서 실제 지주·배선과 벽을 구분하고 모호한 구간만 몇 cm 재배치해 확인한다. `review_c1_self_returns.py`에 상자 배경 분리 기능이 있다고 가정하거나 가까운 벽이 있는데 `--nearby-clear-confirmed`를 주지 않는다. 검토한 거리 제한 마스크와 IMU 편향은 planner·guard 양쪽에 같은 값으로 적용·재확인한다. 일반 이동은 차량 마커 점유 보조OFF로 수행한다.

기존 센서별 수신·손 회전·무부하 서보 시험과 전면 배선 검사는 반복하지 않는다. 실제 이동의 엔코더 부호·대략적인 환산과 장착으로 달라진 영점·출력·STOP을 확인한다. 배선은 담당자가 승인 도면대로 완료하는 전제이며 이상 징후가 있을 때 해당 부분을 확인한다. 공중 고속 단계는 필수 저속 이관 뒤 여유가 있고 실제 상한/차단 확인이 된 경우에만 검토한다. 설치·통합 출력 과정 때문에30분 완료를 확정하지 않는다.

### 대회장 연습 시간

공식 안내는 [11/14 연습11:00–12:00·프리랩12:30–13:00·본선13:30–14:00](https://github.com/MOSW626/istech-it-arena/blob/6c2589c61acb83928339291ae237180b17c2cb54/MANUAL.md)다. 필수 실물 확인이 성립하고 연습 시간이 남으면 실제 신호 출발·본선 유지·코너·STOP/재출발을 확인하는 기회부터 사용한다. 마커 정밀화나 추가 시뮬 완료를 기다리느라 트랙 시간을 소진하지 않는다. 중간 공백을 자유 주행 시간으로 가정하지 않으며 추가 접근은 운영진 허용 여부를 확인한다. 문제가 생기면 원인에 맞는 속도 상한/안정 설정으로 복귀하고 현장에서 새 기능 대량 추가는 하지 않는다.

### 랩타임·추월 성능 작업의 범위

**11/13 영상 후속 조건:** 실제 신호등 촬영/HSV 맞춤은 사용자 일정·재료상 어렵고 intrinsic 보정은 추후 담당자에게 맡긴다. r339 저장 변형에서 밝기0.60배 미검출·밝은 소등 초록의 늦은 출발 오검출을 확인했으므로 단순 색 임계값 완화 대신 점등 전/전이 근거를 검토한다. 사용자 승인으로 낮은 상대용 마커 보조를 기본OFF 옵션으로 준비하며 r340은 관측/기록까지만 연결했다. 감속 연결 전에 직선 앞차·옆차·커브·중복 크기·소실의 제한 반례를 확인한다. r341의4mm 판/8mm 분리 지주처럼 희소 상부는 기존 오목형과 구별해 대표 교통 시험에 넣되, 없는 반환을 자유 공간으로 채우거나 실제 차체 외곽을 줄이지 않는다. 정밀 거리/추종과 전수 형상 검증으로 확대하지 않는다. [조건·구현 구분](sensors/B0390_SIM_2026_11_07.md#1113-실물-신호-시험-불가와-차량-마커-보조-검토).

목표인 빠른 완주와 기존 추월 과제는 유지한다. 추가 랩타임/고속 추월의 P2 분류는 이번 일정 수정 전에도 있었으며, 이번 변경으로 성능 개발을 종료한 것은 아니다.

- **현재 주행 손실은 계속 줄인다.** 계산 지연·명령 만료 때문에 생기는 정지/저속, 불필요한 추종 감속, 기존 속도·우회·추월의 퇴행은 원인에 따라 P0 실행 지연 또는 P1 주행 과제로 처리한다. 최고속도만 보지 않고 긴 저속·속도 유지·랩 시간을 함께 평가한다.
- **기본 교통 동작을 완성한다.** 앞차 추종, 정지차 우회/복귀, 피추월·코너 측방 대응과 기존 직선 추월의 연결을 유지한다. 저속 직선 대표의 성공으로 중속/변속·빠른 상대 추월까지 완료 처리하지 않으며, 미완료 범위는 아래 기존 과제 목록을 따른다.
- **추가 성능 개선으로 돌아가는 조건을 둔다.** 선택한 실행 구성으로 입력→판단→보호→MCU 명령 경로와 단독/대표 교통 주행이 성립하면, 남은 모든 예외가 없어질 때까지 기다리지 않고 랩타임·고속 유지·직선 추월의 시간 이득을 비교한다. 실물 통합 일정을 침범하지 않는 독립 시뮬 묶음은 앞서 진행할 수 있다. 채택은 실제 계산 지연과 갱신된 형상을 반영한 결과로 판단한다.
- **최종 설계와 결합된 튜닝은 설계 반영 뒤에 집중한다.** 축거·조향·센서 가림 변화의 영향을 받는 코너 속도/궤적과 추월 간격은 새 모델에서 확인한다. 설계가 없어도 고칠 수 있는 실행 병목·확인된 주행 오류는 먼저 처리한다.
- **경기 이득으로 작업을 고른다.** 추가 최고속도, 코너 감속/재가속, 빠른 상대 직선 추월, P21 중 실제로 시간을 줄이는 항목을 우선한다. 공격적인 코너 추월·세 대 동시 추월은 기존대로 확대하지 않는다. 관제 화면 미관과 드문 형상의 전수 검사는 성능 개선보다 뒤다.

### 24시간 가동 환경의 사용

- **가용성 우선:** 장비 사용 가능한 이후의 계산 운영 원칙이다. 11/14 11시 전 양 장비 사용 불가와 조립 완료 시 Jetson 실물 전환을 우선한다. 사람의 취침·휴식·식사 시간을 별도 작업 큐로 만들지 않고 가용한 시뮬·저장 입력·비구동 연결·빌드를 필요한 순서로 진행한다. 계획 수립만으로 백그라운드 작업이 시작되지 않으며 실제 프로세스·로그로 기동을 확인한다.
- 노트북은 시뮬·분석과 필요한 설치 빌드, Jetson은 조립 전 저장 입력 비교/조립 후 실센서·제어·실험 기록을 맡는다. 한 장치의 계측에 무관한 경쟁 부하를 겹치지 않는다.
- 이미 완료한 개별 센서 수신·엔코더 손 회전은 반복하지 않는다. 실제 동시 입력→판단→보호→MCU의 공백을 장착 후 확인한다.
- 시뮬레이션은 완료한 단독·앞차 대표를 재사용하고 r499 이후 결과로 드러난 경기 손실을 개선한다. 전 분야의 기계적인 재실행 순환은 하지 않는다.
- 장시간 가동은 무인 계산/비구동 수신의 기회이며 무인 실차 반복 구동의 허용이 아니다. 실행마다 로그·종료 상태·재개점을 남긴다.

| M5 출발/재개 | 실제 신호 시야·앞차 가림 뒤 출발·선정 구성의 밀집 시작, STOP→START와 재배치 구분 |
| 이동차 추월 | 저속 직선 대표는 완료, 중속/변속 보완과 빠른 상대 추월은 미완료. 불리하면 급정거 없이 추종. 코너 공격적 추월/세 대 동시 추월은 확대하지 않음 |
| 센서/연산 | 실제 단위·취득시각 추정·새 boot, 입력 적체/계산 지연/현재 재검사, 장착 후 축/가림/영점 |
| 운영/하드웨어 | 실제 MCU 어댑터·엔코더·서보·모터/제동, 속도 상한·개발 조작, 공용망·로그/백업·검차 STOP |

최종 간격의 과거 실패와 진행/접촉의 기능 판정을 구분한다. 종전150 mm·97 mm 같은 시험값을 실물 절대 간격으로 고정하지 않는다. 사용자 허용인 두 바퀴 잔디를 활용하되, 미관측 공간을 자유 공간으로 채우거나 상대가 반드시 양보한다고 가정하지 않는다.

<a id="작업-순환과-중단-기준"></a>

## 작업을 이어가거나 넘어가는 기준

- 실제 경기의 완주를 막는 대표 실패면 필요한 수정을 계속한다. 정해진 시간이나 실험 횟수만으로 미완성을 완료 처리하지 않는다.
- 해당 기능이 대표 조건에서 성립했고 남은 문제가 미세 성능·드문 예외·확장 기능이면 다른 미완성 필수 기능을 우선한다. 전 분야가 그 수준에 도달하면 경기 손실이 큰 곳으로 돌아온다.
- 새 검사는 줄일 접촉·개입·주행 손실이 분명할 때 추가한다. 작은 분기 단위 통과만으로 전체 정체가 개선됐다고 보지 않는다. 변경 근거 없이 같은 실패를 반복하지 않는다.
- 실제 부품/장착이 없어 확인할 수 없는 항목은 외부 의존으로 남기고 독립적으로 가능한 입력/운영 연결을 진행한다. 질문과 필요한 동작은 [제작 전달 목록](HARDWARE_AND_RULE_QUESTIONS.md)에 모은다.
- **11/13 사용자 재확인:** GPT 주 에이전트가 전체 설계·우선순위·통합·최종 검토를 맡고, 독립적인 분석·구현은 Astra xhigh 서브에이전트에 병렬 배정할 수 있다. Terra6.1 low는 정해진 실행·대기·회수의 비용 절감용이며 분석 병렬화를 대신하지 않는다. 에이전트 수와 작업 분할은 주 에이전트가 자율 조정한다. Jetson/WSL 실행 자원은 각 한 담당자가 소유하고 동결 시험 중 공통 소스를 바꾸지 않는다. 어려운 문제에는 Claude Fable5.2/high 어드바이저를 재량껏 활용하며, 사용자 중단 요청까지 필요한 다음 묶음으로 이어간다. 이전 워커 금지 지시는 현재 지시로 재적용하지 않는다.

<a id="통합-후-권장-속도-시험"></a>

## 주행·속도·연산 평가

계획 명령→독립 보호 출력→MCU 목표→모터축→차체 중 먼저 속도가 막힌 위치를 구분한다. 지도·차체/상대 정답은 평가 전용이며 `/drive → 독립 보호층 → /drive/safe`를 유지한다. 명시 STOP와 실제 앞길 점유·지속 입력 고장을 구별해 처리한다.

C1 10 Hz에서2 m/s는 한 회전20 cm,10 km/h는약28 cm를 이동한다. 점별 보정·관측 거리·계산 지연·제동을 함께 평가한다. 12 Hz만 올려 이를 해결했다고 하지 않는다. 계산비는 빠른 거절과 실제 진행 판단을 나누며 입력 수신·저장 CPU·전체 ROS·실차 결과를 구분한다. 오래된 소스 해시 검사를 통과시키려고 과거 파일을 덮어쓰지 않는다.

직접 필요한 장면은 단독 한 랩, 앞차 추종/급정지/재출발, 끼어들기, 정지차 우회/복귀, 좁은 코너 측방 지속, 최초 시각 출발/가림 해제, 같은 경기 STOP/START다. 기존 대표는 조건이 같으면 재사용한다. 단독 최고속도와1초 평균/유지 시간, 랩 시간, 긴 저속, 명령 급감속, 접촉, 노면, STOP/정상 종료를 따로 보고한다.

<a id="방지턱하드웨어"></a>

## 실물 의존·운영 범위

방지턱 인식/전용 감속/정밀 현가는 필수 목록에서 뺀다. 음수 모터축에서 전진 복구, 도로/잔디 접지·차동기 헛돎, 피치/롤 변화는 일반 주행 항목으로 남기되 실제 근거 없이 세부 모델을 확대하지 않는다.

[승인 전장](hardware/APPROVED_ELECTRICAL_LAYOUT.md)과 [실물 이관](hardware/PHYSICAL_HANDOVER_APPROVED_LAYOUT.md)을 따른다. 카메라 최종 높이·신호 세부 시야·센서 축/영점·실제 측정면 가림·구동 응답은 장착 후 확인한다. 실제 장비 사용 가능·재연결을 확인한 뒤 필요한 정지 실센서 연결/기록을 진행한다.

[운영 요구](autonomy/RACE_MONITOR_AND_RECOVERY_PLAN_2026_11_02.md#1111-추가-요구-시험-속도-상한과-간단한-수동-조작)의 개발 속도 상한과 짧은 전진/좌·우 CLI는 기존 선택 기능으로 구현됐다. 새 runtime의 B3 운영 요청 연결은 [r407](../artifacts/validation/2026-11-13/runtime_ops_r407_v1/RESULT.md)의 실제ROS/가짜MCU PTY에서 확인했고, 기존 수동 조작 도구의 최신 MCU 상태 계약 호환성은 [r408](../artifacts/validation/2026-11-13/development_jog_r408_v1/RESULT.md)의 공통50순수검사까지 완료했다. 양수 주행·실물 출력 확인은 별도로 남긴다. WASD는 미구현이며 같은 기능의 새 도구를 중복 작성하지 않는다. **자율주행 모드에서는 수동 입력 비활성**, 경기 원격 조작은 STOP/START/RESET 범위다. RESET 없는 같은 경기 재개와 최초 신호 대기를 혼동하지 않는다. 일반 시험에 브라우저를 항상 띄울 필요는 없다.

## 차량 조립 전후 전환과 최종 인계

현재 가용 시각과 역할은 [11시 이후 전환 계획](#field-work-20261114)이 기준이다. 조립 전 개선과 조립 후 실물 우선 전환은 아래처럼 나누며, 미검증 후보를 설치 기준본에 자동 반영하지 않는다.

| 전환 조건 | 우선 작업 | 유지할 경계 |
|---|---|---|
| **11:00 이전 장비 불가** | 원격 저장소의 계획·자료 정리 | 노트북/Jetson 실행을 시작하거나 실행 중이라고 가정하지 않음 |
| **11:00 이후·조립 전** | 설치·실행 버전 준비, PC r499 1회, Jetson 보존 r498 후보 확보 후 필요한 ARM 비교 | 센서 가용성 별도 확인, 완료한 기초 시험 반복 없음 |

차량 조립 완료 시각과 설치·시험 소요는 미정이며 30분 완료를 보장하지 않는다. 공식 연습/프리랩은 위 [대회장 연습 시간](#대회장-연습-시간)을 따르고 별도 자유 주행 시간을 가정하지 않는다.

실물 최종 판단은 눈에 띄는 방향/영점/출력/정지 이상을 우선 해소하는 수준으로 제한한다. 조립 작업의 배선 안전은 [승인 전장](hardware/APPROVED_ELECTRICAL_LAYOUT.md)과 [실물 이관 문서](hardware/PHYSICAL_HANDOVER_APPROVED_LAYOUT.md)를 담당자가 따른다. 이미 완료한 개별 시험을 새 필수 통과 관문으로 되돌리지 않는다.

마지막에는 **주행 launch·선택 옵션·소스 해시·로그/백업·STOP/START/RESET**을 하나의 실행 묶음으로 고정한다. 새 센서·P22·공격적 코너 추월·전수 예외·관제 화면 미관을 확대하지 않되, 실차 통합을 침범하지 않는 범위에서 랩타임·속도 유지·추월 개선은 계속한다.
