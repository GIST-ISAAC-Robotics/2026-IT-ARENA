# 현행 개발 계획: 빠른 완주와 실제 실행 연결

갱신: **2026-11-13 실물 도착 전 무인 작업·최소 실차 확인 순서 반영**. [전체 재점검](reports/READINESS_REVIEW_2026_11_12.md)의 근거와 우선순위를 적용한다. 과거 시점별 계획과 ‘다음 작업’은 [바이트 보관본](archive/2026-11-12-midproject/DEVELOPMENT_PLAN.before.md)에 보존했다. 실제 결과는 [현재 현황](PROJECT_CONTEXT.md), 상세 실패와 변경은 [실행 보고서](reports/DECISION_EXECUTION_2026_11_11.md)가 기준이다.

목표는 **직접 충돌 위험이 없고 진행 경로가 보이면 급정거·큰 감속을 줄이며 빠르게 완주하는 것**이다. 단독 최고속도 약10 km/h의 제한 대표는 이미 확보했다. 현재 우선은 차량 도착 전 Jetson 처리 지연과 현재 연결 센서의 비구동 통합을 끝내고, 시뮬레이션의 단독·교통·추월 성능을 순환 개선하는 것이다. 실물 차량은 오늘 저녁 이후 제한된 시간에 4방향 벽 확인, 바퀴를 띄운 모터 출력, 장착 서보 확인과 짧은 저속 확인만 수행한다. 이 목표를 안전 조건의 무조건 누적이나 불확실성의 무조건 무시로 바꾸지 않는다. [ADR 0028](decisions/0028-speed-continuity-and-final-gearing.md)을 따른다.

[r291](../artifacts/validation/2026-11-12/signal_post_revision_r291_v1/README.md)에서11/12 제작측 첨부 STL을 확보했으며 앞뒤 대각 버팀대가 추가된 것을 확인했다. 선택형 시설 이관 뒤 r292첫12m는 통과했지만 r294한 랩은19.87m 경계 미확정으로 실패했다. 저장 입력에서 원인을 분리하며 마커 지주의 동일 사양까지 공식 확정된 것으로 쓰지 않는다. 차량 자체 기둥과 트랙 시설 지주를 구분한다.

### 차량 도착 전 실행 순서

1. **Jetson 병목 개선을 먼저 진행한다.** 최신 코드에서 계획 계산과 부모 재검사의 실제 지연을 줄이고, 같은 입력으로 출력이 보존되는지 확인한다. 계산 최적화만을 위한 새로운 복잡한 수치 커널 탐색은 중단한다.
2. **현재 연결 센서 3종을 동시 사용한다.** 이미 끝난 IMU 단독 수신, C1 단독 수신, 카메라 단독 수신, 엔코더 손 회전을 반복하지 않는다. 동시 수신에서 공통 노드와 계획기가 실제 입력을 처리하는지만 확인한다.
3. **비구동 통합 실행을 만든다.** 실물 센서 입력으로 판단·보호·명령 생성과 STOP 상태를 확인하되 모터/서보 출력은 차단한다. 실제 취득시각으로 검증되지 않은 값은 기존 미검증 표기를 유지한다.
4. **시뮬레이션은 순환한다.** (a) 확정 기하 단독 완주, (b) 긴 저속/정체와 명령 만료, (c) 추종·정지차 우회·재출발, (d) 피추월·코너 측방, (e) 신호 출발·마커 보조 순서로 최소 기준을 확인한다. 한 기능이 충분히 나아지면 다음으로 이동하고, 전체를 한 바퀴 돈 뒤 가장 큰 경기 손실로 돌아온다.
5. **운영 준비를 마친다.** 실행 명령·설정·로그 경로·노트북 모니터링을 고정한다. 무인 시뮬/센서 수신은 가능하지만 차량 구동을 무인 반복하거나 무기한 시험이 실행 중이라고 가정하지 않는다.

최신 상태 메모: r307 카메라 그리드, r340 마커 관측, r341 희소 상부 표적은 이미 준비됐다. r353 확정 기하 주행은 부분 주행 후 정체로 실패했고, r358 계산 공유는 개선됐지만 10Hz 목표 미달이 남았다. 이 결과를 다시 만드는 데 시간을 쓰지 말고 해당 실패 입력/산출물을 재사용한다. ### 차량 도착 후 최소 실물 확인

실물 차량은 오늘 저녁 이후에야 확보될 예정이고, 토요일 05:00 출발 전까지 별도 트랙을 만들거나 충분한 주행 연습을 할 수 없다. 따라서 실물 작업은 **이미 끝난 센서별 진단을 재실행하는 시간이 아니라, 장착 상태에서 방향·영점·출력·가림을 짧게 확인하는 시간**으로 제한한다.

1. **4방향 벽 기준 센서 확인:** 작은 벽 공간에서 차량을 네 방향으로 정렬하고 C1의 벽 반환/방향, IMU yaw 부호·변화, 실제 이동 시 엔코더 방향이 서로 모순되지 않는지 확인한다. 짧은 직선 이동과 제자리 방향 전환을 사람이 직접 수행하며, 벽의 절대 직각도를 보증하지 않는 한 절대 각도 교정값으로 과장하지 않는다. 최종 배선 상태에서 C1 자기 반환이 보이면 review_c1_self_returns.py로 짧은 검토 기록을 남기되 마스크는 검토 후 적용한다.
2. **모터 출력 확인:** 바퀴를 띄운 상태에서 저출력으로 방향과 응답을 확인한 뒤 단계적으로 속도를 올려 출력 여유·진동·발열·전압 강하를 본다. 고속 확인은 바퀴를 띄운 상태에서 별도로 하고, 지면에서 최고속도 시험을 하지 않는다.
3. **서보 장착 확인:** 기존 무부하 서보 시험은 반복하지 않는다. 링크와 바퀴를 연결한 뒤 중립 직진, 좌우 실제 바퀴각, 간섭/끝단 여유만 확인한다. 이는 장착으로 기구 전달이 달라지기 때문에 필요한 재확인이다.
4. **짧은 지면 확인:** 공간이 허용되면 저속 직진·좌우 회전·정지/재출발만 확인한다. 트랙 랩이나 다중 차량 실차 시험을 시도하지 않는다.
5. **배터리/PDB가 필요한 엔코더 작업:** 이미 수행한 손 회전 시험을 반복하지 않는다. 차량 전원 구성이 준비된 뒤 실제 이동 중 엔코더 방향과 대략적인 속도 피드백이 맞는지만 확인한다. 정밀 count/rev 재측정은 주행 제어에 꼭 필요하다고 드러날 때만 수행한다.

배선 담당자가 승인 배선도에 따라 조립하는 것을 전제로 하며, 별도의 전면 배선 재감사나 이미 끝난 커넥터/전압 검사를 중복 작업으로 추가하지 않는다. 명백한 이상 징후가 보이면 즉시 중단하고 담당자에게 확인한다.

### 대회장 연습 시간

공식 트랙 주행은 대회장에서 허용되는 연습/프리랩 시간에 처음 수행할 수 있다고 가정한다. 그때는 차량 설정을 새로 개발하기보다 신호 출발, 본선 유지, 코너, 정지/재출발, STOP 동작을 짧게 확인하고, 문제가 생기면 속도 상한을 낮추거나 안정 설정으로 복귀한다. 연습 시간에 새 기능을 추가하거나 대규모 보정을 시도하지 않는다。

### 랩타임·추월 성능 작업의 범위

**11/13 영상 후속 조건:** 실제 신호등 촬영/HSV 맞춤은 사용자 일정·재료상 어렵고 intrinsic 보정은 추후 담당자에게 맡긴다. r339 저장 변형에서 밝기0.60배 미검출·밝은 소등 초록의 늦은 출발 오검출을 확인했으므로 단순 색 임계값 완화 대신 점등 전/전이 근거를 검토한다. 사용자 승인으로 낮은 상대용 마커 보조를 기본OFF 옵션으로 준비하며 r340은 관측/기록까지만 연결했다. 감속 연결 전에 직선 앞차·옆차·커브·중복 크기·소실의 제한 반례를 확인한다. r341의4mm 판/8mm 분리 지주처럼 희소 상부는 기존 오목형과 구별해 대표 교통 시험에 넣되, 없는 반환을 자유 공간으로 채우거나 실제 차체 외곽을 줄이지 않는다. 정밀 거리/추종과 전수 형상 검증으로 확대하지 않는다. [조건·구현 구분](sensors/B0390_SIM_2026_11_07.md#1113-실물-신호-시험-불가와-차량-마커-보조-검토).

목표인 빠른 완주와 기존 추월 과제는 유지한다. 추가 랩타임/고속 추월의 P2 분류는 이번 일정 수정 전에도 있었으며, 이번 변경으로 성능 개발을 종료한 것은 아니다.

- **현재 주행 손실은 계속 줄인다.** 계산 지연·명령 만료 때문에 생기는 정지/저속, 불필요한 추종 감속, 기존 속도·우회·추월의 퇴행은 원인에 따라 P0 실행 지연 또는 P1 주행 과제로 처리한다. 최고속도만 보지 않고 긴 저속·속도 유지·랩 시간을 함께 평가한다.
- **기본 교통 동작을 완성한다.** 앞차 추종, 정지차 우회/복귀, 피추월·코너 측방 대응과 기존 직선 추월의 연결을 유지한다. 저속 직선 대표의 성공으로 중속/변속·빠른 상대 추월까지 완료 처리하지 않으며, 미완료 범위는 아래 기존 과제 목록을 따른다.
- **추가 성능 개선으로 돌아가는 조건을 둔다.** 선택한 실행 구성으로 입력→판단→보호→MCU 명령 경로와 단독/대표 교통 주행이 성립하면, 남은 모든 예외가 없어질 때까지 기다리지 않고 랩타임·고속 유지·직선 추월의 시간 이득을 비교한다. 실물 통합 일정을 침범하지 않는 독립 시뮬 묶음은 앞서 진행할 수 있다. 채택은 실제 계산 지연과 갱신된 형상을 반영한 결과로 판단한다.
- **최종 설계와 결합된 튜닝은 설계 반영 뒤에 집중한다.** 축거·조향·센서 가림 변화의 영향을 받는 코너 속도/궤적과 추월 간격은 새 모델에서 확인한다. 설계가 없어도 고칠 수 있는 실행 병목·확인된 주행 오류는 먼저 처리한다.
- **경기 이득으로 작업을 고른다.** 추가 최고속도, 코너 감속/재가속, 빠른 상대 직선 추월, P21 중 실제로 시간을 줄이는 항목을 우선한다. 공격적인 코너 추월·세 대 동시 추월은 기존대로 확대하지 않는다. 관제 화면 미관과 드문 형상의 전수 검사는 성능 개선보다 뒤다.

### 24시간 가동 환경의 사용

- 노트북은 시뮬·코드 분석, Jetson은 실제 센서 동시 입력과 저장 입력 비용 시험을 맡긴다. Jetson 성능 기준 측정 중 무관한 CPU 부하를 겹치지 않는다.
- 이미 완료한 개별 센서 수신과 엔코더 손 회전은 반복하지 않는다. 동시 입력→판단→보호→명령 생성의 공백을 찾는 데 사용한다.
- 시뮬레이션은 단독·정체·추종/우회·피추월·신호/마커를 순환한다. 각 장면의 최소 기준이 확보되면 다음 장면으로 넘어가고, 전체 순환 뒤 가장 큰 경기 손실을 다시 개선한다.
- 24시간 가동은 무인으로 가능한 계산/비구동 수신의 시간 확보를 뜻한다. 모터/서보 구동이나 무인 실차 반복 시험을 뜻하지 않는다. 각 실행 후 로그·종료 상태·재개점을 남긴다.

<a id="작업-순환과-중단-기준"></a>

## 작업을 이어가거나 넘어가는 기준

- 실제 경기의 완주를 막는 대표 실패면 필요한 수정을 계속한다. 정해진 시간이나 실험 횟수만으로 미완성을 완료 처리하지 않는다.
- 해당 기능이 대표 조건에서 성립했고 남은 문제가 미세 성능·드문 예외·확장 기능이면 다른 미완성 필수 기능을 우선한다. 전 분야가 그 수준에 도달하면 경기 손실이 큰 곳으로 돌아온다.
- 새 검사는 줄일 접촉·개입·주행 손실이 분명할 때 추가한다. 작은 분기 단위 통과만으로 전체 정체가 개선됐다고 보지 않는다. 변경 근거 없이 같은 실패를 반복하지 않는다.
- 실제 부품/장착이 없어 확인할 수 없는 항목은 외부 의존으로 남기고 독립적으로 가능한 입력/운영 연결을 진행한다. 질문과 필요한 동작은 [제작 전달 목록](HARDWARE_AND_RULE_QUESTIONS.md)에 모은다.
- 현재는 **GPT가 설계·구현·실행·대기·분석을 직접 수행**한다. 11/12 최신 지시에 따라 구현/실행 워커는 사용하지 않고, 어려운 문제에는 Claude Fable 5.2/high 어드바이저를 재량껏 활용한다. 사용자 중단 요청까지 필요한 다음 묶음으로 이어간다.

<a id="통합-후-권장-속도-시험"></a>

## 주행·속도·연산 평가

계획 명령→독립 보호 출력→MCU 목표→모터축→차체 중 먼저 속도가 막힌 위치를 구분한다. 지도·차체/상대 정답은 평가 전용이며 `/drive → 독립 보호층 → /drive/safe`를 유지한다. 명시 STOP와 실제 앞길 점유·지속 입력 고장을 구별해 처리한다.

C1 10 Hz에서2 m/s는 한 회전20 cm,10 km/h는약28 cm를 이동한다. 점별 보정·관측 거리·계산 지연·제동을 함께 평가한다. 12 Hz만 올려 이를 해결했다고 하지 않는다. 계산비는 빠른 거절과 실제 진행 판단을 나누며 입력 수신·저장 CPU·전체 ROS·실차 결과를 구분한다. 오래된 소스 해시 검사를 통과시키려고 과거 파일을 덮어쓰지 않는다.

직접 필요한 장면은 단독 한 랩, 앞차 추종/급정지/재출발, 끼어들기, 정지차 우회/복귀, 좁은 코너 측방 지속, 최초 시각 출발/가림 해제, 같은 경기 STOP/START다. 기존 대표는 조건이 같으면 재사용한다. 단독 최고속도와1초 평균/유지 시간, 랩 시간, 긴 저속, 명령 급감속, 접촉, 노면, STOP/정상 종료를 따로 보고한다.

<a id="방지턱하드웨어"></a>

## 실물 의존·운영 범위

방지턱 인식/전용 감속/정밀 현가는 필수 목록에서 뺀다. 음수 모터축에서 전진 복구, 도로/잔디 접지·차동기 헛돎, 피치/롤 변화는 일반 주행 항목으로 남기되 실제 근거 없이 세부 모델을 확대하지 않는다.

[승인 전장](hardware/APPROVED_ELECTRICAL_LAYOUT.md)과 [실물 이관](hardware/PHYSICAL_HANDOVER_APPROVED_LAYOUT.md)을 따른다. 카메라 최종 높이·신호 세부 시야·센서 축/영점·실제 측정면 가림·구동 응답은 장착 후 확인한다. 지금 가능한 정지 실센서 연결/기록 검사는 기다리지 않는다.

[운영 요구](autonomy/RACE_MONITOR_AND_RECOVERY_PLAN_2026_11_02.md#1111-추가-요구-시험-속도-상한과-간단한-수동-조작)의 속도 상한과 개발용WASD 또는 짧은 전진/좌·우 버튼을 구현한다. **자율주행 모드에서는 수동 입력 비활성**, 경기 원격 조작은 STOP/START/RESET 범위다. RESET 없는 같은 경기 재개와 최초 신호 대기를 혼동하지 않는다. 일반 시험에 브라우저를 항상 띄울 필요는 없다.

| 11/13 저녁 조립 뒤 | 장착 보정·조향/엔코더 환산·지면 구동/제동·짧은 자율주행 | 실제 방향/중립/회전·정지 확인 후 속도 확대 |
| 11/14 현장 연습 | 실제 코스·조명·신호·재개 대조 | 현장 조건에 맞는 최종 주행 조정 |

가능하면 전체 상판 조립 전 치수표·라이다 광축 높이 단면·시험 가능한 하부 구동/조향계를 먼저 전달받는다. 설계/차체 없이 확정할 수 없는 영점·축·조향 링크 유격·실제 가림은 최종 장착 후 확인한다. 조립 후4~6시간 확보는 소프트웨어 연결과 엔코더가 해결된 경우의 작업 배분 추정이며, 고장 수정·재제작·이동 여유를 보장하는 납기가 아니다.

차량이 연결되면 **정지/방향/중립/축/카운트 → 저속 제동/단독 → 중속 추종·가림 → 선택 속도/밀집 시작·재개** 순으로 짧게 확인한다. 최신 실행 구성·의존성·복구 명령·로그 내보내기·백업을 함께 묶고 새 옵션을 한꺼번에 기본 활성화하지 않는다.

선정 구성으로 단독1랩·대표 교통 경기거리·출발/STOP/재개를 확인한 뒤 주행 영상과 미해결 목록을 남긴다. 다음3인칭 촬영은 차량 앞 코스가 더 넓게 보이도록 위치/주시점을 미리 확인하며, ‘75°’를 기준축 없이 pitch에 그대로 넣지 않는다. 촬영 실패만으로 성공한 주행을 버리고 반복하지 않는다.

전역 지도/새 제어기 전면 교체·새 센서·P22·공격적인 코너 추월·정밀 현가·모든 후방 형상 보장·화려한 관제 화면은 후순위다. 필수 기능의 완료 수준을 균형 있게 확보한 뒤 속도 유지와 추월 성능을 다시 보강한다.
