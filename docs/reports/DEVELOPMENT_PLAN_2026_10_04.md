# 대회 준비 개발 계획: 다중 차량 대응과 실물 이관

기준일: 2026-10-04. 상태: **GPT·Claude 조사·협의를 반영한 현행 권고 계획 — 새 기능 구현 전**.

이 문서는 현재 작업 순서의 기준이며 [9/22 계획](DEVELOPMENT_PLAN_2026_09_22.md)을 대체한다. 과거 계획·시험·실패를 삭제하거나 완료 판정을 바꾸지 않는다. 알고리즘 선택·입출력·관측 한계·시험 설계의 상세 기준은 [다중 차량 설계](../autonomy/MULTI_VEHICLE_DESIGN_2026_10_04.md) 한 곳에 둔다.

## 1. 목표와 바뀐 전제

- **사용자 일정:** 10/5부터 시험기간, 10/24부터 적극적인 작업 참여 가능. 시험기간에도 에이전트 작업은 가능하지만 반복적인 사용자 판단·실물 조작을 전제로 하지 않는다. 이 계획 작성은 미래 자동 실행이나 상시 모니터링을 예약하는 지시가 아니다.
- **하드웨어:** 10/4 사용자 전달로 부품은 구매했지만 설계는 시작하지 않았다. 수령·조립·실제 사양/응답 확인 완료와 구분한다. 현재 코드의 B0183 + C1 + LSM6DSOX, 단일 모터/차동·모터축 엔코더·65 mm·15:1 기준을 임의 변경하지 않는다.
- **전략:** 프리랩 성능과 안전 완주를 우선하되, 이동 차량 추월을 영구 제외하지 않는다. 추종/정지부터 별개 코드를 누적하는 대신 **같은 인지·지역 계획 구조에서 우회/추월을 선택적으로 허용**하는 방향을 검토한다.
- **시간:** 확인한 공식 대회일은 11/14다. 10/24 이후 약 3주가 있어도 차량 완성일과 실차 시험 시간이 보장되지는 않는다. 공식 문구는 경기 시작 1시간 전 프리랩 허용이며 팀별 연습 점유 시간이 보장된 것은 아니다. 현장을 최초 통합 시험으로 쓰는 계획은 피한다. [공식 일정·규정](https://github.com/MOSW626/istech-it-arena/blob/3a9ada035f77305390217795edaa73c495687b6e/MANUAL.md).

성공 목표는 단독 랩타임만이 아니다. **관측 가능한 상대차와 함께 진행하고, 통과 불가능하거나 관측이 부족하면 올바르게 멈추며, 조건이 회복되면 허용 절차에 따라 다시 진행하는 것**이다. 가려진/측정면 아래 차량과 악의적 충돌까지 소프트웨어만으로 해결했다고 선언하지 않는다.

세부 현재 결과는 [프로젝트 현황](../PROJECT_CONTEXT.md), [A2/A3 인수인계](RECORD_REPLAY_JETSON_HANDOFF_2026_09_29.md), [A4 프로세스 고장](../autonomy/PIPELINE_FAULT_VALIDATION_2026_10_04.md), [C1/IMU](../autonomy/SENSOR_INPUT_GUARDS_2026_10_04.md), [모터축](../autonomy/MOTOR_ENCODER_VALIDATION_2026_10_02.md)을 따른다. 이 표는 시험 수치를 새로 합산하지 않는다.

MCU `control_deadline_missed`는 후속 재현에서 반복되지 않았지만 **원인 미해결**이다. 다음 시험기에서 `/actuation/diagnostics`를 종료 전에 회수한다. 재발 시 먼저 최초 공백의 시각/경로를 조사하고, 시간 한도를 늘려 통과시키지 않는다. A3도 새 반복 보호 정지·누적 적체·정지 실패가 생기면 다시 우선순위가 올라간다.

## 3. 우선순위와 기능 허가

아래 단계는 달력 날짜가 아니라 **통과 조건**이다. 하위 단계에 실패했는데 일정이 지났다는 이유로 다음 기능을 활성화하지 않는다. G는 다중 차량 설계의 단계 이름이며 기존 A/B/C 작업 분류와 별개다.

| 우선순위 / 기존 분류 | 작업 묶음 | 통과 근거와 범위 제한 |
|---|---|---|
| **P0 / B0·C1** | **G0 관측·기하와 시험기부터** | 상대차/도로/측정면/가림을 바꾸는 유한한 시험 목록, 가능한 통과와 불가능한 통과의 계산, 평가용 정답 분리, 실패/정지/진행성 판정. 소프트웨어가 풀 수 없는 장착 문제를 먼저 드러냄 |
| **P1 / B1** | **G1 공통 기반의 최소 추종/대기** | 상대차를 벽으로 채택하지 않기, 짧은 경계 기억과 점유 분리, 상대 속도의 이득을 가정하지 않는 간격 제어, 등속/정지/재출발과 피추월. 현행 R0와 비교하며 단독 회귀·독립 보호 유지 |
| **P1 / B3·A1** | 경기/고장 상태 계약·설정형 출발 시험 틀 | 출발 허가와 추종 행동 분리, 임시 보호 후 재개와 고정 고장 후 명시 해제 구분, 재시작 때 의도치 않은 출발 없음. LED 색·개수·순서별 후보를 시험할 구조만 먼저 준비하고 공식 상세 전에는 실제 출발 판정 확정 보류 |
| **P2 / B2** | **G2 제한 정지차 우회** | 통로가 실제로 있는 가장자리 표적만. 전체 회전 외곽·관측 범위·중도 포기/복귀 검사. 중앙 완전 봉쇄 사례에서는 거절이 정답 |
| **P2 조건부 / B2+** | **G3 제한 이동 추월** | G2와 시간축 점유·측후방 관측·상대 운동 불확실성·취소 정책 검증 후. 실험 기능으로 시작하고 기본 활성화는 별도 판단 |
| **P1 병행 / A3** | 새 기능의 Jetson 처리 비교 | PC 기능 회귀가 성립한 입력으로 기존 기록/재생을 재사용. 입력 나이·큐·최대 지연·정지·종료 확인. 새 부하만 측정하고 무관한 최적화는 보류 |
| **P1 병행 / C1·C2** | 하드웨어 전달·실물 입력 준비 | 아래 최소 요구사항과 교정/드라이버/통신 검사 틀. 부품을 기다리며 없는 계수를 합성값으로 확정하지 않음 |
| **출전 전 필수 / C3·D** | **G4 실차 이관과 경기 통합** | 실제 STOP·시간/축·구동 응답·낮은 표적부터 단독→복수 표적→경기 절차. 방지턱·조명·그리드·5랩·열/전원 포함 |

**필수와 조건부를 구분한다.** 관측성, 추종/정지/정상 재개, 시간·정지 계약, 실물 점검은 필수다. 실제 여유가 있는 정지차 우회는 높은 우선순위 목표지만 관측이 성립하지 않으면 출전 기능에서 제외할 수 있다. 이동 추월은 같은 기반을 쓰는 확장 후보이며 개발 일정이나 희망만으로 필수 성공 약속을 하지 않는다.

### 다음 구현 요청의 첫 묶음: G0 + G1 인터페이스 고정

처음부터 추월 제어기를 완성하려 하지 않고, 다음 범위에서 설계가 성립하는지 확인한다.

1. 새 기능을 끈 단독 기준선의 소스/설정·실행 경로를 고정하고 기존 실패를 보존한다. 현행 보호층은 경로 계산 모듈의 일부 함수/운동 입력을 공유하므로 리팩터링 전에 동작 고정 회귀를 둔다. 새 기능은 플래그/모드로 구별해 코드나 사용자 변경을 되돌리지 않고 기준선과 비교할 수 있어야 한다. 현재 변경을 무조건 전부 Git에 올리는 뜻이 아니다.
2. 표적 사례는 중앙 정지차, 가장자리 정지차, 등속 앞차, 급정지/재출발, 벽 가림, 낮은 차·측후방 사각으로 시작한다. 짧은 분기 벽을 차로 오인하는 반대 사례도 넣고 R0와 비교한다. 모든 조합을 무작정 곱하지 않는다. 방지턱은 현재 기본에서 제외를 유지하며 별도 선택 시험의 관측 위험을 정의한다.
3. 상대차의 실제 렌더링·순차 광선 취득과 평가용 차체 점유를 연결한다. 완성 스캔에 점을 덧붙인 합성 검사는 단위 시험이지 동체 취득/물리 검증이 아니다.
4. 도로 경계·관측/점유·시간/프레임·실행 가능한 제동 후보·시험 결과의 계약을 고정한다. 임계값/관측 이력 길이와 판정선은 현행 시간 계약과 오차 예산을 보고 시험 전에 기록한다. 보호층이 사용하는 경로 모듈의 공통 함수를 리팩터링하기 전에 기존 동작 고정 회귀를 둔다. 전방 결측의 정지 원인과 실제 주행 경로의 관계는 먼저 기록 전용으로 분석한다.
5. 가능한 틈에서도 현 보호/관측 조건 때문에 전부 멈추는지, 반대로 보이지 않는 차를 지나가는지 확인한다. 성공할 수 없는 구성을 발견하면 기능/기구 변경 제안에서 멈춘다.

산출물은 작은 시나리오 정의·재현 명령·소스/설정 해시·가능/불가능 표·주행/정지/진행성/종료의 별도 판정·후속 G1 범위다. 이 첫 작업에서 알고리즘 전체 교체·센서 추가 구매·고속화·새 물성 확정은 하지 않는다.

G0 가능/불가능 표는 **표적 높이×거리×피치**, **도로 침범량×차체/yaw×오차 여유**, **센서 위치×가림 형상×복귀 궤적**으로 나누어 필요한 조합만 분석한다. 일부 광선/외곽을 보았다는 사실과 그 뒤의 안전한 대응 시간이 있다는 사실을 별도 판정한다.

## 4. 시험기간의 작업 경계와 점검 시점

아래 날짜는 작업시간/성공률 추정이 아니라 **범위 확대를 재고할 점검 시점**이다. 실제 진행은 별도 작업 요청 때 시작한다. 사람이 답하지 않는다고 승인으로 취급하지 않는다.

| 시기 | 우선 목표 | 미달 시 선택 |
|---|---|---|
| 10/5–10/11 | G0, G1 최소 수직 구현, 하드웨어 관측 요구사항 정리 | G0부터 관측 불가능하면 사유와 축소안 기록. 대형 대체 알고리즘을 몰래 시작하지 않음 |
| 10/12–10/18 | G1 회귀·Jetson 비교·경기 상태 설계, 가능하면 G2 | G1이 불안정하면 추월 구현을 넓히지 않고 추종/정지의 최초 실패에 집중 |
| 10/19–10/23 | 안정된 G1/G2 증거와 운용 초안, 조건부 G3 타당성/제한 실험 | 새 아키텍처보다 재현·복귀·실차 인수인계 우선. 미완성 기능은 비활성화 |
| 10/24 팀 검토 | 하드웨어 설계/완성 일정, 관측/정지 실현성, 경기 기능 집합 결정 | G3 유지/보류, G2 범위 축소, 필요 시 장착 변경을 사용자가 결정 |
| 10/24–11/7 | 실물 C2/C3, 낮은 속도부터 단독/다중 차량·경기 절차 통합 | 차량이 늦으면 모듈 시험을 진행하되 실차 완료로 표시하지 않음. 새 기능보다 필수 이관 우선 |
| 11/8–대회 | 검증한 기능/설정 고정, 필수 결함 수정·반복·운영 준비 | 미검증 기능은 경기 기본값에서 제외. 중대한 결함은 고정 일정 때문에 덮지 않음 |

일정의 사용자 의존성도 분리한다. **하드웨어 요구사항 전달은 가능하면 설계 착수 전**, Jetson 재생은 전원/접속이 가능할 때 수행한다. 불가능하면 PC 입력·검사 틀을 먼저 준비하고 Jetson 실측은 10/24 이후로 이월하며 완료로 표시하지 않는다. 10/24에는 직선·코너·가능하면 분기 일부를 포함한 실물 시험 공간/벽·노면 재현물, 무선 채널/원격 STOP 운용도 함께 결정한다.

미커밋 작업이 많은 현재 상태에서 장기 작업을 시작하기 전 소스/설정 스냅샷과 해시를 남긴다. 개발 브랜치의 단계별 커밋과 원격 백업 정책은 사용자와 별도 확인한다. 이번 문서 작업에서는 커밋/푸시를 하지 않는다. 승인 전에도 기존 파일·활동/실패 기록을 보존하며, 자동 `reset`/checkout으로 다른 작업을 지우지 않는다.

시험기간에 이어서 맡길 수 있는 범위는 승인된 묶음의 구현·단위 시험·합성/시뮬 회귀·문서화다. 기존 부품/계약을 유지하는 제한된 수정과 미리 명시한 축소안은 제안 범위 안이다. **구매/기구·센서 교체, 전역 지도 의존성 도입, 안전 임계값 완화, 고속화, 외부 게시/푸시, 실물 위험 시험, 경기 추월 활성화**는 별도 판단을 요청한다.

각 묶음 종료 시 한 번만 다음을 남긴다: 무엇을 확인했는지, 첫 실패와 원인, 바꾼 것/유지한 것, 통과한 조건과 미검증, 다음 묶음·중단 조건. 실행/대기를 별도 담당에게 맡겼다면 부모가 같은 상태 조회를 반복하지 않고 결과와 판정 근거를 독립 검토한다. 필요한 검토 시간을 보장하되 의미 없는 반복 실험이나 성공할 때까지의 임계값 변경은 하지 않는다.

동일한 원인으로 수정이 반복되면 기능 범위를 더 넓히지 않고 원인·대안을 보고한다. 자동 코드 되돌리기 대신 보존된 기준선 모드를 선택한다. 관측 전제 불성립, 비의도 구동/정지 실패, 반복 보호 정지·누적 큐·MCU 마감 실패는 선행 문제로 돌리고, 안전 한도를 완화해 다음 단계에 진입하지 않는다.

## 5. 하드웨어팀에 먼저 전달할 최소 요구사항

설계가 시작되기 전 전달할 내용이며, 아직 수치를 알고 있다고 가정하지 않는다. 상세 질문은 [하드웨어·규정 질문](../HARDWARE_AND_RULE_QUESTIONS.md)을 이어 사용한다.

| 확인 대상 | 왜 지금 필요한가 | 받아야 할 자료 |
|---|---|---|
| C1 측정면과 기구 가림 | 낮은 상대차를 아예 못 보면 필터/계획기 개선으로 해결 불가 | 센서 높이, 차체/지지대 단면·가림 각도, 피치/롤 범위, 낮은 표적을 전방/측방에서 본 시험 |
| 카메라 시야 | 앞차·갠트리·출발 신호 가림, 노면 보조 가능성 | 높이/피치/외부 보정, 그리드별 신호 시야, 조명/노출/블러 자료 |
| 조향·차체 외곽 | 45 cm 도로에서 두 대의 회전 여유가 작음 | 실제 축거·윤거·타이어 폭·최대 조향각·응답·바퀴 포함 회전 외곽 |
| 모터/차동/엔코더 | 모터 회전은 차체 전진과 다를 수 있음 | 실제 감속비·유효 바퀴 둘레·카운트/시각·전진/제동 응답·슬립/공회전. 원웨이 등 부품 변경 시 모터축 환산/제동 재검토 |
| MCU·STOP·전원 | 호스트가 멎어도 정지해야 함 | 핀/전압·PWM+DIR/서보 경로, 타임아웃·부팅 기본값, 물리 버튼·PC 정지와 단절 시험, 전류/열/전압 강하 |

주요 부품을 샀다는 사실만으로 장착/전기 안전을 승인하지 않는다. LiDAR 높이를 임의 확정하거나 ToF를 자동 재도입하지 않으며, 관측이 성립하지 않으면 그 근거와 최소 변경 선택지를 가져온다. 차량을 줄여 통로 문제를 해결하지 않는다.

### 실물 도착 전과 후

- **지금 준비:** 드라이버 축/단위/부호·시각 계약, 원시/보정값 기록, 정지/재시작 검사, 잡음/지연/포화 주입 틀, C1/RGB 장착별 관측 시나리오, 교정 데이터 수집 절차.
- **실물로 확정:** C1 취득 순서·시각·무반사 의미, IMU 영점/온도/내장 필터, 엔코더 펄스·유효 둘레, B0183 FPS/노출/지연, MCU 시간 변환, 조향/제동/열·전원. 시뮬의 임시 계수는 교정값이 아니다.
- **필터 선택:** 기존 A4 입력 보호는 유지한다. 새 추적의 평활화는 지연과 오차를 함께 비교한다. IMU/엔코더에 LPF/EKF를 일괄 추가하지 않으며 실측/주입 시험에서 개선 필요성이 확인될 때만 추가한다. 독립 정보 없이 그럴듯한 슬립/고착을 항상 판별할 수는 없다.

## 6. 경기 준비에서 빠뜨리지 않을 것

- **출발:** 공식 LED 제작/시퀀스 자료 확인 후 실제 판정 구현. 앞차 움직임으로 출발을 대체하지 않는다. 임시 빨강/초록 모델을 공식 신호라고 간주하지 않는다.
- **복구:** 일시 센서 보호·행동 대기·비상정지·MCU 고장의 해제 조건을 구별한다. 공식 허용 개입 이후 재출발 때 신호/주행 상태를 어떻게 복구할지 팀 운용 절차로 고정한다.
- **주행 방향/분기:** 기본은 본선. 코스 ID와 차량 ID의 역할을 분리하고, 다른 차의 후방 마커가 경로 선택을 바꾸지 않게 회귀에 포함한다. 지름길 합류는 별도 기능이며 폭이 좁다는 이유로 차량 축소/미관측 진행을 허용하지 않는다.
- **방지턱:** 현재 새 모드의 임시 제거는 유지하지만 출전 준비 완료 조건에서는 되돌려야 한다. 공식 형상과 팀 인식/감속 방안이 정해지면 피치에 따른 2D 관측·접지·통과/재개를 확인한다.
- **반복/운영:** 단독 및 다중 차량의 5랩, 여러 그리드의 시야, 정지/복구, 통신·노드 종료, 로그 용량·부팅·설정 복구·열/전원. 모든 조합 전수 대신 위험 기반 대표 조건을 사전 고정한다.
- **공식 변경:** 다음 작업 시작 시 필요한 규정/릴리스만 대조하고 변경이 있을 때 차이를 정리한다. 질문/댓글은 초안을 만들 수 있으나 승인 없이 게시하지 않는다.

## 7. 선택하지 않은 일과 재개 조건

| 보류 항목 | 다시 검토할 근거 |
|---|---|
| 전역 SLAM·지도 경주선·전체 ForzaETH 이식 | 짧은 지역 관측/이력으로 필요한 진행성을 확보할 수 없고, 지도/현장 매핑·통합 비용을 감당할 수 있을 때 사용자와 재논의 |
| MPC/MPPI로 추종기/계획기 전면 교체 | 같은 인지·시나리오·속도 조건에서 현재 소수 후보/Pure Pursuit의 특정 한계가 재현될 때 제한 비교 |
| RL/상대차 행동 학습·전략적 방어 | 기본 관측/정지/실물 이관 이후. 이번 출전의 필수 의존성으로 넣지 않음 |
| 20 km/h·공격적 추월·지름길 | 실제 제동/조향·관측과 경기 규칙이 허용하고 기존 단계가 통과한 후 별도 승인 |
| 모든 센서 누락의 근본 원인/모든 물성 정밀 모델 | 기능 실패·누적 지연·실물 안전에 연결되는 구체적인 증거가 있을 때 우선 재개 |

이번 요청의 종료 조건은 **독립 조사와 협의, 전체 계획·설계·현황·활동 기록 정리**다. 구현·시뮬레이션·Jetson 실행·하드웨어 변경·게시를 수행하지 않는다. 다음 구현 시작점은 위 G0 묶음으로 제안한다.
