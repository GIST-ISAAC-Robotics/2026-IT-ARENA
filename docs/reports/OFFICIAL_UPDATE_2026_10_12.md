## 2. 신호등: 출발 의미는 공개, 설치·실물 검증은 남음

Pinocchio가 10/9 18:00 KST에 [제작 사양](https://github.com/MOSW626/istech-it-arena/issues/3#issuecomment-6077787556)과 [Arduino 코드](https://github.com/MOSW626/istech-it-arena/issues/3#issuecomment-6077789894)를 공개했다. 아래는 코드의 **명목 시퀀스**이며 실물 지연 실측값이 아니다. 빨강은 누적 점등된다.

| 단계 | 상태 | 유지 시간 |
|---|---|---|
| 준비 | 전체 소등 | 1 s |
| 1 | 빨강 1개 | 1 s |
| 2 | 빨강 2개 | 1 s |
| 3 | 빨강 3개 | 1~3 s, 정수 ms 난수 |
| 4 | 빨강 4개 | 1~3 s, 정수 ms 난수 |
| 출발 | 빨강 4개 소등 + 초록 점등 | 초록 5 s 후 전체 소등 |

시퀀스 시작부터 출발까지 명목 5~9 s, 난수 평균으로는 7 s다. 시작 전 소등과 출발 후 소등은 모두 존재하므로 **단순히 화면이 어두워졌다는 이유로 출발하지 않는다**. 고정 대기시간이나 앞차 움직임으로 직접 시각 인식을 대체하지 않는다.

공식 `traffic_light.py`는 이 시퀀스를 반영하고 UDP schema 3의 `go`·`reds`·`reds_on`·`green`을 제공한다. **UDP는 시뮬레이터 연동/평가용이지 대회 제어기 입력이 아니다.** 공식 `world.sdf`는 빨강 4 + 초록 1의 정적 램프로 바뀌었으나 상태에 따른 발광 전환은 아직 연결되지 않았다. 스크립트 실행만으로 카메라 입력에 점등 변화가 생기는 것은 아니다. [공식 트랙 설명 §6](https://github.com/MOSW626/istech-it-arena/blob/b27f94730b869837a804a3088447103d6b35b87e/track/README.md#6-시뮬--실전-차이-개발-시-반드시-감안)

### 남은 사양과 팀 쪽 후속

- 세트당 위아래 광원 2개와 5 mm 간격이 소개됐지만, **발광면 지름 15 mm가 광원 하나인지 세트 전체인지**는 운영진이 제작자에게 확인 중이다. 공식 SDF는 지름 15 mm 구체 5개·피치 30 mm를 사용하므로 실제 두 광원 구조까지 재현한 모델은 아니다.
- [CAD 링크](https://github.com/MOSW626/istech-it-arena/issues/3#issuecomment-6077879126)는 공개됐다. 기둥·고정부는 트랙에 맞춰 수정 예정이며 **발광면 중심의 실제 높이·그리드와의 거리·방향**은 [운영진 확인 요청](https://github.com/MOSW626/istech-it-arena/issues/3#issuecomment-6084019922)이 남아 있다. 현재 공식 `scene.json`의 갠트리 1.2 m와 SDF 램프 z=1.08 m를 실물 확정치로 사용하지 않는다. 이번에는 CAD 원본을 내려받아 치수를 재검증하지 않았다.
- 조사 시점에 조립·실물 시험 완료 후속 댓글은 없었다. 설치 사양을 기다리지 않고 시퀀스·상태 계약의 시험은 계획할 수 있지만 그리드별 실물 시야 합격 판정은 남겨 둔다.
- 팀 임시 빨강→초록 판정은 **출발 색의 의미는 최신 사양과 같은 방향**이다. 10/6 보고서의 “반대”라는 결론은 당시 공식 모델에 대한 설명으로만 남긴다. 현재 검출기의 작은 광원/배열 대응이나 공식 시퀀스 적합성이 입증됐다는 뜻은 아니다.
- 후속 시험은 `출발 대기 → 직접 관측에 의한 출발 확정 → 주행`과 STOP/재무장 상태를 분리한다. 초록이 5 s 후 꺼진 것을 경기 종료로 오인하지 않는지, 관측 누락·반사·가림·재시작 때 출발을 잘못 허가하지 않는지 확인한다. 구체적인 판정 창·임계값은 아직 채택하지 않았다.

## 3. 방지턱: 최신 제작안과 시뮬레이션은 별개

담당은 MeKENic → power-on → **MR**로 변경되었으며, 10/10에 운영진이 직접 파일을 공개했다. 첫 공개 뒤 결합부가 여러 번 수정됐으므로 **최종 [제작 지침](https://github.com/MOSW626/istech-it-arena/blob/b27f94730b869837a804a3088447103d6b35b87e/parts/speed_bump/README.md)과 [후속 댓글](https://github.com/MOSW626/istech-it-arena/issues/2#issuecomment-6098273497)**을 읽는다.

| 항목 | 최신 공개 제작안 |
|---|---|
| 외형·단면 | 도로 폭 방향 450 mm × 주행 방향 50 mm × 높이 10 mm. `h(x)=H(1−cos(2πx/L))/2`, 최대 경사 약 32.1°, 양 끝 기울기 0 |
| 출력물 | 권장 2분할: `speed_bump_225mm_h10_1_of_2.stl` / `..._2_of_2.stl`. 턱 포함 첫 조각 231 mm, 두 번째 225 mm이며 결합 후 전체 450 mm. 소형 베드용 3분할도 제공 |
| 결합 | 턱 14×6×4 mm, 천장이 남는 홈 14.4×6.2×4.2 mm, 공차 0.2 mm·모따기 0.4 mm |
| 재질·표면 | PLA, 무광 권장, 레이어 0.2 mm·인필 20% 이상·서포트 불필요로 안내. 대회용은 주황 `#E69919`, 별도 도색/상부 테이프 없이 출력 상태 사용 |
| 시험용 사본 | 기계적 시험용 색은 자유. 다른 색 사본으로 대회용 비전 색 임계값을 맞추지 않음 |
| 고정 | 포맥스에 **얇은 양면테이프 0.1~0.2 mm**, 이음새 아래를 가로지르는 테이프 포함. 초기 폼테이프 안내는 대체됨 |

**공개 설계와 검증 경계:** 공식 자료의 강도·테이프 하중 계산은 설계 근거이며 실차 충격·접착 수명 시험 성적서가 아니다. 특히 여기의 PLA–포맥스 마찰계수 예시 0.3~0.5는 방지턱 바닥의 고정 논의다. **우리 타이어–도로/잔디 마찰계수로 이식하지 않는다.** 공식 문서의 “박스가 더 가혹하다”라는 설명도 모든 속도에서 피치·슬립·전복이 보수적으로 재현됨을 보장하지 않는다.

공식 배포 월드의 방지턱은 여전히 같은 외형의 **박스**다. 새 STL의 곡면·결합부가 `world.sdf`에 자동 반영된 것은 아니다. 팀의 기존 임시 곡면 모델도 새 제작안과 일치한다고 아직 검증하지 않았다. 현재 새 주행 모드의 방지턱 해제는 유지하며, 이후 별도 시험에서 공식 곡면·접촉 형상 대조, 65 mm 바퀴/하부 여유, 피치에 따른 C1 관측 손실·RGB 흔들림·접지와 통과 후 복귀를 확인한다. 색 하나에 의존한 인식이나 인식 없이 항상 통과하는 동작 어느 쪽도 이번에 확정하지 않는다.

## 4. 차량 마커 정정과 아직 남은 충돌

10/7 00:04 KST의 `590aacf`와 [정정 댓글](https://github.com/MOSW626/istech-it-arena/issues/1#issuecomment-6019158070)은 power-on이 사전 변경에 동의했다는 이전 기록을 바로잡았다. **사전 통일은 권고이며 power-on은 `DICT_7X7_100` ID 91을 유지할 수 있다.** 모든 팀의 모든 프레임에서 두 검출기를 반드시 실행해야 한다는 뜻은 아니다. 향후 마커를 차량 식별 보조로 사용한다면 사전별 처리 주기·부하를 설계하고, 마커가 없어도 거리 점유와 보호가 유지되어야 한다.

| 팀 | 공개 사전·ID | 확인 상태 |
|---|---|---|
| MR | `DICT_4X4_50` 1 | 공식 목록 |
| Pinocchio | `DICT_4X4_50` 7 | 공식 목록 |
| ISAAC | `DICT_4X4_50` **49** | 우리 등록·모델 유지 |
| power-on | `DICT_7X7_100` **91** | 변경 의무 없음 |
| ROD | `DICT_4X4_50` **11 / 14** | [팀 수정 댓글](https://github.com/MOSW626/istech-it-arena/issues/1#issuecomment-5978592693)은 14→11, 그 뒤 공식 목록은 14. 최종 불일치 미해결 |

코스 ID 0/20/30/45와 차량 ID를 분리한다. 우리 후방 마커의 흰 여백 포함 5×5 cm와 ID는 바꾸지 않는다. power-on의 여백 부족 주의는 해당 등록 이미지에 관한 것으로, 우리 마커가 변경 대상이라는 뜻은 아니다.

## 6. 후속 계획과 이번 검증

1. **지금 유지:** 현재 G1 제동·접촉 진단, 독립 보호, 단일 모터축 28카운트·15:1·65 mm, 센서와 기본 기둥 제외/방지턱 해제. 규정 갱신 때문에 기존 실패 판정이나 물성을 완화하지 않는다.
2. **경기 상태 작업에 반영:** 신호 사양 공개 대기 대신 새 명목 시퀀스로 출발/재출발 상태 시험을 준비한다. 발광 렌더링 연동은 별도 구현이며 실제 높이/방향은 설정과 미확정 항목으로 분리한다.
3. **출전 전 필수:** 공식 곡면 방지턱을 선택 시험에 반영하고 통과·접지·영상/스캔 복귀를 확인한다. 실물 장착·제동·전원과 함께 검증하며 현재 제어 진단에 즉시 끼워 넣지 않는다.
4. **질문 목록 정리:** 이미 공개된 LED 수/색/순서·방지턱 파일을 다시 요청하지 않는다. 발광면 단위·설치 위치·실물 시험 결과·ROD ID·노면 물성 등 실제 미확정 사항만 남긴다. 새로 우리 팀에 직접 요구된 회신은 발견하지 못했으며 upstream 게시도 하지 않는다.
5. **운영 일정 유지:** 대회 11/14·결산 11/13, 반납·높이·예산·잔디 판정은 10/6 기록을 유지한다. 별도 LiPo 규칙이 없다는 공식 결정은 배터리 안전 검증을 생략해도 된다는 뜻이 아니다.

검증 범위는 공식 커밋/릴리스/댓글/현재 파일의 읽기 전용 대조, ZIP 해시·목록 확인, 문서 링크·변경 범위 검사다. 시뮬레이션·ROS·Jetson·공식 생성기/자체 시험은 실행하지 않았다. 코드·설정·원본·증거 파일 변경 없이 팀 `main`에 문서 갱신을 반영한다.
