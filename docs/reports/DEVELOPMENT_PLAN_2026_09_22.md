# 실차 이전 개발 계획: 필수 기능·조건부 보완·검증 순서

날짜: 2026-09-22. 상태: **코드·시험 기록·공식 규칙을 대조한 권고 계획**. 팀 설계 확정이나 아래 기능의 구현 완료를 뜻하지 않는다.

최신 후속(9/24): [A2 기록·재생 기반과 1차 진단](../simulation/RECORD_REPLAY_2026_09_24.md)을 마무리했다. 12 m 기록 주행/무결성·0.5배속 기능/스케줄·회귀 395개·미완료 기록 거절 7조건은 통과했다. 그러나 **1배속은 재생 발행이 제시간에 이뤄져도 지역 제어기의 IMU/RGB 누락과 운동 입력 보호 정지가 반복되어 기능 실패**다. 다음은 같은 bag로 지역 제어기의 내부 시간 분해·적체 개선을 먼저 검토하고 A3 Jetson 시험을 병행한 뒤 A4로 잇기를 권고한다. 사용자는 이번 범위를 기록·재생 검증까지로 정했으므로 이 후속 개선/시험을 아직 시작하지 않았다. 아래 원래 계획의 필수 항목은 그대로 남는다.

이전 후속(9/22): [A1-2 ROS 연결](../hardware/ACTUATION_ROS_2026_09_22.md)까지 진행했다. 선택형 가상 MCU 경로에서 ROS 고장 14조건·Gazebo STOP/호스트 종료 부분 주행·전체 회귀 365개를 통과했다. 당시 다음은 A2 기록/재생이었으며, 상위 센서 복구/경기 상태 정책과 실제 MCU 내부 제어/독립 차단은 미완료로 남는다. 아래 계획 당시의 구현 공백 전체가 해소됐다는 뜻은 아니다.

후속 진행: 사용자가 이 계획에 따라 첫 작업을 승인했다. **A1-1 구동/정지 계약의 PC 참조 구현·11조건 시험**을 마쳤다. [결과/다음 A1-2](../hardware/ACTUATION_CONTRACT_2026_09_22.md)를 먼저 확인한다. MCU는 ESP32-S3 우선 후보이고 Jetson 속도 명령을 MCU가 엔코더로 폐루프 제어하는 분담이다. 실제 펌웨어·ROS 코스 연결·A2/A4 전체를 완료한 것은 아니다. 아래는 계획 수립 당시의 기준선을 보존한다.

## 1. 결론과 전제

지금은 주행 알고리즘을 더 복잡하게 만들기보다 **실차로 옮길 수 있는 입력·정지 체계, Jetson 실행 검증, 다른 차량이 있는 주행**을 준비할 단계다. 잡음·튀는 값에 대한 추가 검증은 필요하지만, IMU·엔코더 필터를 반드시 먼저 넣어야 한다는 근거는 아직 없다.

- 현재 바로 쓸 수 있는 하드웨어는 **Jetson Orin Nano뿐**이다. 센서·모터 등의 도착일은 미정이며, 하드웨어팀의 **설계 시작까지 약 1~2주** 남았다. 이를 부품 도착일이나 차량 완성일로 바꾸어 해석하지 않는다.
- 앞서 언급한 실제 차량 시험 기간 약 1~2주도 미확정이다. 실물 도착 전에는 이식·계측·고장 처리·시험 절차를 최대한 준비하고, 도착 후에는 실측이 필요한 작업에 집중한다.
- B0183 RGB + C1, 깊이/ToF 미사용을 유지한다. 6축 IMU는 LSM6DSOX가 후보이고, 후륜 엔코더 두 개의 사양·통신은 미정이다.
- 지역 경로 생성 + Pure Pursuit, 단일 모터 + 기계식 차동을 유지한다. 현 속도 기준선을 보존하고 고속화·이동 차량 추월·지름길은 후순위로 둔다.
- 고정된 주차별 일정 대신 **선행 조건과 완료 기준**으로 진행한다. Jetson 작업은 사용자가 예정한 별도 세션에서 병행할 수 있지만, 이 문서 작성으로 새 세션이나 원격 접속을 시작하지 않는다.

## 3. 필수 여부와 착수 순서

‘필수’는 **대회 전 반드시 해결하거나 성립 여부를 확인할 항목**이다. 모든 항목을 지금 동시에 구현한다는 뜻은 아니다. 공식 의무와, 선택한 주행 방식이 성립하기 위한 기술적 요구도 구분한다.

| 순서/묶음 | 작업 | 구분 | 지금 가능한 범위 | 완료 또는 다음 단계 진입 조건 |
|---|---|---|---|---|
| A1 | 센서·구동 명령 계약, 고장/정지/재출발 상태 정리 | 기술 필수·원격 STOP은 규정 의무 | PC 코드·가상 MCU로 구현/시험 | 낡은 명령·노드 재시작·통신 단절로 임의 출발하지 않음. 비상정지는 명시적 해제 전 유지 |
| A2 | 원시 입력 기록·재생·지연 계측 | 검증 기반 필수 | PC에서 먼저 준비 | 원시 입력과 처리/명령 시각을 재현하고, 정답값이 제어에 섞이지 않음 |
| A3 | Jetson 이식·실시간 처리 시험 | 실차 이전 필수, A2와 병행 | 현재 보유 Jetson 사용 가능 | 목표 입력률에서 입력 적체·안전 시간 한도 초과를 계측하고 해결. 정지 경로도 부하 속에서 동작 |
| A4 | 작은 잡음·튀는 값·고착의 추가 시험 | 시험은 필수, 필터는 조건부 | PC 합성 입력/재생 | 깨끗한 기준선과 비교해 위험한 변화가 있는지 결론. 필요한 최소 보완만 적용 |
| B1 | 가림·다중 차량 감지와 추종/정지 | 경기 방식상 필수 | PC에서 상대차 추가 | 벽이 가려져도 상대차로 돌진하거나 상대차를 따라 벽 방향을 잘못 바꾸지 않음 |
| B2 | 완전 정지 차량의 저속 우회 | 사용자 목표상 필요, B1 이후 | 공간 조건부터 PC 검증 | 확인된 통로에서만 우회. 불충분한 공간·관측에서는 정지하고 무리하게 진행하지 않음 |
| B3 | 출발·마커·분기·중도 복구·경기 종료 절차 | 경기 대응 필수 | 상태 구조/가림 시험은 지금, 공식 신호 최종화는 자료 후 | 조기 출발 없음, 마커 누락 때 경로/정지 원칙 명확, 허용된 재출발·종료 절차 확보 |
| C1 | 센서 관측 범위·기구·전원 요구사항 | 설계 전 필수 협의 | 요구사항은 지금, 확정 장착은 팀 설계 후 | 센서가 볼 수 없는 충돌 경로를 파악하고 설계/운영으로 대응 가능한지 확인 |
| C2 | 실제 드라이버·교정·MCU/ESC·서보 연동 | 부품 후 필수 | 인터페이스와 교정/시험 틀은 지금 | 실제 취득 시각·축·단위·구동 응답 확인, 독립 정지 및 저속 폐루프 통과 |
| C3 | 방지턱 대응·실측 물성/제동 반영 | 대회 전 필수, 현재 보류 유지 | 시험 항목 정의, 자료/설계 후 구현 | 턱에서 시야/스캔 평면 변화·접지 변화에 대응하며 실제 형상을 통과 |
| D | 반복 완주·경기 리허설·배포/운영 패키지 | 최종 필수 | 자동화와 체크리스트는 지금 | 여러 시작 위치/오차와 다중 차량에서 지속 주행·정지·복구·정상 종료, 실차 최종 점검 |

실행 순서는 **A1/A2 → A4의 짧은 검증 → B1 → B2**를 기본으로 권고한다. A3는 별도 세션에서 병행한다. B3의 상태 설계와 C1 요구사항은 A1 때 함께 잡고, 구체 구현/실측은 정보가 준비되는 시점에 이어 붙인다. 센서 잡음 연구가 끝없이 B1을 막지 않도록 A4에는 아래 종료 조건을 둔다.

## 4. 첫 묶음: 하드웨어 없이 준비할 안전·입력·시험 기반

### A1. ‘0을 보냈다’와 ‘차가 안전하게 멈췄다’를 분리

현재 ROS 정지 서비스·LiDAR 보호층·시뮬레이션 명령 수신 중단 감시는 출발점이지, 실차 원격 비상정지 체계의 완성이 아니다. 현재 고장 시험에서 확인한 **입력 복구 후 자동 재주행**도 모든 고장에 적용할 정책은 아니다.

1. 준비/주행 허가/출발 대기/주행/일시 보호정지/비상정지 유지/종료 상태와 전환 사유를 명시한다. 전원 재인가·프로세스 재시작은 기본 정지에서 시작한다.
2. 사용자 비상정지·중대한 고장은 명시적 해제와 준비 확인 전까지 유지한다. 짧은 관측 실패에서 자동 복귀를 허용할지는 별도로 정하고, 연속 정상 입력과 경로/공간 재확인을 거치게 한다.
3. 최종 구동기에서 명령의 원래 생성 시각·순번·유효기간을 검사한다. 수신이 늦은 과거 명령이 통신 복구 후 한꺼번에 실행되지 않게 한다. MCU 재부팅·카운터 초기화·중복/순서 역전도 포함한다.
4. Jetson이 멈추거나 통신이 끊겨도 MCU/하드웨어 측 정지가 가능해야 한다. 시뮬레이터의 0.5초 타임아웃을 실차에 그대로 채택하지 않고 실제 속도·제동거리로 한도를 정한다.
5. 속도 0 명령, 엔코더 속도 0, 실제 차체 정지는 별개다. 슬립·경사·ESC의 자유회전/제동 차이를 남겨두고 실측한다. 전원 차단이 항상 최단 제동이라는 가정도 하지 않는다.

가상 MCU는 처음부터 완전한 펌웨어 에뮬레이터일 필요가 없다. 명령 승인/거부·순번·하트비트·통신 중단·피드백·정지 상태를 흉내 내는 작은 시험 상대면 충분하다. 실제 모터 속도 루프를 MCU와 ESC 중 어디서 담당할지, ST3215-HS 제어/피드백 경로가 무엇인지는 부품 선택 후 확정한다. 서보를 임의로 PWM 장치라고 고정하지 않는다.

**완료 기준:** 정상 경로와 모든 정지 사유의 자동 시험, 시작 전 데이터 부족·운영 중 프로세스 종료·정지 중 재부팅/통신 복구에서 비의도 재출발 0. 이후 실제 MCU/HW STOP 시험은 별도 완료 항목으로 남긴다.

### A2/A3. Jetson은 센서가 없어도 시험할 수 있다

- PC에서 RGB·CameraInfo·순차 스캔·IMU·엔코더 원시 입력과 출력 명령/상태를 기록한다. 데이터 생성 시각, 수신 시각, 처리 종료/명령 시각을 구분한다. 재생용 시계와 실기기 단조 시계의 사용처도 나눈다.
- Jetson 설치 상태를 먼저 확인한다. 기존 [ADR 0001](../decisions/0001-simulation-platform.md)의 JetPack 유지·Humble 이식 방향을 우선하며, PC와 OS를 같게 하려고 바로 재설치하지 않는다. ARM64 의존성·OpenCV 검출기 버전·런치/메시지/QoS 호환성을 점검한다.
- 기록을 목표 주기로 재생해 **컴퓨터의 실제 시간 기준** 처리율, 입력 나이 p95/p99/최대, 큐 증가, 누락, CPU/GPU·메모리·온도·클록 저하를 측정한다. 평균 FPS만으로 통과시키지 않는다.
- 현재 RGB 60 Hz 요청과 인식 약 10 Hz, IMU 208 Hz 요청과 시뮬 관측 약 250 Hz는 서로 다르다. 주기별 시험 부하를 명시하고, 제어 50 Hz라면 전체 처리 예산을 20 ms 주기와 함께 검토한다. 기존 운동 이력/입력 만료 한도와 연결해 합격 한도를 시험 전에 정한다.
- 최적화는 병목 측정 후 시행한다. 큐/복사/불필요한 영상 처리부터 확인하고 GPU·C++ 전환은 필요한 경우만 한다. PC Gazebo의 GPU 가속 성공은 Jetson 제어기의 연산 검증이 아니다.
- PC→Jetson 센서 전송→PC 구동의 폐루프 시험은 추가 수단이다. 네트워크 왕복 지연을 별도로 측정하고 실차 내부 지연으로 착각하지 않는다. 서로 다른 ROS 배포판의 직접 통신은 먼저 호환성을 확인하며, 막히면 동일한 입력 재생으로 분리 검증한다.

**완료 기준:** 재현 가능한 입력 묶음/설정과 Jetson 성능 보고서, 장시간 부하 중 지연이 계속 증가하지 않음, 최악 지연에서 안전층 동작 확인. bag 재생은 연산 검증이지 실차 완주·카메라/USB/CSI 드라이버 검증은 아니다. Jetson에 Gazebo 전체를 올릴 필요도 없다.

### A4. 필터링은 ‘검증은 필수, 구현은 조건부’

이미 작은 임의 IMU 잡음·엔코더 양자화는 들어 있지만, 기존 시험이 현실의 값 튐을 충분히 대표하지는 않는다. 반대로 정체불명의 잡음을 크게 넣어 실패시킨 뒤 강한 필터로 덮는 것도 타당하지 않다.

| 입력 문제 | 먼저 할 일 | 필요할 때 적용할 보완 |
|---|---|---|
| 연속적인 작은 요동 | 여러 합성 강도에서 이동 보정 오차·조향 떨림·제동 여유 비교 | 약한 저역통과 등. 지연과 실제 커브 추종 손실을 함께 평가 |
| 한 번/몇 번 크게 튀는 유한값 | 물리적으로 불가능한 값과 실제 급회전을 구분하는 시험 | 변화율/범위 점검·짧은 이상치 처리. 무조건 직전값 유지하지 않음 |
| 센서 값 고착·좌우 엔코더 불일치 | 유효 시각만 갱신되는 고착, 좌우 개별 누락을 별도 주입 | 다른 입력과 일관성 진단 및 감속/정지. 일정한 정상값을 고장으로 단정하지 않음 |
| 펄스/카운터 문제 | 펄스 손실과 통신 패킷 손실 분리, 누적 카운트 보존·랩어라운드·재부팅 시험 | 취득 시각 기반 속도 계산, 누락을 0속도로 바꾸지 않는 처리 |
| 지연·시계 문제 | 취득 시각/도착 시각·역전·중복·시계 초기화 감사 | 시간 정렬·노후 데이터 폐기·안전 정지. 평활화로 대체하지 않음 |

같은 안전 시험 묶음에 **주행 중 LiDAR 지연 급증/연속 누락, RGB 중단/고착, 제어기 또는 보호층 프로세스 종료**도 넣는다. 기존 300 ms LiDAR 시험은 출발 거부였으므로 주행 중 제동 검증을 대신하지 않는다. 반사 불량에 따른 결측·고립 오검출도 거리 ±3 cm 잡음과 별개다. 센서 내용이 우연히 일정한 것과 고장을 완벽히 구분할 수 있다는 가정 없이, 관측 불확실성을 줄이거나 정지하는 기준을 마련한다.

우선 기존 깨끗한/복합 조건을 대조군으로, 대표 잡음·단발/연속 튐·고착·좌우 개별 오차를 작은 독립 시험에서 점검한다. 실패가 나오면 원인을 좁혀 보완하고 동일 입력으로 다시 비교한다. 개선안은 원시값을 보존하고, 필터가 처리한 신호의 시간 의미와 추가 지연을 표시한다.

**종료 조건:** 시험한 범위에서 경로/정지 여유에 의미 있는 악화가 없으면 추가 필터 없이 B1로 넘어간다. 위험한 값 튐은 걸러내거나 안전 정지로 대응해야 하지만, 모든 정상 잡음을 매끈하게 만드는 것은 목표가 아니다. 합성값은 민감도 범위일 뿐 실물 허용 오차로 인증하지 않는다. EKF·자동 영점/온도 보정·복잡한 적응 필터는 지금 필수가 아니다.

## 5. 다음 주행 기능: 상대차가 있어도 본선을 유지

현재 제어기는 벽에서 경로를 만드는 방식이다. 앞차를 단순히 장애물로 멈춰 세우는 것뿐 아니라, **앞차의 윤곽을 벽으로 채택하거나 벽이 가려져 분기로 잘못 들어가는 문제**를 다뤄야 한다.

1. **정적 표적과 벽 가림:** 다양한 폭/높이/색의 상대차를 추가한다. 측정된 물체와 관측 불가능 공간을 구분하고, 경로 선택과 독립 보호층 모두에 반영한다. 정답 위치는 평가기에만 사용한다.
2. **느린 앞차 추종·급정지:** 거리가 가까워지면 감속하고 안전 간격을 유지한다. 필요한 수준의 연속 관측/상대 접근속도 추정을 추가하되, 처음부터 차량 종류를 분류하는 학습 모델이나 완전한 다중 객체 추적기를 요구하지 않는다.
3. **동시 출발·옆차·끼어들기/합류:** 코너에서 옆차와 함께 달리기, 앞차가 표지판/신호를 가리기, 합류 차량을 포함한다. 먼저 정지로 충돌을 피하고, 다음으로 불필요한 정지·교착을 줄여 실제 진행 가능성을 확보한다. 다른 차도 협조적으로 움직인다고 가정하지 않는다.
4. **완전히 정지한 차량 우회:** 양쪽 공간·자차 회전 점유 영역·합류 구간이 확인될 때만 저속 우회한다. 공간이 없으면 대기/허용된 개입 절차로 이어진다. 45 cm 본선에 폭 15 cm 차량 세 대는 산술적으로 여유 0이므로 이를 병렬 주행 가능성으로 취급하지 않는다.

움직이는 상대차의 점에는 자차 이동 보정만으로 제거되지 않는 상대 운동 왜곡이 남는다. 모든 점을 고정 벽으로 처리하는 가정을 검토한다. 후방 5 cm 마커는 보조 단서일 뿐이고 상대차가 모두 ArUco를 쓴다고 가정하지 않는다.

**완료 기준:** 벽·차량 충돌, 노면 이탈, 관측 부족 상태의 무리한 진입, 미검출/정지 지연을 평가한다. 통과율뿐 아니라 추종 간격·완주 가능성·정체 지속 시간도 기록한다. 아무 때나 정지해서 충돌만 없었던 시험을 다중 차량 주행 성공으로 세지 않는다.

## 7. 하드웨어팀 설계 전후로 나눌 작업

### 지금 전달할 최소 요구사항 — 설계 완료를 기다리지 않는다

- **관측:** 현재 C1 측정면 9.5 cm는 임시값이며 낮은 차를 놓칠 수 있다. 전방/측방 충돌 경로, 지지대 자기 가림, 사각에서 나타나는 차, 신호등/갠트리 카메라 시야를 요구조건으로 전달한다. ToF 없이 성립하는지 먼저 검토하고, 안 되면 높이/기구/센서 구성 재논의가 필요하다고 명시한다. 아예 안 보이는 물체는 필터나 감속만으로 해결할 수 없다.
- **조향/외형:** 20×15 cm 목표, 실제 최대 바퀴각·축거·회전반경·돌출 범위와 제조 공차를 주고받는다. 긴 축거 선호와 급커브 통과가 양립하는지 확인한다. 고정 20×15 cm 평가뿐 아니라 조향 중 바퀴를 포함한 점유 영역을 보수적으로 검사할 준비가 필요하다.
- **코스 오차:** 현재 기준 벽에서 약 0.425 m 떨어진 경로를 만드는 설정은 명목 도로/잔디 폭에 의존한다. 실물 벽·잔디 경계가 조금 달라졌을 때의 노면 여유를 시험하고, 현장에서는 측정한 치수로 설정한다. 상대차 때문에 관측 벽이 달라진 상황과 코스 자체 치수 오차를 구분한다.
- **구동/정지:** 모터·ESC의 전진/제동/역전 동작, 데드밴드·응답 지연·명령 단위, 저속 출발, 엔코더 장착/누적 카운트·취득 시각·업데이트 주기, MCU 고장 시 정지 책임을 정한다. 정확한 수치가 없으면 ‘미정’으로 남긴다.
- **전원/공간/열:** 전원 보드 두 장·배터리·Jetson·서보/ESC·배선을 포함한 실제 배치와 지속/피크 전력 예산을 확인한다. 공식 전원 자료의 M01 입력 24–36 V와 지원 6S 배터리 명목 22.2 V, J01의 Jetson 출력 19 V/2.3 A, 12 V 채널 2 A 등은 팀에서 모델별 실제 허용 범위를 확인할 항목이다. MANUAL의 ‘업체 확인 중’과 상세 페이지의 ‘공급처 자료 기준’ 표현도 달라 해소된 것으로 단정하지 않는다. 배터리 패스스루에 서보를 바로 연결하거나 출력들을 임의 병렬하는 결선은 권고하지 않는다.

여기까지는 요구사항·질문 정리이며, 현재 센서 장착 위치를 변경하거나 하드웨어팀 대신 설계를 확정하는 작업이 아니다. 세부 [정지/통신 검토](../hardware/EMERGENCY_STOP_AND_TELEMETRY_REVIEW_2026_09_18.md)와 [구동계 회의 자료](../hardware/DRIVETRAIN_MEETING.md)를 이어 사용한다.

### 부품 도착 전 준비 / 도착 후에만 확정 가능한 것

| 지금 준비할 것 | 실제 장치로 확인할 것 |
|---|---|
| 드라이버 출력 계약·축/단위/부호·장치별 설정 파일 | C1 배열 순서·회전 방향·점별 시각/스캔 시작 시각·무반사값 의미·통신 지연 |
| 교정 데이터 수집/보고 틀, 원시값과 보정값 기록 | IMU 축/온도별 영점·배율/포화·내장 필터 지연, 엔코더 분해능/부호·유효 바퀴 둘레 |
| 카메라 보정판·신호/마커 테스트 시나리오 | B0183 드라이버/해상도·노출/모션블러·왜곡·실제 FPS/지연·설치 시야 |
| 가상 MCU와 실제 어댑터 교체 경계 | 실물 ESC/서보·속도 루프·통신·HW STOP·SW STOP·재부팅 시험 |
| 조향 지연·제동력·마찰·슬립의 범위 민감도 시험 | 실제 최소 회전반경·조향 지연·감속 한계·질량/CG·노면 마찰·전원 강하/발열 |

교정 도구의 틀을 지금 만들 수 있지만, 실제 교정 계수를 합성값으로 미리 확정하지 않는다. 기존 모터 모델이 받지 않는 센서 오류는 MCU 속도 루프 모형/실제 연동에서 별도로 시험한다. 정밀 기어/타이어 모델 전체를 만드는 대신 **조향이 늦거나 제동력이 약할 때도 버티는지**부터 확인한다.

방지턱은 현재 사용자 요청대로 새 모드에서 뺀 상태를 유지한다. 다만 대회 준비 완료 조건에는 반드시 되돌려 넣는다. 최종 형상/설치·인지 방식이 정해지면 접근 감속, 통과 중 피치에 의한 LiDAR 관측 변화, 접지 회복을 검증한다. 상세 3차원 운동 보정은 필요성이 확인되면 도입하며, 저속 통과/보수적 보호 정책과 비교한다.

## 8. 최종 검증·운영 준비와 하지 않을 일

### 반복 검증은 기능별 완료 조건에 포함한다

- 기존 무오차·LiDAR 복합·운동 복합·주행 중 고장을 회귀 기준선으로 유지한다. 실패 기록과 주입값/난수 seed·설정/소스 버전·정지/종료 결과를 보존한다.
- 우선 제안은 대표 깨끗한/복합 조건에서 각각 여러 seed(예: 3개)의 5랩 연속 주행과 6개 출발 위치의 신호/가림 검사다. 전체 조합을 무작정 곱하지 않고 실패 위험에 따라 조합을 선택한다. 3회 통과를 통계적 안전 인증으로 표현하지 않는다.
- 고장 직전부터 정지한 시험은 동적 제동 성공에서 제외한다. 약 10 Hz 평가 표본의 정지 시각만으로 정밀 반응시간을 단정하지 않고, 중요한 정지 경로에는 더 촘촘한 시각 기록을 준비한다.
- 충돌/노면 평가는 현재 이산 차체 표본의 한계를 남기고, 차량 간 충돌·조향 중 외형·가능한 표본 사이 통과를 보완한다. 기준을 완화해 성공으로 만드는 변경은 하지 않는다.
- 실차는 바퀴를 든 정지/방향 확인 → 통제된 공간 저속 → 조향/제동 실측 → 단독 반복 → 상대차/턱 순서로 높인다. 충분한 정지 수단·시험 공간 없이 고속 시험으로 건너뛰지 않는다.
- 부팅/실행/중단/로그 수거를 한정된 절차로 만들고, 설정 버전·정상 동작본 복귀·오프라인 의존성·로그 용량/부하를 관리한다. 경기 중 원격 조작 금지와 개발용 도구를 구분한다.

### 지금 필수로 넣지 않을 것

| 항목 | 판단 |
|---|---|
| IMU/엔코더 저역통과·중앙값 필터 | 추가 시험에서 개선 효과와 허용 지연이 확인될 때만 |
| EKF·SLAM·전역 위치 추정 | 현재 지역 경로 주행의 필수 전제 아님. 누적 오차/경로 복구에 실제 필요할 때 재검토 |
| GPU/C++ 전환 | Jetson 병목 계측 이후. 측정 없는 최적화는 후순위 |
| 자동 랩 카운팅·전체 자동 심판 | 경기 종료/개입 운용은 필수지만 자동화 범위는 별도 선택 |
| 이동 차량 추월·지름길·최적 경주선·20 km/h | 현재 사용자 우선순위에서 제외. 추종/정지/정지차 우회와 실차 제동 확인 이후 |
| 모든 물성의 정밀 모델·추가 미관 작업/영상 | 필요한 오차 범위·안전성 검증을 먼저. 영상은 결과 확인용 선택 산출물 |

## 9. 다음 작업의 권고 범위

다음 구현 요청에서는 **A1의 정지/복구·입력 계약 + A2의 기록/재생 기반 + A4의 제한된 잡음/이상치 진단**을 한 묶음으로 시작하는 것을 권고한다. 우선 깨끗한 기준선과 고장 시험을 유지하고, 문제가 드러난 부분만 수정한다. Jetson A3는 이 입력 묶음을 받아 별도 세션에서 진행할 수 있다.

이 묶음이 끝나면 필터를 더 정교하게 만드는 데 머무르지 않고 **B1의 정적 표적/가림 → 앞차 추종·급정지**로 이동한다. 하드웨어팀에는 C1의 요구사항을 먼저 전달하되 설계 착수 전 수치 확정을 요구하지 않는다. 실제 센서가 없다는 이유로 기다릴 필요도, 없는 부품의 정밀 교정을 끝냈다고 할 필요도 없다.

이번 작업은 계획·문서 정리만 수행했다. 제어기/센서/월드 변경, 새로운 주행/Jetson 시험, 외부 이슈·댓글 게시, GitHub 반영은 하지 않았다.
