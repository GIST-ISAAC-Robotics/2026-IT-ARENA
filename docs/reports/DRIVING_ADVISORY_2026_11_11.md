# 주행 정체·Jetson 처리 지연 자문

2026-11-11. 사용자의 요청으로 가장 큰 문제를 우선순위로 추려 Claude Fable 5.2에 자문했다. GPT가 구현과 검증을 계속 담당한다. 자문은 실행 결과나 채택된 설계와 구분한다.

## 범위와 완료 상태

첫 설명 기반 자문은 `medium`으로 답변을 받았다. 이후 사용자가 관련 원문 열람을 허용하고 `high`를 요청해 실제 저장소에서 재검토했다. **high 재검토는 5시간 사용량 경고(92%) 뒤 정리를 요청했으나 최종 답변 전에 호출 한도에 도달했다.** 이를 코드 검토 완료나 새 결론으로 기록하지 않는다. 아래는 앞서 받은 답변과 GPT의 후속 판단이다. 주간 경고만으로 중단하지 않았으며 새 호출로 제한을 우회하지 않았다.

전체 저장소를 일괄 전달하지 않고 C1 교통 정체, 경로 유효시간, 측방 상태 전환, Jetson 계산 비용을 묶어 질문했다. high 검토에는 관련 소스·대표 기록을 직접 볼 수 있도록 경로를 제공했다. 구현을 위임하거나 제어기 변경을 받지는 않았다.

후속 사용자 지시로 사용량이 복구된 것을 확인했으나, 소진을 목적으로 추가 호출하지 않는다. 계속 해결되지 않는 문제나 중요한 설계 판단에서 다른 관점이 필요할 때만 Fable 5.2/`high` 자문을 다시 사용한다. 이번 한도 도달 전의 미완료 검토를 완료된 것으로 바꾸지 않는다.

## 대표 검증의 범위

자문 초기에 제안된 여러 seed·여러 랩을 매 수정의 필수 조건으로 삼지는 않는다. 후속 논의에서는 **원인에 대응하는 저장 입력·반례와 대표 폐루프 결과**를 먼저 확보하고, 범위 확장은 다른 필수 기능이 갖춰진 뒤 진행하는 데 동의했다. 단순 재생 3회 개선을 실제 완주로 확대하지 않으며, 실패한 실제 주행은 보존한다.

현재 근거는 [r80 저장 후보](../../artifacts/validation/2026-11-11/transported_guard_r80_v1/PLAN.md), [r81 native 교통 실패·결측 구분](../../artifacts/validation/2026-11-11/native_nonreturn_r81_v1/PLAN.md), [최신 Jetson 재생](../../artifacts/validation/2026-11-11/jetson_traffic_r79_v1/PLAN.md)다. 이후 GPT는 PC/Jetson의 경로 재표본화 점 개수가 부동소수점 경계에서 달라지는 현상을 별도로 확인했다. 이는 자문 결론이 아니라 새 계측 결과이며 먼저 수정·대조한다.

## 후속 high 자문: 좁은 지주와 벽 사슬

사용량 복구 후 r81의 반복 정체에 한정해 Fable 5.2/high 자문을 완료했다. 위 미완료 세션과 별개다. 주간 경고만 발생했고 5시간 한도 경고는 없었다. [답변 원문과 제한 비교](../../artifacts/validation/2026-11-11/wall_occluder_r83_v1/advisory/review.md)를 보존했으며 아래 수치는 **자문자가 수행한 저장 입력 비교**로, GPT의 새 주행 결과가 아니다.

- r81의43.6–48.3초47개 새 스캔에서 경계 성립은15회에 그쳤다. 한쪽만 끊겨 벽에 붙어 보이는 좁은 지주와, 매우 짧은 이웃점 현의 방향이 ±3cm 잡음으로 흔들리는 것이 주요 후보 원인이다.
- 짧은 현의 법선 대신 차량 원점 기준 방사 거리 차이를 쓰고, 단절 옆 좁은 점 묶음을 비교한 후보는44/47회 경계 성립을 보였다. 그러나 새 실제 주행이나 모든 차량 형상에 대한 보장이 아니다.
- 후보는 가림체 점을 **벽 적합에서만** 제외한다. 원시 점유·충돌 보호에는 그대로 남긴다. 최소 깊이.06m, 시선 수직 폭.04m·방사 방향 길이.10m 등은 제한 후보값이며 실제 센서 인증값이 아니다.
- 일부 코너가 일반 곡선으로 바뀌거나 초반 속도가 낮아진 저장 판단도 있었다. 단순 개선으로 채택하지 않고 좌우 대칭·넓은 차체·잡음 벽 끝 반례 및 최신r82 저장 입력에서 비교한다. 자문 코드가 호출자의 연결 해제 상태를 다시 계산한 점도 구현 전 검토한다.
- r81의 `traffic_boundary_refresh_trial`은 **false**였다. 별도 파편 벽 가설이 당시 활성화됐다는 전제로 원인을 설명하지 않는다. TTL·경계 길이·확인 횟수를 늘려 정체를 덮지 않는다.

이 자문은 충분한 후보를 제공했으므로 추가 문답을 반복하지 않고 GPT가 구현·검증한다.

## 14:52 후속 자문 완료: 수신과 계산의 주기 분리

r89의 동등 계산 최적화 뒤에도 중앙65.37ms·p95 170.05ms가 남아, Fable 5.2/high에 구조 선택만 자문했다. 관련 소스를 읽었으며 수정·실행·장치 접속은 하지 않았다. 주간 경고는 있었지만5시간 경고는 없었고 정상 완료 후 종료했다. [인사를 제외한 답변 원문](../../artifacts/validation/2026-11-11/decision_cadence_r90_v1/advisory_20261111.md)을 보존했다. 사용량 소진 목적의 후속 문답은 하지 않는다.

추천은 **센서 수신과 무거운 판단의 분리 → 큰 비용의 동등 계산 축소 → 필요할 때 경로 운송과 빠른 추종 분리** 순서다. 같은 source 스캔이라고 장면/명령을 단순 재사용하면 기준 차체 위치, 광선 나이, 실제 조향 외곽이 달라져 위험하다는 지적은 코드 구조와 일치한다. `VisionProcess`와 기록 복원 구조를 참고해 최신1건 snapshot·seq/generation·원천/기준/완료 시각을 분리하고 STOP/RESET 때 이전 결과를 버리는 안을 제안했다.

GPT 검토에서 다음 한계를 분리했다.

- 입력 수신을 긴 판단과 분리할 필요는 타당하다. 다만 정확한 ROS QoS 유실 횟수·시간은 아직 계측하지 않았다. 자문의 구독 깊이/스케줄링 설명과 r90 정지 연쇄는 추론이며 실측 원인 확정이 아니다.
- `.1s` 판단과50Hz 출력만 연결해도 충분하다는 결론은 아직 이르다. 실제 적용 시각의 장면 나이, 직전 **발행된** 조향과 작업 안의 상태가 일치해야 한다. 독립 보호가 있다는 이유로 오래된 계획을 새 명령처럼 계속 발행하지 않는다.
- 임의의170ms 고정 지연이나 `.3s` 하나만으로 운용 승인을 판단하지 않는다. 기존 운동 이력·광선별/장면별 나이 계약을 함께 보존하고, 결과가 도착하는 동안 STOP/세대 변경이 발생한 반례를 확인한다.
- 빠른 추종 분리(B-lite)는 기하 검사가 실제 적용 조향과 달라질 수 있어 즉시 채택하지 않는다. 먼저 더 작은 주기 변경과 수신 분리의 필요성을 확인한다. CPU를 쓰지 않는 기본 경로에 새 worker/진단 비용을 얹지 않는다.

자문 직후 r91 run3가 **실제10Hz이지만 첫 판단 전 SENSOR_STOP·진행0m**로 끝났다. 따라서 자문의 “10Hz 성공이면” 분기는 아직 적용할 수 없다. GPT는 영상 결과 회수와 판단 타이머의 결합 여부를 짧게 진단하고, 그 뒤10Hz 주행 입력과 처리 비용을 확인한다. 이전2,837/3,060판단 등 저장 검증과 실제 운용을 구별한다.

## 16:13 후속 자문: 비동기 판단의 적용 시점

수신 분리의PC 증거와r98 Jetson 비용을 확보한 뒤, 비동기 결과를 실제 조향에 적용하는 최소 계약만Fable 5.2/high에 읽기 전용으로 자문했다. 관련 코드를 읽었고 구현·실행·장치 접속·서브에이전트는 없었다. 요청/실제main 모델이 같고 정상 성공·미응답0·readyToStop 확인 후 종료했다. 경고는 **주간98%**, 당시5시간41%였으므로5시간 인계 경고로 오인하지 않았다. 사용량 소진 목적의 추가 문답은 하지 않았다. [답변 원문](../../artifacts/validation/2026-11-11/decision_age_r101_v1/advisory.md).

추천은 진행1건·새 스캔 중심의 제출·결과당1회 발행, 대기 중 양수 명령 재발행 금지, STOP/RESET/시계와 운동 세대 폐기다. 센서 수신만 분리하면 기존 판단 중 서비스/영상 회수 지연이 남는다는 지적은 타당하다. 기존 동기 제어도 판단 시작 장면의 명령을 계산 완료 시각으로 발행한다는 한계가 있다.

GPT는 다음 부분을 그대로 채택하지 않았다.
