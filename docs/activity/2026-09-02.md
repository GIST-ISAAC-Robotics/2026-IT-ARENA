- 이슈 #12는 실제 마커 방향이 아직 미정이라 운영 회의 안건으로 이관된

  댓글은 등록하지 않았다.

## 팀 시험용 공식 월드 갱신

- `track:=official`의 입력을 `config/tracks/official_v2026.09.02.yaml`로
  교체하고 월드를 재생성했다. 노면·잔디·벽·중심선·지름길·공식 흰색
  출발 슬롯 6개는 새 릴리스 값을 사용한다.
- #12 회의 결론 전까지 코스 마커 네 개를 공식 벽 부착점에서 본선
  1.2 m 상류를 향하도록 기울이는 임시 브래킷을 구현했다. 공식 ID,
  누적 거리, 10 cm 판, 7 cm 코드와 PNG/PBR 재질은 유지했다.
- 최초 PBR 단독 렌더링에서는 회색 판 외곽이 큰 사각 후보가 되어 12개
  정지 표본을 모두 놓쳤다. 잘린 마커 이미지를 정규화하면 ID가 나오는
  것을 확인해, 공식 판을 남긴 채 정면에 같은 패턴의 0.2 mm SDF 셀을
  겹쳤다. 최종 정지 표본은 12개 중 11개를 검출했다. ID 30의 0.75 m
  표본은 급커브에서 판 전체가 화면 밖으로 나간 경우였다. 실패 화면과
  수정 후 화면을 모두 검증 산출물에 보존했다.
- 공식 명목 5 cm×1 cm를 쓰는 20분할 코사인 방지턱과 낮은 동적
  신호등, 체크무늬 피니시는 담당 동아리 파일 전까지 임시 표현으로
  유지했다.
- 고정 20×15 cm 차체와 조향 점유 외형 모두 본선 2,332개, 두 분기
  155개·141개 표본에서 정적 벽 겹침이 없었다. 출발 슬롯 6개도 통과했다.

## 후방 식별 마커 임시 구현

- 차량 후면 중앙에 흰 판 전체 5×5 cm의 `DICT_4X4_50` ID 10을
  추가했다. 코스 ID 0·20·30·45와 겹치지 않는 팀 내부 시험값이다.
- 검은 코드는 3.5 cm, 흰 여백은 사방 7.5 mm다. 판 하단 6.5 cm,
  상단 11.5 cm로 두어 후방 ToF 중심 4 cm를 가리지 않고 LiDAR
  스캔면 12.5 cm보다 낮게 했다.
- 질량·충돌체가 없는 시각 요소로만 구현했다. 생성된 6×6 패턴을 OpenCV
  ID 10과 대조하고 치수·배치·충돌체 부재를 자동 검사했다. 실물 장착,
  주행 중 다른 차량에서의 검출과 공식 팀별 모양은 아직 검증하지 않았다.

## 실행 검증

- 짧은 센서 실행에서 RGB·깊이 848×480 약 30.30 sim Hz, ToF 여섯 개
  8×8 약 15.15 sim Hz, IMU·좌우 엔코더·직진·조향·watchdog 정지와
  정상 종료를 확인했다.
- 신호등 정지 표본 6개는 모두 실제 차량 RGB에서 통과했다.
- 방지턱 첫 단독 재검사는 센서 준비가 제한시간 직후 완료되어 실패했다.
  깊이 스트림을 끄고 준비 대기를 늘린 뒤에도 7 sim s를 50초 벽시계로
  제한한 값이 현재 약 0.1 RTF보다 짧아 다시 실패했다. 판정 구간은 그대로
  두고 벽시계 한도만 180초로 늘린 세 번째 실행에서 통과했다.
- 최종 방지턱 실행은 0.16 m/s 명령으로 1.1363 m를 이동했고 차체 기준
  높이가 0.002998 m에서 0.008058 m까지 올라간 뒤 0.003000 m로
  돌아왔다. 명령 중단 후 0.5 sim s 연속 0.01 m/s 미만 정지와 정상
  종료도 통과했다. 앞선 실패 로그는 원인 추적을 위해 보존했다.
- 최신 공식판에서 `brisk` 본선 한 바퀴+약 2 m, 총 48.6927 m를
  진행했다. 최고 지면 속도 0.789711 m/s, 최대 중심선 거리
  0.128371 m, 고정 외형과 정적 벽 겹침 0개였고 조기 출발 없이
  ID 0·20·30·45, 좌·우 벽 선택, 센서 기반 입력과 실제 정지·정상 종료를
  확인했다. 지름길·다중 차량·20 km/h 검증은 아니다.

## 전체 코스 화면 기록

- 처음에는 별도 Gazebo GUI의 `/gui/screenshot` 서비스를 사용했다. 카메라
  이동과 캡처 요청은 `data: true`였지만 WSLg 창이 화면에 합성되지 않은
  상태에서 PNG가 생성되지 않았다. 트랙 파일 오류로 분류하지 않고 실패한
  임시 GUI 설정·호출 파일은 정리했다.
- 같은 월드를 수정하지 않고 고정 외부 카메라를 순차 생성하는
  `scripts/capture_official_track_views.py`를 추가했다. 정수직·남·서·동·북
  사선의 2300×1500 PNG 다섯 장을 저장하고 해상도·비단색·해시·종료를
  자동 확인했다.
- 다섯 장을 직접 열어 코스 전체와 두 지름길이 잘리지 않고, #13의 큰
  노면·잔디 공백이 다시 보이지 않음을 확인했다. 사진·해시·재현 범위는
  `artifacts/screenshots/2026-09-02/official_update/README.md`에 기록했다.
- 촬영용 카메라·브리지·Gazebo 서버를 순서대로 제거했으며 촬영 뒤 남은
  ROS/Gazebo 프로세스가 없음을 확인했다.

## 최종 회귀 검사

- ROS 패키지 5개 빌드, Python/ROS 검사 117개, C++ 단일 모터·차동
  검사 1개와 무작위 동력 관계 20,000회를 통과했다.
- 공식 생성물 29개와 배포 ZIP 24개 파일의 해시, `experimental` 원본
  23개 보존·생성 해시·정적 경로 검사를 통과했다. 공식·실험·초기 원본
  재현 월드의 엄격한 SDF 검사도 모두 통과했다.
- 첫 `experimental --check`는 공유 시설 생성기 변경 뒤 과거 파생
  출력의 `facility_builder_sha256`가 달라 중단됐다. 현재 설정으로 실험
  출력을 재생성하고 같은 검사와 전체 회귀를 다시 통과했다.
- 첫 원본 SDF 확인 명령은 실제 `it_arena_track` 대신 존재하지 않는
  `it_arena_original` 폴더를 적어 실패했다. 실제 경로로 다시 실행해
  `Valid.`와 종료 코드 0을 확인했으며 월드 파일 오류가 아니다.
- 최종 확인 뒤 실행 중인 Gazebo·ROS·이미지 브리지가 없고 GUI도 남기지
  않았음을 확인했다.
