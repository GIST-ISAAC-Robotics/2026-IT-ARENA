# 2026-09-22 활동 기록

## C1 거리 오차·지연 내성 시험 시작

- 사용자 요청으로 C1 거리 오차를 우선 시험하고 문제를 재현하면 제어기를 수정하기로 했다. 장착·방지턱·회피/추월은 이번 범위에서 제외한다. 회피/추월의 주말 검토 의향은 기록만 하고 예약 작업은 만들지 않았다.
- 공식 C1 사양의 ±30 mm와 분별력 15 mm를 확인하고, 오차 범위를 Gaussian 표준편차나 통신 양자화 간격으로 오해하지 않도록 [시험 문서](../autonomy/LIDAR_ROBUSTNESS_2026_09_22.md)에 구분했다. PDF 각주는 접근 실패로 확인하지 못했다.
- 명시적 시험 JSON을 사용한 경우에만 순차 회전 취득 뒤 거리 오차/전송 지연을 주입한다. 취득 시각·미관측 값·기존 기본 동작을 보존하고, 제어기/보호층 모두 같은 오차 입력을 사용하게 했다. 시험 조건과 실제 주입 통계를 보고서에 남긴다.
- Luna가 수행한 조건별 50 seed 직선 진단에서 균일 ±3 cm와 고정 ±3 cm는 정지 0/50, Gaussian 표준편차 3 cm의 별도 스트레스는 7/50 정지였다. 코스 폐루프 성능과 구분한다. 설계·코드 수정은 주 에이전트, 지정 실행·대기는 Luna가 맡는다.

## 거리 오차에 따른 경로 길이 과소평가 수정

- v7 균일 ±3 cm 한 바퀴는 안전 정지·정상 종료·노면 감사를 통과했으나 최고 6.03 km/h·코너 중앙값 2.77 km/h로 둔화했다. 점 사이 잡음의 지그재그를 벽 호길이에 합쳐 전방 경로 관측 예산을 일찍 소진하는 원인을 합성 직선과 코드에서 확인했다.
- 호길이 측정 좌표만 7점 평균하는 첫 안은 과거 급커브 관련 회귀 두 건을 실패해 주행하지 않았다. 연결 구간의 수직 잔차 중앙값이 3 mm를 넘는 경우에만 적용해 깨끗한 실제 모서리는 기존 방식으로 보존했다. 원시 관측의 벽 적합·독립 보호층·안전 기준은 유지했다.
- v8 동일 균일 오차 한 바퀴는 48.7127 m·최고 8.07 km/h·코너 중앙값 4.44 km/h, 중심선 RMSE 1.81 cm였다. 실제 정지·정상 종료·잔존 없음, 주행 343/정지 474 노면 표본의 이탈 0을 확인했다. `PATH_TOO_SHORT` 일시 상태 표본 한 개는 남는다. 관련 회귀 75개 및 추가 보호 검사 등을 포함한 89개를 통과했다.
- 후속으로 v8 고정 상태의 오차+지연 두 바퀴와 ±3 cm 편향/80 ms 지연/무오차 각 12 m·300 ms 출발 거부를 Luna에게 순차 배정했다. 완주와 짧은 구간·출발 거부의 판정은 분리한다.

## 오차·지연 결합 두 바퀴와 실행 장애

- `combined_v8_two_laps`는 균일 ±3 cm·추가 50±20 ms(seed 23)로 **95.3056 m·최고 8.06 km/h·코너 중앙값 4.26 km/h**, 중심선 RMSE 1.71 cm를 기록했다. 실제 정지·정상 종료·잔존 PID 없음·주행/정지 벽 겹침 0이며 평가기 `passed=true`다. 실제 주입 지연 32~70 ms·순차 취득 검증을 통과했다. 일시 경로 거부 상태 표본 9개는 남는다.
- 직후 노면 감사용 WSL 실행이 승인 서비스 `502 Bad Gateway`로 시작되지 않았고, 같은 승인 경로의 1회 재요청도 실패했다. 남은 배치는 수행하지 않았다. Windows에서 결과 요약은 만들었지만 Shapely 부재/설치 실패로 별도 노면 감사는 미완료이며 pytest 부재로 전체 회귀도 미실행이다. 독립 결과 집계 assert 2건은 직접 실행해 통과했다.
- 별도 정지 커브 스캔 50 seed 검사에서 v7/v8 모두 과주행한 두 자세는 각 50/50 정지, 도달 가능한 커브와 반대 벽 대체 사례는 각 50/50 경로 생성이었다. 초기 임시 계산의 유효 거리 필터 누락, 감사 도구의 상대 경로 저장 오류는 고쳐 재계산했고 실주행 결함으로 기록하지 않았다.
- 다음은 결합 두 바퀴의 노면 감사 → 미실행 ±3 cm 편향/80 ms 지연/무오차 각 12 m → 300 ms 출발 거부 → 전체 회귀다. 검증 성공·실패·미실행을 [시험 기록](../autonomy/LIDAR_ROBUSTNESS_2026_09_22.md)에 구분했다. 공식 월드·차량 설정 해시는 그대로이며 다른 작업의 문서/산출물은 보존했다. GitHub 게시·영상 추가·컴퓨터 종료는 수행하지 않았다.

## 사용자 요청 후 즉시 재개

- 사용자 재개 요청으로 Luna의 정식 승인 요청을 다시 시도했으나 검토 서비스 연결 종료로 명령이 실행되지 않았다. 일반 권한의 WSL 목록 조회도 `E_ACCESSDENIED`였다. 주 에이전트가 동일한 정식 추가 승인 경로로 읽기 전용 실행 확인·기존 결과 감사를 요청하자 통과했다. 권한 설정이나 승인 검사를 우회하지 않았다.
- `combined_v8_two_laps`의 추가 노면 감사를 완료했다. 주행 726·정지 530표본에서 도로 밖 차체 면적은 모두 0이었다. 이전 미완료 기록은 장애 당시 이력으로 보존한다.
- `resume_v8` 배치 시작 전 전체 Python/ROS 회귀 **276개 통과(17.28초)**를 확인했다. 제어기 소스 해시는 이전 v8 두 실행과 같았다. 남은 다섯 조건을 순차 실행하는 도구를 추가하고 한 번의 정식 승인으로 시작했으며, 실행 대기와 결과 수집은 Luna에게 맡긴다. 미완료 시 앞선 산출물을 지우지 않고 중단 사유를 남긴다.
- `resume_v8_bias_plus30`/`bias_minus30`/`delay80`은 각각 12.1985/12.0785/12.1785 m·최고 8.07/8.11/7.68 km/h로 주행/실제 정지/정상 종료/노면 감사를 통과했다. 고정 편향과 지연을 바꿔도 제어기·안전 한도는 유지했다. 이는 12 m 구간 시험이며 전체 코스 완주가 아니다.
- 이어진 `resume_v8_clean`은 `malformed launch argument 'lidar_test_profile:='`로 Gazebo가 시작되지 않았다. 빈 시험 프로필을 CLI로 전달한 검사기 오류이며 센서 표본/진행거리 없는 초기화 실패다. 기존 실패 폴더를 보존하고, 빈 선택 인자를 생략하도록 수정했다. 같은 경로의 빈 `runtime_artifacts`도 생략하고 빈값·공백 포함 경로 회귀를 추가했다. 주행 제어기는 바꾸지 않았다.
- 수정 후 `resume_v8_remaining`에서 전체 회귀와 남은 clean/300 ms 조건만 새 출력으로 시작했다. 이미 통과한 편향·80 ms 주행을 불필요하게 반복하지 않았다.

## 재개 검증 마무리

- 수정 후 전체 Python/ROS 회귀 **277개 통과(16.88초)**를 확인했다. 무주입 대조는 12.0585 m·최고 8.16 km/h·구간 코너 중앙값 4.80 km/h, 실제 정지·정상 종료·벽 겹침 0이었다. 노면 감사 주행 85/정지 635표본의 이탈 면적도 0이다.
- 300 ms 추가 지연은 초록 신호 인지 후 7.074초·71표본에서 독립 보호층이 `stale_input`·최종 명령 0을 유지했다. 실제 평면 속도 1 cm/s 미만·벽/노면 이탈 표본 0·정상 종료·잔존 없음으로 출발 거부 검사를 통과했다. 완주 평가기의 `passed=false`와 지속 정지 종료 사유는 변경하지 않았다. 주행 중 새로 지연이 생겼을 때의 제동 시험은 아니다.
- 마지막 코드/결과 대조에서 기존 경로 제어기와 운동 보정의 허용 나이는 450 ms, 독립 보호층은 300 ms임을 확인했다. 이 때문에 300 ms 시험의 제어 상태는 `RUNNING` 22/`SENSOR_STOP` 49표본이고 운동 보정이 받아들인 나이는 최대 417 ms였다. 보호층의 71표본 연속 차단과 혼동하지 않도록 보고서를 보완했다. 제한을 늘리거나 보호층을 우회하지 않았으며, 실제 차량이 움직였다는 뜻도 아니다.
- 설계·코드 수정·최종 판정은 주 에이전트, 배치 대기·결과 수집은 Luna가 맡았다. 공식 월드·차량 설정·다른 작업 파일은 보존하고, 실행 프로세스 종료와 최종 변경 내용을 확인했다. 결과/현재 현황/인수인계 문서를 갱신했다. GitHub 게시·영상 추가·컴퓨터 종료는 하지 않았다.

## IMU·엔코더·시간 정렬 내성 구현과 1차 시험 시작

- 사용자 후속 요청으로 위 계획의 첫 과제를 시작했다. 엔코더 분해능과 통신 주기는 다시 확인했으며 **아직 미정**이다. 기존 2048틱·100 Hz·2 ms는 시험용 가정으로만 유지한다. 현재 속도·v8 제어기·안전 한도·공식 월드·차량 형상은 변경하지 않는다.
- 명시적인 `motion_test_profile`에서만 동작하는 중계기를 추가했다. 자이로 z축 편향/배율, 양쪽 후륜 환산 배율, 추가 전송 지연/지터, 취득 시각 오류와 구간별 패킷 누락을 구현했다. 제어기와 독립 보호층에 같은 공개 입력을 주고, 원래 취득 시각은 시각 오류 시험 외에는 보존한다. 실제 변환·방출 시각·누락을 사후 감사하며 정답 자세는 평가에만 쓴다.
- [시험 계획·결과 기록](../autonomy/MOTION_SENSOR_ROBUSTNESS_2026_09_22.md)에 단일 오차 7조건의 12 m 검사, 주행 중 입력 끊김/일시 지연, 대표 결합 한 바퀴의 순서와 판정을 정했다. 실제 정지와 정상 종료, 주행/정지 노면 검사를 포함한다. 고장 직전부터 정지해 있거나 0 명령만 나온 것은 동적 제동 성공으로 세지 않는다.
- 작업 전 회귀 277개, 중계기 빌드 후 297개를 통과했다. Luna의 WSL 승인은 검토 서비스 연결 장애로 시작되지 않았고 주 에이전트의 정식 추가 승인으로 빌드·배치를 실행했다. Luna는 결과 파일 감시·수집을 담당한다. 승인 우회·설정 변경은 하지 않았다. 실패·완료 결과는 후속 항목에 추가한다.

## IMU·엔코더 내성 1차 검증 완료

- `stage_a`의 무오차 중계·자이로 ±1°/s·후륜 환산 ±5%·각 15 ms 지연·IMU −5/휠 +5 ms 취득 시각 오류 7조건을 각각 12 m 시험했다. 모두 실제 정지·정상 종료·잔존 없음·주행/정지 벽 겹침 및 노면 이탈 표본 0·주입 감사를 통과했다. 각 1회·짧은 구간이라는 한계를 남겼다.
- 주행 중 IMU 2초 누락(500개), 휠 2초 누락(200개), IMU 80 ms 일시 지연(500개)은 모두 실제 정지와 복구 후 재주행을 통과했다. 약 8 km/h 누락 두 조건에서 보호층 0 명령은 약 0.09초 후 관측했고 안정 정지 시작은 약 0.9~1.0초 후, 마지막 고장 직전 표본부터 이동은 약 0.88~0.90 m였다. 약 10 Hz 비동기 평가 표본/임시 구동계 결과이며 실차 제동거리나 정확한 반응시간으로 승격하지 않는다.
- 복합 조건은 C1 균일 ±3 cm·자이로 +1°/s·후륜 −5%·두 운동 입력 각 10±3 ms 지연·IMU 취득 시각 −5 ms에서 48.6527 m 한 바퀴+약 2 m, 최고 8.26·코너 중앙값 4.37 km/h, 중심선 RMSE 2.00 cm였다. 실제 정지·정상 종료·노면 345/433표본 이탈 면적 0·벽 겹침 0·마커 네 ID·조기 출발 없음·실제 주입을 확인했다. `PATH_TOO_SHORT`/`front_unobserved` 각 1표본도 남겼다.
- 고장 판정의 잘못된 성공을 막는 5개 회귀를 추가해 `stage_b` 전 전체 Python/ROS **302개 통과(16.53초)**를 확인했다. 이번 기본/고장/복합 시험은 총 11/11회 통과로, v8 제어기와 안전 기준을 수정할 실패는 재현되지 않았다. 경로/운동 보정/보호층과 공식 월드·차량 해시가 동일한 비교다.
- 시험 중계기는 공개 ROS 입력만 바꾸며 가상 모터 내부 관절 속도 피드백을 바꾸지 않는다는 경계를 문서에 추가했다. 센서 영점/시간 계약·엔코더 환산·실차 제동 및 MCU 내부 제어, 장기 드리프트/고착·좌우 펄스 손실은 후속이다. 문서·활동·인수인계와 재현 안내를 갱신했고 기존 실패/다른 작업 파일은 보존했다. GitHub 게시·녹화·컴퓨터 종료는 하지 않았다.

## A1-1 시작: MCU 구동 계약·정지 상태·PC 참조

- 사용자 승인으로 첫 작업을 시작했다. 사용자는 ESP32-S3 우선 후보·Arduino/ESP32 계열 MCU가 Jetson 속도 명령과 엔코더로 모터 속도를 제어하는 구조를 재확인했다. 추가 질문에 ESC 모델/명령 방식은 미정이라고 답했다. 실제 핀/ESC 제동/조향 신호와 최종 통신 방식은 확정하지 않았다.
- 부품 없이 검증 가능한 명령/피드백 계약과 정지 상태기계를 구현했다. 부팅 구동 금지, 정지 고정, 명시적 CLEAR/ARM 분리, 유효기간/부팅 ID/세대/순번/소유 호스트 검사, 신선한 좌우 카운트 기반 준비 조건, CRC 프레이밍, 평균 엔코더 속도 PI·포화/적분 초기화를 포함한다. 통신 처리만으로 제어 작업 watchdog을 갱신하지 않는 회귀를 추가했다.
- 단순 종방향 모형의 10조건은 정상 주행/정지·송신 중단·재생/지연·엔코더 누락·STOP 해제·MCU/호스트 재시작·CLEAR만/별도 ARM 후 복구를 확인한다. 실제 모터/ESC·Gazebo 코스가 아닌 PC 참조이며 평가용 모형 속도를 제어 입력으로 넣지 않았다.
- 최초 `development_v1`은 10조건 자료 생성 후 Windows `multiprocessing.Pipe`에서 `WinError 5`로 초기화가 실패했다. 파일을 보존하고 초기화 오류도 전체 보고서에 기록하도록 도구를 수정했다. 정상 승인 재실행은 기존 Luna에게 맡겼으며, 주 에이전트는 문서/최종 코드 검토를 수행해 진행상황 중복 감시를 피했다.
- `windows_v2`는 단위 37개·시나리오 11/11·WSL 전체 339개(17.58초)를 통과했다. 별도 가상 MCU가 실제 시간의 송신 중단을 스스로 감지하고 만료 고정 정지·옛 명령 거절·모형 정지를 보였다. 자식 종료 코드 0·강제 종료/잔존 없음이다.
- 최종 검토에서 `math.isfinite(10**400)`이 `OverflowError`를 내는 것을 재현해 비정상 큰 정수 입력이 수신/PI 검사를 예외 종료하지 않도록 수정했다. 관련 검사 추가 후 Windows 단위 38개 통과이며 최종 실행/전체 회귀를 새 `windows_v3` 폴더로 요청했다. v2·초기 실패는 그대로 보존한다.
- [구현/시험 설명](../hardware/ACTUATION_CONTRACT_2026_09_22.md), ADR 0023, 기존 역할 분담 결정·계획·인수인계를 연결했다. 아직 ROS 경로/실차 펌웨어를 교체하지 않았으며 다음은 A1-2 어댑터/노드 재시작·시계·재허가 검증이다. 기존 코스/속도/제어기·다른 작업을 보존하고 새 Gazebo 주행·Jetson 접속·구매·외부 게시·GitHub 반영·컴퓨터 종료는 하지 않았다.
- 최종 `windows_v3`는 11조건 모두 통과·반환 코드 0, 독립 프로세스 정상 종료·강제 종료/잔존 없음이다. WSL 전체 회귀 **340개(17.06초)**·반환 코드 0과 Windows 단위 38개를 확인했다. 최종 소스 해시/한국어 실행 요약을 보존하고 문서 연결과 변경 공백 검사를 수행했다. 앞선 미완료/중간 검증과 현재 결과를 구분해 기록했다.

## A1-2: ROS 구동 연결·별도 가상 MCU

- 사용자 승인으로 다음 단계를 시작했다. 선택형 `actuation_mode:=virtual_mcu`에 호스트 어댑터·별도 가상 MCU·독립 최종 출력 감시를 추가했다. `/drive/safe` 뒤에만 연결하며 기존 보호층/지역 Pure Pursuit·속도·공식 코스/차량/물성·legacy 경로는 보존했다. ESC 모델/명령 방식·엔코더 사양 미정 조건을 유지했다.
- 단조 벽시계 감시와 시뮬레이션 시계를 구분하고, 원래 명령/엔코더 취득 시각과 CRC/세션/만료 계약을 연결했다. ARM/CLEAR/STOP 서비스는 실제 수신기 ACK를 기다리며 출력부의 현재 부팅/허가 세대 수신 확인도 추가했다. MCU의 관측 입력은 양자화 엔코더지만 Gazebo 내부 모터 PI는 기존 이상적 관절 피드백이므로 두 구현 수준을 구분한다.
- Luna가 2패키지 빌드 및 실행/대기를 맡았다. `build_v1` 전체 350개 회귀 통과, `build_v2` 352개 통과를 확인했다. 주 에이전트가 코드 설계/원인 분석/수정과 추가 회귀를 담당하고 실행 상태 중복 조회를 피했다.
- 첫 `ros_v1`은 `/clock` 첫 수신 전 0시각 대기를 고장으로 처리해 시작하지 못했다. 부팅 중 구동 금지 대기와 작동 중 시계 멎음을 분리했다. `ros_v2`는 12조건 통과 뒤 새 MCU의 출력부 연결/허가 경계에서 대기 초과했다. MCU는 ACTIVE였지만 최종 출력은 0이었으며 6프로세스 정상 종료·잔존 없음이다. 두 실패와 이벤트를 보존하고 수신 준비 왕복 확인을 보완했다. DDS 내부 지연 원인은 확정하지 않았다.
- `ros_v3`와 최종 `ros_final`은 14조건 모두 통과했다. 최종 6프로세스 종료 코드 0·강제 종료/잔존 없음, 관련 5소스 해시 일치를 확인했다. 추가한 회귀에는 옛 출력 세대/부팅의 재생 거절, 중복 명령 수명 미연장, 명령 취득 시각 보존, 출력 허가 확인 전 DRIVE 금지, 시계 역전 시 호스트 ID 교체/미완료 요청 무효화, 잘못된 ACK 타입 거절이 포함된다. 전체 Python/ROS **365개 통과(14.42초)**다.
- `gazebo_stop_v1`은 12.21847 m·최고 8.15 km/h·코너 중앙값 4.59 km/h, STOP 고정/실제 모형 정지·주행/정지 벽 겹침 표본 0·자식 14/14 정상 종료를 통과했다. 정지 요청 후 변위 0.773847 m·안정 정지 0.5초 포함 확인 시간 1.348초다. 첫 코스 실행 후의 시계/ACK/준비 판정 보완은 소스 스냅샷과 구분해 기록했다.
- 최종판 `gazebo_host_exit_v1`은 12.15847 m·최고 8.17 km/h·코너 중앙값 4.74 km/h, 송신 호스트 종료 후 `command_expired` 고정 정지·실제 정지·주행/정지 벽 겹침 표본 0·자식 14/14 정상 종료를 통과했다. 정지 요청 후 변위 0.965680 m·안정 정지 0.5초 포함 1.448초다. 보고서 입력 전체 해시가 현재 코드와 일치하며 실제 구독 목록으로 새 제어 경로에 정답 입력이 없음을 확인했다. 부분 주행을 전체 코스 완주로, 벽 겹침 0을 별도 노면 감사 완료로 표현하지 않는다.
- [A1-2 결과/재현 안내](../hardware/ACTUATION_ROS_2026_09_22.md), 현재 현황·ADR·개발 계획·AGENTS를 갱신했다. 실물 MCU 내부 엔코더 속도 제어/ESC/독립 차단과 상위 센서 복구 정책은 미완료로 구분한다. 다음은 A2 원시 입력/명령/상태 기록·재생 및 Jetson 성능 검증 인계다. 기존 실패/활동·다른 작업 파일을 보존했으며 새 영상·GitHub 반영·외부 이슈/댓글·구매·실물 연결·컴퓨터 종료는 하지 않았다.
