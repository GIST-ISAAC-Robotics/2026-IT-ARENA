# 2026-09-24 활동 기록

## A2 기록·재생 기반 착수

- 사용자의 다음 작업 승인에 따라 전체 계획 A2에 착수했다. 원시 RGB/CameraInfo·순차 LiDAR·IMU·후륜 엔코더, 비교용 명령/상태, 실제 실행 매개변수와 콜백 계측을 남기는 선택형 MCAP 기록기를 구현했다. 원래 헤더/직렬화 바이트를 유지하고 기록기 수신 시각을 별도로 남긴다.
- 별도 ROS 도메인·localhost·`/replay` 경로에서 지역 Pure Pursuit와 LiDAR 보호층만 실행하는 재생기를 추가했다. 저장된 명령·정답 자료는 제어 입력으로 재생하지 않고, 센서 공급 종료 뒤 보호층 0명령을 검사한다. 원시 데이터 무결성·실제 콜백 전달량·재생 기능 판정을 분리한다.
- 기존 구동 경로·제어 수치·차량/코스는 유지하며 기본 기록/계측은 비활성이다. 대용량 원시 파일은 로컬에 보존하고 Git 추적에서 제외했다. [ADR 0024](../decisions/0024-isolated-sensor-record-replay.md)와 [실행/해석 안내](../simulation/RECORD_REPLAY_2026_09_24.md)를 작성했다.
- 설치된 Jazzy에서 MCAP·Zstd 청크 압축, Python 쓰기/읽기 및 종료 API를 확인했다. WSL 일반 실행의 `E_ACCESSDENIED`는 정식 추가 권한으로 진행했고, native Python 3.14에는 pytest가 없어 설치를 늘리지 않고 기존 WSL 시험 환경을 사용한다.
- 사용자가 이후 단순 실행/대기에 **GPT-6 Luna**를 요청했다. 이미 끝난 5.6 Luna의 환경 확인은 보존하고 새 실행 담당을 6 Luna로 구성했다. 설계·코드·판정은 주 에이전트가 맡으며 실행/대기 상태의 중복 조회를 최소화한다.

## 검증

- `record_replay/build.log` 3패키지 빌드, `regression_initial.log` 당시 회귀 391개 통과(41.02초)를 확인했다. 추가된 최종 소스 전체를 다시 실행한 결과는 아니다.
- 첫 `capture_v1` 기록 주행의 실제 실행이 느린 상태에서 사용자가 사용량 확보를 위해 중단을 요청했다. 시뮬레이션 약 6초·빨간 신호 대기·진행 0 m였으며 주행/재생 성공으로 집계하지 않는다. 진행하던 시험만 종료하고 새 시나리오는 시작하지 않는다.
- 소스/부분 자료·로그를 보존하고 현황/안내에 재개 순서를 남겼다. 재생기 실행·최종 회귀·실패 시나리오·Jetson 검증은 후속이다. GitHub 반영·외부 게시·컴퓨터 종료는 하지 않는다.
- 중단 신호 후 검사기 `passed=false`, 사유 `검사 중단 요청`, 진행 0 m를 확인했다. Gazebo/ROS 자식 **14/14 정상 종료·잔존 PID 없음·강제 종료 없음**이다. 기록기는 `complete=true`, 반환 코드 0으로 파일을 닫았다. 원시 직렬화 합계 1,785,405,572바이트·MCAP 파일 32,991,832바이트이며 내부 기록 완료와 주행/재생 성공은 다르다. 파일을 다시 읽는 무결성/전달량 감사는 아직 하지 않았다.

## 재개: 기록 무결성·미완료 거절·GPU 기록

- 사용자 재개 승인으로 GPT-6 Luna가 단순 실행/대기를 맡았다. 원시 `capture_v1`을 다시 읽어 파일/토픽 CDR 해시·개수 및 수신 로그 일치를 확인했다. 기록 길이는 10.276초이고 RGB 약 62.4 Hz·LiDAR 10 Hz·IMU 250 Hz·후륜 100 Hz였다. 출발 대기 기록이지 새 주행 통과 자료는 아니다.
- 입력 없는 기록의 시간 제한·미완료 표시·MCAP 닫힘·제어기를 시작하기 전 재생 거절을 `failure_v1` 7조건으로 확인했다. 당시 회귀 393개 통과(39.54초)이며, 래퍼 셸의 종료 코드 전달 오류는 pytest 실패와 구분한다. 이후 추가 검사와 최종 재실행은 별도 기록한다.
- 기존 렌더 로그에서 `GL_RENDERER = llvmpipe (LLVM 20.1.2, 256 bits)`를 확인했다. 새 `capture_v2`는 기존 정상 주행의 `wsl_nvidia` 실행 설정을 사용한다. 트랙/센서/제어 수치를 바꾸지 않는다.
- 재생 상태 콜백의 기본 인자 캡처가 ROS MessageInfo 인자로 해석될 수 있어 1인자 factory로 수정했다. 입력 종료 전에 이미 0이던 명령만으로 EOF 정지를 통과시키지 않도록 실제 EOF 이후 시각을 검사하고, 비동기 기록/재생 명령 비교 지표를 추가했다. DDS 부가정보는 사전/속성형 모두 수용하고 송신자별 순번을 구분하도록 보완했다. 초기 파일의 빈 순번을 무손실 증거로 사용하지 않는다.
- `capture_v2`는 **12.11848 m·최고 8.16 km/h·코너 중앙값 4.74 km/h**, 실제 모형 정지·벽 겹침 주행/정지 각 0·자식 14/14 정상 종료·잔존/강제 종료 없음으로 통과했다. 실제 렌더러는 `D3D12 (NVIDIA GeForce RTX 5070 Laptop GPU)`다. 20.968초 기록·원시 3,608,286,772바이트·MCAP 59,526,815바이트이며 파일/토픽 CDR 감사도 통과했다. 부분 주행이며 실차/노면 전수 감사가 아니다.
- 기록기 RGB는 1,298개, 평가기는 1,310개여서 upstream부터의 완전 무손실은 확인되지 않았다. LiDAR 209·IMU 5,242·후륜 2,097개와 실제 입력률을 기록했다. 부가정보의 DDS 시각/순번은 읽혔지만 publisher GID는 없으므로 송신자별 누락 인증은 미완료다.
- `replay_half_v1`은 센서 발행 전 DDS 노드별 그래프 조회가 아직 준비되지 않아 실패했다. 토픽 구독 개수와 노드 이름 조회 준비를 별도로 기다리도록 수정했다. 두 자식은 정상 종료했다.
- `replay_half_v2`는 명령 생성/EOF 정지·정상 종료를 통과했지만 재생 발행이 최대 약 **19.97초** 늦었고 지역 제어기 IMU 콜백 3개가 누락됐다. 당시 `passed=true`는 기능 판정에만 해당하며 목표 속도 재생 통과로 사용하지 않는다. 비교용 관측 메시지마다 ROS 시계를 발행/스핀하던 비용을 제외하고, 실제 시간 기반 시계로 늦어진 입력 나이가 드러나게 수정했다. 이후 판정에는 재생기 지연 p99 20 ms·최대 100 ms(시뮬 시각 기준)를 별도로 요구한다.
- 첫 1배속 시도는 실행 전 승인 검토 서비스 연결 오류로 시작되지 않았다. 수정된 재생기의 새 0.5배속 검증은 정식 권한 요청이 정상 처리되어 시작했다. 승인 우회/외부 설정 변경은 하지 않았다.

## 재생 지연·계측 구분 보완

- `replay_half_v3` 기능/발행 지연 기준 통과를 확인했다. 실제 시간 지연 p99 19.68 ms·최대 28.98 ms(0.5배속 시뮬 시각 p99 9.84 ms·최대 14.49 ms), EOF 0명령·자식 2/2 정상 종료다. 진단 수신 로그에는 IMU 15개·RGB 1개 부족이 남았다.
- `replay_1x_v2`는 최대 약 8.33초 발행 지연·기능/스케줄 실패였다. root가 회귀 시험을 동시에 시작하여 부하가 겹친 시험이므로 단독 성능 수치로 해석하지 않는다. 실패 자료와 EOF 정지·정상 종료 결과를 모두 보존한다. 겹친 회귀 자체는 394개 통과(38.65초)였다.
- 진단 로그 수신 개수만으로 실제 센서 콜백 누락을 단정할 수 없어, 선택형 계측에 노드 내부 완료 횟수/순번과 읽기 전용 snapshot 서비스를 추가했다. 이전의 ‘콜백 누락’ 표현은 수신한 계측 행 부족으로 정정하며 원래 자료는 고치지 않는다.
- 설치된 rclpy의 원시 직렬화 메시지 발행 경로를 확인해, RGB를 Python 객체로 풀었다가 다시 직렬화하지 않고 원래 CDR를 그대로 전달하도록 보완했다. 입력 프레임/해상도·헤더·제어 설정은 유지한다. 재생 단독 재시험을 진행한다.
- 사용자는 이번 작업을 기록·재생 검증까지로 한정했다. 후속 센서 이상치 시험은 이번 턴에 시작하지 않는다. 서브 에이전트 승인 서비스 503 장애는 우회하지 않았고 root의 정식 권한 요청으로 검증 실행을 시작했다.

## 최종 기록·재생 판정과 인계

- 최종 `replay_half_raw_v1`은 원시 CDR 발행·0.5배속 기능/스케줄 통과, 발행 지연 시뮬 p99 7.11 ms·최대 10.45 ms다. 내부 완료 횟수로 IMU 15개·RGB 1개 부족을 확인했으며 그중 IMU 13개·RGB 1개는 시작 1초 안의 입력이다. 나머지 IMU 2개는 약 10.8초 부근이다.
- 최종 `replay_1x_raw_v1`은 재생기 지연 p99 7.06 ms·최대 17.07 ms로 스케줄 기준은 통과했지만 **제어 기능 실패**다. 지역 제어기에 IMU 1,563개(29.82%)·RGB 245개(18.88%)가 부족했고, 제어 콜백 p99 43.97 ms·최대 49.90 ms, `RUNNING/MOTION_STOP` 반복·최고 안전 명령 0.03 m/s를 확인했다. 누락이 약 11~20초에 반복되며 단순 초기 준비 문제만은 아니다. 보호층은 LiDAR/IMU/후륜을 모두 받았다.
- 두 최종 재생은 재생만 단독 실행했고 EOF 0명령·자식 2/2 정상 종료다. `timing_snapshot` 내부 완료 수와 진단 행 수가 일치해 최종 부족분을 별도 확인했다. 헤더 대조 `delivery_audit.json`에 구간을 남겼다. 아직 어떤 내부 함수가 주요 비용인지 분해 계측하지 않았으며, 시뮬레이터 렌더링/GPU나 Jetson 성능으로 원인을 단정하지 않는다.
- 최종 전체 Python/ROS 회귀 **395개 통과(36.63초)**, 미완료 기록 거절 **7조건 통과**다. [A2 결과](../simulation/RECORD_REPLAY_2026_09_24.md), 현황·AGENTS·계획·산출물 안내를 갱신했다. 다음 권고는 1배속 제어기의 시간 분해/적체 개선과 Jetson 검증 병행, 이후 제한된 이상치 시험이다.
- 사용자가 재확인한 범위에 따라 이번에는 기록·재생 검증까지만 종료한다. 제어기 최적화나 필터/다중 차량 시험을 시작하지 않았으며 속도/안전 한도·차량/트랙 및 이전 기록은 보존했다. GitHub 게시·컴퓨터 종료를 하지 않았다.
- 종료 시 최종 재생 두 보고서의 소스 16개 해시가 현재 파일과 모두 일치했다. `git diff --check` 통과, 원시 bag/수신 로그의 Git 제외 및 기존 추적 없음, WSL 기록기·재생기·이번 Gazebo/제어/가상 구동 프로세스 잔존 없음도 확인했다.
