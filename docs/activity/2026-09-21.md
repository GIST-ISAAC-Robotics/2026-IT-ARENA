## 후속 조사: UNIST Pinocchio 후방 마커의 표준 규격 검출

- 별도 AprilTag의 `tag16h5`만 일부 축소/이진화에서 ID 8·Hamming 2를 반환했다. 오류 보정 0/1/2비트의 추가 30조건으로 2비트 허용 때만 일부 반환함을 확인했다. 정상 ID 8 대조군은 모두 Hamming 0이다. ‘정상 규격’과 ‘일부 조건에서 다른 코드로 읽힐 가능성’을 구분한다.
- 최초 C 생성기 대조군 3계열 실패를 보존하고 OpenCV 독립 생성 대조군으로 해당 3계열의 ID 0·Hamming 0을 확인했다. 나머지 5계열의 대조군과 QR/Data Matrix/Aztec 대조군도 통과했다. 임시 Python 환경만 사용했으며 ROS·주행 코드·시뮬레이션 마커·외부 댓글을 변경하지 않았다.

## 지역 경로 생성 + Pure Pursuit 선택과 센서 전제 갱신

- 사용자 결정에 따라 지역 경로 생성 + Pure Pursuit부터 개발하고, 다른 제어기·지도 기반 주행은 여유가 있을 때 검토하도록 [ADR 0021](../decisions/0021-local-path-pure-pursuit.md), [알고리즘 노트](../autonomy/ALGORITHM_OPTIONS.md)와 프로젝트 현황을 갱신했다. 기존 단계 번호는 필수 구현 순서가 아니라 과거 후보 구분임을 명시했다.
- Pure Pursuit 자체에 전역 위치 추정이 필수라는 앞선 설명을 정정했다. 차량 기준 지역 경로에는 상대 목표점이 필요하며, 기존 엔코더·자이로 운동 보정의 이동량·회전량과 지도상의 자기 위치 추정을 구분했다.
- 일반 RGB+C1은 거의 확정, ToF는 아마 미사용, 엔코더는 있으나 구체 사양 미정, IMU는 후보가 있는 6축 검토안이라는 사용자 설명을 기록했다. B0183 견적 이력은 보존하고 새 모델 선정이나 구매 완료를 선언하지 않았다.
- 낮은 LiDAR 설치·후방 일부 가림·전방 얇은 기둥 가능성을 미확정 배치 조건으로 기록했다. 자기 반사 제거와 가림 뒤 미관측을 구분하고, ToF 없는 신규 감속·정지층의 구현·검증 필요를 명시했다. 기존 ToF 안전층·모델·검증 결과는 보존했다.
- 사용자 요청에 따라 주차별 일정이나 6주 우선순위는 작성하지 않았다. 문서 갱신만 수행했으며 실행 코드·트랙·차량·센서 장착 변경, 새 시뮬레이션·실차 시험, 외부 게시를 하지 않았다.

## B0183+C1+별도 IMU 지역 Pure Pursuit 구현

- 후속 구현 요청으로 B0183+C1 확정·깊이/ToF 제외·LSM6DSOX 6축 후보를 새 선택형 프로필로 구성했다. 전방 RGB 720p60, C1 순차 10 Hz·500점, 독립 IMU 208 Hz, 좌우 후륜 엔코더와 기존 결합 운동 보정을 연결했다. 정확한 실물 노출·크롭·센서 바이어스·시간 계약까지 재현한 것은 아니다.
- 관측 한쪽 벽의 강건한 곡선 적합→평행 지역 경로→후륜축 Pure Pursuit를 구현했다. 속도는 곡률/횡가속도·증속 한도와 독립 LiDAR 제동층으로 제한한다. RGB 출발/분기 인식은 유지하고 새 모드에만 ArUco 0.02·고유 ID 처리를 적용했다. 제어와 보호 노드의 센서 전용 입력을 실제 ROS 구독 목록으로 확인했다.
- 차량 외형 20×15 cm·축거·단일 모터/이상적 오픈 차동은 유지하고 센서 질량 차이 62 g을 차체에 보충해 총 2 kg으로 맞췄다. 카메라/라이다/IMU 장착은 임시다. 방지턱은 실행 사본에서만 제거했다.
- 처음에는 과도한 렌더링 부하로 녹색 신호까지 도달하기 전에 벽시계 제한을 넘었다. 정적 도로/잔디/벽 수천 개 visual을 동일 재질 OBJ로 묶고 headless EGL 경로를 추가했다. 원래 모든 충돌 XML·네 공식 마커 XML·상자 꼭짓점 보존을 검사하고 실제 RGB 화면을 확인했다. 해상도/센서 주기·물리 충돌 형상을 줄이지 않았다. 배칭과 EGL의 개별 효과는 분리 측정하지 않았다.
- 새 ArUco 매개변수 생성에서 OpenCV 4.6의 호환 생성자 문제로 최초 검사 프로세스가 종료됐다. 구/신 API 분기를 수정해 검출 회귀를 통과했다. 첫 최적화 실행에는 신호등 최소 허용값보다 짧은 빨강 0.5초를 넘겨 실패했고, 호출부/평가기에서 1초 이상으로 맞췄다. 실패 산출물도 보존했다.
- 회귀 검사 221개 통과(신규 차량 엄격 SDF 검사·2 kg·무깊이/무ToF 포함). 12.058 m 시험은 최고 1.34252 m/s(4.83 km/h), 중심선 RMSE 2.58 cm, 주행 중 벽 겹침 표본 0, 실제 정지·정상 종료를 통과했다. C1 수신은 시뮬레이션 시각 기준 10 Hz, 명령 수신 약 50 Hz였다. 정지 구간의 벽 겹침 평가는 별도이며 이 통과를 전체 코스/실차 안전으로 확대하지 않는다.
- 이어진 `local_fast` 한 바퀴 시험은 출발부터 오른쪽 후륜 약 107 rad/s·왼쪽 거의 0·차체 약 0인 헛돎으로 실패했다. 정확한 접촉 하중 원인은 미확정이다. 기존 충돌 검출 설정으로 비교 시험하며 기록은 [구현·시험 문서](../autonomy/LOCAL_PURE_PURSUIT_2026_09_21.md)에 이어 정리한다.
- 사용자가 요청한 역할 분리에 따라 설계·수정·판단은 상위 에이전트가 담당하고 Luna에는 지정된 빌드/회귀/실행만 맡겼다. WSL 승인과 자동 승인 서비스 오류가 있었으며 권한을 임의 변경하지 않았다. 세션 핸들이 에이전트 사이에 공유되지 않는 점도 확인했다.
- 사용자 정정으로 ‘한 시간’은 작업 마감이 아니라 완료 후 여유가 있을 때 녹화를 추가하는 조건임을 확인했다. 진행 중인 시험은 보존하면서 품질·반복성 검증을 우선하도록 계획을 정정했다.
- 기존 충돌 검출·3인칭 녹화 실행은 정상 출발해 최고 9.33 km/h를 기록했지만 19.617 m 급커브에서 `WALL_FIT_UNCERTAIN`으로 정지했다. 조향기에서 선택한 벽을 단일 `y=f(x)` 곡선으로 표현할 수 없는 구간이었다. 정지 스캔을 회귀 입력으로 넣고 유효한 반대쪽 관측 벽으로 지역 경로를 대체하도록 보완했다. 분기용 우선 벽은 유지하며 대체 중 속도는 1.2 m/s로 제한한다. 실패 영상도 보존했다.
- 보호층의 축거/외형·후방 마스크를 실제 설정에 연결하고 독립 IMU 장착축을 카메라 기울기와 분리했다. 시간 되돌림 정지 검사 등을 포함해 회귀 224개를 통과했다. 다음 주행 평가에는 RGB/IMU 수신 주기와 정지 구간 충돌 표본도 추가했다. 제어기의 센서 입력을 정답값으로 교체하지 않았다.
- `v3`에서도 약 19.90 m에서 전방 경로가 짧아 정지했다. 반대 벽 선택만으로는 단일 `y=f(x)` 표현의 한계가 해결되지 않았다. 관측 벽을 방위 순서의 연결 구간으로 나누고 호길이/평활 법선으로 경로를 만드는 방식으로 교체했다. 두 실제 실패 스캔 회귀와 전체 225개 검사를 통과했으며 새 폐루프 주행은 별도로 확인한다. `v3`의 Gazebo SIGKILL 종료도 실패 기록에 남겼다.
- 실제 수신 계측에서 RGB 약 62.51 Hz·IMU 약 250.02 Hz로 요청 60/208 Hz와 다른 것을 확인했다. 메시지 시각 기반 보정은 유지하며 명목 설정과 실측 수신 주기를 구분해 기록했다.
- `v4`는 1.740 m에서 기둥 때문에 끊긴 가장 가까운 벽만 고르다가 정지했다. 실제 관측된 긴 연결 구간을 선택하도록 고쳤다. `v5`는 2.980 m에서 작은 벽 끝면의 법선을 과장한 경로와 짧은 관측 길이에서의 증속 때문에 경로를 잃었다. 최대 중심선 거리는 31.2 cm였으며 벽 겹침이 없더라도 정상 주행으로 취급하지 않았다.
- `v6`에는 매개변수 3차 곡선 `x(s), y(s)`의 강건 평활화, 관측 경로 길이 기반 제동 한도와 전방 곡률 예측 감속을 적용했다. 48.713 m(한 바퀴+약 2 m), 최고 8.18 km/h·코너 표본 중앙값 4.94 km/h를 기록하고 실제 정지/정상 종료를 통과했다. 중심선 RMSE 1.94 cm, 주행/정지 벽 겹침 0, 네 마커 ID·좌우 벽 전환을 확인했다. 노면 사후 감사에서는 주행 337표본의 20×15 cm 외형이 모두 도로 안에 있었다. 당시 정지 yaw 기록이 없어 노면 감사에서 제외하고 이후 평가기에 추가했다.
- 같은 `v6` 제어기로 두 바퀴를 요청한 반복 시험은 2.200 m에서 `PATH_TOO_SHORT`로 정지했다. 한 바퀴 성공만으로 반복성을 확정할 수 없음을 확인했다. 벽에서 평행 경로를 만들 때 작은 반경으로 끝부분이 접혔고, 벽 자체는 찾았기 때문에 반대 벽 대체 로직에 들어가지 않는 결함이었다. `v7`은 접힌 경로 가지를 제외하고, 전방 목표가 짧거나 없을 때도 반대쪽의 실제 관측 경로를 확인하도록 보완했다. 원시 장애물 점과 독립 보호층은 그대로 유지했다.
- `v7` 수정 후 Python/ROS 회귀 231개를 통과했다. 사용자는 사용량 여유를 남기기 위해 현재 실행 중인 두 바퀴 시험과 정리 후 일시 중단을 요청했다. 추가 튜닝·새 시험·녹화는 시작하지 않고 재개 지점을 남기기로 했다. 한 시간은 녹화 추가 조건이었으므로 성공 완주 영상은 아직 없으며 앞선 실패 진단 영상은 보존한다. GitHub 게시·컴퓨터 종료는 이번 요청에 없으므로 하지 않았다.
- 최종 `lap_configured_v7_repeat2`는 **95.3256 m·두 바퀴 연속 주행과 실제 정지**를 확인했다. 최고 8.16 km/h, 코너 표본 중앙값 4.91 km/h(10–90백분위 4.02–5.88), 중심선 RMSE 1.81 cm·95백분위 3.79 cm·최대 9.03 cm(출발 오프셋 포함)였다. 네 마커·좌우 기준 벽 전환·센서 전용 입력·순차 10 Hz·제어 명령 약 50 Hz를 확인했다.
- 최종 정지 시작 지면 속도는 약 1.046 m/s였다. 정지 요청 후 변위 16.24 cm·안정 판정 0.992 시뮬레이션 초, 주행/정지 정적 벽 겹침 0이었다. 노면 사후 감사는 주행 628·정지 494표본에서 20×15 cm 외형의 도로 밖 면적이 모두 0이었다. 이를 8.16 km/h 비상제동·연속 접촉/실차 안전으로 확대하지 않았다.
- **Gazebo 종료 감사는 실패했다.** SIGINT 5초→SIGTERM 10초 후에도 종료되지 않아 SIGKILL·반환값 −9로 끝났다. 다른 노드와 상위 프로세스 반환값 0에도 전체 보고서 `passed=false`, `shutdown_clean=false`를 유지했다. 현재 실행은 종료됐고 종료 문제의 추가 수정·재시험은 하지 않았다. 주행 성공/종료 실패/한정된 반복 조건을 인수인계에 구분해 기록한 뒤 사용자 요청대로 중단했다.
