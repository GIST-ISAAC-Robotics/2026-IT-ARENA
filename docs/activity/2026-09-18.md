# 2026-09-18 활동 기록

## 15만원 이하·720p60 RGB 모듈 추가 조사

- 사용자 요청에 따라 USB 또는 CSI로 연결하는 렌즈/보드 포함 컬러 모듈을 다시 조사했다. [비교 문서](../hardware/RGB_CAMERA_MODULE_RESEARCH_2026_09_18.md)에 B0183·B0371·oCam-5CRO-U-M·B0385·477M/B0466N 계열의 모드·VAT/단독 배송가·공급 조건을 정리했다.
- B0183의 국내 광고 1080p60/720p180은 제조사 최신 Jetson 표의 1080p30/720p60과 달라 채택하지 않았다. oCam은 USB3 YUV 720p60, 477M은 1080p60으로 비교하고 B0385의 사용자120fps 경험과 문서100fps/품절 상태를 구분했다.
- IMX519/IMX708의 JetPack 6.2 지원표와 개별 초점/색상 문제 보고를 함께 기록했다. 모든 출고품의 동작 실패로 일반화하거나 Orin에서 지속 FPS를 실측한 것으로 표현하지 않았다. B0482는 추가 검토했으나 문서 상충과 ISP 사례 때문에 우선순위를 내렸다.
- 제조사와 국내 판매처 패키지/케이블의 차이 및 재고 미공개를 남겼다. 구매·Jetson 설치·실물 주행·엑셀/실행 설정·외부 게시는 하지 않았다. 기존 예산과 제어 기준선은 유지했다.

## 원격 비상정지 규정과 노트북 통신 검토

- 공식 main `4c8d3d34671dd5066ce96193365977aa4d1a7662`의 MANUAL·9/14 회의록·PDB 설명·전체 이슈 목록과 #6(댓글 0개)을 재조회했다. 원격 HW/SW 스위치 각각 하나 이상과 경기 전 시연, 자체 연산·리셋 한정, 채널 배정 이월을 확인했다. 물리 버튼과 독립 전기 차단의 의미, 관찰용 텔레메트리의 명시적 적합 판정은 구분했다.

- Espressif 공식 문서에서 ESP-NOW의 MAC 성공과 애플리케이션 수신 보장의 차이, AP 동시 사용 채널 제약, S3의 BLE 전용 및 공용 RF를 확인했다. NVIDIA 문서에서 Orin Nano NVENC 부재를 확인해 영상 압축이 무부하라는 가정을 배제했다. 수치 10–20 Hz·영상 5–10 fps는 검증 전 시작 제안으로만 남겼다.

- 공식 main `4c8d3d34671dd5066ce96193365977aa4d1a7662`의 MANUAL과 #14 전체 댓글을 금일 재조회했다. 공개 문구의 주요 집계 30만 원/제외 항목 10만 원과 사용자 40만 원 견적 전제를 구분했다. 기보유품 별도 산입 없음은 여전히 공식 답변이며 금지 확정으로 바꾸지 않았다. 센서의 자체 10만 원 산정 허용은 미확인으로 남겼다.

- 국내 가격을 갱신했다. C1 99,000원, OV2710 63,360원, L7CX 35,200원은 직접 공개 페이지를 저장했다. L1X TOF400C는 초기 직접 조회가 시간 초과였지만 재조회에서 15,400원·무료배송 조건을 확인하고 원문을 보존했다. STL-19P VCTEC는 세전 179,000원/VAT 포함 196,900원으로 바뀌어 9/8의 129,800원 추천을 현재가로 재사용하지 않는다.
- 문서와 현재 현황만 갱신했다. 구매·판매자/운영진 연락·새 주행·센서 배치/엑셀 변경·GitHub 게시는 하지 않았다.

- C1+RGB162,360원을 기본안, B0410+RGB+L1X4 212,960원을 깊이 후보, STL-27L+RGB265,160원을 상급 거리 후보로 정리했다. 사각·실제 제동·실물 센서 시각 검증은 남았다. 공개 원문과 배포 목록만 저장했고 설치 스크립트 실행·구매·엑셀/차량/실행 설정 변경·외부 게시를 하지 않았다.

## 실물 시험 제약과 B0410 시뮬레이션 가능 범위

- 사용자는 현재 실물 트랙/비용이 없어 구매와 실기 시험이 어렵고 내년에는 가능할 수 있다고 설명했다. 구매를 다음 검토의 선행 조건으로 두지 않고 시뮬레이션에서 먼저 비교하는 방안을 정리했다.
- 기존 D435i의 Gazebo 깊이 카메라, 내부 파라미터 설정, 깊이 제어 노드와 ADR0015/0018을 대조했다. B0410 명목 해상도/시야각/주기/모드별 거리 설정을 재사용할 기반은 있으나 실물 ToF 광학 원리와 검은 재료 응답을 검증하는 모델은 아님을 기록했다.
- 깊이 처리45ms 제한과 RGB/깊이 같은 원점 가정을 확인했다. 실제 처리율/지연 계측, 별도 RGB 정렬, 단일영역 측면 센서 모델 구분을 후속 구현 항목에 남겼다. 거리·지연·결측 조건을 바꿔 필요한 센서 성능의 범위를 구하고 기존 순차 취득 C1과 비교하는 방안을 제안했다.
- [기존 비교 문서](../hardware/TOF_LIDAR_SPEED_AND_JETSON_REVIEW_2026_09_18.md)에 검토 절을 추가하고 현재 현황을 갱신했다. 모델/제어 코드 변경, 신규 시뮬레이션 실행, 실물 성능 판정은 하지 않았다.

## B0410의120fps 원시 출력·30fps 깊이와 Orin Nano 부하 추가 조사

- 제조사 판매 페이지에서 Jetson 깊이 최대30fps/4-phase와 Orin Nano를 포함한 시험 보드 각주를 확인했다. 앞선 Raspberry Pi 문서만의 확인 범위를 보완했다.120fps 원시 영상4장을 깊이1장으로 구성하는 원리이므로 Pi 연산 부족이나 Orin 교체 시 깊이120fps를 뜻하지 않는다.
- 2026-03-18 제조사 포럼의 B0410+Orin Nano CAM1 구동 보고를 찾았다. 동작 근거로 사용하되 JetPack6.2의 지속FPS·CPU/GPU 점유율 실측은 확보하지 못했다고 명시했다. 과거 저FPS 오류 글의 CAM1 안내와 제목/로그 버전 불일치를 연산 성능 부족으로 해석하지 않았다.
- Jetson SDK의 취득/계산/메모리 관리와 공식ROS2 예제의점군 변환/발행을 대조했다. 깊이초당1,296,000픽셀이라는 계산을 CPU점유율로 바꾸지 않았고, SDK내부CPU/GPU 분담과 전체동시부하는 미확인으로 남겼다. 비교·구성 제안·현재 현황을 갱신했으며 설치/실행/구매는 하지 않았다.
