# 활동 기록: 2026-08-30

## 작업 범위

이 컴퓨터에서 2026 IT ARENA 자율주행 경주 소프트웨어·시뮬레이션 프로젝트를 시작했습니다.

## 완료한 작업

- 참조된 시뮬레이션 검토 대화를 읽고, 구상했던 ROS/Gazebo 아키텍처를 확인했습니다.
- Windows 호스트, WSL, GPU 연동, 개발 도구와 GitHub 인증 상태를 점검했습니다.
- WSL2 Ubuntu 24.04.4, WSLg와 Linux에서의 NVIDIA GPU 인식을 확인했습니다.
- 최초 점검 당시 ROS 2, Gazebo와 Docker가 설치되어 있지 않음을 확인했습니다.
- 비어 있던 공개 저장소 `GIST-ISAAC-Robotics/2026-IT-ARENA`를 찾아 복제했습니다.
- 제공된 트랙 ZIP을 보존하고 압축을 풀었으며, SHA-256 `DE448BA10C614E0F635D44B2F36BAB29EBF455C323DE442562DD01A8296758E4`를 기록했습니다.
- 실제 `output_final` 데이터를 감사하고, 동봉된 README와의 중요한 불일치를 문서화했습니다.
- PC 시뮬레이션에는 ROS 2 Jazzy + Gazebo Harmonic을 선택하고, Jetson의 JetPack 6.2.1은 유지하기로 했습니다.
- 프로젝트 현황, 결정 기록, 하드웨어·규칙 질문, 임시 차량 설정과 후속 에이전트를 위한 인수인계 규칙을 추가했습니다.
- WSL Ubuntu 24.04에 ROS 2 Jazzy Desktop, Gazebo Harmonic / `ros_gz`, 개발 도구와 OpenCV ArUco 지원을 설치했습니다.
- 제공된 압축 파일을 바이트 단위로 보존하면서, 엄격한 SDF 검증을 통과하는 파생 실행용 월드를 생성했습니다. 시작 시간을 줄이기 위해 반복적인 정적 형상을 병합하여 링크 수를 1,090개에서 10개로 줄였습니다.
- 매개변수로 조정 가능한 0.18 m x 0.12 m Ackermann 차량, 6개 출발 위치 선택, `/drive` 어댑터, 제한값과 0.5 s 명령 수신 감시 기능을 추가했습니다.
- D435i와 유사한 임시 RGB-D 카메라·IMU를 추가하고, RGB·카메라 정보·깊이·포인트 클라우드·IMU ROS 토픽을 연결했습니다.
- Jetson은 자율주행을, ESP32는 명령 수신 시간 초과 처리·ESC와 서보 출력·좌우 구동륜 엔코더 신호 수집을 맡는 잠정 역할 분담을 채택했습니다.
- 분해능, 샘플링 빈도, 지연과 샘플 누락을 조정할 수 있는 엔코더 시뮬레이터를 추가했습니다. `/wheel_states`를 발행하고, `/wheel_encoder_ticks`에는 `[rear_left, rear_right]` 순서의 누적 카운트를 발행합니다.
- 셸을 거쳐 Gazebo를 실행하던 방식을 서버·GUI 하위 프로세스를 직접 추적하는 방식으로 바꿨습니다. 이에 따라 Ctrl+C 종료 후 고아 프로세스가 남지 않도록 했습니다.
- 자동 인터페이스 테스트 4개와 호출 위치에 의존하지 않는 환경 점검 도구를 추가했습니다.
- WSLg의 Gazebo 렌더링 화면을 `artifacts/screenshots/gazebo_baseline.png`에 저장했습니다.

## 검증 근거와 확인 결과

- 호스트 GPU: RTX 5070 Laptop GPU, VRAM 8 GB, 드라이버 610.74
- 실제 트랙 출력물: 한 바퀴 길이 46.6329 m, 주 경로 폭 0.35 m, 분기 경로 폭 0.12 m, 실제 배치된 ArUco ID 4개, 신호등 중심 높이 1.08 m
- 실제 장면 검증 결과의 일반 구간 최소 곡률 반경은 0.298695 m이며, `min_radius_general_ok=false`입니다.
- 동봉된 README에는 실제와 상당히 다른 형상·마커 정보가 기재되어 있습니다.
- WSL 환경 점검에서 ROS 2, colcon, Gazebo, rosdep, Python, RTX 5070 GPU 연동과 OpenCV ArUco를 확인하고 검사를 통과했습니다.
- 파생 실행용 월드가 `gz sdf -k` 검증을 통과했습니다.
- ROS 패키지 4개를 모두 빌드했습니다. 엔코더·명령 인터페이스 테스트는 4개 통과, 0개 실패였습니다.
- 창 없는 주행 테스트에서 속도 0.30 m/s와 조향각 0.20 rad를 입력했을 때, 오도메트리 위치가 약 `(x=0.782 m, y=0.111 m)`로 변했고 좌우 뒷바퀴의 누적 카운트는 서로 다른 `(9584, 11059)`로 나타났습니다.
- D435i와 유사한 IMU는 정지 상태에서 자세, 각속도와 약 `+9.8 m/s^2`의 수직 가속도를 출력했습니다.
- RGB 카메라 정보·영상의 너비는 848 px였고, 깊이 영상은 `32FC1` 형식이었습니다. 격자 형태로 구성된 포인트 클라우드는 한 행에 848개의 점을 포함했습니다.
- 창 없는 실행과 GUI 실행 모두 정상 종료했습니다. 종료 후 프로세스를 확인했을 때 프로젝트의 Gazebo·ROS 프로세스는 남아 있지 않았습니다.
