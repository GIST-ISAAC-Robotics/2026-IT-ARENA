# 2026-09-08 활동 기록

## LiDAR 운동 보정 구현·시험 — 완료, 공식 촬영의 정지/종료 검증은 미통과

- 사용자 후속 요청으로 마지막 촬영을 공식 코스 전체 한 바퀴의 3인칭 영상으로 정했다. 직선 20 km/h 목표·코너 감속이며 실제 도달 속도를 표시한다. ToF가 독립 보정 시험에서는 꺼져 있고 일반 데모에서는 켜져 있음을 설명한 뒤 계속 진행 승인을 받았다. 다음 작업의 검토 주제는 카메라 기반 방지턱 인식이며 이번에 구현하지 않는다.
- 사용자가 이전 조사 계획의 구현·시험을 승인했다. ROS와 무관한 SE(2) 보정 계산, 양자화 후륜 엔코더·IMU 자이로 입력 어댑터, 기존 벽 추종기와 독립 속도 시험의 선택형 none/deskew/shift/both 연결을 추가했다. 바이어스는 명시 설정이며 자동 영점 추정·EKF·IMU 자세 정답·가속도 이중 적분을 쓰지 않는다. 기본 차량·트랙·구동·센서 사양·일반 ToF 보호·조향 이득은 바꾸지 않았다.
- 점별 취득 시각·마지막 광선 기준·현재 기준을 구분하고, 장착 오프셋·입력 공백/외삽 한도·시간 역행 초기화·관측 나이 보존을 검사했다. 첫 관련 검사 21개가 통과했다. 전체 검사에서는 기존 가짜 제어 객체에 새 motion 필드가 없어 5개가 실패했으며, 대역을 갱신하고 실제 보정 거부→0 속도 검사를 추가한 뒤 183개가 통과했다.
- WSL 일반 조회는 접근 거부였고 승인된 실행 경로로 Ubuntu-24.04에 접근했다. 최초 파일명 wall_follower.py 조회는 잘못된 경로여서 실제 wall_follow.py를 확인했다. 첫 문서/소스 패치는 불일치 문맥으로 적용되지 않았음을 확인하고 정확한 문맥으로 다시 적용했다. 첫 colcon은 기존 산출물까지 탐색해 약 1분 30초 걸렸지만 두 패키지 빌드는 정상 완료했다.
- 5 km/h 순차+결합 보정 스모크는 software 렌더러에서 160.145초 동안 실행되어 목표속도 유지·노면/벽 겹침 없음·실제 정지·21개 하위 정상 종료를 통과했다. 제어 입력은 scan·wheel_states·camera/imu·clock으로 확인했으며 주행 중 보정 거부 0, 최대 외삽 5 ms, 계산 p95 0.632 ms였다. 원문과 당시 13개 입력 소스 해시를 대조하고 ZIP으로 보존했다.
- 합성 벽·알려진 두 단계 운동으로 보정 수학과 바퀴 배율/자이로 바이어스/시간 오차를 검사했다. 최초 합성 조건은 속도 변화가 일부 유효 벽 광선보다 먼저 일어나 음의 시간 오차에 둔감했으므로 원문 geometry_v1은 보존하고 전환 시점을 유효 관측 구간 안으로 옮긴 geometry_v2를 별도 생성했다. 합성 28조건은 폐루프 주행이나 실물 센서 오차 측정이 아니다.
- 과거 무보정 실패가 있던 15 km/h에서 순간 부하 일치 대조군·순차 네 모드를 같은 GPU 렌더러로 비교 중이다. 각 실행은 원시 scan·엔코더/IMU·제어·물리 평가·정상 종료·소스 ZIP을 기록한다. 결과는 완료 후 추가하며 GitHub·upstream 게시나 컴퓨터 종료는 하지 않는다.
- 후속 완료: 15 km/h 첫 5조건은 순간/내부/이후/결합 통과, 순차 무보정 실패였다. 다섯 실행 모두 획득·보정 입력·정지·21개 하위 정상 종료를 확인했다. 무보정의 최대 중심선 오차는 34.17 cm, 내부 보정 3초 이후 RMSE는 5.13 mm였다. 같은 조향 이득·차량·추가 입력/기록 부하에서 비교했으며 특정 보정의 일반적 우월성을 확정하지 않는다. 비교 그림을 육안 확인했다.
- ROS 고장 입력 검사를 추가하면서 IMU covariance=-1 처리의 numpy.bool_가 JSON 직렬화를 실패시키는 문제를 발견했다. 기록 경계에서 Python bool로 변환하고 비유한 값은 null로 남겨 재검사 191개를 통과했다. 최초 unit_results.xml과 재통과 unit_results_v2.xml은 구분 보존한다. 15 km/h 실행 소스 ZIP은 수정 전 로그 경계를 포함하며 정상 입력의 보정 수학은 변경하지 않았다.
- 실제 15 km/h 결합 실행의 원시 센서 기록을 네 보정 모드로 재생해 각 800개 제어 시각의 처리를 통과했다. 같은 수신 시각의 callback은 순서를 알 수 없어 보수적으로 제외했다. 실물 기록이 아니고 새로운 폐루프 주행 성공도 아니다. geometry_v2의 결합 벽 RMS는 바퀴 ±5% 약 3.45 mm, 자이로 ±1°/s 약 4.92 mm, 공통 시간 ±5 ms 약 19.94~20.05 mm였으며 임의 합성 조건의 민감도로만 기록한다.
- 20 km/h 첫 비교에서는 순간 대조군도 노면 이탈했으며 기존 통과 기록을 대신 사용하지 않는다. 스캔 도착 위상·추가 센서 구독/기록·GPU 실행 조건이 과거와 완전히 같지 않으므로 차이의 원인을 보정 하나로 단정하지 않는다. 내부만 모드도 큰 이탈했으나 센서·보정 입력·정지는 정상이다. 이후/결합 및 커브 검증을 이어서 진행한다.

### LiDAR 보정 작업의 후속 검증 누적

- 독립 20회 완료: 20 km/h 첫 5모드는 결합만 주행·제동 통과, 이후만은 주행 통과·제동 노면 이탈이었다. 8 km/h 반경 1 m 커브의 다섯 모드는 모두 통과했다. 결합 직선 10·커브 5/10·직선 20 재시험도 모두 통과해 20 km/h 결합은 2/2회가 됐다. 모든 독립 실행에서 취득·보정 입력·실제 정지·21개 하위 정상 종료를 확인했고 5개 이탈 실행은 종합 실패로 보존했다.
- 촬영 옵션을 추가한 검사에서 tests 디렉터리만 실행해 196개가 통과했다. 이전 198개와 비교한 개수 차이는 차량 인터페이스의 src 하위 9개를 이번 명령에서 제외한 탓이며 테스트 삭제가 아니다. 전체 경로를 포함한 후속 재검사를 별도로 수행한다.
- 공식 코스 최초 짧은 실행은 느린 계산과 벽시계 3초 감시의 충돌로 반복 SENSOR_STOP/TOF_STALE_STOP을 보였다. 센서·물리 시각 기준을 늘리지 않고 오프라인 벽시계 감시만 선택 인수로 분리했다. 최초 실행은 5.3 sim초 부근에서 진단 중단, 부모·하위 정상 종료했으며 원문 demo_short_v1의 실패/중단 판정을 유지했다. 기본 3초, 재검사/촬영 30초를 구분한다.
- 마지막 패치의 테스트 문맥 불일치로 적용이 거부됐을 때 새 키가 어느 파일에도 들어가지 않았음을 확인하고 다시 적용했다. 공식 월드·차량·물성·보정 수학·실물 입력 시각 제한은 바꾸지 않았다. 재검사 demo_short_v2와 공식 한 바퀴 촬영을 순서대로 진행한다.
- 전체 경로 tests + src/arena_vehicle_interface/test를 포함한 최종 검사 206개가 통과했다(unit_results_v5.xml). 오프라인 벽시계 한도를 늘려도 오래된 측정 시각의 스캔에는 0 명령을 내리는 경계 검사를 추가했다. 현재 실제 렌더러도 Ogre2에서 D3D12 NVIDIA RTX 5070 Laptop으로 확인했다. WSL에는 rg가 없어 로그 조회는 grep으로 대체했다. GPU·수명 보조·GUI/깊이 해제는 적용하되 물리 궤적 변화가 있던 Bullet과 검증에 필요한 상태 발행 해제는 사용하지 않았음을 사용자에게 설명했다.

- LiDAR 후속: `demo_short_v2`는 1.01989 m·실제 정지·정상 종료를 통과했다. 순차 10 Hz·일반 20 Hz 제어·ToF 보호를 유지했고 주행 중 SENSOR_STOP 0·보정 상태 15개 거부 0·조기 출발/벽 겹침 0을 확인했다. 이어 공식 전체 한 바퀴 녹화를 hardware_target·순차10Hz·both·100Hz 제어·ToF 해제·GPU로 시작했다. 영상 취득 시각과 원본 소스를 별도 보존한다.
- 최종 촬영은 공식 본선 한 바퀴와 약 2 m 추가(48.6727 m)를 마쳤다. 실제 최고 12.3775 km/h로 요청 목표 20 km/h에는 도달하지 못했고, 주행 60.426 sim초의 시간 가중 평균은 2.8190 km/h였다. 코스 마커 네 ID·양쪽 벽 전환·조기 출발 없음·최대 중심선 거리 0.131084 m·평면 벽 겹침 표본 0을 확인했다. 기록된 보정 상태 294개는 정상이지만 launch 로그에는 짧은 WALL_LOST 두 번이 있어 상태 표본만으로 무오류를 주장하지 않는다.
- 초반 방지턱에서 최대 절대 피치 42.67°·롤 10.14°를 기록했다. 해당 영상 2.5/2.95/3.3초 프레임을 추출하고 차체가 들렸다가 회복되는 모습을 확인했다. 평면 운동 보정의 한계이며 안전한 고속 주행으로 판정하지 않는다. 사용자와 정한 다음 카메라 기반 방지턱 인식/사전 감속 검토에 이 근거를 연결했다.
- 공식 실행은 목표 이후 정지 확인 벽시계 60초 제한 초과, 이어 GPU Gazebo 종료 지연/강제 종료(-9)로 report.json의 passed:false를 유지했다. DISABLED 이후 sim시간 약 1.2초만 진행한 정황은 검사 시간 부족을 시사하지만 최종 제동 trace가 없어 실제 정지 여부는 미확인이다. 부모 반환 코드 0을 정상 종료로 잘못 처리하지 않았다. 실패를 숨기는 재실행이나 물성 완화는 하지 않았다.
- 960×540·20 fps·60.5초·1,210프레임 3인칭 영상의 디코딩과 취득 시각을 검사했다. 1배 시간 사본은 누락/유지 프레임 0이며 원본도 보존한다. 시작/중간/끝과 방지턱 장면을 육안 확인했고 마지막 신호등의 짧은 가림을 기록했다. 영상에는 최종 제동 구간이 없다. 속도/궤적 그래프도 확인했다.
- 최종 전체 검사 208개 통과(unit_results_v6.xml), 실행 23개 소스 ZIP 해시 일치, 22개 정상 종료/공식 촬영 1개 비정상 종료를 재감사했다. 세션 오류 후 저장 파일과 실행 상태를 확인해 중복 시뮬레이션 없이 후처리를 이어 갔다. 활동·실패·영상은 보존하고 인수인계와 산출물 색인을 갱신했다. 남은 시뮬레이션 프로세스 없음, GitHub 게시·컴퓨터 종료 없음.

## 실행 속도와 GPU 종료 후속 진단

- 사용자의 계속 진행 요청에 따라 원인 분리와 선택형 개선을 수행했다. 기존 코스·센서·물성·실패 기록과 전일 작업은 보존했다. GitHub 게시나 드라이버/OS 업데이트는 하지 않았다.
- Gazebo C++ 서버 계측기를 준비해 100회 준비 후 1,000회 실제 갱신을 검증했다. 차량·ROS·카메라 없는 공식 정적 코스에서 전체 6.5996초, 물리만 5.4697초, 물리 제외 1.2250초가 걸렸다. 빈 물리 월드는 0.00454초였다. 고정 1 ms 물리 간격을 유지하며 벽시계 대기만 해제했다. 시작/로드/종료는 계측에서 제외했다.
- 초기 셸 변수 전달 오류는 빈 경로 실행이므로 `.log`의 결과를 폐기 판정했다. 로그 자체는 보존했고 파일 기반 실행 및 엔티티/누적 갱신 횟수 검사를 추가했다. 설치된 Server API에 없는 WorldCount 사용으로 난 초기 빌드 오류는 EntityCount/IterationCount 검사로 바로잡았다.
- 코스 충돌 형상 3,740개를 그대로 두고 DART의 충돌 검출만 비교했다. ODE/Bullet/FCL은 5.1619/2.3412/5.0984초였으며 DART 검출기는 90초 제한 내 완료하지 못했다. 엔진 전체나 솔버를 교체하지 않았다.
- `collision_detector`와 headless 전용 `scene_broadcaster` 선택 인수를 simulation/demo에 추가했다. 기본 configured/true는 그대로다. 원본 파일은 수정하지 않고 상대 리소스 경로를 해석한 임시 사본만 만들며 종료 시 정리한다. 정답 pose를 읽는 기존 자율주행/시설/ToF 검증기에서는 상태 발행을 끄면 안 된다.
- RGB-D 848×480@30·ToF6·순간 LiDAR·GUI/녹화 없음·영상 90개(2.938 sim초) 계측 후 직진·조향·실제 정지를 같은 조건으로 비교했다. CPU 기본/Bullet/Bullet+상태 발행 제외는 0.10953/0.14302/0.13937 RTF였다. 세 실행은 센서·주행·실제 정지와 22개 자식 전부 정상 종료를 통과했다. Bullet은 약 31% 속도 개선이나 직진 거리·회전량이 달라 기본 검출기 전환은 보류했다.
- GPU+Bullet+상태 발행 제외는 0.14222 RTF로 추가 이득이 없었고, 센서/주행/정지 후 종료 실패였다. 종료 2초 후 GDB 스택은 Ogre 장면 노드 해제와 메모리 free 경로였으며 D3D12 core는 여전히 로드돼 있었다. 단일 스택이며 교착 확정은 아니다. GDB는 종료만 교란할 수 있고 영상 계측에는 개입하지 않았다.
- 종료 유예 70초(자식 SIGINT 60초)를 준 별도 짧은 GPU 진단은 첫 실행 2.019초 정상 종료, 반복은 약 65.280초 후 강제 종료였다. 후자는 디버거를 부착하지 않았다. 단순히 기본 종료 시간을 늘려 해결된 것으로 볼 수 없으며 기본 유예/렌더러는 유지했다. 반복의 준비 단계에서 자동 검사를 병행했으므로 이 진단들의 전체 실행 시간이나 서로 다른 길이의 계측 RTF를 주 비교에 혼합하지 않는다.

## 남은 사항

- 실시간 1배 달성은 미해결이다. 코스 물리 계산이 큰 비용임을 확인했으며 선택형 Bullet은 전체 시험에서 약 31% 개선했다. 기본값 전환 전에는 바퀴 접촉·제동·턱·본선 궤적 비교가 필요하다.
- GPU 종료는 간헐적이며 core 언매핑 외의 정리 경로가 남아 있다. 늦은 종료 단계의 시간별 스택과 관련 라이브러리 버전 비교가 다음 진단이다. 임의의 강제 종료를 정상으로 처리하지 않는다.
- 기존 고속·순차 LiDAR·스테레오 장시간·마커·물리 임계값 결과를 새 충돌 검출기로 승계하지 않는다.

## 시뮬레이터 GPU 마지막 추가 진단 완료

- 사용자는 로봇 영상 인식 코드와 시뮬레이터 계산을 구분한 뒤, 시뮬레이터에 남은 GPU 이득 확인·적용을 요청했다. 코드 확인상 RGB·깊이·C1 LiDAR·ToF6는 같은 렌더러 대상이며 순차 원시 광선도 이미 gpu_lidar다. 이번에 로봇 제어·영상 인식·물리 엔진은 바꾸지 않았다.
- Gazebo Rendering 8.2.3 계측기로 단순 장면의 RGB-D 30쌍·500점 LiDAR 500프레임·ToF6 각 15프레임을 CPU/GPU 2회씩 비교했다. 프레임 수·크기·RGB 중앙색·거리 약 2.5 m·정상 종료와 실제 렌더러를 확인했고 시간은 각각 약 24/39/24% 감소했다. 공식 코스/ROS/물리 RTF가 아니며 각 센서 별도 갱신 값을 합산하지 않는다.
- EGL `headless=1`을 실제 적용한 센서 시험은 D3D12/NVIDIA·EGL 시작·출력·정상 종료를 확인했지만 RGB-D 0.805초로 기존 GPU GLX 평균 0.808초와 같았다. 속도 개선으로 운영 옵션에 추가하지 않았고 실제 Gazebo 종료 버그 해결로 판정하지 않았다.
- 기존 독립 LiDAR 시험기에 `--render-backend`만 추가 연결해 5 km/h 직선·10 Hz 순차·500 Hz 원시·8초 주행/정지를 비교했다. CPU 161.701초/GPU 108.582초로 준비·종료 포함 전체 약 32.9% 감소였다. 양쪽 취득·주행·정지·21/21 자식 종료 통과, 최대 시간 오차 약 1.8 ms·원시 공백 폐기 0회·100 Hz 제어를 유지했다. 시험장의 형상 해시와 물리/제어 소스 해시는 같고, 공식 코스·Bullet 비교와 혼합하지 않는다.
- 이번 GPU 실제 실행은 1회 통과다. 과거 종료 실패를 삭제하거나 안정성 해결로 승격하지 않았다. 전역 `system` 기본은 유지하되 고부하 순차 실험에서 선택형 GPU를 활용할 근거를 확보했다. GPU 관련 추가 대규모 이식은 멈추고 알고리즘/보정 실험을 우선하는 것으로 후속 권고를 정리했다.
- 센서 단독 13회와 실제 주행 2회 원문·재현 코드·집계/해시는 `artifacts/validation/2026-09-08/gpu_final/`에 보존했다. 최초 빌드 경로의 상위 폴더 오류는 센서 실행 전 수정했다. Python 관련 검사 19개를 통과했다. [최종 진단](../simulation/GPU_FINAL_DIAGNOSTIC_2026_09_08.md)을 작성했다.
