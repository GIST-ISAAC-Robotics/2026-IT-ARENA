# 2026-09-06 활동 기록

## C1급 순차 회전 취득과 속도 비교

- 9월 5일 사용자의 요청을 이어서 10 Hz·500점의 순차 회전 라이다 어댑터를 구현했다. 회전 중 실제 시각별 Gazebo 광선 계산 결과를 모으고, 첫 광선 시각·점 간격·원시 프레임 오차를 기록한다. 기존 순간 스캔 기본값은 보존했다.
- 같은 고빈도 원시 광선 부하를 사용하는 순간 스캔 대조군 `snapshot_matched`를 추가했다. 제어기에는 `/scan`만 전달하며 정답 위치는 시험 관측에만 사용한다.
- 자동 검사 165개가 통과했다. 초기 1000 Hz 원시 프레임의 5 km/h 순차 직선 주행은 목표 속도 유지·노면 이탈 없음·실제 정지·21개 자식 프로세스 정상 종료를 통과했다. 초기 실행 소스의 해시와 실행 결과는 9월 5일 산출물에 보존했다.
- 500 Hz 원시 프레임의 부하 일치 비교를 별도 폴더 `artifacts/validation/2026-09-06/rotating_lidar/matched_matrix_v1/`에서 진행한다. 직선 5/10/15/20 km/h와 반경 1 m 커브 5/8/10 km/h가 대상이다. 일반 데모 속도 제한·ToF 보호는 독립 시험에서만 해제한다.
- 이 시험을 공식 코스 완주·실차 C1의 최대속도·다중 차량 안전으로 확대하지 않는다. 보고서에는 순차 취득·무보정 제어·물성·제동 실패를 구분한다. 기존 예산 문서·엑셀과 모든 활동 기록을 보존한다.
- 원문 집계기의 `elapsed < 8` 조건이 조기 중단 후 제동 표본도 주행 통계에 넣는 문제를 확인했다. 최종 집계에서 `phase == running`을 추가하고 회귀 검사를 보완한다. 최초 `report.json`·`summary.json`·원시 trace는 보존하고, 표에는 별도 `phase_audit.json` 재집계를 사용한다. 센서·조향·물리 구현은 이 집계 수정으로 바꾸지 않는다.
- 완료: 본 비교 14회와 직선 15 km/h 추가 비교 2회. 순간은 직선 5/10/15/20·반경 1 m 커브 5/8/10 통과, 순차는 직선 5/10·커브 5/8/10 통과·직선 15/20 실패였다. 15 km/h 재시험도 같은 판정으로 순간 2/2 통과·순차 0/2 통과였다. 16회 모두 센서 취득·실제 정지·정상 종료를 확인했다. 원시 시간 근사 최대 1.8 ms, 원시 공백 폐기 0회였다.
- 집계 수정 후 165개 자동 검사를 재통과했고, 14회의 통과·실패 판정은 바뀌지 않았다. 본 비교 당시 검사기 전체 파일을 해시와 함께 보존했다. 회의용 한국어 요약과 모든 조건의 한국어 그래프를 만들고 15 km/h 그림을 육안 확인했다. `git diff --check`는 통과했다. 주최 측 게시·GitHub 반영·컴퓨터 종료는 하지 않았다.

## 센서 거리·FPS 상세화와 RGB 주행 예산 재검토

- 9월5일 시작한 사용자 요청을 자정 이후 마무리했다. 엑셀 스테레오10종의 거리·해상도별최소거리, 깊이/RGB 각각 최대해상도에서fps와최대fps에서해상도를 정리했다. 제조사 PDF와 현행 센서 드라이버·벤치 자료를 대조하고 조건·출처를 각 행에 남겼다.
- D436 RGB 최대1280×800의fps는 상품·상세표 불일치로 미확인 표시했다. 상세 RGB1280×720@30/848×480@60,335L의깊이848×480 최소34cm와D43619.5cm, D455RGB640×360@90, 좁은848×100특수 깊이 모드를 보완했다. OAK센서 입력과깊이출력을 구분하고 미공개 최대값을 추측하지 않았다.
- 후속 사용자의RGB 메인 주행 아이디어를 반영해 깊이카메라를 필수 전제로 둔 추천을 수정했다. RGB로노면·경로, 별도 거리센서로근접 간격을 감시하는 구조를 검토한다. 마커 가림·차량 전체외곽·전방 거리·반응시간은 별도 조건이다.
- 최종 수량은LiDAR포함ToF0, LiDAR없는RGB/스테레오ToF4이다. RGB+ToF4두 안과D436+S3 20Hz를 추가해20개 구성으로 갱신했다. 기존 단가·차체 가정·부자재/예비비 제외를 유지했다.
- C1+RGB는OV2710기준162,360원, B0385기준195,360원이다. RGB+ToF4는각204,160/237,160원으로같은RGB에서C1안이41,800원낮다. OV2710의720p60미확인/B0385국내품절조건을유지했다.

## 회전식 라이다 보정 자료 조사와 다음 구현 준비

- 사용자 요청에 따라 내부 deskew와 스캔 이후 이동 보정의 관계를 공식 자료로 다시 확인하고 [구현 준비 문서](../sensors/ROTATING_LIDAR_COMPENSATION_RESEARCH.md)를 작성했다. 공통 시간 예제·좌표 변환식·센서 입력·재사용 코드·오차 경계·네 가지 보정 조합의 비교 계획을 정리했다. 같은 궤적에서는 두 단계 변환과 점별 시각→현재 직접 변환이 같으며, 한 보정의 성능 우위를 검증한 것은 아니라고 명시했다.
- ROS `LaserScan`, SLAMTEC C1·공식 ROS 드라이버/SDK, `laser_geometry`, Nav2 Jazzy, `robot_localization`, LIO-SAM·FAST-LIO의 유지관리자/저자 자료를 대조했다. 드라이버·SDK와 주요 참고 구현은 커밋을 고정했다. 일부 ROS 문서 접근 제한은 공개 소스로 대체했고, 검색 캐시와 실제 브랜치 불일치는 실제 조회 가능한 고정 소스로 재확인했다.
- C1의 `angle_compensate`가 운동 보정이 아닌 각도 격자 배치·복제이며, 각도 정렬·출력 반전·호스트 시각 처리 때문에 점별 시간과 배열 대응을 실물에서 먼저 확인해야 함을 기록했다. SDK의 timestamp/부분 스캔 API 존재와 C1의 하드웨어 시각 지원·정확도 미확인을 구분했다. 실물 버그 확정이나 upstream 신고는 하지 않았다.
- 로컬 엔코더·IMU·구동 소스를 읽어 `/wheel_states`의 취득 시각, 헤더 없는 tick 토픽, `/odom`의 이상적 관절 적분 경로를 구분했다. 양자화 엔코더+자이로의 짧은 이동 버퍼부터 권고하되 별도 IMU 필요 여부·장착 오프셋·시계·슬립·방지턱·상대차 운동의 한계를 함께 남겼다.
- 기존 순차 속도 시험과 운동 보상 설명, 프로젝트 현황·인수인계 규칙에 조사 문서를 연결했다. 기존 활동·실패·주행 결과·예산 작업은 보존했다. 이번 작업은 문서만 변경했으며 보정 코드 작성·시뮬레이션/주행 재실행·구매·GitHub 반영·컴퓨터 종료는 하지 않았다.
- 문서 검토: 관련 Markdown 6개의 로컬 링크 86개는 모두 대상을 확인했고 깨진 링크·문자 대체 기호는 없었다. `git diff --check`를 통과했으며 예시 오차 2.78/3.49/5.56 cm를 다시 계산했다. 코드·주행 검사를 이번에 재통과한 것으로 기록하지 않는다.
