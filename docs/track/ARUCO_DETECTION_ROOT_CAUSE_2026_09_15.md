# 거리별 ArUco 검출 누락의 내부 원인 추적

검사일: 2026-09-15. 대상: 공식 `v2026.09.14`, OpenCV 4.6.0, 기존 차량 상당 RGB 정지 표본.

## 결론

**2 m에서 검출되고 1.5·1.2 m에서 사라졌다가 1 m에서 다시 검출되는 주요 현상은, 읽을 수 있는 마커 후보를 중복 후보 제거 단계에서 버린 결과였습니다.** 저장 영상 자체에는 해당 ID를 해독할 정보가 있었습니다. 이번에는 후보 좌표만 비교한 추측이 아니라, 설치 버전과 같은 검출기 내부 함수를 별도로 추적했습니다.

다만 3 m의 일부 실패와 0.75 m의 시야 밖 문제까지 같은 원인으로 설명하지 않습니다. 이번 검사는 저장 사진의 인식 과정이며 실물 출력물·D435i 주행 영상의 성능 검증이 아닙니다.

## 검증 방법과 범위

- 공식 원본 `raw_route`, 지지대 포함 PNG `face_compare_pbr`, 같은 조건의 도형 앞면 `face_compare_cells` 사진을 사용했습니다. 각 24개 시야, 후보 거리 기준 0.05/0.02로 총 **144개 조건**입니다. 기존 실패·사진·회신 표는 덮어쓰지 않았습니다.
- [OpenCV 4.6.0 공식 소스](https://github.com/opencv/opencv_contrib/blob/4.6.0/modules/aruco/src/aruco.cpp)의 후보 생성·그룹화·비트 추출·해독 함수를 별도 실행 파일로 구성했습니다. 그룹 구성 기록만 추가했으며 설치 OpenCV와 주행 노드는 수정하지 않았습니다.
- 내부 추적 결과와 설치된 `cv::aruco::detectMarkers`의 최종 ID 목록은 **144/144 일치**했습니다. 중복 ID도 포함해 비교했습니다.
- 그룹화 전의 각 후보에도 동일한 해독 함수를 독립 적용했습니다. 이는 실제 검출기의 처리 순서를 바꾼 운영 패치가 아니라, 버려진 후보가 유효했는지 확인하는 진단입니다.
- 소스 SHA-256: `54216287d5bd7eea843d3d02c55d27f576967dee6e0767f3933de4ab2c23283c`. [전체 추적](../../artifacts/validation/2026-09-15/official_update/aruco_internal_trace.json)과 [집계](../../artifacts/validation/2026-09-15/official_update/aruco_internal_summary.json)를 보존했습니다.

## 실제로 누락되는 순서

1. 검출기는 영상의 밝기를 흑백으로 나눌 때 기본 3·13·23픽셀 크기의 주변 영역을 각각 사용합니다. 여러 크기로 처리해 사각형 후보를 모읍니다.
2. 같은 마커의 비슷한 윤곽이 여러 번 검출될 수 있으므로, 가까운 후보를 같은 그룹으로 묶습니다. 여기서 `minMarkerDistanceRate`를 사용합니다.
3. 현재 기본 설정에서는 **그룹에서 면적이 가장 큰 후보만** 다음 해독 단계로 보냅니다. 아직 ID를 읽기 전의 선택입니다.
4. 중간 거리의 일부 사진에서는 올바른 검은 코드 윤곽과 판 외곽 또는 그 주변의 부풀어진 잘못된 윤곽이 같은 그룹에 들어갔습니다.
5. 큰 잘못된 후보가 남고 정답 후보가 버려졌습니다. 남은 후보는 검은 테두리 검사에서 탈락했으며, 버린 작은 후보를 다시 시도하지 않아 최종 결과가 미검출이 됐습니다.

이는 물리적인 판이 마커를 가린 상황과 다릅니다. 같은 사진에서 버려진 후보를 해독하면 정답 ID가 나오는 것으로 구별했습니다.

### 공식 원본 ID 30의 사례

거리는 카메라에서 판까지의 직선거리가 아니라 **중심선상 마커 위치까지의 진행 거리**입니다.

| 진행 거리 | 그룹화 전 정답 후보 | 기본 그룹화 이후 | 최종 결과 |
|---|---|---|---|
| 2.0 m | 존재, 3픽셀 처리에서 생성 | 정답 후보가 별도 그룹으로 보존 | ID 30 |
| 1.5 m | 존재, 13픽셀 처리의 후보 2·3 | 판 외곽 후보와 묶여 후보 6만 보존 | 미검출 |
| 1.2 m | 존재, 후보 2 | 더 큰 후보 6만 보존 | 미검출 |
| 1.0 m | 존재, 13픽셀 처리의 후보 4 | 정답 후보가 별도 그룹으로 보존 | ID 30 |

1.5 m에서 정답 후보 2의 면적은 769.5 px², 실제 선택된 후보 6은 1,700 px²였습니다. 선택된 후보는 검은 테두리 20칸이 잘못 읽혀 허용 5칸을 초과했습니다. 정답 후보 2는 테두리 오류 0으로 ID 30을 읽었습니다. 여기서 20칸은 내부 데이터의 오인식 개수가 아니라 **6×6 배열의 바깥 테두리 전체**입니다.

ID 0 등에서는 판 전체 외곽이 아니라 약간 부풀어진 후보의 테두리 오류 6·8칸으로 탈락한 사례도 있었습니다. 모든 실패를 똑같은 회색 판 사각형이라고 단정하지 않습니다.

## 왜 거리에 따라 다시 좋아지는가

카메라에 투영된 크기·각도는 거리별로 바뀌지만, 기본 밝기 구분 영역은 3·13·23픽셀로 고정됩니다. 따라서 가까워질수록 후보가 단순히 확대되는 것이 아니라, 나타나는 윤곽의 종류와 그룹 구성도 바뀝니다. 실제 ID 30 추적에서는 2 m의 작은 영역에서 읽힌 코드, 1.5 m의 코드/외곽 혼합 그룹, 1 m의 다시 분리된 코드 후보를 확인했습니다.

따라서 이 결과는 “더 가까우면 항상 더 잘 읽힌다”는 단순한 거리 한계가 아닙니다. **영상의 명암·픽셀 크기와 검출기 후보 선택의 상호작용**입니다. 렌더링이 윤곽 형성에 영향을 주지만, PNG 손상이나 텍스처 미표시가 직접 원인이라는 증거는 아닙니다.

## PNG와 도형 결과의 관계

| 사진 집합 | 기본 검출 | 기본 미검출 중 정답 후보가 그룹화로 탈락한 표본 |
|---|---:|---:|
| 공식 원본 PNG | 10/24 | 7개 — 1.2·1.5 m의 실패 전부 |
| 지지대 포함 PNG | 9/24 | 8개 — 네 ID의 1.2·1.5 m |
| 지지대 포함 도형 | 15/24 | 4개 — ID 20/30의 1.2·1.5 m |

도형은 재질·명암·픽셀 경계가 달라져 일부 후보 구성을 바꾸었지만, 같은 중간 거리 문제가 남았습니다. 따라서 “PNG를 도형으로 바꾸면 원인이 제거된다”는 설명은 옳지 않습니다. 지지대가 없는 공식 원본에서도 재현되므로 임시 지지대가 이 현상 전체를 새로 만든 것도 아닙니다.

## 해결 후보와 회신에 사용할 수 있는 범위

- **우선 후보:** 공식 PNG와 위치를 유지하고 `minMarkerDistanceRate=0.02`를 시험합니다. 이는 ID 해독 신뢰도를 낮추는 것이 아니라, 서로 다른 윤곽을 같은 후보로 합치는 범위를 줄이는 설정입니다. 같은 저장 영상에서 공식 원본/지지대 PNG는 17/24, 도형은 19/24로 개선됐습니다.
- 단점은 같은 ID의 중복 후보가 남을 수 있다는 점입니다. 현재 ID 존재 여부만 사용하는 분기 판단은 중복의 영향이 작지만, 향후 위치 추정·개수 세기에는 중복 정리가 필요합니다. 오검출률·영상 연속성·실시간 부하는 별도 검증입니다.
- 다음 후보는 밝기 구분 영역 조합, 최신 검출기의 후보 처리 방식 비교입니다. 아직 시험하지 않았으므로 해결됐다고 쓰지 않습니다.
- 도형 앞면은 렌더링 대조군으로 보존합니다. 인식률이 좋아졌다는 이유만으로 실물에 더 가깝다고 판단하지 않습니다.

회신에서는 “현재 OpenCV 4.6 기본값에서 중간 거리의 유효 코드 후보가 잘못 묶여 탈락했고, 후보 그룹 기준 조정으로 회복했다”까지 설명할 수 있습니다. **공식 PNG 불량·실제 설치 각도 불량·실물 인식 거리의 증거로 확대하지 않습니다.** 이번 작업에서는 기존 회신 초안과 운영 검출기를 변경하지 않았으며 외부 게시하지 않았습니다.
