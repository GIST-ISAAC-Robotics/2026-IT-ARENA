20×15 cm 외형과 보수적 조향 점유 외형의 본선·분기·그리드 정적 표본 검사도 통과했습니다. 이는 정적 벽/시설 평면 간섭 검사이며 연속 주행·급커브 조향 가능성·높이 제한 없는 모든 상대차의 통과 보장이 아닙니다. 기존 급커브 최소반경 약 0.2987 m는 그대로이며 새 결함으로 분류하지 않습니다.

## 3. 실제 렌더링과 마커 검출

환경: WSL Ubuntu 24.04·ROS 2 Jazzy·Gazebo Harmonic·Ogre2 소프트웨어 렌더링·OpenCV 4.6.0. GUI 창의 단순 외관 확인이 아니라 Sensors가 생성한 RGB를 ROS bridge로 수신했습니다.

- 원본 정면: 마커 중심 높이·정면 35 cm, 640×480·수평 화각 0.65 rad. 카메라마다 3프레임을 수신했고 마지막 저장 영상에서 ID가 각각 일치했습니다. 물리 켠 상태, 두 프로세스 정상 종료.
- 차량 상당 시야: 높이 0.078 m, 전방 오프셋 0.055 m, 848×480·수평 69.4°·수직 42.5°, 수평 pitch. 본선 중심선을 보간한 3/2/1.5/1.2/1/.75 m 전방 각 24개 **정지** 표본. 주행 동역학·차체 가림·모션 블러는 제외했습니다.
- 원본 기본 검출: ID 0/30/45는 2 m·1 m, ID 20은 3/2/1.5/1 m에서 검출. 전체 10/24. [회신 초안 표](ISSUE_12_REPLY_DRAFT_2026_09_15.md)에 전 표본을 기재했습니다. 시간상 3프레임 모두 같은 판정이며 공간적 연속 검출 구간을 실측한 것은 아닙니다.
- 임시 신호등을 그대로 겹친 최초 실행본은 ID 0 전체 미검출. 가로대 가림을 사진에서 확인했습니다. 신호등 0.60 m 이동 후 원본과 같은 10/24·ID 0 2 m/1 m 검출로 복구됐습니다. 이 문제는 **팀 임시 시설 결합 문제**이며 upstream 마커 버그가 아닙니다.
- 같은 최종 RGB의 출발 슬롯 6개 모두 기존 `StartSignal`이 빨강을 인식했고 시작 상태는 false였습니다. 정지 빨강 표본을 반복 입력한 확인이며 실제 녹색 전환·자율 출발 완료 시험은 아닙니다.

### 원본을 고치지 않는 해결 후보

같은 저장 영상에서 OpenCV `minMarkerDistanceRate=0.05`→`0.02`만 변경하면 원본·임시 신호 이동본 모두 목표 ID 검출이 **10/24→17/24**로 늘었습니다. 네 ID의 2/1.5/1.2/1 m 표본과 ID 20의 3 m 표본이 검출됐습니다. 운영 `marker_ids()`는 기본 설정을 유지했습니다.

이 매개변수는 가까운 사각형 후보를 묶는 기준이며 4.6.0 기본값은 0.05입니다. 공식 소스는 묶인 후보의 큰 윤곽을 선택하므로, 보이는 판 외곽과 코드 윤곽의 경쟁이 일부 누락 원인이라는 **추론**과 이번 단일 변수 비교가 일치합니다. 모든 실패의 원인을 증명한 것은 아닙니다. [OpenCV 4.6.0 소스](https://github.com/opencv/opencv_contrib/blob/4.6.0/modules/aruco/src/aruco.cpp#L268-L378).

| 후보 | 얻은 근거·장점 | 남는 검증 |
|---|---|---|
| 검출기 후보 거리 기준 조정 | 마커 수정 없이 보존 사진 17/24 검출 | 중복 ID 후보 발생. 코너/ID 중복 제거·오검출·여러 마커 동시 관측·실물/주행 검증 |
| 카메라 상향 pitch 또는 장착 높이 조정 | 근거리 상단 이탈 완화 가능 | 이번에는 운영 차량 변경 안 함. 지면/신호등/깊이 사각과 함께 비교 필요 |
| 시간적 추적과 분기 상태 유지 | 한 프레임 미검출로 벽 선택이 흔들리는 것을 줄일 수 있음 | 다른 구간 마커의 조기 노출·가림·오인식 시 안전 정책 필요 |
| 실물 인쇄 표본 시험 | 실제 반사·노출·조명에서 확인 가능 | 카메라·인쇄물·실측 환경 필요. 이번 결과로 대체 불가 |

0.75 m의 상단 시야 이탈은 기하적 문제입니다. 반대로 1.2~1.5 m에는 화면에 판이 있는데 검출기가 놓친 표본이 있습니다. 이를 모두 시야각 문제나 모두 주최 측 모델 오류로 뭉뚱그리지 않습니다. 3 m에서 미검출인 ID도 있어 이 결과를 장거리 고속 인식 해결로 쓰지 않습니다.

ID 0·45가 함께 보이는 정지 표본도 있습니다. 실제 코드가 같은 ID를 중복 반환하거나 다른 구간을 먼저 볼 수 있으므로 추후 랩/분기 상태기는 단순 발견 순서만으로 구현하지 않는 편이 좋습니다. 현재 벽 추종기에서 두 ID는 모두 왼쪽 벽 선택이므로 이것만으로 현재 조향 실패가 증명된 것은 아닙니다.

## 4. 실패·경고 및 짧은 차량 시험

- 원본 24카메라 거리 촬영은 완료했으나 Gazebo 종료가 지연되어 SIGKILL(-9)이 필요했습니다. 원본 정면 검사·신호 이동 전후 실행본 거리 촬영은 정상 종료했습니다. 기존의 종료 불안정과 같은 증상이지만 내부 원인을 이번에 확정한 것은 아닙니다.
- 카메라 렌더링 시 Ogre2 예약 visibility-mask 비트 경고가 발생했습니다. 실제 영상 수신·ID 검출은 됐으며 이를 텍스처 로드 실패로 분류하지 않습니다. 무경고 검사라고도 쓰지 않습니다.
- 최초 회귀 검사 200개 중 199개 통과·1개 실패: 이전 마커 브래킷 8개 제거로 충돌체 3,740→3,732개가 되어 기존 고정 개수 검사가 실패했습니다. 변환 전후 형상 비교는 유지하고 현재 기대 개수만 갱신했습니다.
- 초기 전체 colcon 탐색이 로컬 성능 진단 패키지 2개까지 찾아 총 7개를 빌드했고 이 둘에 install-target 경고가 있었습니다. 대회용 패키지는 `--base-paths src`로 5개만 명시해 다시 검사합니다. 기록을 삭제하거나 진단 패키지를 대회 기능으로 세지 않습니다.
- 신호 이동 후 짧은 차량 시험: RGB/깊이 848×480·30.303 sim Hz, ToF6 8×8·15.152 sim Hz, 엔코더·IMU 수신, 직진 약 0.23065 m·조향 변화 0.18914 rad, 명령 중단 정지 명령·odom 약 0.000003934 m/s를 확인했습니다. **Gazebo 종료 -9로 종합 실패**입니다. 이 시험의 odom 정지 관측을 차체 지면 정답 속도 정지 검증으로 부풀리지 않습니다.
- 현물·고속·자율 한 바퀴/5랩·상대차·방지턱 완주 시험은 이번에 하지 않았습니다. 기존 9/8 영상의 실패 판정도 보존합니다.

## 5. 최종 인수인계

후속 사용자 요청의 지지 구조는 위 공식 원본 검사를 마친 후 **별도 팀 임시 링크**로 추가했습니다. 기둥 폭 20 mm·중심 횡방향 ±30 cm, 상부 빔 높이 52 cm·폭 22 mm, 연결대 폭 10 mm입니다. 공식 마커 원본 링크 비교는 추가 후에도 통과했습니다.

ID 30의 오른쪽(-local Y) 기둥은 지름길 1의 11표본을 막아 최초 생성이 거부됐습니다. 해당 기둥을 생략한 한쪽 지지형으로 수정한 뒤 20×15 cm·조향 점유 외형의 본선 2,332·분기 155/141·그리드 6표본을 통과했습니다. 새 충돌체는 총 3,759개입니다. 상부 빔·연결대는 인쇄판 정면을 덮지 않으며, 실제 지지 강도/실물 시공은 검증하지 않았습니다.

최종 기본 검출은 **9/24**로, 지지대 없는 임시 신호 이동본의 10/24에서 ID 20의 1.5 m 표본 한 개가 미검출로 바뀌었습니다. 같은 이미지의 0.02 후보는 17/24, 출발 슬롯 6개 빨강 인식은 유지했습니다. 공식 원본 회신 표에는 지지대 없는 10/24 결과를 사용하며 팀 구조가 추가된 영상을 원본 증거로 혼합하지 않습니다. 최종 거리 촬영은 정상 종료했습니다.

최종 ROS 프로젝트 5개 빌드·Python/ROS **210개 통과**, 엄격 SDF·공식 및 실험 해시 검사를 통과했습니다. 기존 실험 월드 형상은 동일하며 공유 생성기 해시 메타데이터만 갱신했습니다. 짧은 스모크의 종료 실패는 지지대 추가 이전 시험이며, 이 최종 자동 검사로 정상 종료 문제를 해결했다고 보지 않습니다.

전체 코스 정수직·네 방향 사선과 ID 20/30 지지대 상세, **7장 촬영을 완료**했습니다. 이 촬영도 마지막 서버 종료에 -9가 필요했고 잔존 시험 프로세스는 없었습니다. 사진을 확보했다는 사실과 종료 성공은 분리합니다. 카메라별 3프레임 이상 수신과 PNG 해시를 `final_overview/report.json`에 보존했습니다.
