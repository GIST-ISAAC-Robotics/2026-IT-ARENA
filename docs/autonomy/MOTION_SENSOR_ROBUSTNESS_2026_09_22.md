# IMU·엔코더·시간 정렬 내성: 1차 구현·시험

날짜: 2026-09-22. 상태: **1차 구현·11조건 시험 완료**. 회귀 302개 통과. 결과는 실물 사양/안전 보장이 아니라 아래 합성 오류 조건의 시뮬레이션 근거다.

## 범위와 유지 조건

사용자 요청에 따라 LiDAR 거리 오차 다음으로 운동 보정 입력의 오차를 검사한다. B0183+C1·별도 6축 IMU 후보·후륜 엔코더, v8 지역 Pure Pursuit와 독립 LiDAR 보호층, 명령 상한 9 km/h를 유지한다. Jetson 성능 검증·장착 변경·방지턱·다중 차량·고속화는 이번 범위 밖이다. **엔코더 분해능과 통신 주기는 사용자에게 재확인했으며 아직 미정**이다.

첫 범위는 자이로 z축 고정 편향, 양쪽 후륜 속도 환산의 공통 배율, 전송 지연, 서로 반대인 취득 시각 오류, 주행 중 2초 누락/일시 지연이다. 값 고착·온도에 따른 편향 변화·좌우 서로 다른 펄스 손실·MCU 시계 장기 드리프트·자동 교정은 이번에 구현 완료로 취급하지 않는다.

## 시험 전용 중계 방식

`motion_test_profile`이 비어 있으면 기존 입력 경로를 그대로 쓴다. 값을 지정한 `local_pursuit`에서만 다음 경로로 바꾼다.

```text
기존 IMU ─→ /test/raw_imu ────┐
                              ├─ 오류 중계기 ─→ /imu/data, /wheel_states
기존 엔코더 → /test/raw_wheels ┘                       ├→ 지역 제어기
                                                     └→ 독립 보호층
```

- 기존 IMU 잡음·엔코더 양자화와 지연은 유지하고 그 출력에 오류를 더한다. 기존 LiDAR 거리오차와 결합할 수도 있다.
- 자이로는 정렬된 가상 IMU의 z각속도에 `측정값 × scale + bias`를 적용한다. 가상 자세·가속도를 보정에 쓰지 않는다. 엔코더는 이름으로 선택한 두 후륜의 각속도/회전각에 공통 배율을 적용한다. 이는 환산 오류의 시험용 근사이며 실제 펄스 손실 모델은 아니다. `/wheel_encoder_ticks`는 기존 진단 원시값으로 남으며 제어 입력이 아니다.
- 전송 지연은 **중계기 수신 뒤 추가 대기**다. 원래 취득 시각을 보존하며, `stamp_offset_s`를 지정한 경우만 의도적으로 잘못된 취득 시각을 만든다. 추가 지연과 시각 오류는 다른 조건이다.
- 시간 구간은 시뮬레이션 절대 시각 `[start_s, end_s)`이다. 같은 스트림은 FIFO를 유지한다. 지연 구간 종료 때 대기 중인 과거 패킷 때문에 이후 패킷도 잠시 기다릴 수 있으므로 실제 방출 시각을 기록한다.
- 시험기의 참 오류값은 제어기의 교정 매개변수에 넘기지 않는다. 원시/오류 입력이 공개 토픽에 동시에 발행되지 않는지 실제 ROS 발행자 목록을 검사한다.
- `motion_injection.jsonl`에 원 취득/수신/주장 취득/방출 시각, 전후 값, 누락과 종료를 기록한다. 사후 감사에서 실제 값 변환·지연·순서·두 스트림 존재·구간 적용을 대조한다. 정답 자세는 평가기에만 있다.
- 구현: `motion_impairment.py`, `motion_fault_relay.py`, `scripts/motion_fault_audit.py`. 시험 실행/집계는 `run_motion_robustness.py`, `summarize_motion_robustness.py`다.

## 사전에 정한 실행과 판정

실제 센서 사양이나 측정된 오류 분포가 아니라 **설계 민감도용 조건**이다. ±1°/s·±5%·±5 ms는 9/8 합성 계산과 연결하기 위한 출발점이다.

| 조건 | 범위 |
|---|---|
| 오류 없는 중계 대조군 | 12 m·실제 정지·정상 종료 |
| 자이로 +1 / −1°/s | 각각 같은 12 m |
| 후륜 환산 +5 / −5% | 각각 같은 12 m |
| IMU·휠 각각 15 ms 추가 전송 지연 | 12 m; 기존 엔코더 2 ms와 별도 |
| IMU −5 ms / 휠 +5 ms 취득 시각 오류 | 12 m; 정확한 시각을 아는 지연 모델과 구분 |
| IMU 또는 휠 패킷 누락 | 각각 시뮬레이션 8~10초, 그 전후의 주행·정지·복구 |
| IMU 80 ms 일시 전송 지연 | 8~10초, 그 전후의 주행·정지·복구 |
| 대표 결합 조건 | 단일 조건 확인 후 한 바퀴. 자이로 +1°/s, 휠 −5%, 각 10±3 ms 지연, IMU 시각 −5 ms, C1 균일 ±3 cm |

기본 판정은 기존 검사의 입력 계약·신호 출발·요청 거리·실제 정지·정상 종료, 벽 겹침/도로 밖 차체 면적 표본 0이다. 모든 실행은 원본 보고서와 당시 소스 ZIP을 남기며 실패한 조건 뒤에는 자동으로 다음 시험을 진행하지 않는다. 12 m를 모든 코너/완주/실물 안전으로 표현하지 않는다.

주행 중 고장 조건은 별도로 **고장 직전 실제 속도 >0.3 m/s**, 고장 이후 0.25초 이내 보호층의 `motion_stale`/`motion_gap`·0 명령 관측, 고장 구간 중 실제 속도 <0.01 m/s를 0.3초 이상 유지, 복구 후 이동 재개·1 m 이상 진행을 요구한다. 이 수치는 이번 진단 기준이지 실차 안전 한계가 아니다. 약 10 Hz 자세/상태 표본에서 구하므로 응답 시각·거리에는 한 표본 정도의 불확실성이 있다. 0 명령만 나왔거나 처음부터 정지해 있던 경우는 동적 제동 성공으로 세지 않는다.

### 주행 중 입력 이상·복구

`stage_b` 시작 전 전체 회귀 **302개 통과(16.53초)**. 추가 5개는 0 명령만으로 실제 정지로 판정하거나 출발 전 정지를 동적 제동으로 오인하지 않는 집계 검사다.

| 조건(시각 8~10초) | 직전 속도 km/h | 보호층 0 명령 첫 관측 | 안정 정지 시작 관측 | 표본 이동거리 m | 복구 후 재주행 |
|---|---:|---:|---:|---:|---|
| IMU 2초 누락 | 8.03 | 0.087초 후 | 0.899초 후 | 0.875 | 통과 |
| 엔코더 2초 누락 | 7.98 | 0.090초 후 | 0.999초 후 | 0.898 | 통과 |
| IMU 추가 지연 80 ms | 5.10 | 0.091초 후 | 0.698초 후 | 0.419 | 통과 |

IMU 500개·엔코더 200개가 지정한 구간에서 실제로 누락됐고, 입력 복구 후 주행을 재개했다. 누락 실행은 각각 최종 12.1585/12.0585 m 진행, 최종 실제 정지·정상 종료·잔존 없음, 주행/정지 벽 겹침·노면 이탈 표본 0이다. 누락 종료 직후에는 과거 공백이 포함된 스캔이 잠시 `motion_gap`으로 차단되고, 충분한 새 이력이 쌓이면 재개한다.

80 ms 조건은 IMU 500개에 실제 지연이 적용됐으며, 최종 12.0585 m 진행·실제 정지·정상 종료·벽/노면 이탈 표본 0을 통과했다. 구간 시작은 절대 시각으로 고정했지만 실행별 출발/주행 시점 차이 때문에 직전 속도는 서로 다르다. 따라서 80 ms 지연의 제동거리가 더 짧았다는 수치를 누락보다 안전하다는 비교로 해석하지 않는다.

시간은 약 10 Hz 평가 표본에서 **고장 구간 시작 시각**을 뺀 값이다. 마지막 고장 직전 자세 표본부터 안정 정지 시작 표본까지의 이동거리를 합산했으므로 고장 직전 최대 한 표본 구간도 포함된다. 센서·보호 상태 수신의 비동기성과 약 한 표본의 오차가 있으며 정밀 실차 제동거리로 해석하지 않는다. 안정 정지는 속도 1 cm/s 미만을 0.3초 이상 유지하는 조건이다.

입력 이상을 감지하고 0 명령을 내리는 것과 차체 정지는 다르다. 약 0.9 m라는 거리는 현재 임시 물성/모터 제어의 결과다. 실물 제동을 측정하기 전에는 이 수치를 안전 여유의 보장값으로 쓰지 않는다.

### 완료 판정

기본 7조건 + 동적 고장 3조건 + 복합 한 바퀴 **11/11회 통과**. 각 조건 1회이며 반복 seed·다른 출발 위치·모든 오차 조합을 포괄하지 않는다. 이번 1차 범위에서는 제어기를 수정해야 할 실패가 재현되지 않아 **v8 경로 제어·운동 보정·독립 보호층·속도 및 안전 한도를 그대로 유지**했다. 실제 동작이 부족한데 제한을 느슨하게 만든 작업이 아니다.

새 산출물은 오류 중계기·시험 프로필·주입/정지/복구 감사·재현 실행기·회귀 검사다. [근거 폴더 안내](../../artifacts/validation/2026-09-22/motion_robustness/README.md)에 실행과 판독 순서를 남겼다. 원본 월드·차량 설정과 모든 실행의 제어기 해시가 동일함을 대조했다. 기록은 로컬에 보존했으며 GitHub 게시·영상 녹화·컴퓨터 종료는 하지 않았다.

## 제한과 후속

엔코더 오류를 넣는 지점은 ROS의 `/wheel_states`다. 따라서 LiDAR 운동 보정, 지역 Pure Pursuit의 속도 기반 목표점 계산, 독립 보호층에 영향을 준다. Gazebo 구동 플러그인 내부의 속도·토크 제어는 기존 관절 속도 피드백을 그대로 사용한다. **실제 MCU 속도 제어기까지 엔코더 오류를 넣은 시험은 아니다.** MCU 구조가 정해지면 그 내부 측정·명령 만료·제동까지 별도로 확인해야 한다.

구간 누락 후 자동 재주행은 현재 데모의 센서 입력 복구 동작을 검사하는 것이다. 실물 비상정지의 잠금/수동 해제 정책을 대신하지 않는다. 작은 고정 편향의 단기 영향과 장시간 자기 위치 추정의 누적 오차도 별개다.

이번 것은 실물 교정값을 알아낸 작업이 아니다. 입력 시간 계약과 오차 허용 범위를 시뮬레이션에서 먼저 좁히고, 실물 도입 시 취득 시각·자이로 영점·엔코더 방향/분해능/환산을 확인하기 위한 준비다. 순서가 잘못된 패킷이나 틀린 시각 중 일부는 검출 가능하지만 작고 그럴듯한 편향·시각 오차를 항상 알아낼 수는 없다. 타임아웃을 늘려 실패를 숨기거나 정답 자세로 보정을 대체하지 않는다.

실물 도입 시 우선 확인할 항목:

1. MCU가 기록한 **취득 시각**과 Jetson의 수신 시각을 구분하고, C1의 점별 순서/시각과 같은 시간축인지 확인한다. header만 수신 시각으로 바꾸어 지연을 숨기지 않는다.
2. 정지 상태가 확실한 구간에서 자이로 영점과 축 방향을 확인한다. 이번 합성 편향을 사용해 실물 교정값을 정하지 않는다.
3. 엔코더 유효 틱 수·부호·바퀴 환산과 실제 이동거리를 대조한다. 공통 ±5% 시험은 좌우 다른 펄스 손실·슬립·MCU 속도 제어기 검증을 대신하지 않는다.
4. 현재 마지막 운동 표본 외삽 한도는 **30 ms**, 표본 사이 허용 공백은 **50 ms**다. 전달 지연뿐 아니라 샘플 주기·큐 대기가 합쳐진 표본 나이를 측정해야 한다. 이번 100 Hz·15 ms 통과를 임의의 낮은 통신 주기에서도 통과한다는 뜻으로 해석하지 않는다. 실제 분해능/주기는 미정으로 남긴다.

Jetson 처리량 시험은 [별도 인수인계 계획](../reports/SENSOR_ROBUSTNESS_AND_JETSON_PLAN_2026_09_22.md)을 따른다. 이번 중계기/파일 기록이 있는 느린 PC 시뮬레이션은 실시간 Jetson 성능 측정이 아니다.
