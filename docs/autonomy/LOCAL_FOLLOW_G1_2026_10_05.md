# G1-a: 지역 경계 확인과 거리 기반 추종·대기

작성: 2026-10-05. **선택형 G1-a 구현·제한 검증 완료.** 합성 앞차 시험과 공식 코스 12 m 단독 연결 회귀를 확인했다. Gazebo 상대차 폐루프·전체 G1 단계 완료는 아니다. 기존 기본 주행 모드는 유지한다.

## 범위와 기준선

[다중 차량 설계](MULTI_VEHICLE_DESIGN_2026_10_04.md)의 G1 최소 연결이다. 사용자가 이번 구현은 GPT 주 에이전트가 직접, 시뮬레이션 실행·대기는 GPT-6 Luna가 맡도록 지정했다. 기존 센서·구동·물성·공식 트랙과 독립 `/drive` → 보호층 → `/drive/safe` 경계를 유지한다. 추월·우회·Jetson 실행·게시·속도 상향은 하지 않는다.

시작 시 Git HEAD는 `25dea6045098105a1289ac8ffdb9b2b366c16edb`, 작업 트리는 깨끗했다. 이 커밋이 G0 사후 입력 거절 보강까지 포함한 소스 기준선이다. Luna의 WSL 사전 점검과 기존 관련 [260개 회귀](../../artifacts/validation/2026-10-05/g1_baseline_v1/green.log)를 확인했다. 이전 실행 권한 오류를 현재 결과로 대신하지 않았다.

## 구현과 선택 경계

- `scene_motion.py`: 기존 `MotionHistory`의 모터축 환산 속도·자이로 이력에서 광선별 base_link 변환을 얻는다. 반환뿐 아니라 원점·방향·미관측·취득 시각·세대를 보존한다. 순차 취득/프레임/이력 공백이 불확실하면 거절한다. Gazebo 위치·명령 속도는 읽지 않는다. 수평 스캔 전용이며 피치 일반화는 이번 범위가 아니다.
- `local_follow.py`: 기존 벽 경로 생성기에서 후보를 얻되, 초기에는 양쪽 경계의 중심 경로 일치와 서로 다른 두 스캔의 일치를 요구한다. 이후에는 운동 보정한 이전 경로와 가까운 전방 형상을 대조한다. 짧은 돌출물로 후보가 끊기면 유효한 직전 경계와 일치하는 **현재 실제 반환점**으로 후보를 다시 만든다. 기존 연결 간격·적합·길이·형상 기준을 그대로 적용하고 점을 합성해 빈 곳을 채우지 않는다. 코너 안쪽 벽이 짧을 때는 **양쪽의 현재 관측 경로가 일치하는 경우에만** 충분히 긴 반대쪽 경계를 선택한다. 선호 벽이 아예 가려졌다는 이유만으로 반대 벽을 채택하지 않는다.
- 경로 형상만 최대 0.3초 기억하고 원천 취득 시각은 갱신하지 않는다. 새 관측으로 확인되지 않으면 만료 후 정지한다. 모든 현재 반환은 별도로 점유 검사에 남는다. 경계 기억이 가려진 공간을 자유 공간으로 바꾸지는 않는다.
- 후륜축 Pure Pursuit의 기존 계산을 같은 조건으로 재현하는 작은 함수를 추가했다. 보호층이 공유하는 `local_path.py`·`lidar_safety.py`·`lidar_motion.py`는 수정하지 않는다. 이번 명령의 조향 변화율과 직전 조향을 모두 거리 검사에 넣는다.
- `CRUISE/FOLLOW/HOLD`는 경기 출발 허가와 별개다. 앞 점유를 움직일 수 있는 장애물로 취급하지만 상대 속도의 이득을 주지 않는다. 거리·정지 여유·시간 간격으로 속도를 낮추며 가까우면 정지, 더 넓은 간격과 서로 다른 두 새 스캔이 확인되어야 재개한다. 기존 RGB 신호·고정 고장·독립 보호는 유지한다.
- `g1_follow.launch.py` 또는 평가기의 `--g1-follow`에서만 활성화한다. 기존 기본 `local_pursuit`는 꺼짐을 유지한다. G1 입력 오류 시 기존 경로로 몰래 되돌아가지 않고 0명령을 내린다.

완벽한 벽/차량 분류기나 객체 추적기는 아니다. 큰 차량·벽에 붙은 차량·초기부터 양쪽 경계가 가려진 상황·분기에서 일관된 잘못된 경계 등은 후속 반례가 필요하다. 미검출 낮은 차/후방 사각은 기존 한계 그대로다. 광선 간 자유공간 다각형·전체 궤적 외곽 검사·상대 미래 cut-in 예측은 구현하지 않았다. 따라서 **G1 전체 통과나 G2 우회 허가의 근거가 아니다.**

## 시험 전 고정한 임시 수치

실측 사양이 아닌 저속 기능 시험 가정이다. 소스의 `FollowConfig`와 [시험 설정](../../config/tests/g1_follow_v1.json)이 정확한 값의 기준이다.

| 항목 | 값과 이유 |
|---|---|
| 새 모드 속도 상한 | 기존 프로필과 1.0 m/s 중 작은 값. 기존 단독 상한은 변경하지 않음 |
| 경계 기억 | 원천 시각부터 <0.30초, 보정 변위 ≤0.45 m. 기존 보호 스캔 만료를 연장하지 않음 |
| 경계 획득 | 전방 관측 호길이 ≥0.65 m, 측면 앵커 거리 오차 ≤0.12 m, 가까운 전방 경로 차이 ≤0.08 m, 서로 다른 2회 스캔 |
| 점유 팽창 | 기존 2.5 cm + 시험 거리 오차 3 cm + 표적 0.5 m/s × 현재 스캔 나이. 과거 취득 시차의 임시 여유이며 미래 충돌 보증 아님 |
| 추종/대기 | 정지 여유 0.16 m·시간 간격 0.8초, 팽창 차체의 잔여 이동거리 ≤0.20 m에서 HOLD, ≥0.28 m 2회 확인 후 재개 |
| 제동 계산 | 기존 2 m/s²·관측 나이+0.1초 반응 계산 유지. 실제 MD20A 제동 능력은 미확정 |

## 검증 계획과 판정 구분

1. 순수 회귀: 광선 끝점의 기존 both 보정 일치, 미관측/시각 보존, 시간·세대·이력 부족, 같은 스캔 재사용, 벽 가림·옆차·정지·재출발, 기존 기본 모드 보존.
2. 합성 폐루프: 빈 회랑·정지차·등속차·정지/재출발, 각 seed 0/1/2. 각 광선 취득 시점의 표적/자차 기하에서 최근접 반환을 계산한다. 이상적 운동학과 이상적 속도/자이로 피드백, ±3 cm 균등 주입. R0와 같은 상한/입력/보호 계산으로 비교한다. 실제 구동·DDS·Gazebo 물리/광선의 대체 근거는 아니다.
3. Gazebo: 공식 코스에 새 모드를 연결한 12 m 단독 부분 회귀. 기존 출발·센서 전용 구독·독립 보호·정지·정상 종료와 virtual MCU 진단을 유지한다. **다중 차량 Gazebo 폐루프는 이 단독 회귀 결과로 대체하지 않는다.**

실패 시 시간/간격 한도를 늘려 통과시키지 않는다. 중복 시험보다 최초 실패와 변경 이유를 기록한다. 시험 소스·설정 ZIP과 해시·새 출력 경로를 보존하고, 이번 작업 이후 추가 검증이 필요한 조건은 미시험으로 남긴다.

### Gazebo 통합 회귀

실행 전 평가기에 `/actuation/diagnostics`의 transient-local 구독·종료 전 파일 보존·MCU 마감 실패의 통과 거부를 추가했다. 정상 시험에서 진단 메시지가 없을 수 있으므로, 빈 파일 자체를 지연이 전혀 없었다는 증거로 사용하지 않는다. `/actuation/status`, 모델 정지, 종료 판정은 별도로 유지한다.

첫 [v1 보고서](../../artifacts/validation/2026-10-05/g1_gazebo_solo_v1/report.json)는 **1.05989 m에서 `FOLLOW_BOUNDARY_UNCONFIRMED`가 지속되어 실패**했다. 충돌 표본은 0, MCU ARM/정상 피드백과 보호층 `clear`를 확인했다. MCU 고정 고장은 0표본, `/actuation/diagnostics`는 `[]`(0건)였다. 마지막 모델 속도는 약 `3.3e-7 m/s`였지만 목표 거리 후의 명시 STOP 검사는 도달하지 않았으므로 정상 주행/정지 통과로 기록하지 않는다.

[보존 정지 스캔 분석](../../artifacts/validation/2026-10-05/g1_failure_analysis_v1/analysis.json)에서 가까운 짧은 가림 앞의 벽만 선택되어 왼쪽 전방 길이가 약 0.282 m였다. 그 뒤 약 x=0.363~1.205 m의 긴 벽도 실제 관측했지만 기존 생성기의 앵커 영역 x<0.35 m 밖이어서 선택하지 못했다. 오른쪽도 비슷하게 끊겼다. 이 분석은 정지한 마지막 스캔의 기하 재현이며 주행 중 모든 원시 스캔·운동 이력을 재생한 결과는 아니다.

수정은 경계/점유 역할 분리에 한정했다. 유효한 경계 이력이 있고 원래 후보가 거절될 때만, 이력의 법선으로 예상한 벽 부근의 현재 반환을 후보에 사용한다. 이력 양 끝 너머의 관측은 그대로 두어 새 전방 경계를 관측할 수 있게 했다. 새 후보에도 같은 연결 간격·0.65 m 길이·0.08 m 형상 기준을 적용한다. **원래 모든 반환은 충돌/간격 검사에 남기며, 큰 가림은 연결하지 않고 기억 만료 후 HOLD**한다. 이력 없이 마지막 정지 위치에 새로 놓았을 때의 초기 획득이나 임의의 기둥/차량 배치 전체를 해결한 것은 아니다.

v1 종료도 별도로 실패했다. Gazebo 서버 자체는 정상 종료했지만 새 `GroupAction`의 scoped 문맥이 하위 launch 설정을 제거해 종료 타이머에서 `gazebo_sigterm_timeout` 조회 예외가 발생했다. ROS launch를 SIGTERM으로 정리했으며 잔존 시험 프로세스는 없었다. 독립 G1 진입점의 그룹을 `scoped=False`로 바꿔 문맥을 유지했다. **잔존 없음과 정상 종료는 다르며 v1은 `shutdown_clean=false`로 보존**한다. 과거 GPU/MCU 지연과 같은 원인으로 해석하지 않는다.

수정 후 [364개 회귀](../../artifacts/validation/2026-10-05/g1_unit_v4/pytest.log)가 통과했다. 보존 스캔·큰 가림·기존 경계 끝 너머의 실제 관측·종료 문맥 회귀를 포함한다. 같은 조건의 합성 v3/Gazebo v2는 별도 출력으로 실행하며, 새 결과로 v1을 성공 처리하지 않는다.

[합성 v3](../../artifacts/validation/2026-10-05/g1_synthetic_v3/report.json)는 G1 12/12 통과했다. [Gazebo v2](../../artifacts/validation/2026-10-05/g1_gazebo_solo_v2/report.json)는 첫 가림 구간을 지나 **8.01914 m까지 진행했지만 코너 진입에서 다시 경계 미확인으로 정체되어 실패**했다. 충돌 표본 0, MCU 고정 고장 0표본·추가 진단 0건, 정상 종료·잔존 없음은 확인했다. 목표 거리·명시 STOP 검사는 미달이다.

[코너 정지 스캔](../../artifacts/validation/2026-10-05/g1_failure_analysis_v1/corner_analysis.json)에서 왼쪽 안쪽 벽의 관측 호길이는 약 0.380 m, 오른쪽 바깥쪽 벽은 1.8 m였다. 양쪽이 만드는 가까운 중심 경로는 기존 0.08 m 형상 일치 기준을 충족했다. 따라서 긴 경계 기준을 낮추는 대신 **실제 선호 벽이 있고 앵커가 정상이며 양쪽 경로가 일치할 때만 충분히 긴 반대 벽을 선택**하도록 보완했다. 유효 기억이 있을 때는 그 기억과도 일치를 요구한다. 초기/만료 뒤에는 여전히 서로 다른 두 스캔의 확인을 요구하며, 반대 벽만 보이는 경우·양쪽 경로 불일치는 정지한다. 상태에는 실제 선택한 `path_wall`, `wall_fallback`, `bilateral_alternative_confirmed`를 구분해 기록한다. 이 변경은 G1 전용이며 기존 R0 경로 모듈과 보호층은 그대로다.

보존 코너와 양측 불일치 반례를 포함한 [366개 회귀](../../artifacts/validation/2026-10-05/g1_unit_v5/pytest.log)가 통과했다. 합성 v4·동일 조건 Gazebo v3의 결과는 별도로 확인한다.

## 재현과 다음 단계

WSL에서 `/opt/ros/jazzy/setup.bash`, `install/local_setup.bash`를 불러오고 `src/arena_autonomy`·`src/arena_vehicle_interface`를 `PYTHONPATH` 앞에 둔다. 신규 ROS 패키지 파일은 `colcon build --packages-select arena_autonomy arena_bringup --symlink-install` 후 사용한다. 첫 빌드의 셸 래퍼 종료 코드 파일은 비어 있지만 [colcon 원본 로그](../../artifacts/validation/2026-10-05/g1_build_v1/build_2026-10-05_19-30-42/events.log)에서 패키지 작업 종료와 실제 하위 명령 코드 0을 확인했다.

- 순수 회귀: [파일 목록과 실행 명령](../../artifacts/validation/2026-10-05/g1_unit_v5/run.sh).
- 합성 비교: `python3 -B scripts/validate_local_follow.py --output artifacts/validation/<새 출력 경로>`.
- 공식 코스 단독 회귀: `python3 -B scripts/validate_basic_autonomy.py --autonomy-mode local_pursuit --g1-follow --lidar-acquisition sequential --lidar-compensation both --control-rate-hz 50 --render-backend wsl_nvidia --collision-detector configured --shutdown-mode service --sensor-wall-timeout-s 30 --disable-speed-bump --red-duration-s 1 --wall-timeout-s 1200 --stop-wall-timeout-s 120 --speed-profile exploratory --target-progress-m 12 --max-sim-seconds 60 --grid-slot 3 --actuation-mode virtual_mcu --output artifacts/validation/<새 출력 경로>`.

후속 우선순위는 **Gazebo 상대차와 실제 순차 광선을 연결한 저속 폐루프**, 공식 코스 커브·기둥/벽 가림·옆차 반례다. 새 연산의 Jetson 재생 비교와 다중 차량 전체 G1 판정은 남아 있다. 우회/추월·속도 상향·센서 추가로 범위를 넓히지 않는다. 단독 회귀에서 진행성이 실패하면 먼저 그 실패를 해결하고 상대차 시험을 확대한다.
