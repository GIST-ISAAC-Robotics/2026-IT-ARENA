# 조향·회피·추월 알고리즘 검토 노트

최종 갱신: 2026-08-31

이 문서는 나중에 알고리즘 방향을 정할 때 다시 읽을 **상시 비교 자료**입니다. 현재 채택된 대회용 조향·추월 알고리즘을 선언하는 문서가 아닙니다. 구현 완료 범위는 RGB 출발·ArUco 분기·상부 2D LiDAR 벽 추종뿐이며, 다중 차량 회피와 추월은 아직 없습니다.

규정 근거는 [공식 매뉴얼](https://github.com/MOSW626/istech-it-arena/blob/d61c5db9252cedfbc163cd044a47671df91e1660/MANUAL.md)입니다. 확인 버전은 `v2026.08.31` / `d61c5db9252cedfbc163cd044a47671df91e1660`이며, 2026-08-30 확정 규칙은 전 차량 동시 투입·시각 신호 출발(UDP 등 무선 신호 없음)·원격 비상정지 의무·차체 공격 금지입니다. 상황별 패널티·규격 초과 처리·총 랩 수·종료 조건은 아직 미정입니다. 과거 회의의 제안이나 현재 시뮬레이터 편의 설정을 경기 규칙으로 승격하지 않습니다.

## 먼저 분리해야 할 네 문제

“자율주행 알고리즘”은 하나의 조향 공식이 아니라 여러 기능의 조합입니다. 다음 네 층을 분리합니다.

1. **인지:** 벽, 노면 경계, 표지, 상대 차량의 위치·속도와 신뢰도를 냅니다.
2. **행동 결정:** 자유 주행, 앞차 추종, 정지, 추월, 추월 포기 중 하나를 고릅니다.
3. **경로·속도 계획:** 차량 폭과 Ackermann 조향 한계를 지키는 짧은 궤적과 목표 속도를 만듭니다.
4. **추종 제어:** 선택한 궤적에 맞춰 조향각과 속도를 냅니다. 이와 별도로 센서 결측·충돌 임박 시 정지시키는 독립 안전층을 둡니다.

`PID`, `Pure Pursuit`, `Stanley`는 주로 4번입니다. 조향 제어기 하나를 고르는 것과 다른 차량 회피·추월을 구현하는 것은 별개의 작업입니다.

```text
RGB / 상부 LiDAR / 하부 ToF / 엔코더·IMU
                    │
        ┌───────────┴───────────┐
        │                       │
독립 안전층: 신선도·TTC      인지·시간축 상대차 추적
        │                       │
즉시 감속·정지        FREE / FOLLOW / PASS / ABORT
                                │
                    충돌 없는 경로·속도 후보
                                │
                    조향·속도 추종 → ESP32
```

## 센서가 맡을 역할

| 입력 | 우선 역할 | 단독으로 맡기지 않을 것 |
|---|---|---|
| 상부 C1급 2D LiDAR | 벽·코스 단면, 중거리 장애물 군집, 위치 추정, FTG | 스캔 평면보다 낮은 차의 안전 검출 |
| 하부 VL53L7CX급 ToF, 임시 6개 | 낮은 범퍼·바퀴·차체의 근거리 점유, LiDAR 아래 안전 보완 | 한 프레임만으로 상대차 정확한 위치·ID 결정 |
| RGB 카메라 | 출발 신호, 코스 ArUco, 후방 의무 식별 마커의 세부·패턴 확인 후 차량 ID 보조 | 가림·블러가 있어도 항상 존재하는 충돌 안전 입력 |
| D435i 깊이 | 전방 형상·높이 비교, LiDAR/ToF 불일치 진단 | 측·후방 360° 안전, 빠른 차에서의 확정 주 센서 |
| 엔코더·IMU | 자기 속도·yaw rate, 위치 추정·운동 보상, 제동거리 계산 | 바퀴 슬립이 있어도 절대 위치라고 가정 |

후방 센서는 경주선 조향만 놓고 보면 필수가 아닙니다. 그러나 추월 뒤 복귀, 뒤차의 고속 접근, 회전 뒤 복구와 다중 출발 안전층에는 필요합니다. 현재 하부 ToF 링에서 후방 두 방향과 정후방을 유지하는 이유입니다.

## 단계 0: 독립 안전층

어떤 주행 알고리즘을 선택해도 먼저 둡니다.

- 모든 센서와 제어 명령에 시각을 붙이고 최대 허용 지연을 넘으면 감속 또는 정지합니다.
- 정면 한 점의 거리만 보지 않고, 현재 조향에서 차량이 지나갈 **swept path** 안의 상부 LiDAR·하부 ToF 점유를 검사합니다.
- 상대 접근 속도 `v_rel`을 안정적으로 얻을 때는 `TTC = distance / max(v_rel, ε)`를 사용합니다.
- 최종 정지 기준은 `속도×전체 지연 + 속도²/(2×실측 감속도) + 여유 거리`보다 앞에 장애물이 있는지로 정합니다.
- 센서끼리 불일치할 때 “다수결로 무시”하지 않습니다. 안전 구역에서 하나라도 신뢰 가능한 근접 검출이 반복되면 보수적으로 감속합니다.

[F1TENTH 교육과정](https://f1tenth-coursekit.readthedocs.io/en/stable/assignments/labs/index.html)의 Automatic Emergency Braking 실습은 구조 참고용입니다. 숫자는 실제 차의 지연·타이어·노면 시험으로 다시 정해야 합니다.

## 단계 1: 현재 벽 추종 유지·개선

현재 데모는 한쪽 벽의 LiDAR 점을 2차 곡선으로 근사하고 거리·방향·곡률로 조향합니다. 장점은 지도와 절대 위치가 없어도 당장 움직이며, 고장이 났을 때 설명하기 쉽다는 점입니다.

한계는 분명합니다.

- 상대 차량을 벽 또는 이상점으로 오인할 수 있습니다.
- 벽에서 일정 거리만 유지하므로 최적 경주선이 아닙니다.
- 갈림길에서 ArUco ID별로 어느 벽을 따를지 미리 정한 현재 규칙은 새 코스에 일반화되지 않습니다.
- 벽이 끊기거나 여러 차량이 시야를 가리면 조향 근거가 사라집니다.

따라서 벽 추종은 초기 실차 통합·비상 복귀 기준선으로 유지하되, 경주용 최종안으로 자동 승격하지 않습니다.

## 단계 2: 반응형 빈 공간 주행

### Follow the Gap(FTG)

2D LiDAR에서 충돌 가능한 점 주변을 차량 반경만큼 팽창시키고, 남은 가장 큰 각도 구간 안의 목표점을 향합니다. 지도 없이 정적 장애물을 피하기 쉬우며 현재 `/scan`을 재사용할 수 있습니다.

필요한 보완은 다음과 같습니다.

- 고정 반경이 아니라 속도·조향각·20×15 cm 외형과 조향 중 점유 폭을 반영합니다.
- 바로 앞의 작은 빈틈보다 경로 연속성·벽 여유·목표 방향을 비용에 넣어 좌우 진동을 줄입니다.
- 하부 ToF가 swept path 안의 낮은 물체를 잡으면 해당 방향을 LiDAR가 비어 보여도 금지합니다.
- 정지차→느린 앞차→cut-in 순서로 시험하며, 처음부터 다섯 대 난전에 투입하지 않습니다.

### Disparity Extender

인접 LiDAR 거리의 큰 불연속을 장애물 가장자리로 보고 차량 폭만큼 가까운 거리를 옆 각도까지 확장합니다. FTG보다 구현이 단순할 수 있지만, 낮은 차량을 LiDAR가 못 보면 불연속 자체가 없습니다. ToF 점유 투영과 결합해야 합니다.

[개발자의 Disparity Extender 설명](https://nathanotterness.com/2019/04/the-disparity-extender-algorithm-and.html)에서 거리 불연속 확장과 차량 폭 반영의 원리를 확인할 수 있습니다. 우리 차량에는 조향 중 점유 영역·제동거리와 저층 점유를 별도로 추가해야 합니다.

반응형 방식은 빠른 안전 기준선으로 좋지만, 추월 후 어디로 복귀할지와 다음 코너를 미리 보는 능력은 약합니다.

## 단계 3: 경주선과 추종 제어

지도 또는 반복 주행으로 기준 경로와 곡률별 목표 속도를 준비하고, 위치 추정 결과를 이용해 따릅니다.

### Pure Pursuit

차량 앞의 경로에서 lookahead 점을 고르고, 그 점으로 가는 원호 곡률을 계산합니다. 자전거 모델의 기본 조향은 `δ = atan(2L sin(α) / Ld)`입니다. `L`은 축거(m), `Ld`는 뒤축 중앙에서 목표점까지의 직선거리(m), `α`는 차량 전방축에서 목표점을 바라보는 상대 방위각(rad)입니다. 왼쪽 조향·방위를 양수로 맞추고, 현재 모델 중앙인 `base_link`를 뒤축 중앙과 혼동하지 않습니다.

- 구현과 튜닝이 쉽고 경로가 매끄러우면 안정적입니다.
- 속도가 빨라질수록 lookahead를 늘리는 방식이 흔합니다.
- lookahead가 짧으면 진동하고 길면 코너를 안쪽으로 자를 수 있습니다.

[CMU Pure Pursuit 구현 보고서](https://publications.ri.cmu.edu/implementation-of-the-pure-pursuit-path-tracking-algorithm/)를 기본 참고로 둡니다.

### Stanley

경로 방향 오차와 횡방향 오차를 함께 사용합니다. 대표식은 `δ = heading_error + atan(k·cross_track_error / (speed + ε))` 형태입니다. 통상 앞축 중앙을 기준으로 횡오차를 정의하므로 Pure Pursuit와 기준점이 다릅니다. 위 식은 개념식이며, 경로 방향 오차·횡오차의 부호를 조향 방향과 일치시킨 뒤 사용해야 합니다. 기준점을 옮기지 않은 `base_link` 오차를 그대로 대입하지 않습니다.

- 횡오차를 직접 줄이므로 경로 복귀가 명확합니다.
- 저속에서 두 번째 항이 커지므로 완화항·조향 제한이 필요합니다.
- 위치·방향 추정 잡음과 경로 최근접점 선택에 민감할 수 있습니다.

[Stanley 차량 논문](https://onlinelibrary.wiley.com/doi/10.1002/rob.20147)을 원리 참고로 두되, 실제 축거·서보 응답에 맞춰 다시 튜닝합니다.

두 방법은 같은 위치 추정, 같은 경주선, 같은 속도·조향 제한에서 비교합니다. 한쪽만 잘 튜닝해 놓고 알고리즘 우열을 선언하지 않습니다.

## 단계 4: 상대 차량 추적과 행동 상태기계

상부 LiDAR 군집과 하부 ToF 점유를 차량 좌표에서 결합하고, 엔코더·IMU로 자기 운동을 보상해 시간축으로 추적합니다. 첫 구현은 최근접 이웃+상수 속도 Kalman filter 정도로 시작할 수 있습니다. 추적마다 위치·속도뿐 아니라 크기, 마지막 관측 시각, 센서별 지지 여부와 신뢰도를 유지합니다.

권장 상태는 다음과 같습니다.

| 상태 | 들어가는 조건 | 행동 | 빠져나오는 조건 |
|---|---|---|---|
| `FREE` | 진행 회랑이 비어 있음 | 경주선·속도 프로필 추종 | 앞차 또는 위험 점유 발견 |
| `FOLLOW` | 앞차가 있지만 즉시 충돌은 아님 | 시간 간격 유지, 추월 가능성 평가 | 길이 열림·정지 필요·추월 허용 |
| `BRAKE` | TTC/정지거리 위반 또는 센서 결측 | 독립 안전 감속·정지 | 충분한 시간 동안 안전 확인 |
| `PREPARE_PASS` | 규정·공간·가시성 충족 | 좌/우 후보 궤적과 복귀점 확인 | 조건 충족 시 `PASS`, 아니면 `FOLLOW` |
| `PASS` | 전 구간·복귀 구간 충돌 없음 | 우회선 추종, 상대차 계속 추적 | 앞섬 확인 후 `MERGE`, 위험 시 `ABORT` |
| `ABORT` | cut-in·공간 감소·계획 무효 | 무리한 병렬 주행 대신 뒤로 복귀 또는 정지 | 안전 간격 회복 |
| `MERGE` | 상대차보다 충분히 앞섬 | 정상 경주선으로 점진 복귀 | 경주선 복귀 완료 |

후방 **5×5 cm 식별 마커 부착은 의무**이며 미부착 시 출전 금지입니다. 각 팀이 모양을 정해 9월 3주차까지 공유합니다. 다만 현행 [매뉴얼 §5](https://github.com/MOSW626/istech-it-arena/blob/d61c5db9252cedfbc163cd044a47671df91e1660/MANUAL.md#L58-L62)는 후방 마커의 ArUco 사전·ID 체계, 5 cm의 코드/여백/판 기준과 장착 높이·방향·외형 포함 여부를 명시하지 않습니다. 패턴과 세부 규격을 확인한 뒤 추적 ID 보조로 구현하며, 현재 상대차 식별 기능이 구현됐다는 뜻은 아닙니다. 마커가 가려지거나 오인식되어도 기하 장애물 추적과 제동은 유지합니다.

## 단계 5: 우회·추월 궤적 계획

쉬운 순서로 비교합니다.

1. **검증된 좌·우 우회선:** 정상 경주선 외에 트랙 안쪽·바깥쪽 후보를 미리 만들고 점유되지 않은 것을 선택합니다. 현재 일정에서 가장 설명하기 쉽습니다.
2. **Frenet 후보 궤적:** 경주선 진행거리 `s`와 횡방향 `d`에서 여러 부드러운 이동을 만들고, 곡률·벽 거리·상대차 미래 점유·복귀 비용을 비교합니다.
3. **State Lattice/Hybrid-A\*:** Ackermann 조향으로 실제 실행 가능한 운동 원시동작을 연결합니다. 단순 XY 직선 RRT를 그대로 조향 명령으로 보내지 않습니다.
4. **MPPI/MPC/MPCC:** 조향·속도·트랙 경계·상대차 예측을 최적화 문제로 함께 풉니다. [Nav2 알고리즘 선택 안내](https://docs.nav2.org/setup_guides/algorithm/select_algorithm.html)와 [MPPI 설정 문서](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/controller_plugins/mppi_controller/configuring_mppic/)는 구현 구조 참고용입니다.

MPC 계열도 모델에 없는 타이어 슬립·서보 지연을 자동으로 해결하지는 못합니다. 축거·조향·가감속 식별과 위치 추정이 안정된 뒤 적용합니다. 위 Nav2 링크는 이동하는 최신 문서이므로 Jazzy에 실제 포함된 기능·매개변수와 대조해야 하며, Nav2를 이번에 설치하거나 대회용으로 채택한 것은 아닙니다.

### 나중에 읽을 다중 차량 경주 자료

- [ForzaETH Race Stack 논문·ETH 보관본](https://www.research-collection.ethz.ch/handle/20.500.11850/695381)과 [연구팀 저장소](https://github.com/ForzaETH/race_stack): 1/10 차량의 위치 추정·인지·계획·제어를 분리한 head-to-head 경주 시스템입니다. 전체 구조를 참고하되 우리 20×15 cm 차량의 센서·구동·코스에 바로 이식 가능한 완제품으로 취급하지 않습니다.
- [Predictive Spliner 논문](https://arxiv.org/abs/2410.04868): 상대차의 미래 궤적 예측을 사용하는 추월 연구입니다. 기본 추적과 안전한 추월 포기가 검증된 뒤 예측 기반 우회선의 비교 후보로 읽습니다.

이 자료는 후속 연구용입니다. 현재 저장소에 논문의 추월 시스템이 구현되었다는 뜻은 아닙니다.

## 현재 트랙에서 추월이 가능한지부터 확인

다음은 **기존 폭 실험 지도의 조건부 계산**이며 새 공식 트랙의 통과 검증을 뜻하지 않습니다. 실험 본선 45 cm에 폭 15 cm 차량 두 대를 나란히 놓으면 벽·차량 사이에 남는 총 폭은 15 cm뿐입니다. 임시 최대 조향에서 계산한 점유 폭 약 16.76 cm를 두 대에 적용하면 남는 총 폭은 약 11.48 cm입니다. 실험 지름길 25 cm는 차량 두 대의 정적 폭 합 30 cm보다도 좁습니다. 공식 파일의 형상·폭을 반영한 뒤에는 같은 계산과 연속 조향 궤적 검사를 새 입력으로 다시 수행해야 합니다.

따라서 다음 규정이 없으면 추월 알고리즘의 목표 자체가 정해지지 않습니다.

- 노면 색 경계와 물리 벽 중 어디까지가 합법 주행 영역인지
- 접촉·경계 침범 벌점, 좌우 추월·블로킹·끼어들기 규칙
- 지름길 진입·합류 우선권과 추월 금지 구간
- 고장차가 정지했을 때 철거 시점과 후진·복구 허용 여부

물리적 회랑이 없으면 더 복잡한 계획기를 넣어도 추월 공간이 생기지는 않습니다.

## 권장 개발 경로와 선택 기준

### A. 출전 가능한 안전 기준선

벽 추종 또는 FTG + TTC 안전층 + 신호/ArUco + 앞차 발견 시 FOLLOW/BRAKE입니다. 구현 속도와 설명 가능성이 가장 좋고, 추월을 포기해도 완주 가능한 백업입니다.

### B. 주력 후보

LiDAR·엔코더·IMU 위치 추정 + 곡률 속도 프로필이 있는 경주선 + Pure Pursuit/Stanley 비교 + TTC + FOLLOW + 검증된 우회선입니다. 단독 기록과 다중 차량 안전의 균형이 좋습니다.

### C. 후반 성능 목표

B에 상대차 시간축 추적, `FREE/FOLLOW/PREPARE_PASS/PASS/ABORT/MERGE` 상태기계와 Frenet/MPPI/MPC 후보 계획을 추가합니다. 규정상 추월 회랑이 있고 A/B가 안정된 뒤 진행합니다.

### D. 제한적 학습 결합

명시적 안전 경계는 유지하고 후보 경로 점수, 상대차 단기 예측 또는 제어 잔차에만 학습을 씁니다. 센서에서 조향까지 종단간(end-to-end) 정책을 필수 경로로 두지 않습니다.
