# C1 무응답·IMU 이상치 입력 보호 검증

날짜: 2026-10-04. [개발 계획](../reports/DEVELOPMENT_PLAN_2026_09_22.md)의 A4 중 C1 부분 무응답과 IMU 입력 무결성을 다룬다. 기존 [모터축 엔코더 검증](MOTOR_ENCODER_VALIDATION_2026_10_02.md)의 다음 작업이며, 다중 차량·실물 센서 시험은 아니다. GPT가 안전 기준과 IMU/ROS 통합을, GPT 6.1 Sol이 명세가 정해진 순수 LiDAR 관측 헬퍼를, GPT 6 Luna가 시험 실행·대기를 담당했다.

## 1. 수정 전 문제

10/1에 고정한 Slamtec 드라이버는 원시 거리 0을 `+Inf`로 발행한다. 이를 무조건 ‘최대 거리 밖 자유 공간’으로 해석할 수 없다. [드라이버 버전·기존 재현](../reports/REPO_REVIEW_2026_10_01.md#no-return-decision)을 기준으로 다시 확인한 결과, 전방 55개 광선이 `+Inf`이고 나머지 445개가 유한한 합성 입력에서 보호층이 `clear`, **2 m/s**를 출력했다. `NaN`과 가까운 유한 장애물은 정지했다.

수정 전 [재현 JSON](../../artifacts/validation/2026-10-04/sensor_input_validation/baseline_reproduction.json)·[소스 사본](../../artifacts/validation/2026-10-04/sensor_input_validation/before_sources/)·[기존 회귀](../../artifacts/validation/2026-10-04/sensor_input_validation/baseline_pytest.log)를 보존했다. 기존 회귀 통과가 이 안전 결함의 부재를 뜻하지 않았다.

## 2. 입력 계약 변경

### C1 전방 관측

- `/drive` → 독립 `lidar_safety` → `/drive/safe` 경계를 유지한다. **차체 전방 ±100°의 단일 결측도** `front_unobserved`·0명령이다. `+Inf`, `-Inf`, `NaN`, `range_min` 미만, `range_max` 초과를 모두 미관측으로 취급한다. 거리 배열을 최대 거리·이웃 점으로 채우지 않는다.
- Gazebo 미교차와 실물 무응답에 같은 보수적 정책을 적용한다. 현재 메시지만으로 둘을 판별하거나 `+Inf`가 유효한 자유 공간이라고 증명할 수 없으므로, 시뮬레이션 예외 통과 옵션은 만들지 않았다.
- 각도·거리 메타데이터, 양의 각 간격, 한 회전 길이와 전방 공백을 검사한다. LiDAR 장착 yaw를 반영해 차체 방향을 판정한다. 최대 2° 각 간격은 **임시 입력 계약**이며 C1 제조사 사양이나 물체 검출 보장이 아니다. 현재 정상 입력은 500점·약 0.72°다.
- 전방 밖의 결측은 기존 정책에 따라 정지 조건에서 제외한다. 이는 후방/옆면 전체가 안전하다는 뜻이 아니다. 기존 후방 가림·정곡률 점군 충돌 검사와 공간 이산화의 한계는 남는다. 이 수정은 모든 주행 점유 영역의 관측 증명이 아니다.
- 투영 후 유효점 30개 경계와 기존 시각·벽시계 감시는 별도로 유지한다. 모든 거리가 `+Inf`이면 이전 `scan_invalid` 대신 보다 구체적인 `front_unobserved`로 정지한다. 정상 입력 복구 시 상위 보호층은 자동 복구하며 MCU 고장 고정/명시 재허가 정책은 바꾸지 않았다.

### IMU 범위·변화율

원시 자이로 각 축을 차체 yaw로 투영하기 **전**에 비유한값과 범위 끝/초과를 거절한다. 현재 구성의 `gyro_full_scale_dps: 500`을 launch에서 두 운동 입력 소비자에 전달한다. ±500 dps는 설정값이지 실제 IMU 레지스터 확인 결과가 아니다. 포화 근처를 완전히 검출하는 것도 아니다.

투영한 yaw 변화율은 직전 **채택 표본의 취득 시각**과 비교한다.

`허용 변화량 = 0.05 rad/s + 100 rad/s² × 취득 시각 차이`

| 설정 | 값과 의미 |
|---|---|
| `motion_gyro_abs_limit_rad_s` | 기본 약 8.72665 rad/s. 각 축 절댓값이 이상이면 거절 |
| `motion_gyro_slew_limit_rad_s2` | 기본 100 rad/s². 실측 전 임시 보호 경계 |
| `motion_gyro_step_slack_rad_s` | 기본 0.05 rad/s. 작은 요동에 대한 절대 여유, 제조사 오차가 아님 |
| 정상 입력 | 값과 취득 시각 그대로 사용. 이동평균/저역통과 필터 지연 없음 |
| 거절 표본 | 0·clamp 값으로 대체하지 않고 정상 입력 시각도 갱신하지 않음 |
| 짧은 공백 | 기존 ZOH(직전 값 유지)와 이력의 시간 한도 안에서만 처리 |
| 연속 거절·통신 누락·취득 시각 고착 | 기존 30 ms 외삽 한도/50 ms 이력 공백 검사로 투영 거절·0명령 |
| 복구 | 정상 표본 한 개가 과거 긴 공백을 지우지 않음. 온전한 이력을 갖춘 새 스캔이 필요 |

진단에는 `gyro_range_or_saturation`, `gyro_slew`, `gyro_timestamp` 등의 거절 누계가 남는다. ‘마지막 거절 사유’는 과거 사건이며 현재 고장 여부와 혼동하지 않는다. 조향 명령이나 Gazebo 정답으로 IMU를 정답 판정하지 않는다.

최종 회귀는 **724개 통과**다. 기존 579개 집합과 같은 방식으로 실행/프로세스 관련 5개 파일을 제외했으며, 제외 목록과 명령은 [최종 실행 스크립트](../../artifacts/validation/2026-10-04/sensor_input_validation/run_final_regression.sh)에 명시했다. ROS/Gazebo 실행 결과와 시험 개수를 합산하지 않는다. ### 합성 입력과 ROS 연결

독립 프로세스의 `lidar_safety`에 `/scan`, `/imu/data`, `/drive_motor/encoder`, `/drive`를 발행하고 `/safety/status`와 실제 `/drive/safe` 출력을 함께 검사했다. **22조건이 통과했고 프로세스는 종료 코드 0**으로 정리됐다. 구동기/MCU는 연결하지 않았으므로 이것은 0명령 검증이지 물리적 제동 시험이 아니다. [ROS 결과·소스 해시](../../artifacts/validation/2026-10-04/sensor_input_validation/ros_fault_v1/report.json)

| 조건 | 확인한 출력 |
|---|---|
| 정상 유한 거리·정상 운동 입력 | `clear`, 목표 1 m/s 유지 |
| 전방 단일 `+Inf`, 조향 0/±0.25 rad | `front_unobserved`, 0명령 |
| 전방 연속/전체 `+Inf`, `NaN`, 최소거리 미만·최대거리 초과 | `front_unobserved`, 0명령 |
| 정상 발행 후 스캔 취득 시각에 300 ms 추가 지연 | `stale_input`, 0명령 |
| 연속 100 rad/s·취득 시각 고정·IMU 중단 | `motion_stale`, 0명령 |
| 각 고장 뒤 정상 입력/이력 회복 | `clear`, 1 m/s 복귀 |
| 새 취득 시각의 일정한 자이로 0 | 정상 직진도 가능하므로 고장으로 단정하지 않고 통과 |

이는 각 조건의 마지막 40% 구간에서 상태/명령을 비교한 검사다. 보고서의 첫 정지 표본 시각을 물리 정지 지연이나 최악 검출 시간 보장으로 해석하지 않는다. 일부 연속 고장 사례는 시작부터 이미 0명령이었다.

### IMU 동일 입력 대조

보존한 수정 전 `MotionInput`과 현재 어댑터에 같은 200 Hz 합성 입력을 넣었다. 공통 운동 적분은 그대로 두고 입력 거절 효과를 비교했다. [전체 결과](../../artifacts/validation/2026-10-04/sensor_input_validation/input_probe.json)

| 합성 입력 | 수정 전 | 수정 후 |
|---|---:|---:|
| 4 rad/s 단발 5 ms | yaw 오차 0.02 rad | 1표본 거절, 이 사례의 yaw 오차 0 |
| 같은 튐 2표본/10 ms | yaw 오차 0.04 rad | 2표본 거절, 이 사례의 yaw 오차 0 |
| 20 rad/s²의 정상 ramp | 41표본 채택·적분 0.39 rad | 동일, 추가 지연/평활 없음 |
| 위와 동일한 값의 잘못된 ramp | 0.39 rad로 적분 | **동일하게 통과. 오측정과 실제 회전을 구별하지 못함** |
| 신선한 일정 0 | 통과 | 통과. 직진/고착 구별 불가 |
| 표준편차 0.001 rad/s, 고정 seed의 작은 잡음 | 41표본 채택 | 동일. 잡음을 제거했다는 주장이 아님 |

500점 전방 관측 헬퍼만 WSL에서 2,000회 계측한 실행 비용은 중앙값 0.110 ms, p99 0.400 ms, 최대 0.557 ms였다. 초기 수치 허용오차 버전의 단일 호스트 미세 계측이며 ROS 전체 지연·50 Hz 마감·Jetson 처리량 검증을 대신하지 않는다.

이 주행은 아래 float32 허용오차 보완 **전** 소스다. 후속 변경은 정상 inclusive endpoint 표현 오차만 대상으로 하며 현재 500점 입력과 IMU 게이트·경로/속도는 그대로다. 이후 최종 회귀로 수치 경계를 검증하며 같은 12 m 시험을 불필요하게 반복하지 않았다.

### 검증 도중 확인한 사항

- 첫 확장 단위 검사에서 202개 통과·3개 실패가 나왔다. 세 실패 모두 기대한 `motion_gap` 대신 `motion_stale`이었으며 0명령을 우회한 사례가 아니다. 시험에 적은 `0.205`와 ROS 헤더의 나노초→초 변환값이 부동소수 경계에서 달라 최신 표본이 구간 끝에서 빠졌다. 시험의 종료 시각을 실제 변환값과 맞췄으며 운영 신선도 한도는 변경하지 않았다. [실패 로그](../../artifacts/validation/2026-10-04/sensor_input_validation/checks_v1.log)
- 독립 검토에서 양 끝 포함 513점 배열의 float32 각 간격이 한 회전에서 약 `1.75e-7 rad` 반올림 오차를 만들고 새 검사기의 초기 허용오차를 초과하는 경우를 발견했다. 허용오차 하한에 `2π × float32 epsilon`을 반영하고 181/361/501/513/721/1025점 inclusive 배열을 회귀에 추가했다. 실제 1표본 각도 공백·좁은 시야·반복 회전 거절 시험은 유지한다.

## 4. 이번에 해결하지 않은 부분

1. **새 취득 시각을 가진 그럴듯한 고착/오측정:** 일정한 0 자이로는 직진과 고착을 구별할 수 없다. 정상 회전과 같은 변화율로 증가하는 잘못된 값도 범위·변화율만으로 구별하지 못한다. 모터축 하나는 좌우 회전 차이를 주지 않는다. 후속 LiDAR/영상 운동 관측과의 불일치 진단 또는 실제 드라이버의 data-ready/취득 시각 계약이 필요하다.
   10/4 후속 검토에서, 현재 제어기에는 IMU와 독립적으로 실제 회전량을 추정하는 관측기가 없음을 확인했다. LiDAR 스캔 정합 또는 영상 운동 추정과 대조하면 검출 범위를 늘릴 여지는 있지만, 정합 신뢰도·직선 벽의 모호성·상대차 가림·지연을 함께 검사해야 한다. 같은 IMU로 보정한 점군이나 실제 조향각이 아닌 조향 **명령**을 정답으로 삼으면 독립 검증이 아니다. 이번에는 새 추정기를 추가하지 않고 조건부 후속으로 남겼다. 개선이 원리적으로 불가능하다는 뜻은 아니다.
2. **초기값과 실제 급회전:** 첫 유효 표본에는 변화율 비교 기준이 없다. 임계값보다 작은 오측정은 통과하며 실제 급회전/충격이 임계값을 넘으면 정상 표본도 거절할 수 있다. 방지턱·3차원 자세 변화는 이번 검증에서 제외했다. 임계값을 실차 보장으로 인용하지 않는다.
3. **C1 가용성:** 전방 무응답 한 점만 있어도 멈추는 보수적 초기 정책이다. 실물의 검은 표면·경사면·근접·자체 가림에서 오정지 빈도를 아직 모른다. 검출 구멍을 자유 공간으로 바꾸어 가용성을 높이지 않는다. 실물 입력을 확보한 뒤 관측 모델과 구간별 정책을 검토한다.
4. **A4 전체:** RGB 중단/신선한 내용 고착, 보호층/제어 프로세스 종료, 전체 랩의 반복 오정지와 차량 정지 거리 검증은 별도다. 이번 ROS 0명령을 실차 제동으로 확대하지 않는다. Jetson 재시험·실물 MCU·드라이버 교정도 미실시다.

## 5. 재현과 다음 작업
