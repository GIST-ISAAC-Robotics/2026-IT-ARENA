# 선택 실행 구성과 실물 이관의 남은 연결

11/12 PC 코드 검토. 사용자가 모터 시험 중 Jetson 접근을 잠시 금지했다가 이후 다시 허용했다. 실제 후속 시험은 현재 펌웨어/연결·장치 소유 상태부터 확인한다. 이 문서는 실차 실행 승인이나 새 기본 구성 선정이 아니다.

## 확인한 연결 차이

r174까지의 지연 교통 대표는 `g1_g2_handoff_trial`의 별도 launch prefix에 계획기 후보, 새 스캔 제출 정렬, 기존 Jetson 비용의 **시뮬 전용 지연 주입**, 현재 경로 재계산을 함께 넣었다. r177부터 현재 재계산은 공통 모듈/노드의 명시 옵션으로 분리했다. 일반 `g1_decision_execution=process_candidate`만 켜면 나머지까지 모두 적용되는 것은 아니다.

또한 `G1G2Node.create_follow_trace()`는 `g1_g2_simulation_trial=true`와 `use_sim_time=true`를 요구한다. 프로세스 실행도 시뮬 시간/50Hz 수신부를 요구한다. 실물 ROS 토픽을 연결하고 이 제한만 지우는 것은 이관이 아니다. 실제 시계·입력 어댑터·출력 모드와 선택 정책이 함께 명시되어야 한다.

## 실물 입력에 아직 남은 계약

PC 코드 검토 기준으로 C1 preview는 `c1_unmounted_preview`, `unverified_estimate`를 보내고 IMU preview도 미장착 frame과 추정 시각을 명시한다. `native_estimated_v1`은 이 데이터를 **받아 해석하는 것**까지만 지원한다. `scene_motion._measurement_transforms()`는 `unverified_estimate`를 `scan_timing_unverified`로 거절하고 `laser_frame`을 요구하므로, 현재 preview를 구독했다는 사실만으로 주행 가능한 경로가 되지 않는다.

[r201 저장 대조](../../artifacts/validation/2026-11-12/c1_nonreturn_audit_r201_v1/README.md)에서는 실제 SDK 거리0을 모두 null로 합치는 어댑터와 제조사/시뮬의 `+Inf` 무반환 표기가 다름을 확인했다. 원시 근거가 있는 거리0만 분리해도204장면의 unknown/반환점은 동일하지만, 제한 공백 검사는 이를 구별한다. 기존 출처 불명 null을 되살리거나 실제 시각을 승인하는 변경은 아니다.

이 표기 수정은 공통 `C1NativePreview`에 적용했고 관련78개 검사를 통과했다. 거리0은 `+inf`, 양의 거리와 품질0인 무효 표본은 기존 null로 구분한다. 어느 쪽도 자유 공간으로 확정하지 않는다. 새 converter를 실물 운영 프로세스에 설치·실행하거나 취득시각/장착 조건을 승인한 결과는 아니다.

후속 [r204 실제 격리 수신](../../artifacts/validation/2026-11-12/c1_nonreturn_live_r204_v1/README.md)은203회전/102,504점의 공통 decoder 수신과 원 배열을 대조했다. 거리0 30,886점과 품질 무효24점이 구분되고 원 각도·순서·추정 시각은 동일했다. 운영 launch는 변경하지 않았고,200μs 명목 시각의 겹침/수신후 끝 시각은 여전히 남는다. C1 정지·ACL 원복·포트 해제를 확인했으며 ESP32/IMU/차량 모터는 사용하지 않았다.

후속 진단에서는 SDK 시각/호스트 수신·IMU FIFO/MCU/호스트 시계와 실제 모터축 피드백을 함께 확인해야 한다. 추정 시각을 검증된 취득시각으로 이름만 바꾸거나, 정지 측정의0속도를 실제 엔코더 대신 계속 넣지 않는다. 실제 운용에 쓸 추정 시각 정책과 그 오차를 수용할 속도/장착 조건은 확인 결과로 정한다. 접근 제한 중에는 새 통합 수신이나 이 조건의 실측을 수행하지 않았다. 재허용 뒤 SSH/기존 호스트 키와 보이는 직렬 포트 소유자0을 확인했고 위 C1 격리 수신과 저장 CPU 시험을 진행했다. 다른 세션의 [모터 시험](../sensors/MD20A_MOTOR_HARDWARE_2026_11_12.md)은 IMU 분리·motor_probe_v1 잔류·실제 회전 중 엔코더0을 보고했으므로, 이를 정상 통합 센서 구성으로 취급하지 않는다. 기존 앱을 자동 복원하거나 모터 시험에 개입하지 않는다.

## 구현 순서와 남은 묶음

1. **공통 현재 재계산 연결 완료:** r176–r202에서 SOLO/parallel/GUARD/RELEASED를 위 범위로 정리하고 저장 출력·노드/반례를 대조했다. 원 경로 시각·상태·부호 있는 운동 이력·실제속도 기반 이동 영역·독립 보호를 유지한다. 전체 실물 실행과 지연 교통 완주는 별도다.
2. **정책과 평가 지연 분리 완료:** r184/r191/r218에서 제출·관측/재검사·만료 경로 참조를 공통 명시 옵션으로 분리했다. 예전 Jetson 계산비를 덧붙이는 prefix는 시뮬 평가용으로 남는다. 기본값은 일괄 켜지 않으며 정책별 검증 범위와 실물 시각 계약을 유지한다.
3. **실물은 구동 없는 진단 실행부터 연결한다.** 센서 단위·새 boot·시간 추정·구독 나이와 계산 결과를 기록하되 차량 구동 토픽/ARM을 만들지 않는 실행을 먼저 확인한다. C1/IMU preview의 `unverified_estimate`를 정확한 취득시각으로 바꿔 적지 않는다. 추정 오차와 이를 받아들이는 운영 조건은 별도 기록한다. 센서 연결 확인은 실제 MCU 제어 완료가 아니다.
4. **같은 구성의 저속 구동은 별도 단계다.** 실제 모터/서보/엔코더 형식·방향·환산·STOP/ARM을 확인한 뒤 개발 상한과 짧은 조작으로 진행한다. 현재 사용자 모터 시험에 원격으로 개입하지 않는다. 최종 카메라 높이·센서 장착 축·제동거리는 조립 뒤 확인할 항목으로 남긴다.

지연 교통 대표 미완주를 이 문서 작성만으로 완료 처리하지 않는다. 현재 결과는 [현황](../PROJECT_CONTEXT.md), 전체 우선순위는 [현행 계획](../DEVELOPMENT_PLAN.md)을 따른다. 작은 시각/상태 예외를 계속 쌓는 대신 실제 실행 경로를 정리하되, 일반적인 코드 미관 리팩터링으로 범위를 넓히지 않는다.

## 11/12 중간 정리 상태

사용자 요청에 따라 r230 결과 감사·r232 Jetson 회수까지 마치고 새 구현/시험은 시작하지 않았다. 해당 로컬/원격 시험 프로세스 잔여0을 확인했다. r231 공통 연결과 현재 재검사의 수신 경로 분리 비교는 다음 재개 지점이며 아직 완료로 표시하지 않는다. 중간 정리 뒤 사용자 추가 지시로 이 후속 변경을 GitHub main 반영 범위에 포함했다.
