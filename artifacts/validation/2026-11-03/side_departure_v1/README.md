# 좁은 병렬 출발 후보의 저장 입력 비교

실제85mm 옆차 간격에서 측정 시차 팽창 때문에 초기 명령이 계속0인 원인을 분리했다. 고정55mm 여유를 유지하고, 관측된 측방 반환에 더 접근하지 않는0.4m 이내 평행 진행 후보를 비교했다. [가정/위험](PLAN.md)·[기하 후보](candidate.py)를 따른다. 저장 입력은 원래 궤적이므로 명령이 바뀐 뒤를 후보의 실제 주행으로 해석하지 않는다.

| 저장 입력 | 호출 | 명령/상태 변경 | 새0명령 / 해제 | 0명령 표본 시간 원본→후보 |
|---|---:|---:|---:|---:|
| 오른쪽 재접근 실패 원본 |284|70|0 /65|2.08→0.78초|
| 기둥 없는 선정 단독 |1,849|0|0 /0|0.62→0.62초|
| 비사각형 상대 우회 |1,100|0|0 /0|0.90→0.90초|
| 상대 재출발 후 합류 |1,222|0|0 /0|1.08→1.08초|

상대가 정지한 구간의 최초 양수 후보는 시뮬7.82초, 측정속도0에서0.3m/s였다([forward_prefix.json](forward_prefix.json)). 기하 반례6개는 통과했다. 실제 제어/독립 보호/접촉/폐루프 검증은 이 결과에 포함하지 않는다.

## 비교기의 중간 실패 보존

첫 전체 비교는 표면 정합의 벽시계 `processing_ms`까지 비교해 단독 입력에서 중단됐다. 기존 `comparable_decision`이 제외하는 두 지정 위치의 비용만 사용하고 원시 차이를 남겼다. v2에는 비교함수/결과목록 이름 충돌이 있어 실패했다. 수정한v3에서 단독/비사각형을 완료했지만 과거 합류 기록 뒤 추가된 `entry_path_conflict` 진단 때문에 중단됐다. v4는 같은 진단의 두번째 위치에서 멈췄다. v5는 `entry_space`/`entry_admission`의 두 경로에서 `rejected=false`, `no_deep_current_path_conflict`인 추가 진단42건만 구분해1,222판단을 끝냈다. 속도·조향·상태 등 다른 차이는 허용하지 않았다. 이는 원시 기록 전체의 바이트 일치가 아니라 현재 제어 출력 보존과 알려진 진단 추가를 구분한 결과다.

근거: [right v2](full_replay_v2.log), [단독/비사각형 v3](full_replay_v3.log), [합류 v5](full_replay_v5.json), 각 `.exit`, 원본 실패 JSON·로그. 이전 실행을 성공으로 바꾸거나 같은 완료 입력을 매번 다시 실행하지 않았다.

다음 단계는 [기본 OFF 런타임 후보](../side_departure_runtime_v1/PLAN.md)다. 최초 격리 후보의 단순 측정속도0.35m/s 절단은 런타임에서 현재 속도의 반응+제동 거리가0.4m 창 안에 드는지로 바꿔 비교한다. 별도 검증 전 기본 활성화하지 않는다.
