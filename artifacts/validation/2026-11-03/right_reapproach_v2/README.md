# 오른쪽 후방 사각 재접근: 장면 성립, 측면 접촉 실패

등록 조건은 [PLAN.md](PLAN.md), 당시 소스는 `scene_source.zip`에 보존했다. 첫 6.2초안은 직선 종료 여유를 못 지켜 준비 단계에서 거절됐고 실제 실행하지 않았다. 여유를 유지한 5.9초안으로 Gazebo를 **1회** 실행했다.

## 결과

- 실행 유효성·소스 불변·명시 옵션 기록은 통과했다. 평가 상대 갱신만 50→100 Hz로 변경했으며 35 mm 위치 추종 기준은 유지했다.
- 초기 우측 반환 82점인 2스캔 → 전체 외곽이 후방 60° 마스크에 들어가 반환 0인 1스캔 → 뒤에서 다시 접근한 우측 반환 9·15점의 2스캔으로 장면이 성립했다. 미관측 구간을 자유 공간으로 채우지 않았다.
- 진행 3.39965 m, 최고 차체 속도 1.5932 m/s, 움직인 뒤 최장 정체 0.608초였다.
- **최소 간격 0 m, 연속 이동 하한 −1.239 mm, 접촉 메시지 265건·겹침 표본 121건으로 실패했다.** 접촉 메시지 수를 독립 사고 횟수로 해석하지 않는다.
- 7,128개 표면 자세에서 벽/바퀴 이탈 0, 명시 STOP·MCU 정지·정상 종료는 통과했다. 실행 담당의 종료 후 점검에서 잔여 시험 프로세스는 없었다.
- 원본 실행 exit 1, 노면 분석 exit 0, 등록 목표 분석 exit 1을 그대로 보존했다. 근거는 `run1_goal.json`, `run1_surface.json`, `run1.exit`, `run1/`이다.

## 확인한 경위와 다음 분석

`run1_selection_transitions.json`에서 출발 후 약 1.019초에 정지 측방 반환을 세계 고정 물체로 분류하면서 위협 이력이 지워져 SOLO가 됐다. r3의 평행 출발 유지로 진행은 이어졌지만 약 1.819초부터 중앙 경로를 택했다. 자차의 도로 중앙 대비 횡위치는 약 +90 mm에서 거의 0으로 변했다. 상대는 −145 mm 경로를 유지했다.

재접근 광선의 스캔 시작은 약 4.401초이고 수집은 약 4.501초까지 이어졌다. 제어기가 재접근을 GUARD로 반영한 시각은 약 4.519초, 첫 접촉은 약 4.558초다. **인지 뒤 약 39 ms만 남아 재등장 후 제동만으로 해결됐다고 볼 수 없다.** 이 시점에는 이미 측방 차체 간격이 사라졌다. 평가 자세는 분석에만 썼으며 제어기 입력이 아니다.

다음은 저장 입력에서 기존 정적 분류 해제·후방 차선 유지 정책을 비교한다. 중앙 복귀 전에 유지할 수 있었는지, 곡선/현재 장애물 대응과 진행 성능을 훼손하지 않는지 확인한다. 동일 실패를 그대로 재실행하지 않는다. 이번 결과는 각본 상대의 제한 직선 시험이며 전체 경기/실차 보장이 아니다.
