# 오른쪽 재접근 장면 미성립과 좁은 병렬 출발 정지

**재접근 장면은 성립하지 않았고 실행 전체도 유효 판정을 받지 못했다.** 상대가 처음1.6초 정지해 있는 동안 자차가 출발하지 못했고, 상대가 먼저 전방으로 빠져나간 뒤 자차가 움직였다. 상대 전체가 후방60° 마스크에 들어간 스캔은0개다. [사전 계획](PLAN.md)의 시간·배치를 결과에 맞춰 늘려 재실행하지 않았다.

| 항목 | 결과 |
|---|---|
| 실행/표면/별도 평가 종료 코드 | 1 / 0 / 1 |
| 실제 광선과 외형 대응 | 관측37스캔, 전체 후방 사각0스캔. 관측→사각→재접근 실패 |
| 4.3초 자차 진행·최고 | 1.41985m / 1.48017m/s |
| 간격 표본/연속 하한 | 84.933 / 84.932mm. 별도8cm 비교는 넘지만 원본15cm는 실패 |
| 접촉·겹침·바퀴 이탈/벽 | 모두0, 표면6,549표본·수신 공백0 |
| 명시STOP·정상 종료 | 확인, 잔여 시험 프로세스0 |
| 출처 | 등록166파일 불변 |
| 상대 이동 하네스 | 최대 위치 오차55.50mm > 등록35mm. **run_valid=false** |

원본은 진행·최종 거리·15cm 간격·앞차 뒤 유지 등에서 실패했으며 [별도 경기 목표 평가](run1_goal.json)도 장면·진행·실행 유효성에서 실패했다. 정지·접촉 표본을 확인했다는 것과 유효한 전체 주행 검증을 구별한다. 상대2.4m/s의 자세 갱신 지연과 기존 저속용35mm 기준의 적용 문제는 후속 하네스 과제다. 이번 결과를 사후 기준 변경으로 통과 처리하지 않았다.

## 다음에 해결할 실제 출발 병목

[정지 상대 구간](stationary_prefix.json)은 상대 이동이 시작되기 전0.3–1.5초만 분리했다. 앞길/스캔은 `fully_observed`인데 평행 경로도 `unchanged_gap_hold`로 막혔다. 고정55mm 여유에 취득 시차×0.5m/s가 더해져 점에 따라 약68–130mm로 팽창하고, 실제 측방85mm보다 커진다. 따라서 실제 충돌 표본이 없어도 현재 위치 자체를 점유된 것으로 보고0명령을 유지한다. 현재 정지 판정의 원인이며 실물 최소 간격의 확정은 아니다.

새 후보는 현재 접촉 여부와 불확실성 때문에 겹친 여유 영역을 분리하고, 실제 관측이 있는 현재 차선을 따라 **옆차 쪽으로 더 접근하지 않는 제한 진행**을 검토한다. 전방 장애물·측방 실제 근접·조향으로 접근하는 경우는 그대로 구별해야 한다. 전역 물체 이동 상계나 거리 오차를 일괄 낮추지 않고 저장 입력/반례부터 비교한다. 현재 제어기는 바꾸지 않았다.

시험 준비의 첫 평가기 검사는 순서가 뒤섞인 스캔을 거부하지 않아1실패였고 원본 코드/로그를 보존했다. 순서 검사와 후열grid0 평가 연결을 고친 뒤 관련97검사는 통과했다. [최종 등록](registered_final.json)·[원시 원본](run1/report.json)·[표면](run1_surface.json)·[소스 이전본](before.zip)을 구별한다. 원시 센서/자세는 기존 Git 제외 정책에 따라 로컬 보존한다.

## 후속 상대 이동 시차 진단

[명령/실제 자세 대응](actor_timing_diagnosis.json)에서2.4m/s 구간225자세 모두 이전 명령 위치와10µm 이내로 일치했다(최대약2.5e-15m). 실제 자세가 가리킨 명령의 나이는 중앙11ms·최대23ms였고,2.4m/s×23ms=55.2mm다. 따라서 이번55.5mm 오차는 제어 차량이 아니라50Hz로 위치를 갱신하는 평가 상대의 유지/적용 지연으로 설명된다. 이 분석으로 원본 실행 유효성을 통과 처리하지 않는다. 다음 고속 상대 장면에서는100Hz 명령을 별도 등록하고 기존35mm 오차 기준으로 실행 유효성을 먼저 확인하는 편이 타당하다.
