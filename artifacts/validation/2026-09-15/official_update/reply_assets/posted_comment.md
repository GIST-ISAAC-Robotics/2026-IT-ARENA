`v2026.09.14`의 **원본 PNG 마커가 정상 렌더링되는 것과, `minMarkerDistanceRate=0.02`에서 네 ID 모두 본선 2.0·1.5·1.2·1.0 m 전 위치에서 검출되는 것**을 확인했습니다. 결과와 검출기 설정에 관한 참고 사항을 공유드립니다.

먼저 측정 환경을 바로잡겠습니다. 이전에 전달드린 0.75~1.2 m도 실제 카메라와 인쇄 마커의 실측값이 아니라 **Gazebo 시뮬레이션의 정지 영상에서 얻은 결과**였습니다. 이번 결과 역시 시뮬레이션이며, 요청하신 실물 검출 거리는 아직 측정하지 못했습니다.

## 참고: 기본 설정에서 발생했던 중간 거리 누락

이번에 사용한 OpenCV 4.6.0의 기본값인 `minMarkerDistanceRate=0.05`로 검사했을 때는, 마커가 화면에 보이는데도 **2 m에서 검출 → 1.5·1.2 m에서 미검출 → 1 m에서 다시 검출**되는 경우가 있었습니다. 원본 PNG에서는 24개 위치 중 10개만 목표 ID가 검출됐습니다.

공식 수정이 반영되기 전까지 주행 테스트를 이어가기 위해, 저희는 기존 마커의 설치 각도만 조정한 임시 마커를 사용했습니다. 그때도 비슷한 검출 누락이 있어, 밝기와 경계 표현을 바꿔 보기 위해 **텍스처 이미지 대신 마커의 흑백 무늬를 도형으로 직접 그리는 방식**으로 우회한 적이 있습니다.

이번에도 같은 방식을 적용해 원본 PNG와 비교했습니다. 같은 카메라 위치와 조명 조건에서 일부 표본의 누락이 없어지고 더 먼 3 m 표본에서 검출되는 ID도 있었지만, ID 20·30의 중간 거리 누락은 남았습니다.

원인을 확인하기 위해 [사용 버전의 검출기 내부 처리](https://github.com/opencv/opencv_contrib/blob/4.6.0/modules/aruco/src/aruco.cpp)를 추적했습니다. 핵심은 **마커 무늬가 물리적으로 가려진 것이 아니라, 읽을 수 있는 후보가 해독 전에 버려졌다는 것**입니다.

1. 검출기는 여러 크기의 주변 영역으로 밝기를 이진화하고, 코드 경계·조금 부풀어진 경계·판 외곽 등의 사각형 후보를 만듭니다.
2. 가까운 사각형들은 같은 마커의 중복 후보일 수 있으므로 한 그룹으로 묶습니다. `minMarkerDistanceRate`는 이때 가까움을 판단하는 기준입니다.
3. 이번 기본 설정에서는 그룹 중 **가장 큰 후보만** 해독합니다. 일부 사진에서 올바른 코드 후보와 더 큰 잘못된 후보가 같은 그룹에 들어가면서, 올바른 후보가 버려졌습니다.
4. 남은 큰 후보는 코드 바깥의 여백까지 포함해 검은 테두리 검사에서 탈락했고, 최종적으로 미검출됐습니다. 실패한 모든 표본의 윤곽이 똑같은 판 외곽인 것은 아니며, 조금 부풀어진 코드 후보가 선택된 사례도 있었습니다.

아래는 원본 ID 30·1.5 m의 **실제 실패 영상 위에, 그 영상에서 추출된 후보 좌표를 겹친 그림**입니다. 가운데는 원본 확대, 오른쪽은 같은 사진 위의 오버레이입니다. 밝기나 마커 무늬를 보정한 그림은 아닙니다.

![실제 RGB 위 코드·중간 윤곽·판 외곽 후보 오버레이와 그룹화 설명](https://github.com/user-attachments/assets/18122c49-b0d2-4b7d-b6a9-71faf93cdf40)

그림의 **A·B·C·D는 같은 사진에서 각각 검출된 윤곽 후보이며, 네 후보 모두 같은 그룹으로 묶였습니다.** A–B, B–C, C–D가 각각 가까운 후보로 연결됐고, 검출기는 그 그룹에서 가장 큰 D만 남겨 해독했습니다. A를 따로 해독하면 ID 30이 나오지만, 선택된 D는 검은 테두리의 오류가 허용 5칸을 넘는 20칸이라 탈락했습니다. 설치된 검출기와 내부 추적의 최종 ID 목록은 중복까지 포함해 144/144개 조건에서 일치했습니다.

거리별로 현상이 달라진 것은 영상 속 마커의 크기·각도가 바뀌는 반면, 기본 이진화의 주변 영역 크기는 3·13·23픽셀로 고정돼 있기 때문입니다. 따라서 거리가 가까워질수록 같은 윤곽이 단순히 확대되는 것이 아니라, 만들어지는 후보와 그룹 구성이 달라졌습니다. 텍스처 대신 마커 무늬를 도형으로 직접 그리는 방식도 최종 영상의 명암·경계를 바꿔 일부 표본의 그룹 구성에 영향을 줬지만, 모든 누락을 해결하지는 못했습니다.

`minMarkerDistanceRate`를 **0.02로 줄이자 서로 다른 윤곽을 한 그룹으로 묶는 범위가 좁아져**, 올바른 코드 후보가 보존됐습니다. 이는 ID 해독의 허용 오류를 늘린 설정이 아닙니다. 같은 사진에서 원본 PNG의 목표 검출 위치는 10/24에서 17/24로 늘었고, 네 ID의 1.5·1.2 m 누락 표본이 모두 복구됐습니다.

대신 같은 마커의 비슷한 후보가 여러 개 남아 **동일 ID가 중복 검출**되기도 했습니다. 예를 들어 위 원본 ID 30·1.5 m 사진은 0.02에서 ID 30이 두 번 반환됐습니다. 현재 저희는 ID의 존재 여부만 사용하므로 중복 검출 자체는 큰 문제가 되지 않을 것 같습니다. 다만 혹시 몰라 함께 공유드립니다.

### 실제 제작 시 참고할 수 있는 점

실제 인쇄물에서도 명암·크기·배경 조건에 따라 비슷한 후보가 생길 가능성은 있으나, **현물에서 같은 현상이 재현되는지는 아직 확인하지 않았습니다.** 이번 결과만으로 실제 판이나 PNG 파일의 결함이라고 말씀드리는 것은 아닙니다.

다만 해당 검출기의 기본값을 사용하는 다른 팀도 있을 수 있고, 당일 시험 시간이 짧으면 이런 설정 문제를 발견하거나 조정하기 어려울 수 있어 참고로 남깁니다. 현재 시뮬레이션은 검출기 설정으로 대응할 수 있으므로 **당장 마커나 월드의 수정을 요청드리지는 않습니다.** 실제 제작 과정에서는 다음 방향도 한 번 고려해 볼 수 있을 것 같습니다.

- 코드 크기와 필요한 흰 여백은 유지하면서, 그 바깥의 밝은 영역을 넓혀 코드 경계와 판 외곽을 더 떨어뜨리는 방법.
- 코드와 흰 여백은 그대로 두되, 그 바깥 지지판 외곽을 사각형이 아닌 형태로 만들어 큰 사각형 후보가 되기 어렵게 하는 방법.

두 방향 모두 이번에 효과를 시험한 해결책은 아닙니다. 특히 지지판만 바꿔도 인쇄 용지의 사각 테두리가 별도로 뚜렷하게 남으면 같은 문제가 남을 수 있습니다. 제작·설치 여건과 함께 검토할 수 있는 제안 정도로 봐주시면 좋겠습니다.
