## 실행 전 범위

2026-10-13의 `per_ray_candidate` 왼쪽 균일 오차 1회 통과 뒤 남긴 두 조건을 실행한다. 시작 소스는 `e77d332`이며 제어·모델·기존 판정선을 변경하지 않는다.

1. `initial_occlusion`, 위치 seed 0, `lidar_positive_bias30.json`: 모든 유효 거리에 +30 mm 편향, 추가 지연 없음.
2. `first_curve`, 위치 seed 0, `lidar_uniform30_delay50_jitter20.json`: 균일 ±30 mm, 발행 지연 50±20 ms. 위치 seed와 오차 난수 seed는 별개이며 설정 원본을 보존한다.

각 최대 1회, 첫 실행/주입/STOP/종료/재생/v6 감사 실패에서 중단한다. 경계 `fragmented_candidate`·점유 `per_ray_candidate`를 명시 선택한다. 기본 `connected`/`oldest`, 1 m/s 상한, 단일 모터축 28카운트·15:1·65 mm, 독립 보호, 물성, 방지턱 임시 해제를 유지한다. 제어기에 지도/정답 입력을 주지 않는다. 과거 실패는 덮어쓰지 않는다.

기존 `g1_traffic_extensions_v1.json`의 초기 정지/재출발·U자 출구·진행·0.15 m 차체 간격·도로·STOP(밀집 0.5초)/정상 종료와 실제 주입 무결성을 그대로 요구한다. 합성 오차/지연이지 C1 실측 분포나 실차 안전 증명은 아니다. 이번 사용자 지시에 따라 한국 시간 03:30 이후에는 새 조건을 시작하지 않고 진행 중인 실행의 정상 정지/회수와 기록을 마무리한다. 커밋·푸시·외부 게시·Jetson/전원 변경은 이번 범위에 없다.

## 점별 취득 시각 독립 감사

`audit_follow_occupancy.py`는 생산 팽창 함수를 호출하지 않고 기록의 각도/거리/취득 시각으로 반환 개수와 여유 최솟값/최댓값을 다시 계산한다. 기존 oldest 실패 기록과 10/13 후보 통과 기록, 새 두 기록을 각각 감사했다. 새 조건의 전체 호출 544/1,789개 중 점유 계산까지 진행한 540/1,788개·고유 스캔 108/358개가 모두 일치했다. 나머지는 입력/경계 정지로 점유를 평가하지 않은 호출이며 빈 공간으로 간주하지 않는다. 첫 광선 최대 나이 0.198/0.257초다.

회전·전진 재투영 중 가림/무응답을 포함한 원천 인덱스·반환 순서 보존 회귀를 추가했다. 사전 관련 70개와 독립 감사 관련 36개가 통과했다(겹치는 집합이며 합산하지 않는다). 감사는 메모리의 모든 점 접근·실제 오차 분포·상대차 외곽/미래 이동·실물 정지를 인증하지 않는다. 기존 실패와 모든 원시 기록을 유지하며 후보를 기본값으로 승격하지 않는다.

후속 검토에서 감사기 소스 해시를 작업 **뒤**에 읽는 순서상 허점을 고쳐, 새 실행은 작업 전 snapshot/hash와 작업 후 대조를 사용하게 했다. 이 폴더의 기존 감사는 수정 전 snapshot과 당시 판정으로 보존하며 이를 소급 변경하지 않는다. 감사 중 소스 변경을 거절하는 별도 회귀를 추가했다.
