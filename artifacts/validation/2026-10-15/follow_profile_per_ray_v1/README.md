# 점별 시각 G1 후보의 PC 판단 비용

`profile_follow_trace.py --input-mode stream --warmups 1 --repeats 3`을 각 입력에 한 번 실행했다. 실제 출력 전부 일치·입력/소스 불변·실행 종료를 확인했다. 최초 지정의 `side_left_s0`는 존재하지 않아 실행 전 경로를 `side_left_uniform_s0`로 정정했다. 주행 재실행은 없다.

| 입력 | 기준 출력 일치 | 측정 호출 | 전체 p50/p99/최대(ms) | 판단 p50/p99/최대(ms) | 스레드 CPU p50/p99/최대(ms) |
|---|---:|---:|---:|---:|---:|
| 10/13 왼쪽 uniform 후보 | 374 | 1,122 | 4.414 / 9.809 / 11.836 | 1.782 / 7.053 / 7.435 | 4.416 / 9.812 / 11.839 |
| 10/15 첫 U자 지연 후보 | 1,789 | 5,367 | 3.530 / 8.108 / 11.431 | 0.806 / 4.019 / 7.810 | 3.533 / 8.110 / 11.434 |

각 항목의 20 ms 초과는 0이었다. 전체는 운동 이력 복원·스캔 재투영·판단을 포함하며 파일 읽기/JSON·ROS/DDS·영상·독립 보호/MCU는 제외한다. 20 ms는 참고선이며 실행 마감 보증이 아니다. 운영 제어 코드·GC·전원 변경과 Jetson 접속은 하지 않았다.

측정 snapshot의 누락을 막기 위해 `occupancy_timing` 및 내부 import 의존성을 검사하는 회귀를 추가했다. 원시 실패/이전 프로파일은 그대로 보존한다. [왼쪽 보고서](side_left/report.json), [커브 보고서](first_curve_delay/report.json).
