# G1 점별 시각 후보의 고장 경계 회귀

## 실행 전 계약

G1 편향/추가 지연 두 조건 마감 후 진행하는 별도 작업이다. 기존 `validate_pipeline_faults_ros.py`의 R0 기본과 보호/MCU 운영 코드는 유지하고, 명시적 `--controller-profile g1_per_ray_candidate --scenario full` 시험 옵션만 추가한다. 분리 경계·점별 시각 후보가 실제 실행됐는지는 모든 재진행에서 `/autonomy/status`의 모드·점유 보존·점별 팽창 점 수로 확인한다.

기존 전체 RGB/영상/제어기/보호층 중단·복구 순서에 C1 발행 중단, 전방 단일 `+Inf`, IMU 발행 중단과 각 정상 입력 복구 6조건을 앞에 추가한다. 후방 사각·단일 모터축 28카운트/15:1/65 mm·독립 보호·STOP/CLEAR/ARM·신선도 한도를 변경하지 않는다. 정상 발행 시 원래 취득 시각을 사용하며 무응답을 자유 공간으로 채우지 않는다.

ROS 실제 프로세스와 합성 직선 센서·임시 종방향 모형의 시험이다. 상한 0.6 m/s·조향 물리 미적분·자차 기준 벽 fixture이며 실제 트랙/다중 차량/Gazebo·실물 제동·Jetson 시험이 아니다. 최종 출력 0과 모형 정지를 구별하며 운영 허가를 만들지 않는다.

관련 단위 검사 후 최대 1회 실행한다. 첫 실패는 보존하고 원인 분석 전 재실행하지 않는다. 기존 `--sleep-wall .01 --wall-cap 600`과 정지/종료 감사는 유지한다. 한국 시각 03:30 이후 새 실행을 시작하지 않는다. 커밋/푸시·Jetson/전원 변경 없음.

## 결과

사전 74회귀·ROS **40/40조건**·실행 소스 해시·최종 그래프·정리 감사 통과다. 정상 주행/재진행에서 실제 G1/점별 팽창·반환 보존 진단을 확인했다. 신규 C1 중단·전방 단일 무응답·IMU 중단의 정지/복구 여섯 조건도 통과했다. 각 정지 구간 모형 변위는 약 0.1782/0.1072/0.0942 m로, 실차 또는 Gazebo 제동거리로 인용하지 않는다.

기존 영상 고장 고정·재시작 시 새 출발 신호 요구, 보호층 고장 복구만으로 재출발하지 않음, CLEAR 뒤 DISARMED·별도 ARM 재허가, 마지막 명시 STOP과 그래프 수렴 중 0출력 유지가 보존됐다. MCU deadline 진단 0건이며 과거 간헐 지연의 원인이 해결됐다는 뜻은 아니다.

의도적 fault SIGKILL 3회(영상·제어기·보호층)는 정상 종료 코드와 구별한다. 나머지 비의도 강제 정리 0, 정리 오류/잔존 영상 PID/소유 세션 구성원 0이다. [보고서](ros/report.json)·[상태 전환](ros/events.json)·[소스 사본](ros/source_snapshot.zip)·[실행 로그](runner.log)를 보존한다. 이 제한 회귀 묶음은 마감하며 별도 기본 활성화나 실차 승인으로 사용하지 않는다.
