# 빠른 앞차의 재가속에서 추종을 유지하는 선택형 보완

[원인·첫 U자 기준 실행](../rolling_lead_v1/README.md)은 정지 누적 이력의 초기화 때문에 전진율이 반복해 0이 되던 구간을 기록한다. 이전 단독 속도 설정을 올려도 마지막 재가속 4초의 명령은 거의 그대로였다.

현재는 `recent_forward_reserve=false`를 기본으로 추가하고, 시험기에서 `--handoff-reserve recent`를 명시해야 켜지도록 연결했다. 최근 세 스캔의 전방 이동을 끝점 불확실성 6 cm만큼 낮춰 평가하며 기존 0.5 m/s 상한, 현재 경로·두 벽·정지/우회 판단을 유지한다. 모터축·IMU로 같은 시점에 이송한 센서 점만 쓰고 상대차 정답이나 지도는 제어기에 전달하지 않는다. 준비 감속·우회 진입·독립 보호·차간격 판정선을 변경하지 않았다.

[144개 회귀](pytest.log)를 통과했다. [통합 후 저장 입력](integration_compare.json)에서도 기존 명령·조향·모드를 589/739/838회 재현했고 새 후보는 미연결 시안과 같은 결과였다. [기준 소스 사본](before.zip)과 [소스 변경 계약](../../../../config/tests/recent_forward_r1_sha256.json)을 보존했다.

실제 비교는 [첫 U자 17초](../rolling_lead_v1/run_recent.py)와 기존 정지·재출발 15초를 각각 한 번 사용한다. 코너는 같은 2×5 신호, 정지 시험은 그 기준 실행과 같은 기존 3등 신호이며 서로 시설 차이를 숨기지 않는다. 새 실행은 `rolling_lead_v1/run_recent`와 `stop_recent`에 쌓는다. 미연결 시안은 당시 `bypass_handoff.py`와 조합한 자료이고, 현재 구현 재생은 이 폴더의 `replay.py`를 사용한다.

## 실제 실행과 정리 결과

두 시험을 한 번씩 마쳤다. [코너 원본](../rolling_lead_v1/run_recent/report.json)과 [정지·재출발 원본](../rolling_lead_v1/stop_recent/report.json)은 모두 입력·실행·소스 검증이 유효하고 정상 종료했으나, 기존 행동 판정은 실패했다. [원본별 비교](actual_comparison.json)는 실패 항목을 그대로 보존한다.

| 각본 | 기존 → 최근 전진 보완 | 해석 |
|---|---|---|
| 첫 U자 17초 | 진행 12.018 → 12.078 m, 최종 간격 1.615 → 1.552 m, 최소 간격 0.736 → 0.742 m | 출구 통과·방향 전환·접촉 없음·차체 도로 안·STOP 통과. 최종 간격 1.20 m 기준은 여전히 실패 |
| 정지·재출발 15초 | 진행 4.460 → 4.420 m, 최종 간격 0.444 → 0.489 m, 최소 간격 0.115 → 0.112 m | 접촉·벽 충돌 표본 0, 명시 STOP·재개 판정 통과. HOLD·15 cm 간격·차체 도로 안·뒤 유지 판정은 기존과 같이 실패 |

**기본 채택하지 않는다.** 재가속 뒤 간격 개선은 약 6.4 cm에 그쳤다. 더구나 코너의 6–13초 구간에서 가장 큰 0.30초 속도 하락은 기존 0.294 → 후보 0.988 m/s로 커졌다. 그 감속 창의 독립 보호 표본은 모두 `clear`였고, 준비 감속과 전진 조각에 따른 제한이 번갈아 개입했다. 해당 구간의 준비용 0명령 누적도 0.039 → 0.120초로 늘었다. 반복 실행의 통계는 없으므로 이 차이 전부가 새 로직 때문이라고 단정하지 않지만, 속도 지속성을 개선했다며 채택할 근거도 없다. [기존 제한 분석](../rolling_lead_v1/run1_binding.json)과 [후보 제한 분석](../rolling_lead_v1/run_recent_binding.json)을 남긴다.

종료 요청 당시 정지·재출발 시험은 이미 시작돼 있었으므로 그 실행까지만 마쳤다. 두 실행의 모델 정지·고밀도 자세 정지·MCU STOP은 통과했고 Gazebo/ROS 시험 프로세스도 종료했다. 300초·5랩은 등록·실행하지 않았다. 코너의 예전 노면 감사 도구는 `time`/`t` 입력 형식 차이로 실패했으며, 이 오류를 도로 이탈 증거로 해석하지 않는다.

기존 `surface_contact_eval.py`로 원시 자세를 분석한 [코너 노면 결과](../rolling_lead_v1/run_recent_surface.json)는 12,704표본에서 바퀴 이탈 0이었다. [정지·재출발 노면 결과](../rolling_lead_v1/stop_recent_surface.json)는 최대 두 바퀴 잔디, 벽·바퀴 겹침 0이었다. 따라서 원래 `inside_road` 실패는 차체 전체가 도로를 벗어나지 않는다는 기준의 실패이며, 세 바퀴 이상 이탈을 뜻하지 않는다. [정지 장면 비교](../rolling_lead_v1/stop_recent_compare.json)의 0.30초 최대 감속은 0.881→0.666 m/s로 줄었지만, 출발 후 0.05 m/s 미만 표본의 누적 시간은 0.909→1.214초로 늘었다. 이 값은 연속 정체 시간이 아니다. 두 실행의 [코너](../rolling_lead_v1/run_recent_motor_audit.json)·[정지 장면](../rolling_lead_v1/stop_recent_motor_audit.json) 모터 감사는 단일 모터축 28카운트·8.9706:1·65 mm 설정과 구독을 확인했다.

**다음 재개:** 앞차의 속도 추정을 더 복잡하게 만들기 전에 현재 저장 입력에서 `prepare_hold`와 일반 추종의 전환이 코너 중 불필요한 감속을 만드는 부분을 확인한다. 정지차 우회 준비와 움직이는 앞차 추종의 책임을 분리하는 기존 계획을 유지한다. 동시에 단독 증속·코너 결합의 마지막 코너 진입 속도와 차체/바퀴 감속 차이는 [미채택 결합 실행](../qualifying_profile_v1/README.md)에 남겼다. 재개 시 이 두 경기 성능 문제 중 근거가 분명한 한 묶음부터 진행하며, 후보 기본 활성화·판정선 변경이나 같은 실패의 자동 재실행은 하지 않는다.

**후속:** 위 재개 항목은 [앞차 추종과 우회 준비 분리](../follow_continuity_v1/README.md)에서 다뤘다.
