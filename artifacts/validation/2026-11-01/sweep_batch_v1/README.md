# 정곡률 차체 점유 검사의 묶음 계산

상태: 기존 판단을 보존하는 계산 최적화로 채택했다. 주행 허용 범위나 정지 거리는 바꾸지 않았다.

[41초 단독 완주 입력의 비용 분해](../solo_runtime_cost_v1/README.md)에서 `swept_limit`의 반복 배열 연산을 확인했다. 기존과 같은 4 cm 간격의 차체 위치를 여덟 개씩 계산한다. `math.sin/cos`, 경계 포함 여부, 첫 간섭 위치에서 4 cm를 차감하는 규칙, 점별 여유를 유지했다. [수정 전 소스](before.zip), [차이](source_change.patch), [기준 함수](reference.py), [소스 계약](../../../../config/tests/sweep_batch_r1_sha256.json)을 보존한다.

## 동등성

- 관련 회귀 **411개 통과**. 무작위 점군, 점별 여유, 차체 모서리의 바로 안/밖, 묶음 경계, 빈 점군과 기존 비정상 점 동작을 순차 기준 함수와 정확히 대조했다. 비정상 점 검사에서 기존 계산과 같은 NumPy 경고 2개가 있었다.
- 단독 완주 기록 **2,176판단 전체 일치**, 비용 측정 중 출력 불일치 0, 입력·소스 전후 불변.
- 앞차 급정지 교통 기록 **533판단 전체 일치**. 이번 변경만을 이유로 Gazebo 주행을 다시 돌리지 않았다.

## 비용과 한계

[함수 비교](benchmark.json)는 실제 저장 점군과 즉시 간섭을 포함한 99사례를 다섯 번씩 번갈아 측정했다. 495호출 합계는 **194.960→83.077 ms**, p50은 **0.3305→0.1421 ms**, p95는 **0.8176→0.3326 ms**였다. 모두 같은 거리를 반환했다.

반면 첫 표본에서 바로 간섭하는 11사례에서는 평균 **0.01311→0.03405 ms**로 약 2.59배 느렸다. 첫 묶음 전체를 계산하는 비용이다. 절대 증가는 약 0.021 ms이며, 아래 실제 판단 흐름의 개선과 함께 보고 채택했다. 즉시 간섭이 더 빨라졌다고 주장하지 않는다.

WSL2 x86_64, Python 3.12.3·NumPy 1.26.4, 같은 단독 입력 2,176호출, stream 방식·측정 1회·워밍업 0회다. [결과](run1/report.json), [소스](run1/source_snapshot.zip), [실행 보존](wrapper_manifest.json).

|---|---:|---:|---:|---:|---:|
| 경로 판단 | 4.481→3.627 | 10.491→9.588 | 26.176→25.761 | 45.710→43.826 | 37→38 |

단위는 ms다. 변경하지 않은 투영 단계도 p99 6.987→7.353 ms, 최대 11.245→13.418 ms로 흔들렸다. 단일 측정의 작은 차이를 확정 효과로 해석하지 않는다. 판단의 중앙 비용은 줄었지만 긴 호출과 20 ms 초과를 해소한 것은 아니다. ROS/DDS·영상·독립 보호·MCU·Jetson 처리량과 실제 50 Hz 마감은 이 시험에 포함하지 않는다.

긴 호출을 모두 없애려는 추가 미세 최적화는 지금 수행하지 않는다. 다음은 최신 판단 소스를 다른 환경으로 옮길 때 빠지는 의존 파일을 정리하고, 현행 계획의 대표 교통 장면으로 돌아가는 것이다.
