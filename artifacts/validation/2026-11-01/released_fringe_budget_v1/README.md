# 통과 후 뒤쪽 1 mm 영역의 공백 예산 비교

상태: 관련 회귀 350개 통과. 네 저장 입력의 수정 전 18,654판단 재현을 완료했다. 실패 코너의 228회 정지만 저속 진행으로 바뀌고 새 정지는 없었다. [동일 코너 v3](../corner_parallel_v3/README.md)는 17초 진행 8.679→10.899 m·정체 3.439→0.808초로 개선했으나 출구/최종 간격과 코너 동행은 미달이다. 기본 OFF와 미검증 범위를 유지한다.

[왼쪽 동행차 첫 코너](../corner_parallel_v2/README.md)에서는 앞쪽 경로가 fully_observed이고 독립 보호가 clear였지만, RELEASED 선택기가 뒤쪽 옆면의 1 mm 미만 움직임을 거절해 멈췄다. [원시 광선 대조](../corner_parallel_v2/unknown_probe.json)에서 최초 여덟 새 스캔의 공백 하나는 약 4.32–4.34°, 움직임은 차체 밖 0.489–0.777 mm였다. 양옆 실제 반환은 최소 약 2.26 m였고 결측 원시는 양의 무한대였다.

## 바꾸는 범위

기존 released_rear_sweep_trial 선택이 켜져 있고 현재 옆차 위협이 없으며, 이전 통과 이력을 유지한 RELEASED·속도와 목표 모두 0.35 m/s 이하·전방 경로 fully_observed 조건에서만 호출된다. 기존 1 cm 후반부 움직임의 **공백 하나 3°** 검사를 먼저 수행한다. 그 검사에서 폭 때문에 거절됐으나 미관측 이동 영역 전부가 **차체 후반 옆면 밖 1 mm 이하**라면 기존 **전체 공백 합계 6°** 예산을 공백 하나에도 적용해 다시 본다.

6°는 이번 결과에 맞춰 새로 찾은 각도가 아니라 기존 함수의 공백 합계 상한이다. 좁은 영역에서 그 예산 배분을 바꾸는 **운용 위험 수용**이지, 4.3° 무반환 구간이 비어 있다는 증명이 아니다. 두 공백이 각각 6°를 쓰는 것도 허용하지 않는다. 얇은 돌출물, 반사 실패, 센서/차체 추정 오차, 동적 측방 접근 위험은 남는다.

가까운 실제 점유와 나이별 팽창, 양옆 반환 0.6 m, 시각/원시 매칭, +inf만 있는 구간, 마스크 경계, 현재 옆차 재등장, STOP·입력 이상·기본 경로 정지는 유지한다. 더 큰 움직임에는 기존 3° 검사를 적용한다. GUARD의 1 mm 기준 자체는 바꾸지 않는다. 미관측 수·숨은 물체 위험을 그대로 기록하며 자유 공간으로 채우지 않는다.

기본 OFF와 기존 ROS 선택 인터페이스를 유지한다. 기존 검사로 통과한 결과는 그대로이며, 새 허용만 released_low_speed_body_fringe_v2로 구분한다. [수정 전 소스](before.zip), [후속 계약](../../../../config/tests/released_fringe_budget_r1_sha256.json), [대조 실행기](compare.py).

## 검증 순서

1. 반사 대칭·1 mm/6° 바깥·공백 합계·실제 근접/불량 입력·현재 위협/STOP의 관련 회귀.
2. 수정 전 함수를 보존본에서 불러 과거 전체 판단을 먼저 재현한다. 실패 코너, 단독 완주, 앞차 급정지, 300초 교통 입력에서 새 후보를 같은 입력 순서로 대조한다. 실제 진행이 늘었다고 해석하지 않는다.
3. 필요한 개선과 회귀가 확인되면 동일 왼쪽 코너 각본 한 번을 실행한다. 현재 차체의 위치·후방 간격·접촉·코너 출구/동행 성립을 별도 판정한다. 시뮬레이션 성공이 실차 1 mm 정확도나 안전 보장은 아니다.

## 최초 저장 비교와 기록기 수정

`compare.log`에서 코너 887판단·단독 2,176판단·앞차 급정지 533판단은 모두 수정 전 출력을 재현했다. 코너에서는 228회 0명령이 양수로 바뀌었고 새 0명령은 없었다. 다른 두 입력의 출력 변경은 없었다. 네 번째 5랩 입력은 계산 후 NumPy `int64` JSON 변환에서 실패해 변경 집계가 보존되지 않았다. 그 집계는 추정하지 않는다.

최초 실패 실행기·로그·소스 묶음을 보존하고(`compare_failed.py`, `compare.log`, `source_snapshot.zip`), 현재 제어 소스가 당시 89파일과 같음을 `partial_source_audit.json`으로 확인했다. 비교 실행기는 NumPy 형식을 변환하고 입력별 결과를 즉시 독립 파일로 기록하도록 고쳤다. 새 출력 폴더만 허용하며 기존 결과는 덮어쓰지 않는다. `serialization_smoke.py` 후 마지막 입력만 `replay_finish_v1`에서 대조한다.

## 기록 복구 후 최종 저장 비교

[직렬화 smoke](serialization_smoke.log)는 NumPy 정수·실수·불리언 변환과 기존 파일 덮어쓰기 거부를 확인하고 종료 코드 0이었다. 마지막 5랩만 [독립 결과](replay_finish_v1/comparison.json)로 다시 저장했다. 입력별 결과를 먼저 보존한 뒤 요약을 기록했으며 소스 해시 불변과 현재 파일 일치를 확인했다.

| 입력 | 기존 출력 재현 | 새 출력 변경 | 정지→진행 | 새 정지 |
|---|---:|---:|---:|---:|
| 첫 코너 옆차 실패 | 887 | 228 | 228 | 0 |
| 단독 완주 | 2,176 | 0 | 0 | 0 |
| 앞차 급정지 | 533 | 0 | 0 | 0 |
| 300초·5랩 | 15,058 | 0 | 0 | 0 |

첫 세 입력은 [최초 로그의 보존 요약](first_three_preserved.json), 마지막은 [전체 집계](replay_finish_v1/trace_1.json)를 따른다. 모두 고정 센서 입력의 판단 비교이며, 코너 진행량이나 접촉 개선은 아직 증명하지 않는다. [동일 조건 v3](../corner_parallel_v3/README.md)로 실제 결과를 별도 확인한다.
