# 단독 마지막 코너의 교통 선택·운동 이력 분리

입력은 [저속 재획득 선택 실행](../low_speed_arc_reacquire_v1/HANDOFF.md)의 실패 기록이다. 정지 해제 조건을 새로 늘리기 전에 **처음 0명령을 만든 경로**와 이후 정지가 유지된 경로를 나눴다.

## 저장 입력 비교

| 비교 | 호출 | 원래 출력과 다른 호출 | 45.12 / 45.22초 목표 | 45.32초 이후 |
|---|---:|---:|---|---|
| 원본 재현 | 2,240 | 0 | 0 / 0 m/s | 장애물 기억 잠금 371호출 |
| 운동 이력의 종방향 속도만 평가 정답으로 대체 | 2,240 | 136 | 0 / 0 m/s | 같은 잠금이 생기지 않음. 여전히 교통 선택기가 정지를 요구하는 호출이 있음 |
| 측방 교통 선택기 제외 | 2,240 | 391 | 0.5 / 0.5 m/s | 이미 기록된 급제동 뒤의 속도 이력 때문에 잠금은 그대로 |

근거: [baseline.json](baseline.json), [truth_history.json](truth_history.json), [solo_route.json](solo_route.json), [재현 코드](replay.py). 정답 대입은 44.6초부터 평가 표본이 존재하는 창 안에서만 수행했다. 원래 제어 속도 입력과 실제 저장 궤적은 그대로다. **정답 대입은 진단이며 실제 제어기 또는 다음 주행에 연결하지 않는다.**

최초 재생의 표 생성에서 마지막 판단 시각이 평가 궤적 끝보다 늦어 보간 범위를 벗어났다. `baseline.log`와 종료 코드 1을 보존했다. 표는 가용 범위 밖을 null로 쓰고 운동 이력은 원래 값을 유지하도록 고친 뒤 `baseline_retry.log`에서 출력 변경 0을 확인했다. 외삽은 하지 않았다.

## 두 단계의 정지

1. 45.12–45.22초: 경로와 부분 관측 정책은 0.5 m/s 감속 진행을 허용했지만, 통과한 측방 물체의 이력을 유지하던 선택기가 `large_motion_region_unobserved`로 평행 후보를 선택했다. 그 후보는 `parallel_hold_partial_observation_outside_trial`로 0을 냈다. 단독 프리랩에도 본 경기용 측방 선택이 연결돼 있었다.
2. 45.32초: 실제 차체 종방향 속도는 약 0.81 m/s였지만 모터축 환산은 약 0.08 m/s였다. 이전 반환을 현재로 옮기는 이력의 이동량이 달라지면서 `previous_point_in_missing_sweep` 잠금이 생겼다. 이후 표면 재대응은 일치점 부족으로 실패했고 제한 시간이 지났다. 정지 뒤에도 경로 2.38 m·점유 여유 0.84 m가 있었지만, 소수 무반환 광선 때문에 완전 관측 조건을 충족하지 못했다.

운동 이력 대조는 두 번째 단계에 속도 불일치가 영향을 준다는 근거다. 그러나 바퀴 접촉력은 이 실행에 없으며 마찰·편측 바퀴 접지의 물리 원인은 미확정이다. 첫 정지를 없애면 이후 궤적·바퀴 속도도 달라지므로 저장 재생만으로 잠금 재발 여부를 판단할 수 없다.

## 다음 비교

현재 반환의 점유 검사·부분 관측·독립 보호층을 유지하고, 단독 프리랩에만 측방 교통 선택을 제외하는 [선택 설정](../solo_route_v1/README.md)을 비교한다. 본 경기에는 적용하지 않는다. 잠금 허용치·마찰·토크·정지 판정선을 바꾸거나 정답 속도를 넣지 않는다.
