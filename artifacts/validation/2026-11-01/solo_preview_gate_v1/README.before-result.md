# 코너 예측을 통상 상한 위 목표로 넓히기

상태: **구현·저장 입력 대조 완료, 단독 1회 실행 전.** 기본 OFF이며 명시 프로필 `g1_open_10kmh_solo_gap05_arc_preview`에만 연결한다. 기준은 [37.934초 완주본](../solo_corridor_arc_v1/README.md)이다. [연속 광선 연결](../solo_ray_join_v1/README.md)과 양측 확인 경로 허용은 이 구성에 포함하지 않는다.

## 왜 이 변경인가

[이전 진단](../solo_ray_join_v1/README.md#다음-속도-병목)에서 37.934초본의 가장 큰 상한은 조향 유지 원호 정지거리였다(14.94초, 중앙 실제 속도 약 1.2 m/s). [코너 예측](../turn_preview_v1/README.md)은 이 상한을 현재 경로의 추종 예측으로 재평가해 47.143→44.278초를 만들었지만, 목표가 `max_speed_mps`(1.0 m/s) 이하일 때만 쓰여 정상 경로 35.2초 중 3.2초만 평가됐다. 이 게이트 하나를 명시 단독 프로필에서 양수 목표 전체로 넓힌다.

## 바꾸는 것과 그대로인 것

`preview_above_base_speed`는 `0 < target ≤ max_speed_mps` 조건에서 상한만 뺀다. `turn_preview.py`는 바꾸지 않았다.

- 그대로: 새 스캔의 unknown·가림·이음매 검사, `source_valid`, 0.20 m 연장, 호출 조건의 `open_route`·`target < cap`·`clearance ≥ resume`, HOLD·release wait, 관측 기한, 모터, STOP, 독립 보호, 물성, 감속 계수.
- 새 경로 좌표나 상태 기억을 만들지 않으며 조향도 바꾸지 않는다.
- **속도를 보장하지 않는다.** 올린 값은 기존 경로·곡률 상한 `cap`을 넘을 수 없고, 저장 입력에서 한 호출의 증가는 최대 0.25 m/s다. 독립 보호는 `braking_speed(원호 여유, 나이)`를 그대로 적용하므로, 제어기가 목표를 올려도 원호가 짧으면 `/drive/safe`에서 다시 낮아진다.

## 2 m/s대 예측 가정 검토

- **취득·응답 시간:** 조향 유지 거리는 `속도×(나이+0.10초)`로 예측 속도에 비례한다. `rollout` 속도는 측정 속도·기존 목표·요청 속도 중 최댓값이라 2.4 m/s에서 약 0.48 m를 유지한다. [37.934초본 기록](response_arc.json)의 조향 명령→실제 지연은 궤적 표본 보간으로 10 ms 이내였다(표본 간격 약 46 ms라 정밀한 측정은 아니다).
- **조향 속도:** 예측은 3 rad/s로 제한한다. 같은 값이 제어기 명령 한도이고 가상 서보 한도는 4 rad/s다. 기록의 실제 조향 속도 p99는 2.09 rad/s였다. 속도가 커질수록 거리당 조향 변화가 줄어드는 방향으로 계산된다.
- **기하 여유 `hop`:** 3 cm 예측 표본 간 차체 휩쓸림이며 주행 속도와 무관하다. 이번 확장으로 달라지지 않는다.
- **예측과 실제:** [같은 기록](response_arc.json)에서 예측 경로와 이후 실제 궤적의 최대 거리는 요청 1.5–2.2 m/s 78회 기준 p50 0.021 m, p95 0.070 m, 최대 0.083 m였다. 2.2 m/s 초과는 7회뿐이다. 광선 점유 여유 최소값 약 0.108 m 안쪽이지만, 그 기록의 실제 속도는 후보보다 낮았고 후속 경로 갱신도 포함된 값이다.
- **모델 밖:** 예측은 무슬립 자전거 모델이다. 횡가속 상한 3 m/s²는 `cap`이 유지하지만, 슬립과 실물 서보 응답은 예측에 없다. 실물 조향·제동은 미측정이다.

## 저장 입력 대조

[대조](compare.json)는 옵션 OFF에서 단독 2,006/2,176/1,099/2,069판단과 교통 1,057판단이 기록 출력과 일치함을 확인했다. 교통은 실행 당시 제어기 클래스를 복원하는 기존 재생기로 봤다. ON 명령은 [앞선 메모리 사본](../solo_ray_join_v1/next_shadow.py)의 539/510건과 모두 일치했다.

| 입력 | 명령 변경 | 올림 / 내림 | 새 정지 / 정지 해제 / 조향 변경 | 목표 적분 |
|---|---:|---:|---:|---:|
| 37.934초본 | 539 | 539 / 0 | 0 / 0 / 0 | 51.637→53.745 m |
| 41.075초본 | 314 | 314 / 0 | 0 / 0 / 0 | 51.683→53.192 m |
| 19.837 m 실패본 | 151 | 151 / 0 | 0 / 0 / 0 | 20.855→21.462 m |
| 38.858초본 | 510 | 510 / 0 | 0 / 0 / 0 | 53.470→55.444 m |

37.934초본 기준 예측 평가는 3.2→16.4초로 늘었고 그중 13.2초가 통상 상한 위다. 재생 비용은 호출당 중앙 6.77→7.53 ms, p95 11.73→15.12 ms, 최대 54.81→59.47 ms다(PC 1회). 적분은 주행거리나 랩 시간이 아니다.

## 검증

- [핵심 회귀](tests_focus.log) 224건 통과(종료 코드 0). 새 [게이트 시험](../../../../tests/test_turn_preview_gate.py)은 기본 OFF·단독 조건, 프로필 한 키, 1 m/s 초과에서만 재평가, 가까운 장애물 HOLD와 release wait 유지, unknown·보이는 장애물·짧은 경로·`cap` 경계, 속도에 따른 유지 거리를 본다.
- [영향권 회귀](tests_wide.log) 402건 중 401건 통과. 실패 1건 `test_corner_follow`는 기존 16건 분류 항목이다. [해시 사슬 확인](chain_check.json)에서 시험 자체 목록이 `fresh_confirmation_r2`에서 멈췄고, 이후 40개 계약이 경로 3개의 변경을 설명한다. 이번 변경이 만든 새 손상이 아니며 시험은 고치지 않았다. 전체 저장소 회귀는 돌리지 않았다.
- [수정 전 소스](before.zip), [출처 계약](../../../../config/tests/turn_preview_gate_r1_sha256.json).

## 실행 범위

37.934초본과 같은 2×5·ID45 이동·방지턱 OFF·C1 순차 10 Hz·8.970588:1·28카운트·65 mm·영상 조건의 단독 1회만 수행한다. 실패해도 원인 없이 재실행하지 않는다. [실행 입력](run.py)은 프로필의 옵션 한 키와 출력 폴더만 바꾼다.
