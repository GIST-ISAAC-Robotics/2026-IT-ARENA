# 41초 단독 완주 구성의 PC 판단 비용

상태: 2,176판단의 기존 출력 일치·입력/소스 불변을 확인했고 1회 비용 측정을 마쳤다. 함수별 비용 분해까지 마쳤고, 후속 묶음 계산 비교는 별도 결과로 연결했다.

[단독 완주본](../solo_route_v1/README.md)의 입력·상태 순서를 유지해 기존 판단 전체 일치를 확인한 뒤, 기존 stream 방식 비용 도구로 **측정 1회·워밍업 0회**만 수행한다. 완주를 못 한 0.5초 간격 후보는 측정 대상이 아니다. 반복성이나 최악 지연을 보증하려는 시험이 아니라 다음 최적화가 필요한 단계인지 살피는 범위다.

기록 복원·순차 LiDAR 투영·지역 경로 판단을 포함한다. JSON 읽기/출력 비교, ROS/DDS, 영상, 독립 보호, MCU/모터, 실제 센서 시각 매핑과 Jetson은 포함하지 않는다. 운영 GC·전원·스레드 우선순위는 바꾸지 않는다. 20 ms는 50 Hz 주기의 참고선이며 새 주행 판정선이 아니다.

[wrapper](run.py)는 기존 [비용 도구](../../../../scripts/profile_follow_trace.py)의 구현을 그대로 호출한다. 오늘 추가된 순수 의존 bypass_yield_progress/front_patch_motion/released_rear_sweep/turn_preview의 소스도 스냅숏에 넣는다. 이는 정적 import 관계를 따라 확인한 보관 목록 보완이며 제어기 최적화가 아니다. wrapper 자체의 전후 해시도 따로 남긴다.

## 1회 PC 결과

WSL2 x86_64, Python 3.12.3·NumPy 1.26.4. [원시 보고](run1/report.json), [소스 보존](run1/source_snapshot.zip), [wrapper](wrapper_manifest.json). 기준 2,176판단 일치와 측정 2,176판단의 불일치 0을 확인했다.

| 단계 | p50 | p95 | p99 | 최대 | 20 ms 초과 |
|---|---:|---:|---:|---:|---:|
| 기록 이력 복원 | 0.219 | 0.287 | 0.415 | 0.683 | 0 |
| LiDAR 현재 좌표 투영 | 2.561 | 3.284 | 6.987 | 11.245 | 0 |
| 경로 판단 | 4.481 | 10.491 | 26.176 | 45.710 | 37 |
| 위 단계 전체 | 7.488 | 13.789 | 29.028 | 48.372 | 48 |
| 스레드 CPU | 7.492 | 13.793 | 29.031 | 48.389 | 원시 보고 참조 |

단위는 ms다. GC 누적 관측은 456.873 ms이며 p99는 4.501 ms, 최대는 8.488 ms다. 스레드 CPU와 벽시계가 비슷하므로 이 측정에서는 단순 스케줄 대기보다 실제 계산 비용이 중요했다. 중앙 경로가 안 잡힌 코너에서 회랑 후보를 고르는 그룹 83회가 특히 컸고, 해당 판단 p95 24.80 ms·최대 45.71 ms였다.

20 ms 초과는 이 좁은 오프라인 단계가 명목상 50 Hz 간격을 넘긴 경우다. 이를 전체 온라인 실패로 단정하지도 않고, 반대로 평균이 작다는 이유로 Jetson 처리 여유가 충분하다고 해석하지도 않는다. 같은 실패 상황을 더 늘리지 않고 현재 입력의 함수별 비용을 한 번 분해했다.

## 함수별 분해와 후속

[cProfile 결과](hotspots/summary.json)와 [함수 표](hotspots/functions.txt)는 위 비계측 측정과 구분한다. 계측 중 총 시간은 약 40.27초였고, 반복 Python 호출에 계측 비용이 붙으므로 이 시간을 온라인 지연이나 비계측 함수별 비율로 사용하지 않는다. motion_scene 누적 약 21.11초, 경로 판단 17.90초, swept_limit 3.51초를 확인했다. SensorRay의 많은 객체 생성·검증도 나타났지만 입력 검증을 건너뛰는 변경은 하지 않았다.

반복 충돌 검사만 같은 4 cm 표본의 묶음 계산으로 바꾼 [후속 비교](../sweep_batch_v1/README.md)에서 411회귀, 단독 2,176판단·교통 533판단 일치와 중앙 계산 비용 감소를 확인했다. 즉시 간섭의 작은 비용 증가와 긴 호출은 남겼다. 현재 단계의 미세 최적화는 여기까지로 제한한다.
