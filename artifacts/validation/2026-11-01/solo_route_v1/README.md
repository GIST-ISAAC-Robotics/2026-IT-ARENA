# 단독 프리랩의 측방 교통 선택 분리

상태: **공식 코스 단독 1회에서 41.075초 완주**, 실제 최고 2.397 m/s(8.63 km/h). 접촉·노면 이탈 표본 0, 신호·STOP·정상 종료·소스 불변을 확인했다. 실물 및 반복 재현성을 뜻하지 않는다.

[직전 실패 분석](../solo_latch_motion_v1/README.md)에서 본 경기용 통과 이력이 단독 코너에서 먼저 0명령을 만들었다. `solo_route_only`는 기본 false이며 **단독으로 운영한다고 명시한 시험에서만** 평행 주행·통과 이력 선택기를 생성하지 않는다. 지역 경로·현재 반환 점유·부분 관측 복구 정책·독립 LiDAR 보호층과 STOP은 그대로다. 장애물을 무시하거나 실제 참가 차량의 존재 여부를 정답으로 확인하지 않는다. 운영 설정이므로 본 경기에 사용하지 않는다.

`g1_open_10kmh_solo`는 직전 `g1_open_10kmh_turn15_arc`에서 이 선택 하나만 더한다. 낮은 측정 속도 재획득 후보는 직전과 동일하게 켜져 있지만 그 후보의 실제 재출발은 아직 증명하지 못했다. 최고속도 상한·가감속·기하·마찰·토크·감속비·센서 주기는 같다. [수정 전 바이트](before.zip), [출처 계약](../../../../config/tests/solo_route_r1_sha256.json), [검사](../../../../tests/test_solo_route_mode.py)를 보존한다.

1. 기존 판단 재현, 앞 장애물·전방 무반환 정지, 비어 있는 복도 진행을 확인한다.
2. 저장 입력의 단독 진단과 runtime 설정의 판단이 같은지 확인한다.
3. 빌드·소스 등록 뒤 같은 2×5 신호·ID45 이동·방지턱 OFF·3인칭 영상의 공식 코스 한 랩을 한 번 실행한다. 실패 시 동일 조건 반복 없이 원인을 회수한다.

저장 입력에는 원래 급제동 이후의 바퀴 속도가 남으므로 이 단계만으로 실제 완주를 판정하지 않는다. 원래 본 경기 구성과 실패 증거는 보존한다. 커밋·푸시는 하지 않는다.

## 실행 전 확인

[tests.log](tests.log)에서 365개가 통과했다. 기본 설정은 [baseline.json](baseline.json)의 2,240판단이 동일했다. [runtime_solo.json](runtime_solo.json)의 변경 391호출·83개 스캔별 행은 직전 순수 진단과 같았다. 전체 저장소 회귀를 새로 통과했다는 뜻은 아니며, 기존 실패 13/16건의 범위별 기록은 보존한다.

## 속도 후속 분석

[증속률 명령 대조](rate_shadow.json)는 이전 성공 입력에서 224개 발행 상태를 오차 0으로 재현했다. 증속률 1.5→2.0 m/s²만 바꿔도 최고 명령은 2.508→2.528 m/s이며 2.6 m/s 이상은 양쪽 0초였다. 저장 경로·센서를 고정한 명령 계산이므로 새 차체 궤적 예측이 아니다. 이 변경만으로 추가 주행은 하지 않는다.

[현재 속도 상한 분해](speed_budget.json)는 완주 창의 정상 경로 1,895판단을 최대 오차 4.45e-16 m/s로 재현했다. 현재 조향 원호의 0.8초 시간 간격이 21.36초에서 최저 상한이었고, 그중 6.96초는 기존 코너 예측이 속도를 높였다. 관측 경로 끝의 제동 제한은 6.32초였다. 단독에도 적용되는 추종 시간 간격을 조정하되 정지 거리·현재 점유·독립 제동을 유지하는 후속 비교를 우선한다.
