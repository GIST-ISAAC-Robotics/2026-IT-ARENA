# 관측 경로의 표본 간격 때문에 끊긴 재확인

2026-11-07. [r8 실제 정지](../paired_prefix_v1/README.md)는 새 스캔마다 거의 같은 경로를 보는데도 재확인이1로 돌아갔다. 원시1327명령 재생·내부 기록에서 이를 확인했다.

## 원인과 후보

`path_agrees`는 양쪽 경로의 공통 끝점 사이에 있는 표본만 남기고 길이를 다시 잰다. 27.82초 두 경로의 좌표 차이는0.73 mm인데, 각각0.27 m 이상인 전방 구간에서 끝 표본이 하나씩 제외되어 최소0.25 m 검사를 통과하지 못했다. 센서 미관측/충돌 여부와 별개인 **이미 계산한 경로의 표본화 문제**다.

후보는 계산된 경로의 공통x구간을 선분으로 비교한다. 창0.05–0.65 m·최소 공통길이0.25 m·원래 표본 각5개를 유지하며, 각 경로는 유한하고x가 엄격히 증가해야 한다. 공통 끝점은 기존 선분 안에서만 보간하고 경로 끝 밖으로 연장하지 않는다. 양방향 점–선분 최대거리≤기존0.08 m로 확인한다. 원래 함수의80백분위보다 새 비교의 형상 오차 조건은 더 엄격하다. LiDAR 결측을 보간하거나 관측하지 않은 이동 공간을 승인하지 않는다.

기본 경로 비교를 모두 바꾸는 대신, 명시 직각 후보의 짧은 공통 경로에만 후속 비교로 연결할 계획이다. 서로 다른 새 스캔 확인횟수·TTL·현재 점유·정지 예산·독립 보호층은 유지한다.

## 저장 입력 탐색

`replay_shadow.py`는 공용 코드 변경 없이1327호출을 대조했다. 비교96회가 표본 간격 차이를 넘어 일치했고, 명령376회가 변했다.29초 이후293호출에서 양수 명령, 첫 새 양수는27.22초0.35 m/s였다. 원래 궤적은 고정이므로 실제 진행 증거가 아니다.

같은 경로의 표본 이동은 허용하고, 횡방향9 cm 불일치·짧은 공통구간·역방향 경로·표본 부족·먼 창은 거부했다. r9 교통 실행 종료 뒤 공용 연결을 했다.

## 실제 연결과 실행 준비

`piecewise_wall_trial`과 현재 `short_prefix`일 때에만 기존 점/호길이 비교 뒤 공통 선분 비교를 추가했다. 실제 연결은 사전 후보1327/1327·옵션OFF 기존643/643 명령과 일치했다.

첫 회귀는169통과·3실패였다. 세 실패는 새 시간 확인 시험이 필수 `corner_distance_candidate`/`per_ray_candidate` 설정을 빠뜨려 생성자에서 거부된 시험 fixture 오류다. 실제 실행 헤더에는 해당 설정이 있었다. fixture를 바로잡아 해당 파일12개만 다시 확인하며 기존160개 다른 회귀와 저장 입력 재생은 불필요하게 반복하지 않는다. 첫 실행 중 횡방향 반례값을 수정했으므로 그 파일의 최종 결과는 후속12개를 기준으로 삼는다.

WSL 시작 오류가 다시 발생해 [커널 원문](../wsl_launcher_failure_v1/dmesg_before_recovery.txt)을 보존했다. WSL Interop의 Broken pipe/fatal signal6 흔적은 있지만 유발 원인은 미확정이다. Ubuntu만 종료 후 새 긴 연결의 `verify_then_run.sh`에서 수정 fixture가 통과하면 소스 등록→원래 조건 본선1회→평가를 순차 수행한다. 실패한 launcher 호출을 pytest나 주행 실패로 세지 않는다.

## r10 실제 본선 결과

수정 fixture 12/12 통과 후 입력860개를 등록하고 원래 1 mm 노면·같은 속도/센서/구동 조건으로1회 실행했다. **26.35 m·최고2.56572 m/s·0랩으로 미완주**다. 늦은 정지는 `follow_boundary_unconfirmed`/`long_outer_reference_unavailable`이며 공통 경로 확인 뒤의 경계 인계는 아직 해결되지 않았다.

노면17,606표본에서 차체/조향 외곽 이탈·도로 밖 바퀴·벽 쪽 바퀴0, 접촉0이었다. 명시 STOP·MCU software_stop·정상 종료·잔여 프로세스0과860입력 해시 불변을 확인했다. 시뮬 약34.8초, 실제 약404초. 초기 fixture 실패와 WSL launcher 실패는 별도 원문으로 보존한다. 같은 실패를 즉시 반복하지 않고, 새 직선의 등속 저속차 추월을 확인하면서 긴 현재 벽/직전 승인 경로의 인계를 분석한다.
