# 직각 벽의 두 직선·접선 원호 후보

2026-11-07, 제한 주행 1회 완료·미완주. [단면 이관 기준](../course_section_v1/README.md)의 최초 코너 정지 입력을 분석해 한 모서리 경로 표현을 별도 OFF 옵션으로 비교했다.

## 원인과 범위

- t=13.52/20.22 s의 실제 새 스캔에서 안쪽 왼벽은 `wall_segment_short`, 바깥쪽 오른벽은 `wall_shape_uncertain`이다. 직각 벽을 하나의 3차 매개곡선으로 적합하는 잔차가 큰 경우다. [fresh 입력/그림](../course_section_v1/corner_fresh.json). 이전 전체 재생은 643/643 일치했다.
- 연결 관측 안에서 두 직선과 한 모서리를 확인한 경우에만 같은 벽 오프셋의 접선 원호로 표현한다. 실제 조향 최소 반경보다 작게 만들지 않는다. 직선·짧은 면·여러 모서리/복잡한 곡선은 기존 적합을 사용한다.
- 경로 표현 후보이며 미관측을 자유로 인증하지 않는다. 기존 양면/코너 근거 확인, 점유·속도·독립 보호·STOP을 유지한다. 지도·코너 위치·정답 자세는 사용하지 않는다.
- `--piecewise-wall` / `--g1-piecewise-wall` / `g1_piecewise_wall_trial:=true`를 명시해야 한다. 기본 OFF, B0390·신 코스·같은 고속 프로필로 비교한다.

## 검증과 재개

기하·기존 주행·잡음·기록·출처 회귀 **205개 통과**. 옵션 OFF는 기존 643/643판단을 그대로 재현했다. ON은 같은 저장 입력에서 400판단의 속도가 달라졌고, 13.5 s 이후 양수 명령이 381회였다. 저장 입력 비교 자체는 이동의 증명이 아니다.

같은 B0390·신 코스·속도 프로필에서 실제 주행 **1회: 25.72 m, 최고 2.5577 m/s(9.21 km/h), 0랩**. 이전 9.0 m 정지 지점을 넘어 진행했으나 t≈32.02 s에 `FOLLOW_BOUNDARY_UNCONFIRMED`로 멈췄다. 이때 경로 후보 자체는 `local_path`·관측 앞길 2.452 m였으나 확인 근거는 `long_outer_reference_unavailable`이었다. 전체 완주 성공이 아니다.

- 벽 footprint 접촉 표본 0. 이는 연속 충돌/모든 외형 접촉을 보증하지 않는다.
- 정리 STOP 수락·조밀 자세 정지 통과, Gazebo 종료 확인·자식 종료 `[0,0]`·잔여 시험 프로세스 없음.
- 실제 주행 반환코드 1, 벽시계 369 s, 등록 **853개 입력 변경 0**.
- [주행 보고서](run1/report.json), [등록·소스 묶음](registered.json), [실행 반환코드](run1.exit), [사후 무결성](postflight_integrity.json), [저장 입력 비교](replay_summary.json).
- 첫 테스트 지시는 존재하지 않는 `test_range_noise_path.py`를 적어 수집 전에 exit4로 실패했다. 실제 파일명 `test_local_path_range_noise.py`로 바로잡은 `piecewise_r4_v2`가 205통과 결과다. 오류 로그도 보존한다.
- colcon은 두 패키지 완료·직후 기록한 종료값 0이다. 빌드 wrapper 끝의 CRLF 때문에 `exit: 0\r: numeric argument required`가 별도로 발생했다. 빌드를 재실행하거나 이 wrapper 오류를 숨기지 않았다. 후속 주행 스크립트의 LF를 확인했다.

`before.zip`은 수정 전 소스, `source_snapshot.zip`은 실행한 소스다. 기본값은 OFF로 유지한다. 다음은 정지 입력을 회수해 재개 조건을 남기고 **새 직선 교통·r16 실제 주행 이관**이다. 원인 변화 없이 완주할 때까지 같은 실행을 반복하지 않는다.

## 남은 정지의 재개 근거

[t=31.82 s 실제 스캔](corner_after_t31.82.png)에서는 좌우 경로가 모두 나왔으며 두 경로의 기존 `path_agrees` 결과도 참이다. 왼쪽은 길고 오른쪽 현재 벽의 앞길은 약 0.478 m다. 재획득의 양쪽 긴 관측 조건을 못 채웠으며, 기존 코너 회랑은 반대쪽 긴 벽 또는 아직 굽는 경로를 요구해 이 출구 형태를 받지 못한다. 좌우 역할만 바꾸어 기존 짧은 경로 후보를 호출해도 `path_origin_displaced`로 거절된다. [정적 함수 대조](probe_final_geometry_with_swap.json)는 원시 스캔의 표시용 소수점 3자리 사본을 사용한 진단이고, 새로운 주행이나 허가가 아니다.

따라서 다음 코너 작업에서는 실제 공통 구간을 기준으로 긴 선호 경로를 잘라 쓰는 방법과 기존 낮은 속도 재획득을 비교한다. 선호 벽 선택을 뒤집어 갈림길로 빠지는 변경이나 0.65 m 조건의 일괄 축소는 하지 않는다. 현재 구현에는 이 보완이 들어 있지 않다. 교통 대표 시험을 먼저 진행한 뒤 본선 완주를 막는 이 지점을 보강한다.

후속 설계 후보는 기존 `short_prefix_evidence`의 방향 제약을 다루는 것이다. 현재 함수는 선호 벽이 짧을 때만 실행되고, 선호 벽이 길고 반대 벽이 짧으면 처음부터 거절한다. 역할을 바꾸면 앞쪽에서 시작하는 짧은 경로의 시작점을 차체와의 변위로 계산해 거절한다. 긴 선호 경로를 조향 기준으로 유지하면서 실제 반대 경로와 일치하는 앞부분까지만 자르면 기존 0.25 m 공통 지지·차체 길이 이내 편측 진입·거리 일치·점유/제동 조건을 재사용할 수 있다. **아직 설계 가설이며 적용/허가/진행 증거가 아니다.** 좌우 반전, 실제 다른 물체가 만든 짧은 면, 공통 구간 중간의 불일치, 먼 곳에서만 일치하는 경로를 함께 확인해야 한다.
