# 빨강 이력을 놓친 뒤의 늦은 출발 — 설계 준비

2026-11-07. **후보는 artifact 안에만 구현했다. 저장 RGB 최소 시험을 통과했으나 ROS/주행에는 아직 연결하지 않았다.** 현재 `official_4red_local_candidate`는 빨강4열 이력 없이는 초록을 보아도 출발하지 않는다. 새 코스와 B0390 이관으로 자동 해결되지 않았다.

## 필요한 최소 기능

- 빨강 전체를 앞차에 가려 못 본 뒤에도, 실제 신호가 드러나면 출발한다. 앞차 이동이나 기다린 시간만으로 출발하지 않는다.
- 기존 빨강→초록 경로는 재사용한다. 늦은 출발은 별도 선택형 모드에서 현재 RGB의 ID45(왼쪽)·ID0(오른쪽), 그 사이의 실제 2×5 신호 영역, 녹색 두 광원의 위치/밝기/크기·여러 촬영 프레임을 함께 확인한다. 신호 제어 상태/지도/정답 좌표를 입력하지 않는다.
- 마커가 하나만 보이거나, 두 마커가 서로 맞지 않거나, 영역에 빨강이 남거나, 녹색 한 점/큰 녹색 물체뿐이면 출발로 해석하지 않는다. 배경의 사람·옷/잔디를 신호처럼 읽지 않는 대표 반례를 확인한다. 모든 배경의 보장을 주장하지 않는다.
- 마커 탐지는 영상 작업 프로세스에서 한 번 수행해 ID와 영상 좌표를 재사용한다. ID 중복 후보는 같은 위치인지 구분하며, 공간적으로 떨어진 동일 ID가 있으면 모호한 앵커로 남긴다.
- 촬영시각/세대/STOP·재개 경계는 기존 VisionPipeline을 사용한다. 예전 프레임/중복 프레임으로 확인 횟수를 채우지 않는다.

## 확인 순서

실제 저장된 B0390 RGB의 빨강/초록/소등 → 대표 배경·부분 가림과 순차 프레임 → 새 코스의 높은 앞차 가림 후 실제 RGB 출발 순서다. 정적인 RGB 파일 반복은 시뮬레이션에서 움직이는 앞차 가림을 증명하지 않는다. 표준0.12 m 상대는 현재0.145 m 카메라에서 신호 전체를 가리지 않을 수 있으므로 가림용 높은 차체는 별도 평가 가정으로 표시한다. 실제 B0390 노출·실물 LED의 소등 시 잔색은 미검증이다.

대표 늦은 출발이 성립하면 세부 배경 전수검사 대신 본선 완주·보존한 증속 후보·교통/운영 이관으로 돌아간다.

## 첫 저장 RGB 결과

새 코스 B0390의 실제 `signal_off.png`·`signal_red.png`·`signal_green.png`를 각각 초기 상태에서 검사했다. 소등은 두 광원 미성립, 빨강은 현재 영역 빨강 때문에 출발하지 않았고 초록은 빨강 이력 없이 세 번째 서로 다른 촬영시각 입력에서 확인됐다. 마커 없음/하나/좌우 ID 역전, 동일 시각 반복, 중간 무효 영상의 대표 반례도 출발하지 않았다. 같은 저장 사진을 반복한 검출기 검증이며 실제 가림 후 주행은 아니다. 상세는 `probe.json`·`probe.log`다.

이후 대표 합성 광원·주변 색/부분 가림·마커 중복/시각 반례를 확인하고 영상 작업 프로세스로 연결한다. 실제 LED의 소등 잔색·직사 반사/대회장 노출은 이 결과로 보장하지 않는다.

## 연결 전 필요한 운영 경계

기존 시뮬 실행기는 공식 출발 순서 전에 **팀 시험용 `green_probe`**를1초 켠다. 이 녹색은 실제 출발 녹색과 영상상 동일하다. 빨강 이력 없이 현재 녹색만 허용하면서 같은 영상의 시험 녹색만 거절하는 것은 영상으로 불가능하다. 이 사실을 숨기려고 검사만 삭제하지 않는다.

선택형 늦은 출발은 기존 B3 경기 운영과 함께 연결한다. 준비 전은 기존 정책 래치로 이동을 막고, 운영자의 **신호 대기/prepare_start**가 수락될 때 출발 전 영상 확인을 초기화하고 그 시점 이후 촬영 영상만 받는다. 따라서 준비 전 시험 점등 이력이 이후 소등에서 출발로 재사용되지 않는다. 새 버튼이나 별도 통신 명령은 만들지 않는다. 실제 행사에서는 시험 점등이 끝난 뒤 신호 대기를 선택해야 한다. 준비 뒤 점등된 같은 녹색이 시험인지 공식 신호인지는 센서로 구별할 수 없다는 한계는 남는다.

현재 후보의 저장 이미지 성공은 위 운영 연결의 성공이 아니다. 이 경계와 진행 중 영상 결과의 세대 거절·명시STOP을 확인한 뒤 실제 가림 장면으로 이동한다.

### 구체적 연결 범위

별도 `official_marker_late_candidate` 영상 모드를 추가하되 기본값은 현재 모드로 유지한다. 이 선택은 `race_control_mode=b3_candidate`와 함께만 사용한다. 기존 `prepare_start`→정상 `acknowledge` 수락 시 아직 경기가 시작되지 않았다면 영상 세대·확인 상태를 새로 만들고 취득시각 경계를 둔다. 기존 빨강→초록·같은 경기 STOP/START의 출발 사실은 다른 모드에서 바꾸지 않는다. 새 영상 모드는 아루코 검출 한 번의 ID/꼭짓점을 재사용한다.

필수 회귀는 준비 전 녹색으로 주행 허가 없음, 준비 뒤 소등만으로 이전 녹색 재사용 없음, 경계 전에 촬영된 지연 프레임 거절, 준비 뒤 현재 마커+녹색 확인으로 출발, 명시 STOP 유지다. 이어지는 실제 가림 시험은 현재 신호 점등/마커 모델을 그대로 사용하며 평가자의 신호 단계는 제어 입력으로 연결하지 않는다.

## r12 연결과 실제 시험 준비

`official_marker_late_candidate`와 B3 준비 경계를 구현하고 기본 OFF로 등록했다. 처음 회귀는213통과·1실패였으며, 새 시험 도구가1.7초의 ns 변환값을 같은 float 현재시각보다1 ULP 미래로 만들었다. 실제 수신처럼 촬영1ms 뒤 제출하도록 시험만 수정했다. 중복 준비 요청은 기존 계약처럼 거절되는지도 함께 확인한다. 원본 로그는 `../track_migration_v1/checks/pytest_marker_start_r12.log`에 남긴다.

실제 실행은 새 코스 grid3에서 B0390 앞의 광학 가림판으로 빨강 이력을 놓치게 한다. 판은 라이다 광축 위에 있으며 시각 요소만 갖는다. 앞차의 충돌·추종·운동을 재현하는 시험이 아니다. 기존 HTTP `prepare_start` 후 빨강이 가려진 채 대기→녹색도 처음0.8초 가림→판 제거→현재 RGB로 늦은 출발→1m 이상 진행→명시 STOP을 확인한다. 신호/가림판 조작과 정답 자세는 평가기만 읽으며 차량 입력은 센서 그대로다. 초록 관측 기회는 요청 뒤5초 안으로 제한하며 실패 시 자동 반복하지 않는다. `occlusion_eval.py`·`register.py`·`run.sh`에 고정한다.

### 광학 가림 시험의 평가기 실패 분리

- `occlusion_run1`: 평가판을 world -X 쪽에 배치했지만 실제 grid3 yaw는+90°였다. 저장 `blocked_red.png`에 광원이 그대로 보였고 기존 빨강→초록 경로로 출발했다. 늦은 출발 증거가 아니며 제어기 오출발로 분류하지 않는다.
- `occlusion_run2`: 공식 scene의grid3 yaw에서 전방0.34m로 판을 배치했다. 빨강/초록 가림 두 캡처에서 ID0/45가 모두 없어지고 `late_markers_unavailable`·정지 유지가 확인됐다. 판 제거 직후 평가 기록의 `sim_s` 인자 중복 TypeError로 종료돼 출발/진행/명시STOP은 미확인이다.
- 두 실행은 종료·잔여 프로세스0·등록863입력 불변을 확인했다. 스크립트/원본/보고서는 보존한다. v3는 평가 기록 키만 `removed_sim_s`로 고쳤으며 모든 `note` 호출의 예약 필드 중복을 정적으로 검사했다. 제어기와 신호/센서 설정은 바꾸지 않는다.

## r12 실제 늦은 출발 결과

v3에서 가려진 빨강/초록은 마커 없음·출발 없음으로 유지됐다. 판을 치운 시뮬3.362초 뒤 **3.640초 첫 출발 상태(차이0.278초)**, 운영 화면에서 확인한 차이는0.298초였다. 현재 ID0/45와 `late_green_confirmed`를 사용했으며 빨강→초록 이력으로 출발한 것이 아니다. 녹색 요청 뒤1.130초 안에 확인했고1.006m 진행했다. 운영자 STOP이 수락되고 MCU는 `software_stop`, 최종 평가 차체 속도0.000334m/s였다.

`report.json`의 `passed=false`는 기존 운영 평가기의 초기 자리표시값으로 어느 경로에서도 갱신하지 않는다. 이것을 물리 정지 실패의 원인이라고 해석하지 않는다. UI의 물리정지 `미확인`은 모터축 속도만으로 차체 정지를 단정하지 않는 표시이고, 별도의 조밀한 Gazebo 자세 판정은 `assessment.json`으로 확인한다. 기존 raw 값은 그대로 둔다. 원시 report 완료/exit0, 자식0/0·잔여0·863입력 불변이다.

후속: 실제 높이가 있는 앞차의 운동·신호/마커 일부만 가림·선두 수평 카메라의 위쪽 시야·실제 LED/노출은 남는다. 대표 늦은 출발 연결을 확보했으므로 모든 배경 반례를 전수 확대하지 않고 교통 직각 옵션과 기존 직선 증속으로 이동한다. 새 모드는 기본 OFF이며 B3 준비 전 시험점등/준비 뒤 현재 영상 경계는 유지한다.

보충 판정은 출발/진행·명시STOP·종료·입력 무결성 통과, **조밀한 마지막0.5초 정지 판정 실패**다. 249표본·최대 간격3ms로 자료가 비어서가 아니라 그 구간의 순간 최대0.0562m/s가 원 판정선을 넘었다. 마지막 한 시점 속도가 낮다는 이유로 STOP 전체 판정을 통과로 바꾸지 않는다. 이 짧은 운용 시험의 정지창 결과를 r11 주행의 별도 STOP 통과나 실차에 소급하지 않는다.
