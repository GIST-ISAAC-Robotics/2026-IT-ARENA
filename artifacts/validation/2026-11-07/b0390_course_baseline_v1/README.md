- [사양과 시뮬 가정](../../../../docs/sensors/B0390_SIM_2026_11_07.md): B0390 1280×720·60 Hz·수평 62.2°, 수직은 16:9 핀홀 계산. 실물 Jetson 모드 미검증.
- 기존 JR60P20 C1·IMU·단일 모터축 28카운트·8.970588:1·65 mm 유지. 카메라 모듈 질량 변경은 기존 비교 보정으로 총 질량 유지.
- 새 코스 `official_v2026_11_06` 선택. 구동·속도/정지 판정·기존 경로 설정 동일, 직선 증속 후보 OFF. 0.425 m 벽 오프셋은 이번 기준 주행에서 그대로 두며 다음 분석에서 분류한다.
- 기존 B0183 기본 진입점은 재현용으로 보존. 신규 개발은 트랙과 B0390 YAML을 명시한다.
- `prepare.py`는 이전 소스 ZIP에 이어 출처 계약을 등록한다. `--register`는 첫 주행 전체 입력과 소스를 보존하며 덮어쓰지 않는다.
- `run.sh`는 1회만 실행하고 결과가 실패여도 자동 재시도하지 않는다. 실제 신호·센서를 사용하며 정답은 평가 전용이다.

## 실제 결과

- 관련 회귀 118개 통과(95.19 s). 기존 B0183 실행 인자와 원본 월드 보존 확인 포함.
- **첫 주행 실패: 진행 0 m.** `green_confirmed`, ID 0·45 인식 뒤 `follow_boundary_unconfirmed` 대기로 7초 정지 판정. 새 코스 코너에 도달한 시험이 아니다.
- 접촉 0, 지면 최고 속도 약 1.21e-9 m/s(정지 수치 오차). 정리 STOP 수락·조밀 자세 정지 통과, MCU `ESTOP_LATCHED/software_stop`, 정상 종료·자식 종료 `[0,0]`·잔여 시험 프로세스 없음.
- 실제 실행 반환코드 1, 벽시계 187 s. 등록 850개 입력 변경 0. [보고서](run1/report.json)·[기록](run1_console.log)·[무결성](postflight_integrity.json).
- 원인 후보는 옛 본선의 0.425 m 벽 오프셋이다. 61 cm 코스의 .505 m로부터 양쪽 각각 .08 m 차이가 생겨 양측 경로가 약 .16 m 벌어진다. [단면 대조 후속](../course_section_v1/README.md)에서 같은 입력 비교와 실제 주행으로 분리한다.

빌드 기록 한계: `build.log`에는 두 패키지 완료가 있지만 실행 보조의 wrapper 종료코드 회수에 `exit: : numeric argument required` 오류가 있었다. 보조가 이 로그를 근거로 작성한 `build.exit=0`은 **직접 회수한 빌드 종료코드가 아니다.** 실제 두 패키지 완료 로그·설치 링크·후속 실행과 구별해서 읽는다. 주행 `run1.exit=1`은 run.sh가 실제 반환코드를 기록했다. 빌드만 다시 실행하지 않았다.
