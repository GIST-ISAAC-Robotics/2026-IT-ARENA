# 1차 쌍 뒤 계측 수정과 남은 2회 등록

A1/B1 모두 주행 입력·STOP·실제 정지·정상 종료와 원시/소스 감사를 통과했고 요청 lateness는 둘 다 0 ms였다. A1은 2세대 GC 8회·최대 177.3 ms 정지가 있었다. B1은 GC 0세대 1회(0.133 ms)가 계측 시작 35.8 ms 후에 남아 있어, 사전 수용 조건 `GC delta=[0,0,0]`을 충족하지 못했다. **B1 결과는 성공으로 소급하지 않는다.**

코드 순서 확인: `collections_before`를 먼저 읽은 뒤 최초 `resource` import(RSS 수집)를 하고, 그 뒤 `gc.disable()`했다. 따라서 연기를 적용하기 전 준비 할당을 계측 창에 넣는 오류가 있었다. defer 적용을 진단 할당/RSS 호출 앞으로 옮기고 해당 순서/시작 실패 복원 회귀를 추가한다. 구동/보호/판정선·실행기 발행 로직은 그대로다. r3 원본·source ZIP을 보존하며 helper만 변경한 r4 계약을 등록한다.

남은 신규 실행은 **A2(native r4) → B2(defer r4)** 한 쌍으로 변경한다. 신규 총 4회 상한은 유지하고 추가 재시도하지 않는다. 두 코드 버전을 동일 입력 반복으로 묶지 않는다. 수정본도 같은 10 ms·정지·종료·원시 무결성·메모리 기준을 적용한다. 원래 ABBA 반복 설계는 완수하지 못한 것으로 기록하며, 수정본 1쌍은 기능 대조이지 재현성/분포/실차 지연 제거 증거가 아니다.
