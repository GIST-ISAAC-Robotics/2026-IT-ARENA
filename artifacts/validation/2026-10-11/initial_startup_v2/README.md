# 초기 배치 반복과 남은 명령 적용 변동의 분리

2026-10-11. GPT 주 에이전트가 설계·분석·검토, GPT-6 Luna가 실행·대기·결과 회수를 맡는다.

## 실행 전 등록

- 이전 `initial_startup_v1/e2_embedded`와 같은 r6 소스·바이너리·명령·물성으로 E3를 한 번 실행한다. 이전 E1 실패와 v1의 당시 반복 미충족 판정은 그대로 보존한다.
- 새 결과는 `e3_embedded`에 저장한다. 기존 실행 경로를 재사용하거나 성공할 때까지 재시도하지 않는다. E3 실패 시 해당 증거를 먼저 분석한다.
- 기존 입력·정지·종료·해시 감사와 첫 물리 갱신 iteration 1 / sim 1 ms / dt 1 ms, 해제 전 paused/sim 0 조건을 유지한다. E2/E3의 동일 소스·모델·월드·메시·프로필·pose와 명령 시작 시각을 대조한다.
- 초기 배치 반복 확인과 전체 물리 결정성을 구분한다. 두 실행의 요청 → safe → MCU → 출력 → 플러그인 수신/적용 전환 및 최초 물리 분기를 기존 원시 자료로 비교한다. 원인 확정이 아니라 어느 구간에서 차이가 관측되는지 분리한다.
- 추가 실행이 진단에 필요하면 목적·조건을 먼저 추가 기록하고 같은 작업 안에서 수행한다. 불필요하게 별도 사용자 턴을 요구하지 않는다. 제어/보호 계약 변경·물리 정답 입력·기본 모델 변경·G1/G2/고속 확장은 하지 않는다.
- 커밋·푸시·외부 게시·Jetson·전원 변경 없음. 기본 startup은 service, GC는 native 그대로다.

`prepare.py`는 원래 E2 계획의 출력 경로/이름만 바꾸고 현재 r6 계약 소스·바이너리 불변을 검사한 뒤 실행 전 사본을 보존한다. `run.sh e3_embedded`가 유일한 초기 실행이다.

## 결과

E3는 exit 0, 입력·STOP·실제 정지·정상 종료·소스/원시 감사 통과. 요청 최대 지연 0 ns, 시작 iteration 1 / sim 1 ms / dt 1 ms, 준비 해제 11.9545초(벽시계), 잔존 프로세스 0. E2/E3의 소스·모델·월드·메시·프로필·pose·명령 시작 시각이 일치하여 이번 **두 실행의 초기 배치 반복 확인은 완료**했다. v1 당시의 실패/미완료 기록은 그대로 보존한다.

요청·safe·MCU의 속도 16/조향 11 전환 stamp는 같았다. 출력 진단 속도는 7/16에서 ±1 ms, 플러그인 적용은 속도 8/16·조향 5/11에서 ±1 ms 달랐다. 모든 전환은 수신 뒤 첫 step 적용이었다. 첫 적용 차이 0.656/0.657 s 뒤 0.658 s부터 운동 진단이 갈렸으며 기존 주 제동 지표 7개 모두 반복 허용치 밖이었다. 한 실행이 개선됐다는 의미가 아니며, 명령 적용 결정성·물리 수렴·실차는 미검증이다.

관련 회귀 80개 통과. 런타임 r6와 기존 바이너리는 그대로이고 새 코드는 사후 분석기/그 회귀뿐이다. 다음 구현 위치·보호 조건·수용 기준은 [기술 보고서](../../../../docs/autonomy/LOCAL_FOLLOW_G1B_2026_10_07.md#1011-반복-마감--초기-배치-확인과-출력-이후-변동-분리)에 정리했다. 전체 1,367개 회귀는 이전 작업 결과이며 이번 검사 수와 합산하지 않는다.
