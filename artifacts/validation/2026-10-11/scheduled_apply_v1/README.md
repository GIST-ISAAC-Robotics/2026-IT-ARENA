# 평가 전용 예약 적용 — 사전 등록

기존 E2/E3의 상위 입력은 같았지만 출력/플러그인 적용이 ±1 ms 달랐다. 이번에는 기본 경로를 유지하면서 평가 전용 출력만 원래 MCU stamp + **20 ms**의 미래 1 ms 물리 step에 적용한다. 속도·조향은 하나의 순번/epoch/유효 기한으로 묶는다. 추가 20 ms는 실험 조건이며 실차 지연 개선이 아니다.

- GPT 주 에이전트가 구현·분석·검토, GPT-6 Luna가 빌드·시험 실행/대기/회수를 담당한다.
- `/drive` → 독립 LiDAR 보호 → `/drive/safe` → MCU → 기존 `AppliedGuard`는 보존한다. 플러그인에 프로필/정답 운동을 직접 넣지 않는다.
- 정상 감속과 0목표는 예약 대상이다. 명시 STOP/보호 개입/유효 기한/watchdog는 예약 양수 명령을 취소하고 바로 0으로 만든다. 재시작은 새 ARM 경계가 필요하다. ACK/순번/epoch/시각 오류는 시험 실패를 latch하며 자동 복구하지 않는다.
- 실제 수신/적용/cancel ACK와 송신 원본을 별도 보존한다. 기존 저빈도 전환 trace의 수신 표지는 예약 모드에서 적용된 envelope의 표지이며 전체 ACK를 대신하지 않는다.
- 선택형 모드는 evidence·headless·embedded_paused·local·guarded·autonomy 꺼짐 조건으로 제한한다. 기본 service/native·물성/토크/제동식·단일 모터축 28카운트·15:1·65 mm·제어/센서·보호 한도는 변경하지 않는다.

## 실행 계획과 수용 조건

1. 단위/보호 회귀 및 빌드. 최초 감사기의 wire 필드 수 오류(실제 9개를 10개로 검사)는 `pretests.log`에 보존하고 수정 후 `pretests_v2`로 확인한다.
2. N1 기본 출력 경로 1회: 새 바이너리에서 선택형 예약 기능이 꺼진 경로의 입력·정지·종료/형상 확인.
3. T1/T2 예약 출력 2회: 같은 r7 소스/바이너리·공식 분할 노면·기존 3.5초 프로필·phase 10 ms·수동 제동 근사·GC defer·embedded_paused. 1 ms 물리 step 유지.
4. 같은 source/profile/model/shape/start와 유효 입력을 확인한 두 예약 실행의 모든 정상 적용 envelope 값/원래 stamp/적용 step을 비교한다. 부팅 UUID는 실행별로 다르므로 그 값 자체는 반복 일치 대상이 아니며 각 실행 내부 epoch 불변성은 따로 검사한다. STOP 수신은 비동기이므로 정상 적용과 분리한다.
5. 기존 요청 지연 상한·source/raw SHA·발행 그래프·시작 준비·실제 정지·명시 STOP·정상 종료·잔존 0 및 ACK 감사가 모두 통과해야 기능 확인으로 인정한다. 신청만 하고 ACK가 없거나 미검출 메시지를 생략한 시험은 통과시키지 않는다.
6. 적용 값/step이 같아진 뒤에도 물리 결과가 갈리는지 기존 제동 지표/허용치로 별도 분석한다. 적용 시각 일치를 물리 결정성/실차 제동으로 확대하지 않는다. 기존 실패는 보존한다.

`before_source.zip`/`before_manifest.json`과 기존 바이너리는 변경 전 보존본이다. `registered_source.zip`/`registered_manifest.json`은 실행 전 r7 소스와 빌드 SHA다. 세부 원시 수신은 로컬 보존/Git 제외한다. 실패 시 원인을 고쳐 새 실행 이름·후속 계약으로 기록하며 실패를 덮어쓰거나 판정선을 완화하지 않는다. G1 재대조·오른쪽 가림·G2·고속·Jetson·외부 게시·커밋/푸시는 이번 범위가 아니다.

## 마감

N1/T1/T2 모두 통과했다. 예약 쌍 정상 적용 741개와 운동 진단 367개가 일치하며 주 제동 지표 7개 차이는 0이었다. 단, 0목표 후 바퀴–차체 차이 0.40449 m/s는 남는다. **최종 회귀 1,410개 통과.** 상세 결론은 [기술 보고서](../../../../docs/autonomy/LOCAL_FOLLOW_G1B_2026_10_07.md#1011-예약-적용-마감--같은-명령의-적용-시점과-제동-반복-확인), 기계 판정은 [analysis_final.json](analysis_final.json), 보존 검사는 [final_manifest.json](final_manifest.json)을 따른다.

`build.log`의 중복 패키지는 보관 소스를 colcon이 검색한 문제였다. 소스 보관본을 바꾸지 않고 `--base-paths src`로 수정하여 `build_v2`가 통과했다. `pretests` 최초 실패와 모든 중간 분석/회귀 출력은 보존한다. 재현은 ROS 환경에서 `run.sh`의 명령을 참고하되 기존 출력 이름을 재사용하지 않는다.
