# G1-b: Gazebo 상대차와 저속 폐루프 추종·대기

작성: 2026-10-07. 상태: **작성 중 — 결과 미기입**.

## 범위와 기준선

[G1-a](LOCAL_FOLLOW_G1_2026_10_05.md)의 선택형 추종기(`g1_follow`)를 실제 Gazebo 상대차·렌더링된 순차 C1 광선·독립 LiDAR 보호층·가상 MCU와 연결해 공식 코스 출발 직선에서 저속(명령 ≤ 1.0 m/s) 폐루프로 시험한다. 정지한 중앙 앞차, 0.35 m/s 등속 앞차, 앞차 정지 후 재출발의 세 사례이며, 수치 튜닝으로 통과시키는 것이 아니라 센서 관측·경로·간격·실제 정지·재진행·정상 종료의 증거를 남기는 것이 목적이다. 사용자 지정에 따라 구현·원인 판단은 Claude Opus 5.5, 시뮬레이션 실행·대기·로그 회수는 Claude Sonnet 5.5 서브에이전트가 맡았고 GPT 주 에이전트가 수용 조건과 최종 검토를 맡는다.

추월·우회(G2/G3), 고속화, 전체 5랩, 코너·옆차·벽 가림 반례, Jetson, 새 구매·센서 위치 변경은 이번 범위가 아니다. 센서·차량 설정(B0183+C1+LSM6DSOX, 20×15 cm·약 2 kg, 모터축 28카운트×15:1·65 mm 바퀴·축거 0.135 m, C1 측정면 0.095 m·전방 0.06 m·후방 60° 마스크)은 바꾸지 않았다. 출발 트리거는 기존 임시 RGB 빨강→초록이며, 10/6 공식 소등 출발 재설계와는 별개다. 노면 이탈은 기존 보수적 차체 외곽 기준을 유지하며 10/6 잔디 완화 메모는 적용하지 않는다.

작업 시작 HEAD는 `25dea6045098105a1289ac8ffdb9b2b366c16edb`이고, 앞 세션의 미커밋 G1-a 변경과 10/6 공식 문서 갱신이 작업 트리에 있었다. [시작 상태](../../artifacts/validation/2026-10-07/g1b_start_state/)에 상태·diff·해시를 남기고 그대로 보존했다.

## 시험 구성

### 상대차(actor)

- 평가 전용 정적 상자 `eval_g1b_actor`: 0.20×0.15×0.12 m, 바닥 0 m, 공식 중심선 위(횡 오프셋 0). C1 측정면(0.095 m)이 상자를 가로지르므로 **센서를 향한 면의 20×15 cm 직사각형 단면이 관측 가능**하다. 측정면보다 낮은 차량은 표현하지 않으며 이 결과를 보이지 않는 낮은 차의 안전으로 확대하지 않는다.
- 공식 `world.sdf`·`scene.json`과 보존 ZIP은 바꾸지 않았다. `simulation.launch.py`에 기본값이 빈 `evaluation_actor_sdf` 인자를 추가해, official·`local_pursuit` 실행 사본(`runtime_world.sdf`)에만 `eval_*` 이름의 정적 모델과 접촉 시스템 플러그인을 넣는다. 다른 요소·이름 중복·비정적 모델은 거부한다.
- 평가기가 자체 `parameter_bridge`로 `set_pose`(50 Hz 이하)를 보내고, 모델의 PosePublisher(100 Hz) 자세와 접촉 센서는 평가기만 구독한다. 일정 기준 시각은 평가기가 처음 본 `applied=green`이며 제어기는 자기 카메라로 출발 신호를 판정한다.
- [격리 확인 실험](../../artifacts/validation/2026-10-07/g1b_contact_probe_v1/report.json): set_pose로 옮긴 정적 actor의 충돌체가 새 위치에서 동적 상자와의 접촉을 보고했고(33개 메시지), 옛 위치에 낙하시킨 상자는 바닥(z≈0.050 m)에 놓여 잔상 충돌체가 없었다. 단, 완전히 겹치도록 순간이동한 경우 상대 상자를 밀어내지는 않았다. 따라서 actor는 무한 질량 장애물이며 차량 동역학 모형이 아니다.

### 비교 조건

G1은 `g1_follow.launch.py`, R0는 기존 평가기와 같은 `demo.launch.py`의 기본 `local_pursuit` 경로다. 두 방식 모두 순차 C1 10 Hz·both 보정·제어 50 Hz·독립 보호층·virtual MCU·방지턱 해제·그리드 슬롯 3을 사용한다. 속도 조건을 맞추기 위해 `exploratory`와 같고 명령 상한만 1.0 m/s인 `g1_compare_1mps` 프로필을 추가했다. G1의 실효 상한은 기존에도 `min(1.0, 프로필)`=1.0 m/s이므로 G1 동작은 같고, R0만 1.4 → 1.0 m/s로 맞춰진다.

### 시험 전 등록한 판정선

정확한 값은 [시험 설정](../../config/tests/g1_traffic_v1.json)이 기준이다. 결과를 본 뒤 완화하지 않으며, 바꿀 때는 새 버전과 재시험을 남긴다.

| 항목 | 판정선과 근거 |
|---|---|
| 차체 간격 | 표본 간격과 **보수적 swept 하한** 모두 ≥ 0.15 m (G1-a 사전 기준). swept 하한은 표본 사이 강체 평면 운동·단조 yaw·곡률 ≤ 3.0 /m 가정에서 두 끝 차체 외곽을 `2·r·|Δyaw| + κd²/8`만큼 깎은 값이며, actor는 창 안의 모든 순간이동 자세를 합친다 |
| 접촉 | actor 접촉 센서의 자차 충돌체 접촉 메시지 0 |
| 벽·노면 | 정적 벽 충돌 표본 0, 20×15 cm 차체의 SDF 노면 밖 면적 표본 0 (모든 자세 표본) |
| 정지 앞차 | 10초 창에서 연속 HOLD·`/drive/safe` 0·모델 속도 < 0.01 m/s ≥ 3.0초, 창 끝 간격 ≤ 0.70 m(초기 1.40 m의 절반: 접근 후 대기와 출발점 정체를 구분) |
| 등속 앞차 | 12초 창에서 진행 ≥ 2.5 m(앞차 4.2 m), 처음 움직인 뒤 앞차 이동 중 0.05 m/s 미만 정지 지속 ≤ 2.5초(G1-a 재출발 한도 재사용), 창 끝 간격 ≤ 1.2 m |
| 정지 후 재출발 | 앞차 정지 구간 [4, 9]초 안에서 연속 정지 ≥ 1.0초, 앞차 재출발 후 2.5초 안에 0.10 m/s 초과, 재출발 후 진행 ≥ 1.0 m, 창 끝 간격 ≤ 1.2 m |
| 정지 확인 | 창 종료 후 명시 MCU STOP: 6초 안에 0.5초 안정 정지, `ESTOP_LATCHED/software_stop`, 출력 0. STOP 전 MCU 고정 고장 0, 마감 진단 0 |
| 실행 유효성 | actor 실행 사본 존재·출발 전 자세 수신·자세 공백 ≤ 0.05초·명령 간격 ≤ 0.10초·이동 추적 오차 ≤ 0.035 m·정지 오차 ≤ 0.005 m(하네스 실패는 제어기 결과로 세지 않음), 센서 전용 구독, `/drive`·`/drive/safe` 발행자, actor 자세 구독자는 평가기뿐, 순차 취득·LiDAR 인터페이스, 신호 순서·조기 출발 없음, 소스 불변, 정상 종료·잔존 없음 |

R0는 같은 판정선을 계산해 비교하지만 통과 조건이 아니다. 행렬은 G1 3사례×seed 0/1/2, R0 3사례×seed 0이다. Gazebo에는 주입 잡음이 없으므로 seed는 actor 출발 위치를 0/−0.10/+0.10 m 옮겨 스캔·명령 위상을 바꾸는 고정 값이다. 모든 actor 최종 위치는 첫 코너(s=5.3 m) 1.0 m 전에 머문다.
