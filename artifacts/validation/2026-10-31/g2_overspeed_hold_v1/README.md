# 순간 측정속도 상한 초과 — 기하 보관의 저장 입력 비교

2026-10-31. [후보 범위](PLAN.md)의 반례 9개와 저장 입력 비교를 통과했다. source·입력·footer 무결성을 확인했고 런타임/기본값은 바꾸지 않았다.

- 재출발 실패의 시뮬레이션 절대40초까지 1,603개 판단을 원래 제어기로 모두 재현했다. 24.64초의 1.02102 m/s 입력에서 측정값은 그대로 보존하고 명령 0·기하 보관을 확인했다.
- 25.32초에 현재 관측과 서로 다른 2개 스캔 조건을 만족해 다시 0.35 m/s 후보가 나왔다. 기존 0명령에서 양수 후보로 바뀐 호출은735개이며, 추가 0명령과 상한 초과 보관 중 양수 명령은 0개였다.
- 직전 정지차 코스 성공의 7,804개 판단을 전부 재현했고, 후보의 속도/조향 명령 변경은 0개였다.

이는 원래 차체가 멈춰 있던 **저장 센서 입력**에서의 대조다.735회 양수 후보가 새 실제 이동이나 정상 FOLLOW 복귀를 뜻하지 않는다. 이 비교에서도 기록된 차체는 움직이지 않으므로 실제 복귀 여부는 별도 폐루프 시험이 필요하다. 기하 보관은 슬립을 보정하거나 엔코더를 차체 속도로 변환하는 기법이 아니다.
