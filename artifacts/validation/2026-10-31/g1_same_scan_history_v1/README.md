# 같은 스캔 대기와 통과 이력 — 후보 비교

2026-10-31. [원인과 설계](PLAN.md)의 후보를 별도로 시험했다. 운영 소스는 이 비교 동안 변경하지 않았으며, 이후 실행 연결은 [별도 기록](../g1_same_scan_history_connection_v1/PLAN.md)으로 구분한다.

19검사에서 같은 스캔 대기 중0명령, 새 스캔 이전 복원 금지, 새 장애물·미관측 이동영역·시각/epoch/잘못된 입력 거절, 미완료 통과 이력을 만들지 않는 조건을 확인했다.

| 입력 | 원본 동일 재생 | 후보의 변화 |
|---|---:|---|
| 실제43.613 m 정체 입력,74.5초까지 |3328/3328|71.50초 대기는0명령 유지.72.02초 새 스캔/경로 확인 뒤125호출에서0→0.35 m/s. 추가 감속0|
| 이전 정상 코스 전체 |7815/7815|속도·조향 명령 모두 동일.133.80/133.82초의 이력 보관·복원 진단2개만 변화|

[기계 결과](run1/summary.json)의 실패 입력 전체 기록은7792호출이지만, 후보 비교는 첫 문제를 포함한3328호출까지만 실행했다. 정상 입력은 전체를 비교했다. 입력·당시 소스·footer 무결성을 확인했고 원본 실패와 소스를 보존했다.

새 진행은 고정 입력에서 계산한 명령이다. 실제 차량이 움직인 다음에도 같은 결과가 유지되거나 전체 코스를 완주한다고 결론 내리지 않는다. 현재 이동영역 확인을 거쳐 진행한 사유는 `released_bounded_same_path_gap`이며, 기존 관측 정책의 위험 한계를 그대로 가진다.
