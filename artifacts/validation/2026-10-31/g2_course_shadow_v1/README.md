# 명시 G1/G2 연결의 기존1랩 저장 비교

2026-10-31. 기존 방지턱·교통1랩 `2026-10-28/bump_traffic_v1/run4`의 센서 기록을 그대로 사용했다. 현재 G1과 명시 `corridor_local_v1` 자동 연결을 나란히 계산했다. 입력·소스 해시와 시험 당시 소스ZIP을 보존했다.

| 확인 항목 | 결과 |
|---|---:|
| 원래 G1 판단 재현 | 7,801 / 7,801 |
| 자동 연결 내부 G1 상세 보존 | 7,801 / 7,801 |
| 우회 상태 진입 | 0회, 전부 FOLLOW |
| 명령 변경 | 1,536회 |
| 기존 양수 명령이 새0명령인 호출 | 1,513회 |
| 처리시간 p50 / p95 / 최대, G1 | 14.11 / 27.35 / 67.48 ms |
| 처리시간 p50 / p95 / 최대, 연결 후보 | 15.94 / 29.89 / 68.01 ms |

첫 차이는 시뮬레이션 시각9.34초에서 1→0.35 m/s 준비 감속이었다. 변경1,535호출은 `observed_entry_distance_reserve` 분기와 함께 발생했고, 그중1,438호출에서는 앞차 조각의 이동도 관측했다. 가장 긴 진입 전이1.2 m를 보존하는 전략이므로 기존의 더 가까운 추종 궤적에서는 추가 대기가 생긴다. 나머지1호출은 음의 측정속도 대기다. 이 비교에서 코너의 우회 오진입은 나타나지 않았다.

**첫 다른 명령 이후에는 실제 자차 위치도 달라질 수 있다.** 따라서1,513호출을 실제 추가 정지시간으로 환산하지 않으며 새 제어기의 완주·교착·1.2 m 유지 능력을 입증한 결과도 아니다. 이 전략의 실제 진행량 손실과 전환을 [별도1회 코스 주행](../g2_course_trial_v1/PLAN.md)에서 확인한다. 비용은 현재PC 함수 계측이며 ROS50 Hz/Jetson 처리율 증명이 아니다.
