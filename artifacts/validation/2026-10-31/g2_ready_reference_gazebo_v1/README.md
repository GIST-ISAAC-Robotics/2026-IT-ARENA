## run1: 주행 전 실행 파일 누락

평가 검사9개와 prepare1135파일·사전 검사는 통과했지만, 실제 launch가 참조한 이 시험 폴더의 `simulation.launch.py`가 없어 즉시 실패했다. `run1/simulation.log`의 `Errno 2`와 `report.json`의 `owned process exited early`, 시작 하위 프로세스0개를 보존했다. 주행·STOP·재생은 미실행이며 잔류 프로세스도 없었다. 이를 차량/제어기 주행 실패나 성공으로 세지 않는다.

공통 prepare는 이 파일을 생성하지 않는다. 이전40초 시험의 동일 handoff 연결 파일을 바이트 그대로 복사했고, 실행 전 해당 의존성의 존재·소스ZIP 등록·해시 일치를 요구하도록 검사했다. 누락/미보존/변경을 거절하는 회귀도 추가했다. r2 제어기·센서·물성·상대차·평가 기준은 바뀌지 않았다. run1 원본은 그대로 두고 `run2_trial.sh`로 다시 실행한다.

## run2: 실제 우회·복귀와19.657 m 후속 진행

사전10검사·1138파일 보존·실행 전 검사 후40초 실제 주행을 완료했다. 원래 평가기 `run2_evaluation.json`은 복귀 후 진행만0 m로 산출해 실패했다. 실제 trajectory의 요약 상태 필드는 `autonomy.behavior`인데 평가기가 `handoff_state`를 읽었기 때문이다. 원본 평가기·실패 결과를 보존한 채 `evaluate_v2.py`와 실제 기록에서 발췌한 schema 회귀를 추가했고,11검사와 [저장 기록 재평가](run2_evaluation_v2.json)가 통과했다. Gazebo를 재실행하거나5 m 기준을 낮추지 않았다. 전후 원시 입력 SHA도 동일하다.
