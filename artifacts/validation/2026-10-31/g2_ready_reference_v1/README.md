# 준비 상태에 한정한 초기 벽 기준 보완

2026-10-31. 기존 거리 보존은 유지하고, 현재 반환으로 추가하는 양벽 기준만 기존 `observed && ready && !motion_evidence` 조건에 한정했다. [10/30 예약 전체 생략](../../2026-10-30/g2_moving_reserve_v1/README.md)은 이동 후 정지할 때 진입 공간을 잃었으므로 반복하지 않았다.

**정상1랩의 추가 감속은561→22호출, 추가0명령은350→6호출로 감소했다. 정지차 입력의 우회 진입 판단과 기존 우회 성공 기록의 명령은 유지했다.** 저장 입력의 제안이며 실제 랩타임·정지 횟수 개선이나 새 우회 완료가 아니다.

| 입력 | 호출 | 기존 코드 판단 동일 | 후보 명령 동일 | 후보 추가 감속 / 추가0 | 상태 |
|---|---:|---:|---:|---:|---|
| 준비 유지40초 실패 | 2,041 | 2,041 | 1,978 | 0 / 0 | 13.12초 BYPASS 진입 판단 |

| 기존 복합오차 우회 전환 | 1,057 | 1,057 | 1,057 | 0 / 0 | 기존 전이 유지 |

세 입력 모두 G1 내부 상세가 전부 같고 입력 SHA·footer·실행 소스 불변을 확인했다. 준비 미완료/이동 근거·현재 반환 없음·원래 기준 보존·같은 호출에서 갱신된 준비 상태·고장 초기화 및 별칭 복구11검사가 통과했다. [결과와 해시](run1/summary.json), [검사](tests1.log), [실행](run.sh).

정상1랩의 남은22변화는13.22–13.82초의 첫 앞차 대기 구간에만 있다. 모두 `observed_entry_preparation`이며, 준비에 이동 근거가 있는데 새 기준 때문에 감속한 경우는 제거됐다. 원래 기준이 이미 유효했던 곳의 기존 예약 비용을 전부 없앴다는 뜻은 아니다.

40초 입력의14.28초 FOLLOW는 이전 후보와 마찬가지로 저장된 음수 피드백/G1 `hold_fault`로 인한 초기화다. 우회 후 복귀 성공으로 쓰지 않는다. 후보 계산p95는 각각36.39/32.57/49.17 ms, 최대76.45/111.97/79.71 ms였으며 PC 저장 입력 계산 비용이다.
