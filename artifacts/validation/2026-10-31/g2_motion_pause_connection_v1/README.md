# 선택형 운동 대기 연결 결과

`HandoffExecutionConfig.motion_pause_policy`와 ROS `g1_g2_motion_pause_policy`를 추가했다. 기본은 `off`다. `bounded_motion_pause_v1`은 명시 `corridor_local_v1`·`corridor_v2_signed_hold` 설정에서만 허용한다.

- 일시적인 양수 측정 상한 초과: 목표 속도는 0, 측정값은 그대로 유지한다. 기존 기억 TTL 0.3 s와 실제 운동 이력 안에서만 경로를 옮겨 보관한다. 지속 초과·입력/시각 고장·이송 불가이면 삭제한다.
- 유효한 음수속도 대기: 기존 BYPASS/REACQUIRE와 경로가 있고, G1의 정확한 음수 대기 사유·측정값이 일치할 때만 G2 signed 정지로 넘긴다. FOLLOW나 실제 입력 고장은 원래 초기화 경로를 유지한다.
- 재개: 현재 경로/벽/점유 검사를 통과하고 서로 다른 두 새 스캔의 확인이 필요하다. 경로를 기억한다는 사실만으로 주행하지 않는다. `/drive`와 독립 보호층을 유지한다.

## 검증

[실행 로그](tests1.log)의 관련 회귀 **718개 통과**. 빌드와 설치된 Python 소스 **81개 바이트 일치**. [연결 재생 결과](run1/summary.json):

| 입력 | OFF 원본 판단 동일 | ON 보존 후보 속도·조향 동일 |
|---|---:|---:|
| 원래 단차 재출발 실패, 절대 40 s까지 | 1,603/1,603 | 1,603/1,603 |
| 단차 제거 실패, 절대 40 s까지 | 1,604/1,604 | 1,604/1,604 |
| 기존 정지차 코스 성공 전체 | 7,804/7,804 | 7,804/7,804 |

원래 단차의 cached event 736개는 명령 변화735개와 명령 변화 없는 상한 초과 대기1개다. 과거 입력·footer·소스 불변을 확인했다. 변경 전 파일은 [보존 ZIP](before_connection.zip), 계약은 [새 연속 소스 계약](../../../../config/tests/g2_motion_pause_r1_sha256.json)에 남겼다. 기존 후보 class·분류 함수 AST가 그대로 연결됐는지도 확인했다.

이는 연결 검증이며 실제 복귀 성공은 별도 [원래 단차 재출발 시험](../g2_motion_pause_gazebo_v1/PLAN.md)에서 판단한다. 실물 모터·차동·타이어·센서의 오차 상계를 증명하지 않는다.
