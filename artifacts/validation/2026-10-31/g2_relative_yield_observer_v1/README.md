# 우회 중 상대 면의 지속 관측과 양보 감속 후보

## 목적과 현재 범위

재출발한 앞차와 G2 차량이 모두 약 0.35 m/s로 진행하면 복귀 띠의 점유가 오래 남는다. 현재 점유를 무시하고 복귀하는 대신, 진행 중인 편이 경로에서 조금 감속해 상대 면이 앞으로 빠져나갈 수 있는지 검토한다. 아직 운영 제어기·ROS·Gazebo에는 연결하지 않았다.

`observer.py`는 센서 기반 제어기 상세에서 현재 벽 방향, 실제 반환으로 얻은 면 구간, 복귀 띠 점유, 스캔 시각만 읽는다. 같은 방향의 작은 면이 0.8초·9개 새 스캔 동안 뒤로 충분히 빠지지 않으면 0.20 m/s 시험 상한을 제안한다. 차량 신원·정지/이동 분류·자유 공간·주행 허가를 선언하지 않는다. 정답 위치·actor 일정·모터축 누적 변위로 상대차 움직임을 분류하지 않는다. 회전·입력 소실·시각축 변경·다른 면·복귀 단계에서는 누적을 버린다. 상한과 관측창은 시험용 가정이다.

## 저장 입력의 관찰 결과

`probe.py`의 첫 40초 분석([run1.json](run1.json))이며, 실제 명령과 원본 파일은 바꾸지 않았다.

| 원래 실행 | 전체 호출 | 제안 호출 | 원래 양의 명령을 낮출 호출 | 제안 시각(시뮬레이션 절대 시각) |
|---|---:|---:|---:|---|
| 정지차 성공 | 1,603 | 0 | 0 | 없음 |
| 재출발·원래 단차 | 1,603 | 315 | 312 | 18.42–24.70 s |
| 재출발·단차 제거 | 1,604 | 287 | 286 | 17.82–23.54 s |

실패 두 사례에서 제안 시작은 방지턱 투영 겹침보다 빠르다. 별도 [복귀 관측 분석](../g2_bump_edge_diagnosis_v1/rejoin_observations.json)의 20–23.2초 새 스캔 각 32개에서 현재 반환이 복귀 띠를 점유했고, 허용된 복귀 띠는 0개였다. 따라서 방지턱 접지 문제와 복귀 공간 부족을 구분한다.

이 표는 양보 감속으로 복귀가 개선된다는 증명이 아니다. 같은 면처럼 보이는 다른 물체, 가림으로 면 끝이 달라지는 경우, 정지차 옆에서 자차도 정지한 경우에 대한 오판 가능성이 있다. 감속만 제안해도 시간을 낭비하거나 뒤차 접근을 늘릴 수 있으므로, 독립 보호를 유지한 제한 합성 주행으로 비용과 효과를 먼저 비교한다. 단위 검사 결과는 실행 후 별도 로그에 기록한다.

## 제한 합성 대조 계획

`controller.py`는 이전 호출의 유효한 관측 제안이 있을 때만 이번 G2 경로 후보의 속도 상한을 낮추는 별도 어댑터다. 실제 측정 속도·원시 입력·점유·정지공간은 그대로 두고 명령 후보를 다시 검사한다. 최종 출력만 사후에 자르지 않는다. 새로운 스캔/현재 검사가 통과하지 못하면 기존 정지 결과가 유지된다. 운영 코드·ROS 선택지는 추가하지 않았다.

`closed_loop.py`는 10/29 `g2_follow_reserve_v1/probe_closed_loop.py`의 순차 센서 생산·독립 보호 함수·이상 bicycle 평가기를 복사하고, 실제 단차 제거 시험의 `baseline_header.json` 설정을 사용한다. 각 18초, OFF/ON 한 쌍씩 아래 네 조건만 비교한다.

- 중앙 정지차: 성공한 우회를 불필요하게 늦추는지 확인.
- 중앙 정지차가 시작 후 4초에 0.35 m/s로 재출발.
- 같은 재출발을 시작 후 7초로 늦춘 조건.
- 4초 재출발 + 기존 복합 오차(거리 ±30 mm, yaw −0.5°, gyro +1°/s·σ0.02 rad/s, 모터축 28카운트·15:1·65 mm 양자화).

actor 일정은 평가기에서 고정하며 제어기에 전달하지 않는다. 판단 기준은 장면 성립·기존 G1 복귀·접촉·두 바퀴 범위·STOP과 진행량 비용을 함께 기록하는 것이다. 의도한 병렬 장면이 없으면 효과 미검증으로 남기고 성공으로 세지 않는다. 방지턱·접지·헛돎·토크 응답·후방 추돌은 이 평가기에 없으며, 표준 schema5 재생 완료로 기록하지 않는다. 이번 실행의 원시 호출 요약과 소스 ZIP은 별도 폴더에 보존한다.

단위 검사는 `test1.log`의 **28개 통과**다. 최초 합성 명령은 `ackermann_msgs` import 실패로 조건 실행 전에 끝났다(`closed_run1.log`, 종료1). 이 결과를 주행 실패로 세지 않는다. ROS 환경에서 받은 `PYTHONPATH`를 유지하고 저장소 경로만 추가하는 [고정 명령](run_synthetic.sh)과 별도 `closed_run2`를 준비했다. `closed_run1` 원문은 보존했다.

## v1 합성 결과와 후속 가설

`closed_run2`는 환경 확인 뒤 네 조건의 OFF/ON을 모두 실행했고 소스 불변을 확인했다. 정지차는 양쪽 모두5.199 m·복귀·접촉0·STOP이며 명령도 동일했다. 4초 재출발은 OFF5.619 m/ON5.487 m·접촉0·STOP이나 둘 다 복귀 실패였다. ON은5.82–8.60 s에140호출 감속했다. 그 뒤 상대차 뒤쪽이 자차 앞약0.53 m로 나갔을 때 감속 제안이 끊겼고, 다시0.35 m/s로 나란히 진행해 복귀하지 못했다. 현재 좁은 면 범위를 벗어났다는 이유만으로 감속을 끝내는 조건을 후속 가설로 본다.

7초 재출발에서는 두 방식 모두9.8 s에 G1복귀했으나 시험장 끝 부근에서 멈춘 자차를 계속 진행하는 각본 차량이18.36 s에 따라잡아 접촉1건이 발생했다. 평가기는 접촉 시 반복을 중단하므로18.5 s 예정 STOP까지 도달하지 않았다(`stopped=false`). 이 실패를 지우지 않으며 감속 후보의 효과로도 해석하지 않는다(후보 제안0, 명령 동일). 4초 재출발 복합 오차는 두 방식 모두4.674 m·12.2 s 복귀·접촉0·STOP였으며 제안0·명령 동일이므로 오차 조건에서 후보 효과는 미검증이다. 모든 조건에서 도로 밖 바퀴는 최대2였다.

후속 `observer_v2.py`는 **시작 조건을 유지**하고, 이미 시작한 감속만 같은 면의 현재 관측·벽 방향·신선한 시각이 유지되는 동안 최대5초 지속한다. 면이 전방으로 이동하는 범위는 현재 관측1.2 m까지이며, 복귀 띠가 현재 관측으로 열리거나 단계가 바뀌면 끝낸다. 면/입력이 사라지거나 바뀌면 누적을 폐기한다. 현재 점유가 없어졌지만 자유 관측이 아직 부족한 경우에도 감속 제안만 유지하며, 공간을 비었다고 처리하지 않는다. 현재 속도·경로/점유 검사·독립 보호는 원래대로다. 같은 네 조건·18초를 한 번씩 대조하며 원래 v1 소스는 `closed_run2/sources.zip`에 보존한다.

## v2 결과와 복귀 확인의 연결

`test_v2_1.log`의14개 검사가 통과했고 `closed_v2_run1`도 네 조건을 완료했다. 4초 재출발 ON은5.41158 m·감속165호출이지만 복귀하지 못했다. 저장 상세에서9.10 s에 복귀 띠가 한 번 열리자 감속 제안이 끝나고9.12 s부터0.35 m/s로 돌아간 점을 확인했다. 기존 복귀기는 서로 다른 새 스캔 두 번의 확인이 필요하므로, 그 확인을 마치기 전에 가속하는 연결 문제다. 나머지 세 조건은 후보 효과가 없고 원래 접촉/종료 한계도 같았다.

네 OFF 조건의 `controller_output_sha256`은 v1과 모두 같다. 원시 records 파일은 처리 시간·관측 상세가 들어 있어 바이트 해시는 다르며, 이를 명령 변경으로 해석하지 않는다. 두 실행의 소스 ZIP과 원시 기록은 보존했다.

`observer_v3.py`에서는 감속을 새로 시작하는 조건과5초 상한은 유지하고, 복귀 띠 한 번의 양의 관측만으로 가속하지 않는다. 현재 관측/시각/면 조건이 살아 있는 동안 **기존 제어기가 실제 복귀 단계로 전환할 때까지** 감속 상한을 유지한다. 복귀 확인 횟수나 점유/관측 기준은 바꾸지 않는다. 제어기가 전환하지 못하면5초 후 이 제안은 끝난다. 같은 네 조건과 별도 단위 검사로 비교하며 아직 생산 코드에 연결하지 않았다.


## v3 결과와 연결 단계

test_v3_1.log의18검사가 통과했고, closed_v3_run1에서 4초 재출발 ON은 **13.4 s 정상 추종 복귀·5.01489 m·접촉0·도로 밖 바퀴최대2·STOP**를 확인했다. 감속은5.82–9.60 s의190호출이었다. OFF는5.61938 m지만 옆 경로에 남아 복귀하지 못했다. 진행량만 더 큰 결과를 더 좋은 결과로 평가하지 않는다. 정지차·7초 재출발·복합 오차 세 조건의 명령은 그대로이고,7초 재출발의 각본 추돌/예정 STOP 미도달은 남는다. 시제품효과는 이 명목 재출발 한 조건에 한정한다.

v3 고정 셸의 첫 호출은 CRLF로 실행 전 실패했고, 원래 바이트와 오류를 보존한 뒤 LF 스크립트로 검사·합성을 처음 수행했다. 네 OFF 명령 해시는 v2와 모두 동일했고 원시 소스도 불변이었다. 실제 ROS/물리 차동/방지턱 검증은 아니며, 이후 [기본OFF 연결 검증](../g2_relative_yield_connection_v1/README.md)에서 생산 클래스·schema5·ROS 매개변수로 이관한다.
