# 도로–잔디 단차 제거 — 같은 위치 정체, 상태 소실 경로는 달라짐

2026-10-31. 사용자의 요청에 따라 원본을 보존하고 잔디 링크만1 mm 올려 상단을 도로와 같은3 mm로 맞췄다. 방지턱·센서·차량·제어기·구동 토크·마찰·상대차 일정은 유지했다. 기본 월드는 바꾸지 않았다.

처음40초만 실행하려던run1/run2는 각각 보조차 일정 종료와 전체코스 최소1랩 경로 조건에서 **Gazebo 시작 전 거절**됐다. 로그·소스ZIP은 보존한다. 기존 판정을 우회하지 않고 [계획](PLAN.md)을 실제 실행 전에155초로 바꿨다. run3이 첫 실제 주행이며,4반례·1,151파일 보존·주/보조차 실제 경로 사전검사를 통과했다.

[첫40초 비교](run3_comparison.json)의 `comparison_valid=true`는 **실험 무결성**이다. 두 실행 모두 약5.07947 m에서 정체했으며, 평탄화 조건의 전체155초도 완주하지 못했다.

## 달라진 정체 경로

단차 제거run3의24.70초에는0.35 m/s 우회 명령이 있었다.24.72초에 모터축 환산−0.14586 m/s가 들어오자 G1 측방 선택기가 `pass_release_reverse_motion_hold`·`selector_choice=hold_fault`를 냈다. 상위G1/G2는 이를 일반 고장 분기로 처리해 우회 기하를 지우고FOLLOW로 초기화했다. `reason=handoff_reverse_motion_hold`이며 **정상 복귀가 아니다**. [해당 원시 전이](run3_handoff_reset.json).

기존 단차 실행에서는 양의1.021 m/s를 우회 입력 범위 초과로 처리해 경로를 지웠다. 이번에는 유효한 음수 측정에 대한 G1의0명령을 상위 계층이 일반고장으로 받아들인 경로가 드러났다. 두 경우 모두 출력 정지와 기하 기억 삭제를 분리할 필요가 있는지 저장 입력에서 검토한다. 음수/양수 측정을 자르거나 실제 차체 정답을 제어에 넣지 않는다.

## 유지된 검증과 한계

런타임에서 잔디 링크pose `0 0 0.001 0 0 0`, 도로pose불변, 도로/잔디 충돌 형상·물성 불변과 방지턱 불변을 확인했다. 잔디2,353개 충돌/시각 상자는 원래 형상을 유지했다. 소스·설정·입력 불변, 접촉/겹침0, 노외바퀴최대2, STOP·명시MCU STOP·정상 종료·잔류0,7,793/7,793판단 동일 재생을 확인했다. 창은녹색7.731초부터155초다.

원래G1의hold·final_gap·full_lap·sampled_gap·swept_gap 및 방지턱 제한평가 실패는 보존했다. 방지턱 분석 프로그램exit0은 분석 실행 성공이다. 평탄화가 실물 트랙을 더 정확히 재현한다거나 기본 월드로 채택됐다는 뜻은 아니다. 접지·강체 타이어·열린 차동의 물리 한계도 남는다.
