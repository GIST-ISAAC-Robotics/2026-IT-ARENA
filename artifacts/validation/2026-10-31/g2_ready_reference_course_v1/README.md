# 준비 완료 양벽 기준 — 전체 코스1랩

조건과 판정은 [PLAN.md](PLAN.md)에 사전 등록했다.40초 제한 주행과 같은 제어기/정지 표적으로155초 전체 코스를 확인한다.

## run1: 주행 전 시험 정의 불일치

11검사 통과·1실패 후 실행을 중지했다.40초 제한 시험에서 복사한 전체랩 비필수 검사가 남아, 실제155초 평가기의 전체랩 필수 조건과 충돌했다. 실패한 검사 소스·SHA는 `before_scope_test_fix.zip`/`scope_test_fix.json`, 실패 결과는 `run1_tests.log`에 보존했다. 전체랩 필수를 확인하는 검사로 고쳤고, 제어기와 평가기 판정선은 바꾸지 않았다. 준비·Gazebo 실행은 없었다. 다음 실행 번호는run2다.

## run2: 실제 우회·복귀, 후반43.613 m 정체로 전체랩 실패

사전11검사·1138파일 보존·실행 조건 확인 뒤155초 창을 완료했다. [별도 코스 평가](run2_evaluation.json)는 전체랩 한 항목에서 실패했다. 성공할 때까지 같은 조건을 반복하지 않는다.

| 항목 | 결과 |
|---|---|
| 상태 전환(시뮬 시각) | FOLLOW7.96 → BYPASS13.12 → REACQUIRE21.92 → FOLLOW22.42(`handoff_return`) |
| 전체 진행 / 최장 연속FOLLOW 진행 |43.61325 m /23.71608 m|
| 최소 표적 간격 |표본121.242 mm /표본 사이 보수 하한121.236 mm|
| 접촉·겹침 / 노외 바퀴 |0 /세 접지면 해석 모두 최대2개|
| STOP·정상 종료 |통과, 잔류 프로세스0|
| 판단 재생 |7792/7792 동일, 입력·소스 불변|

40초 run2와 달리 이번13.12초의 [실제 진입 기준](run2_entry_reference.json)은 `current_tracked_pair_candidate`였다. 종전 왼쪽 기준은 `straight_entry_only`로 실패했지만, 현재 연결 반환133/172점의 양벽 기준을 사용해 우회에 진입했다. 현재 후보가 실제 동작에 사용된 근거이며 모든 상황의 효과나 반복 성공률을 입증하지는 않는다.

약43 m에서 제어기0명령 정체가 나타났다.71.50초 `follow_same_scan_missing_wait`가 기존 측방 통과 이력을 지웠고,72.02초 경로가 다시 생겨도 GUARD의 왼쪽 접근 거절이 남았다. 이후 약43.613 m까지 일부 진행한 뒤 종료 시각까지 대기했다. 이는 이번 G2 거리 보존/준비 감속이 직접 막은 상황이 아니며 헛돎으로 판정하지 않는다. [별도 연속성 후보](../g1_same_scan_history_v1/PLAN.md)를 원본 소스 변경 없이 먼저 대조한다.

원래 G1의 앞차 뒤 유지/최종 거리/접근/전체랩 실패와 원시 결과는 보존한다. STOP 대기 이동 약0.0021 mm는 이미 정체한 상태에서의 결과이므로 주행 중 제동거리 성능이 아니다. 방지턱 네 바퀴 기하 통과는 확인했으나 실물 충격/안전 증명이 아니다. 이번 구성의 전체 완주는 아직 확인하지 못했다.
