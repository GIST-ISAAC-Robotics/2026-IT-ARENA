# 짧은 경로의 연속 공통 구간

## 발견한 문제와 변경

[앞선 영상 주행](../g2_relative_yield_course_video_v1/README.md)은 전체 랩 평가를 통과했으나 후반 약30초 동안 경계 미확정으로 멈췄다. 약57cm의 선호 경로는 관측됐지만, 반대 경로와 8cm 이내로 일치하는 첫 **이산점**이 현재 위치에서20cm를 조금 넘었다. 경로는36개 점으로 표현되므로 점의 간격/배치가 실제 연속 구간의 시작을 늦게 표시했다.

기존 성공과 다른 거절은 유지하고 `insufficient_contiguous_common_prefix`에서만 현재 두 경로의 **선분**을 비교한다. 선호 경로가 반대 경로의 반경8cm 안에 들어가는 연속 구간을 계산한다. 단측 진입 길이20cm·공통 구간25cm·기존 표현점5개·전진하는 대응 조건은 그대로다. 첫 섬만 쓰며 떨어진 지지 구간을 이어 붙이지 않는다. 조향 경로는 선호 경로를 관측 범위 안에서 자른 것뿐이고, 반대 경로·과거 관측을 새 자유 공간으로 넣지 않는다.

`short_boundary_prefix_enabled`가 켜진 기존 선택형 연결 안에서만 사용한다. 기본값 OFF·현재 점유 전체·현재/이전 조향 검사·관측/제동 예산·독립 보호·STOP·물성은 유지했다.

- 저장 입력7,821판단에서 118.42–147.80 s의1,470개 명령만0→양수로 바뀌었다. 양수→0·음수 피드백 중 양수·방지턱 구간 변화는0이다. [시제품 비교](replay1/publication_summary.json).
- 실제 연결의7,821명령은 시제품과 모두 같았다. [연결 비교](connected1/publication_summary.json).
- 관련 회귀는193개 통과했다. 최초192통과/1실패는 최소 재생 번들에 기존 G2 의존성8개가 빠진 문제였으며, 명시 배포/계측 목록을 보완했다. 실패 소스는 `connection_failure1_source.zip`, 변경 전은 `before.zip`에 보존했다.
- 시험 중간 목록 편집에서 `validate_g1_traffic.py`의 CRLF가 LF로 변한 것을 원복했다. 당시 검사 소스는 `connection_tests2_source.zip`에 보존하며 로직 변경은 없다. 최종 출처 검사와 빌드를 통과했으며 설치된 Python84개가 소스와 모두 일치했다. [빌드](build_course.log), [설치 대조](install_course.json).
- 기하 추가 계산 비용은 저장 비교에서 p50 11.27 ms·p95 12.03 ms·최대13.77 ms였다. 전체 파이프라인/Jetson 실시간 처리율이나 마감 보장은 아니다.

저장 비교는 고정된 센서 입력에 대한 명령 변화다. 새 명령에 따라 실제 차량 위치와 다음 관측이 바뀌는 효과는 [대표 폐루프 계획](../g1_continuous_prefix_course_v1/PLAN.md)에서 별도로 확인한다. 방지턱 정체는 이 변경의 대상도 개선 근거도 아니다.
