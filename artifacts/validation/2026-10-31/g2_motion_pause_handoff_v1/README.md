# 우회 중 운동 대기의 분류 — 저장 입력 비교

기존 상한 초과 대기와 함께, G1의 `pass_release_reverse_motion_hold`를 유효한 음수 측정의 정지로 구분했다. 기존 BYPASS/REACQUIRE와 경로가 있고 측정값·고장 메타데이터가 일치할 때만 G2의 signed 대기로 넘긴다. 실제 입력 고장·FOLLOW의 음수 측정은 그대로 초기화한다. 음수/상한 초과 동안 양수 명령을 내지 않으며, 기하 보관 자체를 주행 허가로 쓰지 않는다.

| 저장 입력 | 원본 판단 재현 | 속도·조향 변화 | 새 0명령 | 대기 중 양수 명령 |
|---|---:|---:|---:|---:|
| 원래 단차 재출발, 절대 시각 40 s까지 | 1,603/1,603 | 735 | 0 | 0 |
| 잔디 높이 +1 mm, 절대 시각 40 s까지 | 1,604/1,604 | 740 | 0 | 0 |
| 기존 정지차 102 m 성공 입력 전체 | 7,804/7,804 | 0 | 0 | 0 |

단차 제거 입력에서는 24.72 s의 음수 대기가 경로를 지우지 않아 25.22 s부터 현재 후보·서로 다른 두 스캔을 확인한 0.35 m/s 명령이 나왔다. **저장 입력의 명령 비교이며 새 이동·복귀·완주를 증명하지 않는다.** [결과와 해시](run1/summary.json), [후보·시험 원본](run1/sources.zip).

처음 비교 코드는 외부 `command`에 분류문이 있다고 잘못 지정해 import 단계에서 실패했다. 실제 `_command`로 수정했고, 변경 전 ZIP·`tests1.log`를 보존했다. 수정 후 `tests2.log`의 15검사와 입력/소스 불변·기록 footer 검사가 통과했다. 기본 실행 모듈은 이 비교 당시 수정하지 않았다.
