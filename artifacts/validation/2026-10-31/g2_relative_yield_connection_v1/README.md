# 선택형 상대 면 양보 감속 연결

`bounded_relative_yield_v1`은 `HandoffExecutionConfig.relative_yield_policy`와 ROS 매개변수 `g1_g2_relative_yield_policy`로만 선택한다. 기본값은 `off`다. `corridor_local_v1`·`bounded_motion_pause_v1` 조합에서 현재 관측된 같은 면이 복귀 띠를 막을 때만0.20 m/s 후보 상한을 사용한다. 이미 시작한 감속은 현재 관측 아래 최대5초, 기존 복귀 단계 전환까지 유지한다. 모터축/gyro 측정값과 원래 점유·제동·복귀 확인·독립 보호를 바꾸지 않는다.

근거는 [미연결 시제품 v1–v3 대조](../g2_relative_yield_observer_v1/README.md)다. v3에서 4초 재출발 조건의 복귀가13.4 s에 성립했으며, 다른 조건의 명령은 같았다. 끝벽에서 각본 차량에 추돌당한 별도7초 재출발 실패와 소스 ZIP을 보존한다.

이번 연결에서는 기본/과거 헤더 유지·현재 입력으로 한 번 재검사·고장/시각/면 교체·해제/STOP 관련 회귀와 같은 네 조건의 OFF/ON 합성·schema5 동일 재생을 확인한다. `closed_loop.py`는 각 호출의 입력을 기록하고 실제 생산 클래스로 재생한다. 미연결 v3와 비교하는 명령 해시는 처리 시간·추가 진단을 제외한 요청/보호 출력·상태·이유의 동일성이다. 물리 방지턱·Gazebo·실차 검증은 다음 단계이며 현재 완료로 쓰지 않는다.

최초 연결 검사는372통과·1실패였으며 합성은 시작되지 않았다(`run1_tests.log`, `run1_exit.txt`). 실패는 새 연결의 후속 소스 계약이 아직 없어 과거 운동 대기 버전의 해시와 현재 파일을 직접 비교한 항목이다. 과거 기대 해시를 덮어쓰지 않고 v3 시험 소스 ZIP의 변경 전 바이트가 기존 계약과 일치함을 확인한 뒤 `g2_relative_yield_r1_sha256.json` 후속 계약과 보존 검사를 추가했다. 별도 `run2_checks.sh`로 검사를 재개한다. 빌드·Gazebo는 아직 미실행이며 이전 정상 종료를 승계하지 않는다.


## run2 연결 검증 결과

관련 회귀 **374통과**, 네 조건×OFF/ON의 **7,188판단이 모두 schema5 동일 재생**됐고 여덟 실행의 명령 해시가 미연결 시제품v3와 각각 같았다. 시험 도중 소스 변경은 없었다. 실행 요약은 `run2/report.json`, 당시 소스는 `run2/sources.zip`이다.

| 제한 합성 조건 | OFF → ON | 보존할 한계 |
|---|---|---|
| 중앙 정지차 | 둘 다 정상복귀·5.19894 m·접촉0·STOP, 명령 동일 | 감속 제안0회 |
| 4초 재출발 | 복귀 미성립 →13.4초 정상복귀,5.61938 →5.01489 m | ON 감속190호출, 양쪽 접촉0·STOP. 더 큰 거리만으로 우열을 정하지 않음 |
| 7초 재출발 | 둘 다 정상복귀 뒤 끝벽 앞 정지, 각본 앞차가 추돌 | 명령 동일·감속0회. 접촉으로 루프가 예정 STOP 전에 종료됐으며 STOP 기능 고장 증명이 아님 |
| 4초 재출발+복합 오차 | 둘 다 정상복귀·4.67355 m·접촉0·STOP, 명령 동일 | 감속 제안0회라 후보의 오차 내성을 입증하지 않음 |

센서 기반 주행 판단과 독립 보호의 이상 자전거 폐루프 결과다. 실제 차동·토크·바퀴 헛돎·방지턱은 포함하지 않는다. 다음 [45초 물리 시험](../g2_relative_yield_gazebo_v1/PLAN.md)은 별도 소스 고정·빌드 뒤 수행하며 기본값은 계속OFF다.
