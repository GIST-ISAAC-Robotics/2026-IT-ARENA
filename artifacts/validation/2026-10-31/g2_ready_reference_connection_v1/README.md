# 준비 완료 현재 양벽 기준 보완의 실행 연결

2026-10-31. 기본 `off`를 유지하고, `ready_current_pair_v1`을 명시한 G1/G2 시험에서만 [저장 입력 후보](../g2_ready_reference_v1/README.md)를 사용한다. 기존 준비 관측이 완료되고 이동 증거가 없을 때에만 현재 양벽 반환으로 만든 기준을 공급한다. 기억한 선은 현재 반환을 찾는 탐색 기준이며 빈 공간/통행 허가가 아니다.

## 구현과 보존

`bypass_initial_reference.py`가 현재 센서 장면·설정에 한정한 기준을 제공하며, G2 준비·초기 벽 확인·경로 비교·회랑 계획·입장 예측이 같은 공급자를 받는다. 기본 OFF는 기존 호출을 유지한다. 정책은 ROS 매개변수와 schema5 기록에 남으며 잘못된 값은 거절한다. 고장·음수 속도·초기화에는 기억을 비운다.

연결 전 5개 파일은 `before_connection.zip`과 `g2_initial_reference_r1_sha256.json`에 보존했다. 최초 연결의 초기 후보 비교 누락을 고치기 전 파일은 `before_connection_r2.zip`과 r2 계약에 별도로 보존했다. 이전 소스 계약을 덮어쓰지 않았다.

## 최초 실패와 수정

- `tests1.log`: 433통과·2실패. 과거 새 의존성의 해시를 현행 파일과 직접 비교하던 검사였다. 후속 변경 계약의 보존본을 거쳐 과거 해시를 검증하도록 검사만 수정했고, `tests2.log`에서435통과했다.
- `run1/summary.json`: 저장 입력 대조 실패. 40초 입력의 OFF2041판단은 모두 같았지만 ON 명령/상태는1983/2041만 일치했다. 정상 코스 명령7815개와 이전 실제 우회1057개는 같았으나, 정상 코스의 상세 판단5개도 달랐다.
- 원인은 최초 `EntryGuide.evaluate`의 `_compare_entries` 호출에 `reference_provider`를 전달하지 않은 연결 누락이다. 초기 벽 확인은 새 기준으로 통과해도 실제 후보 비교는 종전 기준으로 다시 실패했다. r2에서 이 한 곳을 연결하고, 최초 경로 비교에 같은 공급자가 전달되는 회귀를 추가했다.
