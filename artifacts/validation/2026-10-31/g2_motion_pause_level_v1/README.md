# 같은 운동 대기 코드의 단차 제거 대조

2026-10-31. [사전 계획](PLAN.md)에 따라 원래 단차의 [운동 대기 주행](../g2_motion_pause_gazebo_v1/README.md)과 같은 제어 코드·옵션·155초 앞차 재출발 일정에서 **잔디 링크만 1 mm 올렸다**. 도로와 잔디 상면을 모두 3 mm로 맞춘 진단 월드다. 공식 원본·기본 월드·마찰·토크·차량·방지턱·명목 센서 조건은 유지하며, 복귀 경로 재제안 후보는 연결하지 않았다.

앞선 [구코드 단차 제거](../g2_level_surface_v1/README.md)와는 제어 코드가 다르다. 이전 결과를 수정하거나, 서로 다른 제어기를 사용한 두 실행을 단차만의 효과로 비교하지 않는다.

## 확인한 결과

| 항목 | 원래 단차 | 단차 제거 |
|---|---:|---:|
| 자차 총 순진행 | 4.75951 m | 5.09947 m |
| 전체 1랩 | 실패 | 실패 |
| 정상 FOLLOW 복귀 | 없음 | 없음 |
| 최소 표본 차체 간격 | 0 m | 68.757 mm |
| 겹침 표본 | 312 | 0 |
| 자차 관련 접촉 메시지 | 632 | 0 |
| 도로 밖 바퀴 최대 (`any`/`center`/`full`) | 3 / 3 / 2 | 2 / 2 / 2 |
| STOP·명시 MCU STOP·정상 종료 | 통과 | 통과 |
| 판단 재생 | 7,792/7,792 동일 | 7,791/7,791 동일 |

단차 제거 실행에서도 정체가 남았다. 따라서 단차 제거만으로 우회 중 재출발과 중앙 복귀 문제를 해결하지 못했다. 원래 단차 실행의 접촉은 정지한 자차에 코스를 돌아온 각본 앞차가 닿은 것이며, 메시지632개는 독립 충돌632회를 뜻하지 않는다. 이번 각1회 대조로 실물 접지나 반복적인 개선 효과를 확정하지 않는다.

최종 [등록 판정](run1_evaluation.json)은 전체랩·정상 복귀·복귀 후5 m 진행 항목에서 실패했다. 나머지 등록 검사와 STOP·정상 종료·입력/소스 보존은 통과했다. 초록7.689 s, BYPASS13.02 s, 앞차 실제 재출발16.71 s이며 끝까지 정상 FOLLOW 복귀는 없었다. `post_restart_follow_progress_m=0`은 정상 복귀 뒤 연속 진행 지표이지 전체 자차 이동0 m를 뜻하지 않는다. 0.34720 m는 앞차의 재출발 후 약1초 이동이다.

노면 분석의 세 해석 모두 도로 밖 바퀴는 최대2개였다. `any` 기준 잔디 접촉은148.913 s로 오래 지속됐으며 이는 원활한 잔디 회피 성과가 아니라 정체를 포함한다. 차체 일부가 도로 밖인 표본 수를 세 바퀴 이탈 횟수나 공식 벌점으로 해석하지 않는다.

[첫40초 비교](run1_comparison.json)는 제어 소스·실행 설정 일치와 양쪽 입력 무결성을 확인했다. 이 구간의 바퀴 평균 표면속도와 차체 종속도의 최대 차이는 원래 단차0.88622 m/s, 단차 제거1.38613 m/s였다. 단차 제거41.625 s에 목표0.35 m/s, 좌/우 뒷바퀴85.976/2.668 rad/s, 바퀴 평균1.44045 m/s에 비해 차체는0.05433 m/s였다. **단차를 없애도 큰 편측 헛돎이 남는 평가 증거**이며, 방지턱·접지·조향 중 어느 항목이 주원인인지는 추가 분리가 필요하다. 평가용 차체속도를 제어에 사용하지 않았다.

원래 G1 결과는 `run1/report.json`에 따로 보존하며 역시 실패다. `comparison_valid=true`는 비교 무결성만 뜻한다. 종료 코드는 원래G1/등록평가1, 재생/방지턱분석/비교0이며, 분석 실행 성공을 주행 통과로 쓰지 않는다. `run1_residual_processes.txt`는 비어 있고 자기 시험의 잔류 프로세스는0이다.

## 보존 범위와 다음 확인

사전17검사와 소스1,156파일·실제 경로·설치·설정을 확인했다. 입력 기록과 당시 소스를 보존하며, 동일 조건을 성공할 때까지 재실행하지 않았다. 평가용 위치·차체속도는 제어기에 넣지 않았다. 명시 운동 대기는 기본OFF이고, 새 복귀 곡선 후보는 여전히 오프라인 비교에 한정한다.

다음 재개에서는 이 실행의 바퀴/차체 운동과 방지턱 진입 자세를 원래 단차의 [기존 헛돎 분석](../g2_motion_pause_stall_v1/README.md)에 대조한다. 이후 [복귀 재제안](../g2_rejoin_refresh_v1/README.md)을 연결할 근거가 있는지, 아니면 방지턱·기구 조건을 먼저 분리해야 하는지 결정한다. 이번 정리 요청 뒤 새 구현이나 주행을 시작하지 않는다.
