원래 G1 보고서는 `full_lap` 및 새 실행 모드 불일치로 실패이며 그대로 보존했다. 별도 G1/G2 평가의 실패는 `course_full_lap`, `bypass_and_follow_established`, `postreturn_course_progress`다. 실행 오류·평가기 중첩 오류·강제 중단은 없다. 같은 실패를 성공할 때까지 반복하지 않았다.

초기 기록에서 이미 준비 대기하던 중 두 벽 직선 기준이 잠시 사라지자 거리 예약이 풀려1 m/s로 접근했고, 다시 벽을 확보했을 때는 진입 공간이 줄어든 것을 확인했다. [원인 분석](../g2_course_analysis_v1/README.md)과 [준비 대기의 제한 유지 후보](../g2_preparation_hold_v1/PLAN.md)를 후속으로 연결한다. 이는 새 후보의 실제 개선을 입증한 결과가 아니다. 도로–잔디 단차는 바꾸지 않았다.

v1의 overlay case 불일치와 v2의 평가기가 앞차까지1랩 이동하도록 요구한 오류는 모두 Gazebo 시작 전 실패다. [v1](../g2_blocked_course_v1/README.md)·[v2](../g2_blocked_course_v2/README.md)의 로그·소스를 보존했다. v3는 정지 각본의 실제1.4 m 경로를 도로·벽에 대조하는 평가 전용 검사를 추가했다.7검사·1,126파일 보존·설치 소스 대조와 실제 전체 배치 사전검사를 통과한 뒤 실행했다. 자차1랩 목표나 제어 입력을 바꾼 것은 아니다.
