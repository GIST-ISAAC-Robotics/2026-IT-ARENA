# G2 signed 피드백 대기: 저장 입력 비교

2026-10-30. GPT 설계·구현, GPT-6 Luna 실행·회수. [복합 오차 Gazebo 실패](../g2_center_stress_v1/README.md)의 후속이며 실제 주행 성공은 이 보고서의 범위가 아니다.

## 가설과 범위

`EntryGuide`는 유한한 음수 모터축 속도를 입력 무효로 보아 우회 기하까지 초기화했다. 원본 시험에서는 순간적인 바퀴 역회전 뒤 양쪽 초기 벽을 다시 요구하면서 길게 멈췄다. G1은 이미 signed 피드백과 입력 무효를 구분하지만 기존 G2에는 같은 처리가 없었다.

후보는 음수 측정을 보존하고 **그 순간 전진을 금지**한다. 동일 출처·시간축과 유효한 운동 기록일 때만 기하를 signed 운동으로 이송한다. 이것은 주행 허가 기억이 아니다. 출처 오류·세대 변경·범위 이탈·운동 이송 실패는 초기화한다. 정상 입력 복귀 후 현재 외벽·관측·점유 검사 및 서로 다른 두 스캔의 진행 후보가 필요하다. STOP과 독립 보호는 별개로 남는다.

## 두 후보의 차이

- **v1:** 현재 불허가 나오면 같은 스캔 재사용 중에도 재개 확인 횟수를 지웠다. 오차 입력에서 진행 가능한 내부 후보가305호출 있었지만 확인이 누적되지 않아 실제 비교 명령 변화는0이었다. 원본은 `candidate_v1.py`, `shadow1.json`, `shadow1_sources.zip`에 보존했다.
- **v2:** 확인 횟수는 새 스캔에서 갱신·취소한다. 같은 스캔의 불허 틱에는0명령을 내고 그 틱을 새 확인으로 세지 않는다. 현재 허가를 기억으로 대신하지 않는다. 새 스캔이 불허면 연속 확인을 지운다.

| 고정 기록 | 원래 판단 재현 | v2 주행 창의 명령 변화/0→양수 후보 | 음수 측정 중 양수 후보 |
|---|---:|---:|---:|
| 명목 중앙 표적 | 1041/1041 | 0/0 | 0 |
| 복합 오차 중앙 표적 | 1028/1028 | 281/281 | 0 |

명목17건·오차18건의 양수 후보는 예약 STOP 창 뒤에 발생하므로 활성 주행 회복으로 세지 않았다. 상위 STOP이 실제 출력을 막는 구간이다. 초기 음수는11.30 s이며11.32 s에 양수 측정이 나와도 현재 기하 후보가 없어서 계속0이었다. 오차 기록의 재개 대기는839→85호출로 줄었다. [v2 결과](shadow2.json).

이것은 원래 차가 멈춰 있던 입력을 재생한 **개루프 비교**다. 새 양수 명령대로 차가 움직였다면 이후 관측도 달라지므로 통과·복귀·충돌 없음으로 확대하지 않는다.

## 검사와 실패 보존

반례11건은 음수 중 진행 금지, signed 이송, 비유한/범위/세대/출처/운동 실패 초기화, 같은 스캔 확인 중복 금지, 새 장애물 관측 시 재개 취소를 확인한다. 최초2실패는 시험용 `LocalScene` 생성 시 광선의 시각·세대를 함께 갱신하지 않은 오류였다. 원본 `test_candidate_attempt1.txt`와 `tests1.log`를 보존했고 시험 입력 수정 뒤11건 통과했다. v2는 다시11건 통과했다. 두 재생은 소스 불변을 확인했다.

후속은 [명시 runtime 연결](../g2_signed_hold_connection_v1/)과 [별도 복합 오차 주행 등록](../g2_signed_hold_gazebo_v1/DRIVE_PLAN.md)이다. 기본off·기존corridor_v1·여유/물성은 바꾸지 않는다.
