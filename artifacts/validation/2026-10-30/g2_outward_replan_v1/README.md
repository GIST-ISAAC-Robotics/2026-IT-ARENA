# 같은 우회 방향의 작은 외측 재계획 후보

2026-10-30. 오프라인 후보의 제한 합성과 추가 조건 오류 감사를 마쳤다. **v1은 추가 여유 검사 누락이 있어 미채택이며, 수정 v2는 저장 입력에서 재계획하지 않았다.** 운영 코드·기본값에 연결하지 않는다.

[중앙 편이 대조](../g2_center_offsets_v1/README.md)는0.26m 후보를 추가해도 최초0.24m가 선택되어 결과가 같았다. 기존은 진행 중 외벽으로 기존 경로를 보정하지만, 다른 편이를 다시 고르지는 않는다. 이번 가설은 좁은 구간에 들어선 뒤 현재 관측으로 작은 외측 경로를 한 번만 다시 고르는 것이다.

- 기존 경로가 있고 `entry` 단계이며, 외벽의 서로 다른 관측을2회 이상 유지한 **새 스캔**에서만 비교한다. 현재 명령이 기존0.35m/s 상한에 도달하면 재계획하지 않는다.
- 같은 우회 방향의 등록 편이 중 현재보다 바깥쪽이고 차이가30mm 이하인 것만 본다. 이번 등록 목록은 앞선±0.26m 목록이다. 최대 범위를 넓히거나 반대편·중앙 복귀를 열지 않는다.
- 현재 후륜축에서 같은 관측 외벽 기준으로 기존0.6/0.9/1.2m 전이를 만든다. 실제 현재/직전 조향, 속도, 점유·미관측·반응/제동 검사는 기존 비교 함수를 그대로 쓴다.
- 양수 후보·완전한 전이 관측 길이·음수가 아닌 현재 점 여유·현재 원호 여유40mm 이상 개선·명령속도 개선이 모두 있어야 채택한다.40mm는 기존 원호 표본 한 칸이다. 전체 미래 경로의 관측/통과를 보증하는 조건은 아니다.
- 채택은 한 번만 가능하다. 벽 확인 횟수를 늘리지 않으며 복귀 확인을 다시 시작한다. 새 경로 역시 이후 호출마다 기존 검사를 통과해야 하고 독립 보호/STOP은 유지한다.

먼저 관측 재사용·고장·반대 방향·점유/미관측 거절·전체 전이 부족·개선 없는 변경을 배제하는 반례와 기존 저장 입력을 비교한다. 기본·소스·판정선을 바꾸지 않는다. 초기 순위에서0.26을 강제로 선택하거나 성공할 때까지 편이를 탐색하지 않는다.

## 반례·저장 입력 결과와 제한 실행

반례16건을 통과했다. 기존 중앙 원시 입력의531판단이 원본과 같고, 후보는4.9초(source4.8초)에0.24→0.26m·전이1.2m를 실제로 선택했다. 현재 원호 여유는0.12→0.16m, 제안속도0.23246→0.34833m/s였다. 기존 순위를 덮어 강제로0.26을 고른 것이 아니라, 새 관측의 재계획 조건을 통과한3전이 중 후보 자체의 규칙으로 선택했다.

전체 명령 변화는66회이며 조향도 달라졌다. 그러나 저장된 원래 운동을 유지한 비교에서 독립 보호 후0→양수/양수→0은모두0회다. 정체 해결을 입증한 결과는 아니며, 경로 변경 뒤 실제 운동/새 스캔이 달라지는 효과는 이 저장 비교로 알 수 없다. 후보 판단비용 median9.14/p9513.58/max74.32ms는 이 PC의 저장입력값이고 실시간Jetson증명이 아니다. 입력·소스는 보존했다. [저장 대조](shadow1/report.json).

이제 같은 중앙 정지차·복합센서 seed17·10초+STOP의 후보만1회 합성 실행한다. 기존 결과는 [직전현재소스기준](../g2_center_offsets_v1/comparison1/existing_027/report.json)을 사용한다. 원시 센서·전체guide·독립guard는 후보 해시가 들어간 별도schema908로 보존/재생한다. 보호·물성·속도·평가를 바꾸지 않는다. 실제선택·재계획·진행/통과/복귀·정지/종료를 나누고, 같은 실패를 통과까지 반복하지 않는다.

## 제한 합성 결과와 추가 검사 오류 정정

[후보 1회 합성](closed1/report.json)은 실제로 4.9초에 0.24→0.26 m 경로를 선택했다. 기존 같은 조건의 진행 0.835314 m 대비 0.882780 m, 횡이동 0.214492 m, 최소 차체 간격 0.111177 m였다. 접촉 0, 잔디 바퀴 최대 2개, STOP 명령/최종속도 0이며 전체 guide·독립 guard 재생이 각각 531/531 일치했다. 끝까지 `entry` 단계여서 **표적 통과·복귀는 실패**다. 이상 bicycle의 중앙 정지차·복합 센서 seed17·10초 결과이며 Gazebo/실차가 아니다.

검토 중 `preview_point_gap_m`의 **미계산 기본값 0을 계산된 여유로 사용한 오류**를 찾았다. 원래 `_compare_entries`는 `stationary_boundaries=True`인 초기 순위 비교에서만 이 값을 계산한다. guide로 고정 외벽을 전달하는 것만으로는 이 진단값을 계산하지 않는다. v1의 비음수 조건은 따라서 실질적인 추가 검사가 아니었다. 기존 현재 명령의 점유/관측·독립 보호는 적용됐지만, README의 ‘음수가 아닌 현재 점 여유’라는 의도는 충족하지 못했다. 당시 코드·소스 ZIP·원시 결과를 보존하며 0.883 m를 정상 조건의 개선으로 채택하지 않는다.

[감사](audit1.json)는 원본 531판단을 동일 재생하고, 재계획 시점의 세 전이를 실제 여유 계산으로 다시 확인했다. 0.6/0.9/1.2 m 전이의 최소 여유는 각각 −10.22/−12.71/−25.08 mm였다. 현재 짧은 명령은 가능해도 미래 경로 표본 일부는 현재 반환점 팽창과 겹친다는 뜻이며, 실제 접촉이나 미관측 공간이 없음을 뜻하지 않는다.

[`candidate_v2.py`](candidate_v2.py)는 해당 계산을 명시적으로 요청하고 고정 외벽 가정 없는 호출은 제외한다. 17반례 후 [동일 저장 입력 비교](shadow2/report.json)에서 기존 531판단 일치·재계획 0·명령 변화 0·입력/소스 불변을 확인했다. 새 조향이 없으므로 수정 후 같은 합성 주행을 반복하지 않았다. 경로 편이 재선택만으로 중앙 정체를 해결하지 못했다.

감사 후반 275호출 중 113호출은 진행 명령, 162호출은 점유 여유에 의한 정지였다. 늦은 스캔에서는 물체 이동 가능 범위가 현재 차체까지 겹치므로 원호 표본 간격만 줄이는 작업은 주원인을 해결하지 못한다. 다음은 현재보다 물체 쪽으로 더 접근하지 않는 제한 이동을 별도 **오프라인 관측/기하 비교**로 검토한다. 고정 측정 여유 안의 실제 점과 전방 장애물을 이 예외로 바꾸지 않으며, 현재 팽창의 겹침을 무조건 무시하거나 실물 정지 차량으로 확정하지 않는다.
