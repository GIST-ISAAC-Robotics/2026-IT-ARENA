# G1/G2 관측 통로 자동 전환 Gazebo 제한1회

2026-10-30. [사전 등록](DRIVE_PLAN.md)의중앙 정지 상자·동일 복합 센서 오차·20초 창·STOP을1회 실행했다. GPT가 설계·구현·분석·검토, GPT-6 Luna가 실행·대기·회수를 맡았다. 사전 검사·1,122파일 보존·실제 헤더/센서 주입 계약을 확인했다.

## 원래 실행 결과와 평가기 문제

실제 기록은 판단 기준 시각으로 녹색 후1.127 s 우회 진입·11.076 s 표적 통과·15.727 s G1 복귀,20초 창6.80928 m, 최소 차체 간격119.11 mm·접촉/겹침0·잔디 바퀴≤2·STOP·정상 종료·1,057판단 동일 재생이었다. 물리 중앙 구간 시작은녹색 후15.416 s,1초 유지 확인은16.416 s다. 모드 복귀와 물리 중앙 판정의 시점은 다르다.

그러나 원래 실행 exit1·`run1_g2_evaluation.json`의종합실패를 보존한다. 유일한 G2 실패는 `g2_controller_rows`다. 단독 우회기의 `mode=g2_entry_trial`, `automatic_race_mode_selection=false`만 허용하는 평가기 복사본을 사용했고, 등록된 자동 전환 모드(`g1_g2_handoff_trial`, true)를 판정하지 못했다. 실제 헤더는 실행 전 등록값과 일치했고나머지18개중17개 G2관문과실행검사는 통과했다. 원래 G1의 '앞차 뒤에 머무름' 실패와G1모드 불일치도 별도로 보존한다.

이는 새 자동 전환을 평가할 때 필요한 모드 판정을 누락한 평가 어댑터 오류다. 기존 평가기/결과를 고치거나 재주행하지 않는다. 별도 v3 평가기에서 등록된 모드만 허용하고 빈 행·다른 모드·혼합·잘못된 자동플래그/보호경계는 거절한다. 기존 공간·접촉·노면·시간·정지 판정은 그대로 두며 실제4상태전환·G1복귀후출력·우회/복귀상한0.35 m/s까지 추가 확인한다. 저장 입력 재평가 결과는 별도 파일로 남긴다.

[별도 v3 저장 기록 재평가](run1_evaluation_v3.json)는 통과했다. 모드 반례4건도 통과했고, 원래 관문 중 모드 행 하나만 false→true로 바뀌었다. 추가 자동4상태전환·복귀후G1출력·BYPASS/REACQUIRE0.35상한 확인도 모두 통과했다. 한 시드·한 중앙 상자·제한 직선이며 전체 랩·불규칙 차량·움직이는 상대의 급측방 침범·실물 완료는 아니다. 기본값과물성은 유지했고 커밋/푸시/외부게시·Jetson/전원 변경은 없다.

표의 전환 시각은 입력의 `reference_s`로 정했다. 최초 회수의8.702/23.302 s는 관련 스캔의 취득 시각이므로 판단 전환 시각과 구분한다. 녹색7.693 s와 활성 창 종료27.693 s를 기준으로 다시 세면 인계 뒤213호출이다. 초기 회수의219는 다른 시각 창과 섞인 수치라 사용하지 않는다.

STOP 평가 창까지의 총진행7.33922 m와 주행 창6.80928 m의 차이529.94 mm는 'STOP 요청 후 제동거리'가 아니다. 주행 창 종료와 실제 요청 시각이 다르며, 실제 요청·정지 증거는 원래 `report.json`/`stop_checks`에 별도로 보존했다. 물리 역회전 자체는 남아 있고 제어기는 음수 측정 중0을 내고 재확인 후 진행했다.

이제 제한 중앙 상자의 **추종–우회–추종 통합 경로**까지 확인한 단계다. 다음은 기존 측방 침범의 노출이 현재 등록 정책에서도 얼마나 남는지 대표 합성으로 대조하고, 옆에서 정지하는 것과 관측된 전방으로 진행하는 것의 조건을 분리한다. 현재 한 조건의 성공을 왼쪽 통로·급측방 침범·전체 랩·실물 성공으로 확대하지 않는다.
