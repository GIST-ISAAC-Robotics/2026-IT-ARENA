# G2 signed 대기의 명시 연결

2026-10-30. [저장 입력 후보 비교](../g2_signed_hold_v1/README.md)에 이어 `corridor_v2_signed_hold`를 추가했다. GPT가 구현하고 GPT-6 Luna가 검사·빌드를 실행했다. 기본 `off`와 기존 `corridor_v1`은 그대로다.

- 새 `bypass_signed_hold_trial.py`는 기존 통로 후보를 상속한다. 유효한 음수 피드백은 전진0으로 대기하면서 기하만 signed 운동으로 이송한다. 현재 관측과 다른 두 스캔의 후보 확인 없이 재개하지 않는다.
- `bypass_entry_follow.py`에서 새 명시 정책일 때만 이 하위형을 만든다. 공간·운동 여유·독립 보호·STOP·차량 물성은 바꾸지 않았다. `g2_entry_node.py`는 기존 정책 목록을 읽으므로 별도 수정하지 않았다.
- [후속 출처 계약](../../../../config/tests/g2_signed_hold_r1_sha256.json)에 연결 전 바이트와 새 의존성을 보존했다. 이전 계약·시험 당시 소스는 덮어쓰지 않는다.

| 검사 | 결과 |
|---|---|
| 관련 bypass/G2/출처 회귀 | 326 통과([로그](tests1.log)) |
| 기존 `corridor_v1` 기록 재현 | 명목1041/1041·복합오차1028/1028 |
| 오프라인 후보와 새 런타임 같은 입력 | 명목1041/1041·복합오차1028/1028 출력 일치([결과](replay1.json)) |
| `arena_autonomy` 빌드 | 성공([로그](build1.log)), 두 모듈 설치본 SHA256이 소스와 일치 |

여기서 기존 판단 일치와 **새 후보의 오프라인/런타임 간 일치**는 다른 검사다. 새 후보가 기존 판단과 모든 틱에서 같은 출력이라는 뜻이 아니다. 새 후보의 주행 창281개 회복 제안은 아직 저장 입력상의 변화다. 저장소 전체 회귀·실차·Jetson 시험은 수행하지 않았다.

다음은 [복합 오차 Gazebo 별도1회](../g2_signed_hold_gazebo_v1/DRIVE_PLAN.md)다. 기존 실패의 성공 소급이나 경기 기본값 채택은 하지 않는다.
