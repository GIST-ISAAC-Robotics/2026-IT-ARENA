## 최초 평가 실패와 원본 보존

`run1/report.json`의 `evaluation.error`는 `KeyError: 'minimum_continuous_hold_s'`였다. 새 case 이름 `g2_center_s_merge`에 기존 G1 비교용 `stopped_center` 규칙 별칭을 넣지 않아 공통 하네스 결과가 반환되기 전에 예외가 났다. 최상위 `error`·`abort`가 비어 있는 것만으로 예외가 없었다고 보면 안 된다. 실행 회수의 최초 설명은 이 중첩 오류를 놓쳤고 최종 검토에서 정정했다. 자차/상대 실행이나 ROS 프로세스 예외는 아니었다.

`run1_exit.txt=1`, `run1/report.json`, `run1_g2_evaluation.json`, 당시 설정·`run1_sources.zip`을 그대로 보존했다. [별도 재평가](reevaluate_saved.py)는 동결 ZIP의 당시 평가 소스와 같은 원시 입력을 사용하고, 메모리 안에서만 누락된 이름을 기존 동일 규칙에 연결했다. 별칭 검사2건이 통과했으며 입력/원본 해시도 모두 보존됐다. **새 주행은 없다.** 새 결과 `run1_evaluation_v2.json`은 모든 합류 관문과 실행 검사를 통과했다. 바뀐 항목은 `harness_valid`, `no_runtime_error` 두 가지뿐이며 다른 주행 판정·수치는 동일하다. 원래 G1의 뒤에서 머무름/도로내차체/150mm간격 등의 실패는 별도로 유지했다.

이 폴더의 원본 `run.py`·설정은 실패 당시 재현용이다. **이를 그대로 재실행하지 않는다.** 다음 새 실행을 준비할 때 case별 비교 규칙이 존재하는지 사전검사에 포함하고 새 소스를 동결해야 한다. 저장 평가의 별칭 수정은 원본 파일을 고친 것이 아니다.

## 남은 범위와 재개점

정지한 자차에 옆에서 계속 밀고 들어오는 횡미끄럼 접촉과, 비스듬한 상대가 좁은 통로를 막은 뒤 정체하는 문제는 [합성 침범 결과](../g2_intrusion_current_v1/README.md)로 남는다. 새 합류 성공이 이 문제를 해결한 것은 아니다. 최소74mm도 실차 안전거리 보장이 아니며, signed 대기·기하 보존의 실제 구동계 재현과 좌측/개방형 헛돎은 미검증/미해결이다.

사용자의 정리 요청에 따라 새 시험을 시작하지 않고 종료했다. 다음에는 현재 명시 G1/G2 후보를 기존 교통 코스 한 구성에 연결해 곡선에서의 잘못된 우회 진입과 복귀 후 주행 연속성을 보는 것을 우선한다. 이미 확보한 기존 후보5랩은 별도 기준으로 보존하고, 새 후보의 전체 랩이나 기본 활성화를 완료로 간주하지 않는다. 원시 센서/상세 수신 기록은 로컬 Git 제외 상태로 남겼다. 게시·커밋·푸시·Jetson/전원 변경은 없다.
