# 확인 기억 v2 — 차체 외곽 기준 오프라인 비교

2026-10-30. [원인 분해](../fresh_confirmation_review_v1/README.md)의 후속이다. 현재 런타임이나 기본 정책은 바꾸지 않는다.

## 바꾼 조건

- 같은 epoch/frame/스캔 시각과 모든 광선의 index·취득 시각·반환/미반환 상태를 요구한다.
- 첫 광선의 원점과 방향으로 두 기준 시각 사이의 강체 변환을 구한다. 모든 원점·방향·반환점이 이 변환과 일치해야 한다. 잔차 `1e-7`은 수치 연산 일치 기준이며 센서 잡음을 허용하는 값이 아니다.
- 기존 5 mm를 전체 반환점 이동에서 **차량 네 모서리의 최대 유클리드 이동**으로 바꾼다. 먼 벽의 회전 이동과 실제 차체 외곽 이동을 구별하기 위함이다. 실제 변위가 크거나 같은 스캔의 내용이 바뀌면 확인을 지운다.
- 기존 벽 기준·조향 변화·0.15 s 확인 유효기간·동일 스캔 중복 집계 금지·시간 역행/reset 조건을 유지한다.
- 현재 명령은 기존 proposal 그대로다. 현재 팽창 검사에 걸리면 0을 내며, 이전 팽창 나이로 계산하는 것은 확인 1회 보존 여부의 분류에만 사용한다. 다음 fresh 스캔의 새 장애물도 그대로 검사한다.

이는 작은 자세 변화의 처리 개선이며 IMU 잡음 필터나 실물 정지 판별기가 아니다. 실제로 작은 회전이 있었어도 현재 경로 검사를 통과해야 한다. 미반환은 자유 공간으로 바꾸지 않는다.

## 실행 범위

[반례](test_body_memory.py) → 저장 입력 좌우/복합 → 합성 명목 좌우·복합 좌우·앞차 정지/재개 순서로 실행한다. 변경 없는 런타임 비교군은 v1 묶음의 동일 합성 조건 결과를 사용한다. 실패하면 다음 단계로 넘어가지 않으며 같은 산출물에 덮어쓰지 않는다. [고정 실행](run.sh).

기존 v1과 실패 기록은 보존한다. 아래 결과를 검토한 뒤 [명시 정책 연결](../fresh_confirmation_connection_v1/README.md)을 진행한다. Gazebo 실행과 기본 활성화는 이 결과에 포함되지 않는다.

첫 실행: 반례21건과 저장 입력3건은 통과했다. 합성 하네스 import에서 `ackermann_msgs`를 찾지 못했는데, `run.sh`가 ROS 환경을 source하지 않은 실행 준비 오류다. 후보 코드/기준은 바꾸지 않고 [resume_probe.sh](resume_probe.sh)에서 ROS·기존 설치 환경을 불러와 미실행 합성 단계만 수행한다. 최초 `exit.txt=1`과 `probe_combined.log`는 보존한다.

### 남은 정지의 주행 영향

[기존 기록 재집계](../fresh_confirmation_review_v1/remaining_progress.json)에서 옆차 가속 전7초의0명령은 기존232/350호출 → v1 208/350 → v2 169/350으로 줄었다. 그러나6.98초의 자차 진행은 각각0.6144/0.7404/0.6406 m다. **긴 정체가 짧은 정지·가속 반복으로 바뀐 효과가 커서, 정체 최댓값 감소만큼 진행이 좋아지지 않았고 v2는 이 구간에서 v1보다도 덜 진행했다.** 옆차는 이미약0.40 m 앞에 있었다. 이 값은 합성 모델의 가속/감속과 같은 오차 표본 한 조건이며, 실물 진동·모터 열·제동 성능을 측정한 것이 아니다.

확인 기억은 원거리 좌표 기준 문제의 제한적 수정이다. 남은 현재 측방 시간 팽창과 진행 명령의 짧은 반복은 별도 과제로 남기며, 이 결과를 노이즈 조건 해결로 보고하지 않는다.
