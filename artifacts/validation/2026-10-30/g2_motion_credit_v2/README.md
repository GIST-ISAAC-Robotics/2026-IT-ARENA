# 우회 진입 공간식의 제한 이동 보상

2026-10-30. 오프라인 후보이며 런타임/ROS 연결·기본 채택은 아니다.

앞선 [예약 생략 후보](../g2_moving_reserve_v1/README.md)는 움직임으로 보이는 동안 추가 간격을 전부 해제해 이동후정지 조건에서 우회 진입을 잃었다. [반환점 분석](../g2_motion_support_v1/README.md)에서는 가까운 점의 겹침만으로 실제 이동과 부품 교체를 구별하지 못했다.

새 후보는 실제 반환의 전방10% 분위값을 모터축/gyro로 이송한0.4·0.6·0.8초 전 반환과 비교한다. 최소2창에서 `(전방 변화−60 mm)/창 길이`가 양수인 경우 가장 작은 값만 쓴다. 60 mm는 기존 거리 오차 비교 여유이며 모든 IMU/각도 오차를 포괄한 신뢰하한은 아니다.0.2초는0.25m/s 앞차도50mm밖에 이동하지 않아 해당 여유보다 작으므로 사용하지 않는다.

기존 준비 상한0.35m/s와 물체 이동 한도 이하로 제한한 `u`를 기존 예약식에 더한다.

`cap = max(0, (관측 후륜축-전방거리 − 기존 예약거리)/0.8 + u)`

최종 명령은 G1 및 기존 준비 명령 이하이다. 거리가 부족한 음수 항을 버리고 `u`를 더하지 않는다. 예약거리·G1/독립 보호·진입관측·다음 스캔까지 팽창·STOP은 바꾸지 않는다. 반환이 사라지거나 시각/epoch/모드가 바뀌면 이동 보상을 초기화한다. 새 스캔이 아닌 호출로 관측 수를 채우지 않는다.

점의 부분 소실이 앞면 교체로 보이는 반례는 여전히 가능하다. 따라서 추정값을 물체 ID/실제 속도/빈 공간 증명으로 쓰지 않으며, 후속 합성에서도 정지·이동·이동후정지·재출발과 변형 반례를 함께 비교한다. 먼저 수식 경계·상태 초기화와 기존 저장1랩을 확인한 뒤 제한 폐루프를 실행한다. v1의 실패를 덮어쓰지 않는다.

## 반례·저장 입력 확인

관측/예약식/기존 인계 **141검사**, 오프라인 기록 경계 **4검사**를 통과했다. 앞면이 사라져 뒷부분만 남을 때 속도가 잘못 양수가 되는 합성 점 반례도 숨기지 않고 검사로 명시했다. 이 경우에도 예약 부족분을 버리지 않는 계산과 G1 상한/0명령 보존을 별도로 확인했다. 수식의0명령 조건은 차체가 실제로 그 거리에서 멈춘다는 물리 보장이 아니다.

저장 1랩은 G1 상세 7,801개가 같고 우회 제안은 0이었다. 입력과 소스도 보존됐다. 이동 보상이 양수인 호출은 4,274개였으나, 대부분 이미 예약 공간이 부족해 실제 명령 변경은 8회(0→양수 8·조향 변경 0·G1 상한 초과 0)뿐이었다. 원래 G1보다 추가 감속하는 호출 수 1,485개는 그대로다. v1의 감속 제안 93개와 같은 효과를 주장하지 않는다. [저장 결과](shadow_motion_v2/report.json), [독립 대조](shadow_comparison.json).

현재 기존과 같은 개방형 5조건의 v2만 한 번씩 합성 실행한다. 기존 5결과는 앞선 동일 소스·설정 실행을 재사용한다. 명목·이동·이동 후 정지·재출발은 12초, 정지 복합 오차는 16초다. 예정 STOP·기존 접촉/잔디 평가·독립 보호는 그대로다. 후보 기록은 별도 schema906이며, 운영 도구가 이를 기존 schema5로 오인하지 않도록 구분한다.

## 제한 폐루프 결과: 운영 연결하지 않음

새로 실행한 것은 v2의 5조건이며, 기존 5조건은 앞선 보존 결과와 대조했다. 관련 141검사와 기록 경계4건도 앞선 단계의 결과로, 이번에 다시 실행하지 않았다. v2의 12초 4조건은각600/600,16초1조건은800/800판단이 전용 재생과 같았고 접촉 샘플0·예정STOP·소스 불변이었다.
