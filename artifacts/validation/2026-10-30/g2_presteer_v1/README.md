# G2 정상 대기 조향 선행 후보

2026-10-30. 오프라인 시제품이며 운영/기본값은 바꾸지 않는다.

[직전 기하 비교](../g2_side_nonapproach_v1/README.md)에서 현재 팽창 겹침을 유지하는 비접근 예외는 진행 후보를 만들지 못했다. 겹침 없는 일부 호출에서는 다른 조향이 가능했지만 직전 조향의 원호가 계속 거절됐다. 기존 출력은 후보가 없으면 `(0, 이전 조향)`이므로 정지 상태에서도 바퀴 방향이 바뀌지 않는다.

이번 후보는 기존 G2 경로·방향·관측 외벽을 유지한다. 현재 출력이 `known_occupied_command_hold`이고 **현재 차체에 기존 시차 팽창까지 겹친 점이 없을 때만** 한 제어주기 조향 변화율 3 rad/s 안의 최대 5개 방향을 살핀다. 기존 원시 반환·광선별 팽창·40 mm 원호 표본 차감·60 mm 제동 잔여·관측·현재/직전 조향을 유지한다. 가능한 다른 조향이 있으면 최대0.10 m/s 명령으로 비교하고, 현재 측정속도의 반응·제동 공간도 별도로 요구한다.

현재/직전 조향을 함께 검사하면 모두 막히는 경우, 직전 요청이0이고 모터축 인접 두 표본도0일 때에만 **속도0으로 조향을 먼저 바꾸는** 후보를 낸다. 조향이 바뀌었다면 다음 호출에서 새 현재/직전 조향과 센서를 다시 검사한다. 미래 양수 가능성을 현재의 구동 허가로 사용하지 않는다. 명시 STOP은 상위 시험기의 강제0/기존 조향 유지가 우선한다.

모터축0은 차체 정지를 증명하지 않고, 마지막 명령 조향은 실제 서보 도달 피드백이 아니다. 이번 단계는 기존 이상 bicycle/즉시 적용 조향 모델 안의 비교이며 실차 구동이나 MCU의 물리 정지를 주장하지 않는다. 보호 노드의 출력을 우회하지 않는다. 첫 단계는 반례와 기존531호출/독립보호 대조이며, 실제 효과는 이후 한정 합성 실행으로만 판단한다.

## 저장 입력 확인과 20초 대조 등록

첫 검사에서 기존 센서 fixture를 읽는 `scripts` 경로가 빠져 수집 단계에 실패했다. 원시 로그를 보존하고 경로를 고친 뒤 15반례와 원본 531판단 일치를 확인했다. [shadow1](shadow1/report.json)의 조향 선행 제안은 9.5/10.1/10.7초에 있었으나 마지막은 예약 STOP이 우선해 실제 명령이 바뀌지 않았다. 실제 변경 2회는 속도0·조향 변경이며 독립 보호 후에도0이었다. 미래 양수 후보3개를 실제 양수 출력3회로 세지 않는다.

첫 작동이9.5초이므로 새 폐루프 비교는 **시작 전에 기존/후보 모두20초+STOP으로 고정**한다. 앞선10초 실패를 소급 통과로 바꾸지 않는다. 중앙 정지 상자·복합 센서seed17·기존0.27m까지의 편이·질량 없는 bicycle·가감속·독립 보호는 동일하다. 기존/후보 각1회이며 시간 연장이나 성공까지 반복하지 않는다. 실제 조향 선행, 이후 저속 대안, 표적 통과/복귀, 접촉·바퀴 이탈·STOP/최종속도를 분리한다. 원시센서/전체guide/guard는 별도schema909로 보존·재생한다.

단순 조향 출력 고착만으로 중앙 정체를 설명할 수 없다. 이 후보는 운영에 연결하지 않는다. 다음 묶음은 누적 실패를 바탕으로 관측 불확실성과 경로 성립 조건을 함께 재설계하는 것이다. 기준선의 수치 자체를 지키기 위해 완주를 포기하지 않되, 실제 점유·미관측·센서 오류를 구별하고 바꾸는 가정의 위험과 반례를 명시한다. [인계 요약](HANDOFF.md).
