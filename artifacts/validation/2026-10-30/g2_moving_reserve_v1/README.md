# 움직이는 앞차의 추가 진입 공간 예약 비교

2026-10-30. 시험 준비·결과 수집 중.

- 기존 희소 반환·진입 공간 보존 후보는 움직이는 전방 조각에도 최대 1.2 m 전이 공간을 예약한다. 10/29 기존 1랩 저장 입력에서는 G1 상세 7,801개가 같고 우회 제안은 없었지만 추가 감속 제안이 1,485회였다. 실제 새 주행의 정지 횟수는 아니다.
- 오프라인 대안은 기존 운동 관측이 아직 유효하고 정지 후보 누적이 끝나지 않은 동안 **추가 예약만 생략**한다. G1 속도·조향, 준비 감속, 우회 허가, 독립 보호/STOP은 유지한다. 제어기에 actor 속도나 정답을 입력하지 않는다.
- 먼저 같은 1랩 입력으로 기존 후보와 비교한다. G1 상세 일치, 소스/입력 보존, 추가 감속 수를 확인한다. 이어 명목/오차 정지차와 이동·정지·재출발 앞차 합성을 비교한다.
- 성공 기준은 감속 수만 줄이는 것이 아니다. 이동 후 정지할 때 우회 공간을 잃거나 접촉·STOP·복귀가 악화되면 그대로 실패로 남긴다. 정지차처럼 보이는 움직임·가림 교체도 물체 신원 증명으로 사용하지 않는다.
- 런타임·ROS·기본값에 연결하지 않는다. 같은 실패를 통과할 때까지 반복하지 않는다.

## 저장 입력 대조

후보 경계 및 기존 인계 회귀 **86건**을 통과했다. 동일 입력 SHA-256의 7,801호출에서 기존/후보 모두 G1 상세가 전부 같고 우회 제안은 0이었다. 추가 감속은 **1,485→93회**, 그중 0→양수는1,379회이고 전체 명령 변경은1,392회다. 조향 변경·양수→0·G1 상한 초과·이동 근거 없는 변경은 모두0이다. 입력/소스/종료 footer를 대조했다. 이 결과는 저장 궤적에 대한 제안이며 실제 정지 시간이나 새 랩 완료가 아니다.

처리시간은 기존 median15.63/p9532.47 ms, 후보14.53/31.98 ms였다. 같은 PC의 순차 실행 측정이고 최적화 효과나 Jetson 처리율을 입증하지 않는다. [기존](shadow_existing/report.json), [후보](shadow_motion_v1/report.json), [독립 출력 대조](comparison.json), [남은 감속](remaining_cap_diagnosis.json).

다음 폐루프 비교는 개방형 표적의 오른쪽 명목·계속 이동·2초 후 정지·1.5초 정지 후 재출발을각12초, 오른쪽 정지 복합 오차를16초로 고정한다. 각각 기존/후보 한 번씩이며 반복 성공 시도는 하지 않는다. 원래6부품 센서 형상과 전체20×15cm 충돌 외형을 유지한다. 후보 기록은 운영 schema5와 구별되는 **오프라인 schema905**로 남기며 후보 해시를 확인한 전용 어댑터만 재생한다. 운영 ROS·Gazebo 검증은 아니다.

## 폐루프 결과와 채택하지 않은 이유

기존/후보 각5조건(총10실행), 기록 구분 반례4건을 마쳤다. 전부 접촉 샘플0·예정STOP·소스 불변·자체 재생 통과(12초각600,16초각800)다. `max_wheels_touching_grass`는 합성 평가값이며 공식 패널티 판정이 아니다.

**이 후보는 연결하지 않는다.** 계속 이동·재출발의 진행량은 늘었지만 정지 후에는1.133m에서 멈춰 우회 진입을 못 했다. 기존은 차체간격1.061m에서 진입했고 후보는 관측 누적이 준비된6.7초에 이미 약0.35m까지 접근했다. 6.7초 첫 준비에서는 서로 다른 벽 관측을 기다렸고,6.8초에는0.6m 전이 후보가 나왔지만 다음 스캔까지100ms 팽창을 반영한 일관 진입 후보가0개여서 인계되지 않았다. 즉 준비 공간 예약을 단순히 없애면 정상 충돌 방지 정지는 남아도 현재 등록된 우회 진입을 잃을 수 있다. [진입 거절 근거](closed_motion_v1_stopping_combined_admission.json). 원래12초내복귀실패도 그대로 보존한다.
