# G1 추종과 선택형 부분 관측 연결

[현행 계획](../../../../docs/DEVELOPMENT_PLAN.md)에 따라 R0 단독1랩 뒤 필수 교통 기능을 연결한다. [마커 가림·정체·원시 실패](../marker_visibility_v1/README.md)를 보존하고, 표면 정합이 실제로 기여했다는 근거는 아직 없다.

## 설계와 범위

- 기본은 `strict`. G1은 `bounded_local_v2/v3/v4`를 명시 선택으로 지원하며 R0+/M3·최근 관측 후보와 혼합하지 않는다. 상한1 m/s를 유지한다.
- G1은 원시 scan과 운동 보정 scene의 시각·frame·유효 source index를 대조한다. 원시 입력이 없거나 서로 다른 자료면 정지한다. scene의 unknown을 return/free로 바꾸지 않는다.
- 부분 관측 중에도 실제 반환으로 경로 후보를 만들 수 있지만, 공통 부분 관측 검사를 통과하기 전에는 양수 명령을 반환하지 않는다. 좁은 측방/정면 공백의 상한 .5/.2 m/s, 이전 가까운 점 소실 래치·넓은 공백·최소거리 미만·만료 처리를 유지한다. raw 전방 창 밖의 결측이 운동 변환 뒤 전방으로 들어온 경우도 별도 거절한다.
- 경로 기억을 폐기하거나 선호 벽이 바뀌어도 소실 장애물 기억을 지우지 않는다. 명시 reset/센서 epoch 전환은 별도로 처리한다. 기존 strict와 파생 제어기의 reset 동작은 유지한다.
- 앞차에 대한 현재 점유·기존 간격/감속·HOLD/재개·회랑 경계 검사는 유지한다. 독립 보호층은 계획기 허가를 입력받지 않고 같은 센서로 자체 판단한다.
- 신규 선택의 raw scan은 판단 기록/재생에도 전달한다. 표면 정합·M3·M5까지 동시에 해결했다고 쓰지 않는다.

## 단위·출처 검사

새 정책의 작은 측방 공백 진행·넓은/정면 과대 공백 정지·앞차 정지·벽 전환 후 장애물 래치 유지·원시 입력 불일치·전방 창으로 이동한 결측 거절과 기존 지역 경로/기록/출처 관련 **135회귀**를 확인했다([로그](run3_tests.log)).

최초 출처 검사에서는 기존 회랑 모듈의 새 변경이 후속 계약에 기록됐음에도 과거 의존성 검사 루프가 그 사슬을 따라가지 않아1개가 실패했다. 다른 의존성과 같은 명시 사슬 검사를 적용했으며, 과거 계약 해시를 바꾸지 않았다. 첫 로그는 후속 호출로 실수로 덮어써 전체 원문을 회수하지 못했다. 도구에 남은 오류·개수·수정 근거는 [실패 기록](run2_initial_failure.txt)에 남긴다. 135통과를 그 최초 실패의 결과로 소급하지 않는다.

## 저장 판단 재생

10/16 원본 입력의 **2,837개 판단은 strict에서 전부 일치**했다. 같은 입력 순서의 v2 후보에서는 출력11개가 달라졌고, 그중 기존 단일 전방 결측 정지에서 새 양수 출력은3개(.5/.5/.35 m/s)였다. 나머지8개는 속도0인 해제 확인 대기였다. 새 양수3개는 모두 좁은 측방 결측 허용이며 unknown은 채우지 않았다. 입력 원본 해시도 유지됐다. [기본 동일성](run4_strict_replay.json), [후보 결과](run4_candidate_replay.json).

후속366호출은 `follow_known_obstacle_latched`였다. 새 명령대로 실제로 이동한 이력이 아니라 기존 정지 시점 이후의 입력을 계속 공급한 결과이므로, 새 폐루프의 진행/정체 결론으로 쓰지 않는다. 최대13.29 ms·p95 8.08 ms는 PC 오프라인 판단 비용이며 ROS 전체/Jetson 지연이 아니다.

## 공식 코스 단독 실행 run5 — 실패

추가된 원시 입력/기록 재생 대조를 포함한 관련 **282회귀**와 **ROS 35사례**를 통과한 뒤 실행했다. `corner_distance_candidate`, `per_ray_candidate`, 회랑 후보, v2 부분 관측, 판단 기록을 명시했고 임시3등·마커 관측·방지턱OFF·상한1 m/s 조건이었다. 시험 전후952파일이 같았다.

**43.213480 m에서 정지하여 전체48.6329 m를 완주하지 못했다.** 접촉0, 실제 실패 정지·MCU ESTOP·정상 종료·잔여 시험PID0을 확인했다. 34,223개 자세에서 네 바퀴 중심은 모두 도로 안쪽이었다. 이는 타이어 접지면/기울기·실차 판정이 아니다. [요약](run5_summary.json), [바퀴 중심](run5_wheel_centers.json), [실행 원본](run5_lap/report.json).

61.113초에는 `wide_or_many_missing`, 이후61.28초에는 `previous_point_in_missing_sweep`가 래치되어 재개하지 못했다. 원시 판단 기록112 MB는 Git 제외 정책으로 로컬에 보존한다. v2 연결 자체가 전체 G1 완주를 해결했다고 쓰지 않는다.

평가용 차체 자세와 실제 기록된 모터 피드백으로61.12–61.28초 구간을 대조하면, 모터 환산 이동과 차체 후륜축 이동은 **56.74 mm** 달랐다. 구간 중 바퀴 속도가 거의0이어도 차체는 약.35 m/s로 이동했다. 이 계산은 정답 회전을 사용해 평행이동 차이를 분리한 평가이며 정확한 제어기 전체 재생/실차 실측이 아니다. 제어 입력에는 정답을 넣지 않았다. [운동 대조](run5_braking_motion.json), [첫 소실 판단의 센서 좌표](run5_latch_context.json).

## 저장 입력 run6과 선택형 v3 연결

run5 판단2,896개를 원래 v2로 재생해 모두 일치했다. 같은 입력에 v3 표면 대응을 적용하면 최초 정지 소실 래치가 생기지 않았고, 승인된 정합3회에서 각각2개의 이전 위협점이 현재 표면과 대응했다. 대응 이동량은 약37/35/29 mm다. 평가용 모터/차체 차이56.74 mm와 구간·계산이 다르므로 서로 같은 값이어야 한다고 보지 않는다. 출력372개가 달랐지만 새 양수는6개이며 나머지는 대부분0속도의 조향 차이다. 실제 새 이동 결과가 아니다. [재생/정합 원문](run6_surface_probe.json).

이에 G1에도 `bounded_local_v3`를 명시 선택으로 연결했다. 기본 strict, v2 동작, 1 m/s 상한, 현재 점유·경로 경계·STOP을 유지한다. 표면 대응은 현재 반환과 예전 점의 대응에만 쓰며 위치 추정값·스캔·모터 피드백을 바꾸지 않는다. 충분한 정적 배경 가정이 필요하고 공통으로 움직이는 여러 물체의 모호성은 남는다.

정합의 `processing_ms`는 벽시계 측정이라 재생마다 달라진다. 해당 필드만 동일성 비교에서 제외하고 원시 기록은 유지한다. 승인 여부·이동량·속도·조향·다른 진단은 여전히 비교한다. 잘못된 음수/비유한 비용은 오류로 처리한다.

run7은 신규 시험1개가 후방 마스크 전 스캔과 마스크 후 점군을 짝지어 입력 일치 검사에서 거절됐다(295통과·1실패). 주행/ROS는 시작하지 않았다. 시험 입력을 실제 노드와 같이 맞춘 후 별도 run8에서 회귀·ROS·단독1랩을 확인한다. run7 실패로그와 소스는 보존한다. 다중 차량·실물 검증 완료가 아니다.

## run8: v3 단독 실행 실패와 다음 원인 분리

관련296회귀·ROS35 뒤 **43.173490 m에서 정지·0랩·접촉0**이었다. 이번 직접 사유는 `wide_or_many_missing`으로, 약80–83° 측방의5개 무반환이 폭3.6°를 차지해 기존3° 단일 공백 상한을 넘었다. 첫 정지는60.243초이고 직전 유효 이웃은약11.71 m와3.72 m였다. 알려진 장애물 소실 래치와는 다른 원인이므로 v3 정합만으로 해결된다고 보지 않는다.

실패 STOP의 정답 자세 감사는 **67.307–67.807초·248구간·최대 .000517 m/s**, MCU ESTOP·정상 종료·소스불변·잔류0을 확인했다. 실행 보조의 메시지에 run5의 STOP 숫자가 한 번 섞여 원본 report와 대조해 정정했다. 과거 실행값을 새 결과로 쓰지 않는다. 33,569자세의 바퀴 중심은 모두 도로 안이었다. [원본](run8_lap/report.json), [요약](run8_summary.json), [바퀴 감사](run8_wheel_centers.json).

v4는 먼저 저장 입력에서 **저속 측방 결측의 물리적 폭**을 비교한다. 속도/요청 상계.6 m/s 이하, 원시/이동 후 방향60–100°, 최소.6 m인 감속 검사 반경에서 결측 현폭5 cm 이하, 실제 이웃반환1 m 이상을 동시에 요구하고 목표를.2 m/s로 제한한다. 전체6°·5% 상한과 정면1.5°·근거리 소실 기억은 유지한다. 이 수치는 개발 후보이며 측방5 cm보다 작은 숨은 표적의 부재를 증명하지 않는다. 기존3°도 안전한 물체 최소 크기에서 유도된 규정값은 아니었다. 동일 실패 숫자를 통과시키는 데 그치지 않도록 큰공백·정면·근거리이웃·속도초과·회전·독립 소실물체 반례와 저장 입력을 먼저 대조한다.

## run9–11: v4 저장 비교와 선택형 연결

run9는 회전 반례의 입력 시각이 의도한 회전량에 못 미쳐 시험1개가 실패했다(84통과). 실제 변환 각도가 60° 아래로 들어가도록 시험 시각만 고쳤고, 다음 run10에서85회귀를 통과했다. [실패](run9_metric_tests.log), [수정 후](run10_metric_tests.log).

run8의 v3 판단 **2,852개가 원래 구성에서 모두 일치**했다. 같은 입력에서 v4는371명령을 바꾸었고 그중 새 양수는363개였다. 소실 래치·표면 정합 승인0, 최대14.90 ms·p95 8.71 ms는 PC 오프라인 비용이다. 새 명령대로 이동한 결과는 아니다. [입력 비교](run10_metric_probe.json).

실행 연결에서는 결측 셀 수만큼의 각도 대신 **양쪽 실제 유효 광선 사이 전체 간격(한 간격 추가)**으로 현폭을 계산하도록 더 보수적으로 정리했다. v4는 기본값을 바꾸지 않으며 G1과 독립 보호층에 각각 명시 전달한다. 큰 공백·정면·근거리 이웃·속도 초과·회전·알려진 물체 소실을 대조하는 회귀 및 ROS 검사 뒤 run11 한 번으로 실제 주행을 확인한다. 5 cm는 저속 시험의 잔여 미관측 폭 예산이지, 측정된 자유 공간 또는 실차의 최소 장애물 크기가 아니다.

## run11: 선택형 G1 단독 1랩 완료

관련309회귀·ROS35사례 뒤 **48.672700 m·1랩·접촉 표본0**을 확인했다. 상한1 m/s·순차 C1 10 Hz·both·가상 MCU·임시3등·마커 관측·방지턱OFF·기존 물성이다. 기존 실패 run5/run8의 결과를 바꾸지 않는다. [요약](run11_summary.json), [원본](run11_lap/report.json).

STOP의 평가 구간은69.283–69.783초,248구간·최대 간격3 ms·최대 속도 .009153 m/s로 등록 정지 기준을 충족했다. 정상 종료·잔류PID0·953파일 불변을 확인했다. 34,686개 자세의 네 바퀴 중심은 모두 도로 안이었고 최소 경계 거리는67.46 mm였다. 타이어 전체 접지·기울기·실차 안전의 증거는 아니다. [바퀴 중심](run11_wheel_centers.json).

기록2,951판단은 모두 동일 재생됐고 입력 불변·누락/기록 실패0이었다. 단, **v4 전용 측방 현폭 분기와 표면 정합 호출은 모두0**이었다. 제어기 부분 관측 사유는 전체 관측2,816, 좁은 측방58, 좁은 정면70, 정면 공백 거절7이다. 따라서 이번 결과는 선택형 G1 구성의 단독 완주이며 v4 현폭/정합의 효과를 입증한 대조가 아니다. 해당 기법의 증거는 아직 run6/run10 저장 입력 비교에 한정된다. [분기 감사](run11_mechanism_audit.json).

앞차가 있는 상태에서도 감속·HOLD·재개·STOP이 유지되는지 [교통 연결](../g1_partial_traffic_v1/README.md)에서 별도 검증한다. 단독 1랩은 5대·코너 병렬·공식4등·방지턱·5랩·실차의 완료가 아니다.

## 이후 교통 연결의 실행 순서 — 실행 전 계획

1. 같은 부분 관측 선택을 `validate_g1_traffic.py`에 명시 인자로 전달하고 실제 선택·소스·기록에 남긴다. 현재 주행이 끝난 뒤 수정하며, v2/v3/v4+G1+기록+10 Hz 순차+1 m/s 제한을 확인한다. M3와 자동 혼합하지 않는다.
2. 기존 `g1_traffic_v1.json`의 `stop_restart` seed0에서 앞차.35 m/s→5초 정지→재출발을 한 번 확인한다. 간격·감속·HOLD·재개·독립 보호·STOP을 동일 구성에서 본다. 관측 결측이 없으면 결측 후보의 효능이 아니라 교통 회귀로 분류한다.
3. 앞차 시험의 기존15 cm 간격·최종1.2 m·재개2.5초·차체 도로 안 판정은 원래 결과로 남긴다. 바퀴별 노면 감사·접촉을 나란히 기록하여 두 바퀴 잔디 정책과 구별한다. 당시 실패를 사후 임계값 수정으로 통과시키지 않는다. 측방 간격/잔디의 실제 정책 재설계는 별도 원인과 적용 범위를 명시한다.
4. 이 결과와 G1 단독 랩을 확보한 뒤 코너의 앞차 가림과 측방·그리드의 미연결 정책을 이어간다. 단독 결과와 직선 앞차 결과를 합쳐 전체 교통 랩이 완료됐다고 부르지 않는다.
