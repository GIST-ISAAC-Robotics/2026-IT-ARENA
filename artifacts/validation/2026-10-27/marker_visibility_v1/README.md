# 코스 마커를 처음부터 놓치는 단독 주행 대조

기준은 [부분 관측 run10](../partial_observation_v1/README.md)의 48.693 m·1랩이다. 제어기·보호층은 그대로 두고 실행 사본의 공식 마커 0/20/30/45 **시각 재질만 회색 판으로 변경**한다. 위치·판 형상·충돌·신호등·라이다 입력·카메라 수신은 유지한다. 원본 월드/PNG는 수정하지 않는다. 실제 앞차가 도로와 마커를 함께 가리는 경우를 재현한 시험은 아니다.

## 사전 등록

- 명시 `--course-marker-visibility blank_all`; 기본은 `visible`. `blank_30`도 구현하되 이번 실행 범위는 전체 가림 한 번이다.
- `local_pursuit`·가상MCU·순차10Hz·both보정·50Hz·grid3·상한1 m/s·`bounded_local_v2`·방지턱OFF·임시3등은 run10과 같다.
- 관련 회귀·기본 월드 동일 bytes·선택 재질 이외 XML 불변을 먼저 확인한다. 실제 주행은 하나라도 실패하면 수행하지 않는다.
- 기존 전체 랩 기준은 마커20/30 관측도 요구했다. 마커를 의도적으로 가린 시험에서는 관측할 수 없는 ID 조건만 제외하고, **전체 진행 거리·본선 연속성·접촉·STOP·정상 종료·센서 입력**은 그대로 본다. 실제 적용 기록과 가린 ID의 미검출도 요구한다. 양수 명령이나 정지하지 않았다는 것만으로 통과하지 않는다.
- 전체 코스46.6329 m+정지여유2 m, 시뮬180초·회수1800초·STOP90초를 유지한다. 실패를 보존하고 같은 조건을 성공까지 반복하지 않는다.

기대 결과를 미리 성공으로 쓰지 않는다. 분기/합류에서 벽 선택이 잘못되면 그 위치·센서 판단·실제 경로를 근거로 다음 수정 범위를 정한다. 이 비교는 다른 차량이 있는 경기 주행이나 실물 가림 증거가 아니다.

## run1 실패와 진단

관련 **135회귀**·기본 사본 동일성·949소스 불변을 확인했다. 실제 주행은 **43.353340 m·0랩·접촉0**으로 실패했다. 표시 변경은 0/20/30/45 판 재질만 적용됐고, 주행 615상태 표본의 마커 ID는 전부 빈 배열이었다. `previous_point_in_missing_sweep`가 시뮬54.900 s에 래치됐다. 명시 STOP·.5초 밀집 정지·정상 종료·잔류0은 통과했다. 밀집31,074자세의 바퀴 중심 이탈도0이다. [원본 판정](run1_lap/report.json), [요약](run1_summary.json), [바퀴 감사](run1_wheel_centers.json).

이 결과만으로 마커 누락이 직접 원인이라고 단정하지 않는다. run10과 달라진 관측/운동 시점에서 보호층의 이전 점 검사가 걸렸으며, 당시에는 래치 원인점과 현재 반환의 근접도가 기록되지 않았다. 코드에서는 이전 점이 넓어진 결측 원뿔과 감속 외곽에 걸리면 래치하며, **그 점 위치에 현재 반환이 남아 있는지**는 따로 비교하지 않았다. 실제로 같은 점이 계속 보이는 단위 반례도 래치된다.

run2는 출력 조건을 바꾸지 않고 최초 래치의 광선·이전 점 현재좌표·현재 최근접 반환·거리·시각·외곽 속도/조향을 최대8개 기록하는 진단 1회다. 알려진 물체가 실제로 사라졌는지와 보이는 벽까지 겹쳐 잡았는지를 분리한다. 1회에서 재발하지 않으면 그 한계를 그대로 남기고 같은 조건을 반복하지 않는다.

## run2: 현재도 보이는 점을 소실로 취급한 진단

관련138회귀·949소스 불변을 확인한 진단 주행도 **43.393330 m·0랩·접촉0**으로 실패했다. 명시STOP·밀집 정지·정상 종료·잔류0을 확인했다. 54.800 s 래치에서 세 원인점 모두 현재 최근접 반환과 **1.78–2.55×10⁻¹⁶ m** 거리였다. 즉, 실제 현재 관측에도 같은 좌표가 남아 있었다. 점/물체의 신원까지 판정한 것은 아니다. [요약](run2_summary.json), [최초 래치 원인점·출처](run2_latch_evidence.json)에 보존한다. 상세 상태 전체는 Git 제외 원시 로그에 남긴다.

코드 조사에서는 새 스캔을 처음 처리할 때 `previous`를 그 스캔으로 바꾸고, 같은 스캔을 다시 처리하면 자신과 비교하는 별도 문제도 확인했다. run2의 과거 source 시각은 직접 기록되지 않았으므로 그 호출이 동일 source였다고 수치만으로 확정하지 않는다. run3부터는 직전 **서로 다른 스캔**을 별도로 남기고 이전/현재 source 시각을 진단에 포함한다.

run3 수정은 현재 유효 반환으로 **2 cm 이내 재관측된 이전 점**을 ‘소실한 점’ 검사에서만 제외하는 것이다. 현재 점은 독립 제동/충돌 검사에 그대로 남는다. 실제로 사라진 점·새 조향에서 위협이 되는 이전 미관측점·입력 만료·넓은 공백·STOP을 별도 반례로 확인한다. 2 cm는 대응 후보값이며 제조사 오차 보장이나 물체 신원 증명이 아니다. 가림 뒤 다른 물체가 같은 위치를 차지하는 모호성은 남고, 실제 거리 잡음에서는 보수적 오정지가 다시 생길 수 있다. 기존 폭·속도·물성·제동값을 느슨하게 하지 않았다.

정책 단위56개 확인 뒤 관련140회귀·ROS35와 같은 전체 가림 1회를 진행했다. run10의 첫 완주와 run1/run2 실패의 당시 소스는 각각 별도 보존한다.

0–43 m의 저장 경로도 대조했다. 마커가 보인 run10은 왼쪽/오른쪽 선호를 전환했고, 가린 run1은 왼쪽 선호를 계속 유지하면서 실제 추종 벽은 23상태 표본에서 오른쪽으로 대체했다. 진행 차이가 .025 m 이내인 253쌍의 최대 위치 차이는 .04322 m였다. 따라서 마커 누락이 전 구간의 동일한 출력을 뜻하지는 않지만, 이 구간에서는 기존 대체 벽 로직으로 진행했다. 전체 완주·누락 일반화는 후속 주행에서 따로 본다. [겹치는 진행 구간 비교](run1_prefix_comparison.json).

## run3: 서로 다른 표본 위치의 대응 한계

결과는 **43.293390 m·0랩·접촉0**으로 실패했다. 명시STOP·밀집 정지·정상 종료14/14·잔류0·949소스 불변은 확인했고, 30,532자세의 바퀴 중심은 모두 도로 안이었다. [요약](run3_summary.json), [최초 래치](run3_latch_evidence.json), [바퀴 감사](run3_wheel_centers.json).

54.78 s 최초 래치의 이전/현재 스캔 시작 시각은 각각 54.502/54.602 s로 서로 달랐다. 원인점 `(0.069183, 0.679100) m`의 현재 최근접 반환은 `(0.052925, 0.665797) m`였고, 거리는 **21.0065 mm**였다. 고정 20 mm 점 대응 바로 밖이지만, 이 결과만으로 그 두 점이 같은 벽이라는 신원 판단을 내리지는 않는다.

다음 run4에서는 점 대응 거리를 올리지 않고 **실제 연속 유효 광선 세 개가 이루는 짧은 표면**도 대응 근거로 사용한다. 각 현 길이≤60 mm·방향 변화≤30°·이전 점의 현 내부 투영·수직 거리≤10 mm를 요구한다. 최근접 실제 점 거리가 20–40 mm일 때만 보조 판단하며, 결측/중복 인덱스 사이 연결·끝점 외삽·긴 현·급격한 코너·반전은 거절한다. 조건값은 저속 후보값이며 센서 정확도나 벽 신원 보증이 아니다.

이 짧은 현은 ‘이전 점 소실’ 가설을 대조할 때만 사용한다. 가상 측정점·자유 공간으로 추가하지 않고 현재 실제 반환은 전부 독립 충돌 검사에 유지한다. 가까운 여러 물체가 같은 표면처럼 보이는 모호성은 남는다. 반례·ROS 고장 검사를 통과한 뒤 같은 전체 가림 1회를 수행하며, 기존 속도·공백 폭·물성·제동값은 유지한다.

## run4: 짧은 표면 대응도 미성립, 제동 중 이동 오차 단서

관련148회귀·ROS35는 통과했으나 주행은 **43.293390 m·0랩·접촉0**으로 실패했다. 최초 래치는54.82 s였고 짧은 표면 대응이 기록된 사례는0이었다. STOP·밀집 정지·14/14정상 종료·잔류0·949소스 불변은 확인했다. 30,926자세의 바퀴 중심도 도로 안이었다. [요약](run4_summary.json), [최초 래치](run4_latch_evidence.json), [바퀴 감사](run4_wheel_centers.json).

원인점의 최근접 반환 거리20.19–26.63 mm는 단순한 점 간격으로 확정할 수 없다. 제동 구간의 운동 기록에서 **바퀴 표면 속도 .00233 m/s와 차체 종방향 속도 .31056 m/s**가 동시에 나타났다. 단일 모터축 피드백은 유지됐고 좌우 바퀴 엔코더로 회귀한 것이 아니다.

평가용 정답 yaw만 사용해 자이로 오차를 제외하고, 저장 모터축 피드백으로54.62–54.82 s의 후륜축 이동을 적분한 별도 대조에서는 실제 이동과 **20.88 mm 차이**가 났다. 피드백 최대 나이는9.5 ms였다. 이 값은 실제 제어기의 모든 보정 단계를 재생한 결과가 아니며, 그 이전 스캔 내부 보정 오차·필터/시각 오차를 각각 분리하지 못한다. 다만 제동 중 모터축 이동을 차체 이동으로 간주하는 한계가 이번 점 대응 차이를 설명할 수 있다는 근거다. 정답 yaw·차체 위치는 이 오프라인 분석에만 사용했다. [이동 대조와 원시 출처 해시](run4_braking_motion.json).

run5는 출력 조건을 바꾸지 않고 최초 실패의 이전/현재 센서 점군과 추정 상대 자세를 보존하는 진단1회다. 이후 대응 가설은 이 입력에서 먼저 비교한다. 가까운 반환의 위치 허용치를 실패 숫자에 맞춰 올리기 전에, 여러 관측 표면이 지지하는 공통 이동 차이가 있는지와 독립 장애물이 사라진 반례를 구분한다. 정합 가설은 아직 제어에 연결하지 않는다.

오프라인 분석 함수는 점과 선분의 법선 방향 오차를 최소화하는 정합 아이디어를 참고한다([Censi, 2008, 원 논문](https://censi.science/pub/research/2008-icra-plicp.pdf)). 여기서는 gyro 회전을 유지하고 이동2축만 제한적으로 비교하므로 논문의 PLICP 전체 구현이나 그 성능 재현이라고 부르지 않는다. 회전·이동을 함께 푸는 논문의 정확한 해와도 구별한다. [분석 함수](probe_surface_translation.py)는 연속 실제 표면만 사용하고, 평행 벽처럼 이동 한 축이 불분명하면 거절한다. 제한 합성4장면에서 작은 공통 이동 복원·평행 벽 거절·큰 이동 거절·사라진 독립 표적의 미대응을 확인했다([합성 결과](surface_translation_selfcheck.json)). 모든 관측 물체가 함께 움직이는 장면과 실제 잡음은 이 확인으로 해결되지 않는다.

## run5 저장 점군과 선택형 v3

출력 불변 진단도 **43.293390 m·0랩·접촉0**으로 실패했다. 관련148회귀·소스불변·STOP·밀집 정지·정상 종료·잔류0을 확인했으며 ROS35는 run4와 제어 조건이 같아 반복하지 않았다. 54.92 s 래치의 이전 점385개·현재 반환414개를 [최초 실패 문맥](run5_latch_context.json)에 보존했다. [주행 요약](run5_summary.json), [바퀴 감사](run5_wheel_centers.json).

새 표본의 모터축/실제 이동 차이는22.49 mm였고([운동 대조](run5_braking_motion.json)), 현재 점군에 대한 고정 회전·이동 정합은 `(-21.32, +4.08) mm`, 크기21.71 mm였다. 최종331개 대응·법선 관측성 비율.479·잔차 RMS2.63 mm로 수렴했다. 보존된 문제점8개의 최근접 반환 거리는 공통 이동 대조 뒤0.38–11.49 mm였다([정합 가설 결과](run5_surface_translation.json)). 모터축 보정만으로 현재 벽과의 관계가 어긋났다는 해석을 지지하지만, 이를 독립적인 실제 속도/위치 확인으로 승격하지 않는다.

기존 [기록 전용 스캔 진단](../../../../scripts/scan_motion_diagnostic.py)은 미보정 원시 스캔의 독립 이동 일치성 검사이며, 순차 왜곡·동적 구조·처리 비용 때문에 운영 연결을 보류했다. 이번 후보는 이미 모터축/gyro로 보정한 점을 재사용하는 **대응 보조**다. 같은 센서 오차를 독립적으로 검증했다고 주장하지 않으며, 새 위치 추정기·SLAM·실제 차체 정지 확인으로 사용하지 않는다.

`bounded_local_v3`는 v2의 명시 후속 선택지이고 기본은 여전히 `strict`다. 실제 연속 표면·50개 이상/65% 이상 대응·양측 공간 지원·.7 m 이상 전후 범위·법선 관측성·60 mm 이동 상한·10 mm 잔차·수렴/개선 조건을 검사한다. 고정된 배경이 충분하다는 가정이 남는다. 동적 물체가 시야 대부분을 차지하거나 모든 구조가 같이 움직이는 경우에는 잘못된 공통 이동을 얻을 수 있어 다중 차량 적용은 별도 검증 대상이다.

허용된 이동 후보를 적용한 옛 점이 현재 실제 반환에 다시 대응하는 경우에만 ‘소실’ 후보에서 제외한다. **대응하지 않은 옛 점의 위협 위치는 이동시키지 않으며, 현재 반환·조향 경로·모터 속도·입력 나이·unknown은 바꾸지 않는다.** 같은 스캔 쌍의 이동 후보는 gyro 회전에 맞춰 재사용하고 새 스캔에서 다시 구한다. 공간/개수 제한은 계산량을 제한하기 위한 후보 조건이며 실패하면 기존 소실 판정이 유지된다.

제한 단위 시험에서 기록된 실패 점 대응·평행 벽/편측/큰 이동/결측 사이 연결 거절·독립 소실 표적 정지·현재 가까운 장애물 제동·같은 쌍 재사용을 확인했다. 구현 중 현을 띄엄띄엄 선택한 최적화가 관측 벽에 인위적인 대응 공백을 만든 반례를 수정해, 현재 입력 상한 안에서는 인접 현을 모두 유지했다. run6은 관련 회귀·실제 ROS 고장 검사 뒤 같은 마커 전체 가림1랩을 v3로 수행한다. 성공하기 전에는 완주 근거로 표시하지 않는다.

## run6: 전체 가림 1랩, 정합 효과는 입증하지 못함

`bounded_local_v3` 선택 실행은 **48.652710 m·1랩·접촉0·명시STOP·정상 종료**를 확인했다. STOP 안정 구간65.407–65.907 s의250개 구간에서 최대 차체 속도 .008223 m/s, 자식14/14 정상 종료·잔류0·949소스 불변을 확인했다. [원본 판정](run6_lap/report.json), [요약](run6_summary.json).

55.06 s에 기존 소실 보호가 일시 래치됐고, 약4.6초 뒤 완전 관측 회복 조건으로 재개했다. 기록된 표면 대응 진단5개 중 승인0·대응점0·캐시4개였다. 정합 자체는 이동 약9.9 mm와 최종 RMS4.56 mm로 수렴했지만, 최초6.84 mm 대비40% 이상 개선 조건을 만족하지 않아 `weak_improvement`로 거절됐다. **따라서 이 완주를 표면 정합 기법의 효과나 v3의 견고성 입증으로 해석하지 않는다.** 계산 시간·입력 시점이 달라진 폐루프이므로 기존 v2 실패를 이 결과로 성공 처리하지도 않는다. 진단에 기록된 최대 정합 비용은21.96 ms이고, 캐시에 남은 비용은 새 계산 비용이 아니다. 전체 제어 지연·Jetson 처리율 근거가 아니다.

검사 중 새 표면 정합 파일 이름을 기존 기록 전용 `surface_correspondence.py`와 겹치게 만든 구현 실수를 발견했다. run6의159선택 회귀·ROS35는 그 당시 실행 사본의 결과이고 기존 전체 기능의 회귀로 쓰지 않는다. 실행 당시 소스는 [스냅샷](run6_source_snapshot.zip)에 보존했다. 이후 새 코드는 `partial_surface_alignment.py`로 분리했고 기존 모듈·테스트는 `0e6c28a`의 바이트와 정확히 같게 복구했다. run7에서 복구 뒤 전체 Python 회귀와 ROS35를 확인하며, 이름 분리만을 이유로 같은 주행을 반복하지 않는다.
