# 현재 G1 구성의 밀집 출발 후속 설계

2026-10-27. 전체 랩 실행 중 독립적으로 정리한 다음 시험 설계이며 아직 구현/실행 결과가 아니다.

## 기존 정지 비교의 해석

`m5_current_masked.json`에서 단독 6칸은 진행하고 2/3/5대의 10위치는 모두 정지했다. 선두 2번 칸은 중앙으로 들어가는 기본 경로의 간격 때문에 정지하고, 다른 칸은 벽 경계를 확인하지 못했다. 상대차까지 정지한 단일 자세를 반복했으므로 영구 교착이라고 단정할 수 없다. 다른 줄이 먼저 움직여 시야가 열리면 같은 제어기가 출발할 수도 있다.

## 최소 후속 비교

기존 `simulate_grid_departure.py`의 취득 시각별 광선·28카운트 모터축·자이로·이상 bicycle·별도 이력의 보호층을 재사용하되 **기존 M3 결과와 새 G1 선택기를 혼합하지 않는다**. 현재 동일 G1 설정을 명시하는 별도 실행 경로를 준비한다. 기본 M3 경로와 기존 결과는 유지한다.

- 2대 중 선두 2번 칸: 초기 간격 정지와 옆줄 선출발 후 진행 여부.
- 2대 중 후속 5번 칸: 앞차가 이동했을 때 벽/경로 확인과 재개 여부.
- 5대 중 가운데 1번 칸: 앞/옆 가림과 같은 줄 뒤 정지 차량이 있는 경우.
- 움직이지 않는 상대차 대조에서는 계속 기다리는 것 자체를 실패로 만들지 않는다. 가까운 물체로 전진하는지와 출발 후 소실을 구분한다.

제어기는 `LocalFollow`의 현재 v4·corner-distance·per-ray·회랑·평행/통과/GUARD 조합만 사용한다. 과거 M3의 직진 우선/복귀 보류 옵션은 동시에 켜지 않는다. 원시 scan에도 현행 후방 마스크를 적용해 `motion_scene`과 계약을 맞추고, `raw_scan`을 같은 호출에 전달한다. 바퀴/IMU 정답이 아니라 기존 합성 카운트/시각 이력을 사용한다.

첫 비교의 목적은 정지 광선 결과가 상대 출발 후에도 지속되는지 분리하는 것이다. 첫 양수 요청/보호 출력 시각·진행량·정지 이유·간격·바퀴 노면·명시 0 명령을 기록한다. 필요한 이후 물리 시험을 선택하는 근거이며 실제 신호 출발, ROS 전달, MCU PI, 접지/제동 또는 자율 5대 주행의 증명이 아니다. 초기 6초 비교를 전체 M5 완성으로 쓰지 않는다.

## 공식 신호와의 순서

공식 제작 설명은 가로 빨강4세트·초록1세트이며, 이전 세로 겹침은 SDF 배열 방향의 문제였다. [가로 배열 팀 시험본](../official_signal_orientation_v1/README.md)에서 기존 검출기를 먼저 대조한다. 방향을 고정하지 않는 순차 증가 시제품의 연결은 보류한다. 실제 점등 전환·빨강 가림 뒤 초록 노출은 별도 확인하고, 카메라 뒤쪽 .20/.30 m 후보는 기존 임시 높이의 시험 결과로만 취급한다.

빨강 전체가 가려지고 초록만 보이는 경우는 별도 영상 근거가 필요하다. 앞차 움직임이나 초록 픽셀 하나만으로 허가하는 로직을 추가하지 않는다. 정상 순차 점등 검증을 이 문제의 완전 해결까지 무조건 보류하지도 않는다.
