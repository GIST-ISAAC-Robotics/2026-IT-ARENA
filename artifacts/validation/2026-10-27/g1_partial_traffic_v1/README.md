# G1 부분 관측 선택 구성의 앞차 회귀

[단독 1랩](../g1_partial_integration_v1/README.md)에서 선택한 구성과 앞차 정지·재개를 연결한다. 단독 결과를 다중 차량 성과로 확대하지 않는다.

## 구현과 시험 경계

- 교통 시험기에 `--partial-observation-policy`를 명시 전달한다. 기본 strict는 기존 실행 인자와 trace 형식을 유지한다. 후보 v2/v3/v4는 기록을 켠 G1·순차10 Hz·both·1 m/s 비교 프로필·가상 MCU에서만 받는다. R0+/M3나 B3 운영 시험과 자동 혼합하지 않는다.
- 제어/보호 양쪽 부분 관측 진단을 원형 그대로 추가 기록한다. 양쪽 진단이나 제어기 선택값이 없거나 `unknown_filled`가 false가 아니면 연결 검증을 통과시키지 않는다. 기존 교통 판정도 별도로 보존한다.
- 추종 간격·현재 점유·HOLD/재개·독립 보호층·STOP·물성은 이번 연결에서 바꾸지 않았다. 추가된 모듈과 계약을 소스 보존 목록에 포함했다. 이전 evaluator와 계약은 `before_traffic_link_source.zip`, 원래 기준은 이전 고정 커밋에 보존한다.
- run1은 기존 `g1_traffic_v1.json`의 `stop_restart` seed0 한 번이다. 앞차 .35 m/s 4초 → 정지5초 → .35 m/s 6초. 임시3등·방지턱OFF·마커 관측·그리드3을 유지한다. 실제로 자기 제어를 하는 차량이 아니라 평가기가 이동시키는 정적 상자다.
- 기존15 cm 간격·최종1.2 m·재개2.5초·차체 도로 안 판정은 그대로 남기고 바퀴 중심 노면 감사를 추가한다. 부분 관측이 없었다면 결측 처리 효과가 아니라 구성 연결 후 교통 회귀다.

## run1 결과

관련234회귀 뒤 첫 앞차 폐루프의 실행·행동12관문을 모두 통과했다. HOLD3.240초·재개지연.547초·재개후1.8398 m·전체4.25956 m·최소 표본간격.364517 m·최종간격.626209 m였다. 접촉0·실제 STOP·MCU software_stop·정상 종료·잔류0·소스불변을 확인했다. [요약](run1_summary.json), [원본](run1_stop_restart/report.json).

STOP 평가창19.059–19.559초·247구간의 최대 속도는.008088 m/s였고 최대 구간 공백3 ms다. 9,606자세에서 네 바퀴 중심은 전부 도로 안이었다. 기록789판단은 모두 동일 재생됐고 입력 불변이다. [바퀴 중심](run1_wheel_centers.json).

실제 제어기145행·보호층181행의 부분 관측 진단을 확인했지만 결측 판단은0행이었다. 따라서 **새 결측 후보의 효능 증명이 아니라 선택형 연결 뒤 기존 앞차 기능의 회귀 통과**다. 기본 strict와 과거 실패를 바꾸지 않는다.

 첫 환경 호출에서 ROS 환경을 로드하지 않아 xacro import 수집 오류가 있었으며 테스트 본문/주행은 시작되지 않았다. 저장 bash는 Jazzy와 install 환경을 먼저 로드한다.

이 기록의 통과는 코너 가림·측방·밀집 출발·공식4등·방지턱·5랩·Jetson/실차를 뜻하지 않는다.
