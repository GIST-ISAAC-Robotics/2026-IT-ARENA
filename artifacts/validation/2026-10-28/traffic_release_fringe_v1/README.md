# 통과 후 후방 결측 처리 연결

2026-10-28. [직전 실제 실행의 조기 정지 분석](../traffic_recovery_connection_v1/EARLY_HOLD_FINDING.md)에 근거한 후속 작업이다. 직전 실행26.656 m 실패·STOP/종료·7,813판단 동일·996파일 불변을 회수한 뒤 구현했다.

현재 `traffic_recovery_trial`은 통과 기억을 유지한 RELEASED에서도 작은 이동을 포함한 실제 예측 영역을 검사한다. 다만 GUARD에서 이미 사용하는 좁은 후반부 무반환 분류가 빠져 있다. 같은40.0 s 입력에서 기존 검사를 직접 적용하면 통과하며, 따라서 선택형 ON·유지된 통과 이력·명령0.35 m/s 이하에서만 같은 검사를 연결한다.

이는 미관측 공간을 자유 공간으로 바꾸는 수정이 아니다. 기존 후반 옆면1 mm·공백3도·먼 양옆 반환·현재 점유 여유와 마스크 검사를 유지한다. 미관측 개수와 얇은 물체·동적 접근 위험도 그대로 기록한다. 기본값은 계속false다.

## 수정 전 재현

`test_release_fringe_candidate.py`는 상태와 예측 영역만 주입하고 실제 `bounded_rear_fringe` 검사를 사용한다. 새 경로/실제 센서 인식을 증명하는 시험은 아니다. `before_tests.log`: 진행해야 할 연결1건 실패, 넓은 결측·가까운 반환·앞부분·1 mm 초과·잘못된 입력·새 옆차·경로 소실·STOP 등19건 통과.

## 구현·검증

`pass_release_trial.py` 한 구현 파일에서 유지된 통과 이력의 후반 분류를 연결했다. GUARD의 같은 경로 후보와1 mm 후반 후보는 명령을 바꾸지 않고 보고 이유/표식만 구별했다. 부모r0·이전 bytes를 `before.zip`과 `traffic_recovery_release_fringe_r1_sha256.json`에 보존했다. 회귀322건이 통과했다. ROS 입력/출력·보호층·물성은 수정하지 않았다.

`compare_recording.py`는 완료된run1의 처음부터60 s까지 입력을 순서대로 공급하고 별도 보호 상태 객체로 출력도 비교했다. 총2,808판단 중1,379명령이 새 후반 분류로 바뀌었고 다른 이유의 명령 변화는 없었다. 목표30–49 s의951회 중 양수 출력은 원래65회→후보/보호 각895회였다. 새로 반환된0명령266건은 독립 보호에서도0이었다. 전체 출력 기본값 OFF는 이전7,790판단과 동일했다. 소스/입력 불변을 확인했으며 실제 독립 ROS 통신·폐루프 주행은 아니다. 비용 중앙22.01/p99 33.23/최대86.60 ms로50 Hz 실시간 통과를 주장하지 않는다. [비교 결과](recording_comparison/report.json).

## 실제 실행과 재개

`run1_snapshot.py`로998파일을 고정하고 이전과 같은155 s·52.5 m 목표·seed0·앞차/옆차 각본·속도/센서/물성·임시3등·방지턱OFF의 `run1_trial.sh`를 실행했다. 변경은 선택형 후반 분류 연결이다. `run1_import_source.log`에서 현 checkout의 Python 모듈을 읽는 것도 확인했다.

결과는 **43.05354 m 진행, 전체 랩·최종 앞차 간격 실패**다. 기존8.659 m의105.304 s 정체는 통과했다. 새 후반 분류는23회 양수 출력에 사용됐고 미관측 질의의 차체 옆면 밖 최대 거리는0.9601 mm였다. 측정 정밀도나 실제 장애물 여유가 아니다. 같은 경로 제한 보완도1회 사용됐다. 후반129.645–158.503 s에는43.054 m에서28.858 s 정지했고 다시 진행하지 않았다.

접촉·노면 밖 자세·표본 바퀴 중심 이탈0, 명시STOP·정상 종료·잔존 프로세스0, **7,791/7,791판단 동일 재생·998파일 불변**을 확인했다. STOP 전에 이미 정지한 경우이므로 이번 STOP 결과를 이동 중 제동 성능 향상으로 해석하지 않는다. [요약](run1_diagnostics.json), [세 실행의 진행 비교](course_comparison.png), 원래 실패 판정을 보존한다.

후반 고정 사본의 부분 관측은 허용되었고 소실 래치/앵커는 없었다. 현재 정체는 `follow_boundary_unconfirmed`가 선택기의 `baseline_not_normal`로 이어진 것이다. 긴 선호 오른쪽 벽과 짧은 왼쪽 안쪽 면의 역할을 분리하는 기존10/17 미연결 후보를 [다음 저장 입력 대조](../traffic_corridor_roles_v1/README.md)에서 검토한다. 반복 주행보다 원인에 맞는 기하·시간·보호 대조를 먼저 수행한다.

## 처리 비용의 제한 진단

현재 실행 코드를 바꾸지 않고 이전40 s의 한 고정 입력을30회 계산했다. 스레드 CPU 중앙값은 이동 영역 분류11.41 ms, 후반 무반환 검사4.62 ms였다. Gazebo와 동시에 수행한 PC 함수 진단이며 전체 파이프라인/Jetson/실시간 판정이 아니다. 결측 처리를 없애거나 표본 수를 줄일 근거로 쓰지 않는다. 실제 주행 결과를 먼저 확인한 뒤 계산 중복·벡터화 검토의 우선순위를 잡는 자료다. [원시 계측과 조건](geometry_profile/report.json).

## 무반환의 사후 기하 대조

이전run1의40.0·136.700·136.720 s 저장 광선449–454를 정적 벽과 대조했다. 첫 시도는 단독/교통 보고서 스키마 차이로 실패했고, 먼저 명목 SDF 높이의 평면 결과를 보존한 뒤 별도 제동 진단의 실제3D 차체 자세를 사용했다. 제어기에는 정답 자세를 넣지 않았다.

40 s에서451번의 정적 벽 교차는12.157 m로범위12 m를 넘지만,452번은11.944 m인데 원시값은+inf다. 벽 충돌 상자와 시각 메시 교차는 일치했다. 기록된roll/pitch는 사실상0이므로 이 예시를 차체 기울어짐에 따른 바닥 반환으로 설명할 근거는 없다. 인접한3.797 m 반환은 벽만 계산한 이 대조와 다르며 이동 차량/다른 물체를 포함하지 않았으므로 물체 신원을 확정하지 않는다.

취득 시각을 둘러싼 자세 표본, 정적 메시의 수학적 교차일 뿐 GPU 광선 렌더링·반사·동적 물체 재현은 아니다. 무반환 전체를 거리 제한만으로 설명하거나 공식 트랙 버그로 단정하지 않는다. `rear_nonreturn_geometry.json`·[3D 자세 대조](rear_nonreturn_pose3d.json)와 첫 시도의 오류를 보존한다. 추가 주행을 이 기하 결과 때문에 반복하지 않는다.
