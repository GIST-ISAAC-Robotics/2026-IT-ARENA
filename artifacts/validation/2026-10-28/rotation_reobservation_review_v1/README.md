# 회전 오차 정체의 상대 정합 개선율 재검토

2026-10-28. 분리 비교와 전체 저장 입력 대조 후 기존 명시 교통 회복에만 연결했다. run4는1랩을 완료했으나 기존150 mm 간격 기준은 실패했으며 새 분기 단독의 인과 효과는 입증하지 못했다. 상세 결과는 아래와 [주행 보고서](../rotation_stress_v1/README.md)에 둔다.

## 확인한 문제

네 반환의 표면 대응을 넣은 회전 오차 run3도43.054 m에서 정체했다. 실제 입력은 run2와 달라졌으며, 첫 과거점이 연속 표면의 내부가 아닌 끝 밖에 있어 새 표면 대응으로는 재관측되지 않았다. 그다음 스캔은 현재 반환까지6.14 mm로1회 확인됐으나 두 번째 정합이 `weak_improvement`로 거절됐다. 원래 실패와 입력은 [회전 오차 기록](../rotation_stress_v1/README.md)에 남긴다.

`extract_latch.py`는 저장된 판단만 추출한다. `inspect_geometry.py`는 거절된 정합 이동을 좌표 진단에만 적용한다. 두 번째 스캔의 정합은약3.4 mm 이동, 잔차4.806→3.800 mm로 수렴했지만 상대40%개선에는 미달했다. 이 이동을 가정하면 과거점은 현재 반환에서5.51 mm 떨어져 있다. 이를 실제 재관측 성공으로 기록하지 않는다. [저장 판단](run3/summary.json), [진단 기하](run3/geometry.json).

## 비교할 대안

거리 대응2 cm·추가 표면4 cm, 두 개의 서로 다른 스캔, 과거점 전체의 확인, 기억 수명을 그대로 두고 **작은 정합의 상대 개선율**만 별도로 검토한다. `small_alignment_candidate.py`는 기존 함수가 성공하면 그대로 반환한다. `weak_improvement`일 때에만 아래 조건으로 비교하며 다른 기하·수렴 실패는 구제하지 않는다.

- 기존 반복의 실제 수렴(마지막 이동10 µm 미만), 전체 이동10 mm 이하, 최종 절대 잔차5 mm 이하이며 초기보다 나빠지지 않음.
- 모든 반복의 지지율65% 이상·법선 관측 비율0.02 이상.
- 이전 표본을 짝/홀 두 집합으로 나누어 같은 함수를 각각 실행한다. 둘 다 위 절대 조건을 만족하고, 전체 추정과 각각2 mm 이내·서로2 mm 이내여야 함.
- 원래 전체 이동만 사용하며 현재 센서 점·gyro 회전·장착 보정을 바꾸지 않음. 정적 배경과 물체 신원의 한계는 남음.

수치는 새로운 시험 가정이며 C1/IMU의 실측 정확도나 통계적 신뢰 구간이 아니다. 짝/홀 표본도 같은 장면의 관측이므로 독립된 센서 검증은 아니다. 이 비교가 통과하더라도 전체 제어기·독립 보호층·폐루프 검증 없이 운영에 채택하지 않는다. 작은 정합까지 상대 개선율을 고집하는 것이 필요한지 확인하려는 목적이다.

## 첫 비교 결과와 같은 표본 비교안

첫 비교는19검사를 통과했지만 run3의 재관측을 회복하지 못했다. `candidate_diagnostics_v2.json`에서 전체와 짝수 집합의 작은 이동은 수렴했으나 홀수 집합의 잔차가4.360→4.538 mm로 증가해 거절됐다. 이때 대응 표본 수도181→184로 달랐다. 기존 함수는 반복마다 가까운 현과 가중치를 다시 고르므로 초기/최종 RMS가 **동일한 표본의 전후 오차는 아니다**. 이 차이만으로 제안 이동이 옳다고 확정할 수도 없다. run2에서는 기존/후보 모두133.62초에 재관측돼 기존 성과는 유지했다. [run3](run3/candidate_diagnostics_v2.json), [run2](run2/candidate_v2.json).

`consistent_alignment_candidate.py`는 이 비교 문제를 분리하는 미연결 v2다. 최종5 mm 잔차·10 mm 이동·수렴·지지 조건을 유지하되, 같은 이전 표본·같은 현재 현·같은 초기 가중치로 이동 전후 오차를 다시 계산한다. 표본을 임의로 골라 잔차가 작아 보이지 않도록 전체의65% 이상과 기존 대응의95% 이상이 유지되어야 한다. 짝/홀 추정은 반대 집합에서도 이 조건을 만족해야 하며, 추정 간2 mm 일치 조건은 유지한다. 서로 다른 표본 수의 RMS 비교를 대체하는 시험안이며 운영 함수에는 아직 연결하지 않았다.

지지율·거리·이동 한계의 위 수치들은 이번 비교를 위한 가정이다. 단순히 run3을 통과시키려는 수치 탐색으로 확대하지 않는다. 반례와 분리된 재관측 비교 뒤에만 전체 저장 입력·독립 보호 대조를 검토한다.

## 실행과 보존

`check_and_probe.sh`와 `probe_diagnostics.sh`는 첫 비교의 실행 원본이다. `fixed_probe.sh`의10계약은 통과했으나 run3 재관측은 회복하지 못했다.133.72초 이동에서 최초 선분의 끝 안에 남은 점만 선택해358→229개가 되며 거절됐다. 개별 현 경계를 지나도 같은 유한 벽에 남을 수 있으므로, v3 `finite_segment_candidate.py`는 점을 버리지 않고 **고정한 유한 선분/끝점까지의 실제 거리**로 비교한다. 무한 표면 연장·미관측 보간은 하지 않는다. 관련 끝점/잘못된 이동 반례와 실제 입력 비교는 `finite_probe.sh`로 실행한다.

`fixture.json`은 상세 센서 좌표가 포함되어 Git 제외하며 해시는 각 summary에 남긴다. 새 probe 결과에는 후보 파일 해시도 남긴다. 이 분리된 상태 재현은 실제 제어기의 해제·새 주행 성공이 아니다. 후속 전체 상태 대조 결과는 아래에 둔다.

## v3 결과와 명시 연결

v3 분리 상태에서 run3은133.72초 두 번째 재관측을 확인했다(기존은 확인 없음). 전체 추정은약3.41 mm, 두 집합의 추정차는1.079 mm다. 동일358점·같은 유한 현의 오차는4.586→4.384 mm, 반대 집합 검증은 각각4.360→4.180 mm·4.806→4.547 mm로 감소했다. 최초 현 끝을 넘어간129점도 지우지 않고 끝점까지의 거리를 포함했다. run2는 기존/후보 모두133.62초 첫일치로 유지됐다. [run3 결과](run3/finite_candidate_v1.json), [run2 결과](run2/finite_candidate_v1.json).

관련91검사와 후보추가19검사를 통과했다. 실제 정합이 아니라 가짜 적합 결과로 연결 조건만 확인하는 단위검사와 센서 입력 복원을 구분한다. 전체 상태 대조는 두 독립 `LocalFollow`와 독립 `RecoveryPolicy`의 보호 함수를 사용했고, 세 번째 기록 분기는 원래 소스의 출력을 확인했다.

[오차 전체 비교](full_stress_v1/summary.json), [명목 전체 비교](full_nominal_v1/summary.json). 입력·소스 불변이며 원래 궤적/속도가 고정된 재생이다.1,475개의 출력 변화는 실제1,475회 재출발이나 완주 증명이 아니다. 명목 baseline에는 이전 짧은 안쪽/표면 개선이 포함되어 있어 후보 양수7,320회와 원래 기록 양수7,217회를 구별한다.

제어+보호 함수 합산 wall-clock p95는 오차 입력에서29.56→80.50 ms, 최대100.95→178.72 ms로 증가했다. 정지 분기가 진행 분기로 바뀐 비용과 정합 검사의 비용이 섞여 있으므로 이를 모두 새 정합의 비용으로 해석하지 않는다. 명목 p95는25.13→25.00 ms다. `validate_connected.py`는 연결 명령과 이전 비교 결과를 전부 대조하며 정합 호출만 별도로 계측한다. ROS 주기/Jetson 처리율 증명이 아니다.

연결은 `SurfaceAnchorTrial(small_alignment=False)`를 기본으로 두고 명시 `RecoveryPolicy`에서만 켰다. 원래 부분 관측 정합·옛 위치 관측 `PositiveClearanceTrial`은 변경하지 않았다. 현재 점군/gyro·2/4 cm 재관측·두 새 스캔·전체 위협·해제 뒤 현재 입력 재검사는 유지한다. 후보 함수는 기존 `surface_reobservation.py`에 넣어 이미 있는 배포 의존성을 재사용했고 artifact 함수와 AST를 대조한다. `small_alignment_r1_sha256.json`은 run1 원본ZIP·이전계약·현재3파일을 연결한다.

연결 관련200검사·`arena_autonomy`빌드·설치 import/기본값 검사가 통과했다. 실제 연결 코드는 사전 후보의 전체 명령·보호 출력과 오차7,790/명목7,808호출 모두 일치했다. [연결 오차 재생](connected_stress_v1/summary.json), [명목](connected_nominal_v1/summary.json).

오차 입력의 정합은 계획기/보호층 합계6회(3판단)에만 호출됐고, 그중 새 작은정합 승인은2회다. 함수 최대65.79 ms, 전체합산 p95 81.08 ms·최대169.24 ms였다. **정합 없는7,787판단에서도 p95 81.04 ms**여서 전체분포 증가의 대부분을 새 정합함수만의 비용이라고 할 수 없다. 명목은 정합8회 모두 기존성공이며 전체p95 25.02 ms다. 센서와 시간/속도가 원래 정지 궤적에 고정된 상황의 진행경로 계산 비용이며, 이 결과가 Jetson/실제50 Hz충족을 뜻하지 않는다. 다음 실제 입력과 전체처리시간에서 별도확인한다.

이 결과를 근거로 같은155초·오차·속도·STOP조건의 `rotation_stress_v1/run4_trial.sh`를1회 실행했다. 평가기에는 별도검사111개를 통과한 정상STOP뒤 actor수신마감 보완도 포함된다.

## 폐루프 결과와 분기 사용 여부

run4는 유효 실행으로53.2522 m·1랩·STOP·14/14종료·7,804판단 동일 재생을 확인했다. 다만 옆차 최소149.9407 mm·연속 구간 하한149.8672 mm가 기존150 mm 기준에 미달해 종합 실패는 유지한다. 소스·원시 입력 불변이다.

[`audit_run4.py`](audit_run4.py)는 계획기 기록만 읽고 원본 판정을 바꾸지 않는다. [감사](run4_audit.json)의 적합7회는 기존 승인5회·개선율 거절2회로 **새 작은 정합 승인은0회**다.134.02·134.72초에 기존 조건으로 재관측했고 최장 후반 정체는 사라졌다. 따라서 run3 고정 입력의 개선과 run4 구성의 완주를 구별하며, 새 분기가 이번 완주를 직접 만들었다고 주장하지 않는다. 후속 다랩에서 반복 조우·다른 관측 위상을 보되 같은 실행을 성공 숫자만 늘리려고 반복하지 않는다.

계획기 적합의 기록상 중앙14.48 ms·최대17.17 ms는 해당 함수 범위다. 전체 제어+보호 p95나Jetson 처리율이 개선되었다는 결과가 아니다. 별도 비교안의19기하/거절 반례는 실제 운영 모듈을 호출하는 `tests/test_small_surface_alignment_geometry.py`로도 옮겨 상시 회귀에 포함했다. 최신 전체 회귀는6,364통과·19건 명시 C++ 바이너리 미지정으로 건너뜀·실패0이다.

`profile_current.py`·`profile_run4.sh`는 이 완주 기록의 비용을 한 번 측정했다. `replay_call`을 사용해 원시 스캔을 포함한 실제 입력 경로를 유지했고 **7,804판단 전체 일치·입력/소스 불변**을 확인했다. [결과](run4_cost_v1/summary.json)의 wall-clock 중앙/p95/p99/최대는 계획기13.23/22.87/34.75/79.18 ms, 독립 보호1.19/1.48/7.88/50.02 ms, 합계14.43/24.25/45.54/127.51 ms다. 정체된run3 입력의p95약81 ms를 이번 완주 기록의 일반 비용으로 적용하지 않는다. 다만20 ms를 넘는 호출이 남으며 Jetson 처리율 완료도 아니다.

스레드 CPU 비용과 새 스캔/재사용 스캔·이유별 분포도 보존했다. 보호 함수는 별도 상태지만 동일 판단 시각에 입력이 도착했다고 가정하므로 실제 ROS 콜백·전송·Jetson 지연의 재생은 아니다. 기록과 일치를 확인한 것은 계획기 판단이고, 기록된 독립 보호의 실제 수신/출력 순서 일치까지 확인한 것은 아니다.
