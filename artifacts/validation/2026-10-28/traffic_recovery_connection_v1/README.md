# 교통 회복 후보의 선택형 실행 연결

2026-10-28. 이전43.173 m 교통 실패와 원시 입력은 보존한다. [독립 보호 함수 비교](../traffic_residual_v1/README.md)는 실제 주행 증명이 아니다.

`--traffic-recovery-trial` / `g1_traffic_recovery_trial`은 기본false다. GUARD·pass release·parallel hold, v4·corner distance·per-ray와 기록되는 시뮬레이션이 필요하다. 기존 속도/간격/STOP/물성/측정 여유는 유지한다.

- 옛 반환 취득→결측 취득→현재의 위협 영역을 분리한다.3 cm·2 m/s는 기존 시험 가정이다.
- 최초 위협 전체를 보존했을 때만 두 새 스캔 재관측과 현재 스캔 재검사를 한다. 기억 만료/정합 실패만으로 해제하지 않는다. 계획기와 보호층의 객체는 독립이다.
- 이번 관측 정책이 검사한 같은 시각·조향·속도 이하의 영역만 좁은 측방 무반환 후보로 다룬다. 현재 반환 점유와 가림 검사는 유지한다.
- 통과 이력은 새 옆차/경로 소실/입력 단절 때 취소한다. 이력 보존 중에는0.35 m/s 이하, 작은 이동도 현재 이동 영역을 검사한다.
- 같은 판단의 이동 영역/관측/가림 계산을 재사용한다. 이전 프레임 판단을 가져오거나 표본을 줄이지 않는다.

소스 문자열을 치환하던 진단 사본과 달리 실행 구현은 정상 import와 명시 옵션이다. 기존 진단 파일은 보존한다.

검증은 반례 재적용→전체 회귀→OFF 동일/ON 사본 대조→빌드·ROS 입력 고장→기존 교통 각본1회 순서로 진행했다. `run1_course`는 종료·회수했으며 전체 랩과 최종 앞차 간격 판정에 실패했다. 같은 코드를 근거 없이 반복하지 않는다.

정적 배경 정합은 물체 신원이 아니다. 동행하는 복수 물체·얇은 미검출 표적·범위 밖 상대 운동은 남는 위험이다. 실차/전체 경기 안전이나 기본 채택으로 해석하지 않는다.

첫 반례 재적용은73통과/10실패였다.6건은 진단 모듈에 남은 mock 주입 대상과 실행 모듈의 불일치,4건은 상태시험의 빈 경로 frame이었다. 원본 실패 로그를 보존하고 시험 주입 대상을 실행 모듈로 연결한 두 번째 검사에서83건이 통과했다. 이 실패를 주행 성공/실패로 해석하지 않는다.

## 연결 회귀

전체회귀는6,081통과/29실패/19건너뜀. 실패29건은 현재 파일 해시의 후속 출처 계약 및 재생/ROS/Jetson 묶음의 새 의존성 누락이었다. 기존 계약을 고쳐 성공으로 바꾸지 않고10개 구현/진입 파일의 이전 바이트를 보존한 후속 계약을 추가했다. 이어3개 도구의 의존성 목록도 별도 이전 사본과 함께 등록했다. 초기10개 등록안과 원본 실패 로그는 보존하며 현재13개 변경·4개 신규 모듈의 완전한 계약을 사용한다.

후속 출처/의존성 관련300검사가 통과하여 전체 실행에서 남았던29건을 해소했다.19skip과 원래 실패 로그는 유지한다. 현재 코드에서 기존 `selector_bounded_rear_fringe_risk_accepted`는 호환용 상위 표식으로도 쓰이므로, 실제 1 mm 후반 영역인지 같은 G1 감속 외곽인지 `selector_guard_candidate.same_path_gap`과 `rear_fringe.reason`으로 구분한다. 같은 경로 후보를 1 mm 이내 이동이라고 해석하지 않는다.

## 교통 코스 비교 사전 조건

`run1_trial.sh`: 기존 `g1_traffic_full_course_v1.json`의155 s 각본·seed0·최대1 m/s·500점 순차10Hz·양방향 운동 보정·가상MCU·원래STOP/도로/앞차/접촉 기준을 사용한다. 왼쪽 각본 옆차도 기존 overlay를 유지한다. 추가 인수는 `--traffic-recovery-trial`뿐이다. 공식 신호 v2/방지턱 ON 단독2랩과 섞지 않으며 이 교통 대조는 임시3등·방지턱OFF다. 실행 전 src/scripts/tests/config 전체 snapshot을 보존한다.

기존43.173 m 정체를 넘어서는지와 실제 전체 진행/접촉/노면/STOP·정상 종료를 별도로 회수한다. 성공 여부와 무관하게 첫 실행 뒤 원인을 검토하며 무조건 반복하지 않는다. 저장 입력/실제 ROS 검사 결과 확인 전에는 이 주행을 시작하지 않는다.

OFF7,790호출 중12건이 원시 비교에서 달랐으나 확인한 차이는 `partial_observation.surface_correspondence.processing_ms`였다. 새 비교 도구가 기존 `comparable_decision`을 쓰지 않은 오류이며 원본passed=false를 보존한다. 이후 아래 표준 OFF 재생에서 같은 문제가 없음을 확인했다.
