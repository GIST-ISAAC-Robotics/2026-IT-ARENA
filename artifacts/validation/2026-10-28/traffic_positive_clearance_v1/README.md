# 움직인 장애물의 옛 위치를 실제 반환으로 재검사

2026-10-28. [읽기 전용 진단](../traffic_anchor_identity_v1/README.md)에서는 시험 앞차의 이동 후 옛 반환 위치가 비었으나 같은 곳의 점을 다시 찾는 정책 때문에 정지가 계속됐다. 이 폴더는 `traffic_recovery_trial`에만 연결하는 선택형 후속 후보다. 기본OFF·원래 정합/재관측·STOP·독립 보호 경계는 유지한다.

## 조건과 한계

- 전체 위협점과 원래 배경/기준시각을 고정해 최대1초만 대조한다. 기존 점 재관측 상태기의0.3초 만료는 바꾸지 않는다. 시간이 지났다는 이유로 해제하지 않는다.
- 기존 정적 배경 정합이 수락된 경우에만 옛 위치를 대응한다. 각 점 주변30 mm의53개 표본에서 현재 인접 유효 반환 양쪽을 요구하고30 mm+취득 후2 m/s 여유와 가까운 점유를 검사한다. 무반환·마스크·가림을 지지로 쓰지 않는다.
- 모든 위협점이 서로 다른 두 새 스캔에서 연속 확인돼야 한다. 같은 스캔 반복·시간 역행·입력 불일치·만료는 해제가 아니다. 이후에도 현재 `TimedPolicy`가 허용해야 상태를 해제하며, 독립 보호층은 별도 상태로 다시 검사한다.
- 정적 배경/운동 보정에 의존하는 제한 표본 정책이다. **옛 위치의 관측은 물체 신원·다른 가림 안의 물체 부재 증명이 아니다.** 기존 좁은 결측 정책의 잔여 위험은 남는다. 새 장애물의 모든 현재 점유와 보호 검사를 유지한다. 완전한 동적 물체 추적·실물 안전으로 설명하지 않는다.

## 진행 상태

선택형 구현·관련271검사를 통과했다. 초기 미연결 검사의19오류는 pytest 예약 이름 `setup`과 fixture 이름이 충돌한 원인이었으며, 뒤의1실패는 시간 여유가 실제로 충분한 위치를 거절 반례로 잡은 문제였다. 원래 로그를 보존하고 이름과 반례 기하를 수정한 뒤 검사했다.

전체7,791저장 입력/독립 보호 함수 대조에서130.32초1점,130.92초5점의 옛 위치가 두 새 스캔으로 확인됐다. 실제 명령 최초 변경은130.42초, 전체 변경1,436회다.130–154초1,201호출의 기존 양수0·후보/독립 보호 각1,154회이며 후보0명령은 보호에서도0이었다. 옵션OFF 기존7,790판단 동일 재생·입력/소스 불변을 확인했다. 비용 중앙14.46 ms/99백분위55.50 ms/최대84.45 ms는 저장 입력의 오프라인 계측이다. [대조 결과](complete_set_comparison.json).

새 모듈을 프로파일 소스와 이관 목록에도 포함했다. 의존성/출처138검사·빌드·소스 고정 뒤 실제155초 주행1회를 완료했다. 기존43.193 m 정체·전체 랩 실패는 별도로 보존하며 이번 후보의 성공으로 소급하지 않는다. 소스 변경 전 `before_source.zip`을 보존했다.

## 실제 주행: 실패와 종료 오류 보존

진행43.373 m,131.169–158.599초의27.43초 정체로 원래 전체 랩·최종 앞차 간격 판정은 실패했다. 접촉·표본 바퀴 중심 이탈0, 최소 표본/연속 차체 간격약362.3 mm·명시STOP을 확인했다. 소스1,013파일 불변·7,790판단 동일 재생·잔여 프로세스0이다. [원래 판정](run1_course/report.json), [분기 요약](run1_diagnostics.json).

**실행 정상 종료는 불합격**이다. 종료 요청 뒤 `parameter_bridge` PID897이exit -11로 끝났고14개 중13개만 정상 종료해 `run_valid=false`다. 요청 전 오류0·요청 후 오류1이므로 이 로그는 후반 주행 정체의 원인으로 보지 않는다. 원래 `run_valid`/종료 실패를 수정하지 않으며 안정적인 실행 성공으로 쓰지 않는다.

129.6초 소실 래치는 기존 표면 재관측 경로로129.92초 해제됐다. 새 옛 위치 확인 경로의 저장 입력 효과와 이번 궤적의 실행 분기를 구분한다. 이후130.84초부터 선택기의 `unknown_outside_side_scope`가1,395회 남았다. 다음은 실제 결측 광선이 어느 각도/영역에 있었는지와 선택기 계약의 일치 여부를 저장 입력에서 확인한다. 종료 오류는 새 주행 때 감시하되 원인 변화 없이 같은 실패 주행을 반복하지 않는다.
