# 교통 코너 경계 재획득과 통과 이력의 선택형 연결

2026-10-28. [선행 기록 대조](../traffic_corridor_roles_v1/README.md)의 v2를 운영 코드에 기본 OFF 옵션 `traffic_path_recovery_trial`로 연결한다. `--traffic-path-recovery-trial`은 기존 교통 회복·회랑·기록된G1 시뮬레이션을 요구한다. 기본 실행 설정이나 독립 보호층은 바꾸지 않는다.

## 선택한 변경

1. 선호 벽과 코너 안쪽 역할을 분리한다. 기존 역할의 성공은 유지하며 추가 역할도 현재 선호 벽의 긴 관측·앵커·경로 일치와 반대쪽 실제점의 지지를 요구한다. 선택된 경로는 기본 벽 기억을 갱신하지 않는다.
2. 완료된 통과 이력과 현재 진행 허가를 분리한다. 경계 대기·유한 역방향에서는 기존0명령을 유지한다. 동일 선호 벽의 새 fresh 경로가 돌아오면 완료 이력을 기존 `retained_passage`에 전달해 저속·현재 이동 영역 검사를 받는다. 미완료 통과를 만들지 않으며 현재 위협·입력 고장·시각/epoch 단절·선호 변경은 복원으로 덮지 않는다.
3. 기존 측방1 cm·후반1 mm·현재 같은경로 관측·STOP·속도/물성 기준은 수정하지 않는다. 통과 이력은 현재 사각의 뒤차 부재 증명이 아니며 제한 무반환/재접근 위험은 남는다.

역할만 바꾼 비교와 첫 이력 후보는 후반 양수0으로 실패했다. 경계 대기 중 유한 역방향을 일반 고장과 구분한 v2에서만 후반1,213회 중 원본0→후보/독립 보호 각1,100회 양수가 나왔다. 전체 명령 변화1,110회 중10회는0속도의 조향 변화다. 이 결과는 저장 입력에서의 함수 대조이지 새 주행이 아니다.

## 검증·출처

기존 종료 실행의9파일과 같은 이전 바이트를 `before.zip`에 보존했고 부모계약 `traffic_recovery_release_fringe_r1_sha256.json`을 덮어쓰지 않았다. 새 계약은 `traffic_path_recovery_r0_sha256.json`이다. 과거 미연결 역할 모듈과 새 이력 선택기를 모든 관련 재생/시험/Jetson 묶음 의존 목록에 추가했다. Jetson 자체 작업은 하지 않는다.

연결·분기·점유·STOP·입력 고장·기존 출처 회귀 **296건**이 통과했다(`regression.log`).

`run1_trial.sh`는 선행43.054 m 실패와 같은155 s·52.5 m 목표·seed0·앞차/옆차 각본·속도/센서/물성·임시3등·방지턱OFF를 유지하며 새 옵션 하나만 추가했다. 등록한1회 실행과 회수를 마쳤으며 추가 주행은 하지 않았다.

원시 판정은 `run1_course/report.json`, 분기/정체는 `run1_diagnostics.json`, 회수 종료 코드는 `run1_exit.txt`에 보존했다. 기존 실행과의 비교 그림은 [course_comparison.png](course_comparison.png)다. 관측 경로와 이력 연결이 실제 호출되어 약0.26 m 더 진행했지만 전체 코너 정체를 해결한 것은 아니다. 같은 실패를 성공할 때까지 반복하지 않는다.

### 재생 실패의 범위

`closeout_audit.py`가 원래 불일치5건을 다시 대조했다. 모두 `partial_observation.anchor_diagnostic.fit.processing_ms`만 다르며 명령·판단·나머지 필드는 기존 비교 허용 오차 안에서 같다. 기존 정규화는 `surface_correspondence.processing_ms`만 다루므로 새 경로의 벽시계 진단값이 비교에 남은 것이다. **원래 재생 실패 보고서는 바꾸지 않았다.** 보충 진단은 `closeout_audit.json`이며 비교기 수정이나 수정 후 재생은 아직 하지 않았다.

### 마감·다음 재개

사용자의 정리 요청에 따라 새 시험·수정 묶음을 시작하지 않고 종료했다. 다음은 아래 순서다.

1. 원시 비용 값은 보존하면서 위의 명시된 진단 필드만 비교에서 분리하도록 재생 도구를 수정하고, 명령/기하 차이가 계속 검출되는 반례와 기존 기록 재생을 확인한다. 이는 실제 주행 실패를 통과로 바꾸는 작업이 아니다.
2. 저장 입력의129.6 s와131.3 s 래치는 재관측으로 해제되었으나 **131.68 s 래치는 `incomplete_threat_set`으로 남았다.** 132 s 이후 회랑 후보는 양수인데 제어기와 독립 보호가 `known_obstacle_latched`로 정지했다. 이때의 이전 반환점·누락 광선·위협 집합과 점별 시각을 분리한다. 새 위협의 실제 정체나 해제 가능성은 아직 확정하지 않았다.
3. 같은 각본의 재실행은 원인이 확인되고 변경 근거가 생긴 뒤 판단한다. 기본 OFF·속도/물성·보호 경계와 이전 실패를 유지한다. 공식 출발/M5·방지턱/다랩·실물 결합은 여전히 남는다.

커밋·푸시·외부 게시·Jetson/전원 변경은 하지 않았다. 상세 JSONL과 소스 ZIP은 삭제하지 않고 로컬 보존한다.
