# 소실 위협 전체 상태와 원래 스캔 기준 복구

2026-10-28. [직전43.313 m 실패](../traffic_path_recovery_connection_v1/README.md)의131.68초 래치를 저장 입력으로 분석한다. 실제 주행 실패를 재생 비교 성공으로 바꾸지 않는다.

## 재생 비교 수정 — 완료

`anchor_diagnostic.fit.processing_ms`만 기존 표면 정합 비용과 같은 방식으로 비교에서 분리했다. 원시 비용·입력·이전 실패 보고서는 유지한다. 명령·판단·기하·같은 이름의 다른 필드는 계속 비교하며 잘못된 비용 값은 거절한다. 관련61검사·기존7,789개 판단 재생 일치·입력 불변을 확인했다(`replay_regression.log`, `replay_fixed.log`). 이 재생은 아래 제어 변경 **전** 소스 결과다.

## 확인한 원인

1. 실제 위협 광선/점 쌍은9개지만 진단 예시는8개까지만 남았다. 운영 재관측은 이 예시를 전체 위협으로 요구해 `incomplete_threat_set`에서 멈췄다. 원시 광선과 취득 시각으로 재구성해9쌍과6개 고유점을 확인했다.
2. 전체6점을 넣는 것만으로는 해결되지 않았다. 옛 위협점을 모터축/gyro만으로 현재로 옮긴 좌표와 현재 배경을 같은 앵커로 취급해 이미 생긴 이동 오차를 보정하지 못했다. 같은 원래 스캔의 위협·배경을 묶은 미연결 대조에서는131.72/131.82초의 두 fresh 관측에서6점 모두 재확인했다. 최근접 차이는 약0.5–6.7 mm이고 기존20 mm/짧은 표면 기준을 바꾸지 않았다.

근거는 `threat_reconstruction.json`, `anchor_reference_comparison.json`과 [같은 시각의 관측점 대조 그림](anchor_reference_comparison.png)이다. 그림의 회색은 현재 실제 반환, 빨간 ×는 기존 앵커 방식의 보존점, 초록 ○는 같은 원래 스캔 기준으로 옮긴 점이다. 모터/gyro 이동 오차의 물리 원인과 정적 배경/동행 물체의 구별까지 증명한 결과는 아니다.

## 변경과 검증 중인 범위

- 기존 부분 관측 정책에 기본 동작 없는 캡처 경로를 추가했다. 선택형 `RecoveryPolicy`만 위협의 전체 고유점을 원래 스캔의 반환 순서·기준 시각·배경과 함께 보존한다. 중복된 광선/점 쌍에서 점을 한 번 보존할 뿐, 위험점 절단이나 표본 추출은 하지 않는다.
- 기존8쌍 진단 예시는 그대로 남긴다. 전체 상태와 시간 메타데이터가 없으면 그 예시로 복원하지 않고 정지를 유지한다. 두 fresh 확인, 현재 입력 재검사, 별도 독립 보호 상태, 거리·물성·속도 조건은 유지한다.
- 관련105검사는 통과했다(`threat_regression_v3.log`). 초기 두 수집 시도는 ROS Python 경로 누락으로 실패했으며 로그를 보존했다. 후속 소스 계약은 `config/tests/traffic_anchor_set_r1_sha256.json`이다. 제어 변경 뒤 전체 저장 입력/독립 보호 함수 대조·Recovery OFF 재생·출처 회귀/빌드를 완료했다. 아래 조건으로 새 Gazebo 주행1회를 완료했으며 전체 랩은 실패했다.

과거 계약/실행 사본을 덮어쓰지 않으며 `before_source.zip`·입력·상세 재생은 로컬에 보존한다. 기본 선택값은 바꾸지 않았다.

## 연결 대조와 고정 주행

- 전체7,789호출에서 최초 명령 변화는131.92초였다. 그 이전 명령은 같았다. 후반132–154초1,101호출 중 기존 양수0, 후보/독립 보호 양수각1,091이었다. 후보0요청511회는 보호층에서도0이었다. 전체명령 변화1,375회는 이 이후 구간이며 입력·소스 불변을 확인했다.
- Recovery OFF 기존7,790판단은 모두 같았다. 영향 회귀281건 통과 뒤2패키지 빌드를 확인했다. 소스1,005파일을 보존·동결했다. 비용 중앙14.09 ms·99백분위73.00 ms·최대89.74 ms는 오프라인 함수값으로 실시간/Jetson 성능 보장이 아니다.
- 실행 조건은 이전과 같은155초·seed0·앞차/옆차 각본·속도/물성·임시3등·방지턱OFF다. `run1_trial.sh`는 STOP·종료·바퀴 중심·재생·소스 검사를 회수한다. 실제 결과를 확인하기 전에는 완주나 ROS 보호 연결의 성공으로 쓰지 않는다.

## 실제 주행 결과와 다음 원인 분리

같은155초·seed0의 `run1_course`는43.014 m에서 전체 랩·최종 앞차 간격에 실패했다.129.615–158.557초의28.942초 동안 진행이 멈췄다. 샘플/연속 외곽 최소 간격은 각각364.544/364.543 mm, 접촉·표본 바퀴 이탈은0이었다. 명시STOP의 안정 변위0.031 mm·14/14정상 종료·잔류 프로세스0을 확인했다. 판단7,790/7,790일치·소스1,005파일 불변이며 원판정을 변경하지 않았다.

이번 궤적에는 `anchor_diagnostic`의 래치/해제 호출이 없다. 따라서 이전 고정 입력의 앵커 수정 효과를 이번 주행에서 다시 입증했다고 해석하지 않는다. 후반 정지는 `large_motion_region_unobserved`와 `same_path_gap.reason=different_or_larger_motion`1,444회로 나타났다. 기본 경로의 부분 관측 승인은 있으나 선택기에서 요구하는 명령 계약과 맞지 않아 정지한다. 어떤 속도/조향 값이 불일치하는지 읽기 전용 재생으로 분리한다.
