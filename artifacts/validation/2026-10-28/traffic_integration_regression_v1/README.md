# 교통 후보 통합 회귀

2026-10-28. 전체 회귀5,982통과는 이전 소스의 결과다. 측방 범위 후보의 실제 교통1랩과 소스 고정·회수가 끝난 뒤 최신 `tests/` 전체를 한 번 검사했다.

## 최초 전체 결과와 수정

`full_v1.log`는 **6,254통과·19건 건너뜀·5실패**, exit1이다. 실패3개는 `test_source_contract_helpers.py`의 최소 임시 폴더가 최신 필수 후속 계약을 준비하지 않아 발생했다. 나머지2개는 `test_official_start_ros_fixture.py`와 `test_pipeline_fault_validation.py`가 새 내부 import `anchor_clearance_trial`의 보존 목록 누락을 검출한 것이다. 실행 담당의 최초 요약은5개 모두 임시 폴더 문제라고 잘못 분류했으며, GPT 주 에이전트가 실패 블록 원문으로 정정했다.

실제 교통 주행의 별도 전체 소스ZIP(1,015파일)에는 해당 모듈이 보존되어 해시가 일치한다. 하지만 시험기 내부의 작은 보존 목록은 불완전했으므로 그 한계를 숨기지 않는다. 제어기/주행 판정은 바꾸지 않고 다음을 수정했다.

- 현재 사슬 목록을 공통 상수로 두고, 과거 계약 단위검사에는 경로 변경이 없는 명시 빈 후속 계약들을 준비했다. 실제 helper의 필수 계약 누락 거절은 유지하고 그 반례를 검사한다.
- 교통·파이프라인·독립 센서 시험기3곳의 목록에 `anchor_clearance_trial`을 추가했다. 이전 파일은 `before_manifest_fix.zip`, 변경 이유/부모/해시는 `config/tests/traffic_manifest_r1_sha256.json`에 보존했다.
- 이후 `manifest_fix.sh`의 **276영향 검사 통과·실패/skip0**을 확인했다(`manifest_fix_v1.log`, exit0). 최초 전체 실패를 통과로 고쳐 쓰지 않으며, 전체 검사를 변경 없이 다시 반복하지 않았다.

건너뛴19건은 명시 사전 빌드 경로가 필요한 C++ parser/link/receiver/API/wire 대조다. 이번 주행 제어 변경으로 C++를 수정하지 않았고 해당 바이너리를 지정하지 않아 실행되지 않았다. 과거 성공을 이번 실행으로 합산하지 않는다. 이 검사는 새 주행·Jetson 처리율·실물 검증을 대신하지 않는다.

시험기 보존 목록 수정 뒤 공식 신호 어댑터6검사도 통과했다(`../official_traffic_v1/adapter_contract_v6.log`). `src/`의238파일은 교통1랩 소스와 모두 동일했다. 실제 통합 주행은 별도 결과로 남긴다.

## 회전 오차 보완 후 전체 회귀

작은 안쪽 경로·표면 재관측·작은 정합 연결·정상STOP 뒤 actor 수신 마감을 포함한 최신 소스를 `run_v2.sh`로 다시 검사했다. `full_v2.log`는 **6,364통과·19건 건너뜀·실패0**, exit0이다. 실제 연결 모듈의 작은 정합 기하 반례19건도 상시 회귀에 포함했다. 이 후속 통과는 앞의 full_v1 실패를 지우거나 그 시점 결과를 바꾸지 않는다.

건너뛴19건은 앞과 동일하게 명시 사전 빌드 바이너리 경로가 필요한 C++ actuation parser/link/receiver/API/wire 검사다. 해당 C++ 소스는 이번 변경 범위가 아니며 미실행 사실을 유지한다. 전체 회귀 성공과 회전오차run4의 기존150 mm 간격 실패는 서로 다른 판정이다.
