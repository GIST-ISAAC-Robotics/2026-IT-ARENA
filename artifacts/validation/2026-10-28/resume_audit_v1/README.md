# 비정상 턴 종료 뒤 재개 상태 대조

2026-10-28 사용자 요청으로 최근 두 개발 턴의 종료와 실제 산출물을 대조했다. 현재 지시는 GPT가 직접 구현하며 사용자가 중단할 때까지 계속하는 것이다. 과거 10/26 일회성 예약의 날짜 제한은 해당 예약에만 적용되며 현재 재개 지시를 덮어쓰지 않는다.

## 확인한 범위

- 로컬 세션 기록에서 두 개발 턴의 최종 응답이 오래된 `it-arena-10-26-17` 예약용 응답인 사실을 확인했다. 각각 10/27 21:52:31·23:37:44 KST 종료다. 이때 사용자의 개발 중단 지시는 확인되지 않았다. 다만 압축이 직접 원인이었는지는 기록만으로 확정하지 않는다.
- 예약 자체는 앞선 로컬 삭제 응답에서 `not_found`였고 새 예약을 만들지 않았다. 이후 00:26:44 KST 종료는 별도 사용량 제한 오류로 기록되어 있으며 두 예약 응답과 구별한다. 현재 사용량 상태의 판정은 이번 감사 범위가 아니다.
- [출발 7회 실행 대조](runs.json): 보고서·소스 ZIP의 존재, 원래 실패와 M5 별도 판정의 보존, 성공 출발의 판단 166/637/650/676/666건 동일 재생을 확인했다. 현재와 다른 운영 파일 네 개는 과거 ZIP 안에서 당시 해시와 일치했다. 실험 실패를 성공으로 소급하거나 소스 손실을 숨긴 흔적은 확인하지 못했다. 저장소 전체 무결성을 완전히 감사했다는 뜻은 아니다.
- 3대 신호 통신 실패는 명시 STOP 미수행·14개 중 13개 프로세스 정상 종료로 남는다. 5대 원본은 0 m 실패·판단 호출 0이다. 이후 5대 명목/오차 성과가 이 실패를 지우지 않는다.
- 거리 오차 어댑터의 초기 정적 검사 실패 3건(예약어 사용, 연결 조건 검사, Path 직렬화) 및 후속 검사 성공은 로그에 보존됐다. 실제 주행 성공으로 바꾸지 않는다.

## 보완한 기록

점별 시각 정책 재생(6,409판단·다른 옛 점 때문에 129.500초에 래치)과 같은 경로 검사 13건의 결과가 기술 README/현황에 아직 반영되지 않은 상태였다. 원시 결과와 대조해 반영했다. 문서의 “비교 중/다음 시행”을 실제 상태로 교체하고, 당시의 교통 전체 랩 실패·후보 미채택·새 폐루프 미실시를 유지했다.

실행 담당의 이동 영역 요약에는 다른 집계가 섞인 1건이 있었으나, 주 에이전트가 원본 `selector_guard_candidate.region`의 1,392표본/317미관측·통과 상태 false를 확인해 결론과 문서에 사용했다. 모호한 요약을 근거로 다음 실행을 통과시키지 않았다.

## 감사 이후의 재개

이 감사로 이전 시험을 완료 처리하거나 재실행하지 않았다. 이후 진행은 [현재 현황](../../../../docs/PROJECT_CONTEXT.md)에서 갱신한다. [시각/정체 진단](../timed_latch_v1/README.md)은 미해결로 보존하고, [방지턱 동적 시험](../bump_dynamic_v1/README.md)과 [제동 중 이동 오차·회복 후보](../traffic_residual_v1/README.md)를 후속 근거로 연결했다. 감사 당시의 다음 작업을 현행 재개점으로 계속 복사하지 않는다.
