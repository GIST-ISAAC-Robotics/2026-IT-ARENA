# r249 실물 입력의 공통 노드 준비

실행 전 범위: 기존 G1/G2 노드는 여러 시작 조건에서 시뮬 시간을 요구하므로, 실물 센서 개별 수신 성공만으로 운영 연결이 되지 않는다. 실제 시계를 쓰되 **구동 출력과 분리된 `hardware_shadow_v1`**을 명시적으로 선택해 동일 노드의 수신·상태·STOP/RESET·계산 자식 정리를 먼저 연결한다.

## 수용 조건

- 기본 실행의 조건/토픽은 유지한다. shadow만 실제 ROS 시계를 사용하며 명령/상태/enable/reset은 `/hardware_preview/` 아래에 둔다. `/drive`·`/drive/safe`·MCU 명령을 발행하지 않는다.
- SDK 추정 시각·IMU 미교정·가짜 엔코더를 검증 완료로 승격하지 않는다. `motion_scan_timing_verified=false`로도 관측용 노드는 기동하되, 기존 계산의 시간/피드백 부족 거절은 그대로 확인한다.
- simulation native와 hardware estimated 입력을 혼합하지 않는다. 실제 source frame·boot·취득/수신 추정값을 그대로 둔다. B3 실물 구동 허가는 이번 shadow에 연결하지 않는다.
- 실제 ROS 노드로 시계·입력 거절·출력 토픽·STOP/RESET·자식 정상 종료를 확인하고 기존 시뮬 노드 회귀를 비교한다. 이후 가능한 실제 센서 연결 대표를 수행한다.

이 단계는 실차 실행 허가나 주행 완료가 아니다. 엔코더 신호/장착·C1/IMU 시간 프로필과 실제 구동 어댑터가 남는다. 구조적 이관을 작은 단계로 연결하기 위한 것이며 새 정지 판정선을 추가하지 않는다.

## 결과

16개 실제 ROS 회귀와213개 출처 검사를 통과했다. 이후 Jetson에서 원 IMU 앱과 기존 C1 SDK를 사용해 두 센서를 약20초 취득하고 공통 G1 노드에서26.61초 관측했다.

- C1 **203스캔/102,480점** 발행·수신 일치. 가변376–544점(중앙508), 원 배열/프레임/epoch 메타데이터203개 일치.
- IMU 원측정3,982개와 warmup50개를 합친 **4,032개가 공통 운동 입력에 수락**됐다. CRC/순번 공백/수락 거부0이다.
- 엔코더 입력0, 카메라 없음, 장착 미교정이다. 노드는 `SENSOR_STOP` 상태에서 전용 토픽에0속도만1,297회 발행했다. 자율주행 계산·실제 구동을 통과시킨 시험이 아니다.
- C1 시각은 여전히 `unverified_estimate`다. 명목 점간격에 의한 인접 배치 중첩198개(최대3.963ms), 수신보다 미래인 끝점148개(최대2.839ms)가 남았다. 실제 취득 지연/회전 위상이 검증된 것으로 표시하지 않았다.
- 자식3개 정상 종료, 강제 종료0, 계산 자식 종료0. IMU는 `X` 확인 후 ODR OFF, C1 정지 확인, 양쪽 포트 미점유다. 펌웨어·구동/전력 설정은 변경하지 않았다.
