# r259 C1 시계 후보의 실제 관측 발행

처음20회전의 표본 개수/SDK 앵커로 간격과 offset을 추정하고 이후에는 고정하는 관측 전용 후보다. 큰 시각/회전 불연속은 별도 세대로 나누고, 추정 끝시각이 약간 미래이면 최대5ms 예산 안에서 기다린 뒤 발행한다. 이는 센서 오차의5ms 보장이 아니다. 원 시각을 현재로 잘라 맞추거나 `unverified_estimate`를 변경하지 않는다.

9검사에서350ms 호스트 수신 지연이 원 시각을 갱신하지 않는 것, 회전 누락/새 시작/시계 변경/큰 앵커 잔차/대기 예산 초과·새 세대, 작은 미래량 지연을 확인했다. r249/r251 저장 입력은 각각20회전 warmup 뒤183개를 공통 decoder로 읽었고 기하/원 순서/거리 상태는 같았다.

## 실제 C1 결과

- 원203회전 중20개는 학습 전용이며, 이후 **183개·93,196점이 발행/수신 모두 일치**했다. 후보 간 중첩0·실제 발행 시 미래 끝점0, 원 거리/각도/무반환/순서 보존을 별도 원문 감사로 확인했다.
-121회에서 기다림이 필요했다. 요청 대기 중앙0.991ms·p954.174ms·최대4.924ms, 실제 수신→발행 p955.791ms였다. 처리 자체도 이 시간에 포함된다.
- SDK 앵커 잔차는−6.172~1.881ms였고 추정 점 간격은196.143μs였다. **새 실행에서는20초 안에도 고정 초기 추정의 편차가 대기 예산에 가까워졌다.** 이전 두 저장 구간의 작은 잔차를 장시간 운용에 확대하지 않는다.
- SDK 정상 종료·센서 정지 응답·포트 미점유를 확인했다. ESP32 펌웨어/모터/카메라/전력 설정은 바꾸지 않았다.

**공통 운영에는 미채택**이다. 내부 일관성과 진단 ROS 전달을 확인했지만 실제 취득 시각·장착·주행은 검증하지 않았다. 다음은 원시 시각/점 순서를 유지하면서 관측 중 배율 변동을 추적하는 후보를 같은 저장 자료에서 비교한다. 이후 입력을 사용해 과거 시각을 다시 쓰거나 지연을 숨기지 않는다. 같은 C1 정지 취득을 다시 반복할 필요는 없다.

근거는 `live_audit.json`, `live_summary.json`, `replay_report.json`, `tests.log`다. 원문은 Git 제외 `build/r259_recovered`에 있고 완료 회수 ZIP SHA256은 `bb70692edec801db143ed27a14926b7881e38382b134b6c6131254e07aed0106`이다. 이 실행은 기존 공통 bridge의 별도 사본에서 이루어졌다.
