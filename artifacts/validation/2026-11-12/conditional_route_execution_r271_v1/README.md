# r271 조건부 보조 제출 결과 — 미채택

[사전 조건](PLAN.md)에 따라 과거 계산 시간으로 새 계획 이전에 활용할 수 있는 보조 검사만 제출했다. r266의 현재 관측/기하/STOP·발행 조건은 바꾸지 않았고 공통·ROS 기본에는 연결하지 않았다.

| 실제15초 저장 시간표 | 보조 없음 | 조건부 보조 |
|---|---:|---:|
| PC 고정147/34ms 양수 갱신 |71|135(보조64)|
| PC 갱신 중앙 / p95 |199.95 / 201.49ms|101.01 / 102.09ms|
| PC 명령 만료 시간 합 |6.252s|1.664s|
| Jetson 추가 지연0 양수 갱신 |101|102(보조0)|
| Jetson 갱신 중앙 / p95 |103.03 / 212.55ms|104.26 / 204.93ms|
| Jetson 최장 갱신 공백 |463.69ms|667.97ms|
| Jetson 명령 만료 시간 합 |8.571s|8.004s|

Jetson은 조건 판단125회 모두 새 계획이 먼저 완료될 것으로 보아 보조를 제출하지 않았다. 따라서 최장 공백의 차이를 실행되지 않은 보조 계산의 효과라고 단정하지 않으며, 단일 대조의 스케줄링 변동이 포함된다. **실제 보조 이득이 없고 사전 최대 공백 조건도 만족하지 않아 미채택**이다. 같은 실패 재실행으로 통과를 찾지 않는다.

PC의 기존14개 실제 프로세스/STOP 검사는 통과했다. 새11검사 중 첫1개는 부동소수점10.06의 정확 비교 때문에 실패했고 근사 비교로 고친 뒤11개 통과했다. Jetson은25개 모두 통과했다. 원 테스트 실패도 보존한다. 공통 수치 커널은 같은 Jetson의 동일3개 C++/빌드 소스와 binary hash를 확인해 재사용했다.

소스255개와 r266 저장 부분 원문 불변, 두 자식 정상 종료·잔여 자식0을 확인했다. 처음 정리 점검이 자기 bash 명령 문자열을 잔여 Python으로 잘못 잡은 기록은 보존하고 실제 executable 이름으로 다시 점검했다. 센서 포트·펌웨어·모터/서보·전력 설정은 사용하지 않았다. 회수 SHA256 `46ae78e1af926e88b493ac3285a52c6e5e57d4e450a3a5e284d80b43c6ad612e`.

이 시간표는100ms마다 기록한 현재 운동 상태를 사용한다. 실제50Hz 부모의 더 최신 IMU/속도 이력과 같지 않아 명령 시각의 나이를 과대평가할 여지가 있다. 다음에는 원 센서 표본을 유지한20ms 현재 관측 재구성의 의미/가정을 먼저 확인한다. 시각만 새로 붙이는 재발행은 하지 않는다. 이 결과는 폐루프 주행이나 r253 실패 해결이 아니다.
