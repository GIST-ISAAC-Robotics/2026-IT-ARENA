# 현재 SOLO 저속 공백·지연 교통 r225

r220의 후반 정체 원인은 원 좁은 무반환 관측 정책이다. r223 저장 비교와 r224 공통 연결/회귀를 마친 뒤 같은80초·시설/ID20·30 누락·두0.8m/s 상대·native C1·이전 계산비 지연 조건에서1회만 수행한다. 보호·차체/노면·간격·STOP/정상 종료·한 랩 기준은 유지한다.

달라지는 선택은 `g1_oblique_gap_trial:=true` 하나다. 교통 제어기는 이전 SOLO 기억과 현재 같은 경로의 옆차 부재를 모두 확인한 호출에서만 기존 단독 공백 계산을 사용한다. 독립 보호층은 자기 관측/이력으로 동일50mm 숨은 폭·실제속도·0.2m/s 상한을 검사하며 제어기 상태를 허가로 받지 않는다. 일반 후보 출력/현재 경로 재검사·원 점유·소실 위협·STOP을 유지한다.

보호층 상태를 별도 평가 구독으로 저장한다. 원 제어 입력에 추가하지 않는다. 원r220 미완주·r224 최초 비교/시험 준비 오류도 보존한다. 성공할 때까지 같은 조건을 반복하지 않으며 결과로 다음 작업을 고른다.

## 결과: 미완주·정체 유지

80초42.66m·최장저속16.402초로 한 랩/지속 주행이 실패했다. 접촉·도로/바퀴 노면 이탈0, 원 간격·시설 조건·명시 STOP/정상 종료·등록 입력/소스 불변은 통과했다. 기존 r220의42.55m/13.473초보다 개선됐다고 보지 않는다.

제어기의 후반 요청은0.2m/s로 바뀌었고 독립 보호층도 같은 저속 공백 정책을 실제 평가했다. 그러나 보호층은71.60초에 `partial_history_expired`를 래치하고 이후 정지를 유지했다. 기록에는 직전71.20초까지 관측 평가가 있고, 다음 관측 평가 전19회 연속 `stale_input`이 있다. `LidarSafety.control()`은 명령의 시각/수신이 오래되면 센서 관측 기억 갱신도 건너뛴다. **명령 갱신 지연이 관측 기억 만료까지 만든 연결**이 다음 분석 대상이다. 센서 자체가19회 모두 새로 들어왔는지는 보호 상태 기록만으로 확정할 수 없다.

원 보호 로그는713개의 `partial_history_expired`,408개의 `stale_input`,19개의 `forward_gap_too_wide`를 포함한다. 오래된 명령의 차단이나 실제 센서 공백·소실 장애물의 정지를 없애는 수정으로 처리하지 않는다. 유효한 센서가 계속 들어오는 합성 반례에서 명령 만료와 관측 갱신을 분리해 검증한 뒤 판단한다.
