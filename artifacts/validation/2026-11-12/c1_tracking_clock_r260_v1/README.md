# r260 C1 표본 시계 추적 후보

r259의 초기20회전 고정 추정은 실제20초에서121/183개 발행을 최대4.924ms 기다리게 했고 SDK 첫시각과의 차이가 −6.172ms까지 누적됐다. 최근 최대100회전으로10회전마다 기울기와 위상을 다시 추정하는 관측 전용 후보를 비교했다. 이미 발행한 시각은 수정하지 않고 이번 회전의 점 간격에 위상 보정을 분배한다. 20회전 준비·180–220µs·SDK 기준±10ms·추가 대기5ms는 후보의 일관성 예산이며 센서 절대 오차 상한이 아니다.

| 저장 입력 | 고정 추정 추가 대기 건수/최대 | 추적 후보 추가 대기 | 추적 후보 SDK 기준 차이 |
|---|---|---|---|
| r249 | 0/0ms | 0 | −0.241~2.952ms |
| r251 | 14/0.671ms | 0 | −0.267~3.325ms |
| r259 | 121/4.924ms | 0 | −0.226~2.627ms |

각203회전 중20회전 준비 뒤183개를 공통 native 디코더로 읽었으며 거리·각도·순서·범위·미검증 시각 표시를 보존했다. 배치 중첩·새 epoch·후속 거절은0이다. 후보12검사는 수신350ms 지연, source/ROS 시계 경계, 약1분의 느린 주기 변화, 이미 발행한 자료 불변, 과도한 위상 수정 거절을 포함한다. 100ms 미만의 ROS 역방향 이동도 배치가 겹치면 새 epoch로 재준비하도록 보완했다.

PC WSL 변환 p95는 약0.85ms(고정0.48–0.81ms)이며 Jetson 비용이 아니다. 후보가 SDK 시각에 더 잘 맞는다고 실제 취득 시각이 정확해진 것은 아니다. 샘플링/복호 지연의 절대 기준은 여전히 없다. 공통 운영 어댑터나 기본값에 연결하지 않았으며 실제 장착·운동 보정 허가·구동도 하지 않았다. 이 시계 묶음은 근거를 남기고 종료하며 다음 우선은 계획/현재 확인 실행 구조다.

`sample_clock.py`가 검증한 후보, `test_tracking.py`가 회귀, `replay_report.json`/`comparison.json`이 결과다. `prepare.py`는 초기 생성 경위이며 기존 결과를 덮어쓰지 않도록 실행을 거절한다. 원시 실내 센서는 기존 Git 제외 정책대로 build에 보존한다.
