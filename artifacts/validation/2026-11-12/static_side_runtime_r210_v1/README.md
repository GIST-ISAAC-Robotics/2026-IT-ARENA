# 실제 경과 시각 기반 측방 판단 주행 대조 r210

r203과 같은60초·두0.8m/s 각본 상대·공식 시설·ID20/30 누락·native C1·기존 지연 하한을 사용한다. r209 공통 정지 물체 이동 근거만 실제 판단 기준 시각으로 바꾼다. 속도·물성·간격·STOP·노면·완료 기준은 그대로다. 새 기둥 분류기나 평가 정답 입력은 없다.

원r203은30.68m·최장저속10.484초로 실패했다. 저장 입력 대조는 새 궤적을 증명하지 않으므로 이번1회에서 시설/상대 접촉·지속 주행·정상종료를 함께 확인한다. 성공할 때까지 자동 반복하지 않는다. 이전 Jetson 비용을 적용한 지연 하한이며 최신 전체CPU/ROS/실차를 재현한 것은 아니다.

실행 전 의존성 import·공통 소스 등록·빌드 검사를 수행하며 결과는 실행 후 기록한다.

## 실행 결과: 시작 단계 실패

150초 동안 autonomy/drive/light/safe_drive/safety/scan이 들어오지 않아 기동 timeout으로 종료됐다. Gazebo 물리 pose6,679개는 있으나 제어 판단/주행 궤적은 없고 `harness_valid=false`다. 노드 예외는 관측되지 않았지만 시계/ROS 전송의 정확한 원인은 미확정이다. 소스/스냅샷 불변·정상 종료·파티션잔여0을 확인했다. 후처리의 gap KeyError는 행동 데이터 부재를 고려하지 않은 평가기 오류이며 원 로그를 보존한다. 이 결과를 r209 주행 성능 실패나 성공으로 해석하지 않는다. 별도 r211 빈 world 시계 연결 확인 후 r212에서 한 번 환경 재시도한다.
