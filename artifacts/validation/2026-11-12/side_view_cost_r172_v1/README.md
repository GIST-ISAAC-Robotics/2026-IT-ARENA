# 사용하지 않는 측방 격자 계산 제거 후보

2026-11-12, 노트북 저장 입력 비교 전용. 실행 중인 r171 소스와 운영 파일은 수정하지 않는다.

r170의 PC WSL 대표15개에서 현재 재계산 중앙24.37ms 중 `threat_view`가12.72ms를 차지했다. 이 함수는 `side_threats`의 최근접 간격을 계산하기 위해 관측 격자를 만들지만, 실제 반환값은 `present`, 점수, 종방향 양 끝과 경로 frame/state뿐이다. 근접 간격은 계산한 뒤 버리고 있었다.

후보는 기존 `ReturnGrid`와 `side_return_masks`의 동일 compact 반환·창·벽·횡위치 조건으로 점수를 구한다. 자유 공간 검사·이동 영역/측방 접근·점유 검사를 삭제하지 않고, 이 함수가 사용하지 않는 근접 간격용 격자만 생략한다. 일반 `side_threats`의 격자 기반 간격 계산은 다른 호출자에게 그대로 남긴다. 시간 사이 캐시·점 축소·판정선 변경은 없다.

동등성은 같은 저장 scene/path의 모든 반환 필드와 전체 계획기 출력으로 대조한다. 계산 비용은 PC 값으로만 표시하며 Jetson 접근 금지를 유지한다. 결과가 충분할 때만 다음 실행에 적용한다.

## 결과와 반영

[장면 비교](comparison.json)468개 반환 필드/경로 frame 일치, [전체 재생](replay.json)468개 명령·전체 출력 불일치0·입력 해시 불변. 해당 함수의 WSL 중앙10.87→1.85ms, p95 12.95→2.43ms다. 전체 제어 비용이나 Jetson 비용 감소율이 아니다. 후보를 설치한 관련153회귀도 통과했다.

r171 종료·소스 불변 확인 뒤 공통 함수에 동일 계산을 반영했다. 변경 전 바이트는 `before_sources.zip`, 선형 변경 계약은 `config/tests/side_view_cost_r172_sha256.json`에 보존한다. 다른 `side_threats` 호출의 관측 격자·독립 보호·이동 영역 검사는 유지한다. 후보 r170/r173의 주행 연결과는 별개인 동등 연산 개선이다.

공통 반영 뒤 기존153개와 출처 사슬을 포함한 WSL347회귀를 모두 통과했다. 이전 계약·실행 소스를 덮어쓰지 않았다.
