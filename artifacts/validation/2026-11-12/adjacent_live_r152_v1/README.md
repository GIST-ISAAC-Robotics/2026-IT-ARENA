# 장착 가림 인접 공백·낮은 목표 재검사의 제한 주행

2026-11-12 실행 전 등록. r149 저장 후보와 r151 현재 입력 재검사를 선택형 launch prefix로만 연결한다. r143과 같은 시설·두 상대·C1 native10Hz·60초 목표·기존 측정 비용에 근거한 배송 지연 하한을 사용한다. r147 동등 연산 개선의 소스 계약을 적용한다. 기본 제어기·새 센서/물성·진행/접촉/노면·STOP 기준은 변경하지 않는다.

새 위험 분류는 실제/목표0.15 m/s 이하, 차체 옆10 mm 내 국소 이동, 선언 장착물 가림 옆의 +inf 구간, 합성 숨은 폭5 cm 이내와 실제 바깥 반환을 요구한다. 미관측을 자유 공간으로 바꾸지 않으며 숨은 물체 위험은 남는다. 이 위험 분류와 현재 재검사 모두 새 주행에서 얼마나 발동하는지 확인한다.

WSL 비용은 baseline465판단 중앙28.93 ms·후보46.80 ms로 증가했다. Jetson 비용은 연결 실패로 미측정이다. 따라서 이번은 **같은 이전 지연 하한에서의 기능 비교**이며 새 Jetson 연산/ROS 부하 재현이 아니다. 실제 계산 완료 전 결과를 내보내지 않지만 느린 시뮬레이션의 벽시계 계산비를 Jetson 실시간 여유로 해석하지 않는다. 실패하면 원시 증거를 보존하고 같은 조건을 자동 반복하지 않는다.

## 첫 시도: 출발 전 환경 장애로 중단

첫 시작 명령은 복사한 셸의 경로 오타로 Python 진입 전에 실패했다. 원 셸 `run_trial_initial.sh`와 로컬 `build/r152_launch_path_failure.log`를 남기고 경로만 바로잡았다. 실행 연결5검사는 모두 통과했다.

실제 첫 실행에서는 신호등이1.1초의 `green_probe` 이후 진행하지 않았고 차량은 계속 `WAIT_GREEN`이었다. 동시에 Ubuntu 일반/root 새 명령 모두 `E_UNEXPECTED`로 실패했다. Windows 가상 메모리 여유가 약1 GB였지만 근본 원인은 확정하지 않았다. 사용자에게 이전에 허용받은 Ubuntu-24.04 종료를 사용했다. 다른 앱·전원 설정은 변경하지 않았다.

[중단 감사](environment_abort.json): 마지막 시뮬 시각34.037초·이동0 m·출발0, 판단 기록0개·footer 없음이다. **정상 STOP/정상 종료는 미수행**이며 주행 후보 성공/실패를 판정할 수 없다. 원 등록 소스와 스냅샷 해시는 모두 동일했다. [환경 측정](environment_failure.json)과 원시 로그를 보존한다. 메모리 여유와 WSL 실행 회복을 확인하기 전 같은 주행을 반복하지 않는다.

## 환경 회복 뒤 별도 실행

사용자가 미사용 브라우저 탭을 정리한 뒤 남은 가상 메모리가 약6.8 GB로 늘었고 Ubuntu 명령이 다시 실행됐다. [재개 전 측정](environment_recovery.json)을 남겼다. 같은 판단/센서/시설/지연 조건을 `two_actor_run2`에 별도로 등록했으며, 신호 순서 완료와 출발을 확인했다. 첫 시도를 정상 종료로 바꾸지 않는다.

**두 번째 실행은 18.48 m·최장 저속7.646초·두 상대 포함 접촉0으로 기능 목표에 실패했다.** r143의9.97 m·33.118초·접촉 발생보다 나아졌으나 한 랩과 지속 주행을 충족하지 못했다. 최종 간격 실패도 원 평가에 남긴다. 노면/시설 위반0·정상 STOP·명시 MCU 정지·정상 종료·잔여 시험 프로세스0·입력/소스 불변을 확인했다. 원469/현재71판단은 전체 재생일치이며 현재 재검사 비용의 PC 중앙4.272 ms·p95 29.359 ms는 Jetson 수치가 아니다.

[결합 판정](two_actor_run2/combined_assessment.json)과 원시 입력을 보존한다. 가장 긴 저속 구간은40.311~47.957초, 진행10.13~10.14 m였다. 단일 실행과 벽시계 계산 변동이 있으므로 차이를 후보의 결정적 인과 효과로 단정하지 않는다. 뒤이은 [r155 상태 진단](../guard_reentry_r155_v1/README.md)은 단순 GUARD 재진입 조건만 바꾸는 대안을 뒷받침하지 못했다. 다음은 기본 경로가 정지를 요청한 실제 관측 공백을 조사하는 것이다. 제어기 기본값은 바꾸지 않았다.
