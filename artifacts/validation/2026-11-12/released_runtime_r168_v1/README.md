# RELEASED 현재 재계산의 제한 주행

2026-11-12, 실행 전 등록. **Jetson 접근 없이 노트북에서만 실행한다.**

r165는18.51m·최장저속4.432초·접촉0이지만 미완주였다. 새 작은 옆면공백 허가는0회이며, r152 계획기로 되돌린 저장467개 전체 출력도 동일했다. 따라서 이번에는 r164/165 공백 후보를 쌓지 않고 r152 계획기와 원 독립 보호를 유지한다.

변경은 r167의 `RELEASED/baseline` 현재 경로 재계산 연결이다. 이미 지난 측방차 상태·현재 양쪽 위협 없음·현재 전방 관측·같은 세대/경로/조향을 확인하고, 원 경로를 현재 좌표로 옮겨 추종/제동 명령을 다시 계산한다. 경로 원시각과 속도 상한은 보존하고, 이 재계산이 성립할 때만 명령 기준 시각을 현재로 둔다. TTL 연장이나 명령 시간만 갱신하지 않는다.

저장388개에서 같은 시각과+20ms는776개 진행, +40ms는388개 운동 이력 만료로 거절했다. 12개 현재 장애물/공백/세대/측방 상태 반례 통과. 저장 비교는 실제 배송·주행 증명이 아니다.

`run.py`는 같은60초 두0.8m/s 앞차·시설/마커 누락·C1 native10Hz·계획0.1초/수신50Hz·기존 지연 하한을 한 번 실행한다. 기존 접촉/노면/STOP/원시 결과를 유지한다. 지연은 옛 Jetson 비용에 기반한 하한이고 실차 CPU를 그대로 재현하지 않는다. 일반 기본 실행점 변경 없음. 결과에 따라 원인과 남은 한계를 정리하며 무변경 자동 반복하지 않는다.

## 결과

60초 대표는 **21.51 m·최장저속 7.957초·접촉/겹침 0**이며 미완주다. 노면·명시 STOP/정상 종료·소스 불변·시험 프로세스 정리와 입력/배송 계약은 통과했다. 원 최종 간격 및 지속 진행 실패는 보존한다. [통합 평가](two_actor_run1/combined_assessment.json)·[평가 로그](assessment.log).

앞차 통과 뒤 `RELEASED` 명령의 현재 재계산 누락은 줄었지만, 이번에는 실제 옆 반환이 있는 `GUARD`의 양수 명령이 현재 재계산 적용 범위 밖에 남았다. 당시 구현은 양쪽 `present=false`와 실제속도 0.35 m/s 이하인 좁은 상황만 지원했다. 원 계획기는 감속 중의 더 높은 실제속도로 제동 영역을 검사해 0.35 m/s를 허가할 수 있어 두 실행 경로가 불일치한다. 기록 시각으로 추정한 명령 만료와 저속 구간이 겹치지만, 보호층 수신 헤더를 직접 기록한 증명은 아니다.

다음은 저장 입력에서 현재 `GUARD` 이동 영역과 접근 방향을 같은 정책으로 다시 검사하는 것이다. 단순 시각 갱신·실제속도를 목표속도로 대체·새 옆 물체 무시·TTL 변경은 하지 않는다. 이 한 번의 결과를 성능 개선이나 실차 완료로 취급하지 않는다.
