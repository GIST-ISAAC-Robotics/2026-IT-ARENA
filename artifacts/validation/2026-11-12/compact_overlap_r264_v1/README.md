# r264 현재 확인에 필요한 원 계획 참조만 전달

r263 현재 검사 프로세스에 보낼 때 원 계획의 광선/운동 이력을 다시 전달하던 중복을 제거했다. 실제 현재 검사에서 쓰는 원 기준 시각·epoch·side·직전 요청각·native 표현/센서 epoch만 내부 참조로 전달한다. 현재 센서 배열/운동 이력은 그대로다. 부모의 적용 검사·기록에는 원 입력 전체를 유지한다. 검사 조건/원 값은 변경하지 않는다.

PC/Jetson 각각13검사와632계획/592현재의 전체 출력 동일을 확인했다. Jetson 겹침 처리76.749→75.139초, 현재 검사중앙32.74→29.52ms·p95 51.56→47.09ms다. 계획p95 147.84ms는 남는다. 같은 일정의 독립2회 대조이며 장시간 부하/ROS 주행 성능 보장은 아니다. r263 순차86.694초보다는약13.3% 줄었지만, 겹침만으로 느린 계산 구간의200ms 명령 공백을 해결하지 못한다.

원 입력/소스 해시 불변, 두 자식 정상 종료와 시험 뒤 잔여 프로세스 없음을 확인했다. 새 센서 취득·펌웨어·구동·전원 설정 변경은 없다. 원 결과 ZIP SHA는 `e155080e80091d9a19c4990c364c02dff256b7402217a8868e2b2b9f7348e2f1`다. 이 후보 역시 공통 코드·ROS에 미연결이다.

다음에는 현재 관측에 근거해 경로를 재검사하는 주기를 계획과 분리할 수 있는지 검토한다. 원천 시각을 현재로 바꾸거나 만료한 명령을 그대로 재발행하는 것은 별개이며 하지 않는다.
