# 현재 SOLO 저속 공백 선택 연결 r224

r223의 저장 비교는 원632+473판단 전체를 재현했다. 기존 단독의 이동 반경/50mm/0.2m/s 공백 정책을 이전 SOLO 상태에만 적용하자 r220의128정지가 모두 양수가 됐고 새 정지0·다른 선택 상태의 양수 변경0이었다. r217은 전체 출력이 그대로다. 이것만으로 새 궤적이나 실차 운용을 확인한 것은 아니다.

공통 연결은 이전 상태만 보는 r223보다 좁다. `oblique_gap_trial`을 기본 OFF로 유지하고, 교통에서는 pass/guard/recovery 구성이 모두 있어야 선택할 수 있다. 양쪽 seen/present=false인 SOLO에 더해 **이번 센서 장면의 같은 경로에서 옆차가 없는지** 다시 확인한다. 일반 관측/설명된 구조 결측뿐이면 이 추가 질의도 생략한다. 실제 partial 허가 뒤에도 원 선택기와 `/drive` 뒤 독립 보호를 거친다.

기존 `g1_oblique_gap_trial`은 보호층에도 같은 좁은 공백 계산을 선택하지만 보호층은 제어기 상태를 신뢰하지 않고 자기 입력/운동/소실 기억을 검사한다. 50mm 숨은 폭·최대 실제/요청속도0.6m/s·0.2m/s 출력·유효 양옆1m·총6°·근접/소실 물체 거절을 유지한다. 숨은 가는 물체 위험이 사라진 것은 아니며, 기존 사용자 목표의 저속 지속성 후보이다. GUARD/RELEASED 상태로 이 선택 범위를 넓히지 않는다.

## 검증 결과

관련367검사·별도 실제 ROS 노드/독립 보호 연결1검사·2패키지 빌드를 통과했다. OFF632+473판단은 원 전체 출력과 같고, ON은 r223의 명령/관측·선택 상태와 같다. 호출 뒤 저속 관측 설정이 다른 상태로 남은 사례는0이다.

최초 ON 비교에서 seq877의 표면 정합 `processing_ms`까지 비교해1개 실패했다. 이미 측정한 산출물을 기존 `comparable_decision` 규칙으로 [재감사](on_audit.json)했으며 해당 벽시계 진단 외 차이0이다. 원 [비교 실패](on.json)와 로그를 덮어쓰지 않았다. 최초 검사 환경의 ROS 설정 누락과 노드 검사 준비값 누락2회도 로그로 보존했으며, 환경/준비값을 보완한 마지막 검사만 통과로 기록했다.

새 [r225 주행](../traffic_solo_gap_runtime_r225_v1/README.md)을 같은80초 조건으로 진행한다. 기본 활성화·실물 구동은 하지 않는다. 원r220 미완주와 시험 당시 소스는 보존한다.
