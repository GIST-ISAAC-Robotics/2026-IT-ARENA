# 최신 현재 관측 재검사의 Jetson 비용 r221

r214는 별도 계획기 비용만 측정했다. r217에서 실제 수행한 현재 관측 재검사들을 저장 입력으로 분리하여 공통r218 소스의 부모 쪽 CPU 비용을 측정한다. 희귀0출력의 빠른 거절과 양수 진행 결과를 분리한다.

표본 복원은 측정 전에 하고 실제 노드 순서인 snapshot 생성→운동 투영→현재 재검사→결과 동결을 측정한다. 원 기록과 snapshot/출력 및 같은 기기의 반복 일치를 확인한다. 복원·ROS 콜백/전송·영상·독립 보호 비용은 포함하지 않는다. 기록 시각에 측정 CPU 비용을 더한 나이는 조건부 하한 계산이지 실물 주행 지연 실측이 아니다.

격리 폴더에서 저장된 시뮬 입력만 사용한다. ROS·센서/직렬 포트·펌웨어·모터·전력 설정은 건드리지 않는다. 기본 정책 변경이나 새 실차 활성화는 없다.

## 결과

Jetson에서460개 실제 저장 재검사를 수행했다. 속도·조향·판정·기준 시각과 snapshot은 PC와 같고, 같은 Jetson에서 전체 출력460개도 반복 일치했다. 소스169개와 입력의 불변을 확인했다. 작업은 종료했으며 원격 격리 폴더는 보존한다.

| 범위 | 중앙 | p95 | 최대 |
|---|---:|---:|---:|
| 전체460개 | 12.219ms | 49.794ms | 184.468ms |
| 양수 진행447개 | 12.197ms | 49.794ms | 184.468ms |
| 양수: snapshot | 1.213ms | 1.242ms | 1.308ms |
| 양수: 운동 투영 | 6.195ms | 6.321ms | 134.517ms |
| 양수: 경로 재검사 | 4.794ms | 42.239ms | 129.260ms |

전체157개가20ms,4개가100ms를 넘었다. 중앙값만으로50Hz 수신부의 실시간 처리가 가능하다고 판단할 수 없다. 기존 기록의 scan 나이에 측정 시간을 단순히 더하면0.3초를 넘는 표본이1개지만, 이는 다른 실행 비용을 제외한 조건부 계산이며 실제 ROS 지연 측정은 아니다. 계획기 r214와 입력/처리 단계가 다르므로 두 p95를 합하거나 개선율을 산출하지 않는다.

원 [Jetson 결과](results/jetson/report.json)의 `passed=false`는 유지한다. PC 전체 출력과4개가 달랐기 때문이다. [해당4개 재검사](results/differences.json)는 seq581·583·602의 `masked_left`, seq617의 `masked_right`와 총 질의 개수만 각각1개 차이가 남고 나머지 출력은 기존 수치 비교에서 같은 것을 확인했다. 명령 차이나 실행 예외로 확대하지 않으며, 반대로 진단까지 완전히 같은 결과로 기록하지 않는다.
