# r174 정체 입력에서 기존 작은 옆면 공백 후보 재검토

2026-11-12, **완료된 저장 입력 비교만 수행한다.** 새 위험 조건·보호 완화·주행 재실행·Jetson 접근은 없다.

r174 실행 중10m 부근에서 계획기 자체의 `GUARD/large_motion_region_unobserved` 정지가 관측됐다. 이전 r164 후보는 옛 저장 입력9개를 개선했지만 r165 실제 주행에서 사용0회였기 때문에 이후 실행에 쌓지 않았다. 이번에는 먼저 완료 기록의 원 판단을 다시 재현하고, **동일한 r164 구현**이 새 정체 입력에서 의미가 있는지만 대조한다. 후보가 도움이 없으면 그 결과도 그대로 남긴다.

`compare.py`는 이전 비교기의 입력/출력 경로만 바꾼다. 후보 구현은 r164 원 파일을 그대로 읽으며 새 기본값이나 실물 안전 판정으로 연결하지 않는다. 현재 배송 재계산·독립 보호층의 효과는 이 저장 비교 밖이다.

## 결과

완료된 r174의 **473개 전체 판단을 원 기록과 동일하게 재현**했다. 같은 입력에 기존 r164 후보를 적용해도 전체 출력 차이0·정지→진행0·진행→정지0·후보 사용0이었다. 원 trace 해시도 동일하다. [기계 결과](comparison.json). 따라서 이 후보를 다시 연결해 주행을 반복할 근거는 확보하지 못했다.

이번 정체는 정상 부분관측 판단을 통과한 뒤 선택기의 이동 영역 검사에서 나타났으며, r164의 `follow_unbounded_missing` 진입 조건에 해당하지 않는다. 전방 공백의 전역 거절만 되돌리는 기존 후보로 해결됐다고 볼 수 없다. 지연 교통 실패는 남기고, 다음은 실제 실행 연결에서 필요한 현재 재계산 모듈의 공통화/동일 출력 검증을 진행한다.
