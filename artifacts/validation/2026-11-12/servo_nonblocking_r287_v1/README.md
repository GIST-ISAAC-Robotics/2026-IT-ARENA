# ST3215 비차단 통신 준비 r287

기존 무부하 probe는 `xfer()` 안에서 TX완료와 최대30ms 응답을 기다렸다. 운영5ms 모터 제어 루프에 그대로 넣을 수 없어 송신/대기/수신을 나눈 유한 상태 거래 후보를 만들었다. 매 호출은 현재 UART가 수락할 바이트만 보내거나 최대64B를 파싱한 뒤 반환한다. 응답이 없어도 모터 제어 주기를 막고 기다리는 루프가 없다.

실제 probe에서 사용한 mode33/position56 읽기, RAM torque40·goal41 쓰기 형식만 제공한다. EEPROM·ID·baud·영점 쓰기는 없다. 위치/속도/가속의 packet 범위와 실제 장착한 조향 각도 제한은 별개이며 장착 교정은 아직 필요하다. 클래스 자체가 ARM/구동을 허가하지 않는다.

부분 송수신·echo·잘못된 checksum/다른ID·응답 없음·취소/새 연결·RAM명령 인코딩·서보 오류·중복 시작·시계/송신 계약11사례를 최적화 빌드와 ASan/UBSan에서 통과했다. ESP32-S3로 모든 공개 거래 경로를 target object 컴파일했다. 노트북에서만 수행했으며 **Jetson 접속·실제 UART·센서·flash·모터·서보 조작은 없다.** 공통/펌웨어에 아직 연결하지 않은 artifact 후보다.

30ms는 기존 probe의 응답 한도이며 실장 환경의 보장값이 아니다. timeout/취소 뒤에는 같은 연결에서 자동 재시도하지 않고 외부 UART정리/새 연결 경계를 요구한다. ST 응답에는 요청 순번이 없어 늦은 같은ID/길이 응답을 이 객체만으로 완벽히 구분할 수 없다는 한계가 있다. 성공 ACK도 실제 조향 완료/기계적 안전을 의미하지 않는다. 다음 단계는 UART1 비차단 HAL과 주기 모터 제어·PCNT/운영 계약의 통합이며 현재 보드 firmware는 바꾸지 않는다.
