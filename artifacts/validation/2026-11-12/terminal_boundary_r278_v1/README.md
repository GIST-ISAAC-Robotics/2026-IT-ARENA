# 저속 반대 벽의 현재 관측 재획득 r278

r274 정체 당시 선호 왼쪽에는 가까운 기준점/경로가 없지만 오른쪽에는1.8m 긴 현재 벽이 관측됐다. 기존 저속 재획득은 선호 벽만 허용했다. [원 센서 장면](terminal_sensor_view.png)·[관측 적합](inspection.json).

후보는 `standing_wall_reacquire` 선택·측정속도절대0.10m/s 이하·유효 기억없음·선호 벽 경로없음에서만 기존 길이/anchor 기준을 만족한 현재 반대 벽을 선택한다. 확인 횟수·전방 점유·미관측·재개·현재 영역·독립 보호를 유지한다. 새 경로를 가정해 빈 공간을 만들지 않는다.

- 원 실제 계산 순서549계획 OFF 전부 동일. ON은243계획 변경,54초 이후234개는 원0에서 진행 후보가 됐다. 같은 저장 궤적이므로 실제 전진/정체 해결 증명이 아니다.
- 관련99검사 통과. 짧은 물체, 빠른 상태, 앞 장애물, 전방 미관측, 동일 스캔 반복 및 기존 선호 경로를 확인했다. 반대 벽 갱신이 꺼지면 기억은 기존대로 만료한다.
- 초기 합성 테스트는 갱신 옵션이 꺼진 구성에서 현재 경로 유지를 잘못 기대했고 정지 조향 이유를 너무 좁게 적었다. 원 실패 로그를 보존하고 시험 기대를 고쳤다. 후보 구현 변경은 없다.

공통/기본 모델에는 미반영. 다음 제한 주행은 [r279](../opposite_reacquire_runtime_r279_v1/PLAN.md)로 분리한다.
