# r252 동일한 단계 지연의 완료 알림 재현

r250 실행 중 계획146.75ms/현재 재검사33.56ms의 최소 결과 나이가50Hz 부모 타이머 대기로160ms+40ms가 되고, 원 스캔 약100ms를 합쳐300ms 만료에 닿는 사례를 확인했다. r250 결과/실패는 보존한다. 실제 공통 구현은 완료 알림으로 부모를 깨우므로 평가 측도 같은 의미의 알림을 재현해 대조한다.

두 단계의 등록 지연·TTL·제어기·독립 보호·센서·물성·교통/STOP 판정은 그대로 유지한다. 실제 자식 결과를 받은 뒤 아직 등록 시각 전이면 시뮬 시계의 한 번짜리 타이머를 예약한다. 도착 기한에 한 번 깨워 공통 수신/제어 경계를 거치며, STOP/세대 변경 시 예약과 보관 결과를 취소한다. 실제 계산이 더 늦으면 그 완료를 기다린다. 1ms 고정 폴링이나 추가 제어 주기는 넣지 않는다.

같은80초 교통 장면을 변경된 완료 알림 조건으로 한 번 수행한다. 소스/판단 재생과 원 기준을 그대로 검사하고, 관측된 지연을 근거 없이 줄이거나 만료선을 늘리지 않는다. 두 p95의 합은 전체 p95도 최악시간 보증도 아니다.

사전 검사의 첫 실제 ROS 시계 시험은 시험용 context와 전역 executor를 혼용해 실패했다. 별도 context의 executor를 명시한 뒤5개 검사를 통과했다. 원 실패 로그/시험소스는 보존했다.

## 실행 결과: 초기 수신 실패

시작 대기에서 ROS `autonomy/drive/light/safe_drive/safety/scan`이 없어 종료했다. 녹색 신호·주행 시작 전이므로 제어기 주행 성능을 판정할 수 없다. 평가기가 받은 ROS clock은0.114초가 마지막이지만 Gazebo pose 원문은14.179초까지 진행했다. **렌더링 단계에서 시뮬 전체가 멈췄다는 초기 추측은 확정 원인으로 사용하지 않는다.**

`ogre2_startup_failure.log`의 실제 렌더러는 D3D12/NVIDIA RTX5070이다. EGL 장치 열거의 `software` 이름을 CPU 렌더링으로 해석하지 않는다. 종료 서비스 응답·14자식 정상 종료·잔여0·소스 보존은 확인했다. 종료 뒤 WSL 사용 메모리약806MB/가용14.8GB, Windows 가용약13GB·GPU 메모리295MiB였으며 당시 실행 중 메모리 기록은 없다.

후속 [r253](../staged_event_runtime_r253_v1/README.md)은 같은 제어/단계 지연을 유지하고 실행 중 프로세스·Gazebo stats를 수집하는 **진단 포함1회 재시도**다. 시작 실패가 반복되면 자동 재실행하지 않는다.
