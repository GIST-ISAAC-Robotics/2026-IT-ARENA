# 실제 C1 거리 0의 무반환 표기 대조

r166의 비공개 원시 기록 204스캔/102,780점과 11/10 보존한 제조사 ROS `publish_scan` 원문을 대조했다. 새 장치 접속·구동은 없다.

| 원시 값 | 점 수 | 기존 진단 어댑터 | 비교 후보 |
|---|---:|---|---|
| 거리 0·품질 0 | 22,888 | JSON null → NaN | 제조사와 같은 `+Inf` 무반환 |
| 양수 거리·양수 품질 | 79,808 | 거리 유지 | 동일 |
| 양수 거리·품질 0 | 84 | null → NaN | 동일 |

제조사 보존 원문은 거리0만 `+Inf`로 보내고 품질은 intensity로 전달한다. 이번 후보는 기존 어댑터의 양수 거리/품질0 무효 처리는 유지한다. SDK가 거리0을 보냈다는 사실만으로 그 방향이 멀리까지 비었다거나, 무반환 원인이 먼 거리였다고 해석하지 않는다. 어두운 표면·너무 가까운 물체 등의 원인은 이 정지 수신만으로 구분할 수 없다.

저장 원시로 기존204 payload를 모두 그대로 재생한 뒤 거리0 표기만 바꿔 공통 decoder/지역 장면까지 비교했다. **204개 장면의 광선 상태·반환점·미관측 분류가 모두 동일**하다. 결과는 return69,082 / unknown16,565 / masked17,133이다. `+Inf`도 unknown이며 자유 공간이나 유효 반환점으로 채우지 않는다. 반면 기존의 제한적인 차체 옆 무반환 검사는 `+Inf`와 NaN을 구별하므로, 현재 모두 null로 합치는 방식은 그 검사에 도달하지 못한다.

시간 추정은 `unverified_estimate` 그대로이며 실제 시각/장착/운영 주행 승인은 하지 않았다. 이미 저장된 출처 불명 null을 일괄 `+Inf`로 바꾸지 않고 **원시 SDK 거리0이 확인된 새 변환만** 대상으로 한다. 비교 근거는 `summary.json`, `comparison.json`과 각 생성 스크립트다. 원시 실내 점군은 기존 Git 제외 경로에 보존한다.

## 적용과 검증

r200 종료·소스 불변 확인 뒤 진단 어댑터에 적용했다. 거리0은 `+inf`, 양수 거리/품질0은 null, 그 밖의 거리는 이전값 그대로다. payload schema·배열 순서·점별 추정 시각·범위·frame은 바꾸지 않았다. 진단에는 표기 이름과 두 종류의 개수, 자유 공간을 뜻하지 않는다는 항목을 추가했다.

분리 후보6검사에서 원시204스캔/22,888변환, 기존 시각 겹침/수신후 추정 끝 시각 불변을 확인한 뒤 같은 바이트를 적용했다. 관련78검사에서 공통 decoder/지역 장면의 unknown 유지, 실제 시각 승인 거부, legacy null 보존, native 운동/전송 경계를 확인했다. 새 Jetson 실행이나 시뮬 주행이 아니며, 운영 설치본을 교체하지 않았다.

`candidate_sources.json`, `candidate_tests.log`, `applied_sources.json`, `applied_tests.log`, 변경 전 `before_sources.zip`이 근거다. `compare.py`는 적용 전 변환 기준에서 생성한 대조이므로 다시 실행할 때는 위 변경 전 사본을 사용한다. 현재 구현과 후보는 바이트 동일하다.
