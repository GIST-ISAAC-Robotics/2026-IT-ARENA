# Jetson 원천 입력 재생의 플랫폼 차이

2026-11-12. r150의 동결162파일 묶음을 재부팅 후 Jetson에 전달하고 전체 원본 SHA를 확인했다. CPU 전용 baseline465판단 비교는 일부 전체 진단 출력 불일치로 실패했다. 이 실패를 통과로 바꾸지 않는다. 첫3불일치의 속도/조향은 같았고, `selector_region` 또는 `selector_guard_candidate/region`의 질의/마스크 점 개수가 각각1개씩 달랐다. Jetson NumPy1.21.5·ARM64와 WSL의 수치 계산 차이가 후보이며 원인은 아직 확정하지 않았다.

원 `measure.py`와 동결 소스/기대 출력은 유지한다. 별도 `measure_audited.py`는 전체출력·명령 불일치·필드별 차이와 계산 시간을 따로 보존한다. 엄격 동등성 검사를 완화해 통과시키는 것이 아니라 실패를 기록한 상태로 성능 관측을 끝내는 진단이다. 모터/서보/센서 입출력과 전력 설정 변경은 없다.

초기 실행 준비에서 셸 CRLF와 sysfs 텔레메트리 읽기 오류로 본 측정 전 중단된 시도도 로컬 로그에 남겼다. 업로드한 Python 실행기로 바꾸고 선택적 텔레메트리의 읽기 실패를 표시하여 본 측정을 시작했다. 실행 소스 자체는 바꾸지 않았다.

## 전체 관측 결과

원본 소스/입력162항목의 SHA는 실행 전후 동일했다. baseline·후보 각각465건의 속도/조향 명령이 기대값과 모두 같았다. 각 모드130건의 전체 진단 불일치는 질의 개수·masked/unknown 분류 개수에 한정됐다. 전체 출력 엄격 동일성은 실패로 유지하며, 다른 입력에서 동일한 명령을 보장하지 않는다.
