# r253 완료 알림 대조의 실행 환경 진단

r252는 시작 전 ROS 센서/상태 수신이 없어 종료됐다. Gazebo 정답 pose는14.179초까지 있었으나 평가기 ROS clock은0.114초 이후 받지 못했다. 따라서 시뮬 전체가0.114초에 정지했거나 렌더러가 원인이라고 확정할 수 없다. GPU는D3D12/NVIDIA였고 종료14자식/잔여0, WSL 메모리 여유14GB 이상이었다. 원 로그/실패를 보존한다.

이 실행은 제어 동작이 시작되기 전 환경 실패를 구분하기 위한 **진단을 추가한1회 재시도**다. r252 지연·완료 알림·교통·소스/STOP 판정을 그대로 두고10/30/60초에 해당 시험 프로세스·메모리·Gazebo stats를 수집한다. 주행 실패나 같은 초기화 실패가 재발하면 자동 반복하지 않는다. 일괄 WSL 재시작이나 드라이버/전력 설정 변경은 하지 않는다.

## 결과: 실행은 성립했지만 주행 실패

- 신호 출발 뒤80초·진행11.940m, 최장저속18.720초로 한 랩/지속 주행 실패. 첫 상대 접촉은sim75.875초다. 시설/벽·바퀴 노면 이탈 표본0과 구분한다.
- 명시 STOP·서버 종료·14자식 정상 종료·고유 파티션 잔여0·등록 소스 불변을 확인했다. 원 실행/후처리 반환1은 실제 실패 판정이다.
- 원 계획403개와 현재 재검사301개가 각각 동일하게 재생됐다. 전달 후보403개·만료 폐기0으로 r250의 전량 만료는 재현되지 않았다. 적용 시 원 광선 나이는중앙/p95 약285ms였다. 단계 지연은 동일146.75/33.56ms이고 보호·TTL은 그대로다.
- 그러나 새 양수 적용은대부분200ms 간격이었다. 현재 재검사 자체의33.56ms 나이를 가진 명령을200ms 뒤 갱신하므로, 다음 명령 전200ms 명령 나이를 넘는 구간이 남았다. `diagnosis.json`에서 보호층의 stale 표본1,405개 중600개는 직전 상태상 양수 명령,805개는0명령이었다. 최초 양수 사례는 현재검사8.287→발행8.321→보호층8.500초 만료다. 현재검사 시각을 이미 사용하므로 단순히 원 계획 시각을 현재검사 시각으로 바꾸면 해결된다는 설명은 맞지 않는다.
- 양수 후보300개와0후보103개가 있다. **모든 장기 저속/접촉 원인이 만료 하나라는 뜻은 아니다.** 시간 관계와 출력 분류를 남겼으며 원 경로 판단의0출력은 별도로 남는다.
- 완성된883개 native 배열은 수신과 모두 대응했지만 취득 누락 누계1건으로 무손실 기준 실패다. 형상/마커/평가 조건과 미발생 측방 관문의 false를 성공으로 바꾸지 않는다.

이 실행은 측정된 단계별p95를 고정 최소 나이로 넣은PC 대조이며 실제 Jetson의 결합 p95/실차 결과가 아니다. 실제PC 계획 계산p9533.02ms·현재검사p955.35ms로 주입 대기가 지배했다. 실행 중 같은PC에서 별도 MCU 후보의 약10초 단위검사/컴파일도 있었으므로 순수PC 계산 성능 벤치마크로 사용하지 않는다.

다음은 실제 MCU 상태 연결 대표를 마친 뒤, 저장 입력에서 **새 경로 계획과 이미 선택한 경로의 현재 관측 확인을 다른 주기로 처리하는 선택지**와 남은 계획 비용 개선을 비교한다. 새 시각만 붙이는 재발행이나 TTL 연장으로 이번 실패를 통과시키지 않는다. 같은 주행을 즉시 반복하지 않는다.
