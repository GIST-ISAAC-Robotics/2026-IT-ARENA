# 현재 검사와 새 양수 계획의 전환 순서 비교

r284에서 확인한82+147ms>200ms 반복 만료를 명령 시한 변경 없이 줄이는 저장 입력 후보다. 새0·감속 계획·주행 의도/선호 벽/selector/입력epoch 변경은 기존처럼 현재 검사를 선점한다. 같은 FOLLOW/SOLO/같은 경계 선택이며 새 속도 상한이 낮아지지 않았을 때만 이미 진행/ready인 현재 검사 하나를 끝내고, 다음 검사는 보관한 새 계획을 먼저 쓴다. 기하/현재 시각·직전 요청각·원 관측의 검사는 원 RouteProcess를 유지한다. 이전 점유 허가나 원 시각을 갱신하지 않는다.

r266 무조건 보조 제출은 새 계획으로 검사64개 폐기·Jetson최장공백 증가로 미채택이었다. 따라서 동일 조건의 `new_only`·`preempt`·`finish`를 대조한다. 첫 대표는 원 r243 dense15초 입력, 취득+20ms 수신 가정, 실제 두 프로세스, 계획146.74551065ms/현재81.304613ms 최소 계산 시간이다. 저장 운동은 새 출력에 반응하지 않는다. 새 r282 궤적/ROS/실제 주행이나 Jetson동시 부하 증명이 아니다.

선택형 artifact 안에서만 구현한다. 같은 방향의 미세 반복 최적화로 확대하지 않고, 폐기/양수 갱신/원 시각 만료·최장 공백/정상 종료를 비교해 유효한 다음 한 단계를 정한다. 새 STOP/경계/만료 반례를 통과해도 기본/실물 활성화는 하지 않는다.
