# 기존 저속 검사의 누락 보완 후 제한 주행

2026-11-12 실행 전 등록. PC LOCALHOST·고유 Gazebo 파티션만 사용한다. Jetson에는 접근하지 않는다.

r174의16.39m/24.866초 미완주를 보존한다. r178 저장473판단은 기존0.15m/s 전체 GUARD 검사 진입을 추가해142개 정지→저속 진행, 새 정지0이었다. 이 중 음수 모터 피드백1개의 현재 재검사 불일치를 r179에서 기존 `forward_drive` 정책으로 맞췄다. 원 signed history와 기존 보호/물성/나이/간격을 유지한다.

계획 후보만 prefix로 선택하며 현재 재검사는 r176–r177의 공통 모듈/실제 노드 옵션 `g1_current_path_recheck:=selected_v1`을 사용한다. 기본값은 OFF다. 과거 Jetson 비용의 배송 지연 하한과 새 스캔 제출 정렬은 평가 prefix에 남기며 이를 실물 지연 재현이나 새 Jetson 성능으로 부르지 않는다.

같은60초·0.8m/s 두 앞차·시설·ID20/30 누락·C1 native·차체/구동계/노면·독립 보호·명시 STOP/종료 조건으로 한 번 수행한다. 현재 재계산 연결의6범위/2,414반환 동일성, 실제 노드 OFF473/ON193재현, 저속 후보/부호/관련 회귀를 근거로 한다. 원 r174는 무관한 서보 시험 파일 변경으로 전체 소스 불변 판정도 실패했으며 그대로 남긴다.

## 결과

60초 제한 주행은 **20.12m·최장저속11.112초로 미완주**다. r178 저속 재검사3회가 실제 사용됐고10m 부근을 지나갔다. 접촉/겹침/노면 이탈 표본0, 명시 STOP·정상 종료·잔여 파티션 프로세스0을 확인했다. 전체 랩·장기정체·최종간격 실패는 보존한다. [기계 판정](two_actor_run1/combined_assessment.json)·[판단 분류](diagnosis.json).

현재 재검사280개 중231개 양수였다. 후반에는 옆차 방향 접근의 현재 관측 부족46개가0이었고, 계획기 자체도 GUARD 접근 거절62개를 남겼다. 저장 입력에서는 통과했더라도 실제 다른 궤적의 완주를 보장하지 않는다는 한계를 보여 준다. 바뀐 궤적·후속 시각을 포함하므로 진행 증가를 단일 변경의 순수 효과로 단정하지 않는다.

보존 ZIP은 불변이다. 다른 하드웨어 작업의 `src/arena_vehicle_interface/firmware_encoder_probe/README.md` 변경1개 때문에 전체 등록 파일 불변 판정은 실패로 남겼다. 나머지 등록 파일은 동일하다. 초기 사후 판정은 프로세스 종료 목록을 쓰기 전에 호출해 파일 누락으로 실패했으며, 실제 종료/잔여0 확인 뒤 별도 `assessment_postflight.log`에 다시 수행했다. 원 실패 로그와 판정은 보존한다.

다음은 실제속도와 현재 점유/관측 조건을 그대로 둔 채 더 낮은 목표의 전체 검사로 정지를 피할 수 있는지 저장 입력에서 분리한다. 같은 실패를 무변경 재실행하지 않는다. Jetson 접근은 없었다.
