# 전방 검사 범위 끝의 즉시 이웃 반환

2026-11-12. r152 두 번째 주행의 `unbounded_missing` 28호출을 원시360도 배열과 대조했다. 9개는 전방±100° 경계 바로 바깥에 실제 유효 반환이 있지만 배열을 잘라서 보던 코드가 그 이웃을 버린 경우였다. 나머지19개는 공백이 검사 범위 바깥까지 이어진다. 대표seq635는 전방 안에서는0.684°·1점이나 전체 공백은4.968°·7점이므로 단일 결측처럼 허용하면 안 된다. [원시 이웃 감사](inspection.json)와 상세 JSONL을 보존했다.

`partial_observation.py`의 경계 조회만 수정했다. 범위 끝이면 전체 각도순 배열의 **즉시 이웃 한 점**이 실제 유효 반환이고 기존 각 간격 이내일 때만 사용한다. 결측/NaN/범위 밖 값을 건너뛰지 않으며, 공백 폭·속도·가까운 반환·이전 장애물 소실·독립 보호 검사는 유지한다. 거리/자유 공간을 생성하지 않는다. 원 함수는 `partial_observation.before.py`에 보존했다.

## 재부팅 전 확인과 중단 이력

- 새20개 경계/CW·CCW/양쪽/근거리/장애물 기억 검사 포함 **관련134개 통과**. `build/r156_tests2.log`와 [정리 시점](wrapup.json) 참조.
- 기존 함수로469판단을 동일 재생한 뒤 수정 효과를 비교할 `compare.py`를 준비했으나 **미실행/결과 없음**이다. WSL 호출이 다시 응답하지 않았고 로그 파일도 생성되지 않았다. 사용자 재부팅 준비 요청에 따라 해당 Windows WSL 클라이언트2개를 종료했다. 종료 뒤 같은 클라이언트0개를 확인했으나 Linux 내부 프로세스 상태는 조회할 수 없었다.
- 앞서 일반/root `E_UNEXPECTED`는 가상 메모리 여유8.44 GB에서도 발생했다. 배포판 재시작 뒤 위134검사는 실행됐으나 다음 WSL 진입이 멈췄다. 메모리만의 원인으로 확정하지 않는다. [환경 실패](environment_failure.json)를 남겼다. 초기 인라인 실행과 Windows 대체 검사는 ROS import 경로가 없어 수집 실패했으며, 올바른 bash 파일/ROS overlay 방식에서134검사가 통과했다.
- **실주행 개선·Jetson 검증·새 live 소스 계약은 아직 없다.** 수정은 미커밋 작업 파일로 남는다. 이전 r147 소스 계약/기존 r152 실행을 이 수정으로 소급하지 않는다.

## 재부팅 후 순서

1. Ubuntu 정상 명령과 자기 시험 잔여 프로세스를 확인한다. `build/r156_compare.sh`를 실행하여 원본469판단 동일 및 수정 전후 판단을 비교한다. 새 작업 전에 이 미완료부터 확인한다.
2. 결과가 유효하면 관련 관측/보호 검사와 소스 계약·overlay 일치를 확인하고 제한 주행 여부를 판단한다. 반복 실패만으로 기준을 낮추거나 동일 주행을 재실행하지 않는다.
3. Jetson 연결이 복구되면 r150의 보존 CPU 묶음을 측정한다. 새 수신 프로필r153·실물 장착/취득시각·다른 미완성 주행 항목은 현행 계획에 남는다. 재부팅 자체를 연결/성능 복구 증거로 취급하지 않는다.


## 11/12 재부팅 후 비교 완료·미채택

WSL 복구 후 [전체 비교](comparison.json)를 수행했다. 원 함수469판단은 원기록과 모두 동일했다. 후보는 진단/상태 출력21개가 달라졌으나 **정지→진행0·진행→정지1**이었다. seq627의 좁은 공백은 인정해도 별도 평행 경로/상태 조건 때문에 계속 정지했고, 뒤이은 기억 만료/래치가 seq660의 기존0.141 m/s 명령을0으로 바꿨다. 단일 조회 수정만으로 정체가 해결되지 않았다.

새 실주행은 하지 않았다. 후보 바이트는 `partial_observation.candidate.py`, 새20검사는 `test_candidate.py`로 보존했고 공통 실행 소스를 원본 `cffd6898…`로 복원했다. `compare.py`는 이제 명시적으로 후보 파일을 읽으며 운영 기본에 설치하지 않는다. 초기134검사와 전체 비교의 다른 결론을 함께 남긴다. 다음은 단일 예외 추가가 아니라 관측/상태/명령 적용을 함께 다루는 [중간 점검 순서](../../../../docs/reports/READINESS_REVIEW_2026_11_12.md)를 따른다.
