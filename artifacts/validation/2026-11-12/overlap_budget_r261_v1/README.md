# r261 겹침 실행의 시간 예산

r256 산술 하한에10Hz 스캔 도착·25ms 새 제출 창·100ms 양수 명령 최소 간격·기존300ms 원천/200ms 명령 나이를 추가했다. 계산 도중 바뀌는 조향/선택 상태, ROS/IPC/CPU 경쟁은 모형화하지 않았다. 시간 예산의 후보 비교이며 실제 발행/주행 성능이 아니다.

- 고정147/34ms: 순차/겹침 모두5Hz·이전 현재 확인 기준에서 다음 명령까지234ms. 겹침만으로 해결되지 않는다.
- 고정100/34ms: 순차5Hz, 겹침10Hz. 다음 명령 직전 나이는234→134ms.
- r257 Jetson 순수 계산632건의 저장 비용: 시간 예산상6.77→7.82Hz, 만료 간격199→109개. 입력과 부하는 새로운 일정에서 달라질 수 있다.
- 새 스캔25ms 창을 없애면 원천 만료로 버리는 결과가7→120개로 늘었다. 이 변경은 채택하지 않는다.

최종 방향은 겹침만으로 완주를 선언하지 않고, 최신 직전 요청각에 대한 현재 경로 확인·STOP 세대·부모 발행 경계를 갖춘 제한 후보부터 만드는 것이다. 원 TTL/물성을 늘리지 않는다. `result.json`의 모든 결과는 조향/상태 검증 미포함임을 명시한다.
