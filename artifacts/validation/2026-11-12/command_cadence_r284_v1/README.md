# 반복 명령 만료와 직선 저속 r284

r282 저장 기록15–60초를 분석했다. 이 구간의 현재 검사307개는 모두 양수이고 접촉은 없었다. 현재 결과는 원 기준시각에서 중앙82ms 뒤 준비되며 다음 결과 간격은147ms였다. 합계229ms가 명령 시한200ms를 넘으므로 결과 사이마다 약29ms가 빈다. 같은 구간 보호층2,250표본 중473개가 `stale_input`이고 MCU 목표에는306개 양수 구간(중앙120ms)과306개0 구간(중앙40ms)이 교대로 나타났다. 새 계획이 길을 못 찾은 구간과 구분한다.

차체 평균속도0.139573m/s와 모터축 환산 평균0.139593m/s가 거의 같았다. 이 구간의 지연을 엔코더 환산 오류나 바퀴 헛돎으로 설명할 근거는 없다. Gazebo `SingleMotor::Step`은 감속/0목표를 가속 기준에 즉시 반영한다. 매번0으로 돌아간 뒤3m/s²로 다시 올라가므로120ms 양수 구간의 기준 상한은0.36m/s다. **이것은 코드와 목표 구간으로 얻은 상한이며 기록되지 않은 실제 토크/PI 상태를 실측한 결과가 아니다.** 후반71.765초 접촉과80초 이후 현재 영역 거절도 별도로 남는다.

`audit.py`와 `result.json`을 보존한다. 결과 준비 시각은 계산 결과의 회수시각이며 `/drive` 바이트 수신 시각과 완전히 같다고 보장하지 않는다. 수신기 목표와 보호층 표본을 따로 대조했다. 명령 시한·물성·판정선을 바꾸거나 새 주행을 하지 않았다.

다음 후보는 새 계획을 기다리는 동안 현재 경로를 최신 관측으로 확인하는 실행 순서다. r266의 무조건 보조 제출은 Jetson에서 불필요 폐기64회·최장공백 증가로 미채택이었으므로 그대로 되살리지 않는다. 새0/STOP/epoch 경계는 즉시 반영하고, 현재 양수 경로 검사가 끝나기 직전 새 양수 계획이 도착할 때의 불필요 폐기/대기부터 저장 입력과 스케줄 반례로 비교한다. 원 시각과200/300/500ms 예산은 유지한다. 동시에 조립 전 MCU 구동 연결을 진행하며 이 한 실패만 반복하지 않는다.
