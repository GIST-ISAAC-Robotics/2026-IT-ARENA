# r236 — 현재 재검사 완료 알림과 긴 수신 지연 계측

r235의 같은 자식 재검사는 IMU 수신 p95를 줄였지만20ms 주기 회수 때문에 결과 나이가 늘었다. 이번 후보는 **작업 완료만 알리는 스레드**가 자식 연결의 읽기 가능 상태를 기다리고 ROS guard condition을 깨운다. 계산·수신·공유 버퍼·상태 변경은 여전히 단일 ROS 소유자에서 한다. 알림 스레드는 결과를 읽거나 제어 계산을 수행하지 않는다. 다음20ms 타이머도 유지하고 종료 때 알림 스레드를 먼저 끝낸다.

[생성 절차](prepare.py)가 r235의 프로토콜·계산을 그대로 보존하고 알림/GC 계측만 넣었다. 공통 노드/기본 정책에는 아직 연결하지 않았다. PC20판단에서 전체 결과 동일·385/385 합성 IMU 수신·알림/자식 정상 종료를 확인한 뒤 Jetson632판단을 수행했다.

## 판단과 다음 연결

완료 알림은 단순20ms 회수의 추가 대기를 줄였고 부모 계산 경합을 완화했다. 다만 계획 자체의10Hz 예산 미달과 드문 긴 지연이 남는다. **조건부 실행 구조 후보로 유지**하며 다음 연결은 원 reference·원천 나이·마지막 발행 조향·센서/운동 세대·STOP을 회수 시 대조하고, 실제 발행 전에는 마지막 적용시각을 앞당기지 않는 방식이어야 한다. 같은 스냅샷의 성공을 곧바로 실차 주행 채택으로 바꾸지 않는다. 실물 입력/MCU 준비로 다음 묶음을 진행하고 이 후보 연결과 기하 비용 개선을 후속에 남긴다.

실제 ROS 격리는 **localhost·domain196**이다. 원 보고서의 `scope` 문자열에197이 남은 표기 오류를 보존했고 [독립 감사](comparison.json)에 정정했다. 입력/명령 만료 관문·센서/영상·독립 보호/MCU가 없는 비용 시험이다. 모든 입력을 처리하므로 누적 스케줄 지연은 실제로 오래된 명령을 발행했다는 뜻이 아니다.

결과 ZIP SHA `7095882dd9f7d215553931f47a24d95060b6a76d9e8076788db46d53eeb8551f`를 원격/로컬 대조했다. 원 입력별 출력·수신 CSV는 로컬과 Jetson 격리 폴더에 두고 Git에서 제외했다. 소스와 전송 해시는 [명세](bundle_manifest.json)·[묶음](bundle_receipt.json)에 보존했다.
