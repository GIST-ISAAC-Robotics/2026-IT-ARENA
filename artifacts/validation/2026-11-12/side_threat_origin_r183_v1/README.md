# 접근 관측 거절 구간의 실제 반환 출처

2026-11-12 PC 저장 입력 진단. 제어 변경·새 주행·Jetson 접근은 없다.

r180에서 현재 재검사가 `guard_current_approach_not_observed`로 멈춘46개 입력을 복원했다. 같은 선택 경로의 측방 반환을 계산한 뒤 **평가에만** 저장 차체/상대 위치와 실행 월드 충돌체를 사용했다. 이 평가 결과나 지주 좌표를 대회 제어기에 넣지 않는다.

## 결과

- 왼쪽155점·오른쪽149점 모두 **ID20 양쪽 지주**의 충돌체 표면과 부합했다. 가장 먼 점도0.389mm 이내였다.
- 두 상대 차량 중심과의 가장 가까운 거리는3.267m였다. 이46개 거절의 측방 반환을 가까운 상대 차량에서 온 것으로 볼 근거는 없다.
- 정답 차체 자세는 현재 입력에 가장 가까운 기록을 사용했으며 시각 차이는 최대39ms다. 위0.389mm는 센서 정확도 인증이 아니라 이 정체 장면의 사후 좌표 일치다.
- 처음 사용한 트랙 전용 충돌체 함수는 별도 모델인 마커 지주를 포함하지 않았다. 그 결과와 당시 분석 스크립트는 `result.json`·`analyze_track_only.py`로 보존했다. 지주 모델까지 추가한 [최종 결과](result_all_static.json)가 출처 판별 기준이다.

현재 제어기는 작은 측방 물체를 정지 시설인지 움직이는 차량인지 분류하지 않고 경로/관측으로 다룬다. 따라서 지주 반환이 위협 후보가 되는 것 자체를 오류로 단정하지 않는다. r181은 시설 이름·지도 없이 기존 낮은 속도에서 이동 영역을 다시 검사하는 후보이며, 새 옆차/점유 거절을 유지한다. 지주를 지우거나 항상 정지 물체라고 가정하는 변경은 하지 않았다.

후속은 r182 실제 주행 결과로 이 저속 진행이 정체를 줄였는지 판단한다. 통과했다면 여기서 별도의 시설 분류기까지 추가하지 않고 남은 실행 구성 연결로 넘어간다. 실패가 남으면 실제 원인을 다시 구분한다.
