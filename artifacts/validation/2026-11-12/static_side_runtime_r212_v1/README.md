# r209 실제 경과 시각 연결의 환경 재시도 r212

r210은 필수 ROS 입력이 오지 않아 시작 전150초 timeout이었다. 소스/스냅샷 불변·정상 종료·고유 파티션 잔여0을 확인했고 행동 결과로 취급하지 않는다. 빈 world의 GZ→ROS 시계와 Python timer를 r211에서 별도 확인(시계2,001개·timer101개·정상 종료)한 뒤 새로운 실행 폴더에서 한 번만 재시도한다. 간헐 원인은 아직 미확정이다.

제어/시설/상대/물성/지연/평가 기준은 r210 그대로이며 평가기에 /clock 수신 카운터만 추가했다. r203 대비 차이는 r209 실제 경과 시각 적분이다. 입력 실패가 재발하면 주행 반복을 멈추고 보존 진단으로 분리한다.

## 결과

유효한60초 주행을 마쳤으나 원/추가 목표는 **실패**다. 진행34.12m·최장저속6.358초로 r203의30.68m·10.484초보다 더 진행했다. 두 폐루프 궤적은 다르므로 결과 차이 전체를 단일 원인의 개선율로 환산하지 않는다. 접촉·시설 겹침·차체/바퀴 노면 이탈0, STOP 안정 도달·정상 종료·소스/스냅샷 불변·잔여 프로세스0을 확인했다. STOP 시점에 이미 멈춰 있어 약1μm의 정지 변위를 제동 성능으로 해석하지 않는다.

입력/지연 연결 검사 모두 통과,466판단 중461개 후보/5개 source 만료 폐기였다. /clock67,908개를 실제 수신했다. 기존 주요 `guard_curve_rejected_toward_left`는 전체1회, 오른쪽1회였고 현재 재검사의0명령은3회다. 이번 주요 실패는 후반 경계 재확정이다. 원 trace SHA-256 `719d08fba983a429628318e560cc914eedfa86119033bcc39180eeafa1565d44`를 보존한다.

후속 [r215](../junction_stall_r215_v1/README.md)에서466전체 출력 재현과60.92–67.32초의 연속60개 `follow_boundary_unconfirmed`를 확인했다. 직전60.72초의 배열 예외가 경로 기억을 버리는 원인인지 [r216](../expiry_candidate_null_r216_v1/README.md)에서 별도 대조한다. 전체 랩·지속 주행·최종 간격은 미완료다.

최초 재시도 준비 시 기존 WSL 임시 namespace의 신원 검사가 중단했다. 일반 Ubuntu 진입이 정상인 것을 확인한 뒤 정상 `wsl -d Ubuntu-24.04` 경로로 실행했다. 배포판/컴퓨터/전원 설정을 재시작하거나 변경하지 않았다. r210의 간헐 입력 실패 원인을 특정한 것은 아니다.
