# 호스트 시계 짝 읽기 대조 r276

r275 C1의 `mapped_clock_overlap`를 재검토했다. SDK monotonic 점 간격은 이어졌지만 ROS−monotonic 대응값이 한 배열에서약0.58ms 커졌다가 돌아왔다. 센서 불연속이 아니라 두 시계의 대응에서 생긴 현상이다. 읽기 사이 스케줄링 지연이라는 원인 가설을 두었으며 과거 기록만으로 그 원인을 확정하지 않는다.

후보는 monotonic-before/ROS/monotonic-after를3회 읽어 가장 짧은 구간의 중간값을 쓴다. 모든 읽기와 선택/구간 반폭을 기록한다. 과거 offset으로 평활하거나 실제 clock step을 숨기지 않는다. 센서 시각·거리·각도·실제 겹침/미래·epoch 검사는 유지한다. 관련6검사가 PC/Jetson에서 통과했다.

| 같은20초 세 센서 결합 | r275 기존 읽기 | r276 짝 읽기 |
|---|---:|---:|
| raw C1 배열 |203|203|
| 준비 후 C1 발행/공통 수락 |162|183|
| 시계 대응 reset |1|0|
| C1 공통 점수 |82,532|93,256|
| IMU 공통 수락 |3,746|3,745|
| 카메라 발행/수신 |1,201/1,198|1,201/1,190|
| 영상 처리/채택 |196|196|

원문203배열을 재변환해 payload/진단/ready가 같고, 현재 epoch 내 겹침/발행 시 미래0·거리/각도 보존을 확인했다. 짝 읽기에서 선택 구간 중앙10.817µs·p9518.017µs·최대20.097µs, 선택 offset의 배열 간 변화 최대3.600µs다. 첫 읽기 구간만 사용하면 최대1.480ms였으므로 짧은 구간 선택의 역할을 실제로 관측했다. 이 구간 반폭은 **호스트 읽기 불확실성 일부**이며 실제 센서 취득/ROS 절대 시각 오차 상한이 아니다.

카메라11장 미수신은 보존한다. 영상196회 채택·처리p9542.68ms·header→채택p9580.00ms는 확인했지만 무손실/촬영 시각/검출 정확도 증명이 아니다. 실제 경로 계획 부하는 엔코더/장착 입력 부재로 실행하지 않았고 private1,301명령은 모두0이다. 네 자식/영상·계획 자식 정상 종료·포트 해제·센서 비활성, 원 소스 불변을 확인했다.

공통 브리지는 아직 이 후보를 사용하지 않는다. 새 공통 연결 때 기존 기본 입력/SDK 메타데이터와 원 시계 읽기 기록을 보존하고 실제 동일 기록을 재생한다. r275 원 실패는 덮어쓰지 않는다. 원 데이터 `build/r276_recovered/run`, 회수 SHA256 `3c66d5461b63e63a5623f1bd2f479e9df3f50d0e58b475f52f86816669fe1028`.
