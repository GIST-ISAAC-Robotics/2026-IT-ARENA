# 현재 영역 정책의 지연 교통 실행 r282

**미완주·접촉 실패다.** 80초 제한 교통에서 법정 코스 진행9.85m, 최장저속7.088초, 첫 상대 접촉71.765초였다. 원 접촉·겹침·간격·진행 실패를 보존한다. 차체/조향 외곽 노면 이탈0·바퀴 벽 이탈0, STOP·정상 종료·소스 불변·잔여 프로세스0을 확인했다. 단독/교통 완주나 실차 증명이 아니다.

r279와 같은 시설·두0.8m/s 각본 상대·ID20/30누락·native C1·81T/28카운트/65mm를 썼다. r281현재 영역 정책과 현재 검사 최소나이81.304613ms가 함께 바뀌었고 계획146.7455ms는 유지했다. 따라서 r279와의 주행 차이를 정책 하나의 효과로 단정하지 않는다. 현재 정책의 좁은 저속 공백 예외는 이번 궤적에서는 발동0회다.

- 실제 두 프로세스 계획548개·현재531개 저장 재생이 원 출력과 같았다. 양수 적용472개, 현재 검사 후0명령59개다.
- 현재 검사 후0사유는 `rebase_current_gap_hold`2회와 `route_current_large_motion_region_unobserved`57회다. 후자는80.044초부터 시작했다.
- 직선15–60초에는 현재 결과307개가 모두 양수였지만 차체 평균0.139573m/s·모터 환산 평균0.139593m/s였다. 보호층은 명령 만료473표본으로0을 보냈다. [r284 시간순 대조](../command_cadence_r284_v1/README.md)에서 반복 만료와 가속 기준 초기화를 분리했다. 후반 접촉·영역 거절은 별도 실패다.
- 실제 적용 간격 중앙147ms, 현재 검사 결과 나이82ms다. 이번 고정 최소 지연은 Jetson의 전체ROS/IPC/동시 센서 부하나 최악지연을 재현하지 않는다.

원 판정은 `two_actor_run1/combined_assessment.json`, 저장 재생은 `parallel_replay.json`, 원시 증거는 `two_actor_run1/run1/`에 있다. `motion_chain_audit.json`은 평가용 자세와 MCU 목표를 대조하며 정답 자세를 제어기에 넣지 않았다. `policy_application.json`의 빈 `counts`는 새 저속 예외 발동0을 뜻한다. `assess.py`의 기존 r248 stage 설명 문자열은 계획 단계에만 해당하며 현재 단계 출처는 `delivery_profile.json`의 r281 실측이다.

첫 spawn 검사에서 전부 양수인 표본을 고른 시험 전제 실패를 보존했고, 실제 거절/양수 혼합4개로 바꿔 동일성과 정상 종료를 확인한 뒤 주행했다. 같은 실패를 무변경 재실행하지 않는다. 공통/기본/실물 구동에는 이 후보를 채택하지 않았다.
