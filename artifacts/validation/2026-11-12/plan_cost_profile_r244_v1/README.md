# r244 Jetson 계획 계산 병목

r242는 부모 콜백의 계산을 옮기지만 계획 자체의100ms 초과를 없애지 않는다. 실제 Jetson에서 r225 저장632개 입력을 같은 순서로 재생하고, r232 계획 비용 상위40개와20개마다 하나의 균등 표본을 합친67개만 cProfile로 조사했다. ROS·센서 포트·모터 출력·전력 설정은 사용/변경하지 않았다.

첫 묶음은 하위 Python 패키지를 빠뜨려 import에서 실패했다. [attempt1](attempt1/profile.log)에 보존하고, 재귀 소스 목록을 포함한 별도 worktree_v2에서 다시 수행했다. 두 번째 소스176개와 입력은 바이트 불변이다.

[결과](result/report.json)는632개 처리·67개 계측이다. 과거 PC 기록과 전체 진단45개가 달라 엄격 동일성 실패를 그대로 남겼다. [별도 차이 감사](result/output_audit.json)에서 속도/조향 명령632개 차이0, 차이는 이동 영역의 질의/좌우 마스크 표본 개수였다. 이전 Jetson 대조에서도 비슷한 진단 차이가 있었으나 이번 원인을 특정 라이브러리나 반올림 하나로 확정하지 않는다. 향후 후보의 동등성은 같은 Jetson 기준선과도 직접 대조한다.

67개 계측의 누적15.165초 중 `depth_support`2.721초(내부 evaluate1.868초), `polygon_distance`1.735초, 원천 광선 `_geometry`1.234초가 관측됐다. 이 값은 cProfile 오버헤드와 상위비용 표본 편향을 포함하며 평균 주행 비용이나 서로 더할 수 있는 독립 단계가 아니다. [전체 함수 집계](result/functions.json)·[호출별 기록](result/durations.json).

우선 좁은 수치 커널을 별도 후보로 비교할 근거가 생겼다. 광선 지지의 선택·동률·원점/깊이 경계를 유지한 네이티브 계산이 후보이며, 판정이나 광선 수를 줄이는 방법은 채택하지 않는다. 성능과 같은 입력 동등성이 확인되기 전 공통 런타임에 연결하지 않는다. 이번 조사는 함수별 비용 진단이며10Hz 달성·실차 운용의 증거가 아니다.
