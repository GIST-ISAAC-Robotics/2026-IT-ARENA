# r242 현재 재검사를 같은 자식 계산으로 연결

r235/236에서 비교한 두 단계와 완료 알림을 공통 노드의 명시 옵션 `g1_current_recheck_execution:=worker_event_v1`으로 연결했다. 기본은 `parent` 그대로다. 이 옵션은 `process_candidate`·`fresh_native_v1`·`selected_v1`·`selected_r181` 조합과 기존 시뮬레이션 전용50Hz 부모 조건을 요구한다.

부모 ROS는 입력과 명령 발행을 소유하고, 기존 자식 한 개가 계획 뒤 현재 재검사를 순차 계산한다. 완료 알림 스레드는 pipe를 읽거나 판단하지 않는다. ROS guard 콜백이 결과를 회수한 뒤 기존 `control()` 전체 경로로 들어간다. 입력이 불량해 명령 함수가 호출되지 않아도 완료 pipe는 비워 반복 깨움을 막는다.

반환 시 원 계획/현재 검사 각각의 취득시각·기준시각·센서/운동 세대·마지막 발행 조향·벽 선택을 확인한다. STOP/RESET은 두 단계와 준비 결과를 폐기한다. 원 경로 시각을 새 시각으로 덮지 않고 현재 재검사 입력/결과를 별도로 기록한다. `last_application`은 실제 발행 뒤에만 갱신하고, 대기 콜백은 명령 수명을 연장하지 않는다. `/drive`→독립 보호층→`/drive/safe`는 유지한다.

## 검증

- [경계·실제 자식·노드·기존 옵션 회귀](boundary_tests.log): **65개 통과**. 실제 자식 계획/재검사 중 STOP 세대 취소20회, 입력 소유권·한 번 사용, 원천 만료·조향/벽/세대 변경, 실제 ROS 노드 disable/reset/종료를 포함한다. 기존 옵션 OFF473개 전체 출력/기록 동일과 이전 현재 재검사193개도 대조했다.
- [노드 연결 검사](node_methods_tests.log): **5개 통과**. 현재 결과를 부모에서 다시 계산하지 않고 원문/기준시각을 연결하며, 계획 완료만으로는 명령을 발행하지 않는다. 알림 콜백은 정상 제어 경로를 통과하고 예외 때도 ACK한다.
- 초기 순수 경계39개는 [initial_tests.log](initial_tests.log)에 보존한다. 위65개와 중복이 있어 합산하지 않는다.

- [출처 계보 검사](provenance_tests.log):211개 통과. 과거 소스/실패를 보존하고 [r242 계약](../../../../config/tests/recheck_delivery_r242_sha256.json)으로 변경 바이트를 연결했다.
- [빌드](build.log):`arena_vehicle_interface`·`arena_autonomy`·`arena_bringup` 세 패키지 성공. 설치 환경에서 새 자식/알림 모듈이 현재 소스로 해석되고 [launch 인자](launch_args.txt)에 명시 옵션이 있는 것을 확인했다.

[r243 제한 주행](../recheck_delivery_runtime_r243_v1/README.md)은63.90m·최장저속0.503초·접촉/노면 이탈0·STOP/정상 종료·810계획/797현재 검사 동일 재생으로 대표를 마쳤다. 이 문서는 실행 연결과 회귀의 근거이며 Jetson 실시간 운용이나 실차 구동을 완료했다는 뜻이 아니다. r236의 별도 비교 프로그램에서 얻은 비용을 이 실제 노드의 성능으로 대체하지 않는다.
