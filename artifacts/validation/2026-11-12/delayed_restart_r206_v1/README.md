# 현재 선택 구성의 지연 정지·재출발 대표

실행 전 등록: 과거 r63의 시설 앞18초 각본(앞차0.50m/s,3–8초 정지,이후 재출발)과 원 목표 평가를 유지한다. 현재 r203의 native C1·81T 감속비·공통 선택 정책/현재 재검사/새 회전 제출·r202 기본 OFF 공백 보완을 명시하고 같은 지연 표본을 사용한다. 현재 selected medium_v1 profile을 적용하므로, 과거 균일 스캔/구동비/slow profile/r63와 단일 수정의 개선율을 비교하는 시험은 아니다.

앞차 재출발 뒤2.5초 내 재개·그 뒤1m 이상 진행·마지막2초0.5m 이상 진행·FOLLOW 복귀, 기존 간격/접촉/노면/STOP/종료 조건을 바꾸지 않는다. 시설 형상과 ID20/30 누락을 유지한다. 원 report와 별도 목표 판정을 모두 보존한다. 오목면 반환 증명은 과거 대표를 유지하며 이번에는 새 형상 검출을 통과시키는 목적을 추가하지 않는다. 원 상대 충돌 기하 보존은 확인한다.

PC/WSL에서1회 실행한다. Jetson/실물 모터 구동은 없다. 현재 지연 교통 r203의30.68m/10.484초 미완주와 곡선 측방 정체는 해결 처리하지 않는다. 정답 자세/각본은 평가 전용이다. 실패하면 원 증거와 원인을 남기고 이유 없이 반복하지 않는다.


## 실행 준비 보완

r205는 prefix 보조 두 파일 누락으로 노드 기동 전 실패했다. 이번에는 r203의 `delay_worker.py`·`expiry_worker.py`를 바이트 그대로 포함한다. 실제 ROS 환경에서 entry/평가기 import와 지연 profile을 먼저 확인한다. 주행 소스·사례·시설·속도/노면/STOP/목표 조건은 r205 등록과 같다. 첫 실행의 원 실패는 r205에 보존하며 새 주행을 완료했다고 쓰지 않는다.

## 결과

기존 우회 허용 재출발 목표와 이번 연결/시설 종합 검사는 **통과**했다. 총5.651m, 앞차 재출발 뒤2.401초에 재개해3.583m를 추가 진행했고 마지막 FOLLOW로 복귀했다. 마지막2초 진행1.345m·최소속도0.642m/s, 재출발 이후 최장 정지0.914초다. 재개 지연은 원2.5초 기준에 가까우므로 여유가 충분하다고 설명하지 않는다.

표본/스윕 최소 간격0.824298/0.824203m, 접촉·시설 겹침·마지막 차체 노면 이탈0이다. STOP 변위0.072971m·안정 도달·정상 종료·잔류 프로세스0·소스/스냅샷/원 native 배열·지연 전달 검사를 확인했다. 모터 구동이나 실제 차량 시험은 아니다.

**원 report는 실패로 보존한다.** 원 추종 평가의 HOLD·최종 간격 조건은 실패했고, 기존 우회 허용 목표가 별도로 통과한 것이다. 이 구분은 시험 전부터 사용하던 `goal_eval.py`의 기준이며 이번 결과에 맞춰 바꾸지 않았다. 지연 교통 r203 전체 랩 실패와 코너 병렬 미완료도 그대로다. 실제 비용 표본은 이전 저장 궤적의 지연 하한으로, 전체 Jetson/실물 지연을 재현한 것은 아니다.
