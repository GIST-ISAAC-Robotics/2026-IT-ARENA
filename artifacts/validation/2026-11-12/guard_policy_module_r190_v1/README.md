# 기존 관측·저속 정책의 공통 선택 이관

11/12 GPT가 PC에서 수행했다. 새 정책을 만들지 않고 r136/r139/r148/r149/r178/r181의 검사 순서·조건·반환을 `guard_observation_policy.py`로 옮겼다. r176에서 이미 이관한 순수 기하 검사 두 개를 재사용한다. 운영 코드의 artifact import와 전역 monkey patch 없이 `FollowConfig.guard_observation_policy`의 `original_v1`(기본)/`selected_r181`로 인스턴스별 선택한다.

새 ROS 인자/launch와 현재 재계산의 r181 저속 재시도는 아직 연결하지 않았다. r186의 최근 경로 참조 보존·평가 지연도 이번 공통 모듈 밖이다. 미완주 후보를 기본 활성화하거나 실차에 배포하지 않았다.

## 동등성과 검사

- 원 소스 두 파일을 ZIP으로 보존하고 별도 프로세스의 원 라이브러리와 수정 라이브러리를 비교했다.
- 기본 정책: r187 저장473판단의 전체 출력 SHA256 동일.
- 선택 정책: r182 439판단·r187 473판단에서 원 prefix와 공통 모듈의 전체 출력 SHA256 동일. 실제 기록 출력과도 불일치0이다. r187의 참조 보존 후보는 양쪽 비교에 같은 보존본을 사용했다.
- 관련 검사 최초265통과/1실패. 실패는 새 격리 테스트에서 자리 인자를 하나 더 넣은 테스트 오류였고, 인자 수 수정 뒤 해당 파일13개를 모두 통과했다(중복을 제외한 관련266개). 실제속도 유지·측방 이력·현재 관측 요구와 인스턴스별 정책 격리를 확인했다. 초기 `tests.log`를 보존한다.
- 전체 소스 계보198검사를 통과했다(`provenance.log`).

`equivalence.json`, `before_*.json`, `after_*.json`, `before.log`, `after.log`, `tests_fixed.log`와 `config/tests/guard_policy_r190_sha256.json`이 근거다. 상세 출력은 Git 제외 `build/r190_*.jsonl`에 저장했다. 새 Gazebo 주행·실물 구동은 없었다.

다음은 같은 명시 선택을 ROS 설정과 spawn된 계산에 전달하고 현재 재검사와 연결하는 단계다. 실제 장치에 전달하기 전에 PC의 실제 노드 STOP/RESET·기본 OFF 동등성·선택 ON 저장 결과를 확인한다. 지연 교통 완주 실패와 갈림길 미확인은 그대로다.
