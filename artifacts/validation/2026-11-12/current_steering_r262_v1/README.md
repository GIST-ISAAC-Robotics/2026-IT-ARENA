# r262 계산 도중 바뀐 직전 요청각의 현재 재검사

계획과 현재 확인을 겹치면 다음 계획 계산 중 이전 명령이 적용될 수 있다. 원 함수는 직전 요청각이 조금이라도 달라지면 모두0을 반환한다. 후보는 이 동등성 조건 대신 **현재 실제 마지막 발행 요청각**으로 조향 변화율, 현재 점군 swept clearance와 각 상태의 측방/관측 검사를 다시 계산한다. 원 제출 입력을 바꾸거나 같았다고 꾸미지 않는다. 과거 경로 시각/수명·이력·epoch·side·속도 상한과 전체 세부 검사, 독립 보호 필요 조건을 유지한다.

현재 후보는 `candidate_recheck`/`candidate_policy.py`에만 있으며 공통 코드/ROS에는 미연결이다. 함수 자체는 발행 허가가 아니며 실제 연결에서는 현재 검사 중 다시 바뀐 요청각, STOP 세대, 완료 시 나이와 발행 간격도 검증해야 한다.

- 기존 요청각592개: 원 구현과 전체 출력 동일.
- ±0.04rad 저장 입력 민감도148개:130개는 현재 검사 후보,18개는 측방 운동 한계/새 측방 관측으로0. 새 폐루프나 성공률이 아니다.
- 관련60검사: 여섯 상태의 동일 출력·현재 요청각 변화·epoch/side/경로 만료/미검증 시계/각도 범위·전방 접촉·0명령 유지.
- 첫 테스트2개는 전방 반환을0.05m로 주입했으나 실제 float 범위 하한0.050000000745m보다 작아 unknown이었다. 원 실패는 `test_attempt1.log`에 보존하고 유효 반환 하한+0.01m로 수정한 뒤 통과했다. unknown의 임의 반환 변환이나 제어 판정선 수정이 아니다.

다음은 두 계산 프로세스의 입력 소유권·완료 순서·STOP 무효화와 현재 적용 관문을 검증하는 것이다. 병렬화 비용/실주행은 아직 확인하지 않았다.
