# r235 — 같은 계획 자식에서 현재 재검사 수행

[자문·설계 검토](../../../../docs/reports/JETSON_RECHECK_ADVISORY_2026_11_12.md)에 따른 **미연결 비교 후보**다. 공통 계획/기하 코드는 그대로 두고 별도 `TwoStageProcess`가 plan→현재 snapshot의 recheck를 같은 자식에서 순서대로 수행한다. 부모는 불변 snapshot 바이트와 generation/sequence/stage를 관리한다. STOP/RESET 이전 결과를 폐기하며 같은 계획의 재검사는1회다. 완료 시각을 명령 시각으로 쓰지 않는다.

PC의 실제 자식 세대/STOP·입력 소유권·단일 사용 **22검사 통과**, ROS20판단 점검도 명령/전체 출력 동일·387/387 합성 IMU 수신·정상 종료였다. [protocol.log](protocol.log), [PC 결과](pc_smoke_two_stage/report.json).

## Jetson 같은 입력 대조

r225의632계획·592재검사와200Hz 합성 IMU를 사용했다. 두 실행의 **전체 출력이 서로 일치**했고 속도·조향·사유·reference 차이0이다. 원 r225 대비54건의 질의 표본 수 차이는 양쪽에 동일하게 남았다. 손실/중복0, 동결 소스 불변, 자식 정상 종료를 확인했다. [독립 비교](comparison.json), [비교기](compare_results.py).

**수신 p95는 개선됐지만 그대로 채택하지 않았다.** 부모가 다음20ms 타이머에서 결과를 회수하면서 재검사 대기 중앙값이약24.6ms 늘었다. 계획 자체의100ms 초과도 남는다. 완료 알림으로 회수를 깨우는 후속 r236에서 이 손실을 확인한다. 200ms대 수신 최대값은 후보의 부모 콜백 최대8.71ms보다 크다. GC/스케줄링 등 다른 구간 가능성이 있어 후속에서 계측하며 원인을 아직 확정하지 않는다.

읽기 전용 부하 표본에서 CPU 온도 최대48.53/49.06°C, swap0, GPU0%였다. CPU 일부 코어1728MHz를 관측했고 전력/클럭을 변경하지 않았다. 이 표본만으로 모든 부하의 열 제한 부재를 단정하지 않는다.
