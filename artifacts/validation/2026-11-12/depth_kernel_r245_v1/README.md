# r245 광선 지지 수치 커널 비교

r244에서 비용이 컸던 `depth_support` 내부 evaluate만 C++로 옮긴 별도 후보다. 원 각도 창·광선 순서·동률 우선순위·원점1e-9m·각도/인접/반환/패딩 경계는 유지한다. 공통 패키지 파일과 기본 실행은 바꾸지 않았다. `candidate.py`는 원 함수에서 내부 evaluate만 치환한 사본이며 원본/사본 해시는 [candidate_source.json](candidate_source.json)에 남겼다.

빌드는 `g++ -O3 -fPIC -shared -std=c++17 -ffp-contract=off -fno-fast-math depth.cpp -o libdepth.so`다. 아키텍처별 바이너리는 Git에서 제외하고 소스를 보존한다. 자동 빌드·동적 기본 선택은 없다.

PC의20개 경계 비교를 통과했다. 이동 원점·무응답·NaN·원점/각도/깊이 경계·순환 인접·동률·512개 묶음 경계와 입력 불변을 포함한다. 처음 두 테스트는 rear mask가 있는 fixture의 빈 hit를 거리로 읽어 실패했으며 [첫 로그](unit_tests_attempt1.log)를 남기고 해당 fixture를 전방/후방이 실제 반환하는 조건으로 바로잡았다. 후보 계산 실패를 숨기거나 경계를 완화한 것이 아니다.

Jetson에서도20개 단위 검사를 통과했다. 두 독립 제어기 상태에 같은632개 입력을 순서대로 넣고 원래/후보의 실행 순서를 번갈아 비교했으며, **전체 출력/명령 차이0**이다. [결과](jetson/result/report.json). 과거 PC와의 진단45차이는 기준선에도 그대로 남았고 후보 대조에서 지우지 않았다.

계획 비용 중앙123.267→113.020ms(약8.3% 감소),p95 183.191→150.802ms(약17.7% 감소),평균112.040→105.226ms다.100ms 초과는400→390/632로 처리율 부족이 여전히 크다. ROS/영상/실물 센서 동시 부하 없는 같은 Jetson 교차 실행1회다. 기본 성능 확보나 실차 적용 완료가 아니며, 네이티브 배포 의존성/전체 결합 검증 전에는 공통 런타임에 연결하지 않는다.
