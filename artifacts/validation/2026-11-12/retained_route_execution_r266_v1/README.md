# r266 이미 사용한 경로의 현재 재검사 실행 후보

공통/기본/ROS 제어에는 연결하지 않은 시험 구현이다. 계획과 현재 확인의 두 실제 프로세스는 r264를 사용하고, 경로 확인은 r265에서 출발했다. 실제 `/drive` 발행 뒤 호출자가 확인해야 하는 `commit_published` 이전에는 경로를 보조로 보관하지 않는다. 이 시험의 호출자는 ROS 대신 파일에 명령을 기록하므로 실제 차량/시뮬 발행 증거는 아니다.

새 계획을 우선하며 같은 회수에서 새 계획과 옛 현재 검사가 함께 끝나면 새 계획 전이를 먼저 처리한다. 새 0/미지원 상태·명시 STOP·epoch 변경 뒤 옛 양수 경로를 되살리지 않는다. 보조 검사 실패는 새로운 양수/0 명령을 만들지 않으며 기존 명령 시각도 갱신하지 않는다. 현재 관측·운동·실제 직전 요청각을 재검사한다. 새 계획은 보조 검사가 이미 사용한 스캔도 사용할 수 있고, 같은 경로의 같은 스캔은 반복 검사하지 않는다.

## 명시적으로 달라진 정책

최초 400ms 기하 후보는 검사 성공 뒤 100ms 발행 간격을 기다리다가 만료되어 보조 양수 발행0이었다. 10Hz 최초점~수신 약117ms, 계획147ms·현재 확인34~47ms와 다음 발행 주기를 포함해 **기하 나이 상한500ms인 별도 후보**를 비교했다. 원 경로 시각/epoch·모든 새 관측 시각은 그대로이며, 현재 raw300ms·명령200ms·최대 기하 이관0.45m·점유/측방/정지 조건은 유지한다. 모든 양수 현재 검사에 현재 진행/제동 영역 증거를 새로 요구한다. 500ms는 실물 검증된 허용치나 기존 경로 TTL 유지가 아니다. 기본 채택은 하지 않았다.

## PC 결과와 실패 보존

- 실제 두 프로세스14검사 통과: 발행 전 보관 금지, 단일 적용, 새 0/새 계획 우선, 검사 뒤 상태 변경, 두 진행 작업 중 STOP, 같은 스캔의 새 경로 우선, 발행 대기 중 만료.
- 첫 시간 재생은 r225의 기록된 계획 입력을 사용했지만 3초 이후 200ms 간격이 있어 10Hz 센서 입력 대조가 아니었다. `pc_*` 원 결과/실패를 보존하고 dense 결과와 합산하지 않는다. 이후 r243의 첫15초 **최대 입력 간격100ms**를 확인했다.
- dense PC 고정147/34ms 최소 계산 시간: 보조OFF 양수71회·발행 간격 중앙200.08ms, 후보 최종판 양수138회(보조67)·중앙100.84ms·p95 101.83ms. 계산 자체가 빨라졌다는 뜻이 아니다.
- 원 명령 시각부터 다음 발행까지200ms를 넘은 시간 합계는6.157→2.190초다. 여전히 만료가 남는다. 이는 저장된100ms 간격 운동/입력 기준이며 실제50Hz 부모의 최신 운동 이력·ROS/독립 보호·주행 반응을 재현하지 않는다.
- v2 재생기의 같은 콜백 발행 뒤 요청각 갱신 누락을 고쳤다. 수정 전 `dense_retained` 결과는 보존하고 최종 `dense_retained_v3`로 대체 해석한다. 새 경로가 도착해 폐기한 보조 결과를 적용 성공으로 세지 않는다.

`source_before_revision/`은 400ms/원 제출 규칙의 소스 보관본이다. `source_manifest.json`은 최종 후보와 Jetson 전달에 사용한 원문 부분 기록의 해시를 담는다. 기존 공통 소스/과거 원시 실패는 바꾸지 않았다. 
## Jetson 실제 비용 대조: 미채택

추가 고정 지연 없이 같은15초 저장 입력을 실행했다. 보조OFF→ON 양수103→94개(ON 중보조12개), 갱신 중앙102.86→145.71ms·p95 205.07→191.42ms·최대500.61→1,115.40ms였다. 원 시각의 만료 시간 합계8.467→7.467초는 줄었지만 계획 제출121→105개와 실제 양수 갱신이 줄고 최장 공백이 늘었다. 일부 지표만 골라 개선이라고 채택하지 않는다.

ON에서는 새 계획 때문에 현재 검사64개가 폐기됐다. 새 계획을 기다리는 동안 무조건 보조 검사를 추가하는 방식이 실제 비용/일정에서 유리하지 않았다. 후속에는 새 계획 완료 예상과 다음 명령 시한을 함께 보고 꼭 필요한 보조만 제출할지 비교해야 한다. 아직 그 개선을 구현하거나 주행한 것은 아니다.

PC/Jetson 각14검사, 전달 원문 부분의 바이트/소스241개(기존226+신규15) 불변, 두 자식 정상 종료와 잔여 프로세스 없음을 확인했다. Jetson 센서/장치·펌웨어·모터·전력 설정을 건드리지 않았다. 회수 ZIP SHA256 `e136845fb602641afa5b07eb1a13830227e3309abb2a792d0229836849789d1d`.


후속은 불필요한 보조 제출을 줄인 뒤 실제50Hz 현재 이력·명령 발행·독립 보호/STOP을 거친 제한 실행 연결이다. 이 결과만으로 r253 교통 실패 해결이나 실차 운용 가능을 선언하지 않는다. 조립 전 실물 시간 계약 준비도 병행하며 미세 후보 개선만 계속하지 않는다.
