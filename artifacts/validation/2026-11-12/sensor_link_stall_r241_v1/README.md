# r241 — ROS 처리350 ms 정지 중 실제 UART 원문 보존

[r240](../sensor_link_ingress_r240_v1/README.md)의 같은 펌웨어/브리지에 시험 wrapper만 적용했다. ROS 소유자에 한 번 **350.696 ms sleep**을 넣었으며 I/O 작업은 계속 읽는다. GIL을 놓는 지연이므로 GIL 전체/OS/USB 정지를 재현한 시험은 아니다. 판정선·센서 주기·MCU 임대·데이터 시각은 바꾸지 않았다.

- 원문 **11,973개·순번 공백0·CRC0·SPI/송신 큐/FIFO 오류0**. 공통 입력 **3,901/3,901·거부0**.
- 큐 최고 **117/512개**, 포화0, 최대 큐 지연348.94 ms. 원 읽기 시각을 유지하여 callback 나이 최대351.78 ms로 지연이 그대로 드러났다. 지연 데이터를 즉시 주행에 써도 된다는 의미가 아니다.
- gyro 표본 시각 최대 간격7.01 ms. 독립 원문·저장 행·ROS 값/시각 대조 통과.
- ARM/CLEAR 거부·STOP 응답3개·DRIVE0·가짜 엔코더 없음. 서비스 시험은 주입 전이며 지연 중 STOP 왕복을 증명하지 않는다.
- 자식 세 프로세스 정상 종료, 원 IMU 앱 복구와 readback 일치·포트 소유자 없음.

이 결과로 한 UART의 실제 IMU/출력 비활성 명령 응답 통합은 제한 대표를 확보했다. 최초 r239의 손실 원본을 지우거나 모든 호스트 지연이 해결됐다고 확대하지 않는다. 원천시각 교정·운영 구동/엔코더·전체 제어와 주행은 후속이다. 새 유사 스트레스 반복보다 다른 P0 연결/실행 지연 작업으로 이어간다.

근거: `injected_stall.json`, `audit.json`, 브리지/수신/정리·복구 요약과 업로드/소스 명세. 독립 검토는 [r240 audit.py](../sensor_link_ingress_r240_v1/audit.py)를 같은 원문에 적용했다. Git 제외 `build/r241_results_private.zip` SHA256 `e1b7cb5fc502c4cb9d2633b297a00d6a8394c4fbba35e17d96728dde5a1025f8`.
