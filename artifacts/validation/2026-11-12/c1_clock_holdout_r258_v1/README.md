# r258 C1 표본 시계의 과거 학습·이후 구간 대조

기존 `SDK 첫 시각 + 200μs×번호`는 r249/r251에서 수신 이후로 추정되는 끝점과 배치 중첩을 만들었다. r213의 이전 배치 간격 평균과 달리, 이번에는 **처음20회전으로만** 표본 카운터와 SDK 앵커의 일정한 시계 배율/offset을 추정한 뒤 나머지183회전에는 고정했다. 이후 데이터를 보고 계수를 다시 맞추거나 원 시각을 덮어쓰지 않았다.

| 저장 구간 | 추정 점 간격 | 이후 SDK 앵커 잔차 범위 | 기존/후보 수신 후 끝점 배치 | 후보 최대 미래량 |
|---|---:|---:|---:|---:|
| r249 |196.074μs|−0.053~2.532ms|136/0|미래 없음 |
| r251 |196.105μs|−2.289~2.405ms|125/14|0.671ms |

후보끼리의 배치 중첩은 모두0이다. 다만 일정한 표본 시계라는 가정으로 시간을 구성했으므로 중첩0이 실제 취득 정확도를 증명하지 않는다. SDK 앵커도 호스트 디코딩 시각의 추정이고, 최소 전송 지연·회전 누락·온도에 따른 배율 변동은 미분리다. 실제 회전/이동 시 보정 정확도는 아직 시험하지 않았다.

새 후보는 작은 미래량을 현재 시각으로 잘라 맞추기보다 해당 추정 시각까지 짧게 기다려 전달할 수 있다. 큰 잔차/회전 단절에서는 시계 세대를 분리해야 한다. 이 후속은 **구동 없는 관측용 추정 정책**으로 검토하며 `unverified_estimate`를 유지한다. 운영 `timing_verified`를 켜거나 계수를 센서 교정값으로 채택하지 않았다. 원 입력 SHA와 세부 잔차는 `report.json`/`*_rows.json`에 둔다.
