# 옆차 관측 GUARD 현재 재계산의 제한 주행

2026-11-12 실행 전 등록. **Jetson 접근 없이 LOCALHOST 격리 ROS/Gazebo에서만 수행한다.**

r168의21.51m·7.957초 실패 뒤 새 원인 근거가 있어 한 번 비교한다. 원 계획기·독립 보호·차량·81T 감속비·센서·노면/접촉/정지 기준은 유지하고, r170의 현재 GUARD 재검사만 r168 적용 범위에 추가한다. 실제속도가 목표보다 큰 감속 중에도 실제속도로 이동 영역을 검사하며, 음수 피드백은 기존 `forward_drive` 정책으로 계획 속력만 해석한다. 부호 있는 운동 이력·원 경로 시각·TTL·옆차 이력은 보존한다.

저장105개에서 현재104개/+20ms103개의 양수 재계산, +40ms105개 운동 이력 만료 거절을 확인했다. 새 쪽 반환과 현재 관측되지 않은 접근은 거절했다. 관련15개 후보 검사와 기존 GUARD/음수 피드백을 포함한 WSL97회귀를 통과했다. 초기 테스트 설정의 종속 옵션 누락2회는 r170 로그에 남겼고 운영 코드를 바꾸지 않았다.

`run.py`는 같은60초 두0.8m/s 앞차·시설·ID20/30 누락·C1 native10Hz·계획0.1초/수신50Hz·이전 Jetson 비용 지연 하한을 사용한다. 새 Jetson 비용 시험이 아니며 현재 재계산의 추가 연산 여유도 실물 미확인이다. 소스/설정을 보존하고 명시 STOP·정상 종료까지 평가한다. 동일 실패를 원인 변경 없이 반복하지 않는다.

## 결과

60초 대표는 **20.27m·최장저속10.772초로 미완주**다. 접촉/겹침/바퀴 노면 이탈0·STOP/정상 종료·입력/소스 불변·시험 프로세스0을 확인했다. 원 최종간격·장기 정체 실패는 보존한다. [통합 평가](two_actor_run1/combined_assessment.json)·[상태별 진단](diagnosis.json).

현재 관측 GUARD 재계산은25회 진행을 허가했지만, `RELEASED/parallel`166개는 적용 대상 밖이었다. 따라서 r170을 연결한 것만으로 지속 주행이 개선됐다고 하지 않는다. 양수 상태 전체를 대조해 누락을 분리했고 r173에서 기존 차로 유지·횡변위 제한을 재사용하는 저장 후보를 준비했다. 원 계획기·독립 보호는 유지했으며, 센서 제출 기준 시각은 이번 원천 스캔 시작보다0.107초 뒤였다(r168은0.118초). 단일 비교의 차이를 한 수정의 효과로 단정하지 않는다.

원 시험의 소스/ZIP은 보존했다. 이후 공통 `threat_view`의 미사용 격자 생략 r172를 별도 적용했으며, r171에 적용됐다고 소급하지 않는다.
