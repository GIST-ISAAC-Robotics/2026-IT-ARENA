# r270 선택형 C1 추적 시계의 공통 연결

기존 `--scan-clock sdk_nominal`이 기본이다. 선택형 `tracking`은 r260의10Hz Standard 후보를 공통 모듈로 옮겼으며, 준비20스캔·과거100스캔 추적·10스캔마다 재추정한다. 거리/각도/원천 순서/무반환 표현을 유지한다. 미래 끝 점은 최대5ms 기다릴 수 있고, 그 이상이나 시계/순번 불연속은 새 epoch의 준비 단계로 돌아간다. 이 수치는 실제 센서의 절대 시각 오차 한계가 아니다.

## 저장 입력·회귀

- 관련63검사 통과. epoch 재시작·시계 뒤로 이동·발행 전 시계 변경·준비/미래 대기·원천 데이터 보존을 포함한다.
- 직전r269 raw203배열을 다시 계산해 과거r260 후보의 모든 payload/ready 시각이 같았다.20준비 이후183배열에서 거리/각도는 원문과 같고 스캔 간 겹침은 없었다. PC 변환 비용 p50 0.460/p95 0.849/max0.895ms.
- 앞선r260 파일은 그대로 보존한다. 공통 이관에서는 거절 시 diagnostic epoch가 변경된 실제 epoch와 같도록 고쳤다.
- `config/tests/c1_tracking_r270_sha256.json`으로 r269 출처를 이어 보존했다. 이전/새 계약2검사 통과.

## 실제 Jetson20초

C1 raw203배열 중 준비20개 이후 **183배열·93,212점**을 ROS 공통 decoder와 비구동 노드에서 모두 수락했다. 점수500~524/중앙508, 추정 점 간격196.028~196.090µs다. 같은 raw의 nominal200µs 계산은 겹침200배열/최대3.904ms·미래117배열/최대2.451ms였고, tracking 발행 기록에서는 **겹침0·발행 시점보다 미래0**이었다. 이 구간은 별도 대기 필요0이며 수신→발행 최대9.419ms에는 변환/스케줄링 비용이 포함된다.

`audit.py`가203개 원문을 독립 재변환해 payload/진단/발행 준비 시각을 대조했다. 전체 스캔의 거리/각도·무반환/무효 구분은 그대로다. 같은 시험에서 FIFO IMU3,794개를 수락했고 private 출력1,297개는 모두0이었다. 장착 전 좌표·엔코더0·카메라 없음이므로 전체 제어 계산/실제 주행 증명이 아니다. `time_contract_verified=false`와 `unverified_estimate`를 유지한다.

세 자식 정상 종료·C1 정지 확인·IMU 비활성·포트 해제·전달 소스 불변을 확인했다. 펌웨어·RPM·전력·구동은 바꾸지 않았다. 원문은 Git 제외 `build/r270_recovered/run`에 보존한다. 회수 ZIP SHA256: `eb45cb7df60f7bbac5d5dcf6e4e9beacd0877e130b978059d953f5b6cd9ce3c2`.

실제 취득 시각 정확도·움직이는 장착 상태에서 deskew 검증·실물 운영 제어는 남는다. 이번에는 내부 시간 일관성/공통 수신 대표를 마치고 P0 실행 지연의 불필요한 보조 검사 제출 문제로 돌아간다.
