# 만료 명령과 갈림길 관측 참조 분리 후보

2026-11-12 저장 대조 전 등록. 실제 실행 연결/Jetson 접근/새 주행 없음.

r185의 최근 경로만 보존한 대안은439원 판단 동일 재현 뒤90개 결과를 바꿨으나, 문제의60.22초부터 다시 왼쪽 대각 벽을 선택해 실패 원인을 해결하지 못했다. 가까운 경로 일부가 일치한다는 비교만으로는 갈림길 방향을 유지하지 못한다.

이번 후보는 **source 만료로 폐기한 결과**에서 이전 관측 참조·선택 벽·epoch/선호 벽/시각만 기록한다. 원 reset은 그대로 수행해 경로 허가·옆차 상태·운영 상태를 버린다. 다음 충분한 현재 경계를 비교할 때만 기존0.6초 최근 참조 창과 운동 이동 한도 안에서 사용한다. 다른 벽으로 바뀌면 기존 `path_agrees_arc` 전방 일치를 추가 요구한다. 현재 같은 벽의 경계를 얻지 못하면 새 허가를 만들지 않는다.

명시 STOP/RESET·시계/epoch/선호 벽 변경은 보존 조건이 아니다. TTL·미관측·물성·간격·참조의 원 시각은 그대로다. 그림/지도/상대 정답은 제어 입력에 쓰지 않는다. 현재는 Python method를 별도 실험 프로세스 안에서만 바꾸며 공통 소스/기본값은 수정하지 않는다.

## 결과

처음 코드 생성에서 들여쓰기 오류가 나 시험이 시작되지 않았으며 `compare.log`로 보존했다. 이를 고친 v1은 원439판단 동일/90개 변경이었지만,60.22초에 한 번 오른쪽을 고른 뒤 다음 최근 참조 갱신에서 벽 정보가 다시 빠져60.42초부터 왼쪽을 선택했다. 이 결과는 미채택이다.

v2는 최근 참조 자체를 `(path, reference_time, source_time, selected_wall)`로 함께 저장한다. 이 형식은 source 결과 폐기 직후뿐 아니라 기존 경로 TTL이 지나 현재 관측을 다시 비교하는 일반 최근 참조에도 적용한다. 따라서 v2의 전체 변경을 폐기5회만의 효과로 보지는 않는다. 원439판단을 다시 동일 재현한 뒤117개 결과가 바뀌었고,60.22–62.12초의 대표에서 오른쪽 본선 벽을 유지했다. 당시 이미 이탈해 있던 저장 차체 자세의62.72초 이후에는 경계를 재확정하지 못해0명령이 나왔다. 저장 입력의 조향 변경을 실제 궤적 성공으로 해석하지 않는다.
