# 작은 장착 가림 인접 공백 후보의 Jetson 계산 비용

2026-11-12 진행 중. r149의 저장 입력 개선을 실제 주행에 연결하기 전, 동일 r143 입력465개에 baseline과 후보를 각각 한 번 적용한다. 순서·reset·상태 누적을 유지하고 전체 출력과 비용을 분리한다. 입력 복원·투영·판단 비용을 따로 기록하며 JSON 파싱/기대 출력 비교는 측정에서 제외한다. 센서·ROS·차량 출력에 접근하지 않는 CPU 전용 시험이다.

첫 Windows 준비는 baseline 출력 불일치로 중단했다. Windows 분석용 NumPy가 2차원 벡터 cross 연산을 거절하여 일부 입력이 `follow_input_stop`으로 바뀌었다. 명령이 모두 같다는 성공으로 처리하지 않았다. `windows_baseline_failed.jsonl`과 로컬 `build/r150_pc.log`에 보존한다. 실제 대상인 Linux/WSL 기준 출력 확인으로 이어가며 이 환경 실패를 주행 후보의 효과로 해석하지 않는다.

WSL에서는 baseline465판단이 원 기록과 모두 일치했고 후보465판단의 기대 출력을 별도로 동결했다. 전체 비용 중앙은28.93→46.80 ms, p95는48.22→59.54 ms였다. 후보의 낮은 목표 재검사216개 중앙은53.75 ms다. [PC 결과](pc_wsl_summary.json). 새 검사에 비용이 추가된 것이므로 기능 개선만으로 처리율 개선을 주장하지 않는다.

Jetson 전송 전 이름 조회가 실패했고 기존IPv4/IPv6 SSH가 모두 timeout이었다. 사용자는 장치가 켜져 있다고 확인했으나 같은 인터페이스의 mDNS 질문에도 응답이 없었다. 전원·네트워크 설정은 변경하지 않았고 아직 원격 측정은 실행하지 못했다.162개 소스/입력/기대 출력·18.06 MB 묶음을 로컬에 준비했으며 [해시 목록](bundle_manifest.json)·[묶음 해시](bundle_archive.json)를 보존한다. 연결 복구 뒤 별도 디렉터리에 해시 검증/추출하고 `measure.py --label jetson`을 실행한다. 센서나 차량 출력에 접근할 필요는 없다.

## 11/12 재연결 뒤 후속

재부팅 뒤 SSH와 묶음 해시를 확인했다. 엄격 전체출력 비교는 플랫폼별 검사점 개수 차이로 실패했다. 원 실패를 보존한 [r158 별도 관측](../jetson_replay_alignment_r158_v1/README.md)에서 baseline/후보 각각465명령은 같고 CPU 중앙115.05→186.79 ms임을 확인했다. 전체 진단 동일성과 실시간 성능 통과는 주장하지 않는다.
