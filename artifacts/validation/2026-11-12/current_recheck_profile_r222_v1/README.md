# 현재 옆차 재검사 비용 분해 r222

r221에서 긴 부모 처리의 대부분은 `rebase_current_present_guard`에 있었다. 같은 입력의 해당24개를 모두 선택해 Jetson의 격리된 r221 소스에서 함수별 호출 비용을 조사한다. 표본 복원·운동 투영은 프로파일 밖에서 수행하고 현재 경로 재검사만 계측한다. 관측/출력/판정선을 바꾸지 않는다.

cProfile 시간은 계측 오버헤드를 포함하므로 실제 지연이나 새 성능 수치로 쓰지 않는다. 원 명령과 소스/입력 불변도 확인한다. ROS·센서/직렬 포트·모터·펌웨어·전력 설정은 사용하지 않는다.

## 결과

24개 전부 명령 동일·소스/입력 불변이다. 원r221의4개 질의 개수 차이는 그대로이며 새 차이는 없다. [누적 비용](cumulative.txt)에서 현재 재검사 총1.741초 중 `motion_region`1.089초가 가장 컸다. 그 안의 이동 영역 질의 생성0.580초와 깊이 지지 판정0.334초가 주요 부분이며, `threat_view`0.234초도 남는다. 같은 함수 호출이25회인 것은 기존 저속 재시도1회가 포함된 결과다.

부모 루프는 점군 투영 뒤 현재 재검사에서 장면 투영도 수행하지만, 긴 꼬리의 주요 부분은 옆차가 있는 이동 영역 계산이다. 작은 투영 캐시부터 복잡하게 추가하기보다 이동 영역의 동일 질의 생성/기하 계산을 개선 후보로 남긴다. 주행 실패 분석과 병행하되 이 계측만으로 알고리즘/안전 판정선을 바꾸지 않는다.

첫 실행은 `profile.py`가 표준 라이브러리 모듈을 가리고 원격 worktree 경로도 잘못 지정해 실패했다. 두 번째는 모듈 경로에 차량 인터페이스 패키지가 누락됐다. 이름을 `recheck_profile.py`로 바꾸고 기존r221의 전체 모듈 경로를 사용한 세 번째 실행만 정상 완료했다. 초기 실패 로그는 보존하며 시뮬/운영 노드의 오류가 아니다.
