# 병렬 신규 계획의 실제 ROS 교통 대표 r274

기본 노드를 바꾸지 않고 명시 prefix에 r273 신규 계획 전용 병렬 인계·현재 영역 재검사·최신 미사용 스캔 제출을 연결했다. 보관 경로 반복 발행은 없다. 현재 raw300ms/명령200ms·양수 적용100ms와 기하500ms 후보를 유지했다. 실제 ROS 운동 이력을 사용하므로 r273의 취득+20ms 도착 가정은 없다.

**80초35.49m·접촉/노면 이탈 표본0이지만 미완주다.** 최장 저속33.952초로 지속 주행 기준을 통과하지 못했다. r253과 같은 두 상대0.8m/s·시설·ID20/30 누락·계획146.7455ms/현재33.5631ms 최소 결과 나이를 사용했다. 원r253의11.94m·접촉/정체 실패는 보존하며, 이번 원 `passed=false`/final_gap 실패도 그대로 둔다.

- 인계/STOP 관련24검사를 통과했다. 주행 뒤 원 계획549개·현재 검사300개가 같은 결과로 재생됐다. 실제 worker generation/sequence 순서를 사용하며, 일반적인 단일 call/reset 로그 순서가 병렬 worker 상태와 같다고 가정하지 않는다.
- 양수285개·0후보139개를 적용했다. 양수 적용 간격은 중앙/p95 약147ms, 최대328ms다. r253의 대체로200ms보다 줄었지만 고정 단계 지연을 주입한 PC 결과이며 실제 Jetson/실차 결과가 아니다.
- 반환 폐기125개는 원 시각 만료124개·이전 요청각 변경1개다. 현재 재검사300개는 모두 적용됐으며 원 시각/epoch/현재 영역/500ms 기하/독립 보호 연결을 확인했다.
- 보호층 stale표본1,491개는 직전 **주기 상태에서 모두0요청**이었다. r253의 양수요청에 대응한 stale600개는 같은 분류에서 재현되지 않았다. 주기 상태와의 시간 대응이며 모든 guard입력 바이트를 직접 증명한 것은 아니다.
- 후반54초 이후 적용된117계획은 `follow_boundary_unconfirmed`였다. 대표 저장 입력은 `wall_segment_short`·가까운 기준점 미관측(`anchor_not_observed`)이며, 현재 관측의 장애물 여부는 `fully_observed`다. 통신 만료와 경로 기준을 잃은 대기를 같은 문제로 묶지 않는다.
- 명시STOP/서버 종료·14 launch 자식 정상 종료·고유 파티션 잔여0·원 소스/스냅샷 불변을 확인했다. `independent_oblique_evaluated=false`는 해당 장면 관문 미발생으로 보존한다.

신규 실행 후보는 기본 채택하지 않았다. 다음은 저장된 정체 직전/정체 구간에서 좌우 벽 기준과 경로 소실 원인을 분석하는 것이다. 같은 주행을 근거 없이 반복하거나 임계값을 일괄 낮추지 않는다. 원문/현재 검사·평가 정답을 제어 입력과 구분한다.
