# r272 현재 운동 이력의 재생 시각 분리

[범위/도착 가정](PLAN.md)에 따라 원 wheels1,711개·gyro3,422개와 native 스캔을 사용했다. 환산된 원 센서 값과 취득 시각을 바꾸거나 차체 정답을 넣지 않았다. 새 reference마다 해당 시점에 사용 가능한 원 운동 이력으로 현재 영역을 다시 검사했다.

| 비교 | 원 snapshot reference 유지 | 표본 취득+20ms 도착 가정 |
|---|---:|---:|
| PC147/34ms 고정 비용 양수 |71|72|
| PC 다음 명령 직전의 기존 명령 나이 중앙 |289.56ms|249.94ms|
| PC 만료 시간 합 |6.275s|3.544s|
| Jetson 실제 비용 양수 |60|90|
| Jetson 갱신 간격 중앙 |196.10ms|101.21ms|
| Jetson 다음 명령 직전의 기존 명령 나이 중앙 |342.16ms|197.28ms|
| Jetson 최장 갱신 공백 |771.25ms|612.07ms|
| Jetson 만료 시간 합 |9.360s|3.318s|

별도 `observed` 대조는 현재 reference를20ms마다 만들되 원 snapshot에서 실제 확인된 시각 이후에만 표본을 공개했다. 중간 운동 표본이 충분히 최신이 아니어서 PC 양수0이었다. 이는 실제 센서가100ms씩 늦는다는 뜻이 아니라,100ms 단위 기록만으로 그 사이 도착을 입증할 수 없다는 한계다. 시각만 새로 붙이고 오래된 운동 이력으로 허가를 얻지 못함을 확인했다.

**실제 도착 시각/실차 성능 증명이 아니다.** 두 Jetson 실행은 같은 원 값이지만 주행 출력이 기록 궤적에 되먹임되지 않으며, 실행 순서·선택 입력·스케줄링 변동도 달라질 수 있다. 개선 수치 전체를 순수 시간 표시 변경이나 처리 속도 개선으로 해석하지 않는다. PC/Jetson 각각6개 재구성 검사·모든 실행의 정상 종료·원 소스 불변과 현재 명령/raw/기하 예산을 확인했다.

공통 제출 규칙과 같이 마지막 광선 뒤25ms를 사용하도록 시험기를 맞췄다. 기존r266/r271은 snapshot reference 뒤25ms여서 이 데이터에서약18ms 더 늦게 제출할 수 있었다. 원 결과는 보존하고 이번 수치를 동일 기준의 연속 개선으로 합산하지 않는다. 제한 창 때문에 계산기가 비어도 다음 회전을 기다리는 가능성은 남는다. 다음 후보는 원 timestamp/현재 재검사/예산을 유지하며 최신 미사용 스캔을 제출할 수 있는 조건을 분리하는 것이다. 아직 기본 변경이나 ROS 주행은 하지 않았다.
