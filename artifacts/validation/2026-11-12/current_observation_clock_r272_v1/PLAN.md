# r272 현재 운동 이력 시각의 재생 범위 확인

r266/r271 시간표는100ms마다 기록한 입력을 그대로 현재 검사에 사용해, 실제50Hz 부모보다 오래된 명령 reference가 남을 가능성이 있다. 이 차이를 해결된 실행 개선과 혼동하지 않도록 시험 입력의 의미부터 분리한다.

원 r243 부분 기록의 native 배열과 환산 이후 wheels/gyro 값·시각만 사용한다. 차체/actor 정답·보간·새 속도0 허용은 넣지 않는다. 현재 영역 재검사는 새 reference와 해당 시점에 사용 가능한 원 운동 이력으로 다시 계산하며, 과거 출력의 시각만 바꿔 재발행하지 않는다.

- `held`: 종전처럼 스캔을 처음 기록한100ms 입력을 현재 검사에도 사용한다.
- `observed`:20ms 현재 reference를 사용하되 표본을 포함한 최초 snapshot이 기록된 시각 전에는 그 표본을 공개하지 않는다. 원 기록으로 확인한 보수적 도착 가능 시각이다.
- `delay20`: 원 센서 시각+20ms에 도착한다는 명시 가정이다. 실제 도착 지연을 측정/복원했다고 주장하지 않는다. 값·취득시각은 바꾸지 않는다.

모든 모드의 스캔은 최초 기록 시각 이후에만 공개한다. 계획 제출25ms 창은 실제 `FreshStartDelivery`처럼 **마지막 광선 시각**을 기준으로 맞춘다. 이전 시간표의 `reference_s` 기준25ms와 약18ms 차이가 있어 r266/r271 숫자와 같은 실행으로 합산하지 않는다. 동일한 세 모드 안에서 비교한다.

두 프로세스와 r266의 기존 현재 증거/500ms 기하 후보·300ms raw/200ms 명령·STOP 경계를 유지하고 보조는 사용하지 않는다. 저장 궤적은 새 출력에 반응하지 않으므로 주행 성능/안전 증거가 아니다. 이 비교로 명령 나이 추정의 왜곡을 구분한 뒤 공통 ROS 연결/추가 구조 변경 필요성을 판단한다. 먼저 저장 원문·비인과/시각 불변 검사와 PC 비교, 이후 필요하면 Jetson 같은 대조를 수행한다.
