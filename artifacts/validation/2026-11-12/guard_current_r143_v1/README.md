# 실제 도착 시점의 제한 GUARD 현재 재검사

2026-11-12 실행 전 등록. r139 원 판단기를 그대로 사용하며, r142의 현재 재검사를 원 판단에 옆차 `present=false`이고 양수 GUARD 기본 경로가 승인된 경우에만 부모에서 수행한다. 그 밖의 일반/평행 현재 재검사와 현재 옆차가 있는 GUARD는 기존 연결을 유지한다. 상태 초기화/복원 방식은 바꾸지 않는다.

15개 기하/입력 반례와 실제 spawn·frozen 입력 어댑터 등 4개 연결 검사를 통과했다. 저장 비교의 다음 입력이 아닌 실제 후보 도착 시점 입력을 기록하고 같은 시설·두 차량·native10Hz·측정 판단 지연 하한·60초 목표를 한 번 비교한다. 판정선·물성·경로 원시각·STOP·독립 보호 경계를 유지하고 실패하면 그대로 보존한다. 새 현재 재검사의 CPU 비용은 기록하지만 실제 Jetson 전체 부하 재현이라고 하지 않는다. 후보는 launch prefix에서만 선택하며 기본 활성화하지 않는다.

현재 프로세스 내 재검사가 오래 걸리면 출력 자체가 늦을 수 있으며, 독립 보호층은 그 오래된 기준시각도 그대로 검사한다. 오래된 계산에 새 완료시각만 붙이는 방법은 쓰지 않는다.

## 실제 주행과 회수 결과

시설·두 상대·C1 native10Hz·측정 판단 비용 하한을 유지한 한 번의 주행은 **9.97 m·최장 저속 33.118초로 실패**했다. r139의 9.99 m·24.246초보다 개선되지 않았다. 두 번째 상대와 65.899–66.460초에 1,486개의 접촉 사건이 기록됐다. 이 수는 충돌 횟수가 아니라 시뮬레이션 접촉 표본 수다. 주 상대만 검사하는 원 보고서의 `no_actor_contact=true`를 전체 비접촉으로 해석하지 않는다. 추가 상대 접촉 수집은 유효하며, 종합 기능 판정은 실패다.

- [종합 판정](two_actor_run1/combined_assessment.json): STOP·정상 종료·원시 입력/등록 소스 불변·노면·시설 간섭 검사는 통과했다. 한 랩·연속 진행·비접촉은 미충족이다.
- [재생 대조](two_actor_run1/rebase_audit.json): 원 판단 465개와 현재 재검사 40개 전체 출력이 일치했다. 현재 재검사는 일반 24·평행 11·새 GUARD 허가 3·미해제 측방 접근 거절 2였다. 시간/속도/상태 계약 위반은 0이다. 현재 계산 PC 중앙 3.433 ms·p95 33.661 ms·최대 46.758 ms이며 Jetson 측정은 아니다.
- [명령 수명 분석](two_actor_run1/delivery_lifetime.json): 양수 GUARD 명령의 재구성 잔여 수명 중앙은 60→200 ms로 늘고, 해당 양수 GUARD의 명령 나이만 초과한 표본은 38→1개로 줄었다. 서로 다른 궤적에서의 관찰이며 직접 인과량으로 쓰지 않는다. 보호 콜백의 실제 수신 시각은 없는 분석이다.
- 경로 선택에서는 `guard_curve_rejected_large_motion_region_unobserved` 215개와 다른 거절이 남았다. 원천 만료 5개 뒤 상태 재구성과 코너 관측 문제도 남으며, 명령 수명 개선이 주행 정체 해결을 뜻하지 않는다.

후보는 **기본 미채택**이다. 같은 조건을 그대로 재실행하지 않는다. 현재 지연/관측 문제는 미해결로 남기고, 연결된 실물 입력의 동시 수신을 확인한 뒤 새 근거와 함께 다음 변경을 결정한다. 기록 SHA-256은 `3f7eb197612e00f59fc809ea98f6af9f41cbe741583f73fdeecc3ba28a2cc9fc`이며 자기 시험 프로세스는 모두 종료했다.
