# 새 회전 입력 제출 정책의 공통 실행 연결

2026-11-12 구현 전 범위 등록. Jetson 접근·새 Gazebo 주행은 수행하지 않는다. 실행 중인 r182의 소스 회수가 끝난 뒤 공통 코드를 변경한다.

r114 이후 시뮬레이션 prefix에서만 쓰던 `FreshStartDelivery`는 이미 오래된 스캔으로 새 계산을 시작하지 않고, 방금 완성된 native 스캔을 기다린다. 이 정책을 원 함수와 동일한 공통 모듈 및 명시 launch 옵션으로 연결한다. 지연 주입은 평가 prefix에 남기고, 기본 실행은 기존 제출 방식으로 유지한다.

수용 조건은 원 제출 함수의 저장 입력/상태 동일성, 만료·STOP/RESET·양수 명령 간격 보존, 실제 ROS 노드의 선택 정책 생성·종료, 기본값과 명시 native 조건이다.25ms는50Hz 수신부 한 주기와5ms 여유로 등록된 **계산 시작 시점**이며 센서 유효시간 연장이나 실물 시각 검증이 아니다. 시뮬 전용/50Hz 조건과 원 취득시각을 유지한다.

기존 계획기 후보의 공통화·실물 추정 시각 수용·하드웨어 구동은 이번 범위에서 완료했다고 표시하지 않는다.

## 결과

공통 모듈 `arena_autonomy.fresh_submission.FreshStartDelivery`와 `g1_submission_policy:=fresh_native_v1`을 연결했다. 기본은 `original_v1`이며 `process_candidate`·`native_simulation_v1`·기존50Hz/시뮬 조건에서만 선택한다. 이 옵션은 지연 주입·워커 재구현·실물 구동을 포함하지 않는다.

- 관련34검사 통과: 원439개 기록의 제출/회수 상태 동등성, 원 현재 재검사 OFF473/ON193, 입력 시각·명령 간격·실제 ROS 노드 STOP/RESET/정상 종료를 포함한다.
- 소스 계보197검사 통과. r179 보관본과 이전 계약은 그대로 보존하고 r184 후속 계약을 추가했다.
- `arena_autonomy`·`arena_bringup`2패키지 빌드 및 launch 인자 표시 확인. 새 Gazebo 주행이나 Jetson 실행은 하지 않았다.

실제 C1 추정 시각을 승인하거나 `native_estimated_v1`을 주행 가능하게 바꾼 것이 아니다. 계획기 후보 선택·평가용 배송 지연은 별도이며, r182의 노면 이탈도 이 연결로 해결됐다고 보지 않는다. 다음은 r185–186의 만료 결과 폐기와 갈림길 참조 대조다.
