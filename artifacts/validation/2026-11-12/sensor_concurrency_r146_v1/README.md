# 실물 세 센서 동시 수신과 제한 CPU 비교

2026-11-12 실행 전 등록. C1·ESP32 IMU·B0390의 개별 수신은 확인했으나 동시 수신은 확인하지 않았다. 차량을 움직이지 않고 기존 진단 도구 세 개를 함께 실행한다. 운영 드라이버나 실차 제어 시험은 아니다.

- C1: 기존 Standard 원천 SDK 진단, 기본 회전수 유지, 준비 5초 뒤 75초 기록. 종료 시 센서 내부 회전을 정지한다.
- IMU: 현재 진단 v2 펌웨어와 기존 v3 수신기, 준비 5초 뒤 75초 기록. 업로드/보정 없이 종료 `X`와 비활성 응답을 확인한다. USB를 열 때 boot가 달라질 수 있으므로 이전 기록과 이어 붙이지 않는다.
- B0390: 기존 720p60 BGR 진단, 준비 3초 뒤 60초 ROS domain73/localhost 수신. 픽셀은 저장하지 않고 길이·CRC·시각만 기록한다. header는 수신 시각이며 촬영 시각이 아니다.
- 시작 약 20초 뒤 센서 프로세스가 모두 살아 있을 때, r144의 동결 입력 37개 CPU 계산을 한 번 실행한다. 새 센서를 제어기에 연결한 것이 아니며 전체 ROS 주행 부하를 재현하지 않는다.

프로세스별 시작/종료 시각과 실제 측정 구간의 교집합을 확인한다. 개별 기준과 평균률·최대 간격·CRC/sequence 공백·본문 대조·정상 종료를 비교하고 실패를 유지한다. 센서 취득 동기화·각도/영점 교정·장착 검증·무손실 전 조건 보증은 범위 밖이다. 임시 두 직렬 포트 ACL만 적용하고 원래 값으로 복원한다. 모터/서보 명령·전력/서비스 변경·원격 게시를 하지 않는다.

원시 점군·UART·시각열은 원격 새 전용 폴더와 Git 제외 `build/sensor_concurrency_r146/`에 보존한다. 공개 자료에는 원시 실내 센서값을 넣지 않는다. 실패하면 원인 없이 같은 측정을 반복하지 않는다.

## 회수 결과

첫 실행은 IMU 수신기를 시스템 Python으로 호출해 `serial` 의존성을 찾지 못했다. 센서 성능 실패가 아닌 실행 환경 오류다. 시작 20초 뒤 비교 조건 미성립을 감지해 나머지 진단을 중단했고 C1 정지·장치 점유 해제·ACL 복원을 확인했다. 카메라 중단 중 rclpy 종료 중복 오류도 남았다. 첫 실행 원문과 `run_capture_v1.py`를 보존했다.

v2는 기존 IMU `tools_venv`를 사용하고 장치를 열기 전에 의존성을 확인했다. 세 센서가 모두 **측정 중인 교집합 57.008초**를 확인했다. 카메라 wall 시각을 같은 호스트 monotonic 축과 대조할 때의 차이 변동은 0.0084 ms였다. 이것은 호스트 기록 창 대조이며 광학/IMU의 실제 취득 동기화는 아니다.

IMU 원문 UART→JSONL→집계는 수신기 모듈을 사용하지 않는 별도 감사로 일치했다. C1 원시 점 행 수/순번과 스캔 집계, 카메라 발행/수신을 대조했고 CPU 비교가 세 측정 창 안에서 실행됐음을 확인했다. 네 프로세스 exit0·IMU 비활성·C1 Stop/motor0·ACL 원복·잔류 점유 없음이다. 센서를 늘 켜 두면 기본 수신부터 무너지는 현상은 이번 제한 조건에서 나타나지 않았다. 지연 교통 실패나 실시간 연산 문제가 해결된 것은 아니다.
