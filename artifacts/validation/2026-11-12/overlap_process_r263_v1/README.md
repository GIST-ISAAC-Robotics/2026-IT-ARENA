# r263 두 계산 프로세스의 겹침 후보

r262 현재 요청각 재검사를 별도 자식에 두고 다음 계획과 동시에 실행한다. 계획/현재 확인마다 진행1개, 회수한 계획1개만 소유하며 대기 작업을 쌓지 않는다. 입력은 직렬화된 사본으로 전달한다. STOP/RESET은 두 단계의 세대를 무효화하고 실행 중 버퍼는 완료 회수 전 재사용하지 않는다. 부모는 현재 검사 뒤의 직전 요청각/side/epoch·원 입력300ms/명령200ms 수명을 다시 확인한다. 실제 발행 간격·독립 보호·race state는 향후 ROS 소유자가 유지해야 한다.

현재는 artifact 후보이며 공통 코드·ROS 발행에 미연결이다. 선택형 만료 참조 보존은 기존 `replay_reset`과 같은 이유를 전달한다. 다른 STOP에서는 보존하지 않는다.

- PC 실제 프로세스12검사: 동시 실행, 입력/회수 사본 변경의 격리, 이중 STOP 무효화, 새 세대 재계산, 현재 검사 이후 변경/시각 거절, 두 자식 정상 종료.
- 첫 전체 재생: 원천 만료의 상태 보존 이유를 전달하지 않아 후속 계획 범위가 달라지는 오류. `pc_attempt1.log`를 보존하고 이유 전달을 수정했다.
- PC와 과거 Jetson의 전체 출력 비교:54개 진단 차이로 원 검사 실패. 속도/조향 차이는0이며 질의/가림 표본 수 차이가 남는다(`pc_jetson_comparison.json`). 플랫폼 차이의 세부 산술 원인은 아직 분석하지 않았다.
- 같은 PC 순차/겹침632계획·592현재 출력: 전체 동일. 순차22.714초→겹침18.858초, 실제 두 단계 겹침2.600초. 계산만의 비교이며 ROS 수신/발행 주기와 실제 주행 성능을 뜻하지 않는다.
- Jetson도12검사·632계획/592현재 전체 출력 동일과 두 자식 정상 종료를 확인했다. 순차86.694초→겹침76.749초(약11.5% 감소), 실제 단계 겹침15.329초. 계획p95는146.83ms로 그대로이고 현재 검사p50은16.63→32.74ms로 늘었다(p95 50.10→51.56ms). 처리량 개선이 명령 지연 개선 전체를 뜻하지 않는다. 현재 검사로 넘기는 원 계획 입력의 중복 직렬화도 확인할 필요가 있다.
- 시험 전 Jetson 부하는0.02였으며 다른 시험 프로세스가 없었다.226개 소스/입력 해시 불변·끝난 뒤 잔여 자식 없음. 센서/MCU/전원 설정은 조작하지 않았다. 원 결과 ZIP SHA는 `19342e8236639a4a23e95bc0a3094292fbc1837fa978edcbe32e41f61db628ef`다.

원632입력과 시험 당시226개 파일의 SHA는 `bundle_manifest.json`에 보존했다. `test_floor_s`는 동시 실행 경계 검사의 명시 비용 주입이며 비용 측정에서는0이다. raw 답/세부 timing/bundle은 Git에서 제외한다.
