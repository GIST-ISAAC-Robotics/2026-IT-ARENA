# 저속 반대 벽 재획득의 제한 주행 r279

r274와 같은80초·0.8m/s 각본 상대2대·시설·ID20/30 누락·native C1,147/34ms 단계 지연을 사용한다. 변경은 r278 저장 입력 후보의 계획 프로세스 연결뿐이다. 물성/속도/STOP/독립 보호/현재 관측/원 시각 예산은 유지한다. 실제 Jetson 지연 전체 분포나 최악 지연을 재현하는 시험은 아니다.

r278 OFF549판단 동일, ON은 후반54초 이후234계획에서 진행 후보를 만들었으나 같은 저장 궤적 비교다. 합성 포함99검사 및 실제 spawn4계획 일치/정상 종료를 선행했다. 초기 검사에서 갱신 옵션 없는 설정의 기억 만료 및 정지 조향 이유를 잘못 기대한 테스트2개/후속1개를 수정했고 원 로그를 보존했다. 후보 알고리즘을 통과시키려고 조건을 바꾸지 않았다.

이번에는 실제 `/drive`→독립 보호층→`/drive/safe`로 진행·접촉·정체·노면·STOP/종료를 판정한다. r27435.49m·최장저속33.952초 실패를 보존하고 원1랩/노면/간격 판정도 유지한다. 실패하면 새 근거를 분석하며 같은 조건을 성공까지 반복하지 않는다. common 기본값/실물에는 설치하지 않는다. 실제 계산 순서의 원 계획·현재 재검사 재생과 시험 당시 소스를 보존한다.
