# r250 Jetson 측정 단계 지연을 가정한 교통 대표

실행 전 등록. r248 공통 native 실행의 계획 p95 **146.746ms**와 현재 재검사 요청→회수 p95 **33.563ms**를 각 단계의 최소 반환 나이로 넣고 기존80초 교통 장면을 한 번 수행한다. 두 p95를 종단 지연의 통계 p95로 더한 것이 아니며, 매 호출에 같은 단계별 대기를 넣는 별도 조건이다.

PC 계산이 실제로 끝나고 등록한 시뮬 시간 나이가 지난 뒤에만 결과를 내준다. 원 관측/명령 시각·세대·STOP·기존 만료 조건은 유지한다. 완료 알림은 실제 PC 계산 완료를 알리고, 인위 대기 후 적용은50Hz 타이머에 양자화될 수 있다. 실제 Jetson 전체 실행·최악 부하·센서/영상 동시 성능을 재현했다고 부르지 않는다.

시설·두0.8m/s 각본 상대·ID20/30 누락·native C1·81T/28카운트/65mm와 기존 접촉·노면·진행·STOP 기준을 유지한다. `worker_event_v1`과`native_v1`을 명시 선택하며 평가용 prefix는 이 시험의 제어 노드 한 개에만 붙인다. 기본값과 대회 제어 코드에는 인위 지연을 넣지 않는다.

준비 검사 뒤1회만 실행하고, 실패해도 원 결과를 보존·분석한다. r243은 지연 없는 PC 실제 계산이므로 이번 결과와 직접적인 성능 향상 수치로 비교하지 않는다. 이번 새 장면의 결과가 나오기 전 성공/완주로 기록하지 않는다.
## 결과와 실패 분리

원 실행·시설/교통 평가 모두 **실패**했다. 80초 진행0m, 양수 적용 후보0이었다. 계획325개 중156개가 양수였고 현재 경로 재검사156개 중155개도 양수였지만, 재검사156개 모두 원 소스 만료로 폐기됐다. 다른169개 적용 후보는0명령이다. [첫 폐기 시각 분해](expiry_diagnosis.json)에서 원 첫 점8.034초→계획기준8.140초→계획 반환8.300초→현재 반환8.340초로 **원 소스306ms**가 됐다. 등록된300ms 만료를6ms 넘겼다.

50Hz 타이머가 두 단계의147/34ms를160/40ms로 올린 것이 직접적인 폐기 원인이다. 공통 실구현의 완료 알림과 다른 추가 대기를 평가 도구가 만들었다. 따라서 이 결과를 실제 Jetson에서 반드시 출발 불가라고 단정하지 않는다. 다만 계획 비용·입력 나이의 여유가 작다는 사실은 남으며, 만료선을 늘려 통과시키지 않는다. [r252](../staged_event_runtime_r252_v1/README.md)에서 같은 단계 비용을 유지하고 결과 기한의 한 번짜리 완료 알림만 맞춰 대조한다.

정지 자차에 각본 상대가 다시 돌아와53.461초/60.961초부터 접촉했다. 접촉/진행 실패를 삭제하지 않는다. 시설 겹침·도로 밖 바퀴0, STOP·자식/서버 종료·잔여0·등록 소스 불변은 별도로 통과했다. 평가기의 `longest_low_speed_s=0`은 움직인 표본이 없는 이 결과에서 무정체를 뜻하지 않는다.
