# 계획 프로세스·부모 재검사와 ROS 수신의 결합 비용 r232

r214의 계획 비용과 r221/r226의 현재 재검사는 별도 측정이었다. 여기서는 r225의632개 저장 판단을 원 순서/초기화/요청 간격으로 계획 프로세스에 넣고, 반환 후 해당 기록의 현재 센서 입력으로 부모 재검사도 실행한다. 같은 부모 executor에는200Hz 합성 IMU 구독과20ms 타이머가 있다. 기존64개 QoS 이력 버퍼를 사용한다.

차량/센서/모터 토픽 없이 localhost·ROS domain198·진단 전용 순번 메시지만 사용한다. 저장 입력 복원은 실행 전에 끝내며 계획기 계산·IPC·현재 snapshot/운동 투영/재검사·ROS 수신의 경합을 측정한다. 실제 G1 노드의 입력 폐기/만료 판정·카메라·독립 보호층·센서 드라이버를 포함한 전체 ROS 운용 시험은 아니다. 과거 시각의 입력을 새 취득시각으로 위장하지 않는다.

원 요청 시각보다 늦어지면 기록을 버리지 않고 지연량을 보고한다. 따라서 모든 판단의 완료와10Hz 실시간 달성은 다르다. 명령/전체 판단 차이, 수신 손실/콜백 지연, 소스 불변과 자식 정상 종료를 분리해 보고한다. 실제 장치·전력/펌웨어 설정은 변경하지 않는다.

PC의 첫12판단 점검은 전체 판단 동일·합성 IMU228/228 수신·자식 정상 종료를 확인했다([결과](pc_smoke/report.json)). Jetson 첫 실행은 `set -u`와 ROS 환경 스크립트의 선택적 환경변수가 충돌해 시험 시작 전에 실패했다. 이를 제거한 두 번째 명령으로 같은 동결 입력/소스의 시험을 완료했다. 환경/부팅/전력 설정을 바꾼 것은 아니다.

## Jetson 결과

632개 계획과592개 현재 재검사를 완료했고 속도/조향·사유/시각 명령 차이는0이었다. 합성 IMU19,823개를 모두 수신했고 중복/뜻밖의 순번0·소스 불변·자식 강제 종료0을 확인했다. 실시간 성능은 미달이다.

모든 기록을 원 순서로 끝까지 처리하는 이 시험에서는 마지막까지 요청 스케줄보다 최대20.31초 늦었다. 이것은 처리율 미달의 크기이며 운영 제어기가20초 묵은 명령을 사용했다는 뜻은 아니다. 실제 최신 입력 대체·만료 폐기는 이 시험에 포함하지 않았다. 메시지 손실0도 즉시 처리나 전체 ROS 운용 완료와 같지 않다.

전체 출력 비교는54건 달랐다. [세부 감사](difference_audit.json)에서112개 차이가 모두 질의 총수/좌우 가림 표본 수였고 최대3개,0↔양수 변화0이었다. 이 입력의 명령/위험·상태 사유에는 다른 차이가 없지만 전체 출력 동일로 기록하지 않는다. 원 차이는 [differences.json](jetson_full/differences.json)에 보존했다.
