# r247 공통 수치 커널의 명시 선택 연결

r245/r246에서 같은 Jetson 출력 동등성과 비용 감소를 확인한 광선 지지·다각형 거리 연산만 공통 CPython 확장으로 연결한다. 전체 제어기 재작성이나 GPU 전환은 아니다. 기본 `g1_numeric_execution:=python`을 유지하며 `native_v1`은 `g1_current_recheck_execution:=worker_event_v1`의 별도 자식에서만 선택한다. 부모 수신/독립 보호 계산은 기존 NumPy다.

## 구현과 경계

- NumPy C API 없이 Python buffer로 연속 배열을 전달한다. dtype·길이·쓰기 가능 여부·인덱스 범위를 검사한 후 두 계산 구간만 GIL을 해제한다.
- Python 원래 각도 후보 선택·면적 합산 순서·기하 경계·출력 시각을 유지한다. `fast-math`와 부동소수점 결합을 사용하지 않는다.
- 기본 NumPy 경로는 컴파일 모듈 없이도 설치 가능하다. `native_v1` 명시 선택 시에는 확장 모듈/ABI가 없으면 실행 오류로 드러내며 조용히 NumPy로 대체하지 않는다.
- 최초 colcon 빌드는 외부 `native/` 경로가 빌드 폴더에 없어서 실패했다. C++ 원문을 패키지 내부 `_native/`로 옮긴 뒤 두 패키지 빌드를 통과했다. 최초 로그를 보존한다.

## 현재 검증

관련63검사가86.58초에 통과했다. 버퍼 경계, 공통 기하 출력, 자식 세대/시각/단일 사용, 현재 재검사 전달, ROS 노드 경계를 포함한다. `pytest_exit=0`인데 WSL 외부 호출 반환은1인 불일치는 남겨 두며 실제 테스트 결과와 구분한다. 추가 native 실제 자식1검사(4.18초)와 출처 계약212검사(278.46초)도 통과했다. native 전용 검사는 컴파일 모듈이 없는 일반 환경에서는 skip하며, 이번 명시 검증에서는 확장 모듈을 빌드·불러온 뒤 수행했다. [r248 Jetson 공통 모듈](../numeric_ros_cost_r248_v1/README.md)은 두 구현의632계획/592현재검사 전체 출력 동등성과 계획p95 감소를 확인했다. 이 단계는 새 Gazebo 주행·실차 구동 완료가 아니다.

원본은 `before_sources.zip`, 최초 실패는 `build_attempt1.log`/`tests_attempt1.log`, 후속 결과는 이 폴더의 빌드·검사 로그다. 수치 커널 채택만으로 기존 r243 주행의 소스나 성공 범위를 바꾸지 않는다.
