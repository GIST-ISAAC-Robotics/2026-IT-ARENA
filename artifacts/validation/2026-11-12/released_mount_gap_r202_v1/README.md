# 통과 상태에서도 기존 장착 구조 인접 공백 검사 사용

r200에서 첫 저속 허가 뒤 남은106정지는 모두 `unbounded_nonreturn`이었다. r201 실물 입력 작업을 마친 뒤 이 실패 궤적을 고정해, GUARD에서 이미 쓰는 `bounded_adjacent_structure`가 같은 범위에 적용되는지 대조했다.

원473판단을 모두 재현했다. 기존 `structure_aware_v1`의 단일 선언 장착 구간·실제/목표0.15m/s 이하·무반환 합6° 이하·앞쪽100° 제외·양쪽 외측 반환0.6m 이상·국소 폭5cm 이하 검사를 그대로 적용하면106정지가 양수로 바뀌고, 같은 현재 입력의 재검사도106개 양수다. 새 정지·선택기 모드 변경은0이다. **실제 새 궤적의 지속 주행 개선은 아직 아니다.**

구현은 r199의 기본 OFF 옵션 안에서만 같은 함수로 분기한다. 추가 옵션/기본 활성화, 마스크 확대, 반환점/자유 공간 생성, 물성/속도/보호 수치 변경은 없다. 구조 정책을 선택하지 않았으면 기존 일반 공백 검사만 사용한다.

관련 첫78검사 중77개가 통과했고,1개는 구조 정책 OFF에 기존 sector 문자열을 함께 넣은 시험 fixture 오류였다. OFF에 문자열을 주지 않는 원 설정 계약에 맞춰 수정한 뒤 새13검사가 통과했다. 실행 전 소스/기존 OFF 재현/빌드 결과는 각 로그로 확인한다. `before_sources.zip`, `sources.json`, `comparison.json`, `config/tests/released_mount_gap_r202_sha256.json`을 보존한다. `compare.py`의 원 대조 재실행은 변경 전 소스 사본을 사용한다.

최종 연결에서는 최신 소스 계약과 기존 M3 계보 연결이 일치했다. r187의 옵션 OFF 473판단은 모두 같았고, ON의 기존108개 저속 보완과 같은 현재 입력 재검사도 유지됐다. `arena_autonomy`·`arena_bringup` 두 패키지를 빌드했다. 실제 새 궤적 비교는 별도 [r203](../released_mount_runtime_r203_v1/README.md)에 남긴다.
