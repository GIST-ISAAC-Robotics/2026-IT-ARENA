# 11/12 차량 CAD 센서·지주 선택형 이관 r290

사용자가 전달한 11/12 STEP의 **두 지주 부품과 광축 단면, C1 위치, 카메라 높이**를 시뮬에 연결했다. 상부 전체·차량 물성·구동계·실차 배치 확정으로 확대하지 않는다. Jetson/ESP32/IMU는 사용자 엔코더 시험을 위해 접근하지 않았다.

## 반영 범위

- 원본 STEP SHA-256 `37890b25fc69c5c56e400b6236872ab480dc96016211055842722d52769a98a4`를 다시 확인했다. [1차 기구 검토](../../../../docs/hardware/PACKAGING_STEP_REVIEW_2026_11_12.md)의 좌표 `X=-c-64, Y=21.2-a, Z=b+32.2` mm를 사용한다.
- `base_link`는 축간 중점의 지면 원점이다. **C1 축 X75.4/Y0/Z134.6 mm**는 CAD와 명목 광축 높이로 얻은 추정이며 실측 외부파라미터가 아니다. 지주2372/2373 실제 삼각망과 해당 높이의 오목한 U/트러스 단면을 사용했다. 단순 원기둥·볼록껍질로 메우지 않았다.
- **B0390 카메라 높이198.363 mm**만 구형 대체 카메라 CAD의 렌즈 축에서 옮겼다. B0390 모델/해상도/60 Hz/명목 화각은 유지했다. X55 mm·pitch0은 기존 임시값이며 렌즈 앞끝을 투영 중심으로 쓰지 않았다. Y0은 대체 렌즈 축과 일치한다.
- 기존 질량·관성·충돌체·축거/윤거135 mm·65 mm 바퀴·단일 모터축28카운트·11.911764706:1·IMU 위치는 유지했다. 추가 지주는 라이다/카메라 표시 형상이다. 전체 CAD 동역학·구조 강도를 재현한 것이 아니다.
- 배선은 전방 면 추가2/4/6 mm, 안쪽 면4 mm와 무배선 비교를 만들었다. 전 방향 감기·후방 외곽 팽창은 하지 않았다. 배선 수직 범위124.6–144.6 mm는 스캔면 근처 예약 근사이며 전체 하니스가 아니다. 어느 두께도 실측 기본값으로 채택하지 않았다.
- 기존 후면 ID49 중심140 mm/50 mm 판은 새 C1 광축을 막는다. 정지 시험에서도 실제 반환을 확인했다. 자동 이동하지 않았다. 중심180 mm 대조는 단면 간섭이 없는 **시험 위치**일 뿐이며 최종 후면 장착 위치 확인이 필요하다.

## 실행 선택과 자기 반환

설정은 `src/arena_description/config/b0390_c1_cad_20261112_{nowire,frontwire_2mm,frontwire_4mm,frontwire_6mm,inboardwire_4mm}.yaml`이다. 기존 JR 프로필을 덮어쓰지 않았으며 `--local-sensor-config`/`local_sensor_config:=`로 선택한다. 주행 시 기존 `g1_follow`의 `bounded_local_v4`·독립 보호층 연결을 그대로 사용한다. `simulation.launch.py` 직접 호출은 해당 보호 정책의 `SetParameter` scope가 필요하다([정지 시험 소스](stationary_probe.py)).

CAD 프로필은 `lidar_blind_sectors_json`에 각도와 자기 구조 거리 범위를 함께 전달한다. 그 거리 안의 자기 반환은 unknown으로 처리하고, 같은 각도라도 더 가깝거나 먼 **다른 유효 반환은 보존**한다. 무반환을 자유 공간으로 채우지 않으며 기존 각도 전용 프로필 의미는 바꾸지 않았다. 거리±2 mm는 이상적 모델/mesh 수치 여유이고 실제 C1 오차를 교정한 값이 아니다. 실차 적용 전 장착·배선 고정 상태에서 범위를 다시 확인해야 한다.

가림 각도 표에는 ID49와 정책 각도 여유0.5°를 포함하지 않았다. [단면 그림](mount_sections.png), [정적 계산](geometry_audit.json), [Gazebo 사진](stationary_v4/cad_mount.png), [원 실행 판정](stationary_v4/report.json), [후속 종료 확인](stationary_v4/post_exit_audit.json)을 구분한다. 주행/완주/실물 성능은 시험하지 않았다.

초기 실패도 보존했다. 기존 JR 회귀의 딕셔너리 끝 문자열 검사가 새 키 순서에 의존해 실패하여 AST로 기본값을 읽도록 수정했다. STL 법선은 float32 저장 꼭짓점에서 계산하도록 바로잡았다. 정밀 각도18,000표본은 실제 입력 상한을 바꾸지 않고 분할 검사했다. 정지 실행의 첫 시도는 운동 보정 인자 누락, 두 번째는 percent-encoded 공백 경로 때문에 mesh 미표시와 보호 정책 scope 누락, 세 번째는 보호 scope 전달 실패였다. 네 번째는 렌더/라이다/보호 노드 정상 실행을 확인했다. 원 로그와 각 실행 소스를 해당 폴더에 보존한다. 전체 과거 소스 계약 재검사는 렌더 경로 수정 시125통과 뒤 중단했고, 최종에는 이번 관련 회귀와 새 계약/이전 바이트 연결을 검사했다.

## 다음 확인

1. 실제 후면 마커 높이·카메라 전후 위치/pitch·C1 광축과 기둥/배선을 조립 후 측정한다. 재배선 시 자기 반환 범위를 다시 확인한다.
2. 같은 외부 입력 조건의 제한 주행으로 새 가림/높이 영향을 확인한다. 기존 완주를 새 CAD 프로필의 성과로 옮겨 적지 않는다.
3. [새 시설 STL 수신](../signal_post_revision_r291_v1/README.md)을 별도 진행한다. 차량 자체 지주와 신호/마커 시설 지주를 혼동하지 않는다.

원시 수신 배열·빌드/실행 상세 로그와 이전 소스 ZIP은 기존 Git 제외 정책을 따른다. 소스/설정 출처는 [r290 계약](../../../../config/tests/cad_mount_r290_sha256.json), 생성은 `scripts/build_cad_sensor_profile.py`, 정적 계산은 `audit_geometry.py`다.
