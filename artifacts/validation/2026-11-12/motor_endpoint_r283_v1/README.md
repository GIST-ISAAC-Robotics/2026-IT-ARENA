# MCU 통신·단일 모터 제어 주기 연결 r283

`ActuationMotorEndpoint`는 기존 IA 프레임→엄격 명령/세션·임대→수신 상태→모터축 피드백→PI 계산→상태/ACK 송신을 한 소유 작업에 결합한다. 수신기 자체는 읽기 전용으로 노출해 `receive` 직접 주입을 피하고, HAL 준비값은 매 호출에 전달한다. 생략은false이며 연결/송신 고장도 준비에 반영한다. 기존 출력 없는 `ActuationBenchEndpoint`는 바꾸지 않았다.

호스트 합성10사례를 크기 최적화·ASan/UBSan 두 빌드에서 통과했다. ARM/DRIVE 실제 바이트,0명령 후 재개,STOP/CLEAR/ARM,음수 모터축에서 전진 의도,준비 상실·피드백/명령 만료·단절·송신 sink계약 위반을 포함한다. 모터축28카운트·2.5×81/17·65mm를 사용했다. 실제 엔코더가 정상이라는 뜻이 아니다.

최초 시험 생성기가 ARM에도DRIVE전용 필드를 넣고 STOP에세션 필드를 넣어 기존 엄격 스키마에서 거절됐다. 두 원 실패 로그를 보존하고 시험 메시지를 기존 계약대로 고쳤다. 계약 수신 조건을 완화하지 않았다. 별도 검토에서 TX sink고장을 준비 상태에 반영하도록 연결하고 후속 제어 의도가0으로 되는 사례를 추가했다.

ESP32-S3 도구체인에서 예외/RTTI 없이 `target_compile.cpp`를 컴파일했다. 이는 **object 컴파일이며 IDF 앱 링크·보드 실행·GPIO/독립 차단 시험이 아니다.** [호스트 결과](host_cases.log), [sanitizer 결과](sanitizer_cases.log), [대상 object 크기](target_size.txt), [대상 심볼](target_symbols.txt).

다음은 이 연결부와 PCNT·PWM/DIR·버스 서보의 실제 어댑터를 연결하는 것이다. 최종 조향 환산/중립·엔코더 신호/부호/개수와 별도 출력 감시는 아직 필요하다. 실물 `output_ready`를true로 만들지 않았고 새 펌웨어를 올리지 않았다. 실제 엔코더0을 유효 정지 입력으로 합성하지 않는다.
