# 공통 최근 경로 참조·80초 지연 교통 r219

r217은60초 동안39.06m를 진행하고 최장저속1.106초·접촉/도로 이탈0을 확인했으나 한 랩은 미달했다. 갈림길 예외 제거 뒤 지속 주행이 성립했으므로 같은60초 실패를 반복하지 않고 코스 끝을 확인할 시간을 사전 등록한다.

- r218 기본 OFF 공통 옵션 `g1_expiry_route_reference_trial:=true`를 명시한다. 계획기/계산 프로세스에 함수 문자열 교체나 만료 전달 wrapper를 쓰지 않는다. 시험 prefix는 기존 지연 주입만 맡는다.
- 주행 창과 두 상대의0.8m/s 일정만60→80초로 늘린다. 후반20초에 옛 프로파일의 마지막 짧은 지연만 고정하지 않도록 동일60초 기록의 첫20초를 반복한다. 원 비용이 다른 궤적에서 얻은 값이라는 한계는 그대로다.
- 속도/원천 TTL/물성/노면·시설·마커 누락/간격·STOP/1랩 기준을 유지한다. 한 랩 판정 실패를 시간 변경만으로 소급 통과시키지 않는다.
- 입력 무결성·보호 연결·계산 시각/발행 간격·현재 경로 검사·최장저속·접촉/도로·STOP/정상 종료를 별도로 확인한다. 원 최종간격 판정도 보존한다.

공통 연결 회귀/빌드 뒤1회 실행한다. 성공할 때까지 반복하는 예약은 없다. 실물 주행이나 임의 동적 차량 전체를 보장하는 결과가 아니다.

## 기동 전 등록 실패

원 설정의 `maximum_actor_laps=1.2`는44.64m 코스에서 상대 이동을53.568m까지 등록한다. 이번80초·0.8m/s는64m이므로 기존 평가기의 경로 범위 검사에서 거절됐다. Gazebo/ROS 주행을 시작하는 코드보다 앞에서 실패했으며 `run1/`은 생성되지 않았다. 제어기 주행 실패가 아니다. 원 등록/소스 보관본·실패 로그와 후처리의 보고서 부재 오류를 보존한다.

후속 r220은 평가기가 원래 허용하는 범위 안에서 **상대 경로 감사 범위만1.5랩**으로 사전 등록한다. 자차 한 랩 성공 기준·간격/노면/충돌/정지 기준은 그대로다. 늘어난64m 상대 경로 전체를 다시 기하 검사하고 시작한다. r219의 시간 변경과 경로 등록을 함께 수정하지 않은 준비 누락을 기록한다.
