# 현재 선택 구성의 지연 정지·재출발 대표

실행 전 등록: 과거 r63의 시설 앞18초 각본(앞차0.50m/s,3–8초 정지,이후 재출발)과 원 목표 평가를 유지한다. 현재 r203의 native C1·81T 감속비·공통 선택 정책/현재 재검사/새 회전 제출·r202 기본 OFF 공백 보완을 명시하고 같은 지연 표본을 사용한다. 현재 selected medium_v1 profile을 적용하므로, 과거 균일 스캔/구동비/slow profile/r63와 단일 수정의 개선율을 비교하는 시험은 아니다.

앞차 재출발 뒤2.5초 내 재개·그 뒤1m 이상 진행·마지막2초0.5m 이상 진행·FOLLOW 복귀, 기존 간격/접촉/노면/STOP/종료 조건을 바꾸지 않는다. 시설 형상과 ID20/30 누락을 유지한다. 원 report와 별도 목표 판정을 모두 보존한다. 오목면 반환 증명은 과거 대표를 유지하며 이번에는 새 형상 검출을 통과시키는 목적을 추가하지 않는다. 원 상대 충돌 기하 보존은 확인한다.

PC/WSL에서1회 실행한다. Jetson/실물 모터 구동은 없다. 현재 지연 교통 r203의30.68m/10.484초 미완주와 곡선 측방 정체는 해결 처리하지 않는다. 정답 자세/각본은 평가 전용이다. 실패하면 원 증거와 원인을 남기고 이유 없이 반복하지 않는다.

## 실행 준비 실패

launch prefix의 `delay_worker.py`·`expiry_worker.py`를 새 시험 폴더로 복사하지 않아 `ModuleNotFoundError: No module named 'delay_worker'`가 발생했다. 노드가 시작하지 않았고 평가기는 autonomy/drive 수신을 기다리다 startup timeout으로 종료했다. 주행 결과가 아니며 원 report의 harness_valid=false·shutdown_clean=false를 보존한다. Gazebo 정지 서비스 응답과 서버/전체 고유 partition 잔류0을 확인했다. 후처리는 없는 판단 기록을 열려다 실패한 로그도 남긴다.

누락 의존성은 기존 r203 바이트 그대로 후속 r206 폴더에 보완한다. 먼저 실제 실행 환경에서 entry/의존성 import·같은 지연 입력을 확인한 뒤 같은 등록 장면을 실행한다. 원 r205 폴더의 실행 코드/입력/실패 기록은 수정하지 않는다.
