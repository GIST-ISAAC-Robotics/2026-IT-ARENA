# B3 명시 운영 도구 v1 — 사전 등록

사람의 상태 조회·명시 STOP/새 경기/같은 경기 개입 해제 진입점을 제공한다. 기본 미전송, 자동 ARM/CLEAR/MCU STOP 없음, 재전송 없음, 명시 session/경기/개입 번호를 현재 상태에 맞춰 자동 갱신하지 않는다. ROS는 격리 domain에서 실제 `LocalPursuit`와 도구를 연결하되 MCU·센서·Gazebo·실물은 실행하지 않는다. 새 경기·정지로 실제 출발을 시험하지 않는다.

새 순수/ROS 도구 회귀와 B3 관련 순수/노드 회귀를 한 묶음으로 실행한다. 종료·소스 불변을 확인한다. 실패하면 같은 명령을 무작정 반복하지 않고 원인 분석 뒤 별도 판으로 남긴다. 실행 담당은 GPT-6 Luna, 구현·분석·검토는 GPT 주 에이전트다.

## 결과

82통과·2실패·skip 0, exit 1. 소스 6개 불변, 실행 뒤 domain 노드·소유 프로세스 잔존 없음.

- endpoint 단위 검사는 직전 사례에서 상태 발행자를 비워 둔 채 서로 다른 노드 오류를 기대했다. 아직 모든 endpoint가 없는 상태에서 기다리는 도구 동작은 정상이며 시험의 전제 누락이다.
- 응답 유실 검사는 전송 후 미확인이 아니라 전송 전 실패로 끝났다. v1 로그에는 반환 오류 본문을 남기지 않아 그 호출의 정확한 예외는 미확정이다. 다만 기본 context 미초기화 검사에서 `_sigint_gc` executor 소멸 예외가 남았고, 코드가 전용 Context로 만든 노드를 기본 전역 executor의 `rclpy.spin_once`에 넘긴 결함을 확인했다. 로컬 rclpy 소스에서도 executor 미지정 시 전역 executor를 쓰는 것을 대조했다.
- 전용 Context에 연결한 명시 executor와 수명 정리를 추가하고, 실패 응답 본문·실제 timeout 여부를 검사하는 [v2](../b3_operator_v2/README.md)를 진행한다. v1 실패·당시 source.zip은 보존한다. 기존 제어기·보호·정지 계약은 수정하지 않는다.
