# 콜백 진단 발행 비용 비교

## 범위와 사전 종료 기준

사용자가 반복 최적화의 목적·종료 기준을 요구하여, 우선 **한 가설의 네 회 비교**를 수행한다. 후속 설명에 따라 횟수를 채우고 빨리 종료하는 것이 아니라, 현재 속도/입력 조건에서 다음 기능 개발로 넘어갈 연산 기반이 확보됐는지 판단한다. 목표는 모든 센서의 무손실이나 하드 실시간 인증이 아니다.

- 이미 보존·전송한 59.53초 정상 입력을 사용한다. PC 재주행·새 기록·입력 재전송은 하지 않는다.
- 동일 소스에서 `topic → buffered → buffered → topic` 네 회. 1배속·legacy·SHM 16 MiB·IMU/엔코더 발행 추적 ON, 최소 수신자 OFF. 센서율·QoS·제어/보호 한도·전력 모드 유지.
- `topic`은 기존 콜백별 JSON/DDS 진단 발행. `buffered`는 동일 단계·취득 시각·진입/종료 시각·순번을 최대 100,000행 메모리에 보관하고 입력/EOF 검사 뒤 서비스 체크포인트에서 파일로 내보낸다. 기본 계측은 여전히 비활성이며 기본 재생 계측도 topic이다.
- 완료 횟수, 파일 SHA-256, 행 수·순번, overflow를 검사한다. 저장/계측 실패는 비교 불성립이며 성공한 주행으로 바꾸지 않는다. 파일 저장은 주행 부하에 포함하지 않지만 메모리 보관 비용은 포함한다.
- 기존 기능·발행 스케줄·계측·운영(주행 비교 구간 보호 0명령 없음)·EOF 정지·정상 종료 판정을 그대로 적용한다. IMU 누락률/최장 공백, 주행 중 입력 나이·제어 간격, 자원 사용은 별도로 보고한다. 임의로 허용 손실률을 만들어 안전을 선언하지 않는다.
- 네 회의 결과로 **계측 방식 유지/선택형 지연 저장 활용/비교 불성립**을 판단한다. 통과할 때까지 반복하지 않고 누락 0개나 모든 주기 20 ms 달성을 요구하지 않는다. 중대한 반복 보호 실패·누적 적체·정지 경로 실패가 확인되면 필요한 보완을 수행할 수 있으나, 이유 없이 미해결 근본 원인 추적·새 executor/프로세스 구조·장시간 열시험을 추가하지 않는다.
- 새 보호 실패가 없으면 A3를 현재 입력·구성의 기능 개발 기반 확인 수준에서 마무리하고 A4 한정 고장 대응으로 이동할 근거로 삼는다. 실패하면 정확한 반례와 다음 기능 작업을 막는 이유를 보고하며 후속 범위는 별도로 정한다. 실차 센서/드라이버·MCU·제동 검증 완료를 뜻하지 않는다.
- 10월부터 사용자는 Claude와 함께 이상치 대응·다중 차량 준비 등도 진행할 계획이다. 제어기/필터 구조가 바뀔 때 재사용할 입력·매개변수·판정·소스 기준선을 남기는 것이 목적에 포함된다. 세부 내부 원인의 완전한 규명보다 정상 입력에서의 운영, 낡은 입력의 정지, 변경 전후 재현 비교를 우선한다. 협업 개시나 다른 에이전트로의 메시지 전송을 이번에 실행하지 않는다.

## 결과

PC(WSL Jazzy)의 계측·파일 검증·재생 관측/연속성·입력 계약·DDS 설정·IMU/엔코더 분석 관련 검사 **90개 통과**, Jetson은 **89개 통과**. 원격 엔코더 분석 시험의 기존본에는 PC의 `test_wait_window_excludes_arriving_callback_and_other_nodes` 한 개가 없었다. 다른 지정 7개 검사 파일은 동일하다. Jetson의 기존 엔코더 분석기도 이전 버전이어서 원본을 보존했고, 최종 결과 분석은 현재 PC 분석기로 수행했다. 90/89를 동일 검사 집합으로 세지 않는다.

주행 비교 구간을 10초 창으로 나눈 입력 나이 집계와 매개변수 동일성 검사를 분석기에 추가했다. 구간 경계·빈 구간의 별도 검사 **4개 통과**. 빈 구간을 0 ms로 채우거나, 관측된 짧은 입력만으로 장시간 적체 부재를 보증하지 않는다.

재생기에 새 import를 추가하면서 다음 배포 묶음에서 누락되지 않도록 `prepare_jetson_bundle.py`의 전체/부분 묶음 의존성을 보완했다. 관련 목록 검사 **2개 통과**. 이는 재생 네 회 종료 뒤의 PC 패키징 보완으로, 실행 소스/시험 결과를 소급 변경하지 않는다.

네 회 모두 기능·발행 스케줄·계측·EOF 정지·정상 종료는 통과했다. **topic 두 회는 운영 통과, buffered 두 회는 보호 0명령 2/4개로 운영 실패**다. buffered는 지역 IMU 누락과 CPU를 줄였지만 순간 지연이 늘어 개선안으로 채택하지 않는다. 해석과 다음 단계 판단은 [기준 보고서](../../../../docs/simulation/JETSON_REPLAY_2026_09_28.md#상세-진단-발행-비용-비교--929)에 둔다. 기존 두 회와 이번 네 회는 소스가 달라 동일 소스 반복으로 합산하지 않는다.

## 실행·보존·회수

- `runner_v1.log`: 두 패키지 빌드/설치본 일치 뒤, 미전송 `test_imu_delivery_analysis.py` 때문에 pytest 수집 전에 중단. 재생 출력은 생성되지 않았다. 빠진 검사와 import 대상 `analyze_imu_delivery.py`만 보완했다. 준비 실패를 재생 회차로 세지 않는다.
- `runner_v2.log`: 빌드/설치본 확인, 89개 검사, `topic_a/buffered_a/buffered_b/topic_b` 네 회 완료. 각 trial은 코드 0·오류/잔존 PID 없음이다. **종료 코드 0은 운영 통과와 다르며** buffered의 운영 실패는 보존한다. 마지막 별도 원격 조회에서도 시험 프로세스 없음.
- 변경/신규 배포 7파일과 누락 보완 2파일은 별도 manifest/패치 압축본으로 확인했다. 기존 원격 파일은 덮어쓰기 전에 보존했고 센서 입력은 재전송하지 않았다. Jetson 설치 `TimingProbe`와 소스 해시 일치 확인.
- 결과: `jetson_results/timing_cost_v1_{topic_a,buffered_a,buffered_b,topic_b}`. 원시 bag 없는 회수본 `build/timing_cost_results_v1.tar.gz`는 **24,988,407 bytes**, SHA-256 **`d3fb086ebd0cee1dcaf3d4786a6ddaf276e2b57ec92616b68bee006fef51577c`**로 원격/로컬 일치. 안전한 archive 항목 108개 중 파일 96개의 추출 해시도 일치했다.
- `comparison_v1.json`: 동일 실행 소스 24파일/스냅샷·mode/path 외 동일 매개변수, 실제 DDS 설정, 운영/지연/자원·10초 창 집계. 지연 저장 파일의 해시/행 수/완료 순번 검사 포함.
- `imu_analysis_v1.json`: 원본 IMU 시각 배열·발행 순서·두 수신자 대조. 진단 누락과 센서 누락을 구분한다.
- `analyze_stop_checkpoints_v1.py`, `stop_evidence_v1.json`: 0명령과 제어 호출의 ROS 시각을 정확히 맞추고, 직전 완료 콜백으로 엔코더/IMU 나이를 복원했다. 실차 정지 시간으로 해석하지 않는다.
- `verify_artifacts_v1.py`, `artifact_audit_v1.json`: archive·96파일·현재 소스/스냅샷 대조. 기존 스냅샷 대비 변경된 기존 파일은 재생기/TimingProbe뿐이다. 분석 코드 14파일은 `analysis_source_v1.zip`에 해시와 함께 보존했다.

기존 topic 계측을 유지하고 buffered는 실패 재현용 선택 옵션으로만 남긴다. 일반 계측 기본 비활성, system/legacy·센서율·QoS·보호 한도 유지. GitHub 게시·전원 종료는 하지 않았다. 이번 결과로 A3의 현 단계 집중 최적화를 보류하고 A4 제한된 이상치/고착 대응으로 이동할 것을 권고하며, 실차/장시간/드라이버 통합 검증은 별도로 남긴다.
