# r425 현재 공백 판정 자문 검토

2026-11-13. r423의 진입 연결은 동작했으나 현재 재검사0이 남아 Fable 5.2/high에 읽기 전용 자문했다. 신규 구현·실행 없이 결과1회 성공, 별도 findings0/누락0과 모델 일치를 확인했다. 답변 완료 때 실제 5시간 사용량90% 경고가 확인되어 후속 자문 없이 워커를 종료했다. 회계상 다른 모델 항목을 자문 서브에이전트 실행 증거로 쓰지 않는다.

## 확인된 사실과 자문 해석

- [r423 대표](../crop_current_scope_r423_v1/RESULT.md): 원 current exact·30검사 뒤 새 scope는 true였다. 0.15m/s는 차체 옆 외곽10.632mm로 거절,0.10m/s는7.390mm로 그 조건을 만족하지만 전체 공백113~118의 일부 광선이100° 이내여서 거절했다. 양 실제 이웃11.9613/1.69694m, 상대 요구거리0.19895m다. 거리 제안은 미진입이다. 이 수치는 저장 실행 결과이며 자문의 예상속도와 구분한다.
- 현재 코드는 차체 좌표의 작은 측면 띠와 센서 방향100°를 함께 제한한다. 센서가 전방75.4mm인 현재 구성에서는 같은 차체 측면 점도 장착 위치에 따라100° 선을 넘는다. 이를 물리 충돌 경계 자체로 볼 근거는 없다. 다만 각도 배제가 추가로 줄여온 허용 영역과 잔여 위험은 있으므로, 자문의 “추가 물리 위험이 없다”는 문장은 검증된 사실로 채택하지 않는다.
- plan의 crop 내부 폭과 전체 raw 성분 폭이 다른데 metric 분류가 먼저 수행되는 점을 코드에서 확인했다. 이번 대표는 crop 내부2.16°/전체 셀4.32°/flank 간5.04°다. crop 후보는 `not metric_gap`으로 선택되므로 해당 원 계획이 기존50mm chord/0.6m/s metric 검사까지 통과한 것은 아니다. 원 plan 약0.5m/s와 기존 metric 상한0.2m/s의 분류 차이는 후속 검토 항목이다. 자문이 추정한0.2m/s 승인·주행 통과는 실행으로 확인하지 않았다.

## 채택하는 다음 비교

기존 fully/일반 측면/guard/원100° 함수는 그대로 두고, **선택된 native simulation의 same-scan crop 성분에만 현재 swept 영역을 다시 검증하는 단일 후보**를 준비한다. 원 current가 양수면 건드리지 않는다. 후보의 목표는 min(원 plan,0.2m/s) 한 번이며 추가 속도 검색을 하지 않는다. 실제 측정속도·양쪽 조향·원 시각/경로·현재 운동 이력·점유는 새로 검사한다.

새 후보에서만 차체 옆10mm 상자와100° 영역 분할 대신, 현재 이동 영역의 질의와 원 계획에서 검토한 **같은 전체 무반환 성분**을 대조한다. 실제 양 flank, raw +inf, 근접 점유/패딩, 전체 공백6°와 국소 폭 합계50mm, 현재 중앙±30° 제외를 사용한다. 독립 검토에서 회전 중 광선 원점들이 서로 다르므로 단순 각도 chord만으로는 폭을 제한할 수 없다는 점을 확인했다. 새 후보에만 성분과 양 flank의 현재 원점 최대 쌍거리, 전체 현재 방향의 unwrap span을 사용한 `origin_diameter + 2*(query_reach + padding)*sin(span/2)` 비교를 준비한다. 현재 질의/패딩에 센서 offset이나 차체 팽창을 다시 더하지 않는다. 이 수식 역시 관측되지 않은 물체의 부재나 연속 충돌 안전을 증명하지 않는다. 미관측을 free로 바꾸지 않고 현재 proof에 제한 위험을 표시한다. 다른 무반환/구조 마스크로 허용을 넓히지 않는다. 독립 보호층과 부모 발행·STOP은 그대로다.

이는 과거 범위보다 허용할 수 있는 이동 영역과 측정속도 범위가 넓어지는 **시뮬 후보**다. 0.6m/s·50mm 등의 수치는 다른 기존 metric 정책에서 가져온 별도 위험 가정이며, 원 crop 계획과 동일한 허가 계약이라고 주장하지 않는다. 두 유한 이웃 사이에 숨어 반환하지 않는 가는 물체까지 배제하지 못하며, 같은 센서를 쓰는 독립 보호층이 그 물체를 반드시 잡는다고 주장하지 않는다. 실물 C1/host-estimated 입력에 자동 이관하지 않는다. 전역100° 삭제, 고정 범위의 일괄 제거, 기본 활성화는 채택하지 않았다.
