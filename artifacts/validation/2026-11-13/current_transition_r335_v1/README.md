# 양수 감속 후보의 교통 상태 전이 저장 실행 r335

r334의15초 초기 구간은 대부분 SOLO였다. 원 시작부터31초로 늘려 이후 GUARD/RELEASED 전이를 포함한다. 중간 장면으로 차체/제어 상태를 강제로 옮기지 않는다. 같은 r325 동결142소스+r334 후보, 실제 Jetson 계산 하한0·delay20 가정을 유지한다. 원시 입력의 처음316호출을 보존하고 두 프로세스 실행을 비교한다. ROS/구동/새 주행/전체 실시간 증명이 아니다.

## 결과

원 기록의 선택 상태는 SOLO234/GUARD53/RELEASED29였다. 이번 후보의 실제 계산은 SOLO216/GUARD42/RELEASED8·0계획3개이며 원 상태를 정답으로 강제하지 않았다. 현재 검사를 유지한 전이는 모두 양수 FOLLOW/SOLO였다. 새 감속 상한62회 중44회가 실제 출력을 낮췄으며0/상태 전이를 양수 유지로 바꾸지 않았다.

| 항목 | 새 계획만 | 감속 상한 후보 |
|---|---:|---:|
| 양수 발행 |236|258|
| 수명 초과 구간 |132|67|
| 수명 초과 합계 s |2.9258|1.6897|
| 발행 간격 p95/최대 ms |169.45/414.28|147.36/288.86|
| 다음 발행 전 이전 명령 나이 p95/최대 ms |262.94/521.93|235.80/421.30|

후반16초만의 수명 초과는1.5575→1.2059초였다. 초기 SOLO 이득을 교통 대응 전체 개선으로 확대하지 않는다.150입력 전후 불변·두 자식 정상 종료·구동/포트/전력 변경 없음이다. 이전 r334도 실제 센서 취득을 재현한 것이 아니라저장 입력의 delay20 가정이라는 한계를 유지한다.

이 후보를 최종 운영 채택하지 않고 다음은 ROS 발행 연결을 검증한다. 이미 확인한 같은 CPU 구간을 반복하며0공백이 나올 때까지 시행하지 않는다. 실제 발행 전/후의 보관, STOP/0·상태 전이, 원 시각·마지막 조향 일치를 우선한다.
