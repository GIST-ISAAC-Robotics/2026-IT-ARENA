# 실제 혼합 수신의 콜백 경계 계측 r312

r311의 gyro 발행3,747/수락3,634 차이를 분리한다. MCU·발행기·알고리즘·QoS는 동일하며 비구동 공통 관측 노드의 실제 motion 콜백 시각/수락과 선택형 MCU 상태 수신만 기록한다. r311과 같은20초 C1/IMU/RGB·출력 비활성 앱을 사용하고 종료 후 원 앱 복원한다. 결과가 나오기 전에는 누락 원인을 시작 부하로 단정하지 않는다.

## 결과

이번에는 자이로3,747개 발행/콜백/수락이 모두 일치하고 거절0이었다. 표본 시각과 수신 시각 차이는 중앙7.81/p9519.00/최대45.84ms, 최대 콜백 간격43.74ms였다. 이는 미교정 추정 시각에 대한 값이며 센서의 절대 취득 지연 측정이 아니다. MCU상태974개 발행/수신의 payload가 전부 일치했고 C1은183/183배열이었다. UART11,960프레임·CRC/순번/큐 폐기0이다.

RGB는1,201장 중1,188장을 수신했다. 영상은 최신 입력 방식으로194개 결과·처리중앙33.17/p9547.40/최대60.58ms였다. **영상 무손실은 아니며**, 공통 대기 상태의 관측으로 전체 경로 계산 부하/주행을 증명하지 않는다. 출력/엔코더 유효false·비영점명령0·최종STOP/ACK·원 앱SHA복원/readback·inactive·포트 반환·정상 종료·155소스 불변을 확인했다.

r311의 자이로113개 누락은 이번에 재현되지 않았다. 계측만 추가했으므로 해결됐다고 주장하지 않으며 원 실패를 보존한다. 반복 시험으로 통과를 누적하지 않고 실제 motion 콜백 기록과 선택형 MCU 상태 수신 기록을 공통 진단 CLI에 유지한다. 관련 실행기7검사와 전후 출처2검사를 통과했다. 실제 센서 값이나 QoS·제어 알고리즘·시각 신뢰 경계는 바꾸지 않았다. 다음 재발 또는 조립 후 운영 통합 때 같은 기록으로 누락 구간을 분리한다.
