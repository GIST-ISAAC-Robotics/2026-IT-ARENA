# r360 실제 센서와 별도 계획 계산의 동시 부하

2026-11-13, Jetson에서 C1·IMU·B0390의 기존 관측 노드를20초 실행하고 별도의 저장 입력 계획/현재 검사 두 프로세스를31초 실행했다. [사전 범위](PLAN.md), [집계](audit.json), [재집계 코드](audit.py), [고정 실행](bench.py)을 보존한다.

IMU 시각은 추정값이며 절대 취득 시각의 정확도를 검증한 것이 아니다. 원 IMU 진단 펌웨어에서 시작 전/후 수동 수신으로 장치·inactive를 확인했다. 프레임 외688바이트는 부팅/설정 출력과 구분하지 않은 decoder 수치이며 곧바로 CRC 손상으로 해석하지 않는다.

실제 센서 관측은 기존135mm hardware shadow·Python·단일 계산 자식이다. 엔코더가 없으므로 가짜0 피드백을 넣지 않았고, 실제 센서로 양수 주행 계획이나 독립 보호층까지 완료했다고 주장하지 않는다. 별도 계산만 r358 동결 native·두 프로세스와 r353 입력을 사용했다. 그 계산의 양수264발행, 발행간격 p95 163.93/최대456.28ms, 명령 만료 뒤 공백100구간·누적3.77초는 파일 재생 결과다. r358과 실행 일정·상태 선택·주파수 조건이 통제되지 않아 센서 부하가 성능을 개선했다고 해석하지 않는다.

원 UART·수신 JSON·영상 메타데이터는 `remote_result/actual/`에 로컬 보존하며 Git에서 제외한다. 픽셀은 저장하지 않았다. 새 동시 부하에서 카메라 수신 누락과 인식 처리비용이 남았으므로 다음에는 취득60Hz를 유지하며 선택 ROS 발행 주기를 낮추는 한 번의 비교를 수행한다. 실제 입력 전체 제어 연결과 실시간 처리율은 미해결이다.
