# r360 실제 센서 수신과 별도 계산 부하

11/13 재개. 주 에이전트가 설계/소스를 고정하고 단순 실행 담당이 Jetson을 독점 사용한다. MCU 펌웨어·모터·서보·전력 설정은 바꾸지 않는다. 원 IMU 진단 앱을 수동 수신으로 확인한 뒤 IMU 스트림만 시작/종료한다.

- 실제 C1/IMU/B0390 20초 관측: localhost ROS domain216, 기존 hardware shadow. 최신 공통 소스를 사용하지만 실행 설정은 기존135mm/Python/단일 계산 자식이다. 엔코더와 검증 시각이 없으므로 양수 주행 판단·독립 보호까지의 전체 운영 검증이 아니다.
- 별도 부하: r358 동결 코드·r353 입력의 계획/현재 검사 두 프로세스31초, native 공유 계산, 계산 지연 주입0, 파일만 출력. 실제 센서와 제어 입력을 섞지 않는다.
- 실제 IMU 데이터가 기록되기 시작한 뒤 계산 부하를 시작한다. 두 부하가 겹친 벽시계 구간을 보존하고 콜백 나이/누락·영상 처리·출력0·입력/명령 시각·정상 종료를 확인한다. 촬영 시각과 IMU 절대 취득 시각은 검증되지 않았다.
- 새 시험은 1회다. 실패하면 원인과 다음 변경을 분리하며 통과까지 반복하지 않는다. 동시 부하가 없는 r312와 수치 차이는 펌웨어/시점/계산 경로도 달라 인과 대조로 단정하지 않는다.
- 중단/오류 시 자기 자식만 종료하고 포트 반환·IMU inactive를 확인한다. 새 구동/flash를 수행하지 않는다. 원시 UART/센서·상세 JSON은 로컬 보존/Git 제외, 요약과 출처만 공개 대상으로 둔다.
