# 실제 생성량의 제한 반복 송신 r303

**30초 비구동 실물 대표에서 혼합 송신이 성립했다.** IMU17,700프레임(gyro/accel/시각 각각5,840개와 metadata/status), 원시 관측1,458개·offer1,457개를 받았다. IMU순번 누락·CRC 오류·IMU/관측 폐기0, boot1개·최저 스택 여유6,632 B였다. 원r302 실패는 보존한다. [실측 요약](assessment.json)·[원 결과](actual/result.json).

기존1ms당 한 번 pump 대신 UART가 바이트를 수락하는 동안 최대4회만 처리한다. 반환0이면 즉시 멈추고 프레임 중간 선점·유한큐/순서·endpoint 우선순위는 기존 pump가 유지한다. baud921600·큐64개는 그대로다. 실제 생성량600 IMU프레임/s와 현재 관측 길이를 반영한30초 합성은 기존1,624폐기→후보0,25ms 정체에서는1,636→0이었다. 관측2개 폐기는 정체 때 양쪽에서 계수했다. 단편1/37/4096 B 독립 복원과 ASan/UBSan 실행의 원바이트 일치를 확인했다. [합성 비교](host_assessment.json).

제어 호출은 여전히약166 Hz·최대7.002ms로 목표5ms와 차이가 있어 완료로 처리하지 않는다. PCNT0은 회전 확인이 아니며 서보 응답도 없었다. ARM/구동 없이 PWM/DIR 읽기0·출력 불허를 유지했다. 재부팅 중 물리 핀 전압·부하·제어 성능은 미검증이다.

끝나면 원 factory app1 MiB를 SHA 일치로 복원했다. 원 IMU inactive·포트 비점유를 확인했으며 현재 운영 앱에 자동 적용하지 않았다. [회수/복원](recovery.json)·[실행 소스](bench.py). raw UART와 flash 백업은 Git 제외 보존이다.
