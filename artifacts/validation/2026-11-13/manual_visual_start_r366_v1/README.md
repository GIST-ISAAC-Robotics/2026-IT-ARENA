# 수동 신호 출발

2026-11-13. 사용자가 신호를 직접 확인했을 때 운영 창의 **신호 확인 후 수동 출발** 버튼으로 최초 `WAIT_GREEN`을 해제한다. 기존 운영 명령의 session/race epoch/intervention·요청 중복 방지·결과/사건 기록을 재사용한다. 버튼은 신선한 상태가 `WAIT_GREEN`이고 미출발·래치 없음일 때만 활성화되며 수신 노드도 현재 대기 조건을 다시 확인한다.

출발 출처는 `operator_confirmed`다. 픽셀 검출 성공, visual 시각, MCU ARM 또는 센서 준비를 만들어 넣지 않는다. 출발 사실 수락 이후 기존 MCU/센서/경로·독립 보호층을 그대로 거친다. 일반 STOP→START는 같은 출발 사실을 유지하고 새 경기는 지운다. 수동 확인 뒤에는 신호 계산만 생략하고 마커 처리는 계속하며, 이전에 제출된 영상의 늦은 신호 결과가 수동 사실을 바꾸지 않는다.

공통 코드에 적용한 뒤 관련 **212개 회귀 통과**: 상태/세대/중복/STOP, 기존 운영·복구, 영상 처리, 실제 ROS 메시지 타입과 노드 메서드 연결. [실행 로그](tests.log). 실제 브라우저 클릭·Gazebo 출발·실차 버튼 주행을 이번에 실행한 것은 아니다. `manual_visual_start.patch`와 `staged`는 인계 당시 초안이며 이후 공통 소스의 수정까지 나타내는 배포본이 아니다.
