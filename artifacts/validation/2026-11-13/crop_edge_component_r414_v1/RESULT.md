# r414 경계 성분 후보의 저장 입력 비교

2026-11-13. **관련24검사와 원본/OFF/ON 각각254개 저장 입력 비교를 완료했다.** 옵션 OFF는 원본과 출력·기록한 상태가 같았다. ON의 정체 이후88입력에서 양수 명령이2→88로 늘었다. 아직 공통 연결·독립 보호층의 실제 실행·새 주행 결과는 아니다.

## 무엇을 바꿨는가

기존 ±100° 전방 검사 끝에 걸린 작은 무반환 구간에 한해, 원본 전체 스캔에서 같은 연속 성분의 실제 두 끝을 찾는다. crop 안3° 이하·전체 결측6°/5%의 기존 예산 안에서만 검토하며 seam·구조 제외광선·범위 미만 값·각도 공백을 건너뛰지 않는다. 정면/기존 metric 허용을 넓히지 않고 가까운 반환과 이전 물체 소실도 유지한다. **crop 밖 성분 전체를 소실 위협 검사에 넣어 바깥의 옛 근거리점을 잊지 않도록 했다.** 거리나 자유 점은 만들지 않는다.

기본false·verified simulation 입력 한정이다. 새 허가 범위를 추가하는 시험 후보이며 단순한 이웃 인덱스 수정으로 설명하지 않는다. [설계와 남은 위험](README.md)·[자문 검토](../partial_history_advice_r413_v1/REVIEW.md)를 따른다.

## 실패와 수정

첫 검사는20통과/4실패로 중단했고 저장 대조는 실행하지 않았다. F1의 위험점3개 보존·래치는 통과했지만, 갱신되는 `anchor_probe.anchor`가 최초 시각에 머물러야 한다는 시험 기대가 잘못됐다. 기존 `SurfaceAnchorTrial.observe`는 같은 호출에서도 기준점을 현재 시각으로 옮긴다. 최초 근거는 `anchor_threat_summary`와 `anchor_probe.created`에 남는다.

[fixture revision2](revision_fixture_v2/README.md)는 최초 근거와 rolling anchor의 기대를 구분했다. **후보 코드·입력 위치/거리/폭/시각/속도·위협3점·래치 기대는 그대로다.** 원 시험·manifest·실패 로그는 원 위치와 `reference_v1/`에 보존했다. 이후24개가 통과했다. 정지/좌회전의 crop밖3점 소실을 Python/native로 확인하고, 직접 광선 위협 한계보다1cm 안쪽의 끝점도 보존했다. 추가로 실제0.4초 입력 공백·같은 스캔 재사용·구조/근거리/seam/metadata·기본OFF를 확인했다. 이24개 모두가 실제 주행 시험인 것은 아니다.
