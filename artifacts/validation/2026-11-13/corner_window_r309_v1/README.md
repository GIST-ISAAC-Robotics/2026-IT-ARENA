# ID20 코너 관측 분리와 일회 순회 후보 r309

## 원인

r308의20.23m 정지 입력을 추적했다. 관측 창의 뒤쪽 길이를0.25→0.5/1.0m로 늘려도 정지 자세의 경로 원점 거리는80.2mm로 동일했다. 선택된 벽 조각 자체가 차량 앞44mm부터 시작하기 때문이다. 시설 반환을 평가 전용으로 제거한 비교의5.95mm는 원인 분리용이며 제어 입력에 사용하지 않았다.

실제 반환에는 짧은 지주 면과 먼 벽 점이 교대로 나타났다. `break_adjacent_occluders`는 동일한 작은 묶음을 매번 다시 탐색하며12번에서 종료했고, 원점 부근에 판정을 통과할 조각이 남았다. 이는 거리·폭 판정 실패가 아니라 탐색 횟수 상한이었다. [창 추적](window_trace.json)·[고정 센서](stall_sensor.npz).

## 시험 후보

최초 후보를 기존 edge/count/방향 우선순위로 한 번 순회한다. 이미 제거한 점이나 그 점을 양쪽 증거로 쓰는 후보는 거부한다. 원 번호 연속 조건상 삭제 뒤 새 이웃은 새 유효 후보가 될 수 없으므로 같은 검사를 반복할 필요가 없다. 작은 묶음의 점수/폭/깊이·양쪽 실제 반환·그림자 길이 기준은 그대로다. 원 점유와 독립 보호는 유지하며 경로 후보에서만 분리한다.

252개 관련 검사(새74·기존178)를 통과했다. 무제한이라는 뜻의 반복이 아니라 입력 점수로 유한하게 제한한 원 순차 탐색과60개 합성 장면의 선택 결과가 같았고, 기존12번 이내 사례·거부 조건·원 입력 불변도 확인했다. 정지 입력의 오른쪽 경로는 원점20mm 이내로 복구됐지만, 전체 제어기의 모든 정지 판단을 해결한 것은 아니다. 후보는 아직 시험 파일에만 있다.

## 저장 입력 비교

| 입력 | 원 기록 동일 재현 | 원 진행 판단 | 후보 진행 판단 | 후보 변경 판단 |
|---|---:|---:|---:|---:|
| r308 | 1,018/1,018 |625|640|96|
| r304 |498/498|105|488|398|
| r294 |1,031/1,031|634|1,019|443|

r308의 원 기준은 이미 r306 직선 조각 후보를 포함한다. r304/r294 후보 비교에는 그 직선 보완도 포함되므로 전체 차이를 이번 일회 순회만의 효과로 세지 않는다. 후보에서도 r308의378개는0명령이다. 정지 전 일부 경로를 복구했으나 이미 멈춘 궤적에서 선호 벽 재획득까지 모두 해결하지 못했다. 새 주행 성공이나 자유 공간의 추가 증명이 아니다.

PC 재생의 r308 전체 판단 중앙10.12→9.32ms·p95 23.40→20.04ms였으나 고정 CPU/독점 부하 시험이 아니며 Jetson 실시간 수치로 쓰지 않는다. [집계](replay_summary.json)·[회귀](regression.log)·[새 검사](tests.log)·[정지 전후](focus.json).

진단 최초 실행은 반환하지 못한 경로의 잔여 지역변수를 읽는 추적기 오류가 있었고 수정했다. 최초 pytest는 작업 디렉터리, 다음 회귀 수집은 ROS 환경 누락으로 실행되지 않아 환경을 수정한 뒤 검사했다. 이들은 주행 성공/실패와 구분한다. 후속은 같은 조건의 제한 폐루프 r310이며 성공할 때까지 자동 반복하지 않는다.
