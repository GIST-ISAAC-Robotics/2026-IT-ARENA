# main 스택 수정과 실제 혼합 송신 r302

**재부팅 문제는 이 30초 시험에서 사라졌지만 혼합 송신 검증은 실패다.** 단일 task의 큰 임시 버퍼를 정적 저장소로 옮겨 app_main 컴파일 스택 2,688→688 B, 설정 스택 3,584→8,192 B로 바꿨다. 실제 boot ID 1개·스택 최저 여유 6,680 B를 확인했다. 로그 빌드 r301의 스택 초과와 구분하여 원 실패를 보존한다.

IMU 15,489프레임·원시 관측 1,440개·offer 1,439개를 받았으나 IMU 폐기 계수 2,157과 순번 누락이 있었다. CRC 오류0은 손실0을 뜻하지 않는다. r293 합성의 400프레임/s는 gyro/accel 외 FIFO 시각 프레임까지 포함하는 실제 생성량을 반영하지 못했다. 1ms당 한 번만 실행하는 송신 pump의 이용률과 실제 프레임 크기를 [r303](../runtime_tx_budget_r303_v1/README.md)에서 대조한다. 유한큐 크기를 늘려 지연을 숨기지 않는다.

PCNT는 원시0만 받았으며 연결/회전 검증이 아니다. 서보 조회는 응답 없이 fault, PWM/DIR 읽기0·output_ready=false를 유지했다. 제어 호출 간격 최대7,001µs로 목표5ms와 차이가 있고 실물 출력/부하 시험은 아니다. 물리 핀 전압과 재부팅 순간은 측정하지 않았다.

시험 후 원 factory app 1 MiB를 SHA 일치로 복원했다. 원 IMU inactive 응답·포트 비점유를 확인했으며 ARM/모터 명령0이다. [계측](assessment.json)·[원 결과](actual/result.json)·[복원/회수](recovery.json)·[실행 소스](bench.py). UART 원문과 flash 백업은 Git 제외로 보존한다.
