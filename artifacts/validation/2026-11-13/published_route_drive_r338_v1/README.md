# 발행 확인 뒤 경로 보관 후보의 ROS 주행 연결 r338

r337의 시설 이름 계약 실패를 보존하고 model 이름에 `eval_r338_` 접두사를 붙인 실행이다. 시설 mesh/위치나 제어 정책은 이 오류 해결 때문에 바꾸지 않았다.

공통/운용 기본은 유지하며 `r336` prefix를 명시한다. 두 0.8m/s 상대·80초·기존 간격/노면/겹침·STOP·완주 판정을 사용한다. 원 r282와 달리 현재 CAD 센서 배치와 확정 구형610 지주를 넣으며, 상대 높이는 우리 차량과 비슷한 **220mm 시험 가정**이다. 더 낮은 차량은 별도다. 광원2×5/ID20·30 미검출, 단일모터28count·2.5×81/17·65mm, 독립 보호층을 유지한다.

PC 실제 계산·RTF0.25·지연 무주입으로 **ROS 인계와 제한 교통 동작**을 확인한다. Jetson 실시간/실차 검증 또는 r282와 한 변수만 바꾼 성능 대조가 아니다. 실행 전 입력을 보존하며 원 판정이 실패하면 그대로 남긴다. 결과가 나쁘다는 이유만으로 같은 시험을 반복하지 않는다.

## 결과 — 출발 불가, 기본 미채택

현재 재검사234개가 모두 `route_current_large_motion_masked_toward_left`로0을 반환했다. 약90mm 중앙 복귀의 왼쪽 조향에서 마스크 꼬리10.072–10.562mm가 기존10mm 조건을 넘었다. 해당 영역의 미관측/전방 마스크 수는0이며 왼쪽 마스크가 남았다. CPU 결과 인계가 아니라 현재 영역 검사가 진행을 막은 사례다. 양수 실제 발행이 없어234회의 `route_publication`은 모두 보관을 거절했다. 양수 명령의 ROS 주행 검증은 아직 아니다.

같은 정지를80초까지 기다리지 않고 STOP/disable 서비스 응답과 MCU `ESTOP_LATCHED`·출력0을 확인한 뒤 시험을 중단했다(`early_stop.json`). 원 평가기는 STOP 후 중단 신호로 `TimeoutError`를 기록했고 `passed=false`, `harness_valid=false`다. 상대 궤적 오차 약0.222m도 원 실패로 남긴다. 별도 STOP 확인을 원 평가기의 전체 STOP 검사 통과로 대체하지 않는다.

14개 자식 정상 종료·잔여PID0·705입력/소스와 보관 ZIP 불변을 확인했다. 같은 실패를 반복하지 않으며 허용10mm를 늘리지 않는다. 후속은 같은 조향에서 더 낮은 양수 목표가 현재 속도까지 포함한 원 영역 검사를 만족하는지 저장 입력으로 확인하는 후보이며, 아직 구현/채택하지 않았다. 희소 상부 차량·광학 보조 등 다른 미완성 항목도 병행한다.
