# r386 현재 거리 예산 후보 — 미채택

후속 `revision_final_geometry_v1`에서 final223입력의 새 양수 회복0을 확인했다. 관련55검사·원 baseline795/legacy795와 비대상572는 유지했으나 시각 반례 장면 생성 예외로 전체 실행은 실패다(완료11/15). 판정선·입력·실패 원문은 보존하고 새 후보를 공통 실행에 넣지 않는다. 상세 원인과 다음 검토는 [후속 분석](revision_final_geometry_v1/recovery_analysis.md)을 따른다.

아래는 원 최초 묶음 준비/보류 당시 설명이다. **원 bundle_sources.zip 자체는 미실행이며**, 후속 최종 기하 revision과 혼동하지 않는다.

## 원 준비 기록: r377 SOLO 코너의 현재 거리 예산 후보 r386

**실행 보류: 현재 검사 기하와 최종 CAD 기하의 차이를 주 에이전트가 먼저 감사한다.** 저장 입력 비교용 코드는 준비했지만 후보 계산·회귀·native 빌드·WSL/Jetson·새 주행은 모두 실행하지 않았다. r377 원10.01m 정체와 `passed=false`를 보존한다. 0.15/0.10m/s 다음에0.09라는 상수를 추가하지 않고, 현재 관측과 실제속도에서 한 개 목표만 제안한 뒤 기존 현재 검사를 수행한다. 기본 운영에는 연결하지 않는다.

## 실행 전 필수 후속 — 실제 검사 기하 감사

최종 CAD 기준 윤거는 **0.1239m**, 바퀴폭은 **0.0261m**인데, 동결 r377의 `ps.lateral_config(cfg)`는 해당 두 값을 전달하지 않아 `LateralIntentConfig` 기본 **윤거0.135m·바퀴폭0.012m**를 사용한다. 두 조합의 정적 총폭은 비슷해도 Ackermann 좌우각·회전하는 바퀴 외곽·공백 질의 위치는 같지 않을 수 있다. 이 차이가 마지막10.766mm 및 반복 정체에 미친 영향은 **아직 계산하지 않았으며 원인으로 확정하지 않는다.**

속도 후보를 먼저 실행하면 기하 불일치로 생긴 정지를 새 감속으로 덮을 수 있으므로, 주 에이전트의 원인감사 뒤 진행 여부를 정한다. r386은 어느 기하도 고치지 않았으며 원 실행 기하를 그대로 기록했다. 감사 결과상 필요한 수정과 후보 실험의 우선순위는 주 에이전트가 통합한다. 이 확인이 끝나기 전 [고정명령](HANDOFF.md)을 실행하지 않는다.

이 실행 보류 문구는 archive 생성 뒤 문서에 추가했다. `bundle_sources.zip`·`source_manifest.json`·후보/예산/실행 코드는 준비 당시 원문으로 보존하므로 archive 안 README에는 이 후속 문구가 없다. 문서 변경을 숨겨 원 manifest와 현재 README가 동일하다고 주장하지 않는다. 실행 재개 시에는 이 감사 결과와 인계 상태를 먼저 확인해야 한다.

## 원 실패와 목표

[r377](../released_cad_drive_r377_v1/README.md)의 마지막 입력은 SOLO/baseline 원 목표0.45m/s, 측정속도0, 현재 조향0.394927rad·직전0.406621rad, dt0.1s·스캔나이약0.12s다. 0.15 재시도는 미관측 side15.209mm, 0.10 재시도는10.766mm로 기존10mm를 넘었다. 마지막 마스크 꼬리9.744mm 자체는 통과 범위다. 이 값들을 후보 코드에 새 판정선이나 특정 입력 식별자로 넣지 않는다.

목적은 직접 충돌 위험 없이 진행 가능한 경로의 불필요한 정지를 줄이는 것이다. 정답 자세·지도·미래 상태를 입력하지 않는다.10mm·6°/5cm 공백·상대 이웃·현재 점유 padding·TTL·물성·실제속도·두 조향·독립 보호는 유지한다. 관측상 더 움직일 수 없으면 원 정지를 유지한다.

## 단일 제안과 최종 검사

[`budget.py`](budget.py)의 `propose`와 `speed_from_distance`는 독립 핵심 함수다. [`candidate.py`](candidate.py)의 `try_from_current_result(before, ...)`는 이미 계산한 r375 결과를 받으며, r375/r370 wrapper를 다시 호출하지 않는다. 운영용 `rebase` wrapper를 새로 만들지 않았다.

1. 양수 출력·GUARD/RELEASED·비대상은 원 객체를 그대로 반환한다. 현재 `.10` 상대 공백 재시도가 `outside_small_body_side`로 거절한 SOLO/baseline, 완전 관측 원 경로, 기억 경계 없음, 측정0–0.15m/s 입력만 이번 저장 비교의 범위다. 범위가 넓은 감속 정책을 미리 바꾸지 않는다.
2. 같은 `D(v)`에서 `.10` 목표의 상한 거리를 구한다. 현재/직전 조향의 **고정 1cm 거리점 + 기존 차체 x/y 극점 + 끝점**을 사용한다. `linspace`의 길이별 부분집합을 가정하거나 통과 함수를 이진검색하지 않는다. 모든 거리점에서 기존 `body_queries`가 만든 차체 외곽·바퀴 지름 외곽·얇은 unknown 각도 셀 교차에 발생 거리를 붙인다. 정확 중복점은 첫 발생 거리를 유지한다.
3. 합친 질의를 현재 스캔으로 한번 분류한다. free 질의에는 새10mm 제약을 걸지 않는다. unknown은 기존 차체 옆10mm/x범위, masked는 기존 꼬리10mm/전방제외를 처음 위반한 거리 **직전의 공통 접두점**을 제안거리로 쓴다. unknown을 free로 바꾸지 않는다. 이 단계는 기하에 대한 제안이며 좁은 공백의 양끝 반환·점유·시각 허가를 대신하지 않는다.
4. 제안거리에서 한 개 속도를 역산한다. `v=max(measured,target)`, `tau=dt+max(0,age)+.1`, `a=2`, `D(v)=v*tau+v²/(2a)`를 그대로 사용한다. 수치적으로 안정적인 `v_budget=2D/(tau+sqrt(tau²+2D/a))`를 원 목표와 기존0.10 상한으로 제한한다. 한 번의 `nextafter(...,0)`는 경계의 부동소수점 반올림만 안쪽으로 처리하며 속도 후보 열을 만들지 않는다.
5. 실제속도 자체의 `D(measured)>Dallow`, 제안거리<기존 최소질의거리10mm이면 제안하지 않는다. 측정0.15에서는 원 tau0.32s의 제동 포함 거리53.625mm가 그대로 남아 목표를 낮춰도 줄지 않는다.
6. 한 개 목표에 원 core 경로/시각/점유 검사를 수행하고, **다시 생성한 실제 `motion_region` 전부**, 기존 `bounded_body_nonreturn(relative_neighbor=True)`, `region_blocked`를 검사한다. 실제 최종질의가 제안격자의 부분집합이 아니어도 최종 검사 자체가 허가를 결정한다. 경로·조향·시각이 달라지거나 관측/점유/공백 검사에서 실패하면 원 정지로 끝낸다. 더 낮은 목표로 재시도하지 않는다.

제안은 표본 사이 연속 sweep 인증이 아니다. 양쪽 조향·차체/바퀴를 포함하지만 그 사실을 연속 안전/숨은 물체 부재로 확대하지 않는다. 최종 full 검사도 기존 이산 검사의 범위다.

## 보수성과 비용·채택 경계

이 입력에서 제안거리0.03m가 나오면 원0.0345m보다 짧고 약0.088m/s 수준의 목표가 될 수 있다. **아직 계산하지 않은 예상**이며 실제 결과로 쓰지 않는다.1cm격자 때문에 더 큰 허용거리를 놓치거나 전혀 제안하지 못할 수 있다. 실패 직전 점을 반복 세분하거나0.09상수로 바꾸어 성공할 때까지 탐색하지 않는다.

현재 코드의 기하는 기존 `ps.lateral_config(cfg)`를 그대로 사용한다. 이 함수는 길이/폭/축거/최대각을 cfg에서 받지만 윤거·바퀴 값은 `LateralIntentConfig` 기본값을 유지한다. CAD 문서의 숫자를 별도 입력해 baseline과 다른 기하로 바꾸지 않는다. 실제 사용한 lateral 기하를 diagnostic에 기록하며, 최종 CAD 전체와 동일하다는 주장은 하지 않는다. 이 차이는 별도 통합 검토 사항이다.

제안은 자세마다 기존 `body_queries`를 호출하므로 광선 전처리의 반복 비용이 추가될 수 있다. 비교는 원 baseline 비용, proposal geometry/classification, final core/region/gap, 추가 합계, baseline+추가의 비교용 합계를 각각 기록한다. 시각/비용을 후보 출력에 넣지 않아 출력 비교를 흐리지 않는다. 이번 후보가 개선 없이 질의량/비용만 늘면 미채택으로 마칠 수 있다.

**운영 통합 시 또 한 wrapper로 붙이지 않는다.** 향후 채택 검토에서는 원 core/current scene·현재 두 조향의 기하 결과를 공유한 한 선택 단계에 `propose`를 넣고 기존 `.15/.10` 고정 재시도 구간을 대체해야 한다. 이번에는 기존 통과를 보존하려고 r375 결과 뒤에서 비교하지만 이는 운영 구조의 목표가 아니다. 원 양수 출력과 `.15/.10`으로 이미 회복하던 출력을 보존할 수 있는지 별도 통합 회귀가 필요하다. 측정된 추가비용을 제거한 가상의 개선률로 보고하지 않는다.

## 저장 비교와 반례

[`compare.py`](compare.py)는 원 r377223개를 먼저 재현한다. 새 함수 적용 여부·원/새 속도·측정속도·제안거리·최종 영역/공백·두 조향·시각·추가검사 횟수를 남긴다. 기존 r371217, r364249, r279/r282106은 그대로 보존하는 비교 집합이다. 이 중 새 변화가 생기면 성공으로 숨기지 않고 `preservation_set_changed`로 보고한다. 원795개 뒤 마지막 입력의15개 반례를 계산한다.

반례는 측정0.15의 제동거리 바닥,0.151 범위밖, 음수속도, **양쪽 후측방 넓은 사각**, 전방+양쪽 근접물체, 전방 두 장애물, 좌/우 근접반환, NaN, 경로 만료, epoch변경, 미검증시각, CAD밖 직전각, dt초과, 반대 직전각+양쪽사각이다. 바뀐 입력은 장면을 다시 복원하여 검사하며 원 record를 수정하지 않는다. 반례15개는 적용하지 않고 정지를 유지해야 한다. 반례가 통과하면 전체 비교 실패로 남기고 조건을 바꾸지 않는다.

[`test_candidate.py`](test_candidate.py)는 거리 역산/실제속도 바닥/10mm 최소질의, 좌우대칭/반대조향, 이미 관측된 바깥점 비제약, 마스크 전방/꼬리, 양수·비대상 불변, 최종 실패시 재시도 없음, 최종 완전관측 처리 등을 검사하도록 준비했다. **아직 실행하지 않았다.**

## 원본 소스와 실행 인계

[`build_bundle.py`](build_bundle.py)는 r377 `sources.zip`/`registered.json`의 해시와 바이트를 기준으로 필요한 두 계산 패키지·11/12 r281/r266을 포함한 후보7계보를 보존한다. 현재 작업 트리의 r379/P0 공통 변경을 섞지 않는다. 원 저장 trace·기대값도 해시로 보존한다. native x86 바이너리는 포함하지 않고 실행 담당자가 새 루트에서 빌드한다.

Windows에서는 AST/링크/번들 바이트 검증과 패키징만 한다. 실행자는 주 에이전트가 지정한 WSL 담당자 한 명이다. [`execute_isolated.py`](execute_isolated.py)는 새 사용자 홈 `it-arena-r386-*` 루트에만 압축을 풀고 native빌드120초→회귀120초→저장비교900초 각1회 후 자기 자식 종료/해시/로그를 회수한다. ROS/Gazebo/센서 포트/장치/구동에는 연결하지 않는다.

```text
python artifacts/validation/2026-11-13/current_corner_budget_r386_v1/build_bundle.py
```

실제 archive/manifest/실행스크립트 해시와 고정명령은 번들 확정 뒤 `HANDOFF.md`에 남긴다. 원 bundle/result가 있으면 덮어쓰지 않는다. 상세 입력/JSONL/압축본은 기존 raw Git 제외 정책을 유지한다. 통과해도 한 랩 성공·정체의 실제 해소·실차 성능으로 쓰지 않는다.
