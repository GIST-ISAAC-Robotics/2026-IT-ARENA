# r386 최종 기하 전달 후 저장 입력 비교 준비

상태: **준비만 완료, 미실행**. 원r386 archive와 원candidate/budget/harness는 그대로 보존하며 원 archive는 계속 미실행이다. 원r377 주행 실패와 r388 r0 검증 실패도 유지한다. 이번 revision은 승인된 최종 기하 전달 소스에서 **동일한 원r386 알고리즘**을 비교하도록 준비한 별도 묶음이다. 공통 소스/WSL/Jetson/시뮬/장치는 실행·수정하지 않았다.

## 선행 결과와 원인 분리

r388 r1은49순수검사와 마지막 저장1입력에서 frozen/legacy 출력·질의 완전동일, 명시 최종 기하 전달을 확인했다. 마지막 `.10m/s` 재시도는 최종 기하에서도 정지했고, 미관측162개·side초과10.766348mm·masked388개는 유지됐다. 전체 외곽 질의는792→802개로 달라졌다. 이 결과는 최종 기하 수정을 생략해도 된다는 뜻이 아니며, 거리 예산 후보를 검토할 현재 근거다.

이번 비교는 세 별도 프로세스로 나눈다.

| 단계 | 소스/설정 | 계산과 판정 |
|---|---|---|
| frozen795 | 당시 r377 원소스 + 저장 legacy 설정 | 같은 r375 baseline795개 재계산. 원r377223개는 저장 기대 결과 exact재현도 별도 확인 |
| legacy795 | 승인 r388 r1 기하 전달 변경 + 저장 legacy 설정 | frozen795 전체 출력과 exact비교. r377 외572개에 원r386 후보를 대입해 미적용/출력불변 확인 |
| final223+15 | 같은 변경소스 + YAML 명시3치수 | r377223개에서 final기하 baseline→원r386 후보 비교, 마지막 입력에서 원15반례 수행 |

795개는 r377223+r371217+r364249+r279/r282106이다. 모든 과거 기록이 당시에도 r375 출력을 저장한 것은 아니다. 따라서 **전체795의 새소스 legacy 재현은 같은 동결r375 baseline과 대조**하고, 당시 r377에 기록된 실제 기대값 exact재현223을 별도로 보고한다. 다른 정책 시기의 저장값까지 전부 r375와 같다고 주장하지 않는다.

원 trace는 한 벌만 공유한다. 두 소스 arm은 원r377 동결소스와 r388 r1에서 승인/검증된 기하 전달 hunk만 포함한다. 다른 최근 공통 변경(r379·P0 등)을 임의로 가져오지 않는다. 이 소스 경계와 최종 공통 전체 트리에서의 실행은 구별한다. 원795입력 목록·15반례·percentile/비용요약 함수는 원r386 compare.py에서 함수 AST를 수정 없이 재사용한다. 후보 계보는11/12 r281/r266까지 보존한다.

## 고정한 알고리즘과 입력

`candidate.py`, `budget.py`, `test_candidate.py`는 원r386 archive와 **바이트 동일**이다. `.09` 같은 상수를 추가하거나 성공까지 반복하지 않는다. 단일 고정거리 접두 제안→원core1회→실제 전체 region/gap검사1회를 그대로 둔다. 10mm/최소질의10mm/공백폭/TTL/실제속도/두 조향/점유/물성/보호식은 바꾸지 않는다. 원 장면의 `D(v)=v*(dt+age+.1)+v²/4`, `v=max(measured,target)` 계약도 그대로다.

명시 final단계에서는 선택 YAML의 길이·폭·축거·float32 송신한계가 저장값과 **정확히 같아야** 진행한다. 실제 `replace`는 track/radius/wheel_width3필드뿐이며 반경은32.5mm로 원값과 같다. 저장 측정속도·원 목표·현재/이전 조향·경로·시각·epoch·센서 이력은 수정하지 않는다. 양수 기존 출력과 비대상은 원결과를 보존한다. r386 후보가 제안하는 추가 저속 목표 외에 baseline을 조작하지 않는다.

실제속도0.15의 제동거리 바닥, 범위밖0.151/역속도, 양쪽 후측방 사각, 복수 근접장애물, 좌/우근접반환, NaN, TTL/epoch/시각/조향/dt, 반대조향+양쪽사각의 원15반례를 새기하에서 그대로 수행한다. 후보 미적용 및 최종STOP를 요구하며, 실패를 해결하려고 반례나 보호선을 바꾸지 않는다.

## 보고할 결과와 비용

- 원795 baseline 재현과 legacy exact795, r377 저장기대 exact223, 기존572 비대상 불변을 별도 집계한다.
- legacy→final기하의 baseline 변화/기하만의 양수 회복과, final baseline→거리후보의 실제 적용/양수출력을 분리한다.
- 원양수/비대상 불변, 최종검사1회/경로·조향·시각 불변,15반례STOP를 각각 검사한다.
- 후보의 추가시간과 baseline시간, proposal geometry/classification·최종 core/region/gap, 비교용 합계를 p50/p95/max 및100/200ms 초과수로 기록한다. 모든 대상/시도/실제적용/비대상/반례를 구분한다.

벽시간은 같은 PC에서 직렬 계산한 대표 비용이다. ABBA나 실시간 명령 만료 시험이 아니며,100ms는 참고일 뿐 안전허가 판정선이 아니다. r375의 기존 고정재시도 뒤에 비용을 추가한 이번 저장비교를 운영 구조로 채택하지 않는다. 개선 없이 비용만 늘면 미채택할 수 있다. 채택 시 기존 `.15/.10` 재시도를 대체하는 통합 구조가 후속이며, 이번 준비에서는 재구조화하지 않는다.

결과 `comparison.json`은 원재현/기하효과/후보효과/반례/비용을 분리한다. 각 arm `report.json`에 마지막 입력 전체 진단과 요약, `rows.jsonl`에 전체 결과를 남긴다. raw행/입력/결과 압축은 기존 Git 제외 정책을 따른다. 미완성 단계·원실패를 새 성공으로 소급하지 않는다.

## 영구 순수검사 후보

`staged_tests/test_vehicle_geometry_contract.py`는 `tests/test_vehicle_geometry_contract.py`로 옮길 단일 파일이다. artifact/env/저장trace 의존을 없애고 실제 repo의 최종 YAML/코드를 검사한다. legacy 기본값/roundtrip, YAML→launch/ROS→세 측방 생성, 잘못된 명시기하 거절, preview 생략/선택, 물리한계와 float32 송신한계 관계 및 장치 I/O 전 거절을 다룬다. 현재 공통 tests에는 복사하지 않았다. 격리 bundle의 geometry/tests에만 넣어 원후보26검사와 새29검사, **총55검사 예상**을 준비한다. 아직 실행하지 않았으므로 통과 수가 아니다.

## 실행 인계

`build_bundle.py`는 원r386 archive해시·모든 입력/알고리즘과 r388 r1 archive/통과결과를 검증한 뒤 새 묶음을 만든다. Native 바이너리는 포함하지 않는다. 실행 담당자는 fresh `$HOME/it-arena-r386-final-*` 루트에서 native1회(120s), 순수검사1회(120s), 세 비교 각1회(각900s), 요약1회(120s)를 수행한다. 동일 native 바이너리를 양 arm에 사용하고 모든 소스/입력 해시를 전후 확인한다. ROS/Gazebo/장치/구동 출력은 없다.

고정 명령·archive/bootstrap 해시는 `HANDOFF.md`에 남긴다. 기존 루트/결과를 덮지 않으며 실패 시 후속단계를 중단하고 자기 자식만 종료·회수한다. Windows 준비에서는 AST/원문/ZIP/해시만 확인했다. 기본 채택·정체의 실제 해소·전체랩·실차 안전/속도 지속 증명은 아니다.
