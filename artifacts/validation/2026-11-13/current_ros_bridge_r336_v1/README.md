# 양수 감속 후보의 ROS 발행 연결 준비 r336

r334/r335 저장 실행의 부분 개선을 실제 ROS 노드와 연결하기 위한 후보다. 현재까지 공통/운용 기본은 바꾸지 않았다. 계획과 현재 확인의 병렬 슬롯, 실제 발행 완료 뒤에만 경로 보관, STOP/0·새 상태 우선과 현재 입력/원 경로 시한을 유지한다.

먼저 발행 어댑터의 순수 계약을 검사한다. `poll`이 반환했다는 이유만으로 이미 발행했다고 처리하지 않고 같은 콜백에서 실제 발행된 시각/속도/조향을 확인한다. 호출자가 발행하지 않았거나 다른 정지 출력을 발행했다면 후보를 소비하되 양수 경로를 보관하지 않는다. 보관하는 것은 이후 현재 재검사에 쓸 경로이며 과거 점유 허가가 아니다.

순수 어댑터12검사와 실제 ROS 노드·두 spawn 계산 자식의 STOP/RESET/종료1검사, 총13검사를 통과했다. 실제 ROS 구독에서 정지 출력을 받았고 두 자식은 강제 종료 없이 exit0이다. 최초 ROS 검사의 시계 fixture는 노드 메서드만 교체해 이미 결합된 clock을 바꾸지 못했으며 제출 이전 실패를 보존했다. ROSClock의 시험 시각을 설정하는 것으로 test만 수정했다.

`node_entry.py`는 명시 prefix·시뮬 시간에서만 설치한다. 완료된 후보를 공통 신호/센서/발행 흐름에 넘기고 실제 발행 결과를 같은 콜백에서 확인한다. 원 시각·조향과 일치하고 확인 속도 이하인 양수 출력만 이후 새 현재검사에 쓸 경로로 보관한다. 발행하지 않음/0/다른 조향/오래된 증거는 새 보관 근거가 아니다. `ros_delivery.py`·`ros_worker.py`는 과거 시험 모듈과 이름이 겹치지 않게 분리했다.

Gazebo의 대표 연결은 r337 실행 전 시설 이름 오류를 보존하고 r338에서 수행한다. 실물 모터·서보를 움직이지 않는다. 일부 속도 상한 조정/현재 계산의 이득을 전체 실시간이나 실차 안전으로 확대하지 않는다.
