# 원천/명령 예산을 먼저 확인하는 일정 후보 r325

r323의 발행 후 기준시각·보조 기하 일정 조건에, 현재 raw/명령이 계산 중 만료될 것으로 보이면 제출하지 않는 조건을 더했다. 일정100ms 예측은 실제 지연 상계나 발행 허가가 아니다. 완료 때 기존 현재 관측/기하/직전조향/STOP 검사를 모두 유지한다.4새 경계 검사·기존 r323/r286 검사를 근거로 저장15초를 비교했다.

| 조건 | 새계획 전용(r323) | r325 |
|---|---:|---:|
| 양수 발행 |87|95|
| 보조 양수 |0|13|
| 만료 합계 s |4.577|3.699|
| 발행 간격 중앙/p95 ms |151.65/153.29|151.25/181.50|
| 현재 원천 만료 거절 |3|0|

고정 계획146.74551065ms/현재81.304613ms 최소 비용·취득+20ms 가정에서 만료 합계가약19% 줄었지만 여전히3.699초 공백과 더 긴p95 발행 간격이 남았다. **문제 해결/운영 채택으로 보지 않는다.** 실제 Jetson 두 프로세스의 비용에서는 결과가 다를 수 있어 같은 저장 구간을 지연 주입 없이 한 번 대조한다. 새 주행/실물 구동은 하지 않는다. 원 r323/r324 실패·기본값은 그대로다.

## 실제 Jetson 저장 입력 비교

계산 하한 지연을0으로 두고 같은15초 입력을 별도2프로세스로 재생했다. 센서 도착의 `delay20`은 여전히 명시 가정이며 ROS/실물 센서 부하나 주행 증명이 아니다.

| 항목 | 새 계획만 | 남은 시간 확인 후보 |
|---|---:|---:|
| 양수 명령 | 124 | 119(보조13) |
| 갱신 간격 중앙/p95/최대 ms | 103.50/161.41/262.98 | 102.31/170.20/589.87 |
| 다음 갱신 전 이전 명령 나이 p95 ms | 244.14 | 259.88 |
| 200ms 초과 간격 개수 | 58 | 38 |
| 만료 구간 합계 s | 1.3823 | 1.4565 |

후보는 만료 횟수만 줄었고 총 공백·꼬리 지연은 개선되지 않았다. **미채택**이다. PC의 하한 지연 모형에서 약19% 감소한 결과를 실제 Jetson 개선으로 확대하지 않는다. 동일 실패를 반복하지 않고 실행 구조 문제는 미해결로 남긴다.

최초 묶음에서 `route_delivery.py`, 이후 동적 로딩 `terminal_boundary_r278_v1/candidate.py`가 빠져 초기화가 실패했다. 두 원문 오류는 `jetson_first_import_failure.log`/`jetson_dynamic_import_failure.log`에 보존했다. 이후 명시 동적 진입점을 포함한 의존성 폐쇄 목록과 `runtime_source_manifest_complete.json`142개 전후 일치를 확인했다. 실제 비교 `jetson_baseline_v2`/`jetson_candidate`는 자식 둘 모두 강제 종료 없이0으로 종료했다. 구동·포트·펌웨어·전력 설정 변경은 없다.


현재 기록에서 후보의 약590ms 최대 공백 구간은 양수 현재 확인5개가 연속으로 `new_plan_superseded_current_check` 폐기된 구간과 겹친다. 계획 중앙72.88ms·현재 확인51.36ms로 개별 중앙 계산보다 공백이 길다. 새 계획의 구체적인 비호환 필드/감속 여부는 기존 이벤트 로그에 없으므로 확정하지 않는다. 후속에서는 이 전이 이유를 먼저 계측하고, 보호 시한을 늘리기 전에 유효한 확인 결과를 반복 폐기하는 실행 의미를 검토한다. [시간·완료 근거](gap_diagnosis.json).
