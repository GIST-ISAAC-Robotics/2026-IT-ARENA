# r451 국소 GUARD 입력 복원과 동일 경로 0.1 m/s 재검사

## 결론과 범위

r441 정체 구간104행에서 기록된 GUARD 함수 입력을 복원하고 기존0.35/0.25/0.15 m/s 검사 결과를 대조했다. 원 이유·정수 표본 수는 같고 실수 비교 허용은1e-12다. 같은 함수에0.1 m/s만 제안했을 때104행 모두 수용했다. 자체 가림 꼬리는7.317~9.198 mm, 미관측/전면 가림 표본은0이었다. 10 mm 한계·원 signed 측정속도·경로/조향·측방 이력·원시 반환을 바꾸지 않았다.

이는 **기록된 국소 함수 입력 비교**다. r445에서 실패한 전체 plan 상태 재생을 성공으로 바꾸거나 실제 진행/완주를 증명한 결과가 아니다. 기존 helper의 정지 관측으로 물체를 고정 구조물로 분류하는 r450 대안은 느린 이동 상대 반례 때문에 채택하지 않았다.

## 연결

- `race_runtime_policy/guard_crawl.py`를 추가하고 기존 명시 runtime의 `released_plan.enabled`에 연결했다. 해당 runtime을 선택하지 않는 기본 제어는 변경하지 않는다.
- 기존 GUARD의 현재 양수 baseline이 있고 원0.35·0.25·0.15 검사 모두 자체 측면 가림 한계 때문에 거절된 경우만0.1을 한 번 더 검사한다. 원 선택 출력이 양수면 그대로 둔다.
- 이전 경로 기억·전면 가림·미관측·원 음수 속도·조건 밖 속도에는 적용하지 않는다. 실제 현재 속도가0.1보다 크면 예측에서 그 속도를 유지한다. 감속을 이미 끝냈다고 가정하지 않는다.
- 같은 `_guard_curve_at_cap`을 사용하므로 점유/관측·측방 누적 접근·현재 접근 검사를 생략하지 않는다. `seen/present/passed`와 GUARD 상태를 지우지 않는다.
- `selector_guard_crawl_retry`는 계산 진단이며 실제 부모 발행이나 진행의 증명이 아니다. 후속 대표에서 적용·진행·STOP·종료를 따로 확인한다.

## 검증과 수정한 오류

[원 국소 결과](result_v1/summary.json)는104행 모두 일치했다. [연결 결과 v2](result_integrated_v2/summary.json)는 원 검사 일치와104행0.1 수용에 더해 baseline reason/path 보존과 현재 경로 검사 지원을 확인했다. 각 scan/history/path/selector 상태와 guard anchor는 기록에서 가져왔으며 지도/actor 정답을 넣지 않았다. native 시간 성능이 아닌 Windows Python 수치 경로다.

독립 코드 검토에서 첫 연결이 실패한 parallel의 전체 detail을 전달하여 성공 baseline의 reason/behavior/path를 덮을 수 있는 문제를 발견했다. **원 selector 상태 키만 전달하도록 수정했다.** v1 통합 검사는 기하/속도만 비교해 이 결함을 찾지 못했으므로 실제 제어 연결 통과로 사용하지 않는다. 실제 `_guard_curve_at_cap`과 후속 `_present.supported`를 함께 확인하는 회귀를 추가했다. 분석의 baseline 행동 문자열은 원 전체 계획의 복원이 아니며, 실제 행동 의미 보존은 이 별도 함수 회귀에서 확인했다.

관련 기존76검사와 신규20검사 총96개의 고유 검사를 확인했다. 최초 실행 중 scripts 경로 누락1건, 새 실제 기하 fixture의2점 경로 오류1건은 원 로그를 남기고 해당 검사만 고쳐 재검증했다. 기본 Python의 pytest 부재는 기존 r449 격리 의존성을 재사용해 해결했다. 전역 설치는 하지 않았다. `pytest_v1.log`~`pytest_v5.log`와 원 통합 v1은 보존한다.

공통 변경은 신규 helper·기존 runtime 연결·신규 회귀3파일이다. 주행용 기록 보완 r449 및 launch의 기본OFF 기록 옵션 전달은 별도 변경이며 다음 주행의 동결 차이에 함께 포함한다. 다음은 동일 r441 조건의 제한 대표1회이며, 성공할 때까지 반복하거나 판정선을 바꾸지 않는다.
