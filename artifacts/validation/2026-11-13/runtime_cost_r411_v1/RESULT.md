# r411 최신 공통 정책의 Jetson 계산 비용

2026-11-13. **380회 계산·동일 장치 내 OFF/ON 불변 확인·정상 회수를 완료했다. 과거 x86 출력과의 정확 일치는 실패했다.** 원 `passed=false`를 유지한다. 이번 결과는 최신 공통 정책과 최종4가림 저장 입력의 단회 직렬 비용이며 실제 센서/ROS와 함께 돌리는 실시간 주행 결과가 아니다.

## 입력과 실행

[원 계획](PLAN.md)의 복원 가능한 plan prefix37개와 독립 current153개를 각각 OFF/ON으로 한 번씩 계산했다. 원 중복11계획 사용행과 복원 불가 후반217계획을 새 호출로 채우지 않았다. current에는 당시 원 계획 출력을 사용했고 새 prefix 출력을 섞지 않았다. 공통 정책23파일과 선택 경계는 r406과 같으며 r410/r414 후보를 포함하지 않는다.

첫 Jetson 시도는 환경 메타데이터 `read_text()` 오류로 실제 계산 전에 종료했다. [revision_env_v2](revision_env_v2/README.md)는 부수 환경 정보 읽기만 보완했고 원157소스 중156개·입력 계약은 동일하다. 새 WSL smoke80호출이 통과한 뒤 새 Jetson root에서380호출을 수행했다. 회수 시 장치 발견이 한 번 실패했으나 **완료된 계산을 다시 실행하지 않고 ZIP 회수만 재시도**했다. 원 실패·suffix a와 새 suffix b를 모두 보존한다.

새 [실행 영수증](revision_env_v2/remote_result/extracted/execution.json)의 source157개 불변, helper/native/import/계산의 exit0, 계산 child4개 exit0·강제종료 없음·잔여 없음이 확인됐다. 센서 포트·모터/서보를 열지 않았고 전력·클럭 설정을 바꾸지 않았다. 결과 ZIP의 원격/로컬 해시도 일치했다.

## 계산 비용

`Evaluator.__call__`의 입력 복원·scene·정책·결과 freeze를 포함한다. Lane의 감사용 직렬화/해시·파일 기록 비용은 별도이며 운영 IPC 비용으로 대신 쓰지 않는다.

## 정확 일치 실패의 분류

[재계산 없는 분류](difference_review.json)는 원 비교의 허용오차나 결과를 변경하지 않는다.

- 명령/측정상태 분류94개는 모두 조향 수치였다. 최대 차이는 **2.8311×10⁻¹⁵ rad**이며 기존 비교기에서는 동일로 인정된다. 속도·모드·정지/허가 boolean·사유·시각 차이는 이 코퍼스에서 나오지 않았다.
- 경로 좌표6,347개 차이의 최대는 **2.8866×10⁻¹⁵ m**, 기타 수치105개 차이의 최대는 **3.7748×10⁻¹⁵**다. 모두 기존 비교기 범위 안이었다.
- 기존 비교기가 실패한 것은 current33개 출력의 **region count70개**였다. `queries`, `masked_left`, `masked_right` 개수가 최대3개 달랐다. `unobserved`나 최종 허가 변경은 없었다. 이를 임의로 비교 대상에서 빼지 않았다.
- `motion_queries()`는 곡선/차체 표본을 만들고 `unique_xy()`로 **반올림 없는 정확 중복 제거**를 한다. 기하의 아주 작은 차이가 합쳐지는 좌표 수에 영향을 줄 수 있는 구조다. 이것이 개수 차이의 유력한 설명이지만 이번에 각 query 배열의 생성 과정을 별도 계측해 원인을 확정한 것은 아니다.

전체 exact 비교에서는222행이 다르다(계획OFF/ON 각36, currentON150). 위 작은 부동소수 차이까지 포함한 수다. 동일 ARM에서 계획 OFF/ON 동일, current 비대상 불변·단일 후보 적용 등 등록된 불변 조건은 통과했다. **이 제한 코퍼스의 명령 차이가 사실상 없었다는 확인과 모든 장치/입력의 동등성 증명은 다르다.**

## 다음에 사용할 결론

최신 공통 코드의 기본 계산은 Jetson에서 완료되며 current p95는 약92 ms다. 후보가 적용된168 ms 한 건과 계획/current의 경쟁·센서·영상·독립 보호 비용을 고려하면 전체10 Hz/명령 만료를 통과했다고 할 수 없다. 이번 입력은 시뮬레이션 원본으로 실제 encoder나 취득시각의 검증을 대신하지 않는다.

같은 직렬 시험이나 이미 완료한 센서 수신을 반복하지 않는다. 최종 기하의 주행 정체와 실장 프로필/실행 진입 연결을 먼저 보완하고, 실제 운영에 쓸 구성이 정해졌을 때 필요한 결합 부하를 확인한다. r406의 정체·전체 실패와 이전r382 실패는 그대로 남긴다.
