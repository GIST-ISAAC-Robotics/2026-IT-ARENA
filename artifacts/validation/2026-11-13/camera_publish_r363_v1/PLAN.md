# r363 카메라 선택 발행20Hz 비교

r360의 실제 센서20초+별도 저장 계산31초와 같은 비구동 구조에서 한 번만 비교한다. 카메라 pipeline은1280×720/60Hz 그대로이며 appsink에서 받은 최신 프레임 중20Hz 일정에 맞는 프레임만 메모리 복사·ROS 발행한다. 밀린 발행을 몰아서 수행하지 않고 의도적으로 건너뛴 프레임 수를 별도 기록한다. 기본 동작은 전체 프레임 발행 그대로다.

새 `/home/q/it-arena-r363-20261113`에는 r358/r360에서 동결한 `src/`, `scripts/`, `config/`만 복사하고 카메라 bridge와 실행 CLI 두 파일을 덮어쓴다. **원 r358 디렉터리와 결과는 수정하지 않는다.** 별도 계산은 원 r358 소스/입력에서 수행한다. 두 소스 manifest를 전후 대조한다.

실제 gyro/C1 수신, 영상 의도적 생략/발행 후 누락, 인식 비용과 정상 종료를 확인한다. 기존 r360은 자연 변동이 있으므로 단일 비교에서 계산 성능 개선의 인과성을 단정하지 않는다. 실제 영상이 더 적게 발행되더라도 취득 프레임 손실과 ROS 전달 누락을 합쳐 표시하지 않는다. 시계 검증·엔코더·양수 실물 제어·보호층 전체 운영 완료는 이번 범위가 아니다.

기존 UART 스트림 시작/종료만 허용하며 모터/서보/펌웨어/전력은 변경하지 않는다. 종료는 자체 프로세스만 회수하고 포트 반환·IMU inactive·C1 STOP·카메라 NULL을 확인한다. 원시 센서/수신 상세는 로컬 `remote_result/`에 보존하고 Git에서 제외한다.
