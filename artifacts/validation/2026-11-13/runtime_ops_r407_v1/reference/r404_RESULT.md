입력은 `host_estimated_v1`, 시간 검증 표시는 false다. 센서 위치·축·취득시각의 정확도, 실제 모터/서보 출력과 차체 정지는 이번 결과가 아니다. 실제 엔코더가 없어 `WAIT_GREEN`/`SENSOR_STOP`을 포함한 0명령 연결만 확인했으며, 전체 경로 계산의 처리율이나 양수 주행을 입증하지 않았다. 별도로 남아 있는 Jetson 10Hz 처리 미달과 최종 기하의 코너 정체는 그대로다.

원시 실행·수신 기록은 Git 제외한 `remote_result/extracted/`에 보존한다. `execution.json`, `actual/supervisor.json`, `actual/node/summary.json`과 센서별 `summary.json`을 대조했다. 이 결과로 개별 센서 기초 수신을 다시 반복하지 않고 최종 기하의 제한 주행과 운영 연결을 이어간다.

저장 수신 자료의 [집계](receipt_analysis.json)에서 C1 첫/마지막 점의 추정 나이는 p95 129.83/29.87ms, IMU 추정 나이는 p95 16.04ms다. 카메라의 호스트 수신→노드 전달은 p95 29.79ms, 영상 처리 p95 49.52ms다. 모두 노출/센서 취득의 절대 지연을 검증한 값은 아니다. 0명령 발행 간격은 보호층 전/후 p95 27.30/25.10ms·최대56.44/49.14ms다. 이 구간은 전체 경로 계산 부하가 없었으므로 주행 시 처리율로 확대하지 않는다. 보호층의 `motion_waiting`은 없는 엔코더를 대신 만들지 않은 결과이며, 준비·종료를 포함한 `missing_input`/`stale_input` 표본도 원 자료에 남겼다.
