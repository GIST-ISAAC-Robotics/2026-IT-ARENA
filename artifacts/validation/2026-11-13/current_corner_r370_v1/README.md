# 첫 코너 정체: 현재 차체 옆 공백과 상대 거리 검사

r364 원 현재 검사249개를 전체 동일하게 재현했다. 끝부분17개 표본에서 목표0.15/0.10/0.05m/s를 비교했으나 기존 정책은 모두 거절했다. 원문 [probe.json](probe.json)과 추가 거리 진단 [probe_relative.json](probe_relative.json)을 구분한다.

마지막 표본의0.15m/s는 차체 옆으로12.67mm 나가는 질의가 있어 기존10mm 범위를 벗어났다.0.10m/s는8.82mm로 그 범위 안이지만 무반환 구간 양끝 거리11.038m/0.5904m 중 후자가 고정0.6m보다 작아 거절됐다. 해당 질의의 광선 원점 기준 최대 반경85.99mm와 기존 padding115mm의 합은200.99mm였다. 따라서 이 표본은 바로 옆 장애물 접촉을 검출한 결과와 구분된다. 구간 안에 숨은 얇은 물체가 없다는 증명은 아니다.

명시 선택형 `relative_neighbor=True`는 기존0.6m 고정값 대신 **모든 해당 이동 질의의 최대 반경 + 모든 현재 광선의 최대 padding**을 이웃 거리 조건으로 쓴다. 기본은 기존 정책이다. 실제 속도≤0.15m/s·목표≤0.10m/s, 차체 옆10mm·후방 방향·6° 공백·5cm 국소 폭과 원시 값/시각 일치·가까운 실제 점유 검사를 유지한다. 미관측 표본 수를 지우거나 자유 공간으로 바꾸지 않는다.

시험 [candidate.py](candidate.py)는 현재 SOLO 계획의 원0.15m/s 검사까지 거절된 경우에만 같은 조향0.10m/s를 다시 검사한다. 보관 허가를 재사용하지 않고 현재 원천/실제 속도/직전 조향/전체 이동 영역을 사용한다. 앞차·GUARD/RELEASED·일반 STOP이나 큰 마스크를 허용하는 수정이 아니다.

[저장 대조](comparison.json)에서 r364의249개 중110개가0→0.10m/s로 바뀌었고 나머지139개 및 과거 교통106개는 출력이 같았다. 초기 합성 시험은 질의의 각도를 바꾸면서 무반환 인덱스를 그대로 둔 fixture 오류4개가 있었고, 같은 광선 사이의 점으로 수정했다. 최종 [60회귀](final_tests.log)에서 실제 근접 반환·padding 증가·넓은 공백·전방·NaN/근거리 유한값·과속·음수·다른 상태·조향/시각 변경 거절을 확인했다.

실제 주행 효과와 Jetson 실행 비용은 이 저장 비교가 증명하지 않는다. [r371 제한 주행 계획](../relative_body_cad_drive_r371_v1/PLAN.md)에서 새 CAD 조향과 함께 연결하며 기본 운영 프로필에는 자동 활성화하지 않는다. 원 실패/입력/소스 보관본은 유지한다.
