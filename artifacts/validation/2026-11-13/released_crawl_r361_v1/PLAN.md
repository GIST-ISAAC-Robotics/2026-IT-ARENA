# RELEASED 자체 가림 꼬리의 제한 저속 후보 — r361

## 범위와 사전 기준

r353 확정 기하 저장 입력을 사용한다. 축거128mm·계획 외곽207×150mm,
native C1 10Hz·확정 r347 장착·구형610 신호·ID20/30 누락·road_level을 보존한다.
r349 구기하 결과는 이 후보의 통과 근거로 쓰지 않는다. 원 r353 파일은 수정하지 않는다.

기본 비활성인 `candidate.enabled()` 명시 범위에서만 계획 선택기를 바꾼다.
RELEASED/non-retained·현재 측방 위협 없음·현재 양수 G1 경로/fully_observed·
선택기에 전달된 실제 속도0–0.15m/s에서 기존0.35/0.25/0.15m/s가 모두
일반 미관측/전방 가림 없이 자체 가림 꼬리 이유로 거절된 경우에만0.10m/s를 한 번 검사한다.
현재/직전 조향·실제 속도·스캔/시각은 원 함수에 그대로 전달한다.
10mm 꼬리 한계·unknown 분류·보호층·물성·신선도 기준은 바꾸지 않는다.

## 검증 순서

1. 기본 비활성/범위 외 불변, 기존 세 후보 후에만 검사, 실제 운동/시각 불변,
   unknown/전방 가림/큰 가림 꼬리/입력·상태·경로 반례를 단위 검사한다.
2. r353 399개 계획 입력을 원 순서/초기화로 재생하고 원 출력과 차이를 보존한다.
   후속 코드와 직렬 재생의 기존 차이를 후보 효과에 섞지 않는다.
3. 동일 원 상태의 shadow 비교와 별도 상태의 선택형 재생을 구분한다.
   마지막173회 실패 구간에서 새 후보의 전체 영역 결과와 명령 차이를 확인한다.
4. 대표 현재 입력 검사도 가능하면 연결하여 양수 계획이 실제 현재 검사에 도달할 때의
   거절 여부를 확인한다. 저장 입력의 출력은 새 폐루프 주행이나 실시간 성능 증명이 아니다.

WSL Python 순수 검사만 허용한다. Gazebo/ROS/Jetson/센서·공통 src 수정·게시를 하지 않는다.
파일/입력 해시, 실패/원 로그와 테스트 결과는 이 폴더에 보존한다.
