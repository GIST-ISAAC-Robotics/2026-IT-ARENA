# 현재 확인 시작 위상 r323 — 미채택

원 r286의 발행/현재 입력 시각을 대조하고, 새 발행 이후 reference에서만 현재 확인 시작 + 보관 경로의 남은500ms 중100ms 일정 여유 조건을 추가한 후보다. 명령/원천 TTL이나 실제 결과 적용 검사는 변경하지 않았다.21관련 검사를 통과했다.

첫 observed 비교는 두 구현 모두 양수0이었다. r286은 delay20 조건이었으므로 동일 조건 비교에 실패한 실행을 보존하고,6호출 진단에서100ms 기록 사이 motion_stale를 확인했다. 조건 오류/가정은 PLAN.md에 명시했다. 관측 누락을 새 데이터로 채우지 않았다.

같은 delay20·계획146.74551065ms/현재81.304613ms 최소 시간의15초 저장 비교는 다음과 같다.

| 항목 | 새계획 전용 | 후보 |
|---|---:|---:|
| 양수 발행 |87|86|
| 보조 확인 양수 |0|13|
| 발행 간격 중앙/p95 ms |151.65/153.29|151.34/303.75|
| 양수 명령 만료 합계 s |4.577|4.742|
| 현재 스캔 만료 거절 |3|12|

경로 기하 만료는 줄었지만 오래된 현재 스캔의 처리 후 만료와 긴 발행 공백이 남아 **채택하지 않는다**. 두 실행의 자식은 정상 종료했다. ROS/실물/새 주행에는 연결하지 않았다. 다음 r324는 같은 실패 반복이 아니라 완료 스캔에 맞춘 계획/현재 확인 제출을 비교한다.
