# r323 발행 후 입력 위상과 보조 확인 예산

r286의 입력을 재검토하면 일부 보조 확인은 새 양수 발행 직후에도 발행 이전 reference(50Hz 양자화)를 사용했다. 결과가 빨리 와도100ms 최소 적용 간격을 기다려 명령 기준시각이 더 낡는다. 또한 남은500ms 경로 수명 안에 끝나기 어려운 보조 확인이 현재 lane을 점유해 새 계획 소비와 다음 계획 제출까지 늦췄다.

후보는 r286의 동일 SOLO/비감속 의도 조건을 그대로 유지하고, (1) 새 입력 reference가 마지막 실제 발행 이후일 때만 현재 확인을 제출, (2) 보관 경로는 reference−원 경로 시각+100ms 일정 예산<500ms일 때만 제출한다. 일정 예산은 지연 상계/발행 허가가 아니며 실제 완료 때 기존 시각·영역·조향·세대 검사를 그대로 한다. 새 계획의 즉시 STOP/감속/상태 전이는 그대로다. 기본값/ROS/실물 연결 없음.

비교는 같은 저장15초·계획146.7455ms/현재81.304613ms 최소 비용, 취득+20ms 도착 가정(delay20)/최신 스캔 방식이다. 새계획전용과 비교해 양수 갱신·만료 합계가 나아지는지 확인한다. 기록된 차량 운동은 새 출력에 반응하지 않으므로 주행 증명이 아니다. 실패하면 원인 변화 없이 재실행하지 않는다.

앞선 Fable5.2/high 자문은5시간91% 경고 뒤 최종답변 없이 한도 종료했다. 구현 추천/검증이 완료된 것으로 취급하지 않는다. 이 후보는 GPT의 원 기록 분석/설계다.

## 첫 조건 선택 오류

첫 비교는 observed 모드로 실행해 양쪽 모두 양수0이었다. 이는 r286 원 비교가 delay20이었다는 것을 대조 전에 확인하지 않은 실행 조건 오류다. 저장 snapshot의100ms 기록 간격에서는 센서의 실제 최초 도착을 알 수 없고, observed는 중간 tick에서 motion_stale로 정지한다. 첫 결과/6호출 원인 기록을 보존한다. 같은 r286과 비교하는 후속은 delay20 가정과 같은 비용으로 수행하며 이20ms를 실제 전달 지연 측정으로 부르지 않는다.
