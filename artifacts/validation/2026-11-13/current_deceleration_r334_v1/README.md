# 양수 계획 감속 상한과 현재 검사 완료의 분리 r334

r329의 실제 Jetson 진단에서7/24전이는 동일 FOLLOW/벽/선택 상태인데 새 목표속도가 낮다는 이유만으로 현재 검사를 폐기했다. 새0명령·상태 변경과 달리, 양수 감속은 더 큰 속도로 현재 점유를 확인한 같은 조향 명령의 속도 상한을 낮추는 방식으로 반영할 수 있는지 비교한다.

후보는 같은 양수 FOLLOW 의도에서만 현재 검사를 마치게 하고, 도중에 받은 작은 목표속도의 최솟값으로 완료 명령을 제한한다. 조향·현재/원 경로 시각·점유 증거·기하 수명은 바꾸지 않는다. 상한만 보관하며 새 경로를 검사했다고 주장하지 않는다. STOP/0·상태/벽/epoch 변화는 기존대로 즉시 폐기한다. 독립 보호를 통과해야 하는 경계도 유지한다.

새 계획 자체의 즉시 조향 변경을 반영하는 기능이나 실차 안전 보장은 아니다. 우선 단위 검사와 같은 저장 입력의 실제 두 프로세스 비교를 수행한다. 공통 코드/ROS/운용 기본에는 연결하지 않는다. r325 미채택 후보와 새 계획만 사용하는 기준을 보존한다.

## 실제 Jetson 저장 입력 결과

PC/Jetson 각18검사를 통과했다. 첫 PC 검사는 비교 대상에 나중에 추가되는 진단 필드까지 동일하다고 잘못 요구한1건이 실패해 원 로그를 보존하고 비교를 수정했다. 같은 r325의142개 고정 소스와 추가4개 후보 파일, 같은15초 입력·`delay20`·실제 계산 하한0을 사용했다. 원 소스/후보146개 전후 불변, 두 자식 정상 종료다. 모터·센서 포트·ROS·전력 설정은 사용/변경하지 않았다.

`comparison.json`·각 `report.json`·`caps.json`·원 이벤트를 보존한다. 이번은 ROS 없는 저장 입력 실행이며 이전 계획/현재 검사 구조의 비교다. 현행 전체 ROS 통합/장착 주행에는 아직 채택하지 않는다. 후속은 같은 성공을 반복하기보다 다른 교통 상태/명시0 전이와 실제 노드 연결의 적용 순서를 확인한다.
