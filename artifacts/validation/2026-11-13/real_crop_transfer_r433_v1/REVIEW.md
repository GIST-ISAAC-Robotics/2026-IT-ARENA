# 추정 취득 시각의 실물 이관 사전 검토

2026-11-13 GPT 주 담당의 읽기 전용 검토다. 시뮬레이션 실행 중 공통 소스/실물 장치는 변경하지 않았다. 본 문서로 실물 후보를 활성화하거나 취득시각이 검증됐다고 간주하지 않는다.

## 현재 실제 연결과 남은 차이

- `execution_environment.py`의 `hardware_runtime_candidate_v1`은 실제 ROS clock·`host_estimated_v1`·`timing_verified=false`를 요구한다. `scene_motion._measurement_transforms`는 실제 native 배열의 `unverified_estimate`를 보존한 채 이동 보정을 수행한다. 따라서 실물 전체 경로가 단순 시각 미검증만으로 막혀 있는 것은 아니다.
- r404는 이 경로에서 C1/RGB/IMU 수신과0명령까지 확인했다. 엔코더 없이 양수 주행을 확인한 결과는 아니다.
- `crop_edge_selection.validate_node_selection`, `runtime_node_backend.validate_corner_selection`, `Evaluator` 및 `crop_current_scope/proof`의 새 경계 보완은 별도로 시뮬레이션 시각을 요구한다. r426의 코너 회복 결과가 나오더라도 이 보완이 실물에서 그대로 동작한다고 말할 수 없다.
- `C1SampleClock`은 추적 모델을 사용하지만10ms anchor residual과5ms publication wait는 내부 일관성 기준이다. 주석에도 실제 취득시각 오차 상한이 아니라고 명시돼 있다. 이 값을 검증된 센서 오차처럼 사용하지 않는다.
- `occupancy_timing.per_ray_padding`은 고정 거리 여유와 보존된 취득 후 나이×상대물체 이동 상한을 적용한다. 취득 추정의 절대 오차가 검증됐다는 뜻은 아니며, 별도 시각 오차/회전 오차를 자동으로 포함하는 항은 아니다.

## 다음 구현의 최소 범위

먼저 r431에서 최신 기하의 실제 코너 통과/정체 이유를 확보한다. 현재 대표가 실패하면 같은 후보를 실물로 넓히기보다 실패 원인이 계획/현재 검사/독립 보호/구동 중 어디인지부터 분리한다.

보완이 필요하고 대표 진행 근거가 확보되면 `verified=true`로 바꾸는 대신 기존 `host_estimated_v1`을 그대로 가진 명시 운용 선택으로 검토한다. 부모의 같은 원 scan·세대·원시 배열 비교, 현재 이동 영역/실제 반환 장애물 검사, 보수적인 저속 후보와 독립 보호를 유지한다. 시각/회전 오차의 가정은 저장 입력 민감도로 명시하고 실제 정확도 보증으로 쓰지 않는다. 기존 시뮬레이션 경로와 실물 선택 경로의 차이가 코드·로그에 남아야 한다.

지금 사람 없이 가능한 일은 해당 선택 경계/입력 보존의 코드 준비와 실제 저장 배열·기존 운동 입력을 이용한 제한 비교다. 센서 이동으로 측정해야 하는 절대시각/축/장착 오차와 실제 모터·서보/엔코더 출력 확인은 조립 뒤 최소 확인에 남긴다. 새로운 광범위한 센서 재시험이나 하드웨어 추가를 선행조건으로 만들지 않는다.

검토 범위는 다음 작업의 경로 확인이다. 공통 수정·후보 채택·실물 주행 성공은 모두 아직 아니다.
