# Fable 5.2 자문 원문 — 2026-11-13

모델 claude-fable-5-2 · effort high. 자문이며 구현/실차 근거가 아닙니다. 개인 호칭만 제거했습니다.

결론부터 말씀드리면 **r316은 주 해법으로 채택하지 않으시기를 권합니다.** 정체는 조향 선택의 시간 불안정보다 앞 단계의 두 원인에서 생기며, r316은 그 결과로 나타난 증상만 저속에서 덮습니다.

## (a) 구조적 원인과 미확정 사항

**관측 1: 첫 정지는 점유 정지가 아니라 경계 미확인 정지입니다.**

r314 `run1/follow_decisions.jsonl`의 20.3–23.0 s 구간을 읽기 전용으로 재생해 확인했습니다.

| 시각 | 관측 |
|---|---|
| 21.12–21.20 s | 속도 1.10–1.22 m/s, 명령 1.0, clearance .88–.96 |
| 21.12 s (스캔 21.003) | 경계 후보 `wall_segment_short`, 미채택. 기억 경로로 주행 |
| 21.22 s (스캔 21.103) | 다시 `wall_segment_short`. 마지막 채택 경로(20.903)가 `memory_ttl_s=.30`을 넘겨 `follow_boundary_unconfirmed`, 약 1.1 m/s에서 명령 0 |
| 21.32 s | 채택 후 `follow_release_wait` |
| 21.52, 21.62 s | 다시 `follow_boundary_unconfirmed` |
| 21.72 s | 재채택. 차량은 기둥 반환 바로 옆 약 (0.13, 0.29) m에서 v≈0 |

- 해당 분기는 `local_follow.py` `_baseline_command`의 `carried is None` → `_hold('follow_boundary_unconfirmed')`입니다.
- r316 재생에서도 `follow_boundary_unconfirmed`는 기준과 똑같이 18회입니다(`facility_arc_stability_r316_v1/replay_summary.json`). r316은 이 층을 건드리지 않습니다.

**관측 2: 정지 자세에서 경로와 기둥의 여유가 padding 톱니 안에 있습니다.**

- 명목 경로와 가장 가까운 도로 안 반환의 거리는 **0.187–0.190 m**입니다.
- 필요 거리는 차폭 절반 .075에 광선별 padding을 더한 값입니다. padding은 스캔 나이 .117 s에서 .099, .197 s에서 .139이므로 필요 거리는 **.174 → .214 m**로 움직입니다(`occupancy_timing.py` `per_ray_padding`).
- 그래서 판정이 스캔마다 뒤집힙니다. clearance는 .92–.96(새 스캔, PP각 약 .32) → .32–.36 → .24–.28 → .20(`follow_steer_in_place`) 순으로 줄고, 다음 스캔에서 다시 .32 rad로 돌아갑니다.

**추론: 원인은 두 층입니다.**

1. **코너 진입의 2스캔 경계 탈락**이 흐르던 접근을 기둥 옆 완전 정지로 바꿉니다. r309/r306은 지속 탈락을 없앴지만 이 과도 탈락은 남았습니다.
2. **경로가 벽 오프셋만으로 만들어집니다.** `observed_path` → `local_path`는 벽 반환만 쓰고, 도로 안 반환은 경로를 옮기지 못합니다. 점유 검사(`swept_limit`)는 거부만 할 뿐 횡방향 자유도가 없습니다. 차체와 기둥의 간격 약 .11 m가 padding 범위 .099–.139 안에 있으므로, 어떤 임계 판정을 두어도 10 Hz로 흔들립니다.

**미확정**

- 21.003/21.103 스캔이 `wall_segment_short`가 된 이유가 기둥의 벽 분절인지 코너 기하 자체인지 확인하지 못했습니다.
- 탈락 없이 주행 중이었다면 통과했을지 모릅니다. r313 `diagnosis.json`의 21.2 s 행에서 조향 ≥.198 rad이면 clearance가 .24이므로 점유 감속이 걸렸을 가능성이 높다고 보지만 추정입니다.
- r310에서도 같은 탈락 순서였는지는 직접 보지 않았습니다.
- 실기 지연에서의 스캔 나이 범위를 모릅니다.
- marker20 위치는 사용자 가정이며 도로와 일부 겹칩니다(`signal_post_revision_r291_v1/fixture.json`: "previous provisional centre +372.5mm upstream of ID20").

## (b) r316 평가와 대안

**타당한 점:** 스캔 수명 끝에 게이트가 적용할 padding으로 미리 고른다는 발상은 원리상 옳고, 톱니 반전의 직접 원인을 정확히 짚었습니다.

**허점**

1. 0–.25 m/s 정체 상태 전용입니다. 차는 여전히 멈췄다가 기어가므로 속도 연속성(ADR 0028)과 어긋납니다.
2. 1층(경계 탈락)을 다루지 않습니다.
3. 예측을 실제 수명 끝 나이가 아니라 스캔 길이에 묶었습니다(`min(.10, span)`, 가드 `0<span<=.12`). 실패한 1건의 시험(120 ms 부동소수 경계)이 이 하드코딩의 취약성을 보여 줍니다. 실기 지터에서는 조용히 비활성화될 수 있습니다.
4. `__globals__['pursue_path']` 치환으로 r309+r306+r313 위에 네 번째 wrapper를 쌓습니다. r313에서 이미 연결 오류가 한 번 있었습니다.
5. 26/30 s의 틀어진 자세에는 후보가 없습니다(r313 README).
6. positive 669→887은 고정 입력 재생이며 궤적 증명이 아닙니다.

**대안 비교**

| | r316 | 대안 1: 관측 반환 인지 경로 이동 | 대안 2: 선택 유지(latch) |
|---|---|---|---|
| 내용 | 선택 전용 예측 padding | 경로점과 관측 반환의 거리가 차폭 절반 + 수명 끝 padding + ε(약 .24 m)보다 작을 때만 경로를 반환 반대쪽으로 밀기 | 정체 중 고른 완화 조향을 재개 확인까지 유지 |
| 적용 층 | 제어(PP wrapper) | 경로 생성 뒤, PP 앞 | 제어 |
| 속도 범위 | ≤.25 m/s | 전 속도 | 정체 상태만 |
| 원인 해결 | 증상(반전)만 | 2층 원인 | 증상만, r316보다 단순 |
| 기존 판정 | 불변 | 점유·STOP·TTL·재개 불변. 실제 반환만 사용, 미관측 채움 없음 | 불변 |
| 위험 | 실기 나이 의존, wrapper 누적 | PP가 코너를 안쪽으로 자르므로 이동량이 PP 호에 충분한지 재생 확인 필요 | 낡은 조향 유지 |

대안 1을 권합니다. 여기서 필요한 이동량은 약 3–6 cm이고, 침입 반환이 없는 곳에서는 무동작이므로 기존 저장 주행이 그대로 재현되어야 합니다. 대안 2는 통과만 급할 때의 최소 임시책이며 주 해법으로는 권하지 않습니다.

## (c) 권장 구현 범위와 다음 검증

**구현(작게)**

1. 대안 1을 `local_follow.py`의 `observed_path` 뒤 한 곳에 솔로 경로 선택형 플래그로 넣습니다. wrapper 누적 대신 소스의 한 함수로 두고, r313/r316은 연결하지 않습니다.
2. 1층은 먼저 진단만 합니다. 21.003/21.103 스캔의 `wall_segment_short` 원인을 고정 입력으로 한 번 분리합니다(기둥 반환을 진단용으로만 제외해 `local_path` 결과 비교). TTL 연장이나 STOP 완화는 하지 않습니다. 수정 여부는 진단 결과와 아래 주행 결과를 보고 정하시면 됩니다.

**검증(두 번)**

1. 고정 입력 재생:
   - 침입 반환이 없는 기존 주행에서 판단이 동일한지.
   - r314 입력의 21.7–23.0 s 정체 자세에서 PP 희망각이 약 .27 rad 이하로 내려가 스캔 수명 내내 clearance ≥ .28이 유지되는지. 제 기하 계산으로는 .32 rad(R≈.407 m)은 간섭, .27 rad(R≈.488 m)은 간신히 통과입니다.
2. 같은 시설·0.25 RTF 제한 주행 1회. 판정은 ID20 통과와 `follow_steer_in_place`/`follow_release_wait` 반복 소멸입니다. `follow_boundary_unconfirmed` 횟수는 따로 기록합니다. 탈락으로 한 번 멈추더라도 재출발해 통과하면 2층이 해결된 것이고, 남는 것은 연속성 문제(1층)로 분리됩니다.

## (d) 묶음 종료 시점

**"구현 1회 + 재생 1회 + 제한 주행 1회"로 시간 상한을 두시기를 권합니다.**

- 통과하면 1층 진단 결과만 기록하고 종료합니다.
- 실패하거나 새 특수 조건이 추가로 필요해지면, 한계를 보고서에 남기고 MCU 실제 출력·연산 지연 통합으로 넘어가시는 편이 낫습니다.

이유는 두 가지입니다.

- 이 문제의 여유는 2–4 cm 규모이고 스캔 나이 범위 .117–.197 s에 직접 달려 있습니다. 그 범위는 실제 지연이 통합되면 바뀌므로, 그 전에 cm 단위로 더 맞추면 시뮬 시계에 과적합됩니다.
- 기둥 위치가 가정값이고 도로를 일부 침범합니다. 실제 배치가 확정되기 전에는 이 코너 전용 조정의 가치가 낮습니다.
