# r357 깊이 지지·자체 가림의 광선 탐색 공유

2026-11-13. r356의 개별 native 분류와 같은 입력에서 비교했다. 두 분류에 반복되던 가까운 광선 탐색만 공유하고 판정식은 각각 유지했다.

- 깊이 지지: 원점 겹침 거절·순환 인접성·기존 거리 여유를 유지한다.
- 자체 가림: 미관측 배제·비순환 인접성·가림 광선 필요 조건을 유지한다. 가림을 자유 공간으로 바꾸지 않는다.
- 기본 Python 경로는 유지하며 명시 `native_v1`에서만 새 C++ 계산을 사용한다. 표본·광선·보호 한계는 줄이지 않았다.

| 환경 | 회귀 | 현재 검사 중앙, ms | p95, ms | 최대, ms | 220개 전후 전체 출력 |
|---|---:|---:|---:|---:|---:|
| PC WSL | 253 통과 | 15.415 → 13.782 | 27.669 → 24.769 | 35.370 → 31.440 | 220 동일 |
| Jetson | 101 통과 | 57.402 → 51.031 | 97.746 → 85.343 | 128.309 → 111.396 | 220 동일 |

동일 입력마다 두 방식을 번갈아 먼저 실행했다. Jetson에서 원 PC 기록과는 52개 표본 수 진단 차이가 남지만 분리/공유 방식 사이에는 차이가 없다. 원 기록 대조 실패를 새 성공으로 소급하지 않는다. 동결 파일 746개의 실행 전후 해시는 유지됐다.

입력 복원·동시 경로 계획·ROS·센서 I/O를 제외한 현재 검사 비용이다. 실제 명령 갱신, 주행 완주 또는 실차 안전의 증거가 아니다. 다음은 r353 센서 기록을 두 계산 프로세스로 시간 재생하여 갱신 공백을 대조하는 것이다.
