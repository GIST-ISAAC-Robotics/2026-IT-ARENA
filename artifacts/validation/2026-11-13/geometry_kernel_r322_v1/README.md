# 원천 광선 투영의 선택형 커널 비교 r322 — 미채택

r321에서 나타난 장면 투영 비용을 거리별 CAD 가림까지 포함해 비교했다. `sources.zip`은 후보 공통 소스이며 `before_sources.zip`은 수정 전 소스다. 시험 후 공통5파일을 전부 이전 바이트로 복원하고 신규 커널/공통 시험 연결을 제거했다. `restoration.json`·`restore_build.log`가 복원 근거다. 이미 미채택한 r257과 유사한 최적화이므로 이번 결과를 새로운 구조적 해결로 세지 않는다.

후보는 기존 native_v1 명시 선택에서만 SE(2) 좌표·사각 마스크·반환 상태의 scalar 계산을 수행했다. 기본 Python, 원 각도/시각/순서·점 수·unknown·점유/보호/TTL을 유지했다. 원점/끝점 overflow와 C buffer 경계도 검사했다. PC138관련검사·Jetson71기하검사를 통과했다. 첫 ROS 환경 wrapper의 unset 변수 오류는 `first_environment_failure.txt`에 보존했다.

같은106입력을 각 구현3회씩 번갈아 계산했다. 아래는 입력 복원+장면+현재 재검사+직렬화이며 ROS/IPC/센서·동시 계획 부하가 없다. p95는 정렬 표본의 floor((N−1)×.95) 항목이다.

| Jetson 대표 | 원 중앙/p95/최대 ms | 후보 중앙/p95/최대 ms |
|---|---:|---:|
| r279, 각156회 |69.819/81.344/106.294|67.329/78.395/103.875|
| r282, 각162회 |45.530/58.581/100.758|42.881/56.722/111.396|

두 구현끼리318/318 JSON이 정확히 같고636/636 명령/운영 필드는 고정 기대값과 같다. Jetson 전체 기대값 일치는594/636이며, 기존 플랫폼 간7개 진단 차이가 양쪽3회에 동일하게 남았다. PC는636/636 전체 기대값 일치·구현끼리318/318 정확히 같다. 소스 변경0이다. 최대 지연은 일관되게 개선되지 않았다.

**중앙 약2.5ms 절감으로 반복 명령 만료를 해결하지 못한다.** 커널 추가·공통 연결은 미채택하고 실행 구조 검토로 돌아간다. 센서/모터/서보·보드 앱·Jetson 전력 설정은 조작하지 않았다. 저장 재생으로 주행 성능을 입증하지 않는다.

재현 시 별도 작업 폴더에 `sources.zip`의 저장소 경로를 풀고 이 `measure.py`와 r296의 같은 `measure_cost.py`/headers/로컬 제외 selected_inputs를 같은 상대 경로에 둔다. 후보 확장은 setup.py build_ext로 빌드한다. 고정 입력 SHA256은 pc/report.json 및 jetson/report.json에 있다. 복원된 공통 소스에 그대로 실행하면 소스 불변 검사가 실패하는 것이 정상이다. 시험 코드는 `test_geometry_kernel.py`로 보존했다.
