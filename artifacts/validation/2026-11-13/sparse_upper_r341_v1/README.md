# 희소 상부 차량의 라이다 반환 r341

사용자 후속 요청에 따라 기존 오목 옆면과 구분하여 얇은4mm 판,8mm 사각 지주4개와 상부 덮개를 준비한다. 하부200×150mm와 전체220mm 높이의 평가 충돌 외곽은 그대로다. 이 형상·치수는 실제 상대 차량 자료가 없는 **대표 가정**이다. C1 높이134.6mm에서 하부80mm 몸체와 상부 덮개 사이를 지나게 한다.

먼저 원r338의504/508/512점 각도 배열을 사용해 거리0.4/0.8/1.2m, 상대 yaw0/45/90°, 한 각도 간격 안8개 위상에서 반환 수를 기하 비교한다. 동일한200×150mm 충돌 외곽에 대해 보이는 면만 바꾸며, 정답은 평가용 광선 생성에만 쓴다. 실제 반사율/빔 폭/노이즈/움직임·전체 주행 검증은 아니다. 이어 작은 Gazebo 정지 월드에서 해당 visual이 실제로 가느다란 반환을 만드는지 확인한다. 전체 코스를 성공할 때까지 반복하지 않는다.

## 결과

관련26검사를 통과했다. 아래 수는 거리별72개 각도/위상/점수 조합의 반환 광선 수이며 실제 센서 반복 측정이 아니다.

| 중심 거리 | 꽉 찬 상자 최소–최대 | 4mm 판 최소–최대 / 0반환 사례 | 지주4개 최소–최대 / 2점 이하 사례 |
|---|---|---|---|
| 0.4m | 38–49 | 0–25 / 1 | 6–10 / 0 |
| 0.8m | 17–25 | 0–13 / 13 | 1–6 / 7 |
| 1.2m | 11–17 | 0–9 / 17 | 1–4 / 52 |

작은 Gazebo 정지 월드의512광선 한 스캔에서는0.8m 상자18점, 옆면을 향한 얇은 판0점, 지주4개2점, 기존 오목형18점을 확인했다. 초기 파서가 protobuf JSON의 `angleMin`을 `angle_min`으로 읽어 실패했다. 원512점은 보존돼 `decode_probe.py`로 다시 해석했고 재실행하지 않았다. 예정된3600점 스트림은 미수집이다. 원 실패 보고서와 분리한 `gpu_probe/decoded.json`이 해석 근거다. 서버 정상 종료·잔여PID0을 확인했다.

**판단:** 낮은 몸체 위 얇은 부품은 같은 외곽 상자보다 훨씬 적게 보이며, 옆면을 향한 판은 아예 한 점도 안 보일 수 있다. 기존 오목형 통과를 이 경우까지 확장할 수 없다. 근접한 몇 점을 잡는 것과 실제 차체 전체를 알아내는 것도 다르다. 현 단계는 관측 모델/한계 확인이며 회피·추종 주행 통과가 아니다. 센서에 없는 차체를 복원했다고 가정하지 않고, 소수 반환과 가림을 남긴 대표 교통 시험 및 선택형 카메라 보조가 후속이다.
