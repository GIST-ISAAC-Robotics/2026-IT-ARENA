# r324 새 스캔 기준 계획/현재 확인 제출

r323은 새 발행 뒤 입력과100ms 보조 일정 예산을 썼지만 명령 공백 합계4.577→4.742초로 실패했다. 현재 검사가 약200ms 나이의 원 스캔을 받으면 약100ms 뒤 적용 시 원천300ms 경계를 넘는다. 이 후보는 부하를 줄인다고 시각을 갱신하지 않고 기존25ms fresh 제출 창을 계획과 현재 확인 양쪽에 적용한다. 현재 확인은 같은 source epoch/첫 취득시각에서 한 번만 시작한다. 계획 계산은147ms이므로 실제 제출은5Hz 정도가 될 수 있지만 현재 확인은 별도10Hz 스캔마다 가능한 구조다. 실제 처리율은 결과로 확인한다.

r286의 동일 SOLO 비감속 전환/새0·감속·상태 경계 처리는 유지한다. 원 경로500ms·현재 명령200ms·첫 광선300ms, 현재 영역/직전조향/STOP 검사와 독립 보호는 불변이다. 자유공간이나 새 센서값은 만들지 않는다. 새계획 전용 fresh와 선택형 scan/fresh를 같은15초, 고정147/81ms 최소 계산 시간, 센서 취득+20ms 도착 가정으로 비교한다. 저장 차량은 새 명령에 반응하지 않으므로 주행/안전 증명이 아니다.
