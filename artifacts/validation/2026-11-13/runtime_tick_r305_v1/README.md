# 고정 위상 5 ms 제어 호출 r305

기존 `capture_end+5000` 예약은 처리 시간과1ms task 깨움 때문에 약166Hz로 밀렸다. 최초 예약 위상의5ms 배수를 유지하고 늦어진 기간은 계수하여 건너뛰도록 수정했다. 한 번의 호출에서 지난 제어를 여러 번 실행하지 않으며 센서 취득 시각은 실제 읽기 시각이다.

30초 비구동 실제 대표에서 **제어 199.986 Hz·누락 제어 tick0·최대 예약 지연1,130µs·최대 호출 간격6,011µs**를 확인했다. 각 호출이 정확히5ms였다는 뜻은 아니다. IMU17,700프레임·순번 누락/CRC/송신 폐기0·스택 최소여유6,616 B였다. 단순 조기/지연/긴 정체/중복 호출/위상 drift 합성 및 sanitizer도 통과했다. [계측](assessment.json)·[실측 원본](actual/result.json).

PCNT는 원시0, 서보는 무응답이며 출력은 항상 비활성이다. 실제 엔코더 회전·조향·모터 부하·물리 핀 전압은 미검증이다. 끝나면 원 factory app1MiB를 해시 일치로 복원하고 IMU inactive·포트 비점유를 확인했다. [복원](recovery.json). 현 운영 앱에 자동 채택하지 않았으며 다음 실물 연결의 준비본이다.
