# 시설 경계 후보의 느린 시계 기하 분리 r304

r299는 경로 호출0·출발 전 MCU 명령 전달 만료로 후보를 평가하지 못했다. 이번에는 같은 물리 시간 간격/속도/구동/시설과 후보를 유지하며 Gazebo의 벽시계 진행 목표만 0.25배로 낮춘다. CPU가 메시지를 처리할 벽시계 여유를 주어 경로/시설 기하를 분리하는 시험이다. TTL·물성·센서 주기는 시뮬레이션 시간 기준 그대로다. 성공하더라도 Jetson/1배속 실행 성능을 증명하지 않는다.

목표46.64 m·최대90초의 제한 단독 주행 1회이며 성공할 때까지 반복하지 않는다. 생성 월드의 변경 전/후 XML을 대조해 real_time_factor만 변경했음을 보존한다. 지도·시설 위치는 평가용이며 제어 입력이 아니다. 공통 기본 코드/launch는 변경하지 않는다. 결과는 run1/report.json과 fixture_execution.json으로 남긴다.

## 실행 결과

2.46m·신호등 지주 앞에서 `follow_boundary_unconfirmed`가 지속되어 실패했다. 전달 만료 없이 경로 계산까지 도달했다. 같은498판단을 후보와 공통 원 코드로 각각 재생했으며 둘 다 원 출력과 모두 같았다. 후보가 새 퇴행을 만들었다고 해석하지 않는다. [재생](replay_summary.json)·[판정](assessment.json).

원 관측에는 양옆 벽이 보이지만 버팀대 반환이 방위 순서의 벽 사슬을 끊는다. 진단용으로 시설 반환만 제외하면 긴 벽이 복구된다. 이는 원인 분리이며 제어기에서는 시설 반환을 제거하지 않는다. 기존 조각 후보는 코너 형상이 있어야 경로를 만들기 때문에 이 직선에서 거절됐다. [원 관측 그림](sensor_path_diagnosis.png)·[원 수치](inspection.json).

628입력/소스 불변·STOP/정상 종료·잔여PID0이다. 평가 겹침0이나 접촉 토픽은0메시지여서 독립 물리 무접촉 증명은 아니다. 실제 직선 조각을 사용하는 r306의 저장 비교로 이어갔으며 같은 주행은 반복하지 않았다.
