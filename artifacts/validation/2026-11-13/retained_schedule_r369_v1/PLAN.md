# 보관 검사 제출 낭비 제한 비교

r367 자문A를 기본 OFF 시험 자식에서만 비교한다. 새 계획이 계산 중이고 기존 RELEASED 경로의 재검사가 아직 시작되지 않은 때 그 보관 검사 제출을 생략한다. SOLO·완료된 새 계획·진행 중 현재 검사에는 개입하지 않는다. 원 점유/명령 시각/기한·STOP·새0계획 우선순위는 그대로다. 이전 검사를 생략하면 오히려 갱신이 나빠질 수 있으므로 개선을 가정하지 않는다.

r365에서22개 실제 평가 출력 일치와 ROS STOP/종료를 확인한 공통 backend·원 r353 기록·r358 시간 재생기를 쓴다. 먼저 PC에서 baseline/선택 후보31초씩을 비교한다. 적용 상태와 제출 폐기·공백/정상 종료를 확인하고 의미가 있을 때만 Jetson의 같은 원천을 비교한다. 파일 출력 시험으로 실제 주행·ROS 명령 발행과 구분하며 센서 포트나 모터를 사용하지 않는다.

초기61회귀는 통과했으나 최초 실행 준비는 importlib로 r358을 읽으면서 그 폴더를 검색 경로에 넣지 않아 `classification_worker` import에 실패했다. 아직 계산 자식/재생은 시작되지 않았다. 정확한 원 폴더를 경로에 추가했고, r358의 종료 목록 형식과 공통 backend의 종료 dict 형식도 명시 어댑터로 맞췄다. 원 시험 코드는 수정하지 않았다.
