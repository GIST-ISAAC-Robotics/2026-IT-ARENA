# G1/G2 복귀 실패: 명령·접촉·모터축 피드백 분리

2026-10-29. [자동 전환 Gazebo run1/run2](../g2_handoff_gazebo_v1/README.md)의 실패를 분석했다. run2는 접촉 센서/기록만 추가했으며 차량 XML은 해당 센서를 제외하면 같고, 월드/배치 OBJ도 실행별 경로를 정규화하면 같다. 제어·구동·마찰·노면·판정을 바꾸지 않았다.

## 실제로 멈춘 위치와 명령

두 실행 모두 표적을 통과한 뒤 **복귀 경로를 생성했다**. run1은 초록 후5.205초, run2는5.257초부터 G2 내부 `rejoin`이었다. 중앙에 도달해야 하는 상위 `REACQUIRE`까지 가지 못한 것이며, 복귀 지시가 없었던 것은 아니다.

## 접촉에서 추가로 확인한 것

run2의73,389개 원시 메시지를 보존했다. 후반부에 왼쪽 앞바퀴는 **도로 `surface_main_580_col`의 가장자리와 잔디 `grass_main_left_1958_col`에 동시에 접촉**했다. 도로 법선의 수직 성분 절댓값 중앙값은0.309이고 잔디는1.0이므로 같은 수평면 두 개의 중복 접촉으로만 설명되지 않는다. 오른쪽 앞/뒤는 도로 접촉을 계속 기록했고, 왼쪽 뒤의 접촉 행은 이 구간에서0개였다. 수신이 없는 것을 측정된0 N으로 채우지 않는다.

아래 값은 **각 메시지에서 접촉점별 법선힘 크기를 더한 값의 중앙값**이다. 부호 있는 바퀴 하중이나 시간 평균 지지력이 아니다.

|---|---:|---:|

근거: [접촉 쌍/형상 대조](run2_contacts.json), [부호에 의존하지 않는 분석](run2_magnitudes.json), [계산기](contact_magnitudes.py). 현재 월드의 도로 상단은3 mm·잔디 상단은2 mm로1 mm 차이가 있다. 위 결과는 경계 접촉·강체 바퀴·열린 차동의 접지 민감도를 지지하지만, 실물 타이어 변형/차동 저항이나 공식 잔디6 mm의 주행 결과로 확대하지 않는다. 힘을 늘리거나 마찰·단차를 임의 조정해 통과시키지 않았다.

## 접촉력 부호 해석의 수정

설치 헤더는 Gazebo Sim **8.11.0**, Physics **7.6.0**이다. 해당 태그의 [Physics.cc](https://github.com/gazebosim/gz-sim/blob/gz-sim8_8.11.0/src/systems/physics/Physics.cc#L3893-L3983)는 접촉 쌍을 양쪽 순서로 조회하도록 저장하고 센서 충돌체를 메시지 `collision1`로 적지만, 원래 접촉의 force/normal 부호를 그 순서에 맞춰 뒤집지 않는다. [DART 변환](https://github.com/gazebosim/gz-physics/blob/gz-physics7_7.6.0/dartsim/src/SimulationFeatures.cc#L254-L293)은 원래 물리 접촉의 값을 복사하며, [DART 계약](https://dartsim.github.io/dart/v6.11.1/db/d36/structdart_1_1collision_1_1Contact.html)은 원래 body1 기준의 힘을 정의한다. [조회 파일 해시](research/sources.json)를 남겼다. 설치 바이너리를 역분석한 검증은 아니지만, 설치 버전과 같은 태그의 이 경로에서는 메시지 이름만으로 힘 방향을 확정할 수 없다.

따라서 기존 `analyze_wheel_contacts.py`의 `force_world_xyz_n`은 **메시지 이름을 기준으로 고른 원시 필드**로만 유지한다. 힘 값은 바꾸지 않고 `force_body_assignment_verified=false`를 추가했으며, 작은/음수 합을 무하중 비율로 출력하던 값은 미확인(`null`)으로 바꿨다. 이전 보고서의 signed Fz 통계는 원시 값으로 보존하되 실제 바퀴 지지력으로 사용하지 않는다. 이는 분석기의 해석 보완이며 Gazebo 엔진·물리 동작을 수정한 작업이 아니다.

새 집계는 원래 접촉 순서가 바뀌어 힘과 법선이 함께 반전되어도 같은 `abs(force·normal)`만 쓴다. 누락/명시0/반전/잘못된 법선4검사를 통과했다. ROS 환경을 로드하지 않은 pytest 첫 시도는 xacro import에서 실패했고 로그를 보존했다. ROS 환경 로드 후에도 같은 모듈 import가 실패했으므로, 변경하지 않은 launch 검사를 통과로 세지 않는다. 실제 변경된 접촉 해석 검사와 G1/G2/기록을 묶은 후속49검사는 통과했다([로그](../g2_handoff_course_shadow_v1/contracts2.log)). 추가 패키지 설치나 환경 변경은 하지 않았다.

## 다음 범위

같은 실패의 추가 주행은 여기서 멈춘다. 정지차 통과/복귀 명령은 확인됐으나 물리 복귀는 실패로 남긴다. 실물 설계가 나오면 바퀴 접지·타이어 변형·차동 저항과 실제 노면 높이를 함께 대조한다. 그동안 [기존 교통1랩의 우회 진입 제안·사전 감속](../g2_handoff_course_shadow_v1/README.md)을 저장 센서 입력에서 확인하여, 물리 문제 하나를 모든 제어 작업의 선행 관문으로 만들지 않는다.
