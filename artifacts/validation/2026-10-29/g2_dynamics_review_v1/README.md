# G2 좌우 우회 복귀의 동역학 진단

2026-10-29. [왼쪽 run1 실패](../g2_entry_left_v1/README.md)는 정지차 통과 후 중앙 복귀 실패다. 원래 실패를 유지하며 제어 정지와 실제 구동 정체를 구별한다.

## 저장 입력에서 확인한 사실

[analyze_saved.py](analyze_saved.py)가 두 원본 `trace.json`과 판단 기록의 SHA-256을 [saved_dynamics.json](saved_dynamics.json)에 남긴다. 초록 후6–11.9 s의59표본 비교다.

| 항목 | 오른쪽 표적(왼쪽으로 우회) | 왼쪽 표적(오른쪽으로 우회) |
|---|---|---|
| 제어·보호 후 속도 명령 | 모두0.35 m/s | 모두0.35 m/s |
| 보호 이유 | 모두 `clear` | 모두 `clear` |
| 차체 속도 중앙값 | 0.3503 m/s | 0.000095 m/s |
| 구간 종방향 진행 | 2.0598 m | 0 m(하네스 진행 표본 정밀도) |
| 왼쪽/오른쪽 뒷바퀴 중앙값 | 10.78 / 10.80 rad/s | 0.00094 / 21.63 rad/s |

왼쪽 실패를 제어기 HOLD·벽 부호 오류·입력 초기화가 직접 일으킨 것으로 설명할 근거는 없다. 관측된 상태는 한쪽 바퀴가 거의 정지하고 반대쪽이 헛돌아 모터축 평균 속도만 목표를 만족하는 열린 차동의 한계와 일치한다. **헛돎이 생긴 접촉 원인은 아직 확정하지 않았다.** 현재 노면의1 mm 높이 차와 바퀴·차동·마찰 모델을 함께 확인해야 한다. 실제 차량에서도 반드시 같다고 확대하지 않는다.

`entry_guide_input_reset`은 두 실행 모두 명시 STOP 이후의 음의 측정 속도에서만 발생했다. 따라서 이번 주행 창 복귀 실패의 직접 원인으로 삼지 않는다. 실제 정지/재출발 중 음수 측정 처리 문제는 별도 잔여 과제다.

## 접촉 계측

**10/29 후속 해석 수정:** 아래 `fz` 통계는 메시지의 원시 부호이며 실제 바퀴 지지력으로 확정할 수 없다. 설치 버전과 같은 Gazebo 소스에서 충돌체 이름을 재배열하면서 force/normal 부호를 보존하는 경로를 확인했다. 과거 JSON을 덮어쓰지 않으며, 접촉 쌍/속도/실패 판정은 그대로 유지한다. [버전·소스·부호에 의존하지 않는 새 진단](../g2_handoff_dynamics_v1/README.md#접촉력-부호-해석의-수정)을 따른다.

[왼쪽 run2 등록](../g2_entry_left_v1/README.md#왼쪽-run2-접촉-계측-진단실행-전-등록)에 따라 바퀴 contact 센서/기록만 추가한 진단1회를 진행한다. 제어·보호·시간·속도·형상·물성은 바꾸지 않는다. 접촉 메시지 무응답을 무하중 증명으로 쓰지 않으며, 실제 접촉 쌍·양의 하중·SDF 차이를 대조한다. 판단 입력에 접촉 정답을 넣지 않는다.

### run2 결과: 복귀했지만 기존 실패의 해결은 아니다

접촉 기록을 켠 run2는 주행 창3.9246 m·통과4.566 s·중앙 복귀7.942 s부터4.060 s 유지, 최소 차체 간격159.45 mm·접촉0·도로 밖 바퀴≤2·STOP/정상 종료·654판단 동일 재생으로 G2 등록 판정을 통과했다. 구형 G1 판정은 실패로 그대로 보존한다. [평가](../g2_entry_left_v1/run2_g2_evaluation.json).

제어·차량 물성은 수정하지 않았다. [차량 대조](run2_contacts.json)에서 추가 contact 센서 네 개를 뺀 차량 XML이 같고, [월드 대조](run2_world_audit.json)에서 임시 OBJ 경로 이름을 정규화하고 OBJ 파일 해시까지 확인하면 전체 월드가 같다. **계측 유무와 실행 시점이 다른 두 실행**이므로 성공을 계측의 개선 효과로 설명하지 않는다. 원래 run1 실패와 반복성 미확인은 남는다.

초록 후4.8–5.8 s에 기록된 오른쪽 앞/뒤 바퀴의 수직 접촉력 중앙값은0.111/1.077 N이고 왼쪽은1.922/8.343 N이었다. 오른쪽 바퀴가 여러 도로·잔디 상자에 함께 닿는 사건과 큰 힘 변동을 기록했다. 힘의 음수 값과 수신 공백도 원본 그대로 남겼다. 이 값은 관측된 접촉 사건의 통계이지 전체 시간 평균 지지력이나 실물 하중이 아니다. run2에서는6초 이후 양쪽 후륜 약10.77 rad/s·차체약0.35 m/s로 회복했다.

**판단:** 현재 모델의 경계 접촉·강체 차체·열린 차동 조합은 복귀에 민감하다. 영구 고착의 접촉 원인을 아직 직접 계측하지 못했으므로, 단차/마찰을 바꾸거나 LSD로 바꿔 통과시키지 않는다. 실물 설계가 나오면 타이어 변형·접지·잔디 높이·차동 저항을 대조한다. 중앙 정지 표적과 비사각형 센서 대응은 이 미확인 사항의 완전 해결을 기다리지 않고 별도로 진행한다.

후속 [오른쪽 개방형 표적](../g2_openframe_v1/README.md#run1-결과-표적-통과-복귀-실패)에서도 표적을 지난 뒤1.66482 m에서 정체했다. 초록 후6–11.9 s에는 명령/보호 출력0.35 m/s·차체 속도 중앙값0.000100 m/s, 좌/우 후륜21.53/0.0024 rad/s였다. 왼쪽 상자와 반대 바퀴에서 같은 형태의 헛돎이 관측됐다. 이는 왼쪽 우회에만 생기는 제어 부호 오류라는 설명을 지지하지 않는다. 추가 바퀴 접촉 센서가 없는 실행이므로 접촉력 원인까지 확정하지 않는다.
