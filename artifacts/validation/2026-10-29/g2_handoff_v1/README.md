# G1 추종과 G2 우회의 선택·복귀 준비

2026-10-29. 가장자리 상자 우회/복귀의 제한 성과와 중앙 정체를 구별하고, 경기 주행에 필요한 자동 선택의 조건을 확인한다. 앞선 초기 추종 예측/시차 팽창 도형 비교는 중앙 정체를 해결하지 못해 생산 코드에 채택하지 않았다. [실패/판단](../g2_motion_envelope_v1/README.md).

## 첫 고정 입력 비교

현재 G1 통합 옵션(v4·corner-distance·per-ray·평행/통과·GUARD·회복·회랑)과 명시 G2의 현재 반환/동일 운동 입력에서 출력 차이를 비교한다. 중앙/좌우 가장자리 정지 표적의 중심 거리1.2/1.0/0.8/0.6/0.4 m, 각4개 새 스캔을 사용한다. 시간/거리값을 운영 제어기에 추가 입력하지 않으며 정답 위치는 센서 생산에만 쓰인다. 정지차라고 제어기에 알려주지 않는다.

이는 초기 고정 자세에서의 **후보 존재와 거절 근거** 확인이다. 실제 접근·자동 전이·폐루프 주행이나 움직이는 차량 대응을 증명하지 않는다. G1이 완전히 정지한 뒤라면 G2의 진입 공간이 이미 부족할 수 있으므로 그 관계부터 확인한다. 같은 표적 상태를 연속 관측했다고 정지/차량 ID/완전 외곽을 확정하지 않는다.

후속 설계는 G1→G2 선택, G2 진행 중 일시 HOLD, 중앙 재관측 뒤 G1 재획득, 센서/시각/명시 STOP의 중단을 분리한다. 두 제어기의 내부 상태나 지난 진행 승인을 그대로 복사하지 않고 현재 센서로 다시 판단한다. 첫 범위는 저속 직선과 현재 관측이 성립하는 가장자리 표적이며, 중앙 실패·가려진 뒤차·가변 기구·고속 접근을 자동 해결한 것으로 확대하지 않는다. 아직 운영 연결이나 기본 활성화는 없다.

### 고정 입력의 확인 결과

15조건 원시 비교 (`approach.json`, 로컬 보존)에서 표적 중심 거리 1.2/1.0/0.8/0.6 m의 가장자리 두 조건은 G2가 각각 1.2/0.9/0.9/0.6 m 전이를 선택했다. 0.4 m에서는 G1이 대기하고 G2도 횡편이 0 m만 선택했다. **양의 속도가 나오는 것과 우회 경로가 있는 것은 다르다.** 중앙 표적은 0.6 m부터 횡편이가 0 m였다. 이는 접근 거리별 고정 장면이며, 이전 중앙 폐루프 실패를 해결한 결과가 아니다.

## 명시 시험용 자동 선택 시제품

`handoff_prototype.py`는 운영 코드에 연결하지 않는다. `probe_handoff.py`가 기존 순차 센서·단일 모터축/gyro 생산·독립 보호 함수·이상 bicycle 평가기를 사용해 다음 순서를 비교한다.

| 상태 | 입력과 전이 |
|---|---|
| FOLLOW | G1 출력을 유지한다. 현재 전방 연속 반환 조각이 있으면 최대 0.35 m/s로 감속하면서 관측을 모은다. 물체가 없거나 사라진 공간을 우회 기회로 해석하지 않는다 |
| 진입 후보 | 최소 0.8초·6개 이상의 서로 다른 스캔에서 엔코더/gyro로 이송한 반환 조각의 중앙값 이동이 60 mm 이내인지 비교한다. 현재 G2의 두 벽 확인·비영 횡편이·양의 출력과 해당 방향의 기존 측방 위협 부재가 함께 있어야 전환한다 |
| BYPASS | 기존 G2의 현재 점유/관측/외벽 재확인으로 출력한다. G1도 같은 입력을 받아 측방 소실 이력을 계속 유지한다. 일시 HOLD를 정상 복귀로 취급하지 않는다 |
| REACQUIRE | G2의 중앙 복귀 뒤 G1의 양의 현재 출력이 새 스캔 2개에서 확인되면 FOLLOW로 돌린다 |
| 고장·STOP | 고장 출력과 출처 세대/시간 역행은 우회 상태를 버린다. 명시 STOP은 모드 판단보다 먼저 0 명령을 내고 다음 실행에 경로를 재사용하지 않는다 |

0.8초/60 mm/전방 조각은 **시험 가정**이다. 낮은 움직임을 보이는 조각을 찾는 것이며 차량 ID나 정지를 확정하지 않는다. 매우 느린 차, 가림으로 바뀐 물체, 측면 형태 변화, 모터축 슬립의 위험이 남는다. 특히 0.03 m/s 이동 물체도 이 조건을 만족하는 반례를 검사에 명시했다. 가려진 뒤차 부재나 향후 빈 경로를 증명하지 않으며, G2의 현재 관측 검사와 독립 보호층을 생략하지 않는다.

첫 폐루프 비교는 오른쪽 가장자리 명목, 좌우 가장자리 복합 센서 오차, 처음부터 0.25 m/s로 움직이는 앞차의 4조건이다. 각 12초 뒤 STOP 0.6초를 기록한다. 접촉·노면·진행·전환/복귀·처리 시간을 확인하며, 실패하면 이유를 분석하고 같은 조건을 성공할 때까지 반복하지 않는다. 생산 코드/기본값/ROS 연결을 바꾸지 않는다.

## prototype1 결과와 전환 지연 결함

회귀 10개와 실행 종료를 확인했다. [결과/소스 해시](prototype1/report.json), [실행 로그](prototype1.log), [검사](tests1.log). 아래는 12초의 합성 운동학 결과이며 공식 코스/실물 완주가 아니다.

| 조건 | 진행 | 전환/복귀 | 접촉·노면·STOP |
|---|---:|---|---|
| 오른쪽 명목 | 5.116 m | 1.40초 BYPASS → 8.70초 REACQUIRE → 8.80초 FOLLOW | 접촉0, 최대 두 바퀴 잔디, STOP |
| 왼쪽 복합 오차 | 5.236 m | 2.20초 BYPASS → 8.60초 REACQUIRE → 8.70초 FOLLOW | 접촉0, 최대 두 바퀴 잔디, STOP |
| 오른쪽 복합 오차 | 1.066 m | 2.20초 BYPASS, 복귀 실패 | 접촉0, 바퀴 잔디0, STOP |
| 0.25 m/s 이동 앞차·복합 오차 | 3.472 m | FOLLOW 유지, 우회 전환0 | 접촉0, 바퀴 잔디0, STOP |

오른쪽 오차 조건에서 1.30초부터 낮은 이동의 전방 반환 후보는 성립했다. 하지만 새 연결 코드가 **출력 상한 0.35 m/s를 측정 속도 허용선으로도 사용**하여, 모터축 속도 양자화의 0.34034/0.36465 m/s 중 후자를 받을 때마다 초기 벽 확인을 버렸다. 1.30–2.08초에 확인 수가 계속1로 돌아갔고, G1이 앞차에 접근하여 감속한 뒤에야 2.20초·진행0.4624 m에서 전환했다. 명목은 1.40초·0.1872 m에서 전환했다. 정체 이후에는 표적 모서리의 팽창과 전이 경로에서 정지/진행을 반복했다. 독립 보호층의 차단이나 Gazebo 접지 현상은 이 합성 실패의 원인이 아니다.

prototype2는 새 연결 코드의 중복 입력 제한만 제거한다. 기존 G2의 입력 범위(최대1 m/s), 측정 속도를 사용하는 반응/제동 영역, 출력 상한0.35 m/s와 독립 보호층은 유지한다. 센서값을0.35로 잘라 넣거나 엔코더 분해능/노면/간격을 바꾸지 않는다. 측정값0.364649의 원값 전달과 기존 입력 범위 초과 거절을 회귀에 추가했다. prototype1의 코드·원본·실패는 `sources.zip`과 로컬 상세 JSON에 보존한다.

### prototype2

[12회귀](tests2.log)·[결과](prototype2/report.json)·소스 불변을 확인했다. 오른쪽 명목5.116 m·왼쪽 복합5.189 m·오른쪽 복합4.705 m에서 모두 BYPASS→REACQUIRE→FOLLOW로 복귀했다. 전환은 세 조건 모두1.40초이며 마지막 FOLLOW는8.80/8.70/10.60초다. 이동 앞차는3.472 m·FOLLOW 유지다. 네 조건 접촉0·STOP, 정지 표적 조건 잔디 최대두바퀴·이동 표적0을 확인했다. 같은 엔코더 양자화에서 초기 관측을 보존하자 오른쪽 복합 실패가 이 한 비교에서는 사라졌다. 가변 형상·복수차·느린 이동차·Gazebo 접지 문제의 해결은 아니다.

## 선택형 코드 연결·기록

`bypass_handoff.py`·별도 `g1_g2_handoff_trial` 실행 파일을 추가했다. 명시 시뮬레이션 활성화·기록된 G1 옵션·절대 경로의 판단 기록을 요구하며 기본 launch는 바꾸지 않는다. 기존 `LocalPursuit`의 센서/영상/명령 경로를 그대로 쓰고 기록 생성 함수만 분리했다. schema5는 G1/G2 실행 옵션과 내부 전환을 기록하며 schema1–4를 그대로 재생한다. `g1_g2_node.py`는 상태 토픽에는 요약만, 판단 기록에는 전체 후보를 남긴다.

[연결 회귀212개](contracts1.log)가 통과했다. 상태 전환·현재 측정값·원시 취득 시각·세대/시간 역행·입력 고장·기록 재생을 확인한 함수/명령 단계 검사이며 실제 ROS 노드 생성이나 Gazebo 검증은 아직 아니다.

**integration1 보존:** 시제품의 차체 중심 궤적에서 후륜축을 역환산해 센서 입력을 재구성한 첫 대조는 세 정지 조건의 상세 판단39/177/159개가 달라졌다. 새 schema5 자체의2,400판단 재생은 모두 동일했다. 차체 중심↔후륜축 부동소수점 왕복차가 지역 경로의 표본화/수치 분기에 영향을 줄 수 있어, 후속 대조는 보존된 실제 적용 명령을 원래 연산 순서로 적분한다. 원본실패와 엄격 동일 판정선을 유지하고, 소수점 허용치를 늘려 통과시키지 않는다. [첫 대조](integration1/report.json).

**integration2/3:** 명령 적분 순서 복원 뒤 명목/이동 표적의 상세 판단은 일치했다. 좌우 오차 조건은 각각150개 불일치했다. 연결 과정에서 추가한 전역 측정속도≤1 m/s 검사가 G1 복귀 후 엔코더 양자화의1.021 m/s를 거절했다. 기존 G1은 이 입력을 잘라내지 않고 제동·관측 계산에 사용한다. 전역 중복 검사를 제거하고 G2 진입의 기존 입력 범위는 유지했으며, 해당 반례를 추가했다. [integration2 실패](integration2/report.json)·[35회귀](contracts2.log)·[integration3](integration3/report.json). integration3의 **4조건×600호출=2,400판단은 시제품과 모두 동일하고 schema5 자체 재생도 전부 동일**, 소스 불변이다. 엄격 상세 비교가 시제품 이식의 오류를 발견한 것이며, 이 검사를 새 주행 결과로 쓰지 않는다.

다음은 [G1/G2 제한 Gazebo 연결](../g2_handoff_gazebo_v1/README.md)이다. 관련 실행 준비·결과는 그 문서를 기준으로 한다.
