# 기존 교통1랩의 G1/G2 진입 제안·사전 감속 관찰

2026-10-29. 선택형 전환의 Gazebo 통과 뒤 물리 복귀는 편측 헛돎으로 실패했다. 해당 실패/접촉 진단을 보존하며, 별도로 기존 일반 주행에 새 전방 반환 후보가 불필요한 우회나 감속을 제안하는지 저장 입력에서 확인한다.

- 입력은 `bump_traffic_v1/run4/follow_decisions.jsonl`의 공식 신호·방지턱ON·각본 교통1랩이다. 실제 해당 실행은 G1이며 정지 후 다시 출발하는 앞차/옆차/코너가 포함된다.
- 같은 FollowConfig·시각·모터축/IMU·스캔·기존 조향을 사용한다. 지도·평가 actor 정보는 제어기에 전달하지 않는다. 새 G1/G2 출력은 구동에 사용하지 않는다.
- **진입 제안만 관찰한다.** `handoff_entry`가 나오면 그 시각·반환 근거·선택을 기록한 뒤 G2/전방 반환 누적만 비운다. 기존 G1의 관측/옆차 이력은 계속 유지한다. 제안 경로를 실제로 주행하지 않은 저장 궤적에서 가짜 우회·복귀 성과를 만들지 않는다.
- G1 내부 판단 상세가 원래 기록과 같은지, 사전0.35 m/s 제한이 원래 명령을 낮추는 구간, 진입 제안 시각, 처리 비용을 집계한다. 후속 명령을 적용한 가상 결과나 Jetson 실시간성은 판정하지 않는다.
- 새 전환의 기본 활성화·후방 미관측 해제·물성 변경은 하지 않는다. 결과가 불필요한 감속을 보여 주면 센서 근거와 실제 기능상 이유를 먼저 분석한다.

## run1 실행 전 설정 거절과 run2 등록

run1은0호출에서 설정 검증으로 종료했다. 기존 교통1랩/5랩은 `short_boundary_prefix_enabled=true`인데 첫 G1/G2 연결의 제한 직선 시험은OFF여서 생성자가 이를 일괄 거절했다. 입력 옵션을 몰래 끄지 않고, 이미 선택형으로 검증한 G1의 ON/OFF 값을 그대로 받도록 연결 범위를 수정했다. G2의 초기 두 벽 확인·점유/관측 조건은 유지하며, G1의 짧은 관측 승인을 G2에 복사하지 않는다. 기본값과 기존OFF 기록도 유지한다.

ON/OFF 보존 검사와 기존 전환/기록 검사 뒤 같은 입력을 `run2`로 비교한다. run1의 빈 상세 파일·소스ZIP·오류로그는 실패 원본으로 보존한다. 수정은 기존 G1을 같은 실제 설정으로 비교하기 위한 것이며, 새 경로 주행이나 기본 활성화의 근거가 아니다.

## run2 결과와 음의 모터축 속도 처리

관련49검사는 통과했다. 저장7,801호출에서 우회 제안0·원래보다 작은 명령3,137호출이었으나(사전 감속 효과만으로 분리되지 않음), G1 내부 판단 상세가6,352호출에서 달랐다. 원인을 확인하니 유한한 음의 모터축 속도51호출에서 새 연결이 G1까지 초기화했다. 첫13.28초의−0.04862 m/s에서 기존 G1은 `follow_reverse_motion`으로 정지하면서 이력을 유지했지만, 새 연결은 경계/옆차 이력까지 지워 다음 호출부터 달라졌다. 따라서 run2를 기존 G1 보존이나 완주 가능성의 근거로 사용하지 않는다.

run3에서는 유한한 음의 측정값을 그대로 G1에 전달하고0명령을 유지하며, G2 경로/전방 반환 누적만 초기화한다. 음수를0으로 바꾸거나 후진 명령을 허용하지 않는다. 기존 시각/epoch·비정상 입력·명시 STOP 계약은 유지한다. 이력 보존/우회 폐기 검사를 추가한 뒤 같은 저장 입력에서 내부 상세 정합과 감속을 다시 비교한다. 새 주행은 아니다.

## run3 결과와 다음 설계 묶음

관련50검사가 통과했고, 기존 G1 내부 상세는 **7,801/7,801 모두 일치**했다. 음의 속도51회는0명령과 G1 이력 보존으로 처리했다. 진입 제안은0건이었다. [결과](run3/report.json), [실행 로그](run3.log).

반면 사전0.35 m/s 제한은 **3,073호출**에서 기존 명령보다 낮았다. 그중3,013호출은 낮은 이동 관측이 아직 준비되지 않았고, 관측 누적 시간의 중앙값은0초였다. 기존 `local_follow/RELEASED`2,861호출에서도 제한을 제안했다. 조향 절댓값0.08 rad 이하도1,973호출이어서 조향각 하나만으로 모두 설명하거나 없앨 수 없다. [집계](cap_diagnosis.json), [집계기](analyze_caps.py). 이것은 저장 궤적에서 **제안한 명령 차이**이며 실제 주행 지연이나 그만큼의 불필요한 감속이 실차에서 확정됐다는 뜻은 아니다.

다음 묶음은 **현재 전방 반환 하나만 생겨도 곧바로 준비 감속하는 조건**을 개선하는 것이다. 이동 앞차·코너/벽 반환을 구별할 관측 근거와 우회 진입 공간을 잃지 않는 시점을 함께 비교한다. 필요하면 G2가 실제로 진입 가능한 직선/양벽 조건, 연속 관측, 이동 증거를 조합하되 특정 숫자 하나를 맞추기 위한 탐색은 하지 않는다. 이미 확인한 명목/좌우 오차의 정지 가장자리 진입과0.25 m/s 이동 앞차 추종, 음의 속도·이력/STOP·기존 독립 보호를 보존한다. 저장 비교 뒤 필요한 대표 합성 폐루프로 영향과 한계를 확인하고, 물리 헛돎을 고치지 않은 채 같은 Gazebo 실패를 반복하지 않는다.

사용자 지시에 따라 여기서 작업 묶음을 전환하여 Claude Opus 5.5가 조사·구현·검사를 맡고 GPT가 설계/최종 검토를 한다. 5시간 사용량 경고 때 GPT가 인계받으며 주간 경고만으로 전환하지 않는다. 단순 실행/회수는 확인된 Claude Haiku 5.5 보조를 사용한다.

**후속 결과:** 위 준비 감속 조건의 비교·구현은 [g2_prepare_cap_v1](../g2_prepare_cap_v1/README.md)에 둔다. 이 문서의 run1–run3 본문과 원본은 그대로 보존한다.
