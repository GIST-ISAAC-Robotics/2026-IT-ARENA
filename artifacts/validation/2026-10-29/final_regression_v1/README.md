# 10/29 마감 회귀와 게시 검토

사용자 요청에 따라 M3 개방형 옆차 좌우 시험까지 마치고 새 주행은 시작하지 않았다. 마지막 전체 회귀 이후 G2 연결이 추가되었으므로 저장소 전체 `tests/`를 확인했다.

## 첫 전체 검사와 보완

`run.sh`/`full.log`/`full.exit`는 **6,556 통과·15 실패·19 건너뜀**, exit 1이다. 실패 11건은 G2 연결로 바뀐 `local_pursuit`·`follow_trace`의 후속 출처 계약이 누락된 데서, 4건은 `follow_trace`의 새 정적 import가 진단/이관 묶음의 모듈 목록에 빠진 데서 발생했다. 주행 실패와 같은 판정이 아니며 최초 결과를 보존한다.

- 5랩 실행 당시 소스 ZIP에서 이전 8파일을 정확한 바이트로 추출한 `before_g2_manifest.zip`과 `g2_handoff_manifest_r1_sha256.json` 후속 계약을 추가했다. 과거 계약·해시·실행 결과를 고쳐서 통과시키지 않는다.
- 진단/이관·시험기 보존 목록에 G2 순수 Python 모듈 4개를 추가하고 전이 의존성 검사와 후속 출처 검사를 연결했다. 주행 제어·물성·보호 조건·기존 판정은 바꾸지 않았다.
- `.gitattributes`에 10/28–29 증거와 CRLF로 기록된 소스의 바이트 보존 규칙을 추가했다. 새 체크아웃에서 줄바꿈 변환으로 기록된 해시가 달라지는 것을 방지한다. 일부 기존 EOF/겹친 CR도 당시 해시를 보존한다.

후속 전체 검사 `run_after_fix.sh`/`full_after_fix.log`/`full_after_fix.exit`는 **6,571 통과·1 실패·19 건너뜀**이다. 남은 `test_actor_tail_provenance`는 새 후속 계약이 생긴 뒤에도 현재 파일을 과거 계약의 after와 직접 비교했다. 다른 출처 검사와 같이 현재→후속 계약의 이전 ZIP→해당 과거 계약 순으로 모든 해시를 확인하도록 수정했다. 이전 실패 주행의 보고서/해시/판정 확인은 유지한다. 마지막 변경은 검사 코드뿐이므로 전체 검사를 반복하지 않고 관련 검사 묶음을 `final_targeted.*`에 별도로 남긴다. 명시 C++ 바이너리가 없는 19건의 skip은 Python 회귀나 과거 성공으로 대체하지 않는다. 이 검사는 Gazebo 재주행·실물 검증·최신 Jetson 성능 증명이 아니다.

## 게시 범위

코드·설정·후속 계약·문서·명령·판정·요약·확인 사진을 함께 게시한다. 원시 센서/판단/자세와 호출별 대용량 분석은 기존 정책에 따라 로컬에 남긴다. 재생 결과는 호출별 전체 출력 대신 통과 수·입력 해시·입력 불변 여부를 담은 요약을 게시한다. 공식 저장소 Markdown 보존본은 원문을 바꾸지 않으므로 그 저장소 내부의 사진/이슈 상대 링크가 로컬에 모두 포함된 것은 아니다.

게시 감사의 링크 수·크기·바이트 비교는 `publication_audit.json`에 남긴다. 원본 링크와 로컬 전용 자료를 작업 문서의 잘못된 링크와 구분한다. `g2_entry_shadow_v1`의 실제 생성되지 않은 combined18 그림 링크 하나는 삭제하고 보고서 수치를 가리켰다. 실제 시험 결과·사진을 만들어 채우지 않았다.


## 최종 확인

`run_targeted.sh` / `final_targeted.log` / `final_targeted.exit`에서 출처 사슬·보존 목록·기존 실패 유지와 관련된 **174건 모두 통과**, exit 0을 확인했다. 검사 코드만 바뀐 마지막 단계 뒤에는 전체 검사를 다시 돌리지 않았다. 따라서 전체 결과는 6,571 통과/1실패/19skip, 후속 관련 검사는 174통과로 구분해 기록한다. 해결되지 않은 기능 실패가 1건 남았다는 뜻은 아니며, 검사 수정 전 결과를 소급해서 전체 통과로 쓰지 않는 것이다. 실행 후 pytest/Gazebo/주행 시험 프로세스 잔류가 없었다.
