# G2 센서 기반 진입의 제한 Gazebo 연결 준비

2026-10-29. [직전 합성 비교](../g2_entry_shadow_v1/README.md)의 가장자리 정지 표적 통과/복귀를 실제 센서 토픽·동역학·독립 보호·STOP으로 대조한다. 중앙 정지 표적 실패는 해결된 것으로 취급하지 않는다.

## 범위와 실행 전제

- 별도 `g2_entry_trial` 실행 파일과 `g2_entry_simulation_trial=true`, `use_sim_time=true`, 전용 판단 기록 경로가 모두 필요하다. 기본 launch와 기존 `local_pursuit` 실행 파일은 G2를 선택하지 않는다.
- 현행 센서 입력·영상 출발·중단·고장·`/drive` 발행은 기존 `LocalPursuit`를 상속한다. 독립 보호가 `/drive/safe`로 전달하는 구조를 유지한다.
- G2는 이번 시험에서 명시적으로 선택한다. 경기 주행 중 정지차를 자동 분류해 G1에서 전환하는 기능은 아직 없다.
- 초기 두 벽 확인, 현재 반환, 작은 외벽 재정합·연속 현재 벽, 중앙 복귀를 사용한다. 고정 외벽 가정은 시험 옵션이며 낮은 미검출 차량·복수 정렬 물체/가려진 뒤차 위험은 남는다.
- 새 trace schema4는 실제 사용한 G2 설정·입력·reset·출력을 기록하고 동일 모드로 재생한다. 기존 schema1–3을 G2 결과로 바꾸지 않는다.
- 먼저 연결/기존 기록 회귀와 빌드를 확인한다. 주행 배치·정상 종료·노면/접촉/STOP 판정은 실행 전에 이 문서와 고정 설정에 등록한다. 중단 시점에는 Gazebo 주행 전이었고, 재개 뒤 [run1](#run1-결과--등록-g2-판정-통과-원래-g1-판정-실패-보존)을 1회 실행했다.


## 과거 중단 상태와 재개 순서(아래 재개 결과로 대체됨)

2026-10-29 사용자 정리 요청으로 중단했다. `contracts1.sh`는 107개 검사 통과·종료 코드0이며 빌드나 Gazebo를 실행하지 않는다. 실행 담당의 마지막 프로세스 조회에서 자기 검사/프로브/Gazebo 잔류는 없었다. [검사 로그](contracts1.log)·[종료 코드](contracts1_exit.json)·[소스 해시와 상태](checkpoint.json)를 보존한다. 로컬 `checkpoint_source.zip`은 종료 시점의 관련 소스 보관본이며 Git 제외 대상이다. 저장소 전체의 과거 미커밋 변경은 그대로 둔다.

**구현됨:** `bypass_entry_follow.py`는 기존 `LocalPursuit.command`와 같은 입력 계약을 사용한다. `g2_entry_node.py`는 기존 신호·고장·명령 발행 경로를 상속하고 명시 시뮬레이션 허가, G1 센서 구성, 절대 경로의 전용 판단 기록을 요구한다. 기본 launch/기존 `local_pursuit`는 이 실행 파일을 고르지 않는다. `follow_trace.py`의 schema4는 별도 G2 옵션·reset·입력·출력을 재생하며 기존 schema1–3과 구분한다. 함수/계약 검사는 통과했지만 실제 ROS 노드 생성·토픽 전달의 실행 증명은 아니다.

**미완료:** 패키지 빌드·설치, G2 전용 fixture와 실행/평가 어댑터, 실제 센서 토픽·가상 MCU/모터·독립 보호를 거친 주행, 원시 판단 전체 재생. 아직 `run1`은 만들거나 실행하지 않았다. 자동 G1→G2 전환도 구현하지 않았다.

1. `contracts1.log`와 소스 해시를 대조하고, 기존 colcon 설정을 확인해 `arena_autonomy`를 빌드한다. 설치된 `g2_entry_trial` 진입점과 기본 OFF 구성을 확인한다. 변경 없이 동일107검사를 다시 반복할 필요는 없다.
2. `2026-10-27/official_departure_v2/fixture`와 `2026-10-28/official_traffic_v1/run.py`를 참고해 **별도 시험 복사본**을 만든다. 기존 원본/성공 주행 소스를 수정하지 않는다. G2 실행 파일·명시 시뮬레이션 허가·전용 trace를 연결하고 기존 독립 보호·영상 출발·MCU/센서 구성을 유지한다.
3. 합성에서 통과한 가장자리 정지 표적 한 조건부터 배치·시간·속도·정상 종료 기준을 실행 전에 등록한다. 설계 출발점은 표적 횡편이150 mm/전방1.2 m·G2 명령상한0.35 m/s다. 실제 공식 그리드/벽과 도로 위치를 먼저 대조하며 아직 확정 실행 설정은 아니다. 중앙 표적 실패를 배치 변경으로 숨기지 않는다.
4. 기존 G1 평가의 `앞차 뒤에 머무름`·HOLD·차체 전체 도로 내 조건은 우회 성공 판정과 다르므로 원래 판정은 보존하고 별도 G2 평가를 작성한다. 표적 종방향 통과·중앙 복귀·접촉·바퀴별 접지/잔디·실제 STOP·정상 종료·센서 전용 구독·출력 경계를 확인한다. 바퀴 중심만 검사했다면 접지면 결과로 쓰지 않는다. 지도/actor 정답은 평가에만 사용한다.
5. 소스·설정과 명령을 고정해 제한 Gazebo 시험1회를 수행하고 실패를 포함해 원시 근거를 회수한다. 동일 실패를 변경 없이 반복하지 않는다. 결과에 따라 필요한 원인 분석과 다음 작업을 선택한다.

이 절은 재개 전 계획의 보존본이다. 이후 실행 결과는 다음 절과 최신 후속 링크를 따른다. 합성 센서에서의 양측 가장자리 성공·중앙 실패, 고정 외벽 가정, 후방 가림의 잔여 위험을 유지한다. 커밋·푸시·외부 게시·Jetson/전원 변경은 하지 않았다.

## 10/29 재개: 연결 수정·빌드·실행 전 등록

체크포인트의 소스100개 해시가 재개 시점 파일과 모두 일치했다. 이후 아래 순서로 진행했다.

**연결 결함 수정.** 기존 `WallFollow.control`은 판단 detail 전체를 `/autonomy/status`에 합쳐 `json.dumps(allow_nan=False)`로 발행한다. G2 detail에는 NumPy bool과 후보 경로점이 들어 있어, 합성 입력으로 재현하면 첫 후보 선택부터 `TypeError: Object of type bool_ is not JSON serializable`이 났다([재현 기록](status_json_probe_before.log)). 그대로 Gazebo를 실행하면 첫 진입 판단에서 제어 노드가 멈췄을 것이다. `g2_entry_node.py`에서만 `command()`를 덮어써 `LocalPursuit.command`가 schema4 기록에 전체 판단을 먼저 남긴 뒤, 상태 발행용 detail을 JSON 안전한 요약으로 줄인다. 명령 속도·조향·예외 처리·`/drive` 경계는 바뀌지 않는다. 기존 계약의 `G2EntryNode.command is LocalPursuit.command` 단언은 명령 값/기록 동일성·직렬화를 직접 비교하는 검사로 바꿨다. [관련108검사 통과](contracts2.log)(기존107+새1).

**빌드.** 기존 방식 `colcon build --packages-select arena_autonomy --symlink-install`이 exit0이며 `g2_entry_trial` 진입점이 설치됐다. 기본 launch 파일은 G2를 고르지 않는다. [빌드](build1.log)·[진입점 확인](build1_entry.log).

**시험본과 사전 검사.** 월드는 5랩에서 쓴 [v2 신호 시험본](../../2026-10-27/official_departure_v2/README.md)을 그대로 참조한다. `prepare_fixture.py`가 만든 launch 사본은 월드 경로·뒤쪽30 cm 시험 카메라·실행 파일 `g2_entry_trial`·시작 자세만 바꾼다([차이](fixture/simulation.diff)). 첫 준비에서 표적 횡편이 −0.150 m는 공식 도로 다각형을 3.9×10⁻⁶ m² 넘어 기존 경로 검사가 거절했다([보존](attempt1_lateral150/)). 도로 경계가 중심선 기준 약0.02 mm 안쪽인 수치 경계 문제이므로 표적을 1 mm 안쪽 −0.149 m로 고정했다. 재검사는 통과했다([사전 검사](preflight.json)).

- 복귀 시작 직후(초록 후5.1–5.8 s) 차체 속도가0.35→0.08 m/s로 떨어졌다가 회복했다. 왼쪽 두 바퀴가 도로 경계 바로 바깥 잔디에 있는 상태에서 오른쪽으로 조향하던 구간이다. 모터축 속도가20 ms 간격으로83–194 rad/s를 오가고 좌우 바퀴 속도가 번갈아 바뀌었으며, 이를 20 ms 계수 차분한 측정 속도가0.4862/0.7293 m/s까지 튀었다. G2 입력 범위(0–1 m/s) 안이라 초기화는 없었다. [진단](slowdown_probe.py)·[출력](slowdown_probe.log).
- 이 Gazebo 월드는 도로 상단3 mm·잔디 상단2 mm 상자이고 마찰은 기본값이다. 공식 실물은 도로 포맥스3T·인조잔디6 mm이므로 **단차 방향과 노면 성질이 실물과 다르다.** 위 감속은 바퀴가 가상 잔디/도로 상자 경계를 넘는 시점과 **함께 관찰된** 것이다(10/29 후속 정정). 접촉력·마찰·바퀴별 하중을 분리 측정하지 않았으므로 단차 모서리를 단독 원인으로 확정하지 않으며, 실제 잔디→도로 복귀 성능의 근거로도 쓰지 않는다. 노면 고도·물성 변경은 이번 묶음에서 하지 않고 후속 검토로 남긴다.
- 6호출의 `entry_guide_input_reset`은 창 종료 뒤 STOP 제동 중 측정 속도−0.049 m/s에서만 생겼다. 주행 창에서는 없었다. 그러나 실제 정지·재출발 중 작은 음의 측정값이 나오면 G2 경로 기억이 초기화될 수 있다. STOP 뒤 제어기는 새 진입을 다시 판단해 `/drive` 양의 요청을 냈지만 MCU 래치가 차단했다. 기존 legacy 구조와 같다.
- G2 실행 시 FollowConfig는 실제 launch 값(최대 조향0.37106 rad·횡가속3.0 m/s²)으로, 합성 비교의 기본값(0.37 rad·3.5 m/s²)과 조금 다르다.
- 범위: 오른쪽 가장자리 20×15×12 cm 정지 상자 1조건, 도로 중심선 출발, 방지턱OFF, 저속0.35 m/s의 1회 결과다. 왼쪽 대칭 조건, 중앙 정지 표적(합성 실패 지속), 불규칙 외형, 숨은 뒤차, 자동 G1→G2 전환, 실물 동역학은 검증하지 않았다. 고정 외벽 가정의 오인 위험도 그대로다.

**당시 후속 제안(이후 왼쪽 결과는 [별도 보고](../g2_entry_left_v1/README.md) 참조).** (1) 같은 소스로 왼쪽 가장자리 대칭 1회를 실행해 좌우 부호 오류가 없는지 확인한다. (2) 계획대로 소수의 비사각형 대표 표적(돌출 바퀴·기둥/개구부·비스듬한 정지차)을 같은 하네스에 등록한다. 상자 결과를 실물 외형 성공으로 쓰지 않는다. (3) 공식 잔디6 mm·도로3 mm 높이를 반영한 팀 파생 노면으로 복귀 단차를 다시 볼지 결정한다(물성 변경이므로 근거와 범위를 먼저 정함). (4) 음의 작은 측정 속도에서 G2 기억을 지울지 유지할지 G1 입력 범위와 함께 검토한다. 중앙 정지 표적은 합성 단계 원인 분석이 먼저다.
