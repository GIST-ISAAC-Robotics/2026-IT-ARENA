# 이동 앞차의 정지에 대비한 우회 진입 공간 보존 비교

2026-10-29. 관측 창 순서 수정은 원거리 지연을 줄였지만 [이동 후 정지 조건](../g2_patch_motion_diagnosis_v1/README.md)에서는 앞차가 멈췄을 때 이미 진입 공간이 부족했다. 보호 여유/물성을 줄이지 않고 전방 추종에 공간 보존을 추가하는 선택형 후보를 비교한다. GPT가 설계·구현·분석·검토, GPT-6 Luna가 실행·대기·회수를 맡는다.

## 실행 전 등록

- `HandoffExecutionConfig.follow_entry_space_enabled`는 기본 `false`다. 이번에는 `observed_entry_space_v1`과 `trim_before_compare_v1`을 함께 명시하며, ROS 노드에는 아직 활성화 파라미터를 추가하지 않는다.
- 연속 두 관측 또는 앞서 얻은 이동 증거가 있고, 현재 전방 조각이 G1 진행 원호를 막으며 양쪽 직선 벽이 관측될 때만 추가 속도 상한을 계산한다. 무반환·경로 밖 조각·양벽 불성립에는 적용하지 않는다.
- 조각 중앙값까지의 후륜축 기준 거리에서 가장 긴 등록 전이 길이1.2 m를 뺀 값을 관측 창0.8 s로 나눈다. 음수면0으로 한다. 기존 G1/G2 명령보다 높일 수 없으며, 우회 진입 자체를 허가하는 조건은 바꾸지 않는다.
- 이는 **이동 앞차에도 더 긴 전방 공간을 남기는 시험 전략**이다. 상대 속도나 ID를 정답으로 받지 않는다. 기존 값의 재사용이 실물에서 최적이라는 뜻은 아니며, 추가 정지/진행 손실을 반드시 비교한다. 후방 차량 대응·실물 기구/제동은 보장하지 않는다.
- 비교 기준은 직전 `closed_window1`의 같은6조건이다. 정지·재출발/계속 이동/좌우 가장자리·원거리, 접촉·진입·통과·복귀·STOP과 schema5 재생을 확인한다. 먼저 영향 회귀를 통과한 뒤 각조건1회, 12 s+STOP. 같은 실패를 숫자만 바꿔 반복하지 않는다.
- 생산 기본값·물성·보호 여유·센서오차·평가기·대회 제어기의 정보 경계는 유지한다. 원본 기록·소스 ZIP/해시를 보존한다.

## 재출발 뒤 G1 복귀 미완료의 분해와 후속 시험

저장 입력에서 차량은 실제 중앙으로 돌아와10.3 s부터 `REACQUIRE`였다. 그러나 앞차와 가까워 G1이 `follow_gap_hold`/`follow_release_wait`로0을 내면 기존 연결은 '양수여야 G1 준비 완료'라며 복귀 확인을 계속 취소했다. 대신 G2 명령을 내보내며 간격 약0.33 m까지 접근했다. 이는 차량이 중앙으로 돌아오지 못한 실패와 다르다.

명시 `reacquire_policy=known_hold_v1` 후보는 G2 중앙 복귀 확인 후, G1이 현재 경로·점유 검사를 끝낸 위 두 정지 이유를 내면 정상 출력으로 인정한다. 서로 다른 두 스캔을 요구하되 확인 중에도0명령을 존중한다. 경계/경로 미확정·고장을 준비 완료로 승격하지 않으며 기본 `positive_command_v0`는 보존한다. G1 이력을 지우지 않는다.

같은 재출발을16 s+STOP으로 두 정책 대조하여 복귀 이후 추종 재개까지 확인한다. 12초 기본 비교의 실패를 소급 변경하지 않는다. 정지 가장자리/이동 후 정지 대표도 영향 확인한다. 추가 구현은 시험용이며 ROS 노드에 아직 연결하지 않았다.

### 복귀 전환 결과

영향 회귀180통과 뒤 [16초 새 조건](closed_rejoin1/report.json)과 [같은 시간 기존 조건](closed_rejoin_control1/report.json)을 대조했다. 새 조건은10.3 s 확인 중0명령을 내고10.4 s G1으로 돌아왔다. 복귀 이후 실제0.611 m를 더 진행했으며, 속도0.005 m/s 미만의 최장 구간은1.88 s였다. 전방 공간을 다시 확보한 뒤 추종이 재개됐다. 기존 조건은16초 내내 G1으로 돌아오지 않았다. 진행거리는 새3.368 m/기존4.279 m로 새 후보가 더 짧고, 이를 속도 성능 향상으로 표현하지 않는다.

[정지 조건 영향](closed_rejoin_stationary1/report.json)은 이동 후 정지/오른쪽 가장자리에서 기존과 같은11.8/9.5 s 복귀, 복귀 후 양수 명령과 진행을 확인했다. 모든 조건 접촉0·잔디 바퀴≤2·STOP·소스 불변, 16초 두 기록은 각800/800, 12초 두 기록은 각600/600 동일 재생이다. 중앙 복귀는 이미 됐는데 모드 인계만 막혔던 문제를, 실제 우회 궤적 실패와 분리한다.

### 명시 ROS 옵션 연결

생산 기본은 그대로 유지하고 `g1_g2_follow_entry_space:=true`, `g1_g2_reacquire_policy:=known_hold_v1`을 선택형 노드에 추가했다. 전자는 `g1_g2_preparation_policy:=observed_entry_space_v1`과 `g1_g2_persistence_window:=trim_before_compare_v1`을 함께 지정해야 한다. 관련185회귀는 통과했고 `arena_autonomy` 빌드도 완료했다.

첫 설치/노드 확인 `ros_options1`은 빌드 전에 source한 환경의 build 경로가 남아, 설치 사본 대신 원본을 가리키는 build 심볼릭 링크를 import해 검사에서 거절됐다. 양쪽 파일의 해시/내용을 대조했으며 이는 오래된 소스나 노드 동작 실패를 확인한 결과가 아니다. 실제 노드 검사는 그 단계에서 미실행이고 실패로그를 보존한다. 새 검사 프로세스의 `PYTHONPATH`만 비우고 ROS·현재 install 환경을 다시 source하는 `ros_options2`로 확인한다. 시스템/사용자 영구 환경은 바꾸지 않는다. 검사는 설치 코드·실제 ROS 파라미터·기록 header·센서 없는0출력/직접 `/drive/safe` 발행 부재에 한정하며 주행/독립 보호 체인 검증이 아니다.

`ros_options2`는 설치 사본의 해시 일치, 기본/후보 두 실제 ROS 노드의 파라미터·schema5 header, 센서 없는0속도 출력과 직접 `/drive/safe` 발행0을 확인했다. 두 기록 모두 accepted/written2·dropped/failed/pending/capture_errors0·기록 작업자 정상 종료였고 시험 중 소스는 변하지 않았다. 영구 환경 변경이나 Gazebo 재실행 없이 완료했다. 앞의 “아직 연결하지 않음”은 각 합성 시험을 시작하던 시점이며, 현재는 **기본OFF인 명시 ROS 옵션까지 연결·빌드·제한 검증 완료**다.
