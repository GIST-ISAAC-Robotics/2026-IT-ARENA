# 공식 출발 선택형 ROS 계약 — 첫 시도 실패

- 회귀 161개 통과 후 `run.sh`의 ROS 실행은 exit 1이다. 12개 사례(초록만/부분 빨강/전체 소등 미출발, 올바른 전환 출발, 초록 소등 후 유지, 영상 누락 정지/복구)는 통과했다.
- 이어 재시작 검사에서 `no-resume requires fresh initial stopped state`로 중단됐다. 아직 주행 중인데 정지 후 무재개용 함수를 바로 호출한 시험 구성 오류다. 검사를 약화하지 않고 후속 v2에서 제어기 종료→보호층 정지 확인→재시작 순서를 넣는다.
- 전체 합격·최종 STOP 완료로 표시하지 않는다. 실패 시 상태는 `RUNNING`, MCU `ACTIVE`였으며 이후 모든 소유 프로세스 exit 0·잔존 0으로 정리됐다. 이때 실행기는 실패 경로에서 별도 STOP을 시도하지 않았다. v2에서 실패 판정을 보존한 채 정리 전 STOP 시도를 추가한다.
- 그래프와 런타임 소스 해시는 일치했다. 상세 `run/report.json`, `run/events.json`, 실행 당시 `run/source_snapshot.zip`을 보존한다. MCU 갱신 진단 목록은 비어 있으며 지연이 없었다고 대체하지 않는다.

Gazebo/실물 제동이 아니라 가상 센서→ROS 보호층→가상 MCU→임시 종방향 모델 검사다. 센서·보호 한도·단일 모터축 환산·기본 신호 모드는 바꾸지 않았다.
