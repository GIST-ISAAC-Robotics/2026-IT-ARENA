# STOP 마지막 0.5초의 자료 완비 수정

2026-10-13. 실제 제어/물성을 바꾸지 않고 사후 감사의 허점을 재현·수정했다.

- [수정 전](before_tests.log): 꼬리 잘림·내부 공백·시작 공백의 3반례에서 기존 감사기가 STOP을 통과시켜 회귀가 모두 실패했다. [당시 소스](before_source_snapshot.zip)를 보존했다.
- v4는 기존 **0.5초·0.01 m/s**를 유지하고, 기존 G1 계측 기준 `POSE_MAX_GAP_S=0.05 s`를 STOP 구간에도 적용한다. 양 끝을 덮는 실제 pose 구간과 내부 공백을 요구하며 보간/외삽으로 채우지 않는다.
- [수정 후 회귀](after_tests.log) 28개 통과. [등록된 5입력 재감사](recheck_report.json)는 원본 해시 불변이다. 네 seed 0 기록의 STOP 완비·속도 조건은 통과했고, 추가 `left_s1`의 기존 HOLD 실패는 그대로다.
- 5개 STOP 창의 최대 pose 간격은 모두 3 ms였으며 속도 상한도 기존 0.01 m/s 이하였다. 기존 소스/실행 결과를 새 버전 성공으로 덮어쓰거나 추가 주행하지 않았다.

[재현](run_before.sh), [수정 후 실행](run_after.sh), [재감사기](recheck.py), [수정 후 당시 소스](after_source_snapshot.zip). 후속은 같은 증거 요구를 실행기 STOP 완료 판정에도 연결하는 것이며, 그 변경은 이 저장 입력 재감사에 소급 포함되지 않는다.
