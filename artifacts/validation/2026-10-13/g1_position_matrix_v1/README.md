# G1 분리 후보: 남은 고정 초기 위치 검증

2026-10-13 실행 전 등록. 이전 네 조건 seed 0을 다시 돌리지 않고 기존 설정의 seed 1/2(상대차 시작 진행 위치 −0.10/+0.10 m)를 확인한다. 노이즈 난수 seed나 물리 결정성 시험이 아니다. 기본 모드 전환 없음.

- 순서: seed 1의 왼쪽·오른쪽·초기 대기·첫 U자, 이후 같은 네 조건 seed 2. 최대 8회다.
- 기존 `g1_side_occlusion_v1.json`, `g1_traffic_extensions_v1.json`의 시간·공간·STOP·정상 종료 판정을 그대로 사용한다. 새 위치 때문에 판정선·물성·구동을 조정하지 않는다.
- 한 실행의 gate/입력/STOP/종료 실패 또는 사후 관측 감사/판단 재생 실패가 나오면 남은 자동 실행을 중지하고 원본을 보존한다. 성공할 때까지 같은 조건을 재실행하지 않는다.
- 최대 1 m/s, 단일 모터축 28카운트·15:1·65 mm, C1 순차 취득/보정·독립 보호 유지. 우회/추월·새 센서/공식 신호/방지턱/Jetson 시험 없음.
- 세 고정 위치의 제한 검증이다. 서로 다른 물성/잡음·실차 안전이나 전체 G1 행렬 완료를 뜻하지 않는다. 접촉 이벤트 0은 연속 무접촉 증명이 아니다.

## 결과: 첫 조건 사후 감사 실패로 중단

`side_left_s1`의 기존 주행 12 gate·입력·명시 STOP·정상 종료는 통과했고 판단 374/374개도 일치했다. 그러나 `side_left_s1.postcoverage.json`의 HOLD 자세 대조가 실패하여 나머지 7조건은 실행하지 않았다. 이 행렬을 통과로 표시하지 않는다. 최종 STOP의 마지막 0.5초 pose 속도 최대 0.009578 m/s와 잔존 프로세스 0은 별도 확인했다.

`diagnose_hold.py`/`hold_diagnosis.json`은 기존 보고서/감사의 입력 해시를 대조해 6.059–6.161 s를 분석했다. 52자세의 최대 간격은 3 ms, 구간 이동은 1.055 mm, 최대 구간 속도 0.014158 m/s이며 0.01 m/s 초과 구간 합은 64 ms였다. 드문 trace 양 끝에서는 0.00267/0.00588 m/s이지만 중간에서 문턱을 넘었다. 해당 6개 판단 요청·5개 구동 진단 목표는 모두 0이었다.

따라서 HOLD라는 **정지 요청**을 실제 안정 정지 완료로 읽을 수 없고, 느슨한 간격의 두 저속 표본도 중간 정지를 증명하지 않는다. 토크/적분의 동시 관측만으로 이 짧은 움직임의 원인을 단정하지 않는다. 기존 실패와 0.01 m/s 기준을 유지하며, 이를 없애려고 물성·토크·보호선이나 감사 gate를 바꾸지 않았다. 자동 주행 행렬은 여기서 마감/보류하고 입력 관측·연관의 독립 오프라인 작업을 진행한다.
