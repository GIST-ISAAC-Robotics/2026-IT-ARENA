# C2 입력 감사기: 자료 무결성과 교정 후보 분리

2026-10-13. 실물/구동/ROS 없이 합성 기록만 사용했다.

## 보존한 문제

`run_before.sh`는 검증된 옛 최소 묶음의 감사기를 읽었다. SHA-256 `b81f6a80578e265f6f80b831cef63eff9c9adb41a49a069322b789069cb00703`.
[수정 전 결과](before.json)는 순번 누락·요청 고정 구간의 일부만 관측·재부팅 뒤 엔코더 부재에서 모두 `candidate_only=true`였다. 순번 누락을 파일 문법 오류와 분리하는 정책 자체는 유지하되, 불완전한 자료에서 교정 후보를 내는 것은 보완했다. 이 실행의 코드 0은 문제 재현 도구의 정상 종료이지 감사기의 적합성 통과가 아니다.

## 수정과 확인

- 부팅별 필수 스트림 존재를 확인한다. 파일 전체에 엔코더가 있었다고 새 부팅의 IMU만 있는 상태를 유효 처리하지 않는다.
- 구간별 자료량·관측 시간·최대 간격을 명시해야 후보 통계를 낸다. 요구조건을 생략하면 거절하며 실물 교정에 적절한 수치를 임의 확정하지 않는다.
- 구간 내부 순번 누락, 양끝 미관측·큰 표본 간격, 카운트 변화는 후보 거절 사유로 분리한다. 파일 순서 검사와 `recorded_sequence_complete`는 별개다. `complete_capture_verified=false`는 항상 유지한다.
- 중복 JSON 키와 잘못된 객체·수치 범위를 명시적으로 거절한다. bias 적용/구동/교정 완료 허가는 없다.

`run.sh` 종료 코드 0, 관련 회귀 **121개 통과**. [합성 행렬](matrix.json) **7/7 기대 결과 일치**, 소스/입력 불변이다. 명시한 자료 기준을 충족하는 합성 40 ms 구간 하나만 미적용 후보를 냈다. **40 ms·5표본은 테스트 fixture이며 실제 IMU 교정 권장값이 아니다.** 다른 6조건은 후보를 거절했다. [기존 예시](legacy_example_report.json)도 요구조건이 없어 후보를 거절한다. 원본 예시와 이전 보고서를 고쳐 과거 통과를 새 결과로 소급하지 않았다.

`source_snapshot.zip`과 `matrix.json`에 당시 소스·입력 해시를 보존했다. 실제 취득 시계/온도/진동/축·장착·펄스 누락·차체 정지는 검증하지 않았다. [계약·이관 절차](../../../../docs/hardware/HARDWARE_CAPTURE_AUDIT_2026_10_13.md).
