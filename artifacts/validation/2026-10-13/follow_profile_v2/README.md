# G1 비용 분해 v2 — CPU와 native GC 관측

회귀 33개, 두 입력 재생/반복 출력 일치·입력/소스 해시 불변을 확인했다. GC 설정·강제 collection·전원·제어 소스는 변경하지 않았다. v1과 달리 스레드 CPU 시간과 GC 콜백의 경과시간을 함께 기록했다.

| 입력 | 전체 p99 / 최대 ms | 스레드 CPU p99 / 최대 ms | GC p99 / 최대 ms | 전체 20 ms 초과 |
|---|---:|---:|---:|---:|
| 왼쪽 | 18.953 / 28.050 | 18.956 / 28.053 | 14.582 / 16.850 | 5 |
| 앞차 초기 | 22.613 / 26.710 | 22.617 / 26.715 | 18.855 / 22.706 | 18 |

모든 측정 행에 GC 3회가 겹쳐 GC 없는 그룹과의 대조는 불가능했다. 분포 분위수끼리 뺀 값을 비GC 비용으로 해석하지 않는다. 큰 벽시계 비용과 CPU 비용이 비슷하며 GC 구간도 크지만, 전체 trace를 메모리에 보유하는 시험기 특성이 섞여 있다. 이것만으로 운영 제어기의 GC 문제를 확정하거나 GC를 끄지 않는다.

다음 v3는 입력을 한 줄씩 읽고 사전 재생의 전체 outcome 목록도 계측 전에 해제한다. 제어 소스·GC 설정은 유지한다. 파일 읽기/JSON은 여전히 별도이므로 v3도 ROS 실시간 마감 시험이 아니다. v2의 계측 소스·결과는 각 `source_snapshot.zip`에 보존한다.
