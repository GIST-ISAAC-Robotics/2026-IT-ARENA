# 공식 출발 선택형 ROS 계약 — 정지 순서 수정 후

`run.sh` exit 0. 사전 회귀 **163개**, 실제 ROS 사례 **20/20개** 통과. 실행 시점 소스는 `run/source_snapshot.zip`, 해시·개별 판정은 `run/report.json`에 있다. 상세 `events.json`은 로컬 보존/Git 제외다.

- 입력은 가상 RGB·LiDAR·IMU·단일 모터축 28카운트/15:1/65 mm이며 `/drive → 보호 → /drive/safe → 가상 MCU → 출력 보호` 경계를 거친다. 정상 명령 상한 0.6 m/s의 가상 직선·±2 m/s² 임시 종방향 모델이다. Gazebo/실물/전체 코스 시험이 아니다.
- 초록만, 부분 빨강, 빨강 전체, 초록 없는 소등에 미출발. 올바른 4빨강→초록 전환 후 출발하고, 초록 소등 후 허가는 유지한다. 신선한 영상 단절에는 SENSOR_STOP, 복구 후 기존 경기 허가를 유지한다.
- 제어기 종료 뒤 보호층의 0출력을 확인한 후 재시작한다. 재시작의 초록만으로는 출발하지 않고 새 빨강→초록을 요구한다. 명시 STOP은 고정되고 CLEAR만으로 움직이지 않으며 별도 ARM 후에만 재개한다.
- 최종 명시 STOP·신선한 0출력·가상 모델 정지·단일 그래프 수렴을 확인했다. 6개 실행 역할은 모두 exit 0, 잔존 영상/세션 프로세스·정리 오류 0, 런타임 소스 해시 일치다. MCU 마감 진단 목록은 비어 있어 갱신 지연 부재를 증명하지 않는다.
- [v1 실패](../race_start_ros_v1/README.md)는 보존했다. 정지 전제를 맞추도록 검사 순서를 수정했으며 실패/보호 판정선을 낮추지 않았다. 시험기가 다른 실패로 중단될 때도 원래 실패를 유지한 채 정리 전 STOP을 시도하도록 회귀를 추가했다. 이 실패 경로는 단위 모의시험이며 이번 정상 ROS 실행에서 의도적으로 실패를 주입한 것은 아니다.

순수 `RacePermission` 후보는 아직 미연결이다. 이번에 확인한 것은 기존 MCU STOP/CLEAR/ARM 정책과 선택형 픽셀 검출기의 조합이다. ROS 단계 유지시간은 검사 관측용으로 정하며 공식 실물 랜덤 지속시간 재현은 앞선 합성 검사와 구분한다. 기본 신호 모드/주행 launch/물성/보호 한도는 그대로다.
