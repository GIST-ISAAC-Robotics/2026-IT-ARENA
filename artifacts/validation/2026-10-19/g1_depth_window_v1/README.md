# 깊이 각도 창 후보 — 2026-10-19 중간 마감

**운영 미연결, 실제 저장 입력 AB/BA 미실행, 성능/전체 제어 동등성 미판정.** 상세 해석과 재개는 [기술 보고서 §15~16](../../../../docs/autonomy/G1_OBSERVATION_ENVELOPE_2026_10_16.md#15-1019-깊이-각도-창-후보--미채택-중간-결과)이 기준이다.

| 자료 | 상태 |
|---|---|
| `candidate.py` | 모든 원점을 포함하는 각도 상계 후보. 운영 모듈에서 import하지 않음 |
| `pytest.log`, `first_failure_sources.zip` | 최초 103통과·3실패와 당시 후보/시험/운영/감사 소스 보존 |
| `diagnose.py`, `diagnose.log` | seed 19/73/1019 각각 후보↔운영 차이 0, 후보↔감사 차이 3. Python 출력 완료와 별개로 래퍼가 exit 인자를 잃어 반환 1; 정상 실행으로 세지 않음 |
| `run_final_checks.sh`, `final_pytest.log` | 원점 차이를 별도 명시한 관련 107회귀 통과, 실제 pytest/스크립트 종료 0 |
| `final_before.sha256`, `final_after.sha256`, `final_source_diff.txt` | 마지막 검사 전후 세 파일 hash 일치, diff 비어 있음 |
| `probe.py`, `run_checks.sh` | 실제 입력 함수 비용 대조 준비만. 첫 실패/사용자 마감으로 비용 대조는 실행하지 않음 |

정확한 원점은 방향이 정의되지 않는다. 운영과 감사의 부호 있는 0 합산 차이가 광선 선택을 바꾸는 고정 반례를 발견했다. 마지막 시험은 후보의 운영 의미 보존과 원점 아닌 질의의 감사 일치를 확인하며, 원점에서 어느 판정이 맞는지는 해결하지 않는다. 운영 함수/감사 함수의 의미 변경은 하지 않았다.

다음 실행은 새 디렉터리를 만들고 실행/시험 소스를 먼저 보존한다. `probe.py`의 출력 경로는 자체 위치 기준이고 `run_checks.sh`는 이미 있는 `pytest.log`를 덮어쓰지 않는다. 새 전체 회귀/성능을 통과한 것으로 소급하지 않는다.
