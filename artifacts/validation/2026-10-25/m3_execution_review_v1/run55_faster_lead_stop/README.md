# run55 — 앞차 초기 0.50 m/s 뒤 급정지

[실행 전 등록](../FASTER_LEAD_PLAN.md)의 조건을 한 번 수행했다. 실제 제어기·센서·기구·보호 설정은 run53과 같으며 추가 actor를 제외하고 첫 4초 앞차 속도를 0.35→0.50 m/s로 변경했다.

- [`report.json`](run/report.json): `passed/run_valid/harness_valid=true`. HOLD **2.930 s**, 재개 지연 **0.744 s**, 재개 뒤 **1.820 m**, 전체 **4.859 m**, 최종 앞차 간격 **0.624 m**. 최소 표본/보수적 구간 간격 **0.360745/0.360744 m**.
- [`stop_diagnostics.json`](stop_diagnostics.json): 정지 전 3.5–4 s 자차 실제 구간 속도 중앙값 **0.528 m/s**, 최대 **0.737 m/s**. 그 창 직후 마지막 trace는 약 **0.517 m/s**, 안전 목표 **0.55 m/s**, 앞차 간격 **0.793 m**였다. 센서 오차 없이 수행한 저속 사례다.
- 앞차 정지부터 첫 안전 목표 0까지 **1.804 s**. 이것은 최초 반응 지연이나 감속 시작 지연이 아니다. 거리 기반 추종이 멈춘 앞차에 접근하면서 목표를 낮추고 0에 도달한 시각이다. 모든 구간에서 최소 간격 기준은 통과했다.
- 측방 위협 촉발 **0회**. 기본 G1 추종 결과이며 M3 측후방 복귀/간격 해결이 아니다.
- 명시 STOP 6항목 참·정상 종료·잔존 0. 요청 후 안정 정지까지 이동 **17.35 mm**, 0.745 s는 안정 창 확인을 포함한다. 재생 **789/789 동일**, 노면 9,724표본 이탈 0, 실행기 115파일 전후/후처리 해시 일치 및 평가기 자체 소스 불변.

run54의 Python 사전 검사는 성공했지만 외곽 bash 마지막 `exit 0\r`는 오류였다. [원본과 구분](../run54_faster_lead_preflight/wrapper_failure.json)을 보존하고 run55 실행기만 LF로 정정했다. 사전 검사·주행을 결과가 나올 때까지 반복하지 않았다.

전체 랩, 고속·실물 제동, 충격 동역학 또는 50 Hz 실시간 성능의 증명은 아니다.
