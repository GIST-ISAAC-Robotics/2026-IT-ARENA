# run64 — 새 경기에서 이전 출발 사실 미재사용

[사전 등록](../M4_NEW_RACE_PLAN.md)대로 한 번 실행했다. 관련 143회귀·같은 경기 과거 입력 대조 뒤 GPT-6 Luna가 고정 명령을 실행·회수했고 GPT가 원본을 검토했다. 사용자 정리 요청에 따라 이 시험 이후 새 작업은 시작하지 않았다.

**새 경기 대기 판정 `m4_operation.passed=true`, 16개 gate 모두 참.** 기존 경기에서 실제 약 1.02 m/s 구간 주행 → `new_race` → MCU STOP → 명시 확인 → CLEAR → 새 ARM 순서를 거쳤다. session은 같고 경기·영상 세대는 각각 정확히 +1, 이전 `started`/`visual_start_fact`는 false가 됐다. 새 신호는 보내지 않았다.

| 항목 | 결과 |
|---|---|
| 중간 실제 정지 | 0.5 s 밀집 창 최대 0.000334 m/s |
| 확인 뒤/재ARM 전 | 1 s 실제 정지·안전 목표 0 |
| 새 ARM 뒤 신호 대기 | 8.119–18.601 s, **10.482 s** 정지 |
| 대기 구간 밀집 자세 | 5,162구간·최대 공백 3 ms·최대 속도 0.001008 m/s |
| 대기 중 MCU/정책 | ARMED/ACTIVE, `wait_visual_start`, 안전 목표 0 |
| 종료 | 마지막 STOP·밀집 정지·정상 종료·잔존 0 |
| 재생·노면·출처 | 89/89 동일·9,505표본 이탈 0·133파일 전후/후처리 일치 |

**원본 교통 `passed=false`는 보존한다.** 새 신호 없이 정지하라는 시험이므로 원래 앞차 추종의 HOLD/재개/진행/최종 간격 gate는 실패했다. 이 수치를 지우거나 원래 교통 시험의 성공으로 바꾸지 않았다. 별도 M4 판정은 사전 등록한 부정 조건과 기존 입력·기하·접촉·노면·종료 조건을 사용하며 `run_valid=true`다. 종료 STOP 전 래치 0 조건도 중간 명시 STOP 때문에 원본에서는 false다.

[원본 보고서](run/report.json), [고정 명령](command.txt), [노면 검사](surface_contact_eval.json), [재생](follow_trace_replay.json). 상세 운영/센서 입력은 로컬 보존·Git 제외다. 새 출발 신호를 다시 보여 두 번째 경기를 실제로 달리는 시험·공식 4-red·실물 MCU/차량·무선 운영 검증은 아니다. 같은 경기 run61의 HOLD 0.912 s 실패도 그대로 남는다.
