# 같은 측면 재관측 기록 보존 — 10/25 조사

## 재현된 결함

`_release()`는 현재 측방 위협이 보이면 `records[side]`를 즉시 덮어쓴다. 반환이 같은 차량이라는 보장이 없으므로 후방 마스크에 남은 A의 가능 영역을 B의 새 반환으로 대체할 수 있다.

- run36은 이력 창 부족과 벽 근처 B 분류 때문에 유효한 대조가 아니었다. 원본 보존.
- run37은 시각마다 이력 포함을 직접 검사하고 A 단독/B 단독/A+B를 비교했다. 각 상자 크기 0.20×0.10 m, 두 상자의 횡면 간격 0.06 m, 상대 종방향 속도 0.4 m/s다. ego는 고정이고 각 스캔 내 물체 이동은 없으므로 실제 회전 센서/동역학 재현은 아니다.
- A는 뒤로 이동해 −0.65 m에서 멈추고, B는 앞쪽에서 측방 창에 들어왔다가 다시 전진한다. A 단독은 끝까지 미해제, B 단독과 A+B는 4.7 s에 해제됐다. A+B에서는 A의 반환이 0인 3.2–3.8 s에, 이전 관문이 막힌 상태에서 기록 점이 갱신됐다.
- 이 결과는 충돌 재현이 아니라 **이전 미확인 위협을 잃는 상태 결함**이다. 일반 운용 허가나 상대 차량 식별 검증으로 쓰지 않는다.

## 수정 수용 조건

1. 새 측면 반환만으로 미확인 이전 영역을 삭제하거나 기록 만료를 갱신하지 않는다. 여러 물체를 한 강체로 가정하지 않는다.
2. 지금 스캔으로 이전 가능 영역을 검사하고, free가 아닌 나머지를 보존한다. 현재 반환의 가능 영역을 합칠 경우 전체 영역의 합집합을 사용하며, 영역 크기/계산 상한 초과는 미확인으로 남긴다.
3. 같은 스캔 재사용·세대/시각 단절·운동 이력 부족·만료는 양의 해제로 바뀌지 않아야 한다. 명시 reset과 구분한다.
4. 두 물체 반례는 수정 전 실패와 수정 후 결과를 따로 보존한다. 단독 정상 추월의 복귀 가능성과 저장 run17/21·run27/32/35의 출력 변화도 대조한다.
5. 보수적 영역이 늘어 단독 복귀까지 막히면 그것도 결과로 보고한다. 시험만 통과시키려고 후방 미관측 칸이나 TTL을 면제하지 않는다. 그런 경우 모델 가정/관측 한계와 구현 결함을 구분한 다음 설계를 선택한다.

run35 주행/재생이 끝나기 전 실행 소스를 변경하지 않는다. 현재 `release_to_baseline` 자체가 기본 false인 시뮬레이션 후보이며, 수정 결과를 기본 주행기에 자동 채택하지 않는다. 독립 보호·STOP·노면·측방 간격은 유지한다.

## 단순 장부 대조(run38)

모든 fresh 위협의 기록을 따로 보존하고 현재 관문이 해제를 확인한 기록만 지우는 미연결 시제품을 검사했다. 정상 전진 단독은 2.1 s에 해제됐지만 접근 후 전진하는 B 단독은 이전 기록의 1 s 만료로 해제되지 않았다. A 단독/A+B도 해제되지 않았다. 최대 기록 11개·누적 14,964칸으로 비용도 늘었다. 따라서 이 장부를 그대로 주행에 연결하지 않는다.

후속은 새 기록의 가능 영역이 이전 미확인 영역을 **포함하는 것이 확인될 때만** 교체할 수 있는지 비교한다. 물체 ID 연관이 아니라 집합 포함 관계를 확인해야 하며, 경계/격자 차이 때문에 포함을 입증하지 못하면 옛 영역을 보존한다. 단순 최근접 반환·같은 측면·비슷한 크기만으로는 교체하지 않는다. 별도 합성 대조 뒤에 구현 채택 여부를 정한다.
