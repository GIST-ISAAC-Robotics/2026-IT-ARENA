# M4 — B3 주행 중 명시 STOP·같은 경기 재개 시험

2026-10-25 GPT 사전 설계. 실행 전 등록이며 결과는 별도 run에 보존한다.

## 범위

현 G1 `corner_distance_candidate`/`per_ray_candidate`/회랑 후보와 `race_control_mode=b3_candidate`를 명시 선택한다. M3 측방 후보는 켜지 않는다. 자차·구동·센서·보호·물성은 유지한다. 앞차는 기존 `stop_restart` 일정(0–4 s 0.35 m/s, 4–9 s 정지, 이후 0.35 m/s), seed 0이다. RGB 임시 신호등만 사용하며 공식 4-red 출발·M5 그리드 시야는 검증하지 않는다.

시험기만 격리 ROS/Gazebo 환경에서 운영자의 정해진 명령 순서를 재현한다. 실제 운영 도구의 미전송 기본값·사람 확인 원칙은 바꾸지 않는다. 시험기의 명시 `--race-operation-test` 없이는 기존 실행 경로와 판정이 같다. `/race/command`와 `/actuation/{arm,stop,clear_stop}`만 사용하고 주행 명령을 발행하지 않는다.

## 순서

1. B3 시작 래치·MCU DISARMED·초기 관측을 확인한 뒤 시험용 초기 확인 1회, MCU ARM 1회. 실물 운영용 자동 승인 기능이 아니다.
2. 신호 이후 2 s에 상위 STOP 1회. 수락 응답과 같은 개입의 래치를 확인한 뒤 MCU STOP 1회. 실제 사전 속도가 0.10 m/s 이상이었는지는 사후 밀집 자세로 별도 판정한다.
3. MCU STOP 이후 최소 1.5 s·MCU `stationary_ready`를 기다리고 같은 session/경기/개입 번호로 확인 1회. 이때 정답 자세는 명령 생성에 쓰지 않는다.
4. 확인 뒤 0.5 s는 MCU STOP을 유지한다. CLEAR 1회 후 다시 0.5 s DISARMED 대기, ARM 1회. 두 대기 구간 모두 실제 정지·안전 목표 0을 사후 확인한다. 응답 유실·거절·새 개입·MCU 고장은 자동 재시도/자동 번호 교체 없이 실패한다.
5. 최초 신호 사실·경기 세대가 그대로인 채 주행이 재개되는지 확인한다. 원래 앞차 정지/재개 일정과 종료 시 명시 STOP·밀집 정지·정상 종료도 보존한다.

## 판정

- STOP 전 밀집 자세의 실제 속도 ≥0.10 m/s. 중간 STOP 뒤 6 s 이내 0.5 s 밀집 정지(<0.01 m/s, 기존 표본 공백 기준) 확인.
- 확인 뒤/ARM 전 안전 목표 0·실제 정지. 같은 session/경기/영상 세대, `visual_start_fact` 유지, 개입 번호 임의 변경 없음. 새 출발 신호 입력 없음.
- ARM 뒤 실제 속도 0.10 m/s 도달 ≤2.5 s, 이후 진행 ≥1 m. 명시 ARM 이후 새 MCU 세대 목격 전 정책 허가가 나지 않아야 한다.
- 기존 최소 차간격 0.15 m·접촉/도로 이탈 0·입력/출처·독립 보호 연결·종료 STOP/밀집 정지/정상 종료를 유지한다. 기존 앞차 HOLD·최종 간격 판정도 원본에 남긴다.
- 기존 교통 평가기의 '마지막 STOP 전 MCU 래치 0'은 이 시험에서 의도적으로 맞지 않는다. **원래 판정은 그대로 보존**하고, M4 결과에서 등록된 중간 STOP의 boot/generation/reason/시간에 한정해 구별한다. 다른 고장/STOP은 실패다. 실패를 숨기기 위해 모든 래치를 제외하지 않는다.

최초 실패를 분류하고 근거 없이 재실행하지 않는다. 실차·고속 제동·무선 조작·M1/M3 해결·기본 채택의 증명이 아니다.
