# M4 새 경기 분리 — 실행 전 등록

2026-10-25. 같은 경기 재개 run61은 실제 정지/재ARM/재출발을 보였지만 기존 앞차 HOLD 1 s 결합 기준은 실패했다. 같은 실패를 성공까지 재실행하지 않는다. 다음은 **새 경기의 이전 출발 사실 제거**라는 별도 필수 조건이다.

## 고정 조건과 순서

- run61의 자차·구동·센서·물성·G1 경로·보호·임시 RGB 출발 신호·앞차 일정·seed를 그대로 쓴다. 추가 센서 주입이나 M3는 없다.
- `--race-operation-test new_race`를 명시한다. 처음 신호로 실제 출발한 뒤 green+2 s에 상위 `new_race`를 1회 요청한다. 이전과 같은 소프트웨어 MCU STOP을 별도로 보낸다.
- 정지 뒤 시험용 명시 확인 1회, 0.5 s 대기, CLEAR 1회, 0.5 s 대기, ARM 1회. 원래 경기로 돌아가지 않으며 **새 출발 신호는 보내지 않는다.** 환경의 초록색은 그대로 두어 재검출 우회가 없는지 본다.
- 명령 생성에는 정답 자세를 넣지 않는다. 기존 부재/신선도/세대 검증·응답 유실 재시도 금지·마지막 STOP과 정상 종료를 유지한다.

## 별도 판정

1. 초기 신호로 실제 움직인 뒤 명시 초기화한다(직전 0.2 s의 이동 ≥0.02 m, 밀집 자세 범위 완전).
2. 경기·영상 세대 각각 정확히 +1, session 유지. 새 경기에서 이전 `started`/`visual_start_fact`는 false여야 한다.
3. 중간 밀집 정지와 확인/CLEAR 대기는 run61과 같다. 실제 정지 <0.01 m/s·0.5 s 창, 공백 ≤0.05 s. 별도 ARM은 MCU 새 세대로 확인한다.
4. ARM 후 끝까지(최소 1 s) MCU는 ARMED/ACTIVE이되 상위 정책은 `wait_visual_start`, 안전 목표 0, 실제 움직임 <0.01 m/s여야 한다. 이는 MCU가 꺼져서 못 움직이는 시험과 구분한다.
5. 기존 교통 평가의 입력/출처·간격·접촉·노면·마지막 정지·정상 종료를 모두 요구한다. 앞차를 따라야 한다는 HOLD/재개/진행/최종 추종 간격은 **새 경기 신호 대기라는 자극과 양립하지 않으므로 이 별도 시험의 목표가 아니다.** 원래 교통 판정은 그대로 계산·보존하며 성공으로 바꾸지 않는다.

첫 실패를 보존/분류한다. 새 신호를 주고 두 번째 경기까지 실제 달리는 것은 이 시험 범위가 아니다. 공식 4-red 검출·그리드 시야·실차 운영 완료도 아니다.
