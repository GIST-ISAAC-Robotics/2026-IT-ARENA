# M4 새 경기의 두 번째 픽셀 신호·실제 출발 — 사전 등록

2026-10-26. 기존 run64는 새 경기 초기화·재ARM 뒤 새 신호 없이 10.482초 정지한 부정 조건이다. 이번에는 같은 임시 신호등을 실제로 다시 빨강→초록으로 바꾼 뒤 새 영상 세대에서 출발하는 정방향 연결을 별도로 확인한다. 공식 4-red/그리드·실차 운영 시험이 아니다.

## 고정 범위

- G1 `stop_restart`, seed 0, `corner_distance_candidate`·`per_ray_candidate`·회랑 후보, 판정 기록/제동 진단을 유지한다. M3·신규 센서 주입·물성/출력/보호 변경은 없다.
- 선택형 `--race-operation-test new_race_restart`에서만 시험기 어댑터를 생성한다. 기존 `same_race`/`new_race` 순서와 기본값은 유지한다.
- 첫 출발 뒤 기존 `new_race` 운영 순서(새 경기, 별도 MCU STOP, 확인, CLEAR, 재ARM)를 그대로 쓴다. 재ARM 목격 뒤 1.5초 이상 기다린 다음 실제 렌즈를 빨강으로 요청하고, 빨강 적용 확인 뒤 2초를 유지해 초록을 요청한다.
- 신호 서비스 응답은 요청 수락일 뿐 렌더링/카메라 검출의 증명이 아니다. 적용 상태·새 세대 픽셀 출발 사실·실제 움직임을 각각 기록한다. 신호 상태는 시험기에만 입력하며 제어기 구독에 넣지 않는다.
- 렌즈 색상 제어는 각 1회 요청, 실패/응답 유실/새 세대·boot·STOP은 재시도 없이 실패한다. 정답 위치로 시험 명령을 결정하지 않는다.

## 판정

1. 이전 run64의 초기 움직임·명시 정지·확인/CLEAR 중 정지·새 경기/영상 세대·재ARM 조건을 **두 번째 신호 전 구간**에서 그대로 확인한다. 구간 한정임을 따로 표시하며 원래 교통 판정은 보존한다.
2. 두 번째 초록 요청 전까지 정책/픽셀 출발 사실 false, 안전 목표 0, 재ARM 후 밀집 실제 속도 0.01 m/s 미만을 요구한다. 재ARM부터 두 번째 초록 요청까지 최소 1초이며 누락/노후 상태를 성공으로 세지 않는다.
3. 빨강 적용 2초 이상 후 초록 요청, 두 색상 적용 확인과 새 경기/영상 세대의 출발 사실을 모두 요구한다. 첫 경기 시작 사실의 재사용은 실패다.
4. 두 번째 초록 적용 확인 이후 2.5초 이내 실제 속도 0.1 m/s 이상, 이후 실제 변위 1 m 이상을 요구한다. 구간 자세 공백은 기존 0.05초 기준이다. 목표 명령만으로 출발을 주장하지 않는다.
5. 전체 시험의 센서 전용 입력 경계·간격/접촉·노면·출처·마지막 명시 STOP·정상 종료를 유지한다. 기존 앞차 HOLD/재개/최종 추종 거리 판정은 원문 그대로 계산하되 두 번째 출발 시험 성공으로 바꾸지 않는다.

관련 회귀·고정 소스/명령·설치본 확인 후 한 번만 주행한다. 실패 원인을 보존하고 같은 실패를 성공까지 반복하지 않는다. 임시 신호등이 두 번째 대기 위치에서 실제 카메라에 안 보이면 그 사실을 실패로 남기며 월드나 카메라를 몰래 옮기지 않는다.
