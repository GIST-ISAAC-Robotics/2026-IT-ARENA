# 저장 입력 비교 이후의 결정 기준

## 서로 다른 세 가지 결과

- **배열 경계 수정의 이관:** 기본 인자 `cycle=None`의 저장 출력 동일성과 명시 증거 ON의 합성 대조로 판단한다. 후방 마스크가 유지된 입력에서 변화가 없다면 새 공식 주행의 근거로 쓰지 않는다.
- **실제 복귀 후 출력 진단:** 기존 복귀가 발생하는 합성 시퀀스에서 원래 제어기가 내보내는 명령을 검사한다. 거절은 그 관측/기하 기준을 충족하지 못했다는 뜻이며, 실제 접촉이 일어났다는 뜻은 아니다.
- **가상의 기본 출력 진단:** 현재 기록 장부가 계속 복귀를 막은 저장 시각은 별도 `hypothetical_baseline_only`로 표시한다. 기본 G1을 다시 계산하거나 차량을 옮기지 않고 같은 입력에 대해 이미 계산된 기본 출력을 읽는다. 이를 폐루프 개선으로 쓰지 않는다.

## 뒤따를 구현 조건

1. 해제 이후 출력이 검사에 실패하면 단순히 기록 장부를 비우고 기본 G1에 넘기는 설계를 유지할 근거가 부족하다. 복귀 상태와 이번 명령 허용을 분리한다.
2. 명령 검사에 통과한 기존 측방 후보·현재 방향 유지 등 대안이 실제로 있는지는 별도로 확인한다. 거절 시 무조건 다른 조향을 발행하는 코드는 넣지 않는다.
3. 정지 목표 자체는 전달해야 한다. 진행 중 0목표의 제동 외곽이 확인되지 않았다는 진단과 STOP 거부를 혼동하지 않는다. 조향을 새로 바꾸기보다 기존 HOLD의 이전각 유지를 보존한다.
4. 실제 출력이 바뀌는 선택형 제어기를 만들면 내부 기본 제어기의 재개 카운터와 별개로 fresh 재개·명령 단절·세대 변경 경계를 검토한다. 자료가 끊겼다고 보호 필요성을 자동 해제하지 않는다.
5. 현재 후보의 관측/제동은 표본 기하·물체 이동 상계·기존 감속 가정에 의존한다. 후방 숨은 차량 부재, 최소 국소 단면, 실물 가림, 실차 제동/슬립에 대한 새 증거가 된 것은 아니다.

지금은 출력 변경 없는 검사를 먼저 수행한다. 운영 기본 활성화·기존 실패 판정 변경·마찰/간격 완화·새 센서 구매 결정은 하지 않는다.
