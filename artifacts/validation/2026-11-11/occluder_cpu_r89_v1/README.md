# 좁은 가림체 후보 열거의 CPU 비용 감소

2026-11-11. [r88 최신 완주 입력의 Jetson 계측](../jetson_completed_traffic_r88_v1/README.md)에서 주행 판단 중앙66.75ms·p95 166.28ms를 확인했다. 이후153판단의 함수 표본에서 `break_adjacent_occluders`는218호출·누적3.872초(자체1.072초)를 차지했다. 계측 오버헤드가 포함된 누적값이며 실제 단일 호출 지연으로 환산하지 않는다.

## 변경과 유지 조건

원본은 [`before.zip`](before.zip)과 [해시](before_manifest.json)에 보존했다. `local_path.py`에 `_adjacent_cluster_candidates`를 추가해 **원본 번호가 연속되지 않거나 기존 방사 깊이 조건을 이미 만족하지 못하는 묶음만** 배열로 먼저 제외한다. 원래 edge→묶음 길이→오른쪽/왼쪽 순서를 유지하고, 살아남은 후보는 기존 현 길이·깊이·폭·방사 길이 검사를 그대로 받는다. 제거 후 다시 계산하는12회 상한과 원 점유·보호·판정 상수는 변하지 않는다. 큰 임의 입력은 기존 열거로 돌아간다. 관측을 추가하거나 기둥을 없애는 변경이 아니다.

좌우·역순·잡음 벽/여러 가림체·미연속 원본 인덱스·경계 깊이·작은 입력·잘못된 입력의 원 함수 대조와 기존 관련 검사84개가 통과했다. 이후 경로·교통·잡음·계보를 포함한 관련 회귀309개가 통과했다(`build/r89_regression.log`). 최초 확장 회귀는 존재하지 않는 테스트 파일명을 지정해 수집 전 실패했으며 경로를 확인해 다시 실행했다.

[`candidate_bundle_manifest.json`](candidate_bundle_manifest.json)은 r88의 동결107파일에서 `local_path.py` 하나만 교체했다. trace와 단계 관찰기는 바꾸지 않았다. PC3,060판단 전체 동일성 이후 새 격리 Jetson 경로에서1회 비교한다. 기존r88의246개 플랫폼 진단 차이는 후보 개선으로 덮지 않으며 원본/후보끼리 직접 전체 출력을 비교한다.

이번 묶음은 계산 변경의 동등성과 비용을 확인한다. 새 Gazebo 완주나 실제 ROS/차량 마감을 주장하지 않는다.

## 결과와 다음 범위

[PC](pc_stages.json)는3,060회 전체 출력 동일, [Jetson](jetson_stages.json)은3,060명령 동일·원 기록 대비2,814회 전체 동일이다. 기존246개 플랫폼 진단 차이는 유지됐다. [Jetson 원/후 직접 비교](implementation_comparison.json)에서는3,060회 전체 출력이 모두 같았다. 두 gzip의 끝까지 길이와 sequence를 대조했고 기존1e-10 비교 허용치를 유지했다. 입력·107개 소스 불변을 확인했다. 회수 도구가 처음 `public/occluder_cpu_r89_v1`에 저장한 두 JSON은 이 폴더로 바이트 동일 복사했다.

| Jetson 단계 | r88 중앙 / p95 | r89 중앙 / p95 |
|---|---:|---:|
| 주행 판단 | 66.748 / 166.280ms | 55.996 / 160.894ms |
| 전체(오프라인 입력 복원 포함) | 75.795 / 175.262ms | 65.365 / 170.055ms |

중앙 비용은 줄었지만 긴 판단의 개선은 작고20ms 초과는 여전히3,060회다. 같은 입력의 각1회 측정이므로 모든 장면의 개선율이나 실제 ROS 마감을 보장하지 않는다. 출력 동등성에 근거해 계산 변경을 유지한다. CPU 미세 개선만 이어가지 않고, 다음에는 기록된 처리 비용으로 바쁜 틱을 건너뛰는 제한 재생을 해 상태 전환과 고정 `dt` 의존을 구분한다. 센서 궤적은 원 기록 그대로이므로 그 분석을 새 폐루프 주행으로 해석하지 않는다.
