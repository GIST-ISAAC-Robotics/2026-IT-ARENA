# Jetson 측정 비용을 이용한 배송 지연 준비

2026-11-11 준비 완료·주행 보류. r105는20.14m 정체로 실패했고 최초 제출 위상의50ms 차이를 확인했다. r107에서 그 대기를 먼저 분리하므로 본 지연 주행은 아직 시작하지 않는다. r106 실행 소스는r105기준으로 준비한 기록이며 후속소스로 수행할 때 별도버전·계보를 남긴다.

## 저장 시각 계산

[schedule.json](schedule.json)은 실제 `DecisionDelivery`와 양수 고정 출력의 모의 계산기만 사용한다. r103 Jetson의 사례 창 안598개 단계별 비용을 시간순으로 적용했다. 결과 전달·이전 명령의 참조시각 만료를 보는 계산이며, 센서/차량 주행·실차 지연 예측이 아니다. 단계 합에는 직렬화·스케줄러 등 모든 비용이 들어있지는 않다. 새 궤적의 판단 내용과 당시 비용도 같다고 보장하지 않는다.

- 20ms 배송 대조는 적용600개·폐기0·최대 적용 간격100ms·직전 명령이200ms를 넘는 노출0초였다.
- 측정 비용 시간열은 적용439개·폐기79개·최대 적용 공백0.96초, 직전 명령이200ms를 넘는 노출18.3초였다. 이는 **60초 동안 차량이18.3초 정지한다는 뜻이 아니다.** 속도·관성·독립 보호·센서 상태를 계산하지 않았다.
- 오래된 결과를 버릴 뿐 아니라 이전 명령의 참조시각을 보존하므로, 처리 시간이200ms 미만이어도 다음 결과 사이에서 명령 만료가 생길 수 있다. 수신 분리 성공과 연속 주행 가능성은 다른 조건이다.

## 시험 장치와 다음 단계

`delay_worker.py`는 실제 계산을 실행하는 worker의 결과를 **실제 완료와 시뮬 지연 종료가 모두 충족됐을 때** 내보내는 시험용 어댑터다. 원 출력·참조시각·실제 wall-clock 측정은 보존한다. 첫 제출을 기준으로 사례 비용의 상대 시간열을 사용하고, 이후 마지막 표본은 끝 구간에서 유지한다. STOP/RESET은 보류 결과를 버리고 기존 worker 세대를 바꾼다. 기본 실행에는 연결하지 않았다.

`delivery_profile.json`은 r103의598개 측정 단계 합계(47.116–284.563ms)와 원본 해시를 보존한다. 원 측정은 이전 궤적이며 새 궤적의 같은 위치/판단 비용을 뜻하지 않는다. `launch_prefix.py`/`node_entry.py`는 별도 평가 명령의 G1/G2 노드에만 지연을 주입한다. 센서·신호·독립 보호·구동기는 같은 원 명령을 사용한다. 프로파일은 제어 판단에 입력하지 않으며 배포 코드/기본 launch를 수정하지 않는다.

지연/취소/세대/실제 완료 이전 발행 방지·실제배송계약결합·단일노드선택 **12검사 통과**. 설치된ROS의`--launch-prefix-filter`가 executable name에 적용되는 것도help와소스로 확인했다. 단위 검사 첫 시도는 Windows 기본Python에 pytest가 없어 실행되지 않았으며 기존WSL 환경에서 확인했다. 새 주행·STOP·종료·소스 무결성은 아직 미검증이다.

시간 만료를 이유로 상태형 제어기 전체를 리셋하는 것에는 재획득 지연 위험이 있다. 그러나 늦은 판단의 추월/복귀 전이가 발행되지 않은 명령을 전제로 진행될 수 있어 상태 전체를 무조건 유지하는 것도 타당하지 않다. 먼저 실제 지연 대표에서 만료·리셋·독립 보호·정체의 관계를 구별하고 필요한 최소 변경을 고른다. 명령TTL 확대나 오래된 명령의 새 시각 반복 발행으로 시험을 통과시키지 않는다.

사용자의 한도 복구 안내 뒤 필요한 쟁점으로 요청했던17:53 Fable 5.2/high 자문은 실제 주간 호출 제한으로 시작 전에 거절됐다. 새 답변은 없으며 같은 거절을 반복 호출하지 않는다. 현재 시험 장치의 판단은 GPT가 수행했다. 사용량을 소진하기 위한 자문은 하지 않는다. [자문 기록](../../../../docs/reports/DRIVING_ADVISORY_2026_11_11.md)을 따른다.
