# r71 IMU 편향 조건의 코너 이력 갱신

## 근거와 변경

기존 [IMU 민감도 시험](../imu_observed_sensitivity_v1/README.md)은 관측된 평균을 미보정 편향으로 가정한 −0.015615217rad/s 조건에서35.05m로 끝났다. 실물 영점 교정값을 뜻하지 않는다. 31.12/31.22초에 현재 긴 벽4.05m와 직전 경로가 관측됐지만, 같은 x좌표를 가진 코너 출구 길이가 달라 직선 창 비교가 실패했다. 기존 공통 호길이 비교는 같은 허용오차에서 통과했다.

단독 `corridor_arc_agreement`와 `piecewise_wall_trial` 선택에서 **현재 충분한 길이·차체 근접 조건을 만족하는 직각 벽 경로**가 유효 이력과 이어지는지도 기존 `retained_boundary_agreement`로 확인한다. 옵션 OFF는 이전 x 비교다. 공통0.25m·각5점·80백분위 허용오차, 이력 TTL·운동 한도·실제 점유/제동·독립 보호층은 유지한다. 더 먼 길을 만들어내거나 IMU 바이어스를 몰래 제거하지 않는다. 다른 코너·짧은 경로·다른 모델은 거절한다.

## 확인 범위

- 관련160검사 통과. 최초156통과/4실패와 환경 수정 전 재시도4실패는 ROS 환경 로드 문제로 [기록](checks.json)했다. LF bash 파일로 rclpy/xacro 환경을 확인한 뒤 해당4검사가 통과했다. 최신 출처 계보 검사 포함.
- [저장 입력 비교](saved_compare.json): 기존판단 불일치0·변경15호출·0→양수10호출·양수→0 없음. 실제 호길이 갱신2호출이며, 최종후보0.71m/s다. 입력과 `local_follow.py` 해시 불변. 새 궤적의 완주 증명이 아니다.
- `run_once.py`는 원 민감도 시험과 같은 IMU 주기·잡음·편향/기존 균일500점 C1로 단독1회만 등록한다. r69 부분 공백 정책과 r72 native CPU 구현도 코드에 있으므로 엄격한 단일 변경 A/B라고 부르지 않는다. r72 native 빠른 경로는 이 균일 입력에서 사용하지 않는다. 속도·구동계8.970588235:1·물성·STOP/종료 기준은 유지하며81T는 대기다.

## 새 주행 결과

같은 편향 조건의 단독1회는 **46.68m·1랩·최고2.871m/s·중앙1.238m/s·접촉0**으로 완료했다. 중앙선 오차 RMSE0.0412m·p95 0.0959m다. 원35.05m 정체를 개선했지만 미보정 IMU 전반의 안전이나 실물 교정을 입증한 것은 아니다.

`motion_fault_relay`만 IMU/모터축 입력을 발행했고, 편향 주입7,815표본을 포함한 값/시각 검사109,425개에서 실패0이었다. 요청 IMU199.069Hz와 평가기의 시뮬 stamp 기준200Hz 집계는 실시간 수신 용량과 구분한다. 이번 C1은 기존 균일500점 입력이다.

STOP은1.516초 뒤 정착했으나 변위 **1.135m**가 남았다. 종료 뒤 조밀한 자세 창·독립 보호 연결·정상 종료를 통과했고14개 자식 프로세스를 회수했다. [등록 입력](registered.json)553개는 종료 후와 GPT 독립 재검사에서 모두 불변이었다([무결성](run_integrity.json)). 원시 결과는 [report](solo_run1/report.json)에 보존한다. 동일 조건을 성공 횟수 확보용으로 재실행하지 않는다.
