# 현재 재계산 뒤 남은 경계 재획득 정지

2026-11-11. r126은 명령 도착 시 재계산으로 진행이 늘었지만 한 랩은 미완료다. 먼저 저장 입력의32~44초 구간에서 경계 후보·운동 보정한 직전 경로·재획득 확인과 재개 확인을 구분한다. 기본 제어기나 임계값을 바꾸지 않고 원471판단과 일치하는지 함께 확인한다. 현재 후보가 존재한다는 사실만으로 확인 실패를 삭제하지 않는다.

반복 주행 전에 이번 진단으로 후보 형상 변화와 지연 때문에 기존 경로가 만료되는 영향을 분리한다. 명확한 원인이 없으면 확인 횟수나 TTL을 단순히 풀어 통과시키지 않는다. 상세 결과는 분석 후 추가한다.

## 확인된 원인

[진단](result.json)은 원471판단 모두 일치했고 관찰한62판단에서 현재 경계 후보55개가 적격이었다. 그럼에도 경계 미확정19회·재개 대기18회가 남았다. 원 시각/입력·구현 SHA를 보존했다.

예를 들어34.02초에는 새 긴 벽이 적격이었지만 이전 경로 원천은33.703초로317ms가 지나 주행 기억이 만료됐다. 기존 `recent_path`에는 이 경로를 **현재 호출이 HOLD로 끝날 때** 넣었다. 따라서 현재의 충분한 벽과 비교할 직전 승인 경로가 있는데도 그 호출에서는 활용하지 못하고, 다음 호출에서야 재개 확인을 시작하는 경우가 있었다.200ms 계산 간격에서 이런 과정이 반복됐다. 실제로 새 벽이 불충분한7후보와는 구분한다.

후속은 기존600ms/이동 한도의 **비주행용 형상 비교**를 만료 첫 호출에서도 하도록 순서를 고치는 것이다. 채택할 경로는 이번에 충분히 관측된 벽에서 다시 만들어야 하고, 기존300ms의 주행 기억·점유/제동·독립 보호는 유지한다. 오래된 경로 자체를 더 오래 주행에 사용하는 설계가 아니다.

최초 진단 위치 탐색은 중첩 `if eligible`까지 포함해 중단됐고, 다음 수집은 NumPy bool 직렬화 때문에 불완전 파일을 남겼다. 이를 원본 그대로 두고 최종 상세는 `details_v2.jsonl`, 로그는 `build/r129_diagnose_v3.log`에 저장했다. 그 사이의 WSL 재시작은 장치/시뮬 구동 없이 완료된 저장 재생만 있는 상태에서 수행했다.
