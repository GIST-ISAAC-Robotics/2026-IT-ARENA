# 시설·두 차량·C1 원천 입력의 추가 스트레스 없는 기준

2026-11-11, 실행 전 등록. 코드 변경 없이 현행r86에서 제한1회 실행한다. [실물 반복성 진단](../c1_repeatability_v1/README.md) 뒤, 원천 입력/주행 기능과 강한 잡음·지연 가정을 분리하기 위한 기준이다.

- 원r84의 같은60초 사례·상대2대·오목 주상대·신호/마커 지주·ID20/30 누락·81T·IMU·native 각도/점수 템플릿을 유지한다.
- **추가 `lidar_uniform30_delay50_jitter20.json`만 선택하지 않는다.** 이 시험의 거리는 기본 이상적 시뮬 반환이며,±30mm 잡음과50±20ms 주입 지연이 둘 다 없다. 원천 순차 취득과 실제 시뮬 처리 주기는 남는다. 실제 센서의 잡음/지연 재현이나 둘 중 하나의 인과 분리 시험은 아니다.
- 기존44.64m 진행·최장저속2.5초·간격8cm·접촉0·최대두바퀴도로밖·STOP·정상종료·소스 불변 판정을 유지한다. 새 기준에 맞춰 판정선을 바꾸지 않는다.
- r84의 스트레스 실패와r86의 저장 입력 정체를 해결한 것으로 처리하지 않는다. 같은 실패를 반복 실행하지 않는다.
- 실행 직전 전체 소스/설정과 형상·각본을 보존하고, 실행 후 native 취득·판단 로그·추가 주입 부재·원본 불변을 별도로 감사한다.

실행: [`run.py`](run.py), 판정: [`assess.py`](assess.py).

## 실행 결과

시설과 두 상대, 마커 ID20/30 누락을 유지한 60초 사례에서 **47.840 m 진행·한 랩·최장 저속 0.200초**를 확인했다. 최고 속도는1.5545 m/s였고 접촉·시설 겹침·바퀴 노면 이탈 표본은0이었다. 최소 상대 간격은 표본0.73855 m, 이동 외곽 비교0.73764 m였다. [사전 등록 기능 판정](two_actor_run1/assessment.json)과 [native 입력 결합 판정](two_actor_run1/combined_assessment.json)은 모두 통과했다.

원 [`run1/report.json`](two_actor_run1/run1/report.json)의 `passed=false`는 그대로 보존한다. 유일한 행동 실패는 `final_gap`이며, 종점 추종 간격과 이 시험에서 사전에 등록한 완주·지속 주행 기준은 별개다. 결과를 보고 통과 기준을 바꾸거나 원 판정을 덮어쓰지 않았다.

- 명시 STOP·정착·정상 종료·시험 프로세스 정리·소스/형상 불변을 확인했다. 등록된 기존203개 소스와 추가 snapshot을 대조했다.
- 원천 취득687 scan은504/508/512점으로 확인됐고 잘못된 입력/원천 템플릿 불일치0이다.
- 전체 판단3,060회 중 사례 구간2,989회가 사용하는598 scan은 취득 로그와 모두 대응한다. 사례 밖71판단 중 취득 로그와 대응하지 않는1건은 따로 남겼다. 사례 안의 첫 광선 시각 대비 판단 나이는 중앙0.158초·p95/최대0.198초다.
- 실제 경과798.64초에 시뮬레이션 약68.77초를 처리했다. 이 시뮬의 완주는 실시간 실행이나 Jetson 연산 성능의 증거가 아니다.

이번 결과는 **추가 거리 잡음과 운송 지연을 넣지 않은 기능 기준선**이다. 실물 C1 오차 전체, r84의 강한 잡음/지연 정체, 모든 상대 배치·지속 병렬 주행, 실제 차량은 검증하지 않았다. 같은 기준 주행을 반복하기보다 [이 완주 입력의 Jetson 단계별 비용](../jetson_completed_traffic_r88_v1/README.md)을 다음으로 확인한다.
