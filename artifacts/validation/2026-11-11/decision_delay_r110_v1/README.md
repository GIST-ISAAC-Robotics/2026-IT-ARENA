# 별도 판단 연결의 저장 비용 지연 대표

2026-11-11. **제한 1회 실행과 회수를 완료했으며 실패했다.** r109의 지연 없는 기준은42.67m·마지막 정체로 실패했고, 이번 지연 조건은8.65m·최장저속6.036초에 그쳤다. 기존 r106 준비/가상 일정과 r109 실패는 그대로 보존한다.

r109 실행 소스와 같은 시설·두 상대·native C1 구성에 r103 Jetson 단계별 비용598개의 시간열을 결과 전달 최소 지연으로 주입한다. 각 판단의 실제 완료와 주입 시뮬 시간이 모두 지난 후에만 결과를 회수한다. 원천/기준시각·기존300/200ms 만료·양수명령 적용 간격·STOP/세대 폐기는 유지한다. 실제 센서 취득과 독립 보호의 주기는 바꾸지 않는다. 원천·비용 자료 SHA는 실행 전 대조한다.

이전 궤적에서 잰 CPU 시간열이므로 새 궤적의 정확한 연산량이나 Jetson 전체ROS 지연을 재현한 것은 아니다. 새로운 정책 선택 없이 긴 계산이 있을 때 명령 폐기·벽 재획득·추월/복귀 상태·실제 정체가 어떻게 연결되는지 확인하는 대표 시험이다. 최대1회, 원 실패와 실제 STOP/정상종료는 보존한다. 시간 만료나 실제 주행 실패를 평가 기준 변경으로 통과시키지 않는다.

다음 판단은 (1) 지연이 실제 정체를 일으키는지, (2) 버린 결과 직후 전체 상태 reset이 추가 정체를 유발하는지, (3) 다음 결과를 즉시 낼 수 없어 만료된 경우인지로 분리한다. 먼저 불필요한 제출 대기가 있으면 제거할 근거를 찾고, 관측 상태/실제 미적용 제어 전이를 분리하는 큰 변경은 이 대표 결과를 본 뒤 검토한다. 기본 실행은 여전히 inline이다.

실행 전 r106에서 보존한 지연 장치12검사를 통과했다(`build/r110_regression_recovery.log`). Windows Python에는 pytest가 없었고 첫 WSL 호출도Python 시작 전 서비스 오류였으므로 원로그를 보존하고 허용된 배포판 재시작 후 기존ROS 환경에서 확인했다. `run_trial.sh`는 현재 설치본 해시를 확인한 뒤 새 주행1회만 시작한다. 종료 후 `postflight.sh`에서 원 기능/시간/STOP 판정과 전달 폐기·상태 reset·평가용 속도 표본의 관계를 각각 기록한다.

## 실제 결과

- [통합 판정](two_actor_run1/combined_assessment.json): 경기 구간482판단 중435개 적용 후보,57개 모두 `decision_source_expired`로 폐기됐다. 적용 후보의 첫 광선 기준 나이 중앙218ms·p95 298ms, 양수명령 간격 중앙100ms·p95 120ms·최대180ms였다. 전체492판단의 주입 지연 중앙69.35ms·p95 159.06ms·최대284.56ms다. 후보는 독립 보호층 통과나 실제 이동과 같지 않다.
- [시설/교통 판정](two_actor_run1/assessment.json): 주 상대의 접촉·간격 판정은 통과했지만, **추가 상대 `eval_second_lead`와63.345초부터 접촉**했다. 원 report의 `no_actor_contact=true`는 주 상대만의 결과다. 추가 상대의 최소 간격0m·접촉 이벤트 때문에 전체 비접촉은 실패다. 시설 겹침과 노면 이탈은0이었다.
- 입력·실행 소스·snapshot 불변, STOP/정상 종료·자식5개 exit0·잔류0을 확인했다. 정지 변위는0.00496m다. 첫 후처리에서 `postflight_processes.txt`가 아직 없는 순서 오류가 있었고 원 로그를 보존했다. 프로세스 확인 파일 생성 후 별도 `build/r110_assess_v2.log`로 후처리만 마쳤으며 주행은 반복하지 않았다.
- [배송/정체 분석](two_actor_run1/delivery_analysis.json): 경기 중57개 만료가 모두 제어기 전체 reset으로 이어졌다. 최초 만료 직후에는 `parallel_hold_baseline_unavailable`·`parallel_hold_release_wait`로0명령이 이어졌다. 독립 보호의 `stale_input`도218개 저속 표본에서 관측됐다. 상관관계이며 reset만으로 전체 실패를 설명했다는 뜻은 아니다.

다음은 [r113 저장 비교](../decision_rollback_r113_v1/replay.py)에서 낡은 명령 폐기는 유지하고 **계산 직전 상태로 되돌리는 방식**과 전체 reset의 차이를 본다. 모든 미적용 상태 전이를 그대로 유지하는 방식도 원인 분리용으로만 비교하며 채택하지 않는다. 정지 후 뒤차 접촉을 평가 누락으로 감추거나 보호 TTL을 늘리지 않는다.
