# 판단 완료 시점과 원천 관측 나이

2026-11-11. r98의610개 실제10Hz 저장 입력과 같은 Jetson 단계별 비용을 연결한 **사후 시각 분석**이다. 명령을 늦춰 차량을 움직인 시험이나 비동기 제어의 성공 판정이 아니다. [분석 집계](report.json)·[발행 시각 대조](scan_wait_report.json).

- 판단 시작 때 첫 광선은0.197초 전의 측정이었다. 단계 비용을 더하면 중앙0.279초·p95 0.379초·최대0.593초로,270개가 기존0.3초 관측 계약을 넘는다. `계산200ms 이내`만 적용하면 이 중249개를 놓친다. 단계 계측 합계라 통신/회수 비용은 추가로 발생한다.
- 원천 audit의 스캔 발행은 첫 광선 뒤0.101초였지만 실제 판단은 **발행 뒤0.096초**에 시작했다. 100ms 타이머와10Hz 스캔의 위상으로 약 한 주기 대기한 것이다. 센서 자체의 취득100ms와 불필요한 제출 대기를 구분한다.
- 각 스캔 발행 즉시 계산할 수 있다고 가정한 최선 비교에서는0.3초 초과가21개다. 그러나 진행1건·최신 스캔·50Hz 회수의 단순 일정 모형은515개 처리/95개 생략/관측나이 초과92개를 예상했다. 입력 끝부분의 남은 작업도 포함하며, 입력/계획 상태가 바뀐 실제 출력이나 실시간 처리율 예측으로 쓰지 않는다.

**판단:** 수신 분리와 스캔 도착에 맞춘 제출은 필요하다. 계산 상한200ms 하나를 새 허용 기준으로 삼지 않는다. 계산 중에도 최신 센서를 받아야 하며 결과의 원천시각과 적용시점, 실제 이전조향, STOP/세대 경계를 유지해야 한다. 우선 긴 계산의 주된 원인을 좁혀 개선하고, 선택형 연결에서는 기본 실행을 바꾸지 않은 채 이 계약을 확인한다. 타임아웃을 늘려 성공으로 만들지 않는다. 기존 동기 제어도 계산 중 경과한 시간을 발행 시점의 기하에 반영하지 않는다는 한계가 확인됐다.

`constant_speed_distance`는 판단 시작 속도가 유지된다고 가정한 이동량이며 실제 이동·충돌 여유가 아니다. 원시 입력·계측 해시는 유지했다.

**경기 창 분리:** 위610개에는60초 사례 창 이후12판단이 포함된다. [별도 집계](case_report.json)에서 실제 사례 창598개는180ms 초과21개·200ms 초과9개·관측나이0.3초 초과258개·최대계산318ms였다. 창 이후12개는 모두180ms를 넘었고 최대396ms다. 전체 최대값을 주행 중 최대값이나 랩당 감속 횟수로 그대로 설명하지 않는다. 사용자 STOP은67.807초이며 사례 종료67.401초와도 구별한다.
