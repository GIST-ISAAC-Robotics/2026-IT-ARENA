# 취득 유실과 완성 배열 수신의 진단 분리

2026-11-11. r114에서 누적 취득 공백2회 때문에 모든 후속 원천 행이 전체 무손실 판정에 실패했다. r116에서 별도 진단 사본으로 확인하던 완성배열 대응을 평가기에 명시적으로 추가한다. 기존 `verified`·`source_errors` 및 원시 실패 report는 변경하지 않는다.

추가 `completed_payload`에는 완성 배열의 수신 내용 대응, 완성 원천 중 수신되지 않은 수, 취득 공백 누계 유효성/무손실 여부를 따로 표시한다. 누계를 0으로 덮어 해석하거나 미수신을 곧바로DDS 유실로 부르지 않는다. 제어기/시뮬 센서/운영 관문은 변경하지 않는 평가 진단 수정이다. 관련 회귀와 r114 저장684개 대응을 검사하며 새 주행은 필요하지 않다.

## 결과

관련81검사를 통과했다. r114 완성 원천684개와 수신684개가 모두 대응하며 잘못된 배열·미수신 완성 배열은0개다. 취득 공백 누계는2회로, 기존 전체 `verified=false`는 그대로다. 이 결과는 완성 이후의 기록 대응이며 누락 없는 취득이나 모든 제어 콜백의 수신을 증명하지 않는다.

[저장 재감사](comparison.json)에 원 acquisition·수신기록·report의 SHA와 전후 불변을 남겼다. 원 실패 report를 덮어쓰거나 누계를 수정하지 않았다. 새 주행 없이 평가 진단 수정까지만 완료했다.
