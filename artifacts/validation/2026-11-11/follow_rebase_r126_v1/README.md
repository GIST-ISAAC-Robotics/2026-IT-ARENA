# 일반 FOLLOW 결과 도착 시 현재 명령 재계산

2026-11-11. r125의 원 경로 수명 오류를 바로잡은 뒤, 계속 옛 계획을 재발행하는 추종기보다 작은 후보를 만든다. **계산 결과가 도착했을 때 한 번만** 현재 좌표·점유·제동/차간거리·실제 직전 요청각으로 명령을 다시 생성한다. 아래 설계로 별도 launch prefix를 연결해 제한 주행1회를 수행했으며 기본 실행에는 채택하지 않았다.

범위는 양수 FOLLOW·SOLO·baseline 선택이다. GUARD, 평행 경로 선택, 우회/추월, 정지 결과는 기존 처리 대상이며 이 후보로 갱신하지 않는다. 계획 중 발행 요청각이 바뀌면 양수 명령으로 되살리지 않는다. `path_source_s`의 기존300ms 이내 수명·이동 한도와 원천/운동 세대를 유지한다. 원 경로와속도상한을 바꾸지 않고 현재/직전 조향의 실제 점유 검사와 최신 광선별 이동 여유를 적용한다.

명령 시각은 실제 현재 재계산 기준시각이다. 원 계획 기준시각과 경로 관측시각도 따로 보존한다. 명령 watchdog200ms는 그대로이며, 현재 센서300ms 제한과 STOP도 별개로 유지해야 한다. 현재 점유가 막히면 새0후보를 내고 과거 양수 결과로 되돌리지 않는다.

새 추종 초안에 일괄 추가했던 무거운 `motion_region` 검사를 이 후보에 또 복제하지 않는다. **기존 독립 보호층의 최신 부분 관측·장착 구조/소실 기억·점유·제동은 계속 필수**다. 따라서 이 함수의 양수 결과만으로 미관측 영역을 허용하거나 안전을 판정하지 않는다. 모드 범위를 넓히거나 이 결과만 `/drive/safe`에 직접 발행하지 않는다.

먼저 현재 장애물·원 경로 수명·세대·정지/지원하지 않는 모드를 단위 검사하고 저장 입력의 계산 비용/적용 후보를 확인한다. 그 후 명시적인 별도 실행 연결에서 기존 지연 대표를 한 번 대조한다. 실제 결과가 나오기 전까지 개선 성공이나 기본 채택으로 기록하지 않는다.

## 제한 주행 결과

관련33검사(실제 ROS 노드 STOP/RESET 포함)를 통과한 뒤 r114와 같은 지연 프로필·두 앞차·시설·원천 C1·차량 물성·속도 설정을 사용했다. 최초 검사에서는 overlay Python 경로 누락으로3개가 건너뛰어졌고, 경로 복원 뒤 건너뜀 없이33개를 확인했다. 주행 [등록](two_actor_run1/registered.json)과 [원시 판정](two_actor_run1/run1/report.json)을 보존했다.

|---|---:|---:|
| 60초 경기창의 진행 | 12.39m | 30.69m |
| 최장저속 구간 | 5.364초 | 2.024초 |

**완주는 실패했다.** 사전 시설 목표에서는44.64m 한 랩 조건만 미달했고, 기존 원 평가의 최종간격 실패도 보존한다. 현재 재계산 외에도 두 실행의 시작 위상/궤적이 달라 모든 차이를 이 수정 하나의 인과 효과로 단정하지 않는다. 같은 실패를 그대로 재실행하지 않는다.

- [별도 평가](two_actor_run1/combined_assessment.json): 완성686원천↔686수신, 취득 공백0, 판단 입력/기록·소스 무결성을 확인했다. 34,319노면 표본에서 도로 밖 바퀴0이다. 이는 시뮬 생성/수신 계약이며 실물 시간 승인이 아니다.
- STOP 안정·명시 MCU STOP·정상 종료·잔여 자기 시험 프로세스0을 확인했다. STOP 변위0.0563m는 이 종료 시점의 결과이며 고속 STOP의 기존 긴 변위를 해결한 증거가 아니다.
- [재계산 감사](two_actor_run1/rebase_audit.json): 원 판단471개와 새 현재 계산316개 모두 재생 일치. 양수315개·이동 한도 초과0후보1개다. 원 경로 시각/상한·세대·실제 직전 요청각을 보존했고 원 기록 SHA는 같았다. 현재 계산의 PC 중앙4.27ms·p95 5.37ms·최대22.22ms이며 Jetson/전체 ROS 비용은 별도다.
- [만료 분석](two_actor_run1/delivery_analysis.json): GUARD/평행 경로 등은 이 후보의 적용 밖이고 기존 시각을 유지한다. 정상 FOLLOW에서도 경계 미확정34판단·재개 확인29판단이0을 냈다. 명령 수명뿐 아니라 경로 재획득과 모드별 계산을 구분해 후속을 정한다.

최초 후처리는 `surface.json` 선행 생성 누락으로 실패했다. 원 로그 `build/r126_assess.log`를 보존하고 기존 노면 평가기로 생성한 뒤 `build/r126_assess_v2.log`에 재평가했다. 이 중 WSL `E_UNEXPECTED`가 재발해, 자기 주행/재생 종료를 확인한 상태에서 승인된 Ubuntu-24.04만 재시작했다. 새 주행을 반복하지 않았으며 원 시험 소스·원 report는 바꾸지 않았다.
