# IMU 이력 큐의 수신 보존 대조

2026-11-11 실행 전 등록. 현재 ROS sensor_data QoS의 기본5표본은200Hz에서 약25ms 분량이다. 현재 계산의 실측36ms와 간헐적180ms 지연보다 짧으므로, 콜백이 늦어지는 동안 수신된 각속도 이력이 DDS 큐에서 밀려나갈 수 있다. 단순2스레드 r132도58개 누락/계산비용 증가가 남아 운영 미채택했다.

r131과 같은 단일 executor·동결316계산·진단200Hz 입력에서 **구독 큐 깊이만64**로 비교한다. 약320ms 이력으로 해당 실측 지연을 포함하되, 표본 시각을 수신 시각으로 바꾸지 않고 신뢰성/발행 주기/제어TTL/독립 보호는 바꾸지 않는다. 큐를 늘려도 이미 오래된 표본의 제어 사용을 허가하지 않는다.

이 시험은 계산 마감 개선이 아니다. 무손실 수신·지연·타이머 간격·출력 동일성과 정상 종료를 분리하며, 소스와 구동 연결은 동결r128 진단 범위다. 실제 센서·차량 토픽·하드웨어 설정/전원은 변경하지 않는다.

## Jetson 결과

[구독 큐64 결과](r134_rebase_run2/report.json)는 **6,201/6,201개 수신·누락/중복0**, 실제196.44Hz·원천 시각 간격 최대5.54ms였다. 계산316개 전체 출력과 동결 소스가 같고 정상 종료했다. r131 큐5의818개 누락과 달리 이 조건의 각속도 표본은 보존됐다.

계산 중앙36.27ms·p95 38.09ms는 그대로이며, 수신 지연p95 34.91ms/최대193.68ms,50Hz 빈 타이머 간격p95 38.51ms/최대180.27ms다. 큐가 표본을 늦게라도 보존한 결과이며 **최신 제어가 제시간에 실행된다는 뜻은 아니다.** 실제 운동 이력의 원 취득 시각·세대 경계·오래된 입력 거부는 그대로 유지해야 한다.

첫 시도는 ROS QoS 객체의 C++ Duration을`deepcopy`할 수 없어 송신 전에 실패했다. 얕은 사본에서 깊이만 바꾸고 전역 원본 깊이5가 유지되는지 검사하도록 고쳤다. 업로드 도구는 기존 원격 파일 덮어쓰기를 거부해 초기 소스를 보존한`_v2` 파일로 새로 전송했다. 초기 빈 출력 폴더와 로그도 남겼다.

원격/로컬 회수 묶음 SHA256은 `5e516637fc5ce5105ffaab7ee3a9e70e8b136e1be052664ba905d937deb49455`로 같다.

## 공통 입력 반영

r133 종료·회수·재생 감사 뒤 `lidar_motion_ros.py`의 IMU 구독에만 독립 QoS 사본과 깊이64를 반영했다. 전역 sensor_data 깊이5와 다른 QoS 옵션은 유지한다. 지연된40개 표본의 원 시각·적분, 만료 일괄 입력 거부, 세대 경계 이전20개 거부를 포함한 관련 **112검사 통과** 및 WSL overlay 소스 일치를 확인했다. 새 live 주행은 아직 없다.

변경 전 파일은 `lidar_motion_ros.before.py`에 보존했다. 변경 후 SHA256은 `2230c6ab91261fba78240bbbe385a3f0360de4778fb6cd9a842c98cfc31c64a2`이며 이후 실행 등록은 `config/tests/imu_history_queue_r134_sha256.json`을 사용한다. 이 수정은 이력 누락을 줄이는 것으로, 제어 계산 마감·C1/IMU 실물 취득 시각 검증을 대신하지 않는다.
