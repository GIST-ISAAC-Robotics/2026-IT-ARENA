# r69 단일 정면 결측의 저속 운용 범위

## 이유와 범위

[r68](../partial_request_r68_v1/README.md)은42.63m에서 약5° 무반환이 차량 x축30° 경계를 넘는다는 이유로 다시 정지했다. 같은 관측에서 경로·먼 양쪽 반환은 계속 보였다. 기존 스캔1,853판단을 그대로 넣은 후보는 기준 불일치0, 원0→양수385회·원양수→0은0회였다. 첫 변화는37.6초의 `forward_gap_too_wide`, 마지막도0.2m/s 요청이었다. 저장 입력 대조는 새 궤적의 성공 증명이 아니다.

이는 시간 비교 버그 같은 단순 오류 수정과 달리 **불확실한 단일 관측 공백을 저속으로 통과하는 정책의 범위 변경**이다. 현재 선택형 `oblique_gap_trial` 안에서, 단일 연속 공백의 고정30° 경계와 정면1.5° 분류 대신 기존 이동 반경의 숨은 현50mm를 적용한다. 총6°·최대 측정/요청속도0.6m/s·양옆 유효반환1m 이상·시각/회전 변환·이전 근거리 장애물 기억은 유지하고, 출력 요청은0.2m/s로 제한한다. 실제속도를0.2로 잘라 검사하지 않는다. 1.5~3° 정면 공백도 같은 검사로 연결해 폭이 작을수록 오히려 거절되는 불연속을 피한다.

알려진 실제 장애물·독립 보호층·STOP은 유지한다. 다중 공백·넓은 공백·지원 범위를 벗어난 입력은 허용하지 않는다. 원시 무반환은 그대로이며 거리/자유 공간을 생성하지 않는다. **가는 물체·저반사 물체를 놓칠 잔여 위험을 제거한 것은 아니다.** 완주 지속성을 위한 제한 운용 후보이며 실차 안전 보증이 아니다. 기본 strict/v4와 교통용 oblique OFF 경로는 기존 범위다.

## 회귀와 실행

초기223회귀 통과·1실패는 회전하여 정면으로 들어온 단일 공백을 무조건 거절하던 이전 기대였다. 새 정책에서는 같은 폭/속도 기준으로 평가하므로, 동일 조건의0.2m/s 상한·무반환 보존을 확인하고 회전 후 전방 관측 영역을 벗어나면 여전히 거절하는 반례를 추가했다. 원 기대/소스는 `before_r69.zip`과 초기 실패 로그에 보존했다. 나머지223검사는 그대로이며 수정한 검사와 새 출처 계보를 확인한 뒤 단독1회만 수행한다.

기어비8.970588235:1, native5000방향 source/504·508·512회전점·현재 IMU·속도/물성/접촉/노면/STOP/종료 기준을 유지했다. 81T는 후속 적용 대기다. 관련225검사와 출처 계보 확인 후 단독1회를 수행했다.

## 단독 주행 결과와 평가기 오류

`solo_run1/report.json`의 원 판정은 **passed=false**이며 그대로 보존한다. 실제 주행은 **44.64m 코스1랩·진행46.69m/종료 목표46.64m**로 경로 완료했다. 최고2.874m/s(10.35km/h), 중앙1.210m/s, 중심선RMSE0.0426m/p95 0.1008m, 주행/정지 중 접촉 표본0이다. STOP·0.5초 밀집 자세 정지 검사·MCU software_stop·정상 종료를 확인했다. 잔여 프로세스/강제 회수0, 입력551파일 불변이다.

실패 항목은 `sensor_only_inputs`와 `safety_sensor_only_inputs`다. 기록된 실제 제어기와 보호층 구독은 모두 `/scan/native`였지만 평가기는 고정 `/scan`을 요구했다. 경로·신호·취득·구동·STOP·종료의 별도 검사는 통과했다. 이 실행은 원천504/508/512점·시뮬10Hz·회전 중 취득 모델의 단독 대표이며, 실물 시각이나 다중 차량의 증명이 아니다.

[r70 평가기 수정과 저장 graph 재감사](../native_contract_r70_v1/README.md)는 선택한 native 토픽을 요구하고 기존 `/scan` 동시 구독·지도/정답 등 추가 입력은 계속 거절한다. 저장 graph의 두 입력 계약은 수정된 검사에서 통과했다. 원 보고서를 성공으로 덮어쓰거나 같은 주행을 판정만 바꾸려고 재실행하지 않았다.
