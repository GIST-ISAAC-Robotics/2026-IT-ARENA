# 최신 native 교통 판단의 Jetson CPU 비용

106파일 묶음/해시·의존성 폐포 확인과 전송 뒤, 격리 폴더에서 저장 입력을 재생했으나 **출력 동일성 관문에서 실패해 비용 측정은 수행하지 못했다**. 입력·필수 소스 불변을 확인했으며, 선택 보존용 `tests/test_follow_profile.py` 누락은 별도 표시한다. 이 누락을 출력 차이의 원인으로 단정하지 않는다. [원격 요약](remote_summary.json).

[첫 불일치 진단](jetson_first_mismatch.json)은 seq384–386(7.68–7.72초)에서 속도·조향은 같고 내부 경로 좌표부터 약2–3mm 차이가 났음을 확인했다. 첫3건만 조사한 결과로 전체 명령 동일성이나 실시간 성능의 증거가 아니다. PC 대조로 플랫폼 차이와 입력/재생 상태 누락을 먼저 구별하며 비교 허용 오차를 키워 통과시키지 않는다.

이전 r72의45.52ms 중앙 비용은 고정r67 단독 정책에 CPU 개선3파일만 바꾼 비교였다. 이번에는 r79 시설·두 상대·native 입력의 저장 실패 궤적을 최신 모듈로 재생한다. 후보 r80은 미도입이며 r81 codec 구분은 저장 입력을 복구하지 않으므로 원 기록의 null/NaN이 유지된다. baseline 출력 일치부터 검사하고 그 뒤 warmup0·측정1회로 CPU 비용을 확인한다. 서로 다른 궤적의 비용을 직접적인 개선율로 계산하지 않는다.
