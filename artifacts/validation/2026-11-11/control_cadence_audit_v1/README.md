# 같은 C1 스캔 안의 명령 변화와 처리 주기

2026-11-11. GPT가 [r84 저장 판단](../guard_masked_speed_r84_v1/README.md)을 읽어 최신 Jetson 처리 비용 문제의 변경 범위를 정리했다. **새 제어기·ROS 주행·주기 변경은 하지 않았다.** Fable 자문 호출은 한도로 거절되어 아래는 GPT의 코드 검토와 저장값 집계다.

## 확인한 사실

[`audit.py`](audit.py)·[집계](r84.json)는3,037판단과 원시 해시 불변을 확인했다. 서로 이웃한 판단3,036쌍 중 같은 스캔2,428쌍, 새 스캔608쌍이다. 같은 스캔인데도 명령이 달라진 쌍은2,031개(속도894·조향2,028), 양수 속도→0은4개다. 기록된 `dt_s`는0.02초였고 판단 기준 시각도20ms 간격이었다. 이는 시뮬 시각이며 실제PC/Jetson의50Hz 달성 증거가 아니다.

따라서 현재 속도·조향 결과를 새 스캔이 올 때까지 단순 재발행하면 기존 제어와 같지 않다. 같은 스캔에서도 실제 엔코더/IMU·현재시각·이전조향이 달라지며, 경로 이송·조향 변화율·제동 지평·측방 접근·오래된 관측의 판단이 바뀐다. 예를 들어20.10→20.12초에는 같은19.903초 스캔으로0.65→0m/s 명령이 바뀌었다. 그 정지가 모두 적절했다는 평가는 별도이며, 이 집계는 캐시가 동등하지 않다는 근거다.

## 코드 경계와 후보

- `local_follow._baseline_command`의 벽 적합은 이미 `fresh`일 때만 수행한다. 별도로 새10Hz 타이머를 추가하는 것만으로 모든 비용이 사라지지 않는다.
- `wall_follow.control`은 `motion.project`를 수행한 뒤 `local_pursuit.command`로 넘긴다. 현재G1/G2 경로에서는 후자가 다시 `motion_scene`을 생성하고 전달된 점 배열을 쓰지 않는다. 부분 관측 정책의 `TimedPolicy.evaluate`도 점 순서/좌표 계약 검사를 위해 다시 투영한다. 이 중복은 변경 가능한 후보이나 기준시각·좌표·unknown/구조 마스크·유효점 수·진단 기록을 보존해야 한다.
- 원천 각도/취득 번호·구조 sector 소속과 같은 불변 입력은 같은 세대/스캔 안에서 재사용 후보가 된다. 현재시각 좌표·광선 원점·미관측 경계·`per_ray_padding`·옛 경로/anchor의 위치는 그렇지 않다. 원천시각을 갱신하거나 이전 결과를 최신 관측으로 포장하지 않는다.
- 별도 프로세스에 무거운 계획을 두는 것만으로91ms가20ms가 되지는 않는다. 입력 최신값 교체/쌓임 방지와 더불어 빠른 루프가 받을 경로·원천/기준시각·유효범위·속도상한·상태 갱신의 계약이 필요하다. 먼저 운영에 연결하지 않은 저장 입력에서 분리를 비교해야 한다.

## 다음에 성능 작업으로 돌아갈 때

현재 시설 대표를 먼저 회수한다. 이후 최신 후보에서 **입력 복원·점 투영·장면 생성·상태/경로 판단의 비용을 구분**하는 계측 한 묶음부터 수행한다. 이미 동결r82→r85에서 확인한 전체 중앙91ms를 최신r86 전체ROS 값으로 부르지 않는다. 가장 작은 판정불변 중복 제거가 유의미하면 먼저 적용하고, 그것만으로 충분하지 않을 때 느린 계획/빠른 추종 분리를 선택형으로 설계한다. 같은 출력 재발행, 보호층 우회,TTL 상향,GC 일괄 중지나GPU 사용만으로 해결된다고 가정하지 않는다.

기본 주기/알고리즘/독립 보호에는 이번 기록으로 변경을 가하지 않았다. [이전 Jetson 계측·한계](../traffic_cpu_r85_v1/README.md)를 유지한다.
