# 긴 판단 구간의 제한 프로파일

2026-11-11 실행 전 등록. 수신 분리는 r100에서 효과를 확인했다. 이어 r98에서180ms를 넘긴 판단만 별도 계측한다. 상태 유지를 위해610판단을1회 모두 재생하지만 cProfile은 사전 지정한 긴 구간에만 켠다. 동결 r98 소스·입력, 기존 전체 출력 비교를 유지한다.

이 계측 시간은 프로파일러 비용을 포함하므로 Jetson 실제 마감 수치로 사용하지 않는다. 가장 큰 중복/불필요 계산 한 곳이 확인되면 동등 결과를 유지하는 범위에서 수정하고, 대표 대조 뒤 다음 연결 단계로 진행한다. 여러 작은 연산을 끝없이 다듬거나 기하/보호 판정을 생략하지 않는다.

## 결과

[profile.json](profile.json)의610판단 전체 출력과 입력/소스 불변을 확인했다. 기존 Jetson180ms 초과33판단만 cProfile로 계측했다. 정렬 자체0.384초 중 약0.365초가 `np.unique(axis=0)`의 structured 정렬이었다. 큰 질의 집합을 만드는 세 호출을 [r103](../query_set_r103_v1/README.md)의 같은 좌표·같은 순서 정렬로 비교했다. 최초 실행의 metadata/상대경로 오류와 WSL 오류 로그는 `build/r102_*`에 남겼다. 이 프로파일만으로 실제 Jetson 병목 전체가 해결됐다고 해석하지 않는다.
