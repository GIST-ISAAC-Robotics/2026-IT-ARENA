# 새 회전 완료에 맞춘 계산 시작 비교

2026-11-11. r110에서 계산 시작 당시 첫 광선 나이가118~198ms였다. 같은10Hz라도 이전 판단 완료 직후 묵은 스캔으로 다음 계산을 시작하면, 계산 시간이120ms여도300ms 원천 만료가 발생했다.

## 후보·합성 결과

선택형 시험 클래스는 **마지막 광선 취득 후25ms 안에서만** 새 판단을 시작한다. 50Hz 수신 콜백 한 주기와5ms 여유를 둔 시뮬 시험값이며 실물 취득시각 허가가 아니다. 이미 실행 중인 판단·대기 슬롯·스캔별1회·100ms 계산/양수명령 간격·300ms 원천/200ms 명령 만료·STOP/세대 초기화는 그대로다. 입력 timestamp를 덮어쓰거나 낡은 명령을 연장하지 않는다. 기본 inline에는 연결하지 않았다.

[schedule.json](schedule.json)의 이전 Jetson 시간열·10Hz입력·50Hz콜백·항상 양수인 가상 출력60초 비교:

| 항목 | 기존 | 새 회전 시작 후보 |
|---|---:|---:|
| 계산 제출 / 적용 / 만료 폐기 | 485 / 427 / 57 | 459 / 453 / 5 |
| 제출 시 원천 나이 p95 | 198ms | 118ms |
| 적용 시 원천 나이 p95 | 298ms | 278ms |
| 양수명령 간격 p95 | 380ms | 200ms |
| 명령 만료 누적 시간 | 19.62s | 18.62s |

**명령 공백은 여전히 크다.** 실제 제어기 상태·경로·차체·독립 보호가 없는 일정 계산이므로 위 개선을 실제 주행 성과로 해석하지 않는다. WSL 서비스 오류의 최초 시도는 보존했고 순수Python 계산과10경계검사는Windows에서 완료했다. 상태 복원 r113은효과0으로 미채택했다.

## 제한 주행 수용 조건

이 후보만 적용한 같은 시설·두 상대·nativeC1·r110 지연 시간열의1회를 준비했다. 원 소스와 원천/출력 TTL·물성·속도·접촉/노면·STOP/종료 판정을 유지하며, r110의8.65m 정체와 추가 상대 접촉이 개선되는지 확인한다. 실패하면 원인 변화 없이 반복하지 않는다. 결과 회수 전에는 주행 성공이나 기본 채택을 주장하지 않는다. WSL 실행 정상 확인 후 GPT-6 Luna가 실행/회수를 맡는다.

## 실제 1회 결과 — 미채택

[통합 판정](two_actor_run1/combined_assessment.json)은 실패다. 진행12.39m·최장저속5.364초로 미완주였고, 계산 만료는6건으로 줄었지만 지속 주행은 확보하지 못했다. 전체466판단 중460개 적용 후보·6개 원천 만료, 적용 시 첫 광선 나이 중앙210ms/p95 280ms, 양수명령 간격 중앙100ms/p95 200ms/최대260ms다. r110과 궤적이 달라졌으므로 만료57→6을 모든 조건의 개선율로 해석하지 않는다.

주·추가 상대 접촉/겹침과 노면이탈은0이었다. STOP 정착·정상종료·자식5개 exit0·잔류0·입력/소스/snapshot 불변을 확인했다. 정지 변위는0.00491m다. CRLF 실행 스크립트는LF 임시 사본으로 실행했으며 등록 원본은 보존했다. 최초 surface 출력 경로 거절과 올바른 상위 결과 경로의 후처리 로그도 보존했다. 주행은 반복하지 않았다.

원천 입력 감사는 `verified=false`다. 누적 `discarded_source_gaps`가 처음부터1이고42.82초의 새 완성 스캔에서2가 되어, 검사기가 모든 행을 거절했다. [별도 r116 분석](../delivery_lifetime_r116_v1/README.md)에서 완성된684배열/수신684배열의 각도·점수·시간 일치는 확인했으나 **취득 무손실 실패는 그대로 남는다.** 이를 정상 입력 시험으로 소급하지 않는다.

독립 보호의 저속338표본 중227개가 `stale_input`,111개가 `clear`였다. 원천 만료 폐기만 줄이는 것으로는 출력 공백을 해결하지 못했다. 다음은 명령 수명과 계산 시점의 계약을 분리한다. 기본 실행은 inline을 유지한다.
