# 현재 명령 계산 중 ROS 입력 수신

2026-11-11 실행 전 등록. r128의 현재 계산은 Jetson 중앙16ms였으나20ms 초과가3회였다. r100의 판단 프로세스 분리만으로 새로운 현재 계산의 수신 경합까지 해결됐다고 볼 수 없어, 동결r128 입력316개를100ms 간격으로 처리하면서 진단200Hz IMU와50Hz 빈 타이머의 수신/간격을 비교한다.

같은316틱의 무계산 기준과 snapshot·현재 장면·재계산·freeze를 포함한 조건을 한 번씩 실행한다. 복원은 준비 단계로 제외하고 출력 동등성 검사는 종료 뒤 수행한다. localhost DDS domain199의 별도 토픽만 쓰며 실제 장치·차량 명령·운영 QoS·전원 설정을 바꾸지 않는다. 소스는 이미 전달한r128 동결 묶음이고 새 진단 스크립트의 해시를 따로 남긴다.

**경계:** 전체 경로 계산·보호층·영상·실물 센서 부하를 포함하지 않는다. 수신 성공을 전체50Hz 마감 통과로 확대하지 않으며, 실패하면 누락과 타이머 지연을 분리해 다음 실행 구조의 근거로 남긴다. 기본 구현을 바꾸거나 같은 실패를 반복하지 않는다.

연속 CPU 전용r128의16ms와 ROS 주기 실행r131의36ms는 다른 실행 조건의 측정이다. 이 차이의 원인을 CPU 클럭·GC·ROS로 특정하지 않았다. 무계산 조건에도 긴 지연과 누락이 있으므로818개 전체를 재계산 하나의 탓으로 확정하지 않는다. 다만 현재 실행 형태가 수신 무손실이나50Hz 타이머를 만족하지 못한 사실은 확인됐다. 사전에 불러온316개 입력의 메모리는 실제 실행보다 크며, 메모리/GC 영향을 포함한 제한도 남는다.

**결정:** 현재 명령 후보를 운영 기본값에 넣지 않는다. 원시 IMU를 받는 실행 흐름과 현재 계산의 관계를 개선한 뒤 이 대표로 확인한다. 센서 큐/실행 분리를 바꾸더라도 원 시각과 세대·오래된 표본 거절은 유지하며, 단순 수신 성공을 판단 마감 성공으로 바꾸지 않는다.
