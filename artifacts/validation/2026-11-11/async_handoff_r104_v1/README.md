# 선택형 판단 프로세스의 제어기 연결

2026-11-11 구현·제한 주행 결과. r100에서 실제 ROS 수신 경합을 분리했고 r101은 원10Hz 타이머의 스캔 대기96ms를 확인했다. r103의 작은 정렬 개선 뒤 부모 수신/운영 콜백과 G1/G2 판단을 분리하는 후보를 연결했다.

## 범위와 적용 계약

- 기본은 기존 `inline`이다. `process_candidate`는 시뮬레이션·G1/G2·수신 부모50Hz에서만 명시 선택한다. 10Hz 원천 스캔별 최대1회·판단dt100ms, 진행1건만 두며 계산 중 대기 입력을 쌓지 않는다.
- 기존 신호·센서·운동·경기 허가를 부모가 확인한다. 결과 적용 직전에 스캔 원천나이300ms, 판단 참조나이200ms, 운동/센서 세대·선호 벽·실제 직전 발행 요청각을 대조한다. **이 수치가 추가 계산 지연의 기하학적 안전 보장이라는 뜻은 아니다.** 기존 시간 예산의 상한을 늘리지 않는 조건이다.
- 양수 결과는 실제 적용100ms 이내 재적용하지 않는다. 가속·조향 제한에는 직전 발행 뒤 실제 경과시간과100ms 중 작은 값을 사용한다. 0결과/STOP·센서 고장을 기다리게 하지 않는다.
- 대기/폐기에는 같은 양수 명령을 다시 발행하지 않는다. 채택 결과 `/drive`의 header는 판단 원 참조시각을 보존하고 `/drive`→독립 보호→`/drive/safe`를 유지한다. 실제 STOP/RESET/입력 경계는 worker 세대를 폐기한다.
- 결과의 전체 판단 기록과 실제 적용/폐기·계산 시각을 별도로 남긴다. 폐기한 결과도 이후 reset과 함께 저장 재생한다. 좌표·동적 상대가 계산 중 움직이는 영향은 후속 실제 연결 시험의 관찰 대상이다.

변경 전5파일은 [before.zip](before.zip)에 보존했다. 단위/ROS 발행 분기·옵션OFF·launch 관련59검사가 통과했다(`build/r104_tests_v1.log`). 기존 r91/r87 시설·두 상대 장면을 동일 속도/물성/센서/판정으로 제한1회 실행했다. 기본 활성화·새 속도·보호 완화는 포함하지 않는다.

원천 무공백 실패는 `discarded_source_gaps=1`이 첫 완성 스캔부터 끝까지 유지된 결과다. 누적 진단값이며 682개 모두 각각 깨졌다는 뜻은 아니다. 첫 출력 이전의 회전 폐기1회가 없었다고 바꾸지 않으며, 원 보고서의 `native_input_verified=false`를 보존한다. 중간 새 누락과 반환된 광선 자체의 유효성은 후속 분석에서 분리한다.

50.06초까지는 현재 반대편 벽 경로를 갱신했으나 이후 갱신을 못 하고50.26초부터 `follow_boundary_unconfirmed`가 지속됐다. 이 실행에서는 시간 만료 폐기나 계산 프로세스 고장이 없었다. [r105 저장 입력 조사](../async_corner_r105_v1/)로 경계 전환을 먼저 조사하며 지연 주입은 아직 진행하지 않는다.

사후 WSL 명령은 `E_UNEXPECTED`로 프로세스 조회 전에 실패했다. 승인된 Ubuntu 배포판 재시작 후에는 해당 시험의 잔류 프로세스가 없었으나, 이를 재시작 전 독립 종료 확인으로 주장하지 않는다. [복구 기록](two_actor_run1/postflight_recovery.json)에 원 실패와 조회 시점을 보존했다.

## 이 대표 다음의 판단

연결 자체가 실패하면 해당 원인부터 수정한다. 정상 연결과 대표 주행이 확인되면, 다음에는 **r103의 사례 창 안 실제 계산 비용을 이용한 가상 시간 배송 지연**을 한 번 대조한다. 계산량을 동일하게 예측하는 시험이 아니라, 이미 관측한 지연 분포가 명령 공백·보호 감속·코너 진행에 주는 영향을 확인하는 시험이다. 사례 종료 뒤 비용 표본을 랩 중 지연으로 섞지 않으며, 제출된 입력의 참조시각 이후 `max(PC 실제 완료, 등록한 지연 완료)`까지 결과를 반환하지 않는다. 그동안 새 판단을 병렬 실행하거나 큐에 쌓지 않는다.

명령 시각·STOP/RESET 폐기·기본 비활성·독립 보호는 그대로다. 미세 CPU 최적화를 추가로 찾아보기보다 실제 불필요 정체가 생기는지 먼저 판단한다. 이 지연 대표까지 확보되면 남은 코너 병렬·C1 스트레스/실물 입력으로 돌아간다. 현 단계는 지연 주입을 아직 구현/실행한 결과가 아니다.
