# 좁은 가림체와 잡음 벽 사슬의 분리 후보

2026-11-11. r81 자문을 근거로 GPT가 구현·검토하며 GPT-6 Luna가 저장 재생/주행 실행을 담당한다. 저장 비교·관련251회귀 뒤 기존 선택형 기능에 연결한 동일 조건 주행1회는 **20.28m·최장 저속27.89초로 실패**했다. 기본 OFF를 유지한다.

## 바꾸는 부분과 유지하는 부분

기존 `narrow_occluder_bridge` 선택형 기능은 벽보다 가까운 좁은 물체를 벽 적합에서만 제외한다. 양쪽이 모두 단절돼야 하고 두 이웃 벽점의 짧은 현 방향으로 깊이를 재기 때문에, ±3cm 잡음에서 지주가 벽에 붙거나 깊이가 작아 보였다. [자문 원문](advisory/review.md)의47스캔 비교와 [이전 r81 원시 근거](../native_nonreturn_r81_v1/PLAN.md)를 구분해 보존한다.

후보는 단절에 닿은1–6점 묶음의 양쪽 실제 반환을 확인하고, 방사 거리 차이>.06m·시선 수직 폭≤.04m·방사 길이≤.10m 및 기존 두 이웃점 간격 한도를 사용한다. 호출자가 광선 연속성 등으로 이미 연결한 경계를 다시 끊지 않는다. 앞서 제거한 다른 묶음과 합쳐 넓은 물체를 단계적으로 제거하지 않는다. 원시 점군을 수정하지 않으며, 제외점도 점유/보호에 남는다. 이것은 물체 종류 판별이나 가려진 공간의 자유 보장이 아니다.

먼저 [probe.py](probe.py)에서 지역 경로의 기존 좁은 가림체 함수만 일시 교체해 r82의 같은 저장 입력을 비교했다. 당시 소스는 [saved_probe_source.zip](saved_probe_source.zip)에 저장된 해시와 일치하도록 보존했으므로 현재 연결된 소스로 baseline을 다시 재생하지 않는다. 이후 `local_path`의 선택형 분기만 `break_adjacent_occluders`를 호출하도록 연결했다. G2의 별도 밀집 광선 직선벽 판정은 유지한다. 공식 원본·점유·TTL·확인 횟수·보호층·물성·81T 구동계는 바꾸지 않는다. 열린 고리 비교 뒤의 센서는 바뀐 제어에 반응하지 않으므로 완주 결과로 해석하지 않는다.

## 검사와 다음 기준

좌우/순서 반전, 한쪽만 붙은 지주, 넓은 차체, 벽 잡음, 벽 끝/긴 그림자, 두 개의 분리된 물체 및 호출자 연결 상태12검사를 통과했다. 첫 WSL 묶음은37통과·2환경 실패(`arena_description` 미검색)로 저장 재생 전에 멈췄다. 기존 install 환경을 불러오도록 wrapper만 고쳤고 원 로그는 `build/r83_probe.log`로 보존한다.

[저장 비교](saved_comparison.json)는 기준선3,038/3,038전체 출력 일치·원 입력 불변을 확인했다. 후보는 명령595건 변경,0→양수537회·양수→0회11회다. [부작용 분류](saved_command_audit.json)에서 감속21회·최대 명령 감소.472m/s, 조향 차이최대.0852rad미만이다. 새0명령11회는40.46초 이후의 기준 경로 비직선/미확정에 의한 측방 대기였고, 초반10회 감속은 일반 주행에서 측방 추종으로 바뀐 경우다. 속도 명령이 높아진 것만으로 안전이나 실제 속도 향상을 판정하지 않는다.

자문자의47스캔을 GPT가 별도로 [대조](advice_static_crosscheck.json)한 결과도 기준선15·자문44·GPT후보44회 경계 성립이었다. 같은 원r81 경로 함수에 가림체 분리만 교체한 점군 검사다. Windows 보조 NumPy2.5에서2차원 `np.cross`를 거부해 원 평가가 시작되지 않았으며, 실제 실행 환경인 WSL NumPy1.26에서 대조했다. 운영 라이브러리나 원본 함수는 바꾸지 않았다.

선택형 연결 후 관련251검사가 통과했고 [동일 조건 실행](run.py)을 마쳤다. 속도·노이즈·지연·상대 각본·판정은 r82와 같다. [종합 평가](two_actor_run1/combined_assessment.json)의 완주·정체·최종간격 실패는 유지한다. 접촉/외형 겹침·노면 이탈0, STOP·14개 프로세스 정상 종료,682개 native 송수신과 원시 입력/소스 불변을 확인했다.

[연속성 분석](two_actor_run1/continuity.json)의 최장 저속은39.435–67.325초다. 이 창1,401판단 중1,400회가0명령이고,1,377회는 경로가 곡선이라 평행 직선 후보를 만들지 못했다. 전체 주행의 `follow_boundary_unconfirmed`에 따른 평행 기준선 부재는37회로, r82의1,588회보다 줄었으나 서로 다른 폐루프 입력이므로 순수 함수 개선율은 아니다. 대신1,449회가 기존 GUARD 곡선 후보의 왼쪽 가림 이동 초과로 거부됐다. 대표 꼬리 확장은약10.65mm로 기존10mm를 넘었으며 기본.35m/s 후보가 정지했다. 경로 복구와 실제 전진은 별개이며, 지주 분리만으로 완주가 해결되지는 않았다.

다음은 RELEASED 상태에서 이미 사용하는 감속 재검사를 GUARD의 같은 경로에도 적용할 수 있는지 저장 입력에서 비교한다. 차체 측정속도·현재/직전 조향·원시 점유를 유지하고 기존10mm 기준 자체는 바꾸지 않는다. 단순히 목표만 낮췄다는 이유로 실제 고속의 짧은 제동을 가정하지 않으며 측방 접근 검사도 다시 수행한다.
