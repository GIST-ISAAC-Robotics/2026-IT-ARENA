# GUARD 곡선 후보의 후방 가림 감속 재검사

2026-11-11. GPT가 설계·구현·분석하고 GPT-6 Luna가 실행·회수를 담당한다. r83의 지주 분리 뒤 경로가 성립해도 기존.35m/s 곡선 후보의 후방 가림 이동이10mm를 넘으면서 정체했다. [r83 실제 실패](../wall_occluder_r83_v1/README.md)와 원 소스를 보존한다.

## 근거와 변경 범위

[저장 기하5장면](geometry_probe.json)에서 측정속도0일 때 목표.35/.25m/s는 거부됐으나.15m/s는 같은 영역 검사를 통과했다. 측정속도.8m/s 대조는 목표 셋 모두 거부됐다. 센서 입력이 그대로인 기하 비교이며 실제 진행·측방 접근 검사 통과를 뜻하지 않는다.

기존 `traffic_recovery_trial`·`guard_curve_trial` 선택형 범위에서 GUARD의 완전 관측 경로가 후방 가림 크기 때문에 막힐 때만 기존 RELEASED에 사용하던.25/.15m/s 후보를 비교한다. 각 후보에서 측정속도·현재/직전 조향·누적 측방 접근·점유·미관측·가림 검사를 모두 다시 실행한다. 현재 측정속도가 원 목표 이상이면 목표 축소로 영역이 줄지 않으므로 재계산하지 않는다. 처음부터 진행 가능한 출력이나 미관측/전면 가림·기존 G1 정지·접근 거부는 이 후보로 바꾸지 않는다.

후방 허용폭10mm·TTL·통과/측방 위협 이력·독립 보호·STOP·물성·81T 환산은 유지한다. 기본 활성화나 실차 인증이 아니다. [수정 전 소스](before_r84.zip)·[해시](before_manifest.json)를 보존하고, 연결 회귀·고정 입력 대조 후 같은 시설/native 교통1회로 실제 손익을 확인한다. 실패 원인 변화 없이 반복하지 않는다.

## 저장 입력 비교

관련98회귀 통과 뒤 [전체 재생](saved_comparison.json)에서 기존 방식3,037/3,037판단이 모두 같았다. 같은 입력의 후보는 명령1,057건을0→양수로 바꿨으며 양수→0은0회다. 재검사1,057회 적용·392회 거부였고, 추가 후보 중 측방 접근 거부362건도 남았다(한 판단에서 두 후보를 검사할 수 있으므로 판단 수와 구분한다). 초기 변경 시각은32.98초다. 단순 영역 통과만으로 출력을 허용하지 않고 기존 GUARD 전체 검사를 다시 거쳤다.

원 입력·실행 소스 해시 불변이다. 이후 입력이 바뀌지 않는 열린 고리 비교이므로 실제 이동이나 완주를 입증하지 않는다. 재검사 때 최대 두 번의 후보 계산이 늘어나는 비용 한계도 있으며, 기존 명령이 통과하거나 실제 측정속도가 원 목표 이상이면 재검사를 실행하지 않는다. 이 묶음에서 CPU 실시간 마감을 통과했다고 하지 않는다.

연결·계보 포함277검사를 통과한 뒤 동일 시설·두 상대·C1 원천/거리 잡음·지연 조건의 실제 주행1회를 수행했다. 원r83와 같은60초 창·완주/정체/접촉/노면/STOP 기준을 유지했다.

## 실제 결과와 해석

[실제 결과](two_actor_run1/combined_assessment.json)는 **41.94m·최장저속6.762초**로 완주/정체 기준에 실패했다. 최고1.557m/s, 접촉·시설 겹침0,34,159노면 표본 이탈0, STOP 정착·14/14프로세스 정상 종료를 확인했다. native682/682스캔과204기본/995추가 소스·snapshot 불변을 확인했다. 원 report의 최종 간격 실패도 보존한다.

이번 주행은 이전20m 정체 위치를 지나갔지만 [판단 감사](decision_audit.json)의3,037판단에서 **새 GUARD 감속 재검사 발동은0회**였다. 진행 거리 증가를 r84의 인과 효과로 주장하지 않는다. 실제 입력·물리 경로가 달라진 폐루프 시험이며, 후보의 효과 근거는 아직 앞 절의 고정 입력 비교다. 성공할 때까지 같은 주행을 반복하지 않았다.

마지막 정체는60.36초 `previous_point_in_missing_sweep` 래치에서 시작했다. 현재 관측과 이전 반환의 표면 대응이 `few_surface_matches`로 거절됐고, 이후 계획·독립 보호 모두 `known_obstacle_latched`를 유지했다. r83의 GUARD 후방10mm 초과와 다른 원인이다. 일반 반환 손실과 구조 사각 기억의 중복, 실제 사라진 물체를 먼저 분리한 뒤 대응을 판단한다. 자동 시간 만료나 허용 오차 확대로 래치를 지우지 않는다.

[짧은 시간표](latch_timeline.json)는 이전7개 점·35광선쌍을 기억한 뒤 첫두새스캔의 공통 표면 적합이 실패하고, 재관측 anchor가기존.3초 유효창을 넘었음을 보인다. [센서 fixture](latch_sensor_fixture.json)와 [한 프레임 비교](surface_fit_probe.json)에서 가장 가까운 끝점 대신 실제 내부 투영 가능한 현을 고르면126/215→151/215점 대응으로 증가했지만, 잔차약18.5mm·미수렴으로 여전히 거절됐다. 해당 선택 변경만으로는 해결되지 않으므로 실행 코드에 넣지 않았다. 이 한 프레임 적합은 새 주행/진행 허가가 아니다.

[연속성 진단](two_actor_run1/continuity.json)은 저속10구간·명령 급감33회를 기록했다. 이는 계측 기준의 사건 수이며 모두 위험한 급정거 또는 독립적 제어 오류라고 분류한 것은 아니다. 다음 묶음은 최신 Jetson의 큰 계산 비용을 프로파일하고 이 정체의 저장 증거를 병행 분석한다.
