# r79 교통 시험기의 C1 원천 입력 연결

현재 **연결108검사·실제 native 교통1회·회수 완료**다. 주행은16.86m·최장 저속35.96초로 실패했다. 접촉/노면이탈0·STOP/정상종료·원 입력 불변을 확인했다. 같은 실패를 재주행하지 않았다.

단독 제어·독립 보호층은 이미 `/scan/native`의 점별 각도·시각과 가변 점 수를 사용한다. 교통 시험기는 `/scan`·500점·200μs를 고정 가정한다. 이를 선택형으로 연결해 시설·두 앞차·마커20/30 누락·C1 거리오차/지연과 **같이** 확인한다. 기본 균일 입력·주행 정책·속도·간격·STOP·물성은 그대로 둔다.

범위는 시험 CLI, 선택 토픽의 실제 구독 검사, 원천 배열 기록, 입력 사본/해시, 취득·수신·주입 대조다. native 시간은 `period_divided_by_count`라는 시뮬 근사이며 실물 시간 승인이 아니다. template의 실제 CW 비균일 배열과5000광선 source의 기존 각도 양자화 한도0.0361°를 대조하고, 무반환·배열 순서·시각을 바꾸지 않는다. 기존 균일 입력의 오차/지연 판정과 결과는 유지한다.

[저장 대조](saved_contract_audit.json)는 r77 취득426회 중 판단 기록에 사용된 고유344스캔의504/508/512점·각도·시각 대응을 확인했다. 전체 수신을 검증한 결과가 아니다. r76의682회 균일 입력에 대한 기존/사본 오차 평가 수치는 같았으며 설명 문구만 선택 토픽으로 일반화했다. 실제 거리오차/지연·수신 손실·STOP 여부는 새 실행에서 별도로 확인한다.

계획한 동일 시설/각본의 native 입력1회와 회수를 마쳤다. 아래 원 실패를 남기고 후속 원인을 분리한다. 이 결과를 독립 차량 경기·실차 검증으로 확대하지 않는다.

연결 전 평가기 두 파일은 [before_r79.zip](before_r79.zip)에 보존했다. 제어기/보호층 바이트는 불변이며 출처 계보205와 [108검사](checks.json)를 확인했다. 오류 전 주행이 시작되지 않은 사실과 환경 복구는 실행 로그에 남기며 제어기 주행 실패로 세지 않는다.

native504/508/512점·689취득↔689수신, 거리오차 최대0.0299999m·추가지연32–70ms를 확인했다. 시간은 시뮬 period/count 근사다. 구동11.911764706:1·IMU 요청199.068509Hz/gyro0.0011rad/s·accel0.0103m/s²이며 독립 raw IMU 수신률 감사는 없다.

원 `assess.py`는 형상 평가기의 균일 `sec` 가정에서 실패했다. 원 로그/평가기/부분 assessment를 보존하고 [posthoc_v2](posthoc_v2/combined_assessment.json)에 점별 각도·시각 후처리만 추가했다. 관련6검사와 native 입력/주입/형상 구조/원시 입력 불변은 통과했고 주행 실패는 그대로다. 오목면37반환/21스캔은30mm 잡음이25mm 형상 차이보다 크므로 형상 인식의 증명이 아닌 진단값이다.

경기 창2,988판단/599스캔의 취득 미대응0, 첫 광선 나이 중앙0.197초·p95/최대0.257초다. 경기 창 밖 마지막69.08초 판단의68.903초 입력1건은 취득 감사에 없으며 그때 측정 모터 속도0이다. 전체 호출의 미대응1은 보존하며 경기 창 일치를 전체 취득 일치로 확대하지 않는다.
