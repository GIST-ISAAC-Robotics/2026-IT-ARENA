# r72 native CPU 중복 생성 감소

[고정r67 Jetson 측정](../jetson_native_r67_v1/README.md)에서 장면/광선의 반복 생성과 형식 검사가 큰 비용을 차지했다. 첫 격리 후보는 검증된 불변 입력의 중복 광선 검사를 줄여1,733판단을 유지하며 전체중앙58.63→47.32ms로 개선했다. 두 번째 후보는 점군만 필요한 호출에서 장면 생성을 생략해49.92ms였다. 두 번째도 초기 실제 장면 생성은 유지하므로 이 투영 단계 비용이 그대로인 것이 정상이다.

이번 구현은 두 방식을 공통 `native_geometry.py`에 정리했다. `scene_motion`의 시간·frame·이력·세대 검사를 공통 함수에 보존하고, 점군 전용 호출은 반환 좌표/인덱스만 생성한다. 실제 장면은 unknown·마스크·점별 시각·방향·출처를 전부 유지한다. 공개 `SensorRay` 생성자의 검증은 유지하고 불변 `MeasurementScan`을 받는 내부 경로에서만 중복 검사를 생략한다. 유한 입력으로 발생할 수 있는 출력 overflow도 검사한다. 균일 LaserScan 경로는 변경하지 않았다.

CW/CCW·가변 점수·마스크·빈 관측·비정상 변환/overflow·부분관측·기록/계측의185회귀와 출처 계보1검사를 통과했다. Jetson 비교는 **고정r67 정책/trace에서 이 CPU 구현3파일만 바꾼106파일 묶음**으로 수행했다([manifest](jetson_fixed_r67_cpu_bundle_manifest.json)). 최신 r71 주행 정책을 함께 비교한 것으로 쓰지 않는다.

## 실제 구현의 Jetson 결과

[판단1,733개 모두 일치](jetson_profile_summary.json), 입력·106파일 전후 해시 불변이다([무결성](jetson_bundle_integrity.json)). CPU 전체중앙45.52ms·p95 70.82ms·최대287.69ms로, 원58.63ms 대비 중앙 약22% 감소했다. 투영중앙5.95ms·판단37.53ms다. **20ms 간격과 전체ROS 실시간 성능은 여전히 미달/미검증**이며 `passed=true`는 출력 일치와 무결성이다. GPU는 사용하지 않았다.

최초 원격 실행은 tar 파일의 mtime이1970인 탓에 `source_snapshot.zip` 생성에서 `ZIP does not support timestamps before 1980`로 실패했다. 그 폴더·원 archive를 보존하고, 시험 폴더 내106파일의 mtime만 현재시각으로 맞춘 뒤 내용 SHA가 모두 동일함을 확인해 별도 output에서 계측했다. 운영/시스템 파일은 변경하지 않았다. 선택 보존 파일 `tests/test_follow_profile.py`가 최소 묶음에 없어 `source_snapshot_complete=false`지만 필수106파일은 검증됐다.

최신 r71 정책까지 포함한 r69 저장 입력 재생은1,677중5회 불일치였다. 첫 변화는21.42초 `current_corner_arc`가 현재 긴 왼쪽 벽을 유지하여 기존 짧은 오른쪽 대체 벽보다 속도를 높인 구간이다. 원 불일치 결과는 보존했다. [별도 재생 도구](replay_r69_without_r71.py)로 r71 이전 정책만 프로세스 안에서 복원하고 r72 CPU를 유지한 결과는 **1,677판단 모두 일치·입력/소스 불변**이다([결과](r69_cpu_only_replay.json)). 이 범위에서 차이는 CPU 계산이 아닌 r71의 경로 선택 변경으로 분리했다. 파일/운영 설정은 되돌리지 않았다.

## 남은 계산 비용

같은 고정 입력에서207호출만 함수 계측한 [후속 분석](hotspot_summary.json)은 표본 불일치0·입력/106파일 불변이다. 누적 비용은 제어 판단12.09초, 구조 그림자 정책6.15초, 경로 명령5.29초이며 서로 포함되는 시간이므로 합산하지 않는다. 자체 비용 상위는 원천 기하 생성1.33초, `swept_limit`1.14초, `numpy.asarray`0.93초다. 함수 계측 오버헤드가 있으므로 비계측ms 수치와 혼합하지 않는다.

반복 형식 검사 하나에만 몰리던 비용은 줄었고, 남은 비용은 경로/그림자 질의와 많은 작은 배열 계산에 분산된다. GPU 프레임워크를 설치하면 자동으로 해결되는 구조가 아니다. 다음 성능 단계에서는 실제 노드의 선행 투영·보호·영상 비용까지 구분한 뒤 중복 계산이나 계획/출력 주기를 검토한다. 현재50Hz 달성을 선언하거나 계측 실패를 이유로 보호 판정선을 낮추지 않는다. 이번 CPU 묶음은 수치/한계를 남기고 IMU 및 교통 대표 검증을 이어간다.
