# 전방 공백 폭과 별개 측방 공백의 범위 정합

2026-11-11. r107의42.63m 정지를 저장 입력으로 분리하고 범위 정합을 수정했다. 후속 실제1회는42.67m·마지막 정체로 **완주 실패**했다.

## 원인과 변경

[원 각도 감사](audit.json)는 원 r107 판단 607개를 그대로 재현했다. seq929의 전방 무반환은 취득 방향 28.15–28.87°, 현재 방향 27.27–27.98°의 **1.44°** 공백이다. 별개 측방 공백을 합쳐 2.88°로 계산하여 전방 1.5° 제한에 걸렸다. 다른 선택 시점도 같은 합산이 있었고, 마지막 스캔처럼 전방 자체가 2.16°인 경우도 따로 남는다.

v4 정책에서 전방 폭은 **취득 방향 또는 현재 방향 중 하나라도 전방에 닿는 연속 공백의 전체 폭 합계**로 계산한다. 경계에 걸친 하나의 공백을 둘로 잘라 축소하지 않는다. 전체 6° 제한, 실제 이웃 반환, 알려진 근거리 점 소실, 실제 측정속도·조향 외곽 검사는 유지한다. 기본 strict·이전 v2/v3 정책은 그대로다. 새 거리나 자유 공간을 만들지 않는다.

첫 연결은 관련 172검사를 통과했지만 [저장 비교](comparison.json)의 r107 607개·기존 성공 r91 610개에서 명령 변화가 없었다. [후속 경로 감사](gate_trace.json)에서 seq929/939의 부분 관측은 허용되어도 `same_path_gap`이 전체 폭을 다시 1.5°에 비교해 거절하는 것을 확인했다. 따라서 같은 시각·동일하거나 작은 이동 명령에 증거를 전달하는 검사도 원천 각도와 현재 광선으로 범위를 재확인하도록 맞췄다. 실제 질의에 필요한 공백은 기존 양옆 반환·원시 +inf·현재 점유 검사까지 통과해야 한다. 이전 전체 폭만 있는 증거의 허용 범위는 넓히지 않는다.

## 검증과 다음 단계

연결 후 관련 **254회귀·계보 1검사**를 통과했다. [두 파일 연결 비교](comparison_connected.json)는 r107 607판단의 baseline 불일치0·명령17회가 모두0→양수로 바뀌었고, 기존 성공 r91 610판단의 명령 변화는0이다. 이는 원 궤적의 저장 비교이며 실제 진행 증명이 아니다. 최초 새 테스트의7실패는 양성 fixture의 과거 반환이 모두8m여서3m 기억에 점이 없고 운동 진단이 생성되지 않은 구성 오류였다. 과거2m 반환을 준비하도록 고친 후 통과했으며 최초 실패 로그도 보존한다.

같은 시설·두 상대·native C1, 첫 제출 정렬/별도 판단의 제한 실제 주행1회를 진행한다. 속도·노면·물성·원 판정은r107과 같다. 성공할 때까지 같은 실패를 반복하지 않는다. r105의 별도 GUARD 0.15 m/s 후보는 이번 변경에 섞지 않는다. Jetson 계산 지연 주입도 별도 단계로 남긴다.

원 r107·r91 입력, [변경 전 두 파일](before.zip), 첫 무효과 비교를 보존했다. r91 기준 재생의 기존 진단 21차이와 이번 수정 전후 명령 차이를 구별한다. WSL `E_UNEXPECTED`로 Python 실행 전 실패한 호출은 주행/회귀 실패로 세지 않는다. 허용된 Ubuntu-24.04 재시작 후 실제로 완료한 로그를 별도 보존한다.

## 실제 제한1회 결과

[종합 평가](two_actor_run1/combined_assessment.json)에서42.67m·최고1.550m/s·출발 후 최장저속4.746초로 실패했다. 원 `no_permanent_stall`·최종간격·전체랩 실패는 보존한다. 접촉/노면이탈0, 실제STOP·정상종료,5개 종료코드0·잔류0을 확인했다. [등록 소스 무결성](two_actor_run1/extra_integrity.json)은변경0·snapshot 불변이며 원 run 입력도 불변이다. 사후 별도회귀 호출의WSL 서비스 오류는 종료/회수 확인 뒤 발생했다.

607개 결과를 모두 적용했고 폐기0, 원천 첫 점→판단118ms·적용138ms였다. 양수 출력 간격은100ms였다. 이는 느린 시뮬 시계의 연결 확인이며 실제Jetson 지연 성적은 아니다.

마지막에는 별개 측방 공백의 중복 합산과 다른 조건이 남았다. 예를 들어seq924/927/930은 각각 약2.088/2.052/2.124°의 **전방 공백 합계**로 거절됐고, 가장 넓은 개별 공백은약1.368/1.368/1.404°였다. 현재 정책의단일 공백 물리폭 예외는 여러 공백에 적용되지 않는다. 양옆 실제 반환의최소거리2.76–3.21m만으로 그 사이를 자유 공간으로 바꾸지는 않는다. 제어기와 독립 보호 모두 `forward_gap_too_wide`가 남았다.

이번 수정은 별개 측방 폭을 전방 예산에 잘못 합산하던 부분을 바로잡았지만 완주 해결은 아니다. 동일 주행 반복 대신 [r110](../decision_delay_r110_v1/README.md)의계산 지연 추가영향을 분리하며, 복수의좁은 공백은 기존 물리폭/속도/관측 조건과 비교한 후 후속 판단한다.

[마지막 공백 감사](final_gap_audit_wsl.json)는 기존WSL 환경의607판단을 전부 재현했다. Windows 별도분석환경의NumPy2.5.4는기존2D `np.cross`를거절해 `follow_input_stop`으로바뀌었으므로 그 [실패](final_gap_audit.json)와소스`final_gap_audit_windows.py`를보존하고 기하근거로사용하지 않았다. 시뮬/Jetson의의존성·코드를바꾸지 않았다. 뒤의 [r112](../cluster_forward_r112_v1/README.md)는전체경로재생이아닌보존센서의공백기하만계산한다.
