# 방금 만료된 경로와 현재 경계의 즉시 대조

2026-11-11. [r129](../rebase_boundary_r129_v1/README.md)에서 확인한 한 주기 늦은 기억 전달을 수정한다. `junction_continuity`가 켜져 있고 주행 경로의300ms 수명이 막 끝났을 때, 기존600ms/이동 한도 안의 승인 형상을 이번 현재 경계와 바로 비교한다. 이전에는 HOLD 뒤에야 이 비교용 기억을 넘겼다.

채택할 후보 자체에 현재의 긴 벽·앵커·형상 일치를 요구하고 원천 시각을 현재 스캔으로 기록한다. 만료 경로로 직접 주행하거나 TTL·확인 횟수·물성·점유·독립 보호를 바꾸지 않는다. 옵션 OFF, 오래된/불일치 기억, 장애물, 현재 입력 없음/만료/세대 변경, 과도한 이동을 회귀 검사한다.

새 주행 전에 직전 r126의471입력과 성공한10Hz 대표 입력에서 직전 method와 수정 method를 대조한다. 과거 실행 결과를 성공으로 소급하지 않으며, 저장 입력의 양수 명령 증가만으로 폐루프 완주를 주장하지 않는다. 결과 확인 전에는 새 시뮬을 시작하지 않는다.

## 주행 전 근거

관련125검사 통과. 최초 scripts/ROS overlay 경로 누락과 빈 장면을 잘못 구성한 새 검사1개는 로그를 보존하고 실행 환경/fixture를 바로잡았다. 최종 `run_checks.sh`는 ROS overlay 경로를 보존하며 건너뜀 없이125개를 실행했다.

[저장 대조](comparison.json)는 r126의471개에서 직전 method가 당시 기록과 모두 같았다. 수정 뒤55개의0명령이 현재 관측을 이용한 양수 명령으로 바뀌었고, 양수→0은0개다. 원천 수명 위반0개이며 적용된103회의 경로는 현재 스캔에서 생성했다. 성공 대표 r91의610개는 두 method끼리 전체출력/명령이 모두 같다. r91 원기록과의 기존21개 차이는 양쪽 모두 동일하게 남아 현재 수정의 성과로 계산하지 않는다.

이 근거로 r126과 같은 측정 지연·두 상대·시설·차량/속도 조건을 한 번 비교한다. 원천300ms·명령200ms·노면/간격/접촉·STOP/종료 기준을 그대로 등록한다. 현재 재계산 prefix는 계속 명시 시험용이고, 운영 기본 연결로 바꾸지 않는다.

## 폐루프 결과: 미완주

60초에 **25.68m·최장 저속4.246초**로 한 랩/주행 지속 기준에 실패했다. r126의30.69m·2.024초보다 나쁘므로 저장 입력의55개 개선을 실제 주행 개선으로 확대하지 않는다. 접촉·시설 겹침·바퀴 노면이탈0, 두 상대 간격·STOP·정상 종료·등록 소스 불변은 통과했다. 원 최종간격 실패도 보존한다. [등록 평가](two_actor_run1/assessment.json)·[전체 대조](two_actor_run1/combined_assessment.json).

[판단 재생](two_actor_run1/rebase_audit.json)은 원467개와 현재 재계산148개가 각각 당시 출력과 같고 계약 위반0이었다. 재계산148개는 모두 양수이며 나머지 평행/측방 모드는 기존 방식대로 원 기준시각을 유지했다. [연속성](two_actor_run1/run1/continuity.json)의13.495–17.741초 구간은 진행 명령23개 모두 양수(최소0.35m/s)였지만 보호층의`stale_input`24표본이 있었다. 이 구간은`parallel_hold_follow`여서 현재 재계산 대상에서 빠졌다. 경로 갱신 수정만으로 명령 수명 문제가 해결되지 않았으며, 다음은 이 선택 경로의 현재 재계산 가능 범위를 저장 입력에서 확인한다.

원천 만료 폐기5건, 원천 완성/수신 검증·판단 로그/소스 불변을 확인했다. 현재 명령 재계산과 경로 확인 수정은 서로 다른 기능이며, 이전 정상 경로를 무조건 최신 명령으로 재발행하는 방식은 사용하지 않는다. 같은 조건의 자동 반복은 하지 않았다.
