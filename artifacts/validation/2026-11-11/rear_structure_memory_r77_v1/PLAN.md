# r77 뒤쪽 구조 사각의 기억과 일반 소실 위협 분리

현재는 **연결253검사·고정 재생 및 실제 native 단독1랩 대표 완료**다. r76 시설+C1 실행·회수를 마친 뒤에만 런타임을 변경했다. 후보 사본은 `known_structure_candidate.py`, 변경 전 소스는 [before_r77.zip](before_r77.zip), 연결 계보는 `config/tests/rear_structure_memory_r77_sha256.json`이다. r75 실패를 보존하고 아래 후속 결과만 별도로 완료로 기록한다.

## 관측 근거

r75 첫 latch의 현재 native source78–86(센서각125.71°→120.10°)은 설정된 차체 지주 사각 `122.8285°±3.2189°`와 일치한다. 바로 옆77/87은 실제 유효 반환이다. 과거 위협6점은 현재 차체 좌표 x −31~−28cm·y 약53cm이며, 점군 정합은 이미1.5mm 잔차로 성공했다. 따라서 표면 이동 한도를 더 늘릴 문제가 아니다. [원 실패](../longitudinal_surface_r75_v1/README.md)·[좌표](../longitudinal_surface_r75_v1/latch_context_arrays.json).

기존 `structure_aware_v1`은 이 지주 뒤로 들어간 점을 삭제하지 않고 정지 물체 가정의 `structure_hidden`에 보존하며 이동 외곽의 속도를 제한한다. 동시에 일반 부분 관측/TimedPolicy가 이 뒤쪽 점을2m/s 움직일 수 있는 물체로 확장해, 별개인 전방 결측에 들어올 수 있다는 이유로 영구 latch를 만들었다. 아래 저장 재생에서 실제 hidden 기억 포함 여부를 확인했다.

[기존 소스 재현](memory_probe.json)1,330판단은 baseline 불일치0·입력불변이다. 여섯 점은 모두 설명된 구조 사각 안/차체 뒤끝 밖이고 기존49개 hidden 기억 중0.038–3.94mm 이내 대응점이 있었다. 따라서 새 기억을 만들 필요 없이 기존 기억 검사의 결과를 같은 호출에서 재사용하는 후보로 좁혔다. 최초 `python` 명령 없음은 런처 실패로 남겼고 `python3`로 실제 프로브1회를 마쳤다.

## 후보 설계와 수용 조건

- 기존 구조 정책에서만 적용한다. 현재 양옆이 유효한 **설명된 차체 고정 사각** 안이고, 차체 뒤끝과 기존 여유보다 뒤에 있는 과거 점만 대상으로 한다. 전방·일반 무반환·설명되지 않은 사각은 그대로다.
- 해당 점이 이미 `structure_hidden`에 보존되어 현재 이동 외곽 검사에 들어간 경우에만 일반 소실 위협의 중복 판정을 그 구조 기억 검사에 맡긴다. 새 자유 공간을 만들거나 기억을 TTL로 버리지 않는다. 미보존 점은 기존 latch를 유지한다.
- 구현 후보는 StructureAwareMixin._refine_threat에서 기존 super의 위협 행렬을 얻은 뒤, 필요한 경우 같은 호출의 `_structure`를 한 번 미리 평가하여 그 결과를 evaluate에서 재사용하는 방식이다. 현재 hidden 점과의 대응은 기존2cm 이내로 제한하고 뒤차/전방 장애물의 현재 반환·STOP·독립 보호는 그대로 유지한다. 새 point cloud나 가짜 위치를 넣지 않는다.
- `_structure`의 기존 정지 가정과 사각 안 움직이는 물체에 대한 한계를 명시한다. 이것을 움직이는 뒤차의 안전 증명으로 확대하지 않는다. 근접한 기억 점은 구조 검사에서 계속 감속/정지를 만들 수 있어야 한다.
- 저장 r75 입력에서 기준 재현·최초 latch 점의 실제 기억 포함 여부·후속 명령을 비교하고, 앞쪽/구조 밖/양옆 무반환/미보존 점과 가까운 뒤쪽 기억의 반례를 검사한다. 같은 `_structure`를 한 호출에 두 번 계산하거나 새 메모리 누적을 만들지 않는다.
- 근거가 맞으면 제한 구현·회귀 후 단독 후속1회를 검토한다. 그렇지 않으면 설계는 미채택으로 남긴다. r76 결과가 다음 우선순위에 영향을 줄 수 있으며 실패한 단독을 자동 반복하지 않는다.

## 격리 검사와 유지한 실패 기록

초기 후보의 [저장 입력 대조](candidate_compare.json)는 r75 고정1,708판단에서 변경 전 불일치0, 변경379회·0→양수374회·양수→0회0이었다. 기존 hidden 기억에 위임한 것은5호출뿐이며 이후 latch가 생성되지 않은 결과다. 실제 차체 이동이나 새 한 랩 결과는 아니다.

최초 넓은 회귀는248통과·3실패였다. 후보를 빼고 기존 런타임에서도 동일3개가 실패했다(45통과·3실패). `test_oblique_sweep_radius.py`가 r69 이전의 ‘30도 안 공백은 무조건 거절’을 기대한 것이 원인이다. r69의 단일 정면 결측에 대한 동일 이동 반경/50mm 폭·0.2m/s 상한 검사로 갱신했고, 다른 넓은 결측·근거리·소실 장애물 거절은 유지했다. 초기 후보/결과는 [initial_candidate_evidence.zip](initial_candidate_evidence.zip), 원 검사와 baseline 로그는 [pre_r77_oblique_tests.zip](pre_r77_oblique_tests.zip)에 보존했다.

후보의 조기 구조 계산이 실패하면 원 위협을 그대로 두고 기존 구조 오류 거절을 반환하도록 보완했다. 관련 반례 포함 **격리252검사 통과** 후 런타임에 연결했다. 현재 코드의 `tests/test_rear_structure_memory.py`는 보관 사본이 아니라 런타임 모듈을 직접 검사한다. 연결 회귀와 재생 결과는 별도로 남긴다.

[현재 연결 재생](connected_compare.json)은1,708판단·baseline 불일치0·변경379·0→양수374·양수→0회0으로 격리 결과와 같다. 연결 회귀/계보253검사·빌드·설치 모듈SHA 확인을 통과했다. 이후 [run_once.py](run_once.py)의 기존81T/native 단독 조건으로1회 실행하며 새 결과·STOP·입력 무결성을 별도 회수한다.

## 실제 단독 후속 결과

[원 report](solo_run1/report.json)는 `passed=true`, **46.67/46.64m·1랩·최고2.847m/s(10.25km/h)·접촉 표본0**이다. 기존42.06m 정체 지점을 통과했다. 실제81T 감속비11.911764705882353·65mm 바퀴·IMU199.068509Hz 요청/200Hz 시뮬 수신·native504/508/512점·10Hz를 확인했다. 원천 시각은 시뮬 취득 시각이며 실물 취득 시각의 승인으로 확대하지 않는다.

[회수 요약](execution_sidecar.json)의 software STOP·정착250구간·정상 종료14/14와 잔류0을 확인했고, 등록552입력은 실행 담당과 GPT 주 에이전트가 각각 대조해 변경0이었다. **STOP 변위0.965m**가 남으므로 즉시 제동이나 실차 제동거리 검증은 아니다. 장애물 기억은 유지했고, 실제 뒤차가 사각 안에서 움직이는 경우까지 검증한 것은 아니다.

이 단독 묶음은 대표를 확보했으므로 시설+C1/다중 차량 정체로 돌아간다. [r76 원 실패](../facility_noise_r76_v1/README.md)와 [후방 띠 연결 후보](../released_fringe_r78_v1/PLAN.md)는 별도 결과로 유지한다.

**작동 범위의 추가 확인:** 새 주행의1,719판단에서는 `structure_rear_memory_transfer` 표시0회·latch0회였고, 저장된 독립 보호 상태 표본에서도 위임 표시는0회였다. 따라서 새 주행은 **변경된 전체 구성이 완주한 대표**이며, 새 위임 분기가 실제 주행 중 개입해 완주를 만들었다는 인과 증거는 아니다. 그 분기의 개선 근거는 r75 고정 입력에서5호출 위임/374회 정지 해소와 연결 반례에 한정된다. 잡음·스케줄링·차량 궤적이 다른 새 실행을 결정적 A/B로 부르지 않으며, 분기를 억지로 발동시키기 위한 추가 반복은 하지 않는다.
