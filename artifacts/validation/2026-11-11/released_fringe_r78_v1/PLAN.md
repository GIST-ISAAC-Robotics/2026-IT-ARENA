# r78 통과 완료 뒤 좁은 후방 무반환 검사 연결

현재 **연결354검사 뒤 시설+C1 제한1회 실행·회수 완료, 20.24m 정체로 실패**다. r77 단독 실행·회수 뒤 런타임을 변경했고, 이번 실제 주행에서 새 후방 재검사 분기는0회였다. 저장 입력에서의 개선을 새 주행의 인과적 성과로 확대하지 않는다.

## 근거와 범위

[r76 실패](../facility_noise_r76_v1/README.md)의 보존 소스203개로3,036판단을 재생해 baseline 불일치0을 확인했다. 상세 분석의 두 외부 의존 `queued_log.py`·`drive_feedback.py`는 현 소스를 읽었으며 완전한 독립 번들이라고 하지 않는다.

첫 HOLD의 sim19.46초에는 G1이 현재 경로로0.85m/s를 제안했고 실제 모터 속도는0.306m/s였다. 일반 전방 관측은 `fully_observed`지만, 회전 중 뒤옆 표본184개가 x −57.6~−45.1mm, 옆면 바깥 최대0.579mm 영역의 후방 +inf 광선에 걸렸다. 원시441–446은 무반환이며 양옆 실제 반환은9.54m/11.83m였다. 전방 장애물이나 단순 거리 잡음으로 단정할 상황이 아니다.

현재 `released_rear_sweep_trial`은 통과 이력을 잠시 유지하는 `retained=True`에서만 기존 저속 후방 검사를 쓴다. 그보다 통과 확인이 더 진행된 `retained=False`의 RELEASED에서는 같은 검사가 빠진다. [동일 장면 비교](geometry_probe.json)에서 목표만 기존 상한0.35m/s로 낮추고 측정속도/두 조향/시각을 유지하면 기존 **1mm 후방 띠·전체6도 예산** 검사를 통과한다. 20/26초의 더 큰 영역과48초 GUARD 장면은 여전히 거절됐다. 새 차체 궤적의 회복을 증명한 결과는 아니다.

## 후보

이미 선택된 교통 회복·후방 검사 옵션을 유지하면서, 현재 옆 위협이 없는 RELEASED/통과 확인 완료 상태에도 같은 함수를 연결한다. G1이 정상 양수이고 부분 관측을 이미 허용했으며 기존 선택이 `large_motion_region_unobserved`인 경우만 검토한다. 원 G1과 같은 현재/직전 조향으로 목표 `min(G1,0.35m/s)`를 한 번 대조한다. 실제속도0.35m/s 초과, 전방/범퍼 밖/큰 후방 영역, 가까운 반환, 잘못된 입력, 남은 옆 위협, STOP은 그대로 거절한다.

공백 각도·폭·점유 여유·TTL·물성은 바꾸지 않는다. unknown의 수와 위험 표시는 남기고 거리를 생성하지 않는다. 이 연결은 이미 사용 중인 정지 물체/가림 위험 가정의 한계를 그대로 가진다. 격리 반례와 고정 입력을 확인한 뒤 채택 여부를 판단하며, 등록된 실제 시설+C1 후속은 소스 변경·검증이 끝난 다음1회만 검토한다.

격리 [candidate.py](candidate.py)는 원 선택기의 결과를 먼저 얻고 해당 거절에만 같은 G1 명령의 속도를 낮춰 대조한다. [19개 합성검사](test_candidate.py)에서0.2/0.35/0.85m/s 원 목표를 올리지 않고 기존 상한을 적용했으며, 현재 옆 위협·0명령/경로 손실·실제속도 초과·앞 가림·가까운 반환·잘못된 입력·큰 후방 영역은 계속 거절했다. 기존 retained 분기는 같은 이유와 출력으로 남았다. 이 결과는 전체 주행이나 실차 검증이 아니다.

[고정 입력 대조](saved_compare.json)3,036판단은 baseline 불일치0이며 sim19.46–19.54초의 **5판단만0→0.35m/s**, 양수→0은0이었다. 이미 정체한 뒤의 큰 영역을 모두 허용하지는 않았다. 현재 입력·미래 궤적이 고정된 비교이므로 실제 정체 방지는 새 주행에서 확인한다.

런타임은 기존 `released_rear_sweep.py`에 검사를 추가하고 `PassReleaseSelector.select`에서 해당 거절일 때만 연결했다. 새 기본 옵션·센서/물성·공백 예산은 없다. 변경 전은 [before_r78.zip](before_r78.zip), 연결은 `config/tests/confirmed_rear_fringe_r78_sha256.json` 계보204다. 최초 연결 검사는353통과·1실패였으며 중복된 옛 `retained=False` 거절 기대였다. [원 검사/로그/계약](first_connected_check.zip)을 보존하고 같은1mm/6도 예산을 확인하는 긍정 검사로 분리한 뒤 [354검사](checks.json)를 통과했다. 현재 옆 위협·STOP 반례는 유지했다.

다음 실행은 [r76과 같은 시설·두 앞차·C1 ±30mm/50±20ms](run.py)이며, 단독에서 확인한 r77도 포함되므로 제어기 단일 변수의 결정적 A/B라고 하지 않는다. 원 진행44.64m·저속2.5초·간격8cm·접촉0·최대두바퀴도로밖·STOP/정상종료 기준을 유지한다. 초기 준비 오류를 피하려고 노면 평가와 실제 잔류 프로세스 조회 후 [assess.py](assess.py)를 수행한다.


## 실제 실행과 다음 원인

[실행 회수](two_actor_run1/execution_sidecar.json)에서 진행20.24/44.64m·앞차 이동 중 최장저속18.432초로 실패했다. 접촉/노면이탈0, software STOP·밀집250구간·정상종료14/14·실제 잔류 프로세스 없음, 등록989소스/사본 불변을 확인했다. C1 거리오차/지연은682취득↔682수신·32–70ms·최대29.9999mm였다. 최신81T와 IMU 명목199.069Hz/시뮬 시간격을 확인했지만 별도 IMU 원시 개수로200Hz를 재측정한 것은 아니다.

실제3,039판단에서 새 r78 분기는0회였다. 이전9.94m를 지났다는 사실만으로 r78이 해결했다고 하지 않는다. 최초 장기 HOLD는32.46초의 `guard_curve_rejected_toward_right`이며, 해당 시각의 G1 자체는1.0m/s를 제안했지만 한 스캔 전 경로를 유지하고 있었다. 이후 짧은0.35m/s 명령이 간헐적으로 나오고 경계 재획득도 실패했다. [대표 필드](first_stop_observation.json).

[고정 재생](diagnosis_summary.json)은 당시989파일 사본에서3,039판단 불일치0·외부 프로젝트 모듈0·원본 불변을 확인했다. [위치 대조](side_points_world_diagnostic.json)의 오른쪽 네 반환은 ID20 왼쪽 지주 부근과 겹치고 주 앞차와는 약1.4m 떨어져 있었다. 보정된 점과 평가용 차체 자세를 겹친 진단이며 정확한 물체 분류나 제어 입력이 아니다. 낮은 발판과의2D 겹침은 실제 레이저가 발판을 봤다는 뜻도 아니다.

균일500점 시험을 같은 조건으로 반복하지 않는다. 다음 [r79](../native_traffic_r79_v1/PLAN.md)는 주행 정책을 유지하며 가변 원천 C1 입력을 교통 시험에도 연결한다. 별도 후속은 지주·짧은 측방 반환에서 유효한 과거 경로를 현재 점유/이동영역으로 재검사할 수 있는지다. 현재의 물체·STOP·점유 검사를 지우거나 경로 출처만 바꿔 승인하지 않는다.
# 첫 측방 정지의 저장 입력 분리

고정된 실패 당시989파일로3,039판단을 다시 계산해 원 결과와 일치했다([진단](diagnosis_summary.json)). 32.46초에 G1은 현재 입력으로 운송한 유효 경로의1.0m/s 명령을 유지했지만, 오른쪽 지주 부근 반환으로 전환된 GUARD는 경로가 이전 스캔 출처라는 이유로 현재 접근 영역 검사 전에 정지했다. 이때 경로 나이는0.257초로 기존0.30초 유효시간 안이다.

[단일 프레임 대조](guard_candidate_probe.json)에서는 경로 출처/시각을 그대로 두고 기존 유효시간의 경로를 **현재 이동영역 재검사에 넣는 사본 후보**를 대조했다. 원0명령은0.35m/s 후보로 바뀌었고, 우측 추가 접근99/99표본이 현재 관측됐다. 미관측0, 기존 허용 범위의 뒤쪽 마스크만 남았다. 이 결과는 한 프레임의 계산이며 새 주행·현재 안전거리의 실물 보장이 아니다. 후보의 격리15검사는 통과했지만 실행 코드에는 아직 연결하지 않았다. 후속은 동일 저장 입력 전체 영향과 현재 native 교통 실패를 함께 비교하는 것이다. 과거 경로를 새 관측으로 표시하거나 유효시간을 늘리지 않는다.
