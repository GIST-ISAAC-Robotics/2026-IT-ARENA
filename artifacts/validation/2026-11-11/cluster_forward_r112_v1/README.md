# 여러 좁은 전방 공백을 포함하는 저속 외곽 비교

2026-11-11. **저장 입력 기하 비교만 완료, 주행 제어·독립 보호 미연결**이다. r109 마지막 정체는 실제 전방의 여러 공백 합계가1.5°를 넘었다. [r109 원 결과](../forward_gap_scope_r109_v1/README.md)는 실패로 유지한다.

## 후보와 관측

각 공백의 폭을 따로 허용하는 대신, 사이에 보이는 점까지 포함해 전체를 둘러싸는 더 큰 하나의 쐐기를 검사한다. 실제 반환은 지우거나 무반환으로 바꾸지 않는다. 양끝 반환까지 취득 방향과 현재 보정 방향의 전체 폭을 비교하며, 전체광선 취득 중 센서 원점의 최대 이동거리도 숨은 폭에 추가한다. 기존 단일 저속 시험의 차체/센서/조향·제동반경과5cm 제한을 재사용한 **분석 가정**이다. 실측속도를 자르지 않고 `max(0.2,abs(measured_speed))`로 비교하며0.6m/s 초과는 거절한다.

원시+Inf만 있는 여러 공백, 실제 사이/양끝 반환1m 이상,200° 전방 관측,기존6도+반환까지한cell 범위·300ms 나이를 확인한다. 이는 자유공간 증명도, 실제 명령 허가도 아니다. 소실한 근거리 반환의 기억·이동 경로별 현재점유·독립 보호는 아직 결합하지 않았다.

저장 r109의 `forward_gap_too_wide`60개 중59개가 이 기하 범위 안에 들었다. [초기 원점 차이 제외 계산](geometry.json)과 [원점 이동 포함 계산](geometry_with_origins.json)을 따로 보존했다. 후자는`probe.py`, 초기 소스는`probe_initial.py`다. 원입력 SHA는불변이며 기존 명령/주행을 수정하지 않았다. 방향 순서,CW/CCW,사이 근거리 물체,NaN/-Inf/거리미만,큰속도/시간/멀리 분리된공백,회전시원점이동,큰차체 반례 **13검사 통과**(`build/r112_probe_tests.log`).

## 다음 판단

1. 더 큰 하나의 공백을 허용하는 가정과 실제로 같은 범위인지 확인하고, 직접 관측된 사이 점은 모든 충돌 검사에 남긴다. 공백 수마다5cm를 따로 지급하지 않는다.
2. 연결한다면 같은 요청/실측속도·이전/현재조향으로 소실 기억과 독립 보호를 함께 검사한다. 원점 이동·조건을 포함한 증거를 다른 경로나 더 큰속도로 재사용하지 않는다.
3. 저장 전체순서 baseline 동일과후속경로 선택을 대조한 뒤 제한1회로 판단한다. 기하59개 통과만으로 실제정지 해소를 주장하지 않는다.

정책 부분만 저장 전체순서에 적용한 [policy_only.json](policy_only.json)은607판단의 baseline 불일치0·기하 후보58개·**실제 명령 변경0개**였다. 같은 경로 증거의 소비부와 독립 보호는 연결하지 않았으며, 기하 조건만 바꾸면 정지가 해결된다고 해석하지 않는다. 입력을 수정하지 않는 분석만 완료했다.

동시에 끝난 r110 지연 주행에서 더 앞선 정체와 접촉이 발생해, 다음 구현 우선순위는 만료 결과와 제어 상태의 처리로 옮겼다. 이 후보는 위 검토 항목과 저장 근거를 남겨 후속으로 유지한다. 사용자 한도복구안내 뒤 필요한 쟁점으로 Fable 5.2/high 자문을 요청했지만 시작 전에 주간한도 실제거절(도구0·추론0)을 받아 조언은 없었다. 자문 결과를 꾸며 채택하지 않았다.
