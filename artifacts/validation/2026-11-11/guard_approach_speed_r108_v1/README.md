# GUARD 접근 거절의 저속 후보 비교

2026-11-11. 실행 코드는 바꾸지 않았다. r105의 현재 경로·실제 측정속도·이전 조향·동일 관측을 유지하고, 측방 접근으로 거절된 목표0.35m/s 대신 기존0.25/0.15m/s 후보를 전체 검사에 다시 넣었다. 현재 경로·완전 관측 경로 증거, 일반 미관측0·전면 가림0인 경우만 비교하며 위협/통과 이력·누적 접근 한계·물성·독립 보호는 그대로다.

[probe.json](probe.json)의 원 실패607판단은 불일치0으로 재현됐다. 후보는346개 명령을0에서양수로 바꾸었고 새 양수→0은 없었다. 기존r91 완주610입력에서는 현행 코드와 후보 사이 추가 변화가 없었다. r91 원 기록과는 앞선r105 직각 적합 변경에 따른 전체21개/명령12개 차이가 양쪽 모두 남는다. 원 기록과 현행 코드의 차이를 이번 후보 효과로 세지 않았다.

이것은 정지 궤적을 고정한 상태형 재생이다. 실제로 움직인 다음의 누적 접근과 완주를 검증한 것이 아니며, 실행 연결/주행은 하지 않았다. r107은20m GUARD 지점을 통과한 뒤42.63m의 별도 전방 결측 분류로 멈췄다. 따라서 이번 후보는 보존하고, 현재 주행을 막은 공백 분류를 먼저 조사한다. 관련 비교는 [r107 관측/단일시점 대조](../scan_start_phase_r107_v1/README.md)를 참조한다.

첫 스크립트는 r91을 과거 기록과 완전히 같아야 한다고 잘못 가정해 assert로 종료됐다(`build/r108_probe.log`). 실제로는r105 변경이 들어있으므로 현행 baseline을 별도로 재생해 후보와 비교하도록 고쳤고 두번째 실행이 완료됐다(`build/r108_probe_v2.log`). 실패 기록과 원 입력은 보존했다.
