# 최신 완주 교통 입력의 Jetson 단계별 연산 비용

2026-11-11 실행 전 등록. [r87](../native_traffic_baseline_r87_v1/README.md)의 실제 native 시설·두 차량 완주 입력3,060판단과 당시 제어기를 동결한다. 이전 r82 비용은 정체 장면이 대부분이어서 이번 실제 완주 입력을 별도로 확인한다. 더 빠른 알고리즘을 택하기 전, 기록 복원·운동 보정 장면 생성·주행 판단의 비용을 구별하는 목적이다.

- [`bundle_manifest.json`](bundle_manifest.json)의107파일을 새 격리 경로로 이관한다. r87 실행 snapshot과 공통101파일이 바이트 단위로 같다. 원시 trace/출력은 기존 Git 제외 정책을 유지한다.
- [`measure_stages.py`](measure_stages.py)는 기존 `follow_trace.replay_call`을 그대로 호출하고 `restore_call`, `motion_scene`, `follow.command`에 시계 관찰만 추가한다. 출력 전체를 메모리에 누적하지 않으며 원 GC 설정을 유지한다.
- 먼저 PC에서3,060판단의 기존 출력과 동일성을 확인한다. 불일치하면 원인을 확인하기 전 Jetson 실행하지 않는다. 그다음 Jetson에서 같은 묶음을1회 실행하고 전체 출력·속도/조향 명령·단계별 wall/CPU 비용·입력/소스 불변을 구분한다.
- 제어·보호·물성·TTL은 변경하지 않는다. ROS 발행·차량 구동·환경/전력 설정 변경 없이 실행한다. 전체 ROS 지연, 실제 센서 취득 지연,20 ms 실시간 마감의 통과를 주장하지 않는다.

## 단계별 결과

[PC](pc_stages.json)는3,060판단의 전체 출력과 명령이 모두 같았다. [Jetson](jetson_stages.json)은3,060속도/조향 명령이 모두 같고 전체 출력은2,814개 일치했다. 입력·소스107파일은 전후 불변이며 두 실행 모두 손실 없는 footer를 확인했다.

| 단계 | Jetson wall 중앙 | wall p95 | 스레드 CPU 중앙 |
|---|---:|---:|---:|
| 기록 입력 복원 | 1.953ms | 2.017ms | 1.950ms |
| 운동 보정 광선 장면 | 6.559ms | 7.161ms | 6.546ms |
| 주행 판단 | 66.748ms | 166.280ms | 66.500ms |
| 전체 | 75.795ms | 175.262ms | 75.511ms |

전체 최대376.266ms·20ms 초과3,060회다. Python3.10.12·NumPy1.21.5·aarch64, GC 켠 상태이며 판단 중 수집3,112회·최대 RSS206,244KiB다. 기록 복원은 실시간 노드에는 없는 재생 비용이고, 실제 노드의 선행 점군 투영·ROS·독립 보호·영상 비용은 여기 포함되지 않는다. 각 열의 백분위는 독립적으로 계산하므로 단계별 p95를 더해 전체 p95로 쓰지 않는다. 이전r85 정체 trace와 다른 입력이어서75.8ms를91.5ms 대비 코드 개선율로 쓰지 않는다.

[플랫폼 출력 비교](platform_comparison.json)는 재실행 없이 회수된 출력끼리 대조했다. 차이가 난246판단은 `motion_region`/`selector_region`/`selector_guard_candidate.region`의 **질의점 개수와 masked_left/right 개수**였다. 속도·조향·선택 결과의 차이는 없었다. 비교 허용치를 바꾸거나 이 항목을 지우지 않으며, 모든 플랫폼에서 전체 출력 동일하다고 주장하지 않는다. 이 기록 밖에서 개수 차이가 선택에 영향을 줄 수 있는지는 미확인이다.

주 비용은 주행 판단에 있으므로 다음은 전체 판단 순서를 보존한 채20호출마다1회만 함수 계측한다([계측기](profile_stages.py)). 이 비용에는 계측 오버헤드가 포함되며 위 지연 수치와 혼합하지 않는다. 새 큰 캐시/주기 변경에 앞서 반복 계산 중 실제 비중이 큰 한 곳을 고른다.

## 함수 표본 결과

[153판단 표본](jetson_hotspots.json)은 전체 순서3,060판단을 유지했고 명령은 전부 같았다. 전체 출력2,814일치와 입력/소스 불변도 단계 계측과 같았다. 자체 비용 상위는 광선 깊이 지지의 내부 `evaluate`1.319초, 여러 NumPy 호출/배열 연산, `break_adjacent_occluders`1.072초, 원천 기하 생성1.017초였다. 하나의 함수만 모든 시간을 차지하는 구조는 아니다.

기둥 분리 함수는218호출·누적3.872초로 확인됐다. 순서·조건을 유지하면서 불가능한 후보를 먼저 일괄 제외할 수 있어 [r89 계산 후보](../occluder_cpu_r89_v1/README.md)에서 검토한다. 다른 비용과 중첩되는 누적 시간을 더하거나 프로파일 시간을 비계측ms와 비교하지 않는다.
