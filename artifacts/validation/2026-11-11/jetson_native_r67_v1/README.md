# Jetson C1 원천 입력 판단 비용 — r67 고정본

**원격 실행·회수 완료. 판단 일치는 통과했으나50Hz 처리 여유는 부족하다.** 함수별 분석 후 CPU 중복 제거 후보를 대조하고 있다.

## 범위

`c1_native_sampling_v1/solo_time_fix/follow_decisions.jsonl`의 원천 CW·가변 점수·점별 시간 입력을 **r67 당시 소스**로 순서대로 재생한다. 먼저1,733개 원 판단 일치를 확인하고, 그 뒤 stream 방식·warmup0·repeat1의 판단 비용을 측정한다. 현재 PC의 후속 r68 요청 감속 변경은 이 묶음에 포함되지 않는다.

입력 복원·운동 보정·주행 판단 비용을 포함하며 JSON 파싱/파일읽기·ROS/DDS·카메라·독립 보호층·MCU·실물 센서 수신/시각 대응은 제외한다. 따라서50Hz 전체 실행이나 실차 주행 증명이 아니다. 환경/전력 설정은 바꾸지 않고 별도 시험 폴더에서 수행한다.

## 실제 Jetson 결과

Python3.10.12·NumPy1.21.5·Ubuntu22.04·6CPU·`schedutil`·`MAXN_SUPER`에서 실행했다. 전후 설정은 유지했다. GPU/CUDA 코드는 사용하지 않은 CPU/NumPy 경로다. [집계](profile_summary.json)의 기준판단1,733/1,733·계측판단1,733개가 모두 일치했고 입력/소스는 불변이다.

|---|---:|---:|---:|
| 새 스캔 |347|63.27 /85.19 /288.26|63.04 /84.85 /286.94|
| 재사용 스캔 |1,386|57.72 /83.34 /296.15|57.53 /82.97 /294.96|

전체 중앙값은 복원1.89ms·점군투영11.30ms·판단45.31ms·합계58.63ms, 전체p95 83.70ms다. 대기보다 CPU 실행 자체가 대부분이다. 오프라인 복원을 제외해도20ms 제어 간격보다 크며, ROS/영상/보호층을 더한 운영 처리율을 아직 입증하지 못했다. 새 스캔을 기다리는 호출도 비용이 크게 줄지 않아 반복 계산이 중요한 조사 대상이다. `passed=true`는 입력/판단/해시 일치이며 실시간 성능 통과가 아니다.

원격 프로세스 종료를 확인했고 원시 report는 로컬 `build/jetson_c1_native_r67_20261111/jetson_profile_report_recovered.json`에 있다. 최초 회수의0바이트 파일은 실패로 보존한 뒤 별도 이름으로 정상 회수했다. 온도 일부 경로는 읽기 실패하여 모든 온도/클럭을 검증했다고 보지 않는다.

후속 `profile_native_hotspots.py`는 같은 고정본에서 전체 상태를 순서대로 진행하되 일부 호출에만cProfile을 켰다. 1,733회 중207회 계측·샘플 판단 불일치0·입력불변이다. [함수 비용](hotspot_summary.json)은 계측 오버헤드를 포함하며 위 비계측시간을 대체하지 않는다.

가장 큰 누적 비용은 `measurement_motion_scene`418회·13.00초와 그 아래 장면 생성이었다. 같은 제어 판단에서 초기 장면 생성과 `TimedPolicy`의 점군 대응 재검사 때문에 약두번 생성한다. `_finite`316만호출·자체2.78초, `isinstance`972만호출·1.54초, `SensorRay.__post_init__`21.2만호출이 관측됐다. 이는207개 샘플의 호출 수이며 전체1,733회의 총량으로 혼동하지 않는다.

따라서 GPU 이관보다 먼저 **이미 검증된 불변 입력의 중복 형식 검사·광선 객체 생성**을 줄이는 CPU 후보를 격리했다. 공개 생성자의 입력 검사는 유지하고, 검증된 `MeasurementScan`을 받는 내부 경로에서 출력 좌표의 유한값/방향과 장면 검사를 보존한다. 균일한 재표본화나 거리/보호 기준 변경은 아니다. CW/CCW·424/508/524점·마스크·비정상변환/overflow의27검사가 통과했다.

첫 격리 후보는 고정r67의1,733판단이 모두 일치했고 전체중앙47.32ms·p95 72.53ms로 약19% 감소했다. 투영중앙5.80ms·판단39.42ms다. 고정105파일·후보·입력 해시는 불변이며 CPU만 사용했다. [집계](scene_candidate_summary.json)와 원시 `build/jetson_c1_native_r67_20261111/native_scene_candidate_report.json`에 보존한다. 20ms 목표는 미달이며 운영 소스에 아직 연결하지 않았다.

두 번째 후보는 단순 점군 투영에서만 필요한 반환 좌표/원천 인덱스를 직접 계산하여 `SensorRay/LocalScene`를 생성하지 않는다. 점별 시간·frame·세대·운동 이력·출력 유한값 확인과 실제 장면이 필요한 호출은 유지한다. 정확한 투영/순서/빈 관측/잘못된 입력·overflow의20검사 및 process-local 연결의 기존81검사를 통과했다. [Jetson 전체1,733판단](projection_candidate_summary.json)은 모두 일치했고 전체중앙49.92ms·p95 74.86ms였다. 첫 장면 생성은 그대로여서 투영중앙11.20ms, 판단중앙36.67ms다. 후보를 중첩하지 않은 개별 결과다.

두 격리 후보와 프로파일 진입점은 [원본 ZIP](isolated_cpu_candidates.zip)에 보존한다. 공통 구현으로 정리한 후속은 [r72](../native_cpu_r72_v1/README.md)다. 실제 제어 노드의 선행 점군 투영·ROS 수신·카메라·독립 보호는 이 판단 단계 계측에 포함되지 않으므로, 이 수치를 전체 노드 실시간 지연으로 쓰지 않는다.
