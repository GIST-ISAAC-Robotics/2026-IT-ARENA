# 수신을 막지 않는 판단 프로세스의 최소 분리

2026-11-11 설계·실행 전 등록. r91 실제10Hz 교통1랩과 r97 스캔 누락 없는 비교가 성립했다. r98의 실제 입력 Jetson 비용을 확인하면서, 기존 판단 함수를 그대로 별도 프로세스에서 호출하는 **ROS 미연결 구성 요소**를 먼저 구현한다. 새로운 경로 알고리즘·빠른 출력 보간·운영 기본값 변경은 범위에 넣지 않는다.

## 이번 수용 조건

- 기존 snapshot/restore와 같은 단위·원천 시각을 보존한다. 단일 모터축 환산을 두 번 적용하지 않는다.지도·정답·actor 입력은 사용하지 않는다.
- 한 작업 진행 중 공유 버퍼를 덮지 않는다. 큰 입력/출력은 공유 메모리, 파이프는 작은 완료/길이/순번 알림에 사용한다. 진행1개·대기 최신1개만 허용한다.
- STOP·RESET·시계 경계에서 부모는 즉시 세대를 올릴 수 있다. 이전 세대의 완료 결과는 채택하지 않고, 새 세대 첫 작업 전 판단기 상태를 초기화한다. 이 구성 요소는 주행 토픽을 발행하지 않는다.
- 원천 취득·계획 기준·완료·회수 시각을 구별한다. 결과 자체가 오래됐을 때는 호출 측이 명시적으로 폐기/상태 경계를 적용하도록 한다. 오래된 양수 명령에 새 timestamp를 찍어 연장하는 기능은 없다.
- 같은 저장 입력과 reset 순서를 주었을 때 기존610판단과 전체 출력이 같아야 한다. 실행 중 reset·busy 중 추가 입력·오류/자식 종료의 경계도 검사한다.

이번 단계는 프로세스 통신과 판단 상태의 분리까지만 확인한다. 실제 ROS 입력 수신, 적용 시점 기하/조향 검사, 50Hz 출력과10Hz 판단의 관계, 독립 보호·STOP 실측은 후속 연결 단계다. 기존 구현/launch는 그대로 두고 기본 실행에 프로세스 생성이나 복사 비용을 추가하지 않는다. 실패하면 이 구성 요소를 운영에 연결하지 않는다.

## 1차 결과

실제 spawn 상태/입력 복사·최신 대기 교체·진행 중 세대 폐기·자식 오류·watchdog·메시지 용량을5개 검사로 확인했다. [PC610판단 비교](pc_process.json)는 전체 출력·명령 모두 동일하며 입력/소스 불변, 자식 강제 종료 없음·exit0을 확인했다. 부모 제출 중앙/p95는0.682/0.809ms, 회수 함수 중앙/p95는0.016/0.188ms였다. 호출 왕복 중앙/p95는23.91/57.22ms로 통신 비용까지 포함한다.

합성5ms 주기 확인은 지연p95 1.382ms·최대3.937ms·주기 누락0이었다. 이는 부모가 계산을 기다리면서 가벼운 작업을 이어갈 수 있다는 제한 근거다. 실제 ROS 수신까지 확인하기 위해 [r100](../ros_ingress_r100_v1/README.md)에서 같은 판단과 합성 IMU 구독을 결합한다. 기존 주행 노드에는 아직 연결하지 않았다.

최초 검사는 Windows의pytest 미설치와WSL 서비스/마지막 CRLF 경로 오류 때문에 실제 검사0회였다. 배포판 복구·스크립트LF 정리 뒤5개 검사와610판단 비교를 각각 완료했고 초기 로그를 보존했다.
