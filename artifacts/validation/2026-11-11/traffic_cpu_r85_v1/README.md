# 교통 판단의 Jetson 계산 비용

2026-11-11. r84 시설/native 교통 대표를 회수한 뒤 실물 이관을 막는 계산 비용을 확인한다. GPT가 분석·구현, GPT-6 Luna가 원격 실행·회수를 담당한다.

동결r82의 [비계측 비용 관측](../path_sampling_r82_v1/jetson_cost_observation.json)은 중앙193.33ms·p95 265.18ms다. 명령3,072회 일치와 전체 출력2,528회 일치는 구분한다. 현재r84나 전체ROS 실시간 성능으로 확대하지 않는다.

[함수 계측](profile_frozen.py)은 동일 입력의 모든 판단 순서를 유지하되20호출마다 한 번만 cProfile을 활성화한다. 프로파일 시간은 오버헤드를 포함하므로 비계측 지연과 구별하며, 원격107파일/입력 해시·명령/전체 출력 비교를 보존한다. 보호 기준이나 주기를 먼저 완화하지 않고 실제 큰 중복 계산부터 찾는다.

Fable 5.2/high 읽기 전용 자문을 요청했으나5시간92% 경고 뒤 최종 답변 전에 호출이 제한됐다. 검토 완료/추천 채택으로 기록하지 않는다. 추가 재호출 없이 GPT가 함수 계측으로 이어간다.

## 함수 계측과 변경

[계측 결과](jetson_hotspots.json)는3,072판단 중153개를 표본화했다. `masked_only`의130호출 누적13.90초·자체9.94초가 가장 큰 병목이었다. 특히 후방 가림을 검사할 때 각 질의점마다 모든 광선에 대해 작은 NumPy 연산을 반복했다. 계측 오버헤드가 있으므로 이 값을 실제1회 지연으로 환산하지 않는다.

`masked_only`만 최대128질의씩 묶고, 광선 원점들의 포함 원으로부터 가능한 각도 범위를 계산해 기존 .025rad 조건에 기여할 수 있는 광선만 선택했다. 원점 원 안·큰 범위는 전체 광선을 유지한다. 동률 선택 순서·취득 번호 인접성·unknown 거절·반환 거리/pad의 엄격 부등식은 유지했다. 먼/미관측 광선을 자유 공간으로 바꾸거나 새 허가를 추가하지 않았다. 원 함수는 [수정 전 소스](before_r85.zip)에 보존했다.

## Jetson 같은 입력의 비계측 비교

[후보 묶음](candidate_bundle_manifest.json)은 r82의107파일에서 `m3_execution_trial.py` 한 파일만 바꿨다. r83/r84 정책 변화와 CPU 효과를 섞지 않기 위한 비교다. [후보 결과](jetson_candidate_cost.json)를 기존 비계측 결과와 대조했다.

| 판단 비용 | 원 r82 | r85 계산 후보 |
|---|---:|---:|
| 중앙값 | 193.33ms | 92.24ms |
| p95 | 265.18ms | 196.87ms |
| p99 | 303.16ms | 255.85ms |
| 최대 | 475.27ms | 402.20ms |
| 20ms 초과 | 3,072/3,072 | 3,072/3,072 |

두 실행 모두 속도·조향 명령3,072개가 기록과 일치했고 전체 출력은 각각2,528개 일치했다. 기존에 남은 진단 출력 차이를 최적화 성공으로 덮지 않는다. 입력·소스 해시는 전후 불변이었다. Python3.10.12·NumPy1.21.5·aarch64의 순수 입력 복원/운동 투영/판단 비용이며 ROS·카메라·독립 보호층·실차 마감 검증이 아니다. GPU·전원 모드·JetPack은 변경하지 않았다.

대표적인 `large_motion_region_unobserved` 2,021호출의 중앙값은200.80→86.62ms였다. 다른 경로의 비용은 대부분 그대로이며, 중앙값 개선만으로 실시간 문제가 해결되었다고 하지 않는다. r84 현행 정책의 저장 입력 재생과 연결 회귀는 별도로 확인한다.

## 회귀와 현행 정책 재생

동결 원 함수와의32비교 검사 및 실행/부분 관측/출처 계보409회귀를 통과했다. [현재 r84 입력 재생](current_r84_replay.json)은3,037/3,037회 전체 판단과 명령이 모두 같았고, 소스127개와 입력 해시도 불변이었다. 첫 세 시도는 ROS Python 경로가 없어 수집/import 단계에서 실패한 로그를 보존했다. 일회성 실행 환경에서 ROS·설치 overlay의 Python 경로를 명시한 뒤 통과했으며 코드/비교 기준을 바꾸지 않았다.

따라서 계산 변경은 유지한다. 새 폐루프 주행의 완주 성과를 이 최적화에 귀속하지 않는다. 전체ROS 처리와 20ms 미달은 남기고, 다음에는 r84의 실제 마지막 정체를 저장 센서로 분리한다.

## 출력 누적을 제거한 추가 대조

앞선 재생기는 모든 판단 출력을 메모리에 보관했다. 이 계측 구조가 GC 비용을 부풀렸는지 분리하기 위해 [단일 스트림 계측기](measure_stream.py)로 두 동결 소스를 각각 한 번 실행했다. JSON 변환·파일 쓰기는 함수 시간 밖에서 하고, 과거 점군/경로를 누적하지 않으며 GC는 켠 상태다. [원본](jetson_stream_before.json)·[후보](jetson_stream_after.json)의 입력/소스는 불변이다.

| 판단 비용 | r82 스트림 | r85 스트림 |
|---|---:|---:|
| 중앙값 | 191.22ms | 91.46ms |
| p95 | 260.58ms | 193.44ms |
| p99 | 297.52ms | 254.36ms |
| 최대 | 470.34ms | 400.03ms |
| 최대 RSS | 205,504KiB | 207,196KiB |

두 실행 모두3,072명령이 예상과 같고 전체 예상 출력은2,528개 일치했다. **원본과 후보끼리 직접 대조하면 전체3,072출력이 모두 같다**([쌍 비교](jetson_stream_pairwise.json)). 따라서 기존544개 차이는 이번 계산 변경으로 추가된 것이 아니다. 두 실행 모두 GC3,126회·판단마다 수집이 있었고 CPU 시간도 wall 시간과 가깝다. 결과 누적을 없애도 비용/개선 폭이 유지되어, 메모리 누적이 주된 설명은 아니었다. 초기 측정과 이번 측정을 별개 원본으로 보존하며, 현재 r86 정책이나 전체ROS의20ms 실시간 성능으로 확대하지 않는다.
