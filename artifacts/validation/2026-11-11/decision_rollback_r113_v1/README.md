# 만료 결과의 상태 초기화·복원 저장 비교

2026-11-11. r110의 동일 입력·동일 적용/폐기 구분으로 전체 reset, 계산 직전 상태 복원, 미적용 전이까지 유지하는 진단용 대안을 비교했다. **실행 제어기에 변경을 연결하지 않았다.**

| 방식 | 적용 후보 중 0명령 | 양수명령 | 명령 차이 |
|---|---:|---:|---:|
| 기존 전체 reset | 102 | 333 | 기준 |
| 계산 직전 상태 복원 | 102 | 333 | 0 |
| 계산 후 상태 유지, 진단용 | 85 | 350 | 22 |

[comparison.json](comparison.json)은492판단 baseline 전부 일치,57개 만료 결과 미적용을 확인했다. 복원 방식의 deepcopy 비용은WSL 중앙4.84ms·p95 5.61ms·최대52.23ms였다. 개선 없이 비용이 추가되므로 **복원 구현은 채택하지 않는다.** 상태 유지 방식은 발행하지 않은 경로/전이가 승인된 것처럼 남을 수 있어 그대로 채택하지 않는다. 저장 결과의 양수명령 증가를 실제 전진·비접촉 증명으로 확대하지 않는다.

WSL launcher의 최초 `E_UNEXPECTED`와 재시작 후 기본 Python의 ROS import 실패는 원 로그에 보존했다. 기존ROS/overlay와`/usr/bin/python3`로 재생만 수행했으며 새Gazebo 주행은 없다. 다음은 계산 시작 시점의 묵은 스캔 선택과 출력 만료를 분리한다. r110의57만료 중51개는 계산 시작 나이를118ms로 바꾼 단순 산술에서는300ms 안에 들지만, 스캔을 기다리는 비용·다음 출력 공백은 아직 반영하지 않은 값이다.
