# 완성 스캔과 명령 수명의 분리 진단

2026-11-11. r114 원시 기록만 사용했다. [analysis.json](analysis.json)의 입력5개 SHA는 전후 동일하며 원 실패 판정·운영 코드를 변경하지 않았다.

- r114 원천 감사 실패의 직접 조건은 누적 source-gap 카운터다. 처음 완성된 스캔(.03초)에서 이미1이고,42.82초 새 스캔에서2가 된다. 검사기는 이 값이0이 아니면 모든 후속 행을 거절한다.
- 카운터 조건만 분리한 **진단 사본**에서는 완성684개와 수신684개의 각도·점수504/508/512·개별시각·형식이 모두 일치한다. 실제 취득 누락2회를 없애거나 무손실로 판정한 것이 아니다. 시작 이전 첫 gap의 정확한 시각은 이 기록만으로 알 수 없다.
- `stale_input`263표본 중191개는 마지막 적용 후보의 기준시각으로 재구성한 명령 나이가200ms를 넘고, 최신 발행 스캔은300ms 이내였다. 나머지72개는 이 재구성만으로 설명되지 않았다. 실제 보호 callback의 수신 시점·상태 발행 주기가 다르므로 강제로 원인을 확정하지 않는다.

명령 기준시각에서 계산 소요를 이미 빼고200ms 수명을 적용하기 때문에, 계산이160ms 걸리면 남는 명령 수명은40ms뿐이다. 새 스캔 제출 정렬만으로 이 문제는 없어지지 않는다. 그렇다고 과거 경로를 현재 관측으로 재검사하지 않은 채 timestamp만 새로 써서 계속 발행하지 않는다. 다음 설계는 계산 결과의 원천 시각과 현재 상태에서 생성한 구동 명령을 구분하고, 필요한 재투영·현재 점유/경로 확인 범위를 정한다. r115의 동일 외곽 캐시는 적중1/318로 미채택하여 작은 최적화 반복은 종료한다.

최초 WSL 서비스 오류는 원 로그에 보존했고, 승인된 해당 배포판 재시작 뒤 저장 자료 분석을 완료했다. 새 시뮬레이션·Jetson 조작은 없다.
