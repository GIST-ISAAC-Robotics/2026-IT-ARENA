# r73 스퍼81T·단일 모터축 환산 적용

사용자 [11/11 전달](../../../../assets/hardware/procurement/2026-11-11/README.md)에 따라 기존2.5단과17T를 유지하고 스퍼만81T로 갱신한다. 실제 조립·치형은 미확인이며2.5단을 중복 적용하지 않는다.

## 구현과 보존

- `vehicle.yaml`·기본 xacro·C++ 독립 기본값을 `2.5×81/17=11.911764705882353`으로 맞춘다. launch의 기존 공통 환산이 encoder·MCU·운동 보정·보호층으로 같은 값을 전달한다.
- 엔코더 자체는 모터1회전28카운트 그대로다. 평균 바퀴1회전333.529카운트·이상적0.61225mm/count, 100Hz 한카운트 속도 단계0.06123m/s다. 좌우 개별 바퀴나 슬립을 새로 관측하는 것은 아니다.
- 동일 모터RPM의 차속은61/81배다. 24V 무부하18,000rpm을 그대로 환산한5.143m/s는 실차 최고속도 보증이 아니다. 토크 상한·마찰·PI·40ms 응답·명령 속도·STOP 기준은 바꾸지 않는다.
- 이전6파일은 [변경 전 사본](before_r73.zip), 연속 계보는 [등록](../../../../config/tests/gearing_81t_r73_sha256.json)에 남긴다. 이전61T/15:1 기록과 당시 고정 config는 새 값으로 소급하지 않는다.

## 검증 결과와 남은 실패

관련 모델 생성/전 소비자 환산/양음 속도·카운트·출처 회귀47개, 두 패키지 빌드와 C++ 방정식 ctest1개가 통과했다. [고정 실행](run_once.py)은 **42.09m/목표46.64m·0랩으로 실패**했다. 최고2.859m/s·중앙1.158m/s·접촉0, 마지막 상태는 `follow_known_obstacle_latched`다. 원 [report](solo_run1/report.json)와 [실행 집계](execution_sidecar.json)를 보존한다. r71 정책/r72 최적화도 포함되어 r69와 엄격한 단일 변수 A/B는 아니다.

runtime SDF의11.911764706:1과 단일 모터 카운트 피드백이 적용됐다. 등록552파일은 종료 후와 GPT 독립 대조에서 불변이다. 종료 시 software STOP은 승인·출력0·조밀한 자세0.5초 정착을 확인했고 자식 exit0/0·정상종료·잔여PID/강제회수0이었다. 이미 정지한 실패 정리이므로 **고속 주행 중 STOP 거리 검증은 아니다.**

첫 latch는37.12초, 직전 관측점과 현재 반환의 대응을 찾는 과정에서 발생했다. 해당0.1초 구간의 모터/IMU 추정 이동은약16mm인 반면 평가용 실제 자세 이동은약71mm였다(평가 시각 약±1ms 차이). 좌우 평균 모터축과 실제 차체의 이동 차이가 관측됐다. 표면 정합은6cm 경계를 넘으며 거절됐다. 이는 **후륜 슬립을 포함할 수 있는 관측 오차**이지 기어 환산 오류로 확정한 결과는 아니다. 평가 정답은 진단에만 사용한다. 정합 경계 민감도와 원시 대응을 먼저 확인하고, 같은 조건을 곧바로 반복하거나 임계값만 통과하도록 늘리지 않는다.
