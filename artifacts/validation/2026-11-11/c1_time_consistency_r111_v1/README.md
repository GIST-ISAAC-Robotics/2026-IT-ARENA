# C1 저장 배치 시각의 명목 간격 일관성

2026-11-11. 11/10에 이미 저장한 SDK 배치 CSV만 분석했다. 새 센서 구동·ROS 연결·시간 계수 교정은 하지 않았다. [집계](report.json)와 [계산](audit.py)에 원본 SHA를 남겼고 분석 전후 원본 불변을 확인했다.

각 배치의 SDK 추정 첫 시각을 `t_first`, 점 수를 `N`이라 할 때 `t_last = t_first + (N-1) × 200 μs`를 계산했다. 다음 배치의 첫 시각 및 현재 `grabScanDataHq` 수신 완료의 호스트 시각과 비교했다. **SDK 추정과 명목 간격을 조합했을 때의 모순 검사이며, 실제 광선 취득 시각 측정이 아니다.**

| 기록 | 배치 수 | 다음 첫 점보다 늦거나 같은 명목 마지막 점 | 다음 첫 시각 − 명목 마지막 시각 중앙 | 수신 완료 이후로 계산된 명목 마지막 점 |
|---|---:|---:|---:|---:|
| 초기 Standard 10 Hz | 102 | 101/101 | −1.791 ms | 93/102 |
| Standard 8 Hz | 162 | 160/161 | −2.342 ms | 155/162 |
| 안정화 후 12 Hz | 242 | 217/241 | −1.571 ms | 203/242 |
| 최종 복원 10 Hz | 102 | 98/101 | −1.807 ms | 90/102 |

연속 SDK 첫 시각 차이를 앞 배치 점 수로 나눈 값의 중앙은 약195.88–196.11 μs다. 그러나 **이를 실제 센서 주기 교정값으로 채택하지 않는다.** SDK 추정 앵커·배치 전송·회전 경계의 영향을 분리하지 않았으며, 기준 장비로 점별 취득 시각을 관측하지도 않았다. 일정한 약196 μs를 넣거나 배치마다 간격을 늘여 맞추면 순서 모순이 줄 수 있지만, 그 자체가 실제 운동 왜곡을 올바르게 보정한다는 증거는 아니다.

현재 시뮬의 점별 시각은 알려진 회전 주기를 기반으로 한 근사다. 기존 저장 CSV의200 μs 투영 시험은 각도·순서·변환의 시험으로 남기고 실물 시간 검증으로 확대하지 않는다. `motion_scan_timing_verified`와 운영 입력은 변경하지 않았다. 실제 연결 전에는 SDK 첫 시각 산출과 호스트 시계 대응을 추적하고, 정적 장면에서 회전/이동하는 검증을 별도로 수행해야 한다. 센서를 움직일 수 없는 현재 조건에서는 이 항목을 후속 실물 검증으로 남긴다.

초기12 Hz 설정이 적용되지 않았던 실패 기록은 다른 보고서에 보존하며 이 비교의 성공12 Hz 표본으로 섞지 않았다. 원시 CSV는 기존 Git 제외 정책을 유지한다.
