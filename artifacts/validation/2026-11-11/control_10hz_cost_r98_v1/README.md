# 실제10Hz 주행 기록의 계산 비용

2026-11-11 실행 전 등록. r91 `two_actor_run4`의 종료·입력 무결성과 실제 `.1s dt`를 확인한 뒤 그 입력과 당시 소스로 격리 묶음을 만든다. 주행 판정 실패가 있다면 그대로 남기며 비용 측정 성공으로 덮지 않는다. PC 재생 일치를 먼저 확인한 뒤 Jetson에서 동일 입력1회를 처리한다.

r88의 단계 계측기와 동일하게 입력 복원·운동 장면·경로 판단을 나누며, 새 제어 주기100ms의 초과 횟수도 기록한다. 기존50Hz 궤적의 계산 비용을10Hz 실험 결과로 부르지 않는다. 원시 입력·출력 전체는 Git 제외 정책을 유지한다.

이는 기록된 센서 궤적을 변경하지 않는 CPU 계측이다. 영상/ROS 수신·발행·독립 보호의 동시 처리나 실제 차량 제어 마감, 취득 시각 검증은 포함하지 않는다. 기본 주기·센서·물성·보호 조건을 변경하지 않는다. 결과가 충분하면 미세 최적화 반복 대신 현재 미완성 기능으로 이동하고, 명확한 계산 과부하가 남으면 수신/계산 분리의 최소 범위를 결정한다.

## 결과와 판단

| 단계 | PC 중앙 / p95 | Jetson 중앙 / p95 |
|---|---:|---:|
| 입력 복원 포함 전체 | 20.126 / 51.680ms | 82.31 / 181.84ms |
| 주행 판단 | 17.824 / 49.514ms | 73.05 / 173.37ms |

PC610판단 전체가 원 기록과 일치했다. Jetson610명령도 모두 같지만 전체 출력은541개가 일치했다. [두 플랫폼 직접 비교](platform_comparison.json)의69개 차이는 `motion_region`/`selector_region`의 질의·좌우 가림 개수이며 원 허용 오차1e-10을 그대로 사용했다. 입력과107파일 묶음은 변하지 않았다. 전체 출력을 동일하다고 보고하지 않는다.

Jetson 전체 최대396.20ms, **610회 중272회가100ms를 초과**했다(판단 단계만은263회). 따라서10Hz 명목 주행 성립만으로 실제 수신·제어가 가능하다고 판단할 수 없다. 현재 단일 executor의 긴 판단과 센서 callback이 경쟁하는 구조부터 분리하되, 지연된 결과의 적용 시점 기하·나이는 별도 확인해야 한다. 다음 [r99 프로세스 구성요소](../decision_process_r99_v1/README.md)는 우선 ROS/출력에 연결하지 않고 동일 입력·상태/세대·통신 비용을 검사한다.

원시 출력 gzip·센서 입력은 로컬에 보존하고 Git에서 제외했다. PC 최초 WSL 호출은 Python 시작 전 서비스 오류였으며 배포판 복구 후 실제1회 계측했다. Jetson은 Python mDNS만 실패하여 Windows OpenSSH로 현재 주소·기존 호스트키 일치를 확인한 뒤 같은 키 검증으로 접속했다. 새 격리 디렉터리에 전송·해시 검증했고 계측 뒤 프로세스 종료를 확인했다. 전원/OS/센서 설정이나 차량 구동은 변경하지 않았다.
