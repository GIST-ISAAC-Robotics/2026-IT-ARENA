# 스캔 누락 없는 첫 판단 비교

2026-11-11 실행 전 등록. Fable 자문에서 제안한 “반복 틱 생략”과 “새 스캔 자체 누락”의 영향을 구분한다. r90 busy 비교는 원천613스캔 중75개를 한 번도 처리하지 않았다.

동결r89 코드·r87 원래 입력·r89 비용을 사용한다. 각 source의 첫 판단만 처리하고 모든613스캔을 남긴다. `.02s`와 `.1s` 두 dt의 결과를 비교한다. 비용값은 원래 seq의 측정값으로 정보 나이 진단에만 사용하며 처리 선택에는 쓰지 않는다. 원래 차체/직전 조향/궤적은 그대로이므로 주행 결과로 해석하지 않는다. 변화된 명령이 다음 관측에 영향을 주는 실제10Hz는 r91에서 별도로 확인한다.

입력·동결 소스 전후 해시, 처리한 scan 수, 새0명령 사유를 확인한다. 운영코드/기본주기/물성/보호/TTL은 변경하지 않는다. 이 결과로 메모리 TTL을 연장하거나 스캔 하나를 여러 새 관측으로 세지 않는다. 실행은 r91주행이 종료된 뒤 수행해 시뮬과 CPU를 경쟁하지 않는다.

두 경우 모두3,060개 원 판단 중 중복 틱2,447개를 생략했다. [20ms](fixed_20ms/report.json)·[100ms](fixed_100ms/report.json)의 원천 입력/계측/동결 소스는 불변이다.100ms의 새0명령은seq2386 하나, 반대 전환은seq996 하나다. r90의145개 새0명령/75개 원천 누락과 비교하면 **반복 호출을 줄이는 것 자체보다 원천 누락·주기 전제의 영향이 컸다는 근거**다. 변수/선택 순서가 여럿 달라 정확한 기여율로 해석하지 않는다.

원래 차체 궤적·직전 조향을 고정한 분석이다.10Hz가50Hz와 출력 동일하다는 의미도, 새 명령을 적용한 주행 결과도 아니다. 폐루프 근거는 별도 [r91 run4](../control_10hz_r91_v1/README.md)에 있다. 이번에는 수신과 계산을 분리하면서 모든 최신 입력을 확보하는 방향을 우선하며, 기억TTL/보호 임계값을 늘리는 근거로 삼지 않는다.

최초 실행은 Python 시작 전 WSL `Wsl/Service/E_UNEXPECTED`로 중단됐다. 허용된 배포판 재시작 뒤 실제 비교1회를 완료했으며 최초 오류 로그와 실제 실행 로그를 분리 보존했다.
