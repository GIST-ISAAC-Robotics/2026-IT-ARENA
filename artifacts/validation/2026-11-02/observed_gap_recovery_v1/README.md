# 관측 경로 GUARD 연결 후보 — 검사 완료, 주행·채택 보류

정지 조향 수정 후 선두칸에서 약 0.101 m 진행했지만, 기둥 옆 평행 후보의 간격 부족으로 다시 정체했다. 현재 스캔에서 확인한 본래 경로를 기존 GUARD 검사로 비교할 수 있게 연결한 선택형 후보다. 상세 설계와 제한은 [PLAN.md](PLAN.md), 이전 폐루프 실패는 [정지 조향 기록](../standing_steering_v1/README.md)에 있다.

|---|---|---|
| 영향권 회귀 | 188 passed, 실제 exit 0 | [로그](tests_attempt1.log), [종료 코드](tests_attempt1.exit) |

저장 입력에서 명령이 달라진 이후의 실제 경로·충돌 여부는 확인하지 않았다. 기존 검사 통과나 빌드는 출발 성공 증거가 아니다. 기본 OFF `standing_wall_reacquire` 조건에 연결한 소스는 남기되, 이번 후보의 채택은 보류한다. 변경 전 소스 [before.zip](before.zip)과 [소스 계약](../../../../config/tests/observed_gap_recovery_r1_sha256.json)을 보존했다.

## 마감과 다음 재개

11/2 후속 사용자 확인으로 실제 트랙 안에는 기둥이 없음을 알게 됐다. 답변 대기는 종료했으며 다음 시험은 기둥 없는 팀 파생본을 사용한다. 현재 파일의 기둥 제거는 아직 하지 않았다. 다음 작업에서 공식 신호·마커를 유지하고 팀 파생본의 기둥 시각/충돌만 제거한 뒤, 이 보정이 여전히 필요한지 판단한다. 공식 원본과 이전 두 번의 선두 출발 실패는 보존한다.

새 시뮬레이션·추가 진단·커밋·푸시는 하지 않았다. 집중 검사·저장 대조·빌드 프로세스는 모두 종료됐다. `run.py`와 `analyze.py`는 준비 코드이며 실행 성공 기록이 아니다.
