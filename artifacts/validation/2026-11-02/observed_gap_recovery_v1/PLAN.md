# 관측된 본래 경로를 막힌 평행 후보와 구별

정지 조향 복구 뒤 선두 출발은 약10cm 이동했다. 이후 왼쪽 앞 기둥을 측방 위협으로 유지하는 동안 현재 위치를 따르는 평행 후보는0.16m 여유로 막혔지만, 관측 벽으로 만든 원래 경로는0.96m 여유가 있었다. 선택기는 이 경우 원래 경로의 기존 GUARD 검사를 호출하지 않았다. 최신 교통 옵션을 연결한 저장 대조도1,576회 속도/조향이 같아 설정 교체만으로는 해소되지 않았다.

명시 standing_wall_reacquire에서 낮은 측정속력<=0.10m/s로 시작하거나 직전 같은 GUARD 후보로 진행 중이며, 현재 스캔이 확인한 원래 경로일 때만 기존 검사를 호출한다. 반환을 지우지 않고, 위협 통과 이력도 유지하며,0.35m/s 상한·위협 쪽 누적 접근·현재/이전 조향·미관측/뒤쪽 제한을 그대로 검사한다. 기본 설정은OFF다.

진단의 최초제어차이는11.96초에0→0.15m/s, 조향0.0674→0.0074rad다. 위협 쪽 추가 접근0, 일반미관측0, 후방마스크 꼬리0.131mm로 기존 제한 안이었다. 새 코드에서는 저속 시작/현재경로 조건을 추가해 범위를 더 좁혔다. 저장 입력은 최초차이까지만 해석하며 실제 주행이 아니다.

관련 회귀·실제 반환 반례·저장 최초차이 확인 뒤, 동일 선두칸/상향20°/1.5mps의 s38m·마커20/30·실제 화면STOP 목표를 한 번 시험한다. 이전 두 실패를 보존한다. 통과를 위해 노면·간격·물성·보호 판정선을 바꾸지 않는다.
