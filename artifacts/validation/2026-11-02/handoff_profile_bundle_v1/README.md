# 최신 단독·교통 판단 계측 이관 묶음

**79파일·32,925,650바이트 묶음의 해시·격리 import·단독 1,860판단·교통 1,059판단 일치를 확인했다.** Jetson에 접속·전송·설치하지 않았다. [파일 목록](bundle_manifest.json), [격리 결과](isolated_result.json), [실행기](isolated_profile.py).

로컬 Git 제외 archive는 `build/jetson_follow_20261102_v1.tar.gz`, SHA-256은 `09bf141c09c9c232ddd97eb3c5682dfd3c608e0336ff4901d8483b8b723d9e3e`다. 원시 센서/판단 파일을 공개 Git에 추가하지 않는다.

## 바뀐 도구

기존 비용 도구는 G1 schema 1만 받아 G1/G2 교통 schema 5를 거절했다. 현재는 기록의 `HandoffExecutionConfig`를 읽어 **실제 BypassHandoffFollow**를 복원하고 전체 판단을 계측한다. FOLLOW/BYPASS/REACQUIRE 비용을 나누며, 오류 경로도 같은 제어기 mode를 보존한다. 묶음 검사도 schema 5와 정확한 controller mode가 맞는 경우만 추가로 허용한다. R0+/다른 전환 형식을 임의로 지원하지 않는다.

관련 회귀 **27개 통과**, 후속 소스 계약 1개 통과. 소스 계약 [handoff_profile_r1_sha256.json](../../../../config/tests/handoff_profile_r1_sha256.json)과 [수정 전](before.zip)을 보존했다. 주행 코드의 변경은 없다.

## 로컬 계측

Python `-I`로 원래 저장소·사용자 PYTHONPATH를 배제했다. 모든 프로젝트 모듈이 새 추출 폴더에서 import됐고 79파일 해시가 유지됐다. 입력별 기준 재생 후 1회 계측, 별도 warmup 0이다. 같은 코드를 다시 실행한 로컬 비교이며 실제 장치 지연 시험은 아니다.

| 입력 | 일치/계측 | 총비용 중앙값 / p95 / 최대 | 20 ms 초과 |
|---|---:|---:|---:|
| 단독 34.451초 구성 | 1,860 / 1,860 | 7.154 / 13.504 / 116.173 ms | 27회 |
| 공식 정지차 우회 p1 | 1,059 / 1,059 | 12.366 / 27.169 / 63.813 ms | 339회 |

교통 BYPASS 315회의 총비용 중앙값은 21.167 ms, 판단 함수 자체 중앙값은 18.371 ms였다. FOLLOW 739회는 총비용 중앙값 10.842 ms, p95 30.796 ms였다. 스레드 CPU 시간도 총 벽시계 비용과 비슷하므로 이번 샘플에서는 외부 대기만으로 설명되지 않는다. 정확한 함수별 원인은 아직 분리하지 않았다.

총비용에는 기록 이력 복원·점별 운동 투영·제어 판단이 포함된다. 파일 읽기/JSON 비교, ROS·영상·독립 보호·MCU, 실제 센서 도착과 시계 매핑은 제외된다. 따라서 **실제 50 Hz 마감 실패율이나 Jetson 성능으로 환산하지 않는다.** 원시 입력 복원 일부는 실제 노드에는 없는 비용이다. 그럼에도 교통 계산 자체의 p95가 약 23.47 ms여서 후속 함수별 분해가 필요하다.

다음은 같은 저장 입력에서 우회 계산의 큰 비용 몇 개를 좁히는 것이다. 단순히 예외 검사를 늘리는 작업이나 실차 준비 완료 선언으로 쓰지 않는다. 이 묶음은 이 시점의 별도 보존본이며 이후 수정이 자동 반영되지 않는다.
