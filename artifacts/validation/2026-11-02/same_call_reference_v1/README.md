# 동일 판단 안의 벽 적합 중복 제거

`ReadyInitialReference.update()`가 같은 scene/config로 `straight_reference()`를 두 번 호출하던 것을 한 번으로 줄였다. 기억 갱신과 원래 기준 선택에 그 결과를 함께 전달한다. **다음 판단에서는 다시 계산하며, 호출 사이 캐시나 관측 유효시간 변경은 없다.** 주행·보호 기준은 그대로다.

[수정 전 소스](before.zip)와 [소스 계약](../../../../config/tests/same_call_reference_r1_sha256.json)을 보존했다. 관련 **130회귀 통과**, 실제 공식 정지차 우회 p1 입력의 **1,059판단 전체 일치**, 계측 중 출력 불일치 0을 확인했다. 직전 테스트 수신 기록을 회수하지 못해 같은 범위만 다시 실행했고 [결과](tests.txt)를 저장했다.

| 로컬 저장 입력 총비용 | 이전 묶음 | 중복 제거 후 |
|---|---:|---:|
| 중앙값 | 12.366 ms | 11.149 ms |
| p95 | 27.169 ms | 26.616 ms |
| 최대 | 63.813 ms | 69.939 ms |
| 20 ms 초과 | 339회 | 299회 |

이전 값은 [격리 묶음 계측](../handoff_profile_bundle_v1/README.md), 이후 값은 [새 결과](profile_after/output/report.json)다. 각 1회·warmup 0이며 환경 변동이 있다. 중앙값 감소만큼 전 구간이 빨라졌다고 보지 않으며 최대 비용은 오히려 증가했다. 실제 ROS/Jetson/영상/보호/MCU 전체 마감 검증이 아니다. 해당 입력의 작은 계산 절약으로 유지하고 장시간 교통 주행으로 넘어간다.

첫 계측 호출은 이미 존재하는 출력 경로를 지정해 입력 처리 전에 종료됐다. [첫 오류](profile_after_attempt1/run.log)를 보존했고 새 하위 출력 경로로 한 번 완료했다. 주행 실패나 반복 성능 측정은 아니다.

## 이관 묶음 갱신

작은 수정까지 포함한 로컬 비공개 묶음 `build/jetson_follow_20261102_v2.tar.gz`를 별도로 만들었다. 79파일·39,333,364바이트이며 SHA-256은 `205daf621873428451bd2e703bc0736a881fe087197e9a57b2b22933414bac63`이다. [목록](bundle_manifest.json)·[내용/해시 검사](bundle_verify.json)를 통과했다. v1 대비 실제 파일 차이는 `bypass_initial_reference.py` 하나다. **v2 별도 격리 실행도 통과했다.** 새 추출 폴더의 모듈만 import하고79파일 해시가 유지됐으며 교통1,059·단독1,860판단이 모두 일치했다([결과](isolated_replay.json)). 추가 성능 계측은 하지 않았다. Jetson에 전송·실행하지 않았으며 로컬 결과를 원격 검증으로 바꾸지 않는다.
