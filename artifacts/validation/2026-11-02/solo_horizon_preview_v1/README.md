# 단독 속도: 관측 벽 탐색 길이의 저장 입력 비교

현재 경로 탐색 길이는 목표 속도·스캔 나이로 필요한 제동 거리를 계산한다. 경로 적합은 새 스캔에서 갱신하므로 다음 갱신까지 남은 관측 경로가 줄고, 경로 끝 기준 감속과 부모 노드 증속 제한이 맞물릴 수 있다. [명령 시각 대조](../solo_alternative_speed_v1/speed_chain_aligned.json)가 출발점이다.

이 후보는 탐색 길이에 `목표 속도 × 현재 스캔 취득 시간(상한 0.15초)`를 더한다. **기존 원시 반환에서 경로를 조금 더 길게 찾는 계산**이며, 외삽·무반환 채움·다음 스캔 도착 보장·관측 유효시간 연장이 아니다. 길어진 적합 구간은 코너 형상이나 판단 비용에도 영향을 줄 수 있어 개선이라고 미리 결론 내리지 않는다.

`compare.py`는 복사한 메서드를 메모리 안에서만 바꾸고, 실행 중인 Gazebo와 소스 파일은 변경하지 않는다. 기준 출력 전체 일치를 먼저 확인한 뒤 같은 저장 입력에 후보를 적용한다. 1.5/2.0/2.5 m/s²의 부모 증속률도 계산만 비교하며 실제 설정은 그대로다. 이후 입력은 원래 차량이 취득한 값이므로 후보의 실제 주행이나 랩 시간으로 해석하지 않는다.

새 정지·조향 차이·2.5 m/s 이상 명령 지속·원본 입력 일치를 확인한 후 제한 폐루프 시험 가치가 있는지 판단한다. 무조건 속도 수치가 높은 후보를 채택하지 않는다.

## 결과: 적용하지 않음

[결과](summary.json)는 기준 1,860판단 일치, 새 정지/기존 정지 해제 0, 최대 조향 차이 0.04395 rad였다. 경로 목표 2.5 m/s 이상은 0.58→0.60초로 0.02초 늘었지만 최고 목표는 2.70567 m/s로 같고, 현재 증속률 적용 후 최고도 2.38012 m/s로 같았다. 증속률 2.0/2.5 계산도 각각 2.3983/2.4461 m/s에 그쳤다.

계산 범위 확대와 조향 변화에 비해 현재 기록의 속도 이득이 작으므로 **런타임에 연결하지 않는다**. 폐루프 실행도 하지 않았다. 다음 비교는 기존 먼 벽 연결 기능을 현재 단독 구성에 조합하는 것이다.
