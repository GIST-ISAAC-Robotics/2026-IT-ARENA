# 경기 운영 후속: 종료 신호와 마커를 건너뛴 재배치

2026-11-02. GPT가 설계·구현·검토, GPT-6 Luna가 실행·회수를 맡았다. 이전 [대표 흐름](../official_ops_v1/README.md)의 결과와 실패를 보존한다. 이 폴더의 결과를 이전 a6에 소급하지 않는다.

## 운영 어댑터 종료 지연

차량·Gazebo 없이 같은 `race_ops` 실행 파일로 [진단](lifecycle_probe.py)을 한 번 수행했다. [원본 결과](lifecycle_report.json):

| 호출 | 부모 PID에 SIGINT | 후속 처리 |
|---|---|---|
| `ros2 run arena_autonomy race_ops` | 3초 뒤 부모와 자식 노드가 모두 남음 | 자체 프로세스 그룹에 SIGINT를 보내 0.665초 뒤 exit 0, 잔존 없음 |
| 설치된 `race_ops` 직접 실행 | 0.715초 뒤 exit 0 | 잔존 없음 |

따라서 관측된 종료 지연은 HTTP 정리 지연이 아니라 **평가기에서 `ros2 run` 부모만 신호를 받은 문제**였다. 운영 노드나 제어기는 바꾸지 않았다. `scripts/race_ops_eval.py`가 `start_new_session=True`로 생성한 자기 실행 그룹에 SIGINT를 보내고, 정상 종료 여부·강제 종료·잔존 PID를 별도로 기록하게 했다. 이전 a6의 어댑터 exit -9는 그대로 남긴다.

변경 전 평가기는 [before.zip](before.zip), 후속 해시는 [계약](../../../../config/tests/official_ops_cleanup_r2_sha256.json)에 있다. 관련 상태·재개·소스 계약 시험 **98개 통과**(69.34초). 전체 시험 반복이나 실물 정지 검증은 아니다.

## 재배치 진단 등록

`d1`: 공식 v2026.11.01 파생 코스, 기존 선정 단독 프로필, 그리드 3, `g1_standing_wall_reacquire=true`. 최초 실제 RGB 신호로 출발한 뒤 왼쪽 추종 상태에서 STOP/RESET을 하고, ID30을 관측하지 않은 채 본선 s=33.7 m에 평가기가 옮긴다. START 한 번 뒤 15초 동안 본선 진행·지름길 진입·정체를 확인한다. 좌표는 평가기만 알고 제어기에 주지 않는다.

목적은 저장된 `side=left`가 배치 위치와 달라도 센서로 본선을 이어가는지 확인하는 것이다. `completed`나 양수 속도 명령만으로 성공 처리하지 않는다. 원시 자세·판단·상태와 종료 결과를 함께 분석하며, 현장 모든 세이브포인트를 검증한 것으로 해석하지 않는다.

실행 명령: `bash artifacts/validation/2026-11-02/official_ops_recovery_v2/run_across.sh`. 한 번만 실행하며 결과를 보고 다음 변경을 결정한다.

ID30은 관측되지 않았고 논리적 `side`는 왼쪽으로 남았다. START 준비 시 실제 `path_wall`은 오른쪽으로, 기존 양측 관측 대조가 이곳의 본선 경로를 찾았다. 이 분기를 고치기 위한 제어 변경은 필요하지 않았다.
