# 상향 카메라 후보의 실제 주행 연결 계획

기본값을 유지하는 `local_sensor_config` 선택 인자와 상향20° 시험 파일을 연결했다. 회귀·빌드·실행 준비를 검증 중이며, 실제 주행과 실물 장착 확정은 아직 하지 않았다. 고속 조합의 미완주는 별도로 보존하고 이 필수 출발 기능을 먼저 확인한다.

## 필요한 동작

기본 수평 B0183의 선두 2칸은 실제 신호가 영상 밖이라 출발하지 못한다. [정지 렌더](../official_start_roi_v1/README.md)에서 여섯 칸의 신호를 본 고정 상향20° 후보를 실제 차량 카메라에 적용해, 출발 뒤 ID20/30에 따른 본선 주행까지 이어지는지 확인한다. 기본 장착은 바꾸지 않으며 실제 기구·크롭·브래킷 확정과 구분한다.

## 최소 변경과 대표 실행

- 현 `b0183_c1.yaml`을 복사한 별도 시험 설정에서 카메라 pitch만 -20°로 바꾼다(SDF 전방+x의 상향). xyz·화각·해상도·FPS·라이다·IMU는 그대로다. 최종 부호는 기존 렌더의 적용값과 대조한다.
- 필요하면 기존 기본 경로를 유지한 선택형 local 센서 설정 경로를 launch에 추가한다. 명시 경로/내용 해시와 실제 생성 모델의 pitch를 함께 보존한다. `vehicle_config`의 D435i pose가 local 모드에서 B0183 값으로 덮이는 현 상태를 우회해 몰래 적용하지 않는다.
- 선두 index2에서 실제 RGB 순서(시험 초록 거부→빨강→실제 초록)로 출발한다. 현재 경기1.5m/s 구성으로 마커20/30을 지나는 본선 구간까지 진행한다. 신규 고속 프로필의 카메라 변경 효과와 섞지 않는다.
- 운영 화면은 시험 전에 열어둔다. 실제 준비 버튼과 주행 중 STOP을 조작하고, 요청 수락→MCU 정지→평가 차체 정지·정상 종료를 구별한다. 기존 화면 STOP의 시간 초과 실패를 성공으로 바꾸지 않는다. 같은 코스를 UI 증명만을 위해 반복하지 않도록 카메라 통합 확인에 함께 넣는다.
- 지도·시뮬/상대 정답은 평가 전용이다. 제어기는 실제 RGB·C1·IMU·모터축 피드백만 사용한다. 진행·마커·기준 벽·접촉/노면·소스/종료 증거를 남기고 기본값으로 자동 채택하지 않는다.

먼 마커가 늦게 보이는 손익은 실제 첫 검출·벽 전환 시점과 경로 유지로 본다. 장착 후보가 대표 주행에서 작동하면 실물 전달값과 확인 필요 사항으로 남기며 각도 전수 탐색을 계속하지 않는다. 다른 선두 칸·높은 앞차 가림·실제 조명은 이번 대표 실행과 별개의 미검증 범위다.

## 실행 전 판정

`analyze.py`에서 실제 RGB 출발, 진행 s≥38m, ID20/30 관측, 본선 경로, 선택 설정/실제 카메라 pitch, 화면 STOP의 정책 수락·MCU 래치·0.2초 연속 정지, 노면 표본/종료/소스 보존을 구별해 판정한다. 접촉 센서가 없는 실행이므로 접촉0을 주장하지 않는다. 원시 평가기의 `passed` 초기값과 `completed`·이 사전 정의 판정은 별개로 보존한다.
