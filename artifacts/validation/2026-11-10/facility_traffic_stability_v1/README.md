## C7: 오목한 상대 옆면과 신호 시설 — 준비와 결과

`stationary_run.sh stationary_recessed_r60 --recessed` 한 번을 수행했다. C6에서 **상대의 라이다에 보이는 옆면만** `recessed_sides`로 바꿨다. 차체 외접 충돌 상자는 유지하고 위치·속도·기둥·노면·센서·정지차 목표와 판정은 그대로다. 단순 상자 측면이라는 가정을 깨도 우회·복귀·시설 통과와 주행 지속이 되는지 확인한다. 바퀴/지붕/임의 차체 전체를 재현한 것으로 부르지 않는다.

`audit_recessed.py`로 실제 실행 SDF의 비시각 구성 불변과 C1 오목면 반환을 확인한다. 오목면 반환 2개 이상·서로 다른 스캔 2개 이상·기존 상자 중앙면보다 많은 반환 및 ±10 ms 자세 시각 대조는 이전 형상 검사 기준을 그대로 쓴다. 실패하면 원인과 범위를 남기고 자동 반복하지 않는다. 경계 갱신 옵션은 이 형상 대조에 섞지 않는다. 통합 두 앞차 저장 입력의 기존 `traffic_boundary_refresh_trial` ON/OFF 비교는 별개로 회수한다.

**경계 갱신 옵션 대조 결과:** [3,053판단 저장 비교](boundary_refresh_probe/summary.json)에서 두 설정 모두 0명령41회, 문제 경계 구간도30회로 같았다. 명령5회가 조금 달라졌으나 모두 기존 양수 `local_follow` 구간이었다. 현재 정지를 해결하는 근거가 없으므로 이 옵션을 해당 통합 구성에 추가하지 않는다. 입력·생산 소스는 불변이며 별도 주행도 하지 않았다.

C7은 **12.025m·우회/본선 복귀·최종 FOLLOW·신호 시설 통과·접촉0**으로 별도 목표를 통과했다. 차량 최소 표본/스윕 간격0.128269/0.128264m, 기둥/발판0.1815/0.1630m, 최대두바퀴잔디였다. 오목면 반환737개/40스캔, 기존 상자 중앙 옆면 반환0개이며 ±10ms 대조에서도 유지됐다. 실행 SDF의3개 시각 도형과 원래 비시각/충돌 상자도 일치했다.

## 실제 구성의 범위

[실행 header 대조](option_coverage.json)에서 시설 두 앞차는 `junction_continuity`·`standing_wall_reacquire` ON/`medium_v1`, 정지차 C6/C7은 두 옵션 OFF/`slow_v1`다. 모두 좁은 가림체 연결·측방 GUARD·교통 회복을 사용한다. 따라서 각 대표를 한 구성의 전체 경기 성공으로 합산하지 않는다. r60 수정 자체가 기존 이동차 추월·피추월에 영향을 주는지는 별도 저장 입력 비교로 확인하고, 최종 통합 구성에서는 갈림길 연속과 이동차/정지차 대응을 함께 확인해야 한다. 기존 실패·원 기록을 소급하지 않는다.

**추가 저장 입력 비교:** r60 이전 `_guard_curve` 함수만 바꾼 독립 재생과 현재 함수의 결과는 오목한 중속 상대753판단·뒤차 피추월398판단에서 모두 같은 명령이었다(각0명령7회). 입력·생산 소스 불변이다. [r60 영향 대조](r60_previous_traffic/summary.json).

`junction_continuity`·`standing_wall_reacquire`·좁은 가림체 연결 ON, `medium_v1`으로 맞춘 결합 설정도 C7 저장1,047판단과 기존 오목한 중속 상대753판단에서 현 설정과 명령이 같았다(0명령 각각17/7). 이는 저장 입력의 호환성 확인이며 해당 결합 설정의 새 실제 주행은 아직 아니다. [정지 비정형](combined_profile_recessed_stationary/summary.json)·[이동 비정형](combined_profile_medium_recessed/summary.json). r60 자체 영향 대조와 설정 결합 대조는 각각 다른 질문이므로 합산하지 않는다.
