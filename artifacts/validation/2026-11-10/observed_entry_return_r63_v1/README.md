# 우회 중 현재 관측을 통한 조기 복귀 후보 r63

2026-11-10 구현·회귀·저장 입력 대조와 같은 장면의 실제 주행 1회를 마쳤다. 재출발·복귀 목표는 통과했지만, 이번 궤적의 오목면 반환은 없어 추가 형상 판정은 실패로 남긴다.

[시설·앞차 재출발 실패](../restart_recessed_facility_v1/README.md)는 우회 경로를 유지하다 오른쪽 신호 지주 앞에서 11.120초 정지했다. 지주 위치는 평가 좌표와 반환점으로 확인했으며 제어 입력에는 사용하지 않는다. 같은 저장 입력의 12.32–13.02초에는 기존 복귀 띠가 관측되고 중앙 경로의 간섭 없는 현재 미리보기 구간이 더 길었다. 기존 구현은 목표 측방 이동과 방향 정렬을 모두 마칠 때까지 복귀를 검토하지 않았다.

기존 `piecewise_wall_trial`과 후방 외벽 증거 옵션을 켠 저속 G2에서만, 현재 우회 경로에 반환점 간섭이 있으면 중앙 경로를 다시 비교한다. 기존 복귀 띠의 전방 관측·점유 부재와 실제 속도·직전 조향·점유 팽창·미관측/가림·조향 한계 검사를 유지한다. 경로 시작점 차이를 없애 동일한 자차 x좌표로 미리보기 끝을 비교하며, 개선 폭은 기존 측정 여유 두 배와 경로 격자 두 칸 중 큰 값 이상을 요구한다. 새 여유를 허용하는 기준이 아니라 불필요한 경로 전환을 억제하는 선택 기준이다.

서로 다른 두 스캔에서 후보가 성립하면 기존 복귀 단계로 들어간다. 같은 스캔을 재사용해 확인 횟수를 늘리지 않고, 입력 고장·역방향 대기·경계 미확정·실제 점유·미관측 거절을 우회하지 않는다. 양수 명령은 원 비교기에서만 받는다. 이동차 추월용 별도 가이드와 일반 기본 경로는 바꾸지 않는다. 선택형 시험의 개선이며 실차/전체 복귀의 보장이 아니다.

검증 순서는 관련 회귀, 실패 재출발·정지 비정형·이동 비정형·시설 결합 한 랩 저장 입력의 독립 상태 비교, 그 뒤 결과를 보고 동일 재출발 장면 1회다. 실제 주행의 속도·판정·시설·노면·STOP 조건은 원본 그대로 유지한다. 실패를 반복해 통과시키지 않는다. 원본과 r60·r61/r62 기록을 보존한다.

WSL은 회귀 실행 전 `Wsl/Service/E_UNEXPECTED`로 단순 명령도 실패했다. 시험 종료 기록을 확인한 뒤 Ubuntu 배포판을 재시작했고, 동일 환경에서 신규14검사를 통과했다. 제어기 실패와 구분하며 OS·Jetson·물성 설정은 바꾸지 않았다.

첫 연결은 꺼져 있는 `adaptive_entry_preview`에 잘못 묶어926/1,047/753/3,060판단에서 적용0·명령변경0이었다. 296검사와 이 실패 연결의 소스·해시·출력을 보존했다. 실제 주행 전 현재 활성 코스/후방 외벽 옵션으로 연결을 바로잡아 `check_v2.sh`로 다시 검증한다. 후속 재생은 이미 동일성이 확인된 원기록과 새 제어기만 대조해 같은 이전 제어기의 중복 실행을 피한다.

## 연결·저장 입력 검증

기존 관련검사282개와 신규15개를 확인했다. v2의 신규 시간축 반례1개는 시험 장면을 잘못 만들어 실패했고, 생성기에서 올바른 시각의 센서를 다시 생성하도록 시험만 고친 v3에서 신규15개가 모두 통과했다. 생산 코드는 v2/v3 사이 불변이다. [v2 로그](tests_v2.log)·[v3 로그](tests_v3.log).

[실제 연결 재생](replay_v2/summary.json): 재출발926판단 중12.42초에 중앙복귀를1회 선택했다. 명령690개가 바뀌었고0명령은588→729로 늘었다. 원 경로로 움직인 센서/직전명령을 새 정책에 그대로 넣은 재생이므로 경로전환 후 이 수치로 실제개선을 주장하지 않는다. 정지비정형1,047·이동비정형753·시설결합3,060판단은 명령 불변이었다. 모든 원입력·소스불변이며 직전 버전의 원기록 재현도 미리 확인했다.

첫 선택은 같은현재속도/직전각/반환/미관측 검사를 통과했고, 관측구간 안에서 중앙목표에 도달하는 전이만 기억한다. 중앙정렬이 아닌 실제 현재 G1 관측으로 조기 인계하는 기존 절차는 유지한다. 이 이후의 폐루프 결과를 확인하기 위해 같은18초 시설 재출발 대표1회를 실행한다. 목표·원실패·속도·기구·시설·센서·STOP 조건은 바꾸지 않는다.

[이관 정적 확인](bundle_dependency_check.json): 기존 묶음 생성기의 의존성 수집99파일에 새모듈이 포함된다. archive생성/실제Jetson 실행 결과가 아니다.

## 실제 주행 결과

[원 report](moving_stop_restart/run1/report.json)와 [원 재출발 목표](moving_stop_restart/run1_goal.json)는 모두 통과했다. 같은 18초 장면에서 총 6.790 m, 앞차 재출발 후 0.457초에 재출발해 4.570 m를 더 진행했고 최종 FOLLOW로 본선에 복귀했다. 마지막 2초 진행은 0.961 m, 최소속도는 0.489 m/s였다. 전체 최장 저속 3.236초는 앞차가 정지한 구간을 포함하며, 앞차 재출발 후 최장 저속은 0.303초다. 두 값을 혼동하지 않는다.

표본/스윕 최소간격은 0.67236/0.672359 m, 접촉·시설 겹침·마지막 차체 노면 이탈 표본은 0이다. STOP 정착·정상 종료·잔여 프로세스 없음·소스 불변을 확인했다. 새 복귀 후보는 시뮬 11.92초에 한 번 적용됐다. [시각 대조](application_timing.json)에서 이는 녹색 뒤 약4.52초로, 앞차 재출발(녹색 뒤8.019초)보다 앞이다. 앞차가 정지해 있을 때 이미 보이는 중앙 경로로 돌아와 기다린 뒤 재출발한 결과이며, 앞차가 떠난 것을 감지해 복귀했다는 설명과 구별한다. 원 실패의 2.417 m·재출발 후 진행 0.0052 m·최장 저속 11.120초와 [동일 평가 대조](motion_comparison.json)를 보존한다. 한 번씩의 폐루프 비교이므로 차이 전체를 후보의 결정론적 효과로 확대하지 않는다.

**추가 종합 판정은 실패다.** [형상 감사](moving_stop_restart/outline_assessment.json)는 요청한 3개 시각 형상과 원 충돌 상자 보존을 확인했으나, 새 궤적에서는 오목한 옆면 반환/스캔이 0이었다. 따라서 이번 결과는 시설 근처 재출발·복귀의 증거이며 오목면 검출 시험을 완료한 근거는 아니다. 이전 정지차·이동차·시설 결합 한 랩의 오목면 반환 증거를 따로 유지하고, 반환을 얻으려고 같은 장면을 다시 돌리지 않는다.

이 대표의 장기 교착이 해소되어 다음은 남아 있는 지속 코너 동행의 조향/정지 문제다. 신호 카메라 최종 배치·추가 증속·실차 검증은 이 결과에 포함하지 않는다.
