# 확정 통과 뒤 기존 후반부 검사 재사용 — r61

**최종: 현재 코드에서는 미채택, r62로 r60 바이트 복원.** 아래 구현·검사·주행은 당시 결과로 보존한다. 같은 주행을 반복하지 않는다.

2026-11-10. [코너 동행 실패](../corner_parallel_continuity_v1/README.md)의 첫 정지에서 관측 영역과 상태별 처리를 비교했다. 통과 직후에는 사용하던 **1mm 후반부·3° 무반환·양옆 실제 반환0.6m 이상** 검사가, 측방 통과 확인을 충분히 쌓은 RELEASED에서는 적용되지 않았다. 통과를 더 확인해도 같은 검사를 거칠 수 있게 한다. 속도/관측 한계를 넓혀 허용하지 않는다.

## 적용 조건과 보존 범위

- 기존 `traffic_recovery_trial` 연결 안에서만 동작한다. 현재 양수 G1 경로, 현재 스캔에서 재확인한 경로, 정상 부분관측 판정, 모든 관측된 쪽의 통과·두 fresh 확인, 현재 위협 없음이 필요하다.
- 목표는 기존 상한0.35m/s 이하로만 낮춘다. 실제 측정속도와 현재/직전 조향을 그대로 사용해 전체 이동 영역을 다시 검사한다. 1mm 제한과 기존 가까운 반환·원시 양의 무한대·스캔 시각/광선 순서·전방 가림·후방 가림1cm 조건을 유지한다.
- 미관측 표본과 위험 수용 기록을 남긴다. 자유 공간을 생성하지 않는다. 가려진 얇은 물체·운동/형상 오차의 위험은 기존과 같이 남는다.
- 조건을 통과하지 못하면 원 선택을 유지한다. 기본 OFF 여부·독립 보호·물성·센서·평가 기준을 바꾸지 않는다.

직전 소스는 `before.zip`으로 보존했다. 최초 구현 검사에서 설정 객체를 잘못 참조한 `AttributeError: FollowConfig has no attribute release_fresh`를 수정했다. 이후 신규22검사가 통과했으며 관련 기존 회귀와 독립 재생을 진행한다.

첫 관련 회귀는228통과·출처 사슬1실패였다. r60/r61 변경이 이전 r48 선택기 해시 뒤에 아직 등록되지 않은 것이 원인이며 검사 실패를 무시하지 않았다. `register_sources.py`가 r60 이전 바이트를 `70dfa9a6`과, r60 바이트를 실제 C6 실행 report와 대조하고 두 후속 사슬 및 원경로 ZIP을 등록했다. 이전 계약·해시·실패 로그는 보존한다. `checks_v2.sh`에서 관련 회귀와 출처 검사를 다시 수행한 뒤 저장 재생으로 진행한다.

## 검증 순서

1. 새 연결 반례22개와 기존 RELEASED/GUARD·무반환 검사.
2. 코너 원1,732판단과 정지/이동 비정형 입력에서 r60/r61 독립 상태 비교. 첫 shadow 비교는38.82/38.84초 두 판단에서만 기존 기준 통과였다. 뒤의 더 넓은 무반환은 미허용으로 남는다.
3. 위 검사를 검토한 뒤 **같은 코너 상대 각본·속도·판정**으로1회 주행. 성공할 때까지 각본이나 판정선을 바꾸지 않는다. 이 단계는 아직 미실행이다.

이 작은 연결 수정이 실제 감속/회전의 연속성을 바꿔 코너 출구까지 이어지는지 확인한다. 저장 입력의 두 후보만으로 코너 동행 성공을 주장하지 않는다. 카메라 신호등 최종 배치·추가 증속·P22는 이번 범위가 아니다.

**연결 확인 완료:** 관련·출처387검사 통과. 독립 재생은 코너1,732판단에서0명령337→335,38.82/38.84초만0→0.35m/s였다. 정지 비정형1,047·이동 비정형753판단은 명령 불변이다. 입력·생산 소스 불변을 확인했다. [검사](tests_v2.log)·[저장 비교](replay/summary.json).

**같은 코너1회 등록:** `run.py`는 직전 실패의 상대 설정/기하 파일 바이트와 기존 평가기 해시를 확인하고, 위387검사/재생 및 시험 소스 해시를 확인한 뒤 실행한다. 속도·간격·노면·STOP·출구·0.5초 실제 동행 기준은 그대로다. `run.sh`로 실행·평가·잔여 프로세스 확인을 수행한다. 진행 중에는 생산 소스를 동결한다.

## 실제 결과와 미채택

같은 장면1회는9.95m·최장저속2.114초·출구 미도달·실제동행0초로 실패했다. 접촉/노면이탈0, 최소표본/스윕간격0.1000/0.099999m, 명시STOP·정상종료·소스/사본불변·잔여프로세스0이다. STOP 변위0.000065m·대기0.5초는 이미 정지한 상태의 결과다.

**새분기158회 검사·실제채택0회**였다. 이전9.91m/2.313초와의 작은 차이를 코드 효과로 보지 않는다. 저장입력2판단의 가능성이 새주행 정지를 해결하지 못했고, 실제 계산만 추가됐으므로 현재 제어기에서 제거했다. `before_restore_r62.zip`에는r61 코드·신규검사를, `archived_candidate_tests.py`에는 해당 후보 전용검사를 보존했다. r62 출처 사슬은 실제C6에서 사용한r60 선택기 바이트로 되돌아감을 기록한다. 시험 당시원본·실패·r61해시를 변경하지 않는다.

## 후속

단순 저속화·통과 상태별 기존1mm 예외로는 지속 코너 정지를 해소하지 못했다. 핵심은 현재 회전 외곽의 후반 무반환과 이전 관측의 관계다. 넓은 결측을 무조건 허용하는 변경은 하지 않았다. 이 원인과 기존실패를 유지하고, 시설+마커누락+비정형 상대의 통합 대표로 전환한다. 이후 코너는 이전센서관측을 현재운동으로 옮겨 실제 지지가 남는지부터 검토하며, 새주행 근거 없이 동일 각본을 반복하지 않는다.
