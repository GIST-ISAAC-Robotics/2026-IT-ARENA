# 직각 코너 팀 시험 코스 v1 — 현행 단독 주행 시험과 수정 범위 추정

- 날짜: 2026-11-05 (KST). 구현·형상 생성·분석·보고서는 Claude Opus 5.5가 맡았다. 주행 실행·대기·회수는 Claude Haiku 5.5 보조(별칭 `haiku`, 자체 보고 `claude-haiku-5-5`)가 1회씩 수행했다.
- 배경: 주최 측이 제안한 새 도면(Discord 사진, 직각 벽 배치)을 바탕으로 한다. **정확한 치수와 배치는 알 수 없다.** 아래 코스는 사진을 재현한 것이 아니다. 직각 코너 유형을 시험하려고 세운 **대표 가정**이다.
- 범위: 사용량 경고(five_hour 90%)를 받아 run6 회수 직후 작업을 멈췄다. 새 주행과 추가 구현은 하지 않았다(§6 재개 방법).

## 1. 결론

## 4. 격리 시험 후보(공용 코드 미반영)

`trial_patch/`에 있다. ws2 사본은 공용 트리와 `local_path.py`·`local_follow.py` 두 파일만 다르다(`ws2_vs_main_code.diff`, `trial.patch`).

1. `local_path`: 3차 적합이 `wall_shape_uncertain`일 때만 같은 관측 표본을 쓴다. 꺾은선으로 근사(Douglas–Peucker 2 cm)하고 각 구간을 0.425 m 평행 이동한 뒤, 45–135° 모서리를 반경 0.45 m(최소 0.40 m) 원호로 잇는다. 관측 끝 밖으로 외삽하지 않는다. 버전별 차이: v2는 첫 모서리의 관측 창 제한을 풀고 가림 뒤 짧은 마지막 조각을 버린다. v3는 모서리 재표본화로 생긴 4 cm 모따기 구간을 교점으로 합친다.
2. `local_follow`: 선호 벽이 승인되지 않았을 때, 꺾은선으로 표현된 반대 벽 경로가 **직전 승인 경로와 일치하면** 쓴다. 기억이 없으면 쓰지 않는다. 실제 통과는 대부분 이 분기가 아니라 기존 `bilateral_observed_corner_distance` 근거로 승인됐다.

보호 조건은 완화하지 않았다. 확인 횟수, 점유, 제동, 독립 보호층, STOP 경계는 그대로다. v3의 오른쪽 코너 바깥 벽 경로는 짧고 방향이 틀리게 생성됐다(run6 17.34 s 그림). 이것은 **시험 후보 자체의 결함**이다.

## 6. 재현·재개

- 형상: WSL에서 `bash gen_world.sh`(v1, 기존 `course_world/`가 있으면 거절), `bash gen_world_iso.sh`(iso 생성 후 ws에 설치).
- 격리 사본: `setup_isolated_ws.sh` → `install_world.sh [course_world|iso_world]` → `run.sh <이름>`(`WORLD=<월드 디렉터리>`), 이어서 `post.sh <이름>`. 진단은 `diag.sh <run> <출력> <시각…>`.
- 시험 후보: `trial_patch/setup_ws2.sh <월드>`(또는 `reset_ws2.sh`) → `trial_patch/install_ws2_world.sh <월드>` → `trial_patch/run_ws2.sh <이름> <월드>`. 공식 기록 재생은 `trial_patch/official_replay.sh`.
- 주의: Git Bash에서 `wsl.exe bash -lc '...'` 안에 `$변수`나 `/home/...` 경로를 쓰면 바뀌어 버린다. 항상 스크립트 파일로 실행한다. run3의 첫 시도는 이 문제로 `run.sh`가 시작되기 전에 실패했고, 산출물은 생기지 않았다. run2 실행 중 `run.sh`의 `WS=` 기본값 줄을 고쳤다(경로는 그대로). 콘솔·종료 기록이 온전하고 결과가 run1과 같아 영향은 없었다고 판단한다.
- 재개 후보: §5의 1·2를 공용 코드에 정식으로 넣을지, 그 설계 여부는 GPT 주 에이전트와 사용자가 판단한다. 추가 주행은 `iso_world`에서 오른쪽 직각부터 확인한다.
