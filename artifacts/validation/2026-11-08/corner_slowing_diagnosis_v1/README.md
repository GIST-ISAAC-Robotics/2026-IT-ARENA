# 코너 감속 상대의 긴 정지: 현재 경로가 짧아진 뒤 갱신 실패

2026-11-08. [원 주행](../corner_slowing_actor_v1/README.md)의 **1,891명령을 동일하게 재생**했고, 원 명령과 차이 0·생산 소스 불변을 확인했다. 경계 계산 직전/직후와 측방 선택기를 계측해 136스캔·673호출을 저장했고, 정지 전후 90스캔의 248경로 후보를 비교했다. 평가용 차체 정답을 제어기 입력에 넣지 않았다.

| 시뮬 시각 | 현재 관측과 판단 |
|---|---|
| 35.52초 | 오른쪽 조각 코너의 현재 경로 약2.05m를 갱신. 기본 경로 명령 양수 |
| 35.62초 | 오른쪽은 `wall_segment_short`. 왼쪽 현재 `piecewise_corner`의 벽 전방 관측은0.510m·앵커 오차9mm이며 생성 경로가 직전 경로와 x/호길이 비교 모두 일치. 그러나 신규 경계의0.65m 조건에 못 미쳐 갱신하지 못하고 직전 경로만 사용 |

직접 원인은 **현재 따라가던 코너의 짧아진 관측까지 새 경계의 길이 조건으로 거절한 것**이다. `boundary_bridge`의 기존 짧은 현재 경로 인계는 단독 전용이어서 이 교통 구성에서는 꺼져 있다. 미관측을 임의로 채우거나 TTL을 늘리지 않고도 유효한 이력이 살아 있는35.62초에서 현재 짧은 관측으로 갱신할 가능성이 있다. **이때0.510m는 벽의 전방 관측 호길이이며, 벽에서 떨어진 원호 경로의 길이1.31m와 다르다.** 새 제한 후보는 관측 길이 이내의 경로 앞부분만 사용한다. 해당 경로에서 실제로 계속 움직일 수 있는지는 점유·측방 선택·폐루프 시험을 따로 통과해야 한다.

긴 정지의 원인은 `parallel_hold_baseline_unavailable`의 내부 `follow_boundary_unconfirmed`다. 제어기 자체가0명령을 내므로, 독립 보호층이나 MCU가 양수 명령을 막은 것이 최초 원인은 아니다. 이 분석으로 모든 실제 충돌 여유가 충분하다고 결론 내리지는 않는다. 원 주행의6.442초 정지·실제 코너병렬0·출구 실패도 유지한다.

다음은 [짧은 현재 코너 후보](../traffic_corner_prefix_probe_v1/PLAN.md)를 미연결 사본에서 비교한다. 최초/만료 이력과 다른 면은 받아들이지 않고, 원시 장애물을 점유 검사에서 제거하지 않는다. 표적 반례와 명령 변화가 타당할 때만 연결을 검토한다.
