# 직각 접근 감속 r19 — 선택형 연결

세 저장 입력에서 문제 제동 전에 32.24–32.40 m부터 기존 명령을 최대 0.39–0.40 m/s 낮추고, 10 km/h 이상 지령 72/72·54/54·74/74회를 유지했다. 이 저장 입력 비교만으로 실제 감속/완주를 증명한 것은 아니다. 후속 폐루프 결과는 아래와 같다. 단독 직선 예산 옵션과 별도 `--corner-approach`를 모두 지정할 때만 사용한다. 기본 OFF·기존 조향/낮은 명령·STOP·보호·물성 유지.

관련 회귀, 직전 계측 주행의 OFF 전체판단과 ON 후보수치 비교 뒤 동일한 접촉 계측에서 1회 대조한다. 원래 거리·노면·정지/종료 판정을 보존한다. 최고속도·완주·접지 개선을 각각 분리하며 신청호 없는 재시도를 반복하지 않는다. 앞선 원인 분석은 [접촉 진단](../solo_contact_diagnosis_v1/README.md), 저장 후보는 [조기 감속](../solo_corner_approach_v1/README.md)이다.

연결 검증: 관련 회귀 **134개 통과**, 직전 계측 주행 **1,544판단 OFF 전체 일치**, ON은 고정 입력 후보와 수치 일치(343판단 변경), 두 패키지 빌드 성공. 이 결과는 아래 폐루프 판정과 구별한다.


## 실제 1회 — 앞선 편측 접촉 문제 구간 통과, 후반 미완주

**42.66 m·0랩·차체 최고 2.877 m/s(약 10.36 km/h)**다. 단독 감속 후보를 추가한 한 번의 비교이며 반복 분산/실물 검증이 아니다. 기존 접촉 계측 주행은 35.10 m에서 멈췄다. 진행 33–35 m의 구동 공통 시각을 대조한 결과, 이전에는 43개 시각 가운데 오른쪽 뒤 접촉이 25개였지만 이번에는 네 바퀴 모두 64/64개 시각에 접촉했다. 같은 구간에서 차체가 1.5 m/s 이상인데 한 바퀴만 0.5 m/s 아래로 느려진 표본은 16→0개였다. 두 실행은 별개의 폐루프이므로 정확히 같은 궤적이나 시각의 인과 실험으로 확대하지 않는다. 상세 산식·원시 해시는 [comparison.json](comparison.json)·[analyze.py](analyze.py)다.

실패는 더 뒤의 FOLLOW_LATERAL_METRIC_OUTSIDE_TRIAL이다. 최종 라이다에서 7개 무반환 광선, 약 5.04°의 구간이 남았으며 0.6 m 기준 횡폭 60.29 mm가 현 선택형 보완의 50 mm 상한을 넘었다. 소스/표면을 바꾸거나 상한만 올려 통과시키지 않았다. 기존 r11의 거리 1랩 기준을 보존하고, 이 증속 구성을 전체 완주 성공으로 바꾸지 않는다.

노면 22,713개 자세에서 세 정의 모두 도로 밖 바퀴 0·벽 바퀴 0, 접촉 표본 0, 874개 등록 입력 불변이다. **정상 완주 뒤 STOP 단계에는 도달하지 않았지만, 실패 정리 경로의 명시 STOP ACK·0.5초 밀집 정지 확인(최대 0.000677 m/s)·MCU ESTOP_LATCHED/stationary_ready=true는 있다.** 정상 완주 STOP과 실패 정리 STOP을 구별한다. 자식 15개 정상 종료·잔여 프로세스 없음이며 접촉/구동 수신기 모두 정상 종료·구문 오류 0이다. 앞선 구두 수집에서 STOP 증거 없음이라고 한 것은 최상위 stop 필드만 본 오류여서 원 report의 failure_cleanup_stop으로 정정한다.

이 코너 제동의 제한 개선은 확보했으므로 뒤차 피추월·여러 차량 출발로 옮긴다. 단독 속도 재개 시에는 마지막 무반환 7광선의 실제 경로 교차/물체 여유를 저장 입력으로 먼저 분석한다. 폭을 단순히 늘리거나 동일 전체 랩을 성공할 때까지 반복하지 않는다.
