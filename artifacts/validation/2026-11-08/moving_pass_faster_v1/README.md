# 빠른 상대 추월 r31 — 진입 후 정체, 미채택

새 코스의 **0.70 m/s 상대를 추월하지 못했다.** 10초 진행 창에서 3.64 m, 첫 출발은 초록 뒤0.678초, 최장0.05 m/s 미만 구간은4.762초였다. 초록 뒤3.119초에 추월 진입했지만 나란히/앞서기/복귀는 없었다. 전체 최고1.529 m/s·최대 명령1.5 m/s는 일반 추종 구간도 포함하므로 추월 속도 성과로 쓰지 않는다. 이 후보는 기본OFF이며 기존 활성 중속 프로필을 대체하지 않는다.

## 변경과 검증 범위

- 명시 `faster_v1`: 추월 명령 상한1.20 m/s, 상대 관측 추정상한1.00 m/s, 실제 선택 경로의 속도 이점0.20 m/s, 대응 탐색과 공통 물체 시차 예산1.20 m/s. 기본 `slow_v1`/기존 `medium_v1`은 유지했다.
- 실제 모터축 측정이 G1 명령상한1 m/s를 넘었다는 이유만으로 추월 경로를 초기화하지 않는다. 실제 측정 속도를 제동·현재 이동 외곽에 그대로 넣고2.5 m 스윕 범위를 넘는 값은 별도HOLD로 구별한다. 비정상값·시각 역행·epoch 변경 초기화는 유지한다.
- v1은 고정 외벽까지1.2 m/s 시차 여유로 취급해 옆 공간 후보가 없었다. v2는 편이 제안에 기존 고정 외벽 가설을 일관되게 적용하되, 실행 전 두 개의 서로 다른 스캔에서 외벽이 일치해야 한다. 상대차 시차 여유는 줄이지 않았다. 명시 빠른 후보에서만 최대35 cm 편이와0.9/1.2/1.5 m 전이를 비교한다. 바퀴 노면은 별도 평가한다.
- `/drive`→독립 보호층→`/drive/safe`, 단일 모터축28카운트·8.970588:1·65 mm·B0390·C1 순차10Hz·JR60P20을 유지했다. 정답/지도/상대 ID를 제어기에 넣지 않았다. 교통의 명시 평탄 잔디 파생본이며 단독 원 노면과 구별한다. r29/r30 경계 후보는OFF다.

최초265관련 검사, 후속395검사, 최종launch/출처 연결154검사를 각각 해당 변경 단계에서 통과했다. 빌드2패키지도 통과했다. 오래된r13 저속/r15 중속 저장 trace와는177/197판단 차이가 있었으나, **직전r30 소스를 격리 복원한 비교에서도 같은 차이가 났고 이번 수정 전후749/748판단 차이는0개**였다. 이 원래 차이를0개로 고쳐 쓰지 않는다. 근거는 `before_comparison_summary.json`, `current_comparison_summary.json`이다. 고정 입력의faster_v2가 진입을 선택한 사실도 실제 새 경로의 주행 성공과 다르다.

## 원인 분리와 다음 순서

판단 기록에는 `moving_pass_current_path_unavailable`235회가 있다. 첫1회는12개 현재 이동 외곽 표본의미관측, 나머지234회는`known_occupied_command_hold`였다. 대표t=12.30s에서 반환점과 여유로 계산한 현재/첫4cm 스윕 간격이0이 됐다. 실제 앞차는 점점 멀어졌고 접촉도없었다. 측정1 m/s 초과 초기화가 주원인은 아니다.

`diagnose_stop.py`로 막은 실제 반환·고정외벽 분류·시차 팽창을 분리한다. 현재 시점에서는 고정 외벽 가까이 진입한 뒤 분류되지 않은 반환에 큰 이동 여유가 적용됐을 가능성을 조사하는 단계다. 실제 반환을 보지 않고 보호 기준부터 낮추거나 동일 주행을 반복하지 않는다. 다음 수정이 필요하면 당시 소스/실패를 보존하고 원인이 달라지는지 저장 입력에서 먼저 확인한다. 지속 코너 병렬·교통 속 운영·실물 이관·지름길 검토도 기존 계획에 남긴다.
