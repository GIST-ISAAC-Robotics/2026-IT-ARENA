# 새 코스 오른쪽 앞 차량 대표 — 실제 주행·사후 집계 완료

정지차/재출발의 공통 손실 보완 결과를 확인한 뒤 실행한다. 현재는 평가 설정과 정적 검사 도구만 준비했으며 등록·실행하지 않았다. 사용자가 요청한 기존 측방 대응 작업을 새 코스에서 이어가는 대표다.

상대는 도로 중앙 기준 오른쪽0.23m, 자차 앞0.50m에서0.50m/s로12초 이동한다. grid3 자차가 이미 중앙보다 오른쪽9cm이므로 같은 종방향에 배치하면 시작부터 겹친다. 시작 위치 겹침을 검사하고 실제 나란히 주행한 시간/표본을 따로 확인한다. 뒤에서 빠르게 접근하는 차량에 추월당하는 장면은 아니다.

원래 앞차 추종 평가(15cm·항상뒤에있기·차체도로안)는 보존한다. 기존 별도 경기 목표의8cm·최대두바퀴잔디·2.5초 저속 한계·마지막2초0.5m전진을 유지한다. 상대 실제 이동은50Hz각본/100Hz자세의 순간 미분 대신1초 이동량0.45–0.55m를 확인한다. 상대 정답은 평가에만 쓴다. 제어기 상한/새 기본값/노면·물성은 바꾸지 않는다.

## 실행 선택

동일0.50m/s상대에서 이미 확인한 r15 `--moving-pass-profile medium_v1`(추월 상한0.90m/s)을 명시한다. 새 상한 조정이 아니며 전역1.5m/s·선택형 r18후방면·새 직각 옵션을 함께 사용한다. r18 정지차/재출발 대표가 개선돼 이 장면으로 전환했다. 정적 배치 검사→등록→12초1회이며 실패를 성공까지 반복하지 않는다.

## 실제 주행과 평가 오류

기하·등록exit0 후12초1회를 실행했다. 그런데 `behavior_kind=slow_lead`만 지정하고 `acceptance.right_side_start` 별칭을 빠뜨려 원 평가가 `KeyError: minimum_progress_m`로 실패했다. 따라서 원report의harness_valid/run_valid는false이며 `HARNESS_EXIT=1`, 보충평가도`t_green`누락으로exit1이다. 이 원본/설정/등록/종료값은 수정하지 않았다.

원시자료가 완전해 등록된 `acceptance.slow_lead`의 같은값을 명시 대응한 `review.py`로 별도 사후계산했다(exit0). `review_report.json`/`review_goal.json`은 원시자료 해시와교정이유를 남기며 새 시뮬이나 원사전등록통과로 간주하지 않는다. 다음 새 측방등록에서는 case별판정연결을 실행전에 확인한다.

사후계산에서 실제 오른쪽0.23m·0.50m/s상대·**나란히10표본/1.010초**가 성립했다. 총9.271m·최고1.555m/s·초록뒤최장0.05m/s미만0.608초·최종FOLLOW, 초록뒤6.730초에 상대 완전통과를 확인했다. 최소표본/스윕간격0.267849/0.267823m, 접촉/겹침/벽바퀴/노면이탈0, STOP/조밀정지/MCU/정상종료·875입력불변·잔여PID0이다. 처음집계한7.89초는신호대기까지포함한값이므로주행정체로쓰지않는다.

사후실행유효성과 기존별도경기목표는 통과했다. 사후 원추종 평가도최종간격/계속앞차뒤에있기 때문에실패이며 이를성공으로바꾸지않는다. 이대표는오른쪽앞차옆을지나는결과이고 빠른뒤차피추월/코너병렬/여러대밀집주행완료는아니다. 다음은새코스최소STOP/START운영연결이다. 피추월과단독증속을후속에남긴다.
