# 정지차 뒤 START 허가 후 우회가 시작되지 않은 이유

[원시 주행](../ops_traffic_resume_v1/PLAN.md)은 같은 경기에서 START가 허가됐지만 1.2 m에 미달했다. [전 구간 평가](../ops_traffic_resume_evidence_v2/README.md)에서 최대 전진 0.220 m, 0.05 m/s 미만 정체 60.35초, 상대와의 최소 표본 간격 0.473 m였다.

고착 중에는 일반 추종이 약 0.15 m/s를 요청해도 우회 준비 여유가 이를 0으로 제한했다. 낮은 이동 전방 조각이 준비된 2,998판단 모두에서 이전 조향 명령은 0.169–0.176 rad였고, 우회 검토 진입선은 0.08 rad였다. 즉 계속 정지했는데도 핸들은 일반 경로 향한 채였고 우회 후보의 경계 확인 자체를 시작하지 못했다. 조향값은 실제 서보 측정각이 아니라 제어기의 직전 명령이다.

원 제어기에서 시뮬 시각 20초 전까지 553호출의 원출력을 재현했다. 독립 4시점 한 호출에서만 각도 제약을 떼도 즉시 진행되지 않았다(서로 다른 경계 스캔 대기). 같은 정지 관측을 연속 공급했을 때 첫 양수 요청은 초기각 검사만 제외한 가정에서 14.42초, 정지 중 3 rad/s로 조향을 중앙 정렬한 가정에서 14.52초였다. 둘 다 우회 후보의 나머지 검사를 통과한 0.35 m/s 요청이다. 후자의 원래 각도 문턱은 바꾸지 않았다. 14.60초에는 -0.0813 m/s 모터축 표본이 있어 이를 임의 0으로 바꾸지 않고 정지 가설을 비교하는 창을 14.00–14.58초로 제한했다. 최초 exact-zero 가정의 실패 스크립트도 보존했다.

이는 열린고리 진단이다. 직접적인 충돌 검사를 풀거나 양수 속도를 강제하지 않고 정지 명령의 핸들만 정렬하는 [선택형 후보](../ops_traffic_centered_entry_v1/PLAN.md)를 실제 주행으로 확인한다. 근거: `probe.py`, `result.json`, `sequential.py`, `sequential_result.json`.
