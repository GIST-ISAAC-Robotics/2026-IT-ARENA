# r16 정지차 우회에 현재 후방 벽 관측 연결

[첫 중앙 정지차 실패](../persistent_block_newcourse_v1/README.md)는1.554m·14.454초정체·미복귀였다. `entry_guide_current_wall_too_short`로 멈췄다. 저장 입력1027판단 완전 동일 뒤 기존 이동차의 후방 벽 근거를 빌린 비교에서598개 명령이 변했고 그중581개가0→양수였다. 최초12.92초에는 주 선분의 뒤 끝이-0.0661m로 후륜축-0.0675m에 못 미쳤지만, 구조 가림75–83광선 반대편에 실제 벽39반환이-0.3920~-0.1048m까지 있었다. 가림 양끝 간격은3.95cm였다. 근거를 못 쓰는 연결 차이이며 실제 탈출 증명은 아니다.

이동차의 `rear_wall_witness`를 `wall_reference_support.py`로 내용 변화 없이 옮겼다(AST 동일 확인). 기존 import는 호환되며 양쪽 실제 점·기존5cm/선분 길이/각도·점 개수 조건, 짧은 조각의 비정적 취급, 원시 점유/가림 보존은 같다. 새 `BypassExecutionConfig.rear_wall_witness`는 기본false다. `--handoff-wall-witness`로 명시 선택하며 현재 raw scan과 구조 가림 정책, tracked wall을 요구한다. G1/G2의 guide 교체에서도 선택을 전달한다. 경로 기준선 보완이고 독립 보호나 관측 밖 통과 허가가 아니다.

실제 비교는 실패했던 동일20초·중앙 정지차·평탄 잔디·B0390·JR60P20·기어비8.970588:1에서 이 옵션만 추가한다. 정적 배우 기하는 같은 시나리오/월드의 `geometry.json`을 재사용한다. 원 판정과 실제 우회→본선복귀→마지막2초0.50m진행·접촉0·두바퀴이하잔디·최소간격0.08m·STOP 판정을 그대로 유지한다. 입력1027의 후보명령만으로 성공 처리하지 않는다. 회귀/실제 연결 재생 뒤 아래 실제1회를 마쳤다.

변경 전8파일 `before.zip`, 출처 `config/tests/stationary_wall_witness_r16_sha256.json`. 기존 이동차749판단도 공유 함수 이동 뒤 그대로 재생한다. 이 대표 교착이 해결되면 정지/재출발·측방 대응과 다른 미완성 기본 기능으로 이어가며 경계 길이 미세 예외만 계속 늘리지 않는다.

관련284회귀 통과, 옵션OFF 정지차1027판단 전체 동일·ON581개0→양수, 공유 함수 이동 뒤 기존 이동차749판단 전체 동일을 확인했다. 연결 재생의 출력 차이는611개이며 동등성 허용오차1e-10을 사용한다(앞선 shadow의 수치 대조는1e-9이므로598과 단순 비교하지 않는다). 같은20초 실제1회의 부분 진전과 남은 교착은 아래와 같다.

## 실제 동일 장면 결과

2패키지 빌드·872개 입력 불변·정상 종료를 확인했다. 초록 뒤12.532초에 정지차를 앞질렀고 최종 차체는 도로 안으로 돌아왔다. 그러나 일반 FOLLOW로 복귀하지 못하고 BYPASS/HOLD로 남아 **전체 우회 기능은 실패**다. 총2.490m, 마지막2초 진행 약0.000017m, 0.05m/s 미만 최장 구간8.389초다. 이 기준은 느린 기어감도 포함하므로 완전한 무이동8.389초라고 해석하지 않는다. 마지막 출력은 다시 `entry_guide_current_wall_too_short`다. 저장 입력을 재현해 실제 벽 범위와 복귀 단계의 차이를 조사한다.

접촉/겹침/벽바퀴0, 최소 표본/연속근사 간격0.127909/0.127908m, 최대2바퀴 잔디다. 명시 STOP·조밀한 정지 검사(최대속도0.001095m/s)·MCU·정상 종료를 통과했다. 원 추종 판정과 경기 목표의 `final_follow`·`no_long_stall`·`post_return_progress` 실패를 보존한다. 앞질렀다는 사실만으로 완주 가능한 우회로 승격하지 않는다.
