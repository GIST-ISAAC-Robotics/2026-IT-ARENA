# 빠른 추월 중단 시 일반 추종 가용성

현재 제어기로 원 r32 명령을 오차 없이 재현한 뒤 같은 입력의 추종 상태기를 별도로 계산했다. 추종 비교도 원 1.2m/s 물체 이동 예산과 B0390/C1 설정을 유지했다. 정답 자세·차량 ID를 쓰지 않았다. 앞서 있다고 확인한 추적점의 벽 접선 방향 상대거리 증가가 최근 0.3~0.5초에 두 거리 오차(6cm)를 넘는 구간을 보았다. 이는 추월이 실패하는 상황을 찾기 위한 진단이며 정답 상대 속도가 아니다.

[원 결과](summary.json)에서 현재 앞차가 보였고 바깥벽과 대조할 수 있던 299판단 중 **자차 정지 명령과 간격 증가가 겹친 170건에서, 경로와 양수 속도가 동시에 나온 일반 FOLLOW는 0건**이었다. 앞차가 보이고 기존 추월 명령이 멈춘 176판단 중 172개에서는 추종 경계가 확정되지 않았다. 양수 1건은 위 조건이 동시에 성립하지 않았다. 정지 직전까지 범위를 넓혀도 6cm 증가와 양수 FOLLOW 경로가 함께 나온 경우가 없었다. 따라서 단순 모드 취소로 복구된다고 보지 않으며 연결하지 않았다. 두 상태기를 항상 동시에 실행하는 비용도 추가하지 않는다.

**다음에 빠른 추월로 돌아오면:** 이미 바깥으로 들어간 뒤 회복시키기보다 진입 당시 선택한 편이가 다음 스캔 동안 유지 가능한지 먼저 비교한다. r32 최초 계획은 중앙에서 34.5cm, r15(0.50m/s 상대)는 24.1cm였다. 진입 때 앞차는 여전히 약1.3m 앞이었다. 서로 다른 프로필/속도라 편이만이 원인이라고 단정하지 않는다. 같은 현재 입력에서 다른 편이·접근 시점의 예측 점유를 대조하고, 추월 대신 추종을 유지할 가치도 비교한다. [측방 전진 후보](../faster_departure_stage_v2/README.md)의 출력은 스캔마다 끊겨 미채택이다. 이 세 미연결 대조 때문에 같은 조건의 Gazebo 빠른 추월을 반복하지 않는다.
