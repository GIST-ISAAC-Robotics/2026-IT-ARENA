# 피추월 속도 손실 재점검

2026-11-08. 저장 센서 판단과 현재 코드 대조이며 새 주행·수정 완료가 아니다. [원 실패](../rear_overtakes_newcourse_v1/README.md)와 당시 소스를 보존한다.

1. 초록 뒤 4.658초 첫 측방 대응에서 측정속도 약 1.545 m/s를 `parallel_lane_trial.proposal`의 옛 `speed <= 1` 조건이 거부해 즉시 0명령을 냈다. 점유를 확인한 충돌 판정과 다른 원인이다. 이후 실제 모터축 속도가 음수로 흔들린 기록도 있다.
2. 입력이 범위 안으로 돌아오면 두 fresh 확인 뒤 평행 경로로 진행하지만 목표는 0.35 m/s다. 측방 이동·점유 검사와 무관한 속도 상한을 곧바로 고속 성능으로 해석하지 않는다.
3. 5.338초에는 앞쪽으로 넘어간 상대의 팽창 점유가 측면 전용 보완 범위 밖에 있어 `overlap_not_only_side_timing`으로 정지했다. 첫 정지를 고쳐도 이 문제까지 해결된다는 뜻은 아니다.
4. 평가 상대는 1.8 m/s인데 50 Hz 명령의 실제 최장 간격은 23 ms다. 최대 위치 오차 41.4 mm는 1.8×0.023과 일치한다. 이는 기록에서 확인한 일치이며 지연 원인 전체를 단정하지 않는다. 후속은 명령 주기를 먼저 개선하고 같은 35 mm 허용치를 유지한다.
5. 상대 중심 편차 225 mm에서 폭 150 mm 두 차가 중앙/측방으로 달리면 여유가 75 mm다. 해당 장면의 80 mm 목표를 일관되게 시험하려면 허용된 두 바퀴 잔디 배치 또는 자차의 관측 기반 위치 조정이 필요하다. 과거 75.5 mm 실패를 성공으로 바꾸지 않는다.

다음은 속도가 명령 상한을 넘는 경우와 비정상 센서 입력을 분리한다. 기존 선택형 `measured_parallel_speed_trial`의 실제 측정속도 기반 제동·관측 검사를 참고하되, 현재 측방 여유 보완과 음수 모터축 전진 정책을 잃지 않아야 한다. 한도를 단순히 높이거나 측정속도를 잘라 해결하지 않는다. 0.35 m/s 상한과 앞쪽 팽창 점유는 별도로 검토한다. 현재 교통 한 랩 실행 중에는 제어기 소스를 변경하지 않았다.

근거: [원시 판단에서 추출한 진단](diagnosis.json), `src/arena_autonomy/arena_autonomy/parallel_lane_trial.py`, `scripts/validate_g1_traffic.py`.


## 오프라인 후보 결과

27개 합성 반례를 통과했다. 기존 기록 376판단/377reset을 현재 r23으로 재생하면 6개 전체 출력 차이(5개 소폭 조향·1개 진단)가 있으므로 원시 기록 완전 일치라고 부르지 않는다. 같은 r23에 제안 함수만 연결한 후보는 비교 기준 대비 **10개 명령만 변경**했으며,첫 5개 invalid_motion와 이어진 5개 재확인 대기를 0.35 m/s 이하 진행 명령으로 바꿨다. 후속 전방 팽창 점유 정지는 그대로다. [대조 요약](comparison_review.json).

명령 상한 초과 속도는 실제 측정값으로 반응·제동 거리와 현재 관측 외곽을 확인한다. 속도를 자르거나 빈 공간을 채우지 않으며 관측 경로 부족·정면 장애물·결측·큰 조향·비정상 입력은 거부한다. 이는 PC 저장 입력/합성 결과이며 실제 주행은 [같은 배치 기준선](../rear_overtake_fixture_v1/README.md)과 연결 후 비교한다.
