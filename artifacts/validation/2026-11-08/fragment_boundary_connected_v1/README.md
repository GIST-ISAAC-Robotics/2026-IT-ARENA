# r30 코너 가림 후보 — 실제 개선 미확인, 미채택

관측된 벽 조각으로 코너 경로를 만들고 이미 승인한 벽의 긴 현재 관측을 이어받는 후보를 같은32초 장면에서 비교했다. 기본OFF이며 실제 활성 교통 설정에 채택하지 않는다.

- 관련 회귀272개 통과. 연결OFF는 원1,618판단과 동일하며 ON은 격리 후보의 모든 기록 행과 동일했다. 저장 입력의0명령은137→28개였다.
- 실제 평가 trace 진행은 **9.84m**, 코너 병렬 **0초**, 최장 저속 **2.418초**였다. 종료평가 창의 진행9.88m와 trace 수치는 구분한다. 코너 출구와 헤딩 조건을 충족하지 못했다.
- 원 r28은10.02m·최장저속1.109초, r29는10.02m·2.418초였다. 원본과 두 후보 모두 실제 코너 병렬0초이며 후보를 성공으로 올리지 않는다.
- 최소 표본/보수 간격은약0.100/0.100m, 접촉·바퀴벽·차체이탈0. STOP6개·정상종료14개, 잔여PID0, 등록890입력불변을 확인했다. 실제 주행은1회이며 벽시계456초였다.
- 원15cm간격/끝까지뒤따름/코너 실패는 `run1/report.json`에 그대로 남겼다. 별도보충평가도 출구/진행/실제병렬 실패다.

## 확인한 원인과 다음 판단

실제 기록에서 `current_retained_wall_refresh`는20판단에 나타났다. 그러나 이후 옆차 가림에 따라 바깥 벽이 짧은 직선으로만 보이면, 앞서 확보했던 코너 경로와 새 경로 표현의 일치가 끊겼다. 32–40초0명령은 경계미확정130회와 큰곡선이동영역 미관측28회 등이었다. 같은 장면을 무변경으로 재실행하거나 평가시간을 늘려 병렬 성공으로 바꾸지 않는다.

코너 병렬은 미해결로 남긴다. 다음 보강 후보는 **현재 반환으로 검증하면서 가림 중 코너 형태를 유지하는 경로/벽 상태 추정**이다. 기억TTL이나 길이 기준을 단순히 낮추는 것으로 끝내지 않는다. 가려진 자유 공간은 여전히 현재 관측으로 별도 검사한다.

이번 후보는 실제 성능 이득이 없으므로 기본OFF로 보존하고, 다음 우선 작업은 더 빠른 추월에 공통으로 걸리는 측정속도 입력 제한이다. 기존 r27의 두앞차 거리5랩·단독r25 결과와 이 코너 병렬 실패를 구분한다. 실패가 남았다는 이유로 기존 완주를 지우지도, 기존 완주로 병렬 실패를 덮지도 않는다.
