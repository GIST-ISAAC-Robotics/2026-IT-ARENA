# 빠른 추월 r32의 남은 벽 여유 분석

2026-11-08. r41 코너 시험 동안 원 r32의 실패 반환과 현재 기하/시차 여유를 분리한다. 미연결 분석이며 제어기·벽/차량 판정선·현재 시뮬 실행 소스는 변경하지 않는다. 기존 빠른 추월 실패와 중속 성공은 보존한다.

## 저장 입력 결과와 결정

기존 r32의 527판단을 먼저 그대로 재현했다. [원점 분해](stop_fragments.json)에서 정체 중 17.0초의 최초 문제점은 왼쪽 벽 적합선에서 0.32mm 떨어진 반환이었고, 실제 차체 내부 반환은 0이었다. 현재 점에 적용한 시차 여유는 약190mm였다. 이전에 관측한 긴 벽의 **실제 점**을 이송하여 일치한 현재 점만 대조했을 때 51개 서로 다른 스캔에서 여유가 바뀔 수 있었다([미연결 관찰](shadow_result.json)). 그러나 [명령까지 고정 입력에서 대조](candidate_result.json)하자 0명령은268→266으로 단 2개(13.12·13.22초)만 줄었다. 새 추월이나 새 궤적은 관측되지 않았다. 이 기억 후보는 주행에 연결하지 않는다.

기존 피추월 코드를 이용해 [측방 비접근 진단](departure_result.json)을 별도로 했다. 실제 앞차가 계속 멀어지던 원 r32의 점유 거절257판단 중, 기존 경로의 두 조향(실제 적용 후보·직전)으로 측방 비접근 검사를 적용했을 때 249개가 해당 사유로 분류됐다. 이 중 50개는 다른 반환 때문에 실제 허용 거리가 0이었고, 52개는 이동 영역 미관측으로 거절됐다. 실제 양수 속도와 이동 영역을 모두 확인한 것은 **147개**다. 문자열 사유만으로 통과를 세지 않았다. 3개는 측방 시차 단독 겹침이 아니었고5개는 정지거리 창 밖이었다. 직전 조향을 임의로 0으로 놓은 표는 원인 분리용이며 명령에 쓰지 않는다. 이는 완전한 제어 판단이나 주행 증명이 아니다.

다음은 빠른 추월을 이미 시작한 상태에서 앞차가 현재에도 **충분히 앞서 있고**, 기존 편이 경로·확인된 바깥벽과 일치하는 측방 반환만 문제일 때 제한 속도로 그 경로를 유지할 수 있는지 보는 것이다. 새로 들어오는 앞·옆 상대, 미관측, 실제 고정 여유 침범에는 기존 거절을 유지한다. 이전 벽 반환을 현재 점유로 되살리지 않고, 기존 움직이는 물체 1.2m/s 팽창 자체도 변경하지 않는다.
