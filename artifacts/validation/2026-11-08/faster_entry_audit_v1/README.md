# 빠른 추월 진입·지속 여유 불일치 (미연결 감사)

저장 입력 [audit.json](audit.json)을 조사했다. 새 주행·제어 변경은 없다. 같은 코드의 최초 진입 선택과 점유 정지 호출을 연결했다.

| 입력 | 첫 편이 | 외벽부터 자차 중심까지 제안 가능한 범위 | 점유 정지 |
|---|---:|---:|---:|
| r32 오른쪽12cm·상대0.70m/s | 344.9mm | 140–180mm | 257 |
| 오른쪽20cm·상대0.70m/s | 306.1mm | 140–258mm | 189 |
| 오목 상대0.50m/s 성공 | 241.5mm | 212–315mm | 0 |

빠른 프로필의 첫 low=140mm는 바깥벽 정적 가정이며 inner high에는 상대 운동 여유가 있다. 반면 실행 중 가림 뒤의 짧은 벽 조각은 여전히 동적 여유를 쓴다. 대표 처음/중간/끝 점유 정지에서 현재 자세의 동적 팽창 겹침은 r32 0/34/30개, 오른쪽20cm 15/31/34개였다. 고정 기계/거리 여유 겹침은 모두0이고 동적 겹침점은 모두 바깥벽 적합선15mm 이내였다. r32 첫 정지의 현재겹침0은 미래 조향 스윕이 원인이 될 수 있음을 뜻하며, 그 한 프레임의 원인은 이 현재자세 검사만으로 확정하지 않는다.

외벽 신원 보증 없이 동적 여유를 지우지 않는다. 다음 사본 비교는 fast 프로필의 최초 편이 제안도 실제 지속 검사의 동적 외벽 여유로 계산하여, 불리한 추월을 시작하지 않았을 때 정상 추종 출력이 남는지 보는 것이다. 성공한 중속 프로필은 기존 계산 그대로이고, 이미 시작한 추월의 위험한 중앙 복귀는 추가하지 않는다. 이는 더 빠른 추월 구현 완료가 아닌, 추월 실패 때문에 정체되는 상황을 줄이는 후보이다.

## 사본 비교 결과

`probe_summary.json`에서 r32 527회·오른쪽20cm 531회는 최초 진입 시점부터 추월 대신 FOLLOW를 유지했다. 각각 최초 양수 목표는1.15m/s였다. 오목 중속753회는 기존 명령과 같았다. 이후 입력 자세는 원래 실패 궤적이므로 이 재생으로 실제 정체 개선을 단정하지 않는다. 후속 연결·검증은 [r44](../faster_entry_consistency_r44_v1/README.md)에 남긴다.
