# r45 코너 진행 중 경계 전환 감사

2026-11-08. [r45 실행](../corner_occlusion_connected_r45_v1/README.md)의 진행10.01 m·최장저속0.703초는 이전보다 개선됐으나 실제 코너 병렬/출구는 실패했다. 같은 실행을 반복하지 않고 저장 입력을 분석한다.

[capture.py](capture.py)로 현재 코드의 **1,644명령을 원 기록과 동일하게 재현**했다. 32초 이후426호출·86스캔에서 현재 경계와 유효한 직전 경로, 라이다 원점/방향/반환만 캡처했다. 소스 해시는 전후 동일하며 [summary.json](summary.json)에 보존했다.

현재 가림 증거는36.62초까지 두 면 경로를 갱신했다. 36.72초 갱신이 실패해 기억을 쓰고36.82초에 유효기간이 끝났다. 이후37.22초 현재 오른쪽 경로를 재획득했으나37.52초 다시 갱신이 끊겼다.37.62–38.10초 정지 뒤38.12초 다시 경로가 성립했다. 경계 상실과 재획득의 전환 문제이며 측방 접근량 제한은 이번 실행의 주요 정지 원인이 아니다.

후속 비교는 [path_compare.py](path_compare.py)로 현재 관측 경로의 길이/앵커와 직전 경로의 공통 구간을 대조한다. 경로 가용성의 원인만 분리하고 속도·TTL·점유·독립 보호를 변경하지 않는다. 새 실행이나 병렬 성공으로 해석하지 않는다.

## 현재 경로 길이와 일치 구간

[path_comparison.json](path_comparison.json)의8시점44후보를 비교했다.36.52–36.82초 현재 오른쪽 `piecewise_corner`는 관측 길이1.380–1.424 m·앵커오차6–12 mm로 충분했으나 기존x구간 비교가 실패했고, 동일허용오차의 공통 호길이 비교는 통과했다. 같은x위치에 놓인 코너출구의 다른길이까지 묶는 영향이다.37.52초 오른쪽 원경로 부재는 별도이며 이 비교만으로 모두 해결되었다고 하지 않는다.

첫 분석 스크립트는 JSON결과를 저장한 뒤 콘솔요약의NumPy bool 직렬화에서 종료코드1이었다. 저장결과는 정상JSON으로 직접확인했으며 이출력오류를 제어기/주행실패로 분류하지 않는다. [현재긴벽 유지 분기 사본](../retained_corner_agreement_probe_v1/README.md)에서 기존호길이비교를 해당선택형직각분기에만 적용해 연속명령을 비교한다. 다른경로/기본OFF/짧은공통구간 반례를 유지한다.
