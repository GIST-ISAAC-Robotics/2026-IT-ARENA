# r41 현재 두 면으로 코너 경로 지지

2026-11-08. [사전 계획](PLAN.md)과 [미연결 분석](../corner_path_support_probe_v1/README.md)을 따라 기존 기본OFF 교통 경계 후보에만 적용했다. r40 운영 대표는 마쳤다.

새8검사와 기존 r30 입력1,640개에서 사본 명령·적용 명령이 모두 같음을 확인했다. 함수와 보조 파일의 바이트도 사본과 같다.13개 현재 스캔 판단에서 두 면 지지를 채택했다. 저장 입력의36.04초 이후에는 다시 경계 가용성 문제가 남고,39.8초에는 큰 이동 영역 미관측이 남았다. 후보가 이 모든 문제를 해결했다고 보지 않는다. 원 점유/광선/TTL/독립 보호는 그대로다.

관련402검사·실제import29항목·원 시나리오 정적기하를 확인한 뒤 동일32초 장면1회를 실행했다. **진행9.10m·코너 병렬0초·출구/방향 전환 미달로 실패**했다. 출발 뒤 최장 저속3.126초, 최소 표본/보간 간격 약100.0mm, 접촉0·바퀴 이탈0이다. 80mm 보조 간격은 통과했지만 원15cm 판정의 실패를 유지한다. STOP·정상 종료와921등록입력/스냅샷 불변을 확인했다. 자기 시험 프로세스는 남지 않았다.

[평가](assessment_run1.json)·[입력 무결성](postflight_integrity_run1.json)·[연결된 판단 재검토](review_support.json)를 보존한다. 주 에이전트가 원 판단에서 직접 확인한 두 면 지지 채택은15판단이며 최초34.42초 실제 출력은1.0m/s다. 즉 후보가 호출되지 않아서 실패한 것은 아니다. 경계 지지 개선만으로 실제 코너 병렬을 성립시키지 못했다. `driving_authorized=false`는 보조 기하 판정 자체의 제한이고 최종 출력이 없었다는 뜻이 아니다.

후보는 기본OFF를 유지한다. 동일 실패를 반복하지 않고 최신 Jetson 재생 패키지의 누락을 정비한 뒤, 빠른 추월의 현재 반환점/과거 관측 일치 비교와 남은 코너 원인을 별도로 검토한다. 이전r28–30과 이번 실패는 성공으로 소급하지 않는다. `run.sh`는 자체 등록하므로 별도register를 하지 않는다.
