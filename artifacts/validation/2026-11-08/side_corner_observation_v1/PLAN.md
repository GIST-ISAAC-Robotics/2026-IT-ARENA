# 코너 외벽의 차량 가림 분석

r28/r29 6개 현재 센서 프레임에서 옆차가 바깥 벽 중간을 가려 연결 성분이 끊겼다. 현재 근거리 벽과 가림 뒤 직선/코너가 실제 반환으로 남은 경우의 경로 가설을 비교한다. `fragment_candidate.py`는 현재 실제 점만 사용해 근거리 직선·같은 선의 전방 관측·그 사이 가까운 물체 반환을 대조한다. 경로 기하를 만들 뿐 가려진 공간에 자유/센서 점을 추가하지 않는다.

현재는 산출물 안의 미연결 후보다. 두 조각이 다른 선인 경우, 가림 물체 근거가 없는 공백, 근거리 앵커 없음, 실제 코너/필요한 면이 짧은 경우를 반례로 검사한다. 후보가 성립해도 현재 점유·관측 검사를 그대로 통과해야 하며 실제 주행 성공으로 보지 않는다. 새 컨트롤러 연결 전에 원 r28 저장입력 비교와 현재 경로 선택의 인계 조건을 따로 확인한다.

## 현재 재개점

저장센서6프레임은 observed_walls.png/summary.json으로 복원했다. 후보v1/v2는 모두 미성립이었다. 진단상 실제 근거리 벽 성분에 옆차 끝점이 붙어있어 일부 점이 최대11cm 벗어났으며, 합성v3에서도 같은 문제가 드러났다. 각소스ZIP/실패를 보존했다.

v4는 우세한 근거리 직선을 재적합하고 **경로 기하용 입력만** 그선으로 투영한다. raw scene/점유는 그대로다. 합성6검사 통과, 실제6프레임 중 초반가림2개에서경로가설이 성립했다(gap 약0.654/0.589m, 앵커0.027/0.035m). 나머지는기존현재벽 경로가 이미 있거나 후보미성립이다. `fragment_walls_v4.png`/`fragment_summary_v4.json`과`fragment_v4_source.zip`이 근거다.

현재 `replay_fragment.py fragment_off|fragment_on`을 실행 중이다. r29소스ZIP에서 임시트리에 autonomy를 추출하고 `candidate_local_follow.py`만 바꾼 **격리된 저장입력 비교**다. 후보는 관측된 조각 경로+이미승인한 반대쪽 벽의 긴현재관측 갱신을 비교하고 r29의짧은선호벽갱신은 사용하지 않는다. production에는연결하지않았다. OFF동일/ON변화·반례를확인한뒤에만 실제연결여부를판단한다. 현재 교통은r27, production의r29기본OFF·미채택 상태이며 새Gazebo는 미실행이다.
