# 새 코스 최소 STOP/START 운영 — 기본 흐름 확인·정지 유지 판정 실패

실제 RGB 출발→새 출발 직선 약1m 진행→HTTP STOP→0.5초 대기→RESET 없이 START1회→1.2m이상 진행→STOP/0.5초 대기를 확인한다. 현재 G1/새 직각/재획득/B0390/JR60P20·1.5m/s 프로필이다. 브라우저를 띄우지 않고 같은 HTTP API를 쓴다.

기존 `race_ops_eval.py`의 HTTP·입력경계·MCU·정지·종료를 재사용하는 이 폴더 전용 평가다. 등록 전용 wrapper에서 새 코스 시나리오와 짧은 동작을 선택하며 원 평가기/프로덕션 기본값을 바꾸지 않는다. 이전 코스 재배치 좌표와 마커 운반/복원 시나리오를 복사하지 않는다. 최초 출발 전 START 거절 확인은 기존 동작대로 남긴다.

새로운 통과 근거는 시작/재개허가3초 이내·같은경기·RESET없음·1.2m전진·두 STOP의밀집자세0.05m/s이하/0.49초이상·도로내차체표본·원시소스/정상종료다. 공용망·실제MCU·Jetson·다중차량재개·재배치·접촉이벤트 검증이 아니다. 소스/설정/원시결과를 등록하고 한 번 실행한다. 실제시뮬보다 긴wall-timeout은 평가기용이며 운행허가시간은 바꾸지 않는다.

## 실제1회 결과

등록/실행/평가스크립트exit0이지만 **등록목표전체는실패**다. 실제RGB출발·준비전정지·RESET없는같은경기START1회·두번STOP이성립했다. 재개허가0.396초,이후1.201m전진,세션/경기epoch유지,B0390설정일치,도로내차체표본·872입력불변·정상종료exit0/0·잔여프로세스0이다.

실패는 두0.502초정지관측창의조밀속도다. 드리프트5.46/5.41mm,최대표본간격3ms,피크0.06345/0.06453m/s여서0.05m/s기준을넘었다. 기존운영도구의 `stopped()`는최근30자세평균속도0.02m/s미만을사용하므로이번조밀최대값과같은판정이아니다. MCU `stationary_ready=false`도보존한다. 실제완전정지로과장하거나기준을올려통과시키지않는다.

기본STOP/START흐름은연결됐으므로 미세정착구간만계속반복하지않고 단독증속의편측제동/접촉진단으로전환한다. 이후 운영보강에서는 현재STOP의정착시간/조밀속도·모터축정지준비를먼저대조하고 교통/재배치/공용망/실물도남긴다. 원평가와원시증거를보존한다.
