# 첫 코너 병렬 실패의 저장 입력 진단

원 r28은32초10.02m·출구까지0.46m 미달·실제 코너 병렬0초였다. 원시 실패와 source snapshot은 `../side_corner_live_v1/`에 보존했다.

- `replay.py base`:1,618판단·382reset, 원출력 불일치0. 입력 SHA-256 `db3f586a0e368e6e51f9d87e9f5f42e639d7aaa9ba54fe609c42f7ee2e6d13e2` 전후 동일.
- 33.52초 선호 벽의 현재 관측 길이0.635m는0.65m 기준에 못 미쳤다. 앵커 오차는0.00773m였다. 최근 경로가 만료된 후 경계 미확정 대기가 생겼다. 해당 구간 전방 관측은 `fully_observed`이며 근접 충돌이 주 정지 원인은 아니다.
- 기존 단독 `boundary_bridge`를 켠 첫 비교는 구성 검증에서 거절됐다(`replay_bridge.log`,exit1). 단독 모드나 검증을 우회하지 않았다.
- 별도 기본OFF `traffic_boundary_refresh_trial`은 기존의 **현재 짧은 벽과 최근 경로 일치 갱신**만 교통에 연결한다. 단독 bridge의 벽 선택 변경/운동량 예외/재개 대기 예외는 포함하지 않는다.
- `compare_refresh.py off`:1,618판단 모두 원출력 일치. `refresh`:전체 결과101개·실제 속도/조향60개 변경. 33–40초351판단의0속도 출력137→87개. 첫 변경33.52초는 조향만 달랐고,34.42초는0→0.35m/s였다. 입력 해시는 동일했다.

이후35.52–36.42초의 경계 미확정과39.02초의 비직선 기준 경로 대기는 남는다. 저장 입력에서 명령이 늘었다고 실제 병렬 통과로 해석하지 않는다. [r29 선택형 연결과 같은32초 주행](../traffic_boundary_refresh_v1/PLAN.md)으로 확인한다. `refresh_comparison.json`·각 replay 결과/rows/log가 근거다.
