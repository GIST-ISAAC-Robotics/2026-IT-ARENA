# r21 이후 다음 코너의 기존 재획득 옵션 대조

저장 입력 0–48초의 2,019판단·380 reset을 재생했다. 기본 출력 전체가 일치했고, standing_wall_reacquire=True의 출력 변화는 없었다. 43.82–48초 정지 구간의 210판단에서도 양수 명령은 0회였다. 원본 SHA-256은 재생 전후 같고 실행 종료값은 0이다.

traffic_lap_budget_v1은 이전 10.90 m 정지를 통과하고 18.86 m에서 다시 멈췄다. 이번 선호 벽 후보는 약 2.22 m여서 이전의 짧은 선호 벽 사례와 다르다. 옵션만으로 해결되지 않으므로 probe.py에서 후보 채택·기억·앵커 조건을 계측한다. 새 제어 로직이나 임계값 변경, 실제 재실행은 아직 없다.

근거는 replay_result.json·replay_rows.jsonl·replay_v1.log·replay_v1.exit.txt다. reset 순서와 모든 교통 구성을 유지했다. 저장 입력 대조이며 실제 주행/재출발 증명이 아니다.

## 계측으로 확인한 거부 원인

21개 새 스캔의 분기 계측에서도 기존 재획득 옵션은 적용되지 않았다. 선호 벽은 길지만 43.72초의 벽 y좌표0.669 m, 정지 뒤 약0.698 m가 명목0.505 m에서12 cm보다 멀어 sufficient()가 거부했다. 옵션은 이 충분조건을 통과한 후보에만 적용된다.

그러나 실제 경로 최근접 거리는 43.42/43.72/44.12/47.92초에 각각0.0128/0.0118/0.0155/0.0171 m였다. 네 시점 모두 좌우 경로의 기존 형상 일치 판정이 true다. 직각 코너를 원호로 도는 중에는 벽 y좌표가 명목 직선 오프셋과 다르므로, 이 좌표 차이를 경로 이탈로 쓰면 잘못 거부한다. 현재 r22는 경로 선분과 원점 사이 실제 최소거리로 코너의 위치 확인만 바꾸는 방향이며 검사 수치나 장애물 여유를 낮추는 작업이 아니다.

[원시 반환과 경로](anchor_geometry.png), geometry.json, probe_result.json이 근거다. geometry_v1은 numpy.bool_ JSON 직렬화 단계에서 실패했고 그림만 남았다. bool 직렬화 수정 후 geometry_v2가 종료값0으로 완료했다. 이전 실패 로그는 보존했다.
