# 실제 인코딩 크기와 직렬 링크 예산

- [실행](run_checks.sh): 전체 **3,570회귀 통과**, 실제 종료 0·소스 불변.
- [결과](export/report.json): 운영 ROS 콜백을 노드 생성 없이 호출한 3시각 표본(부팅 근처·100초·24시간), 32자 식별자. 최대 offer 673 B / DRIVE 봉투 260 B. STOP 서비스 봉투 형태 103 B, 미구현 compact offer 투영 238 B.
- 8N1·전이중·각 50 Hz에서 현재 형식은 115200/230400 baud의 MCU→호스트 방향이 포화다. 460800/921600은 표본 기준 용량 미만이다. 각 방향을 합산해 전이중을 반이중처럼 계산하지 않았다.
- MCU 내부 제어/엔코더 취득 빈도 축소, baud/전송 형식 변경, USB/실물 연결은 하지 않았다. 표본 크기는 모든 필드의 최악 상한이 아니며 다른 센서·ACK·로그·USB 스케줄·큐·처리 지연도 제외했다.

해석은 [구동 계약 §11](../../../../docs/hardware/ACTUATION_CONTRACT_2026_09_22.md#11-1021-후속--현재-인코딩의-직렬-링크-예산)을 따른다.
