# C1·D435i 선택형 단독 주행 검증

현재 상태: **두 구성 모두 한 바퀴+약 2 m 주행·실제 정지·3인칭 촬영 완료.**
C1은 전체 검사를 통과했습니다. 스테레오 완주 실행은 깊이 전달률과 Gazebo 종료가
실패했으므로 `report.json`의 종합 `passed: false`를 유지합니다.

## 스테레오 완주 실행에 남은 실패

1. **깊이 전달률**: 검사 노드에서 받은 깊이 영상은 평균 23.97496 sim Hz였습니다.
   명목 30 Hz·848×480·`32FC1`·내부 파라미터는 확인했지만 개발용 전달률 기준
   25~33 Hz를 통과하지 못했습니다. 최대 수신 간격은 0.198 sim초, 자율주행
   `SENSOR_STOP` 표본은 0개입니다. 이를 실물 D435i의 FPS 한계로 해석하지 않습니다.
   성공으로 만들기 위해 임계값을 낮추지 않았습니다.
2. **Gazebo 종료**: 실제 차량 정지를 확인한 뒤 ROS 노드들은 정상 종료했으나
   Gazebo가 SIGINT 5초·SIGTERM 10초 내 끝나지 않아 SIGKILL로 종료됐습니다.
   부모 반환 코드 0만 보고 정상 종료라고 판단하지 않습니다. 정확한 내부 대기 원인은
   미확정입니다. 녹화 없는 짧은 실행을 별도로 비교하며 이 완주 원문을 덮어쓰지 않습니다.

같은 소스의 녹화 없는 2.0598 m 시험에서는 수신률 27.56176 Hz와 자식 18개
정상 종료를 확인했습니다. 두 조건은 녹화 유무뿐 아니라 실행 길이도 다릅니다.
녹화만이 원인이라고 단정하거나, 짧은 실행으로 장시간의 문제가 해결됐다고
해석하지 않습니다. 남은 진단은 영상 렌더·ROS 전송·검사 노드 부하와 Gazebo
종료 대기의 분리입니다. 주최 측 트랙 오류로 보고한 사항이 아닙니다.

스테레오의 활성 주행 표본은 130.065 sim초였습니다. 상태 중복을 제거한 524개 중
520개는 RGB-D 목표점 추종, 4개는 저속 깊이 복구였습니다. C1보다 느린 것은 이
두 제어기의 감속 정책까지 함께 달라진 결과이므로 센서 제품의 처리 속도 순위가 아닙니다.

## 조건과 해석 경계

- 공식 `v2026.09.02` 기반 팀 파생 월드, 단독 차량, `brisk` 최고 명령 0.70 m/s,
  빨강 1초·노랑 2초·초록 유지의 시험 순서, 독립 ToF 보호층 활성화.
- C1: 10 Hz snapshot LiDAR+ToF6와 RGB 신호/마커. 스테레오: 명목 30 Hz
  D435i급 RGB-D+측면 ToF4. 제어기는 지도·정답 위치·관찰 카메라를 읽지 않습니다.
- 카메라·LiDAR는 이상화된 Gazebo 센서입니다. 실물 스테레오 매칭·노출·결측·
  RGB-깊이 정렬, LiDAR 순차 회전 왜곡은 구현하지 않았습니다.
- 두 비교 모델은 2.000 kg입니다. 스테레오는 제거 센서 0.111 kg을 차체에
  보충하므로 질량 중심·관성까지 같지는 않습니다. 녹화 센서는 별도 1 mg입니다.
  C1 원 보고서의 `same 2.000 kg dynamics` 문구는 **같은 총질량**으로 한정하여
  읽습니다. 후속 검사기에서 표현을 바로잡았고 과거 원문은 덮어쓰지 않았습니다.
- C1 실행 뒤 달라진 파일은 검사기의 기록 보강, 차량 Xacro의 1 mg 설명 주석,
  실행 파일의 스테레오 내부 파라미터 전달, 스테레오 전용 조향입니다.
  C1 제어·구동·트랙은 바뀌지 않았습니다. 정확한 이전/현재 해시는 종료·소스
  재감사에 남겼으며 새 스테레오 성공을 과거 실패 소스에 소급하지 않습니다.
- 조향 알고리즘도 다르므로 구매 제품의 우열이나 공정한 센서 성능 순위가 아닙니다.
  약 2~3 km/h 수준의 단독 데모이며 20 km/h, 다중 차량·추월·가림·실차 안전을
  검증하지 않았습니다. 벽 겹침 0개는 노면 경계 준수와 같지 않습니다.
- 영상 20 FPS는 시뮬레이션 프레임의 재생 기준입니다. PC 실시간 연산 성능과
  다릅니다. 보고서의 실제 지면 속도와 시뮬레이션 시간을 함께 봅니다.
  영상은 출발 허가 이후의 주행 구간입니다. 빨강/노랑 대기와 종료 직전의 별도
  지속 정지 검사는 영상 전체에 포함되지 않으므로 보고서·상태 기록으로 확인합니다.

## 재현

### 소스·형식 회귀 검사

- Python/ROS: 160개 통과 (`tests`와 `src/arena_vehicle_interface/test`).
- C++: `single_motor_equations` 1개 통과. ROS 패키지 5개 빌드 통과.
- 두 선택형 차량 SDF: 센서·관절·관성의 엄격 형식 검사 모두 `Valid`.
- 공식 생성물: 29개 출력의 해시 일치. 초기 원본 ZIP·압축 해제 파일 23개와
  실험 트랙의 보존·정적 형상 검사 통과.
- 처음 전체 검사의 1개 실패는 센서 설정 변경 후 공식 생성 이력의 입력 해시
  누락이었습니다. 별도 생성 결과와 기존 29개 출력이 동일함을 확인한 뒤
  `provenance.json` 입력 해시 한 줄만 갱신했습니다. 실제 트랙 출력은 미변경입니다.

### 실제 주행

WSL에서 빌드·ROS 환경을 준비한 뒤 모드별로 **새 출력 폴더**를 지정합니다.

```bash
python3 scripts/validate_basic_autonomy.py --autonomy-mode lidar --speed-profile brisk --laps 1 --red-duration-s 1 --video --output artifacts/tests/lidar_comparison_new
python3 scripts/validate_basic_autonomy.py --autonomy-mode stereo --speed-profile brisk --laps 1 --red-duration-s 1 --video --output artifacts/tests/stereo_comparison_new
```

구현·권한은 [결정 0015](../../../../docs/decisions/0015-selectable-lidar-stereo-autonomy-prototypes.md),
전체 활동은 [9월 4일 기록](../../../../docs/activity/2026-09-04.md)을 확인합니다.
개인 임시 제안·팀 미협의 상태입니다. 최초 작업은 로컬 보관으로 마쳤고,
2026-09-04 후속 승인에 따라 팀 GitHub `main`의
[`23b7076`](https://github.com/GIST-ISAAC-Robotics/2026-IT-ARENA/commit/23b70767e5498394d80d9f0f6b717d6a4cce90ea)에
소스·영상·실패 기록을 함께 게시했습니다. 원격 확인은 위 활동 기록에 남겼으며,
컴퓨터 종료·upstream 게시는 수행하지 않았습니다.

## 다음 작업 권고

장시간 영상 수신률·종료 문제의 분리 진단과 저속 반복 검증을 우선합니다.
그다음 정지 차량 → 느린 앞차 → 측면 접근·끼어들기 순서로 확장하고,
노면 이탈·미관측 공간·제동거리 판정을 보강합니다. RGB-D 목표점 방식은 현재
회색 도로·녹색 잔디·평지 가정이므로 실물 정렬·노출·상대차 가림 확인이 필요합니다.
기존 궤적·상태 기록과 후속 센서 재생용 기록을 활용하고, 긴 완주 녹화는 최종
확인에 한정하는 편을 권고합니다. 새 기능의 구현이나 팀 구매 결정은 아닙니다.
