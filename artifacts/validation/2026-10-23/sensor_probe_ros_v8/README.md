# 낮은 발행 빈도 대조 — 실패 유지와 전달 경계 분리

0.2 s 회차 대기·2 s drain에서 20개씩 보낸 Image는 **10개**, 나머지 네 토픽은 각각 20개 기록했다. 관련 120회귀가 통과했지만 ROS 전체는 실패다. 소스 불변·정상 종료·내부 기록 무결성 통과와 전송 무손실을 구분한다. v7보다 수신 개수가 적으므로 단순 발행 빈도/마지막 대기 부족 해결로 해석하지 않는다.

`transmissions.json`의 송신 크기/해시와 수신을 분리하여 다음을 확인했다.

- Image 누락 index: **0, 1, 6, 7, 10, 11, 12, 13, 15, 16**. 수신된 10개의 픽셀·padding은 기대값과 같고 송신 CDR 해시와도 일치한다.
- CameraInfo의 20개 digest 불일치는 **333 B 송신 prefix 전체는 동일하고 뒤에 0 바이트 3개가 추가된 336 B**라는 차이였다. 기록기가 잘못 저장한 것이 아니라 ROS 송수신 경계의 별도 변화다.
- 그 경계는 기록기 없는 단일 프로세스/별도 프로세스 각 1표본으로 분리했다. 전자는 333→333 B 그대로, 후자는 333→336 B·원래 prefix/모든 메시지 필드 동일이었다. [직접 대조](../camera_info_wire_v2/report.json).
- `sensor_probe_delivery.py`의 18회귀 뒤 저장 자료를 재검사했다. 정확한 prefix 해시/길이를 보존하면서 4 B 끝 정렬에 해당하는 최대 3개 0만 별도 표시했다. 이 설명 아래 예상하지 못한 내용 변경은 0개지만 Image 누락 10개는 여전히 실패다. 원래 실패 보고서를 덮어쓰지 않았다.

`delivery_diagnostic.json`·`timing.json`은 읽기 전용 후속 진단이다. 원시 bag/receipt는 그대로이며 callback 이후 CDR 무결성 검사는 어떤 padding도 삭제하지 않는다. 송신 raw 파일·생산자 시각·실제 장치 취득/성능을 확인한 결과는 아니다. 같은 큰 영상 기록을 성공할 때까지 반복하지 않고 기록기 없는 전송 대조로 원인을 한정한다.
