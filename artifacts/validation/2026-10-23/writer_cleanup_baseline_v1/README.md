# writer 정리 재호출·추가 오류 — 수정 전 재현

검사 스크립트 exit 1, 소스 불변. 실제 MCAP writer를 감싼 래퍼가 실제 close를 먼저 수행한 뒤 오류를 주입했다. 정상 160표본은 한 번 종료·exit 0·CDR 감사 통과다.

- close 오류: 기록기가 close를 두 번 호출했고 두 번째 `RuntimeError`가 처리되지 않은 writer 스레드 예외로 남았다.
- write 오류 뒤 close 오류: 세 표본을 보존했으나 manifest에는 쓰기 오류만 남고 종료 오류는 스레드 traceback에만 남았다.
- 두 고장 모두 기존에도 `complete=false`·exit 1·감사 거절이었다. 정상 완료로 오인한 문제는 아니며 정리 호출과 오류 원인 보존의 결함이다.

실제 디스크/전원/장치 고장 재현이 아니며 원본 소스·기록·결과를 보존한다.
