# 720p 포함 5개 센서 입력 기록 — 첫 ROS 시험 실패

선행 형식 회귀는 120개 통과했고 ROS 실행/정상 종료·내부 기록 무결성은 통과했다. 그러나 20회 발행 중 camera Image는 **17개**, 다른 네 토픽은 각각 20개여서 전체 시험은 **실패**다. 내부 큐 drop/error는 0, `complete=true`지만 이것은 상류 무손실을 뜻하지 않는다. 소스/실패 판정/원시 기록을 보존했다.

저장 입력만 읽은 `inspect_camera.py` 결과, 빠진 fixture index는 **0, 1, 19**이고 수신된 17영상의 픽셀 전체/행 padding·해상도는 기대값과 일치했다. 첫/끝 누락이라는 사실만으로 정확한 전달 단계나 원인을 확정하지 않는다. 송신 전 digest 목록 자체를 이 판본은 저장하지 않았으므로 수신 CDR의 송신 bytes별 차이를 사후 완전히 복원할 수 없다.

조건은 1280×720 RGB/BGR 교대·일부 행 padding 16 B, 5토픽마다 합성 20회, 회차 뒤 spin 대기 0.05 s·마지막 drain 0.25 s, localhost BEST_EFFORT depth 30이다. 고정 FPS/60 Hz 시험이 아니며 실제 카메라/Jetson/차량 시험이 아니다. 모터축 28카운트·15:1·65 mm를 명시한 하나의 JointState만 썼다.

후속은 송신 digest/시각을 남기고 0.2 s 대기·2 s drain의 별도 **저속 형식 확인**을 한다. 기존 기록기 QoS/한도를 늘리거나 이 실패를 성공으로 덮지 않는다. 추가 무손실 성공이 있어도 이 조건의 누락 원인이 해결됐다는 뜻은 아니다.
