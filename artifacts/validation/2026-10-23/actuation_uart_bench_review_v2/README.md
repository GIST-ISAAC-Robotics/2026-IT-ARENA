# UART 주기 어댑터 최종 검토 수정 v2 — 결함 재현·관련 회귀·변이

검사 exit 0, 실행 전후 소스 해시 차이 0 B다. [v1](../actuation_uart_bench_review_v1/README.md) 뒤 공유 가짜 I/O 재생성을 임시 객체 대입에서 제자리 재생성으로 바꾸고 빌드 스크립트에 큰 정적 프레임 거절을 더한 최종 소스다([v3 대상 빌드 발견](../actuation_uart_bench_idf_v3/README.md)).

## 고친 계약 불일치(최종 검토 지적)

1. **사건 큐 포화 관측 순서:** 이전 판본은 사건을 먼저 꺼낸 뒤 `pending >= capacity`를 봤다. 진입 때 정상 DATA로 가득 찬 큐(용량 16)에서 8개를 꺼내면 8로 내려가 직전 확인 이후의 유실 가능성을 놓쳤다. 수정본은 꺼내기 전 진입 검사와 꺼낸 뒤 종료 검사를 모두 한다. 소비자가 이 작업 하나뿐이면 직전 확인 이후 포화는 다음 진입 때까지 유지되지만, 두 검사 사이 가득 찼다가 우리가 꺼내 내려간 순간 포화는 볼 수 없다(사례 31로 한계 고정).
2. **사건 예산:** `max_events_per_cycle`이 확인 호출마다 다시 채워져 한 주기에 여러 배를 처리했다. 수정본은 주기 전체 예산이다. 바이트를 꺼내기 전 사건을 모두 확인하지 못하면 읽지 않고, 새 읽기에는 `post_read_event_reserve`가 남아 있어야 한다. 읽은 뒤 오류나 미확인 사건이 남으면 그 조각은 연결부에 넣지 않고 세션을 끊는다. 한 주기 경계는 한 번이며 두 번째 오류는 다음 주기 시작으로 미룬다.
3. **주기 실행시간:** 이전 판본은 마지막 시각 읽기를 재사용해 송신·입력 폐기·단절 시간을 빠뜨렸다. 수정본은 마지막 작업 뒤 시각을 다시 읽어 `end_us`/`max_cycle_us`를 구하고, 이 읽기의 역행도 시계 고장으로 고정한다. 수신 버퍼 시각(`last_rx_buffered_us`)과 분리했고 `cycle_budget_us` 초과·제어 간격 초과 주기를 따로 센다. `cycle_budget_us`는 새 읽기 시작 상한이며 주기 마감 보장이 아니다.
4. 대상 앱은 합성 자기 검사가 하나라도 실패하면 계획이 준비돼도 외부 I/O를 시작하지 않는다.

## 결과

- 결함 재현: 결함 판본 헤더(SHA-256 `4f5fb2ec…`)에서 6건 모두 실패(exit 1) — 진입 포화 놓침·호출별 예산·예산 뒤 오류 꼬리 전달·미확인 조각 전달·마지막 작업 시간 누락·종료 시각 역행 미검출. 수정본에서 0건(exit 0). [결함 판본](repro_defect.log), [수정본](repro_fixed.log).
- 관련 회귀 **9개 통과**(공유 사례 32개 ASan/UBSan·`-Os`, 결함 재현기, 정적 경계 검사, smoke 공유 사례 2개).
- 변이 **22/22** 검출, 정상 대조 통과. 주기 전체 예산·진입/종료 포화 검사·읽기 뒤 확인·미확인 조각·예약분·미룬 경계·종료 시각을 각각 제거한 변이를 포함한다.

전체 4,128회귀는 반복하지 않았다. 바뀐 파일은 이번 묶음에서 새로 만든 어댑터·검사 앱·스크립트·검사뿐이며 기존 모듈이 이를 포함하지 않는다. 실행은 Claude Haiku 5.5 보조(브리지 기록상 nested subagent `claude-haiku-5-5`), 원시 결과 대조는 Claude Opus 5.5가 맡았다. 실제 UART/보드 실행이 아니다.

**2차 검토(같은 날):** 이 소스에는 빈 큐 응답 뒤 마지막 조회에서 보인 사건을 Clean으로 처리하는 경쟁이 남아 있었다. 위 결과는 이 소스에 대한 것이며, 수정본은 [v4](../actuation_uart_bench_review_v4/README.md)를 따른다.
