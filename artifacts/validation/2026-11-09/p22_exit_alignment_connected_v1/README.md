# r51 출구 정렬 연결 — 실제 주행 전 중단

사용자의 작업 종료 요청으로 **구현·기본 검사·저장 입력 비교까지만 완료**했다. 새 Gazebo는 실행하지 않았다. 이 후보의 입출구 통과나 본선 복귀 성공은 미확인이다.

[r50 원 실패](../p22_route_connected_v1/README.md)는 입구 통과 뒤 통로 한쪽으로 치우쳐3.563초 저속·본선복귀실패였다. 현재 관측 통로 중심과 이송 경로 말단의 차이는 약49mm였다. r51은 현재 경로의 시작 위치/접선을 유지하며 말단을 관측 중심으로 부드럽게 정렬하고, 그 뒤에 출구 회전을 연장한다. 미래 경로의 .37rad 조향각·3rad/s 변화율을 확인한다. 기본OFF·점유/관측/독립보호·STOP·물성은 유지했다.

## 재개 순서

1. `registered.json`과 현재 입력 SHA256을 대조한다. 현재 기본값과 `--p22-entry-trial --p22-route-trial` 명시 선택을 확인한다.
2. 기존 bash ROS 환경에서 필요한 빌드/import를 확인하고 [등록 명령](registered.json)으로 **동일 단독1회**를 실행한다. `run_live.py`는1회만 허용한다.
3. `evaluate_live.py`로 실제 입구/출구 통과, 본선 인계 후 실제1m, 노면/접촉/최장저속·STOP/종료·무결성을 대조한다. 수용조건은 [PLAN](PLAN.md)을 따른다.
4. 실패하면 원인을 남기고 무변경 반복하지 않는다. 성립하면 같은 물리 단면의 본선 저장시간과 비교한 뒤 지름길 채택 여부를 검토한다. r11/r25 기준은 각각6.334/5.279초이며 독립1회끼리의 비교다. 기본 자동활성화·교통합류·전체랩 이득은 별도다.

빠른앞차 추월·코너 지속병렬·속도유지·공용망/실물/최신Jetson 과제는 그대로 남는다. 이 선택형 지름길을 완벽하게 만들기 위해 필수 기능을 뒤로 밀지 않는다.
