# P22 저장 관측 비교 — 사전 등록 (2026-11-09)

분석 전용 묶음이다. 새 Gazebo 실행·연결·생산 코드 수정·실물 접근은 하지 않는다. 이 문서는 관측기 코드를 저장 입력에 처음 적용하기 전에 작성했으며, 실행 뒤 기준을 바꾸면 최초 결과와 변경 근거를 함께 남긴다.

## 1. 질문

저장된 같은 계열의 본선 한 랩 두 개(r11 단독 빠른 본선, r27 교통 느린 본선)의 C1 순차·운동보정 관측만으로 P22 진입(본선 남행 중 오른쪽 90° 분기)을 다른 장소와 구별되는 특징으로 식별할 수 있는가. 특히 ID20이 보인 직후 먼저 오는 C4(왼쪽 코너)와 혼동되는가. 감지 가능성 판정이며 조향·제어 설계가 아니다.

## 2. 입력

| 실행 | 경로 | 비고 |
|---|---|---|
| r11 | `artifacts/validation/2026-11-07/junction_handoff_v1/run1/` | 단독 본선, P22 부근 약 2.5 m/s |
| r27 | `artifacts/validation/2026-11-08/traffic_faster_reacquire_live_v1/two_actor_course_lap/run1/` | 앞차 2대, 약 0.5–0.8 m/s |

관측 단계는 각 실행의 `follow_decisions.jsonl` 호출 입력만 읽는다(`restore_call` → `motion_scene`, 기존 P21 분석과 같은 경로). 같은 스캔 시각이 반복되면 첫 호출만 쓴다. 평가 단계에서만 `trace.json`, `ego_poses.jsonl`, `runtime_world.sdf`, `scene.json`, 교통 상대 자세를 읽는다. 모든 입력의 SHA256을 실행 전후로 기록하고 불변을 확인한다.

## 3. 실제 월드 확인(사전, 평가용 근거)

공식 파생 월드 벽 상자(두께 0.05 m)로 본 P22 입구 부근:

- 본선 남행(x=6.14) 오른쪽 벽면 x=5.635는 C4 바깥에서 y=4.80까지 이어지고(E1), 그 뒤 y=4.80–4.20의 0.60 m가 비어 있다(지름길 폭 0.20+양쪽 잔디 0.20).
- 간극 너머 남쪽은 닫힌 정사각 섬(x 4.84–5.61, y 3.53–4.175)이며, 섬 동쪽 면 x=5.635가 y=4.20(E2)부터 다시 이어진다.
- 입구 북측 지름길 벽(y=4.80 남쪽 면)은 접근하는 차량에서 보이지 않는 방향이다. 접근 중 간극으로 보이는 직각 면은 **섬 북면(y=4.20)** 이며 E2에서 섬 동쪽 면과 볼록 모서리로 이어진다. 따라서 "오른쪽 직선 벽 A가 직각 벽과 바로 연결된다"는 가정은 접근 관측에서는 성립하지 않으며, 등록 특징은 **같은 직선 위의 벽 끊김(간극)과 간극 너머 실제 반환**으로 정한다.
- 같은 형태의 오른쪽 간극이 P22 출구(본선 북행 x=4.31의 오른쪽 벽 x=4.815, y 4.20–4.80)에도 있다. 이는 실제 분기 구조이지만 진입 지점이 아니다.

## 4. 관측기(센서 전용, `observe.py`)

차체 기준(base_link, 기준 시각) 좌표 x 전방·y 왼쪽. `status=='return'` 광선만 점으로 쓰고 `unknown/masked`는 연속성을 끊으며 **간극 근거로 세지 않는다(No hit=free 금지)**. 지도·진행량·마커·정답 자세·시간·절대 위치·순번을 쓰지 않는다.

1. 선분: 광선 번호가 연속인 반환점을 이웃 간격 ≤ max(0.08 m, 3·r·Δθ)로 묶고, 현 기준 최대 편차 0.02 m 초과 시 재귀 분할한다. 점 ≥5·길이 ≥0.15 m·SVD 최대 잔차 ≤0.02 m만 선분으로 쓴다.
2. 평행 측벽 A: 진행방향 대비 |각| ≤20°, 해당 쪽 횡거리 0.20–1.20 m, 하류 끝 E1의 x ∈ [−0.10, 3.00] m.
3. 깊이 근거: 반환 광선(원점→반환점)이 A의 직선을 따라 좌표 구간 안에서 가로지르고, 반환점이 직선 너머(차량 반대쪽)로 ≥0.25 m 떨어진 경우만 센다.
4. **끝남 T(일반 측벽 끝)**: A의 E1 뒤 (E1+0.03, E1+0.80] 구간에서 깊이 근거 광선 ≥3.
5. **간극 N(등록 주 특징, P22형)**: T이면서 A와 같은 직선 위의 다른 평행 선분 C(각 차 ≤8°, C 양 끝의 A 직선 거리 ≤0.05 m, C 길이 ≥0.15 m)가 있고, C의 상류 시작 E2까지 간극 g=E2−E1 ∈ [0.40, 0.85] m, 간극 내부 (E1+0.03, E2−0.03)의 깊이 근거 광선 ≥3.
6. 정보용: 간극 너머 직각 면 B′(진행방향 대비 70–110°, A 직선 너머 0.05–1.2 m, 간극 구간 안), 간극을 지나는 무반환 광선 수(근거 아님).

양쪽(오른쪽/왼쪽) 모두 같은 기준으로 계산한다. 주 판정은 오른쪽 N이며 왼쪽 결과는 혼동 비교에만 쓴다.

## 5. 평가(사후, `evaluate.py`)

- 기준 시각의 차량 자세는 `ego_poses.jsonl`을 시간 보간한다(평가 전용). 선분 끝점을 월드로 옮겨 실제 벽 상자 꼭짓점과 대조한다. 대조 허용 0.15 m.
- 이름 붙인 실제 구조: P22 입구(E1 (5.635,4.80), E2 (5.635,4.20)), P22 출구, 그 밖은 중심선 코너 Cn(중심선에서 자동 번호, C4≈s 17.55 확인)·직선.
- 구간: 본선 s 기준 C4 접근 [16.55, 17.55), C4 통과 [17.55, 17.85), P22 접근 [17.85, 18.68] (E1 통과 전), P22 옆 (18.68, 19.36].
- 각 스캔의 E1/입구 중심까지 남은 전방 거리(참 자세 차체 좌표)와 그 시점 속도로 나눈 남은 시간.
- ID20: r11은 저장 상태의 서로 다른 원 영상 시각(`vision.last_result.stamp`)과 상태 시각, r27은 원 영상 시각이 저장되지 않아 상태 시각만 쓴다(제한으로 명시).
- r27 교통 상대 자세로 차량에 의한 선분/가림 여부를 표시한다.

## 6. 결과 의미(사전 정의)

| 판정 | 조건 |
|---|---|
| **판별 가능** | E1 통과 전, P22 입구에 대응하는 오른쪽 N이 연속 ≥2스캔, 그리고 랩 전체에서 실제 간극이 아닌 곳의 오른쪽 N 0, C4 구간 오른쪽 N 0 |
| **부분** | 대응 N이 있으나 1스캔뿐이거나, 실제 간극 아닌 곳 오검출/C4 구간 검출이 있음 |
| **판별 불가** | E1 통과 전 대응 N 없음 |

- P22 출구 간극의 N은 오검출로 세지 않되, 센서만으로 입구와 구별되지 않는 **유사 후보**로 따로 보고한다.
- 일반 오른쪽 끝남 T는 코너(C3·C5·C6 등)에서도 생길 것으로 예상한다. T만으로 입구를 구별할 수 있는지 장소별로 집계한다.
- 남은 거리/시간은 보고값이며, 정적 회전 기하를 다시 계산하지 않는다. 진입 준비 충분성은 [기존 감사](../../../../docs/track/OFFICIAL_V2026_11_06_AUDIT.md)의 결론(반경 0.35 m·사전 치우침)을 인용만 한다.
- 두 실행은 속도 외에 교통·경로가 달라 속도 단일변수 비교가 아니다. 한 랩씩의 사례이며 검출률/오검출률이 아니다.
