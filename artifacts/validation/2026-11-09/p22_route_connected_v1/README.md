# r50 P22 출구 연결 1회 — 본선 복귀 실패

GPT가 입출구 경로와 연결·평가를 구현했고 GPT-6 Luna가 재생·빌드·주행·결과 회수를 수행했다. Claude Opus 5.5의 부분 검토는 5시간 한도 경고로 중단됐으며 [검토](review.md)·[후속 처리](review_resolution.md)를 구분했다. 기본 실행은 본선 유지이며 새 후보는 `--p22-entry-trial --p22-route-trial` 명시 단독 시뮬 옵션이다.

## 구현과 사전 확인

현재 센서로 찾은 출구를 두 스캔에서 측정 운동에 맞춰 비교했다. 입구 회전이 남아 있을 때 즉시 바꾸지 않으며, 출구 말기 두 스캔에서 본선 주행기의 현재 경로를 확인한 뒤 복귀하도록 연결했다. schema7은 r49 입구만 시험(schema6)과 구분한다. 자동reset 이후 영상 재전달과 명시reset의 force 값을 기록에 남겼다. `/drive → 독립 보호 → /drive/safe`, STOP·물성·센서는 유지했다.

- r49 833판단·출구 전 명령 불일치0, 첫 출구 후보23.42초/.65m/s([재생](replay_summary.json)).
- 관련 최종42검사, 직전 전체 출처계약147검사와 실행직전 최신r50계약검사 통과([검사](../../2026-11-07/track_migration_v1/checks/pytest_p22_route_final_1.log), [출처](chain_final.log)). 서로 겹치는 검사를 합산하지 않는다.
- 두 패키지 빌드는 완료됐으나 래퍼가 존재하지 않는 별도 `p22_route_trial` 실행점을 찾으며 exit1이었다. 실제 연결은 `p22_entry_trial` 실행점+route파라미터다. 재빌드 없이 [실행점/import v2](check_entrypoint_v2.log)를 확인했고 원 실패를 보존했다.

## 실패 원인과 다음 비교

본선 전환을 검토할 만큼 출구 회전까지 가지 못했다. 출구 경로 선택 뒤23.966초의 실제 차체는 y=4.435, 서향에서 약4° 비껴 있었다. 새 경로가 남아 있던 입구 정렬 경로를 버리고 당시 차체 방향으로 직선을 만들면서, 통로 한쪽으로 치우친 상태를 계속 유지했다. 24.3초의 점유 경로 여유는0.12m, 24.8초에는0.04m로 줄어 제동명령이 나왔다. 실제 접촉 전 감속했으며 이를 단순한 보호 임계값 문제로 처리하지 않는다.

다음은 [입구 경로를 보존한 출구 연장](../p22_exit_continuity_v1/probe.py)을 저장 입력에서 비교한다. 원 입구 경로의 말단 위치·방향이 현재 관측된 통로 중심과 맞을 때만 뒤에 출구 회전을 덧붙이는 후보이며, 아직 새 주행 결과가 아니다. 같은 실패의 무변경 재실행·시험시간 연장으로 통과시키지 않는다. 전체 지름길·시간 이득·교통 합류는 미완료다.
