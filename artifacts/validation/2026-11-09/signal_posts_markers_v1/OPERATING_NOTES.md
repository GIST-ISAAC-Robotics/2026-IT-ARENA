# 11/9 시설 포함 시험의 실행 기준

- **현재 사용자 확인:** 신호등 양쪽·갈림길 마커 지주 설치. P22 지름길 개발 제외, P21만 후속 검토한다. P22 앞 본선과 ID20 누락 대응은 유지한다.
- **시설 형상:** 신호등은 제작측 STL의15×14.62mm 지주·40×50×10mm 발판을 사용하고 도로61cm에 맞춰 중심간격745mm로 둔다. 이 간격은 임시 환산이다. 마커 지주는 같은 단면을 빌린 **별도 임시 모델**이다. 마커 지주 규격이 공개된 것으로 쓰지 않는다.
- **마커 배치:** 원본 마커 판은 모두 그대로 둔다. ID20은 코너 위여서 판 직하에 두 지주를 놓으면 남쪽이 도로를 막는다. 시험 지지틀은 접근 방향372.5mm 앞 잔디에 두고 위에서 받친다. ID30은 판 양옆 잔디에 둔다. 실제 제작 설계로 채택한 것은 아니다.
- **현재 실행 선택:** `signal_posts:=stl_61cm_provisional`; 마커는 `evaluation_actor_sdf:=.../marker_posts_provisional.sdf`. 두 옵션은 시뮬 월드에만 적용하며 제어 입력에 시설 좌표를 전달하지 않는다. 범용 기본값은 과거 재현용 `none`을 유지한다.
- **단독 재현:** `e_run.py`는 r25속도 프리셋·좁은 가림체 연결·갈림길 본선 연속 후보를 켜고 `blank_20_30`을 평가 주입한다. 기존 성공 출력에 덮어쓰지 않는다. 다음 새 시험은 목적에 맞는 새 결과 경로와 인자를 기록한다.
- **교통 통합 시 주의:** `validate_g1_traffic.py`는 이미 `evaluation_actor_sdf`를 상대차용으로 쓴다. 두 SDF 경로를 같은 launch 인자로 중복 전달하지 말고, 기존 상대차 모델과 마커 지주 모델을 한 평가용 SDF로 합친다. 상대차 일정·접촉 플러그인은 보존하고, 새 지주도 평가 장애물에 포함한다.
- **평가:** 원시 report, source snapshot, 실제 `runtime_world.sdf`, 센서 입력과 STOP/정상종료를 보존한다. 지주·발판 간격은 낮은 발판의 높이를 구분한2D평가이며 물리 연속충돌 증명이 아니다. 실패한 원 결과를 후속 성공으로 덮지 않는다.

**정리 시점과 다음:** 단독/마커 누락 B·D·E와 정지차 우회·복귀·신호 시설 통과 r59/C5의 제한 대표를 마치고 사용자 요청으로 중단했다. C5 원 추종 평가는 실패이며 기존 별도 경기 목표와 시설 통과 평가를 통과했다. 현재 시험 프로세스는 없다. 다음에는 준비만 한 `traffic_posts_run.py/sh`의 두 앞차·전체 지주·마커 누락 통합 대표를 확인한 뒤, 남은 지속 코너 병렬·빠른 추월·고속 유지·P21 시간 이득·실물 이관으로 돌아간다. 지주 치수 전수조사나 같은 단독 랩 반복은 우선하지 않는다. P22 개발은 제외한다.
