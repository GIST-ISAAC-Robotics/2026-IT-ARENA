# r525 큰 벽 굴곡·실제 접합 공백·중심 이동 대표 민감도

2026-11-14. **현재 r518+r521 코드에서 아래 세 변형 대표는 모두 기존 추월 정지0에서 현재 경로 재획득0.10m/s로 연결됐다. 같은 최대 변형에 실제 전방 장애물을 추가하면0을 유지했다.** 이번5조건에서 뚜렷한 잔여 정체나 기존 양수 명령 손실은 발견하지 못했다. 새로운 공통 수정은 없다.

## 범위와 결과

모든 길이·굴곡·이동량은 현장 실측이 아닌 가정이다. 재료5T를 진폭으로 사용하지 않았다. `tests/test_current_wall_reacquire.py`의 ray 교차 생성기를 재사용하고, 벽 polyline 생성 부분만 stage에서 확장했다. 파장1.0m, 두 벽이 같은 방향·같은 굴곡으로 움직이며 벽 간 폭은 기존 r521 fixture의1.01m다. 차량·컨트롤러의 형상/설정은 원 fixture 그대로다.

| 대표 | 굴곡 진폭 | 접합 공백 폭 | 벽 중심 이동 | r521 연결 전 MOVING_PASS | 현재 MOVING_PASS | UNKNOWN |
|---|---:|---:|---:|---:|---:|---:|
| 직선 기준 | 0 | 0 | 0 | 0.900m/s | 0.900m/s | 0 |

기존 양수인 직선 기준의 속도·조향·상세 판단은 완전히 동일하다. 변형1–3의 기존 정지 사유는 `entry_guide_current_outer_wall_unavailable`이며 현재 출력은 `moving_pass_current_wall_reacquire_trial`이다. 160mm 벽 이동에서 helper가 사용하는 현재 경로의 앵커 오차는136.261mm로 기존120mm보다 크지만, 과거 앵커 일치를 요구하지 않고 실제 현재 점유·조향·제동을 검사하여 진행한다.

LocalFollow의 별도 직접 baseline fixture에서도 변형1–3은 `follow_boundary_unconfirmed`0→0.10m/s, 장애물 조건은0→0이었다. 이 fixture는 과거 입력을0.4/0.5/0.6s에 넣고1.1s의 현재 입력을 호출하는 메모리 만료 조건이며, 직선 기준도0→0.10m/s였다. **이를 실제 정상 직선 주행이0으로 정지한다는 근거로 쓰지 않는다.** 기존 양수 보존의 직접 비교 근거는 위 MOVING_PASS0.9m/s다.

## 정지와 점유의 구분

- 변형1/2: 현재 조향0.3rad에서 swept 여유0.600m, 직전 조향0rad에서0.880m. 현재 관측 벽 예산0.65m로 생성한 경로를 사용한다.
- 변형3: 현재 조향0.3rad에서0.640m, 직전 조향에서0.880m. 원하는 조향0.457844rad는 기존 조향 변화율 제한으로0.3rad가 되며, 두 각도를 모두 검사했다.
- 실제 전방 장애물: 현재 경로 자체는 생성된다. 그러나 현재 조향과 직전 조향의 swept 여유가 **둘 다0m**, 제동 허용속도0m/s이므로 helper가 후보를 반환하지 않고 기존 정지를 유지한다. 경로/기억 불일치만으로 정지하는 경우와 직접 점유 정지가 구분된다.

## 원 ray·UNKNOWN·원시 점유 보존

벽 연결부는 x=0.40/1.00m 두 곳에 정확한 구간 경계를 넣고 해당 구간의 벽 선분을 기하에서 제거했다. 폭20/50mm는 벽을 따라 잰 호길이가 아니라 x축 투영 폭이다. 5mm 간격의 연속 사인 polyline과 ray의 가장 가까운 교차를 계산했다. iid 잡음이나 임의 거리 변경이 아니다.

각 조건은500개의 동일 원 광선 방향·시간 간격을 유지한다. 실제 벽 구간이 없으면 다른 면/장애물과의 가장 가까운 교차를 그대로 쓰며, 교차가 없을 때만 원 생성기와 같이unknown이다. 관측 후 unknown을return/free로 바꾸거나 장애물 반환을 삭제하지 않았다. 컨트롤러에는 벽·장애물 label이나 정답 기하를 전달하지 않았다.

모든 계산 전후 scene/ranges가 동일하며500ray가 보존됨을 assert했다. 저장 `*_ranges.json`에 광선 거리·metadata, `report.json`에unknown 원 인덱스와 점유/경로/제동 진단을 남겼다. 장애물 때문에 가려진 틈의 UNKNOWN 개수가 줄어드는 것은 가장 가까운 실제 반환이 생긴 결과다.

## 실행 환경과 한계

- Windows Python3.14·NumPy2.5.4. NumPy2D `cross`는 **이 시험 프로세스 안에서만** 기존2D 행렬식으로 호환했다. 기존 r518 전용 pytest 의존성 경로를 읽었고 새 환경 설치는 없다. native 확장은 사용하지 않았다.
- 공통 소스는 별도 snapshot으로 복사했고 r518 `bypass_wall_fit.py`·r521 `current_wall_reacquire.py`의 원본 불변을 확인했다. 수정 범위는 이 r525 산출물 폴더뿐이다. WSL·ROS·Jetson·실물 출력 접근0.
- 다섯 조건은 전체 조합이나 임계값 탐색이 아니다. 단일 시점의 현재 벽과 저장된 과거 직선벽을 비교하며 차량의 폐루프 이동, 벽이 접촉으로 밀리는 동역학, 재획득 후 정상속도 복귀를 증명하지 않는다.
- 양쪽 벽을 같은 양만큼 평행 이동한 조건이므로 **한쪽 벽만 안으로 밀려 통로가 좁아지는 경우**, 임의 코너·서로 다른 위상의 굴곡·얇은 판의 두께/기울어짐·실물 반사 특성까지 검증한 결과가 아니다. 실제 r520 주행과 현장 검증을 대신하지 않는다.
