# r535 현장 패널 계약 확인

현재 속도 상한·수동 단발·STOP/START·신호 확인 출발·센서 미리보기는 각 기존 API에 연결되어 있습니다. 새로 확인한 결함은 **재연결 뒤 이전 접속의 미리보기 영상/설정이 새 화면에 표시되는 문제**이며, 화면 코드만 고친 stage를 검토한 뒤 root 승인으로 공통에 통합했습니다. 제어·서버 라우트 코드는 변경하지 않았습니다.

## 기능별 현재 근거

| 기능 | 현재 연결과 확인 범위 |
|---|---|
| 속도 상한 m/s·km/h | `race_ops_page.py:144`의 서버 적용값·편집값 분리, 두 단위 상호 변환, `/api/command set_speed_limit` 또는 별도 수동 모드 `/api/manual set_speed_limit`. 상한 설정만으로 ARM/출발하지 않습니다. 정지·MCU 비ARM 조건은 기존 정책에서 검사합니다. 기본 상한은 현재 차량 설정의 최대값이며 실측 속도 상한 보증이 아닙니다. |
| 시간·거리·조향 수동 단발 | `race_ops_page.py:55`, `race_ops_manual.py:46`에서 m/s·km/h, 0.05–2 s, 중앙 등가 바퀴각을 입력합니다. 단발 유효 상한은 `min(0.2, 서버 상한)` m/s이고 입력 초과는 거절합니다. **거리는 v×t 예상값만 표시하며, 거리 입력이나 엔코더 거리 도달 정지는 없습니다.** +각은 좌회전, −각은 우회전이고 서보축 각도가 아닙니다. |
| STOP → START, RESET 생략 | `/api/command resume_start`는 현재 `resume_start_ready`를 사용합니다. `recovery_ready=False`여도 일반 명시 STOP 후 준비 가능하면 별도 RESET 없이 접수됩니다. START 수락과 최종 주행 허가는 별개이며 이 기존 동작을 순수 계약 검사로 확인했습니다. |
| 최초 신호 대기에서 명시 출발 | 실제 상태 이름은 `WAIT_GREEN`입니다. `race_ops_core.py:171`은 아직 출발하지 않았고 latch/resume이 없는 해당 상태에서만 버튼/API를 허용합니다. `race_session.py:444`도 실제 노드 확인 함수를 다시 검사하며, 수동 신호 확인은 출발 사실만 설정합니다. MCU·현재 센서·경로·보호 조건을 우회하는 강제 구동은 아닙니다. |
| 재연결 중 전역 STOP | 화면의 상태가 없어 `/api/command stop`으로 보내져도 `race_ops_node.py:305`에서 `manual.stop`·준비 취소·기존 MCU STOP을 요청합니다. 실제 `execute`와 가짜 단발 자식으로 취소 연결을 확인했습니다. |
| 선택형 LiDAR·카메라 | `/api/preview` 설정 → 기존 ROS 토픽 구독 → `/api/state` 메타데이터·점군과 `/api/preview.jpg`입니다. 기본 OFF, LiDAR 최대720점·5 Hz, JPEG 가로640 px·2 Hz, 종류별 최신 대기1개, 마지막 설정 탭 조회가3초 끊기면 구독/캐시 해제입니다. view 토큰도 보기 설정은 가능하지만 구동 명령은 거절합니다. 실제 Jetson 동시부하는 미측정입니다. |

자율 구성은 수동 버튼을 비활성화합니다. 수동 시험은 자율 제어기를 정상 종료하고 guard·host가 있는 기존 별도 `operation_mode:=manual` 구성을 사용해야 합니다. 패널이 센서나 카메라 장치를 직접 열거나 실행하지 않습니다.

## 확인된 표시 결함과 stage

원본 화면은 일반 상태 조회와 구동 명령 응답에는 연결 식별을 적용하지만, 미리보기 설정 응답/JPEG 응답에는 적용하지 않았습니다. 재연결 때 이미 표시된 영상·점군도 지우지 않았습니다. 다음 세 경우가 실제 페이지 script의 DOM/HTTP 모형에서 실패했습니다.

1. 새 접속의 OFF 상태 뒤에 이전 접속의 ON 설정 응답이 도착하면 ON 표시로 덮습니다.
2. 새 접속의 미리보기가 켜진 뒤 이전 접속 JPEG가 도착하면 이전 영상을 표시합니다.
3. 새 접속을 시작했지만 아직 상태가 오기 전, 이전 영상·점군이 남습니다.

`race_ops_page.stage.py`는 요청 때의 `auth` 객체를 캡처해 응답·오류 표시 직전에 같은 연결인지 검사하고, 재연결 시 표시 캐시를 지웁니다. 구동 정책·API·기본 수동 속도·sensor 주기·lease는 바꾸지 않았습니다. `preview_connection.patch`가 이 변경만 포함합니다. 추가 timeout이나 서버 상태기계는 넣지 않았습니다.

- 원본: 새 세 대표 **0/3 통과**. 실패 원문은 `dom_results.json`에 보존했습니다.
- stage: 기존8개+새3개 DOM 계약 **11/11 통과**.
- 실제 Handler·코어·가짜 MCU 연결 및 관련 기존 대표 검사: **13개 통과, 0.38 s**. `contract_checks.xml`에 보존했습니다.
- 원본 SHA-256: `a4a30d4ee8100c6184e0f5bcace2209bbf54de0bae62dd27f773ad266cab0560`.
- stage SHA-256: `72f69b43c280d60c48f39a22e33e790d589938454333f860caa77b18d0bed3d1`.

root 승인 후 baseline SHA가 일치함을 확인하고 `race_ops_page.py`와 기존 `operator_panel_page_checks.js`·`test_operator_panel_page.py`에만 이관했습니다. 기존 내용은 보존하고 세 반례를 추가했습니다. 실제 공통 대상 **11개 통과, 1.11 s**이며 `common_transfer/regression.xml`에 보존했습니다. `git diff --check`도 통과했습니다. 정확한 통합 직전/직후 파일·SHA·패치는 `common_transfer/`에 있습니다.

원본·stage 모두 엄격한 UTF-8 디코딩을 통과했고 대체문자 U+FFFD가 없습니다. `<script>` 앞 기존 정적 HTML은 UTF-8 바이트가 완전히 동일하며 대표 한글 레이블의 Unicode 코드포인트도 일치합니다. 확인된 원파일 인코딩 손상은 없으므로 콘솔 표시 문제 때문에 재인코딩하지 않았습니다.

`previewImageBusy`는 재연결 때 강제로 풀지 않습니다. 이전 JPEG가 진행 중이면 새 JPEG를 중복 요청하지 않고, 이전 요청의 `finally`에서 해제한 다음 새 토큰의 조회가 재개되는 것도 같은 회귀에서 확인했습니다. 기존 fetch에는 별도 timeout이 없어 네트워크 무응답의 대기 길이를 짧다고 보장하지는 않습니다. 이번 범위에서는 timeout/중복 요청 정책을 추가하지 않았습니다.

## 현장에서 누를 순서

1. 실행 중인 패널 주소에 접속해 차량 이름·토큰을 입력하고 현재 차량/MCU 상태를 확인합니다. HTML 파일 자체를 여는 것은 운영 서버 접속을 대신하지 않습니다.
2. 정지·MCU 비ARM 상태에서 m/s 또는 km/h 상한을 입력하고 **상한 적용**을 누릅니다. **서버 적용 상한**이 바뀌었는지 확인합니다.
3. 자율 최초 출발은 **출발 준비** 후 영상 신호를 기다립니다. 운영자가 신호를 확인해 대신 출발 사실을 넣는 경우에만 `WAIT_GREEN`에서 **신호 확인 후 수동 출발**을 누릅니다. 일반 잠깐 정지는 **STOP → 재개 START**이며 RESET은 필수가 아닙니다.
4. 별도 수동 구성에서는 초기 지상 시험 계획에 맞게 목표를 **0.05 m/s(0.18 km/h)**로 직접 바꿉니다. 페이지의 기존 기본 입력은0.15 m/s로 남아 있습니다. 예를 들어0.5 s·0°이면 화면 예상거리는0.025 m입니다. **수동 준비 → 입력값으로 실행 → STOP/종료 상태 확인** 순서이며, 다음 단발에는 다시 준비합니다. 현재 범위에서 실제 시험은 실행하지 않았습니다.
5. 보기만 필요하면 해당 센서 체크·실제 토픽/형식 입력 후 **미리보기 적용**을 누릅니다. 현재 runtime의 예시는 native `/hardware_runtime/c1/native`, RGB `/hardware_runtime/camera/image_raw`이며 실제 실행 설정을 따릅니다. 마치면 **모두 끄기**를 누릅니다. 입력이 없으면 대기/OFF로 표시되며 센서 준비를 자동으로 대신하지 않습니다.

## 검증 경계

Windows 메모리 HTTP 요청·DOM 모형·가짜 MCU만 사용했습니다. HTTP 서버나 listening port를 만들지 않았으므로 기존 패널 포트와 충돌하지 않았습니다. PID 회수 대상도 없습니다. ROS 발행·물리 장치 명령·WSL·Jetson 접속은0회입니다. 실제 브라우저 레이아웃/영상 렌더, 실센서 거리·시각, 구동 방향·각도·거리·정지, 공유망 지연·실행 부하는 이번 증거에 포함되지 않습니다.

저장 before/stage 비교 재현은 `run_dom_checks.py`, 통합된 공통 검사는 `tests/test_operator_panel_page.py`입니다. `prepare_stage.py`·`integrate_common.py`는 원 baseline SHA에서만 동작하며 이미 통합된 소스에 다시 실행하지 않습니다. `test_field_routes.py`는 기존 `tests`를 PYTHONPATH에 둔 Windows pytest로 실행합니다. 이미 확인한 기능을 새로 구현하거나 넓은 회귀를 반복하지 않았습니다. 세 공통 파일의 소유권은 root에 반환했습니다.
