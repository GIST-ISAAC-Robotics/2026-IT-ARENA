# r531 원시 입력으로 재구성한 guard 비교

2026-11-14. r520 실패 당시 원시 scan과 제어 기록의 운동 표본을 사용했다. 원시 배열의 `+inf`, 자기 가림, 취득 시각과 좌표 변환을 보존한다. 센서·평가 actor 정답을 추가하지 않았다.

## 범위

실제 guard callback 수신 시각과 내부 최초 기억 전체가 기록되지는 않았다. 따라서 6.007–9.007 sim초를 20ms 간격으로 **재구성**했고, 각 시점 이하 취득 표본만 사용했다. 실제 도착 순서를 복원한 기록 재생이나 폐루프 주행이 아니다. 7.72초 이후의 0.5m/s·0.3rad 명령은 후보를 비교하기 위한 가정이며, 자차 운동은 원 실패의 정지 기록이다. MotionHistory의 stream 객체를 유지해 콜백마다 인위적 reset이 발생하지 않도록 했다.

| 같은 151회 입력 | 양수 요청 65회 중 출력 양수 | 상한 | 최대 활성 기억 |
|---|---:|---:|---:|
| 공통 기존 guard | 0 | 0 | 별도 계산 없음 |
| 동결 r528 stage | 65 | 0.1m/s | 138점 |
| 동결 r532 stage | 65 | 34회 0.1, 이후31회 0.5m/s | 89점 |

원시 전방 경로가 남아 있어도 `known_obstacle_latched`가 계속 0을 만드는 점을 재현했다. r528은 해당 원 기억을 유지하면서 현재 명령의 외곽·제동을 검사해 저속을 허용했다. 다만 활성 기억 138점이 남아 정상 속도로 복귀하지 않았으므로, 실제 유한 광선이 옛 위치를 다시 통과한 근거를 반영하는 r532 후속을 같은 입력에서 비교한다.

초기 baseline의 첫 래치 시각은 재구성 7.507초이고, 원 수신 trace의 첫 래치는 7.607초다. **동일 callback 시각 재현으로 주장하지 않는다.** 초기 raw 형식 오류와 잘못된 rear 마스크로 인한 projection 불일치 실행도 별도 로그로 보존했다. 이 실패를 실제 guard 결함이나 통과로 세지 않는다.

실행: `run_extended.sh`, 입력/계산: `stage_replay.py`, 결과: `baseline_extended/summary.json`, `r528_extended/summary.json`. 실제 코스 검증은 후속 r530에서 별도로 수행한다.

후속 r532는 실제 유한 광선의 옛 위치 통과를 확인해 활성 계산만 현재 raw 검사로 인계했다. 65개 양수 요청을 모두 보존했고 후반31개에서 가정 요청0.5m/s로 복귀했다. 원 기억·래치·UNKNOWN은 보존했다. 같은 정지 자차 입력의 반사실 비교이며 실제 주행 효과는 후속 r530 결과로 판단한다. `r532_extended/summary.json`과 `run_r532.sh`를 추가 근거로 사용한다.
