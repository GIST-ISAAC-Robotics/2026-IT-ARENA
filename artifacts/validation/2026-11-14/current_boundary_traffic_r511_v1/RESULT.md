# r511 교통 중 LocalFollow 경계 미확정 원인

2026-11-14. 결론: **r503에서 단독 경로가 사라지는 주원인은 벽 반환 소실이 아니라 추월 횡이동 뒤 기본 경로와 차량 사이의 앵커 거리 초과다.** 기존 LocalFollow를 병렬 관측시킨 뒤 그대로 복귀시키는 것만으로는 정체를 해결하지 못한다. r513은 주 담당자가 별도로 확인한 moving-pass 뒤쪽 기준 범위 문제와 이 LocalFollow 재획득 문제가 구분된다.

## 현재 입력으로 확인한 원인

같은 저장 scan의 점별 취득시각·엔코더/gyro 이력으로 현재 좌표 반환을 복원했다. 지도·Gazebo 위치/자세·심판 상태는 사용하지 않았다. `local_path`의 실제 반환 경로에 `anchor_error`를 적용했다. 현재 설정은 벽 오프셋0.505m, 현재 경계 길이 하한0.65m, 앵커 오차 상한0.12m, 경로 기억0.3s다. 앵커 오차는 차량 원점에서 생성 경로 선분까지 거리이며 장애물 여유가 아니다.

r503/110에는 반대쪽도 길이1.04373m, 앵커0.213521m다. r503/179에는 양쪽이 모두1.8m지만 앵커가 각각0.213607/0.213608m다. 양쪽에서 동일한 중심 경로를 보는데 차량이 그 경로에서 벗어난 상태다. 측정 속도0이어도 `standing_wall_reacquire`는 `sufficient(candidate, info)`를 다시 요구하므로 자동 해소되지 않는다. 확인 횟수나 UNKNOWN을 더 허용해서 해결하는 문제가 아니다.

코드 연결은 `local_follow.py`의 `sufficient`(길이+앵커) → 현재 경로 채택 실패 → 기억 만료 → `follow_boundary_unconfirmed`이며, 저속 재획득도 같은 `sufficient`에 의존한다. `local_path.py`는 관측 경로를 생성하고 `path_anchor_error_m`를 제공한다. 현재 공통 local_follow의 r498 최적화 등 다른 변경은 그대로 보존했다.

## 앵커만 바꾸면 해결되는지 분리

`probe_follow.py`에서 r503 seq84–120의37입력에 현재 LocalFollow를 독립 실행했다. baseline의 **속도·조향·reason 37/37이 r510 대안과 일치**했다. r510의 원 계획125/125 전체 출력 일치 기록은 그대로 유지했다. 이번37비교를 전체 상세 출력 일치로 확대하지 않는다.

같은 입력에서 앵커 상한만0.25m로 바꾼 원인 분리용 객체는 seq95–97에 각각0.30/0.25/0.25m/s를 냈다. 현재 경계 채택이 앵커 때문에 막혔다는 근거다. 그러나 seq98에서 sweep 여유0.08m, seq99 이후0m로 다시 정지했고 `parallel_hold_lateral_motion_not_small`/`parallel_hold_baseline_unavailable`로 이어졌다. **0.25m는 진단값이며 채택한 설정이나 권고값이 아니다.** 고정된 기존 궤적의 저장 입력을 대입한 결과이므로 실제로 일찍 추종 전환했을 때의 움직임도 증명하지 않는다.

## 최소 대안과 우선순위

1. **현재 주 담당자의 moving-pass 관측 경로 유지 수정이 우선이다.** 이미 현재 반환으로 긴 경로가 생성되는 동안 이동을 이어가고, 기본 중심 경로로 기하학적으로 돌아온 뒤 기존 LocalFollow에 인계하는 방식이다. r514의 외벽 뒤쪽 기준 거절 수정을 이 분석이 대신하지 않는다.
2. 별도 fallback이 필요하면 **추월 중 사용한 현재 차선/외벽 기준을 유지하는 짧은 회복 경로**를 만든 뒤 기존 점유·조향·감속 검사에 통과시키는 방식이 최소 설계 후보다. 곧바로 오프셋0.505m의 중심 경로로 꺾는 것과 구별한다. 미관측 공간을 채우거나 원점부터 벽까지의 빈 공간을 가정하지 않는다. 현재 센서가 지지하는 전방 경로만 쓴다. 이는 설계 제안이며 구현·채택·폐루프 검증은 하지 않았다.
3. 전체 `boundary_anchor_error_m`만 넓히거나 기억TTL을 연장하는 수정은 이번 근거만으로 채택하지 않는다. 전자는 위 저장 입력에서 뒤따르는 점유/추종 실패를 해결하지 못했고, 후자는 현재 경로 재획득 원인을 고치지 못한다.

이번 분석에서는 새로운 정지 조건이나 추가 확인 단계가 필요하다는 근거를 찾지 않았다. 억지 추월보다 현재 관측에 따른 지속 추종을 우선한다는 목표에 맞춰, 이 분석만으로 공통 LocalFollow를 변경하지 않는다.

## 산출물과 한계

- `geometry.json`/`geometry.log`: r503의20개·r513의19개 선택 입력, 총39개의 양쪽 경계 길이·앵커와 원 trace SHA256.
- `anchor_probe.json`/`anchor_probe.log`:37개 baseline 대조와 비채택 앵커 진단값 비교. `anchor_probe.err`는 비어 있다.
