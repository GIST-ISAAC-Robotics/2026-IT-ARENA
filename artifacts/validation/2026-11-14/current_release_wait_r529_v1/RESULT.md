# r529 현재 경로 재개 확인을 관측 준비 대기가 지우는 문제

r520의 첫92계획을 같은 원 입력으로 순서대로 재생했다. 기존은 첫 저속 명령1개만 양수였고 나머지는 정지였다. 현재 경로 확인 두 번째 표본 전에 별도 partial 관측기의 warmup 실패가 `_hold()`를 호출해 `release_count`를 매번0으로 만들고 있었다.

명시 current_route_priority 정책에서 **현재 source의 실제 점유/제동을 통과한 새 경로**가 `follow_release_wait` 중이고 관측 사유가 `partial_history_warmup`뿐이면, 이번 출력은 계속0으로 두되 경로 확인 횟수를 보존한다. 다른 실제 점유 정지/입력 오류/기억 경로에는 적용하지 않는다. 다음 새로운 관측에서 기존2회 확인이 성립해야 정상 양수로 돌아간다.

- 저장92판단: 양수1→91, 기존양수→0은0. 첫 번째 재개 대기1회는 그대로0이며 세 번째판단부터0.45→0.50m/s를 냈다.
- [기존158검사](tests.log) 통과. 신규5검사는 fixture의 구조정책/legacy 설정 오류를 수정한 뒤4개와나머지1개가 각각통과했다([4개](fixture_tests.log), [1개](legacy_fixture_test.log)). 생산 검증조건은 변경하지 않았다.
- 공통 `local_follow.py`에 반영했다. [기계 결과](result.json)와 원본 `local_follow_before.py`, stage, 입력 재생 결과를 보존한다.
- 고정된 이전 입력의 반사실 재생이다. 자차가 실제로 이동한 결과나 독립 guard 해결이 아니다. r520의 guard 최초래치는 첫양수보다이전이므로 별도r528에서 다룬다.
