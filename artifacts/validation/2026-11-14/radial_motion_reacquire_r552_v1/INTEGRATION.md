# r552 저속 현재벽 재획득의 운동 반경

실측 서보 상한을 반영한 r550은25.81m에서 정체했다. [독립 기하 분석](../current_short_path_r549_v1/revision3/independent_analysis.md)에 따르면, 최초0 입력의 실제 반환점이 고정55mm 여유의 차체에 닿으려면48.49mm 이동해야 하지만 그 점의 취득 후 운동 상계는36.45mm였다. 기존 축별 사각 팽창은 x/y 동시 최대를 허용하여 간섭 거리0.04m를 만들었다.

## 적용과 남긴 경계

`swept_limit`에 기본 `None`인 `radial_margin`을 추가했다. 기본 식은 유지하고, 지정할 때만 고정 여유 직사각형 밖의 유클리드 거리를 점별 이동 반경과 비교한다. 기존4cm 표본·한 칸 차감·원시 점유·고정 여유·정지 간격·제동·현재/직전 조향을 유지한다. 물체 속력 상계 자체의 실물 타당성을 증명한 것은 아니다.

현재 연결은 `current_wall_candidate`의 최대0.1m/s 후보에 한정한다. 일반/고속 LocalFollow·독립 guard·기억 소실점·영상 추가 점유는 변경하지 않았다. current/retained 재검사는 해당 후보의 표시와 속도 범위를 확인한 뒤 **새 현재 반환점과 실제 취득 시각으로 다시 반경을 계산**한다. 예전 clearance나 반경을 전달 허가로 재사용하지 않는다. 기본 고속 경로의 축별 여유와 해석이 다르다는 범위도 명시한다.

## 확인한 결과

- Windows 기하35개 통과. 기본/명시None/반경0 일치, 실제 전방·측방 점유, 대각 모서리·잘못된 입력을 포함한다.
- [실제 ROS 환경 관련195개](native_regression.xml)15.17초 통과. helper·기존 현재 재검사·갈림길·독립 guard·STOP을 포함한다.
- [새 연결 반례12개](recheck_verification/junit.xml) 통과. 새 전방 장애물0, 취득 후 시간 증가 반영, 입력 불변, STOP·시각·epoch 거절 및 비대상 기존 sweep를 확인했다.
- [저장 r550 4입력](saved_diagnostic.json): 이전 양수2개 동일, 최초 정지2개가0.1m/s/−16.315° 후보가 됐다. 원시 점유 거리의 해석은0.04→1.00m다.
- [구성된 SOLO 후보의 실제 current/retained 함수](saved_rebase.json) 모두0.1m/s를 유지했다. 이는 보존 센서에서 helper 및 재검사를 연결한 결과이며, 전체 상태 재생이나 주행 결과는 아니다.

[통합 소스·설정 SHA](integrated_manifest.json)와 당시 파일을 보존했다. 다음 실제 주행은 r553 같은 조건 단독1회다. Jetson·ESP32 접근/설치0, 커밋·푸시0이다. 이전 r544/r550 실패와 r549 revision1 미채택 소스는 그대로 남긴다.
