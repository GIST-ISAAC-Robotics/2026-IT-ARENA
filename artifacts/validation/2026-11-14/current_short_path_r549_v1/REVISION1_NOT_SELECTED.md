# r549 현재 반대벽으로 경로 재획득

실측 서보 범위를 적용한 r544 두 번째 단독 주행은19.56m에서 정체했다. 최초 정지 입력을 분석한 결과, 보호층의 충돌 정지가 아니라 **선호벽 앞쪽 관측 길이의 고정 최소조건**으로 경로가 사라진 경우였다. 공통 helper에서 선호벽 경로 생성이 실패하면 현재 반대벽을 한 번 계산하도록 수정했다. 실물 설치·새 주행 결과는 아직 아니다.

## 근거와 수정

- 직전 양수 입력의 왼벽 관측 길이는0.300646m, 최초 수락된0명령 입력은0.254690m였다. `local_path`의0.28m 최소값 때문에 후자가 `wall_segment_short`였다.
- 같은 입력의 오른벽은0.65m 관측됐고, 기존 길이·형상·Pure Pursuit·조향 변화·현재/직전 점유 검사로0.1m/s, −0.151023rad 명령을 만들었다. 시각적으로도 두 벽의 오프셋 경로가 같은 길을 가리킨다.
- [그림](current_geometry.png)과 [대조](alternatives.json)는 저장 센서 입력만 사용했다. 진단용으로 최소길이를0.10m로 바꾼 왼벽 경로도 비교했지만 **그 변경은 공통에 채택하지 않았다.**
- `current_wall_reacquire.py`만 제어 수정했다. 선호 경로가 있으면 기존 흐름 그대로다. 없을 때만 반대벽 생성1회를 시도하며, 이미 생성된 경로의 점유·제동 실패 때문에 다른 벽을 다시 찾지는 않는다. 실제 `path_wall`과 `wall_fallback`, 선호벽 실패 이유를 기록한다.
- 운영자 선호 방향·경로 기억·관측 길이/형상·원시 점유·입력 시각·0.1m/s 재획득 상한·실측 조향 상한·독립 guard/STOP은 유지했다. 보이지 않는 공간을 채우거나 맵/평가 자세를 넣지 않는다.

## 확인

[최초 전후6입력](transition_compare.json)에서 직전 양수2개는 전체 helper 출력이 정확히 동일했고, 경로가 없던4개는0.1m/s 후보가 됐다. 둘 중 앞선0계획은 원 실행에서 전달 취소된 계획이며, 뒤의0계획이 실제 정체 시작이다. 전체 상태 있는 제어기 재생이나 개선 후 궤적 증명으로 해석하지 않는다.

WSL의 관련42검사 통과([JUnit](regression.xml),9.38초). 실제 측정 상한에서 반대벽 재획득·전방 장애물 유지·양벽 소실·점유 실패 시 반대벽 미탐색을 포함한다. 기존 갈림길/현재 경로/이동차 복귀 검사도 포함했다. Windows 진단 첫 시도는 NumPy의2차원 `cross` 호환 오류로 양수행을 재현하지 못했으므로 채택하지 않았고, 실행 환경인 WSL에서 원 양수값을 재현한 뒤 비교했다. 환경이나 공통 수치 코드는 그 오류 때문에 변경하지 않았다.

## 한계와 다음

반대벽이 보인다는 사실만으로 원하는 갈림길임이 증명되지는 않는다. 반대벽은 기존 정상 추종에서도 사용하는 정보이며, 이번 변경은 현재 재획득 helper에만 연결했다. 원 선호 방향을 지속적으로 바꾸지 않는다. 별도 갈림길 대표와 실제 같은 단독 코스1회(r550)로 영향 범위를 확인한다. 원 r544 실패·종료 판정·입력/소스는 보존한다. 현장 모터·서보·Jetson에는 접속하지 않았다.
